この章は、画面の幅や置き場所の違いへのCSSの対応を扱います。対応する相手はビューポートの幅だけではなく、文章や画像の量、コンポーネントが置かれたコンテナの幅、ユーザーが設定した文字サイズの違いも含みます。レスポンシブ対応は、「どの幅で切り替えるか」から考え始めず、「そもそも切り替えが必要か」から順に検討します。クエリは、ほかの手段で解決できないときに使う最後の手段です。

私自身、以前はデザインカンプの幅に合わせてブレイクポイントを決め、コンポーネントごとにメディアクエリを書いていましたが、この方法で見た目を保証できるのはカンプの幅だけです。幅や文字サイズが変わっても破綻しない指定を用意するという前提は「[1-1 CSSはブラウザへの「提案」である](/principles/browser-suggestion/)」で説明しているので、この章では、その前提をクエリとレイアウトの機能で実装する手順を扱います。

もうひとつの前提は、コンポーネントの置き場所が決まっていないことです。同じカードをメインエリアとサイドバーの両方に置くと、ビューポートの幅が同じでもカードの幅は異なるため、ビューポートの幅だけではカード内の配置を決められません。そこで、ページ全体の段組みはビューポートの幅で、コンポーネント内の配置は置かれた場所の幅で決めます。この役割分担が、章全体に共通する考え方です。

置かれた場所の幅を調べる仕組みを、本書ではコンテナサイズクエリと呼びます。`@container` には、カスタムプロパティの値を調べるスタイルクエリと、スクロールの状態を調べるスクロール状態クエリもあり、この3つをまとめてコンテナクエリと呼びます。

## この章で判断できるようになること

この章を読むと、幅の違いで表示が崩れたときに、クエリを足す前に静的な指定やイントリンシックな指定で解決できないかを確かめ、必要なときだけコンテナサイズクエリかメディアクエリを選べるようになります。ブレイクポイントも、カンプの幅からではなく内容が成り立たなくなる幅から決め、その根拠を式で残せます。カンプの比率を保ちたいという要望を受けたときも、全体を拡大・縮小せずに、デザイナーとブレイクポイントを決めるか、局所だけを `cqi` で拡大・縮小するかを選べます。

## この章の節

この章は次の10の節で構成しています。

- [13-1 検討する順番](/responsive/escalation/)：静的、イントリンシック、コンテナサイズクエリ、メディアクエリの順に検討する理由
- [13-2 ブレイクポイントの決め方](/responsive/breakpoints/)：内容が成り立たなくなる幅から閾値を決め、remと `calc()` の式で根拠を残す書き方
- [13-3 コンテナサイズクエリ](/responsive/container-size-queries/)：置き場所の幅に合わせて振る舞うコンポーネントの書き方、`--scoped` のコンテナ、閾値をスタイルクエリで子孫に伝える方法（仕組みは「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」）、コンテナの副作用
- [13-4 コンテナの副作用とコンテナ単位](/responsive/container-units-and-side-effects/)：コンテナにしない要素、`cqi` の基準、外側のコンテナの幅を `@property` で渡す方法、閾値の間を `cqi` で埋める方法
- [13-5 メディアクエリ](/responsive/media-queries/)：ページ全体の段組みの切り替えと、使うメディア特性、使わないメディア特性
- [13-6 375px未満の画面で配置を保つ例外](/responsive/min-viewport-width/)：自然に折り返す表示を基本とする理由、例外としてカンプの配置を保つ要件があるときに限って狭い端末だけビューポートの幅を375pxに固定するスクリプト、判定に `outerWidth` を使う理由
- [13-7 カンプの幅で全体を拡大・縮小しない](/responsive/design-comp-pattern/)：カンプの比率を保つ要望にフルリキッドで応えない理由と、デザイナーとブレイクポイントを決める方法、局所だけを `cqi` で拡大・縮小する書き方
- [13-8 セーフエリアに対応する](/responsive/safe-area/)：ノッチやホームインジケーターを避ける余白と、画面の下に固定する要素の書き方
- [13-9 収まらなくなったらナビゲーションを折りたたむ](/responsive/overflow-collapse/)：閾値を書かずに、ナビゲーション自身の溢れをスクロールタイムラインで検知し、メニューのボタンに切り替える書き方
- [13-10 流体的な値の区間をそろえる](/responsive/fluid-range/)：画面の幅で変える値の区間の端をトークンにして変わり方をそろえる方法と、`progress()` で比率を幅に合わせて変える型スケール

単位の選び方（pxとrem、ビューポート単位とコンテナ単位）は[第6章「値と単位」](/values/)で、コード例で使っている `@scope` とカスケードレイヤーは[第4章「カスケードを制御する」](/cascade/)で説明しています。この章のコード例では、説明に関係しない `@layer` の記述を省略しています。デモのCSSでは省略していません。

## 最初に押さえるルール

次のルールを先に押さえ、ほかのルールは、該当する場面で付録A「[ルール一覧](/appendix/rules/)」から引けば足ります。

- [`responsive-escalation-order`](/responsive/escalation/#rule-responsive-escalation-order)：「静的 → イントリンシック → コンテナサイズクエリ → メディアクエリ」の順に検討し、上の段階で解決できるなら下の段階を使いません。
- [`breakpoint-from-content`](/responsive/breakpoints/#rule-breakpoint-from-content)：ブレイクポイントは、デバイスの幅ではなく、レイアウトが崩れる幅から決めます。
- [`container-name-required`](/responsive/container-size-queries/#rule-container-name-required)：ルートのコンテナは `container: --scoped / inline-size` と書きます。外側のコンポーネントのコンテナは問い合わせません。
- [`threshold-as-formula`](/responsive/breakpoints/#rule-threshold-as-formula)：閾値は「列の最小幅×列数＋隙間×隙間の数」のように、レイアウトが成り立つ条件を `calc()` の式で書きます。
- [`threshold-includes-gap-and-padding`](/responsive/breakpoints/#rule-threshold-includes-gap-and-padding)：閾値の式には、レイアウトが成り立つ条件に関わる `gap`、`padding`、`border` を省かずに含めます。
- [`no-container-on-intrinsic-size`](/responsive/container-units-and-side-effects/#rule-no-container-on-intrinsic-size)：インライン要素や `fit-content` の要素のように、幅が中身で決まる要素をコンテナにしません。

## 判断の問い

この章の内容で答えられる問いを1つ置きます。答えを開く前に、どの書き方を選ぶかを予想してください。

記事のカードは、幅が広いときに画像を左に、狭いときに画像を上に置きます。このカードを、トップページの3列の一覧と、記事ページのサイドバーの両方に置きます。画像の位置の切り替えは、`@media (width >= …)` と `@container --scoped (inline-size >= …)` のどちらで書きますか。

`@container --scoped (inline-size >= …)` で書きます。画面が広くても、サイドバーに置いたカードは狭いままです。ビューポートの幅で切り替えると、サイドバーのカードまで画像が左に並び、文字の入る幅が足りなくなります。カードの幅で切り替えれば、置かれた場所ごとに形が決まります（「[13-3 コンテナサイズクエリ](/responsive/container-size-queries/)」）。

画像の位置に合わせて見出しや余白も変わるなら、クエリはフラグを立てるルールの1か所にだけ書き、ほかの子要素はフラグで切り替えます（「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」）。ページに1つしかない見出しの区画やページ全体の骨組みは、ビューポートの幅で決まるので、メディアクエリで足ります（「[13-1 検討する順番](/responsive/escalation/)」）。

## 手を動かす課題

判断の問いでは、切り替えにどのクエリを使うかを選びました。ここでは、第10章の「[手を動かす課題](/components/#手を動かす課題)」で主欄とサイドバーに置いたカードを使い、同じ画面の幅のまま、置かれた幅でカードの形を変えます。

まず、主欄とサイドバーを横に並べます。`main` と `aside` を「[12-6 sidebar](/compositions/sidebar/)」の `sidebar` で包み、`main` に `main-column`、`aside` に `side-column` のクラスを付けます。`sidebar` のCSSは `css/compositions/sidebar.css` に置き、`layer(compositions)` として読み込みます。

そのうえで、カードの中身の幅（`padding` の内側）が480px以上のときだけ、日付を見出しの右に並べてください。それより狭いときは、これまでどおり日付を見出しの下に置きます。見出しの文字の大きさは、クエリで切り替えずに、カードの中身の幅に合わせて連続的に変えます。中身の幅が320px以下のときは20px、640px以上のときは24pxで、その間は幅に比例させます。

合格の条件は3つです。画面の幅が1280pxのとき、主欄のカードは日付が見出しの右に並んで見出しが24pxになり、サイドバーのカードは日付が見出しの下にあって見出しが20pxになることです。主欄とサイドバーが縦に積まれる768pxのときは、どちらのカードも日付が見出しの右に並び、見出しが24pxになることです。480pxのときは、どちらのカードも日付が見出しの下にあり、見出しが20pxと24pxの間の大きさになることです。画面の幅ではなくカードの幅で決まっていれば、この3つは同時に満たされます。

日付の位置のように途中の状態がない変化は、コンテナサイズクエリで切り替えます。見出しの文字サイズのように途中の値を取れる量は、`clamp()` と `cqi` で連続的に変えます（「[13-4 コンテナの副作用とコンテナ単位](/responsive/container-units-and-side-effects/#閾値と閾値の間の値)」）。カードのルートをコンテナにし、配置を切り替える見出しと日付は、HTMLで `<div class="_header">` に包みます。コンテナ自身は自分の幅を問い合わせられないので、配置を変える要素はルートより一段内側に置く必要があるからです。

```css title="🙆‍♂ Recommended: 日付の位置はクエリで切り替え、見出しの大きさは cqi で連続的に変える" use="diff" from="tasks/13-responsive/css/components/news-card.css"
@scope (.scoped.news-card) to (.scoped) {
  :scope {
    /* ... */
    container: --scoped / inline-size;

    /* ... */
  }

  ._header {
    display: block grid;
    gap: calc(var(--spacing--xxs) * 1px) calc(var(--spacing--sm) * 1px);

    /* 見出しの最小幅 320px 相当・隙間 16px・日付の幅 144px 相当が並ぶ幅 */
    @container --scoped (inline-size >= calc(320 / 16 * 1rem + 16px + 144 / 16 * 1rem)) {
      grid-template-columns: 1fr auto;
      align-items: baseline;
    }
  }

  h2 {
    /* ... */

    /* デザインの2つの大きさ（狭いカードの20px、広いカードの24px）の間を、置かれた幅に合わせて補う */
    font-size: clamp(20 / 16 * 1rem, 1.25cqi + 16 / 16 * 1rem, 24 / 16 * 1rem);
  }
}
```

閾値は、見出しの最小幅320px相当、隙間16px、日付の幅144px相当を足した480pxです。1280pxのとき、サイドバーの幅は `sidebar` のデフォルトの320pxなので、そこに置いたカードの中身の幅は288pxで、日付は見出しの下に残ります。768pxで縦に積まれると、サイドバーのカードも主欄と同じ幅に広がり、日付が見出しの右に並びます。`@media (width >= …)` で書くと、1280pxではサイドバーのカードまで日付が右に並んで見出しの幅が足りなくなり、768pxでは画面の幅だけで決まるので、置き場所の違いを表せません（「[13-3 コンテナサイズクエリ](/responsive/container-size-queries/)」）。

見出しの `1.25cqi + 16 / 16 * 1rem` は、中身の幅が320pxのとき20px、640pxのとき24pxになる直線です。2点から式を組み立てる手順は「[6-3 計算関数で根拠を式に残す](/values/math-functions/)」で説明しています。`h2` とルートの間に別のコンテナはないので、`cqi` の基準はカードのルートです。Chromeで確かめたところ、1280pxでは主欄のカードの見出しが24px、サイドバーのカードの見出しが20pxになり、480pxでは、主欄のカードが約21.4px、サイドバーのカードが約21.6pxになりました。最小値と最大値をremで書いているので、ブラウザの文字サイズの設定を大きくすると、見出しも大きくなります。

この課題でクエリによって変わるのは `._header` の配置だけなので、フラグを作らず、`._header` のルールにクエリを直接書いています。同じ幅で余白や画像の縦横比も変えるなら、クエリはフラグを立てる1つのルールにまとめ、ほかの要素はフラグを読みます（「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」）。

この答えでは、コンテナにしたカードのルートに、第10章から続く `padding` が付いたままです。コンテナにする要素の `padding` は、クエリと `cqi` が基準にする幅をその分だけ狭めるので、本書では推奨していません（「[13-4 コンテナの副作用とコンテナ単位](/responsive/container-units-and-side-effects/#rule-no-padding-on-container)」）。ここでは、閾値と見出しの式をどちらも「カードの中身の幅」で決めているので、結果は変わりません。カードの外形の幅で判定したいときは、見出しと本文を包む要素を足して `padding` をそちらへ移し、閾値と式を外形の幅で書き直します。

答えの例のファイル一式は、[補足サイト](/book-support/index.html)のサンプル一式の `tasks/13-responsive/` にあります。

</details>

## この章の判断のまとめ

幅の違いで崩れたら、クエリを足す前に、静的な指定や折り返し、列数の自動調整で済まないかを確かめます。クエリが要るなら基準で選び、ページ全体の骨組みやビューポートに固定する要素はメディアクエリ、幅の違う複数の場所に置くコンポーネントはコンテナサイズクエリです。列数が増減するだけならイントリンシックな方法で足り、並び順や組み合わせが変わる組み替えになって初めてクエリを使います。

閾値は、カンプやデバイスの幅ではなく、レイアウトが成り立つ条件の式から決めます。画像の幅や文字サイズのように途中の値を取れる量は `clamp()` と `cqi` で埋め、配置のように途中の値を取れない変化だけを閾値で切り替えます。画面の幅で変える値が複数あるなら、変わり始める幅と変わり終える幅をトークンにして、値ごとに区間がずれないようにします。ナビゲーションのように中身の量が変わる横並びを別の表示に置き換えるときは、閾値を書かず、収まらなくなったこと自体を条件にします。「判断の問い」のカードは、置き場所が複数あるのでコンテナサイズクエリを選ぶ例です。
