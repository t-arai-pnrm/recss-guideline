この章では、ユーザーの操作に反応する部分のCSSを扱います。ホバーやフォーカスの状態の表し方、ダイアログやアコーディオンのような開閉するUI、フォーム部品、カルーセルです。インタラクションはできるだけブラウザの機能に任せ、CSSでは見た目を足すことに徹します。

操作に関わるUIは、見た目が同じでも使いやすさが変わります。キーボードで操作できるか、スクリーンリーダーで状態が読み上げられるか、ページ内検索で中身が見つかるかといった違いがあるからです。以前は、こうした振る舞いの多くをJavaScriptで作り直す必要がありました。現在は、`<button>` の `command` 属性で開く `<dialog>` や、`popover` 属性、`<details>` の `name` 属性のように、HTMLとCSSだけで実現できることが増えています。

私自身、少し前まではモーダルの開閉や背景のクリックの判定をJavaScriptで書いていました。入力エラーの表示も、`:invalid` ではページを開いた時点でエラーが出てしまうので、JavaScriptで管理していました。どちらも、いまはブラウザの機能で置き換えられます。

## この章で判断できるようになること

この章を読むと、ホバーで変える見た目をどの状態に限定し、キーボードで操作したときにどう表すかを決められるようになります。開閉するUIでは、`<dialog>`、`popover` 属性、`<details>`、`hidden="until-found"` のどれを使うかを、背面を操作できなくするか、ページ内検索で中身を見つけられるようにするかといった要件から選べます。フォーム部品やカルーセルについても、JavaScriptで作り直していた振る舞いのうち、ブラウザの機能に置き換えられるものを見分けられます。

## この章の節

この章は次の8つの節で構成しています。17-1から17-5は、どの部品にも関わる操作の基本で、17-6から17-8は、部品ごとの作り方です。

- [17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)：`any-hover` によるホバーの書き方、`:focus-visible` との対応、キーボード操作とトランジション、透明度ではなく色で表す変化
- [17-2 押せる範囲とタッチ操作](/interaction/hit-area-and-touch/)：操作する要素の最小の大きさ、余白を付ける要素、項目の間に隙間を作らない並べ方、`user-select` と `touch-action` を指定する範囲
- [17-3 状態を属性で表す](/interaction/state-attributes/)：擬似クラス、HTML要素の属性、ARIA属性、`data-*` 属性の順で選ぶ状態のセレクタ、`:focus-within` と `:has(:focus-visible)` の使い分け
- [17-4 カード全体をリンクにする](/interaction/card-link/)：見出しのリンクの `::after` を広げる方法と、フォーカスリングの出し方
- [17-5 要素を隠す方法を選ぶ](/interaction/hiding-elements/)：見た目、場所、支援技術、操作とフォーカスのどれから消すかで選ぶ隠し方と、`.-visually-hidden` の定義
- [17-6 開閉するUI](/interaction/disclosure/)：`<dialog>`、`popover` 属性、`<details>`、`hidden="until-found"` の使い分け、ドロワーの背面に付ける `inert` 属性
- [17-7 フォーム部品](/interaction/forms/)：`accent-color`、`input` 自体に描くチェックボックス、`switch` 属性、`:user-invalid`、入力欄の文字サイズ
- [17-8 CSSでカルーセルを作る](/interaction/carousel/)：スクロールスナップを土台にした `::scroll-button()` と `::scroll-marker`、隠れているスライドを外す `interactivity: inert`、自動再生をしない判断

トランジションとアニメーション、開閉するUIの出現と退場の動き、View Transitionsによる画面の切り替えは、第18章「[モーション](/motion/)」で扱います。フォーカスリングの定義、スムーススクロール、モーダル表示中の背面の固定は、ベーススタイルに書くものとして「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」で扱います。強制カラーモードでの部品の見え方は「[15-5 強制カラーモードとコントラスト](/color-media/forced-colors/)」で扱います。この章のコード例では、説明に関係しない `@layer` の記述を省略しています。デモのCSSには省略せずに書いています。

## 初めて読むとき

初めて読むときは、基本の節の「[17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)」「[17-3 状態を属性で表す](/interaction/state-attributes/)」を読みます。

## 最初に押さえるルール

次のルールを先に押さえ、ほかのルールは、該当する場面で付録A「[ルール一覧](/appendix/rules/)」から引けば足ります。

- [`hover-with-focus-visible`](/interaction/states-and-focus/#rule-hover-with-focus-visible)：ホバーで変える見た目は、`:focus-visible` にも同じように指定します。
- [`hover-operable-in-any-hover`](/interaction/states-and-focus/#rule-hover-operable-in-any-hover)：ホバーのスタイルは、`&:any-link:hover` や `&:enabled:hover` のように操作できる状態に限定し、`@media (any-hover)` の中に書きます。
- [`native-disclosure-elements`](/interaction/disclosure/#rule-native-disclosure-elements)：開閉するUIは、`<dialog>`、`popover` 属性、`<details>` のようなHTMLの機能で作り、`div` とクラスの付け外しで作りません。
- [`state-by-pseudo-class-or-aria`](/interaction/state-attributes/#rule-state-by-pseudo-class-or-aria)：状態のスタイルは、`.is-active` のような状態クラスを使わず、擬似クラス、HTML要素の属性、ARIA属性、`data-*` 属性の順に選んだセレクタで書きます。
- [`no-maximum-scale`](/interaction/forms/#rule-no-maximum-scale)：入力欄での拡大を防ぐために、`maximum-scale` や `user-scalable=no` でズームを止めません。

## 判断の問い

この章の内容で答えられる問いを1つ置きます。答えを開く前に、開閉の状態をどこから読み取るかを予想してください。

よくある質問を `<details>` と `<summary>` で並べたアコーディオンで、開いている項目だけ背景色を変え、`<summary>` の右端の矢印を半回転させたいと言われました。開閉に合わせて、JavaScriptで `<details>` に `.is-open` クラスを付け外しする案が出ています。開閉の状態は、どの要素の何から読み取りますか。あわせて、`<summary>` にホバーの見た目を付けるときの書き方も考えてください。

```html
<div class="scoped faq-accordion">
  <details class="_item">
    <summary class="_question">送料はかかりますか？<span class="_icon" aria-hidden="true"></span></summary>
    <p>…</p>
  </details>
</div>
```

<details>
{/* textlint-disable ja-technical-writing/ja-no-mixed-period */}
<summary>答えと解説</summary>
{/* textlint-enable ja-technical-writing/ja-no-mixed-period */}

`<details>` の `open` 属性から読み取り、`.is-open` は付けません。`open` 属性は、`<summary>` を押したときも、キーボードで開閉したときも、対応したブラウザでページ内検索の結果として自動で開いたときも、ブラウザが付け外しします。状態を表すセレクタは、擬似クラス、HTML要素の属性、ARIA属性、`data-*` 属性の順に選ぶので、HTML要素の属性がある状態にクラスを足すと、同じ状態を2か所で管理することになります（「[17-3 状態を属性で表す](/interaction/state-attributes/)」）。`:open` 擬似クラスもありますが、Safariが対応したのは26.5からなので、本書の対象のすべてでは使えません（「[17-6 開閉するUI](/interaction/disclosure/)」）。

```css title="🙆‍♂ Recommended: 開閉の状態を open 属性から読み、summary のホバーをフォーカスとそろえる"
@scope (.scoped.faq-accordion) to (.scoped) {
  ._item {
    &[open] {
      background-color: var(--background--surface);
    }
  }

  ._question {
    &:focus-visible {
      background-color: var(--background--hover);
    }

    &:hover {
      @media (any-hover) {
        background-color: var(--background--hover);
      }
    }
  }

  ._icon {
    display: inline flow-root;

    /* ... */

    @media (prefers-reduced-motion: no-preference) {
      transition-duration: var(--duration--base);
      transition-property: rotate;
      transition-timing-function: var(--ease--in-out-quint);
    }

    &:is(._item[open] *) {
      rotate: 0.5turn;
    }
  }
}
```

矢印は `<summary>` の中の子要素なので、`&:is(._item[open] *)` で祖先の `<details>` の状態を読みます。`<span>` は初期値でインラインの要素で、`rotate` のような変形が適用されないので、`display: inline flow-root` にしてから回します。矢印の描き方は省いています。回転は大きな変動にあたるので、トランジションは `prefers-reduced-motion: no-preference` の中に書きます（「[18-7 出現と退場](/motion/entry-and-exit/)」）。`<summary>` には無効の状態がないので、ホバーは `&:any-link:hover` や `&:enabled:hover` で絞らずに `&:hover` と書き、`@media (any-hover)` の中に置きます。同じ見た目を `:focus-visible` にも指定し、キーボードで操作するユーザーにも同じ手がかりを示します（「[17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)」）。

</details>

## この章の実装を終えたら確かめること

操作の実装を終えたら、キーボードだけで、すべてのリンク、ボタン、開閉の操作に届くか、フォーカスが見えるか、移動の順番が見た目の順番と合うかを確かめます。ホバーで変わる見た目は、`:focus-visible` でも同じように変わるかを見ます。押せる範囲は、24px相当（タッチ操作ができる環境では44px相当）あるかを確かめます。条件の再現のしかたは「[19-3 表示と操作を確かめる](/operations/verification/)」で説明しています。

## この章の判断のまとめ

操作に応じた振る舞いが要るときは、JavaScriptで作り直す前に、ブラウザの要素や属性で足りないかを見ます。状態に合わせて見た目を変えたいなら、クラスを足さず、その状態をブラウザや支援技術に伝えている擬似クラスや属性をセレクタにします。

押し損じや、ホバーの背景が途切れるといった症状は、余白を外側の要素や項目の間の隙間に置いていないかを調べ、操作する要素自身の `padding` に移します。ホバーで変えた見た目は、`:focus-visible` でもキーボードの利用者に同じ手がかりが出ているかを確かめます。

## 次の章へ

ここまでで、操作に応じて状態を切り替え、その状態を伝えられるようになりました。切り替わる瞬間に動きを付けると変化は分かりやすくなりますが、繰り返し触るUIでは待ち時間が増え、動きを減らす設定をしているユーザーには不調の原因にもなるので、動かすかどうかは別に判断します。第18章「[モーション](/motion/)」では、動かすかどうかの判断から、出現と退場、View Transitionsまでを説明します。
