開閉するUIは、HTMLの機能で作ります。モーダルは `<dialog>` を `command` 属性で開き、`closedby="any"` で背景のクリックでも閉じられるようにします。メニューのような小さな表示には `popover` 属性を、その場で開閉する項目には `<details>` を使います。

見出しの構造を保ちたいアコーディオンやタブでは、閉じたパネルを `hidden="until-found"` で隠します。ヘッダーのボタンで開閉するドロワーはモーダルにできないので、開いている間は背面の要素に `inert` 属性を付けます。どれも `display: none` とクラスの付け外しで作るより、少ないコードで、キーボードやページ内検索にも対応できます。

## 開閉をブラウザの機能に任せる

モーダルやアコーディオンは、`div` に `.is-open` のようなクラスを付け外しし、閉じているときは `display: none` で隠す形で作られてきました。この方法では、ブラウザが本来持っている振る舞いを、すべて自分で作り直すことになります。

```css title="🙅‍♂ Not Recommended: クラスの付け外しで開閉する" issue="behavior"
/* 🙅‍♂ Not Recommended */
.modal {
  display: none;
}

.modal.is-open {
  display: block;
}
```

モーダルなら、開いたときのフォーカスの移動、Escキーで閉じる操作、背面を操作できなくする処理、ほかの要素より手前に出すための `z-index` の調整が必要です。アコーディオンなら、閉じたパネルの中身がページ内検索で見つからなくなります。どれもJavaScriptで補えますが、補うほどコードが増え、抜け漏れも出ます。

現在は、用途に合わせた要素と属性がそろっています。

| 用途 | 使う要素・属性 |
| --- | --- |
| 背面の操作を止めるモーダル | `<dialog>` と `command="show-modal"` |
| メニューや通知のような小さな表示 | `popover` 属性 |
| その場で開閉する項目（FAQなど） | `<details>` と `<summary>` |
| 見出しの下で開閉するパネル、タブ | `hidden="until-found"` |
| ヘッダーのボタンを残したまま開くドロワー | 背面の要素に付ける `inert` 属性 |

## `command` 属性と `closedby` 属性によるダイアログの開閉

モーダルのダイアログは、`<dialog>` で作ります。開くボタンに `commandfor` 属性で対象のIDを、`command="show-modal"` で操作を指定すれば、`showModal()` を呼ぶJavaScriptは要りません。閉じるボタンには `command="close"` を指定します。

```html title="command 属性と closedby 属性で開閉するダイアログ"
<button type="button" commandfor="contact-dialog" command="show-modal">お問い合わせ</button>

<dialog id="contact-dialog" class="scoped site-dialog" closedby="any" aria-labelledby="contact-dialog-heading">
  <h1 id="contact-dialog-heading">お問い合わせ</h1>
  <p>…</p>
  <button type="button" commandfor="contact-dialog" command="close">閉じる</button>
</dialog>
```

`command` 属性は `<button>` でしか使えません。そのため、`div` や `span` にクリックの処理を付けたボタンのような、マークアップの誤りも防げます。`closedby="any"` を指定すると、Escキーに加えて、背景（`::backdrop`）のクリックでも閉じます。これまでクリックの位置を調べていた処理は不要です。

組み込みのコマンドは6つあり、それぞれ対象の要素のメソッドに対応します。`commandfor` 属性には、同じ文書（Shadow DOMの中なら同じシャドウルート）にある要素のIDを書きます。ダイアログを非モーダルで開くコマンドはないので、`show()` で開く場合はJavaScriptを使います。

| `command` の値 | 対象 | 対応するメソッド |
| --- | --- | --- |
| `show-modal` | `<dialog>` | `showModal()` |
| `close` | `<dialog>` | `close()` |
| `request-close` | `<dialog>` | `requestClose()` |
| `show-popover` | `popover` 属性の要素 | `showPopover()` |
| `hide-popover` | `popover` 属性の要素 | `hidePopover()` |
| `toggle-popover` | `popover` 属性の要素 | `togglePopover()` |

`close` と `request-close` は、閉じる前に `cancel` イベントが発生するかどうかが違います。`close` はすぐに閉じます。`request-close` はEscキーで閉じるときと同じく先に `cancel` イベントを発生させるので、`preventDefault()` で閉じるのを止められます。入力中のフォームを含むダイアログでは、閉じるボタンに `request-close` を指定すると、破棄してよいかの確認を `cancel` イベントの処理1か所にまとめられます。どちらのコマンドでも、ボタンの `value` 属性の値はダイアログの `returnValue` に入ります。

`showModal()` で開いたダイアログは、背面の要素を操作できない状態にし、閉じたときには開く前の要素へフォーカスを戻します。独自のフォーカストラップは作りません。ブラウザのアドレスバーやツールバーへの移動まで妨げてしまうからです。ダイアログの見出しは `<h1>` にして、`aria-labelledby` でダイアログの名前にします。背面の要素は操作できないだけでなくinertになり、アクセシビリティツリーからも外れるので、ほかの見出しはツリーに現れません。そのため、ダイアログの中の見出しレベルは、ページ本体と続けて数えず `<h1>` から始めます。背面がinertにならない`show()`の非モーダルなダイアログには、この理由は当てはまりません。

`command` 属性と `commandfor` 属性はChrome 135、Firefox 144、Safari 26.2から対応していますが、`closedby` 属性はSafariが未対応です。`command` 属性に対応していないブラウザでは、ボタンを押してもダイアログが開きません。私は、Web標準で使えるようになる機能はポリフィルを入れてでも使う方針なので、`invokers-polyfill` と、私が作った `dialog-closedby-polyfill` を読み込んでいます。`closedby` 属性に対応していなくても、Escキーと閉じるボタンでは閉じられます。

`command` 属性には、`--` で始まる独自の値（カスタムコマンド）も書けます。カスタムコマンドのボタンを押すと、ブラウザは何も操作せず、対象の要素に `command` イベントを発生させます。イベントの `command` プロパティにはコマンドの値が、`source` プロパティには押されたボタンが入ります。処理は対象の要素の側に1つ書くだけで済み、ボタンごとにクリックの処理を付ける必要はありません。

```html title="カスタムコマンドのボタン"
<button type="button" commandfor="photo-viewer" command="--zoom-in">拡大</button>
<button type="button" commandfor="photo-viewer" command="--zoom-out">縮小</button>
<img id="photo-viewer" src="photo.jpg" alt="…" width="800" height="600">
```

```js title="対象の要素で command イベントを受け取る"
const viewer = document.getElementById('photo-viewer');
viewer.addEventListener('command', (event) => {
  if (event.command === '--zoom-in') zoomBy(viewer, 1.25);
  if (event.command === '--zoom-out') zoomBy(viewer, 0.8);
});
```

`command` イベントは、組み込みのコマンドでも、操作の前に発生します。イベントは取り消し可能で、`preventDefault()` を呼ぶとダイアログやポップオーバーの開閉も行われません。

ダイアログと背景を `@starting-style` でフェードさせる方法は、「[18-7 出現と退場](/motion/entry-and-exit/)」で説明します。

## ドロワーの背面を不活性にする方法

ヘッダーと一体になったドロワーメニューでも、開いている間は、背面のメインエリアとフッターを操作できなくします。ただし、ドロワーを開閉するボタンをヘッダーに置いたまま操作させたい場合、ドロワーを `<dialog>` のモーダルにはできません。`showModal()` で開いたダイアログは、ダイアログの外をすべて不活性にするので、ヘッダーのボタンも押せなくなるからです。

そこで、背面の要素だけを不活性にします。不活性になった要素は、クリックとフォーカスができなくなり、アクセシビリティツリーからも外れます。この状態は、HTMLでは `inert` 属性で、CSSでは `interactivity: inert` で指定できます。2025年3月の時点で、私はこの場面をCSSで次のように書いていました。

```css title="🙅‍♂ Not Recommended: ページ全体を起点にした :has() で、ヘッダー以外を不活性にする" issue="behavior"
/* 🙅‍♂ Not Recommended */
body:has(.drawer-button[aria-expanded="true"]) {
  & :not(.global-header, .global-header *) {
    interactivity: inert;
  }
}
```

このコードには、問題が3つあります。1つ目は、`:has()` の起点が `body` で、引数も子孫全体を調べる形になっていることです。DOMが変わるたびに `body` の子孫全体を調べ直すので、要素の多いページではスタイルの再計算が重くなります（第5章「[5-3 :has() で祖先と前の兄弟を選ぶ](/pseudo/has/)」）。2つ目は、ヘッダーが `<div>` などで包まれている場合に、その祖先も `:not()` に一致して不活性になることです。`interactivity` は継承し、子孫から打ち消せないので、ヘッダーごと操作できなくなります。

3つ目は、未対応の環境で機能が損なわれることです。`interactivity` に対応していない環境では、ドロワーが開いている間も背面を操作できてしまい、フォーカスがドロワーの外へ出て、見えないリンクを操作することになります。開閉のボタンの `aria-expanded` はJavaScriptで切り替えているので、本書では、同じ処理の中で背面の要素に `inert` 属性を付けることを基本にします。`inert` 属性は、主要なブラウザで使えます。

<Baseline id="inert" name="inert 属性" />

```js title="ドロワーの開閉に合わせて、背面の要素に inert 属性を付ける"
const button = document.querySelector('.global-header ._drawer-button');
const drawer = document.querySelector('.global-header ._drawer');
const background = document.querySelectorAll('body > :not(.global-header)');

const setExpanded = (expanded) => {
  button.setAttribute('aria-expanded', String(expanded));
  drawer.hidden = !expanded;
  for (const element of background) element.inert = expanded;
};

const initializeDrawer = () => {
  if (!button || !drawer) return;
  button.setAttribute('aria-controls', drawer.id);
  setExpanded(false);
  button.hidden = false;

  button.addEventListener('click', () => {
    setExpanded(button.getAttribute('aria-expanded') !== 'true');
  });

  document.addEventListener('keydown', (event) => {
    if (event.key !== 'Escape' || button.getAttribute('aria-expanded') !== 'true') return;
    setExpanded(false);
    button.focus();
  });
};

initializeDrawer();
```

ドロワーも、「`hidden="until-found"` で隠すタブとアコーディオン」のパネルと同じく、初期のHTMLでは隠しません。初期のHTMLではナビゲーションを表示し、JavaScriptがなければ働かない開閉のボタンに `hidden` 属性を付けておきます。初期化が成功した時点で、ボタンに `aria-controls` と `aria-expanded` を付けてボタンを表示し、ドロワーに `hidden` 属性を付けて閉じます。スクリプトの読み込みや実行に失敗しても、ナビゲーションは表示されたままです。

開閉では、ドロワーの `hidden` 属性と、`body` の直下の要素のうちヘッダー以外の `inert` を切り替えます。ヘッダーが `body` の直下にある構造が前提で、ヘッダーを包む要素がある場合は、その要素の兄弟を対象にします。

背面を不活性にしている間、ドロワーはモーダルのダイアログと同じように振る舞います。利用者はダイアログと同じくEscキーで閉じられると期待するので、Escキーでも閉じ、フォーカスを開閉のボタンへ戻します。`<dialog>` と違ってブラウザはこの操作を受け持たないので、`keydown` イベントで書き足します。

次のデモでは、上のスクリプトをそのまま動かしています。まずドロワーを閉じたままTabキーを押し、本文のリンクにフォーカスが移ることを確かめてください。「メニュー」ボタンでドロワーを開いてからTabキーを押すと、フォーカスはヘッダーのボタンからドロワーのリンクへ移り、最後のリンクの次は、灰色になった本文のリンクを飛ばしてデモの外へ出ます。開いている間にEscキーを押すと、ドロワーが閉じ、フォーカスは「メニュー」ボタンに戻ります。

CSSだけで書く場合は、`:has()` の起点をヘッダーに絞ります。`.global-header:has(._drawer-button[aria-expanded="true"]) ~ *` のように後ろの兄弟を選べば、ページ全体を調べ直さずに済みます。Chromeでは、この形で背面のリンクにフォーカスできなくなることを確かめました。ただし、`interactivity` がBaselineになるまでは、`inert` 属性の代わりにはしません。

## スクロールの連鎖を止める

モーダルやドロワーの中を端までスクロールすると、そのまま背面のページがスクロールし始めます。このスクロールの連鎖は、`overscroll-behavior` で止められます。

`dialog` と `[popover]` 自体には、kiso.cssが `overscroll-behavior-block: contain` を指定しています。ドロワーの本文のように、中の要素がスクロールする場合は、その要素にも指定します。

```css title="🙆‍♂ Recommended: ドロワーの中でスクロールする部分に、スクロールの連鎖を止める指定をする"
@scope (.scoped.site-drawer) to (.scoped) {
  ._body {
    overflow-y: auto;
    overscroll-behavior-block: contain;
  }
}
```

`contain` は連鎖だけを止め、要素の中の跳ね返りの動きは残します。軸を付けない `overscroll-behavior: contain` は、横方向のスワイプで前のページに戻る操作まで止めてしまうので、スクロールする方向の軸だけに指定します。

<Baseline id="overscroll-behavior" compatKey="css.properties.overscroll-behavior-block" name="overscroll-behavior-block" />

上の表示が「一部のブラウザのみ」なのは、はみ出しのないスクロールコンテナにも適用されるという新しい仕様を含むためで、スクロールする要素にはSafariも16から対応しています。モーダルを開いている間の背面のスクロールは、`:root:has(:modal)` で止めています（「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」）。

## `popover` 属性による小さな表示

メニュー、ツールチップ、通知のように、背面の操作を止めない小さな表示には、`popover` 属性を使います。ボタンの `popovertarget` 属性で対象を指定すれば、JavaScriptなしで開閉できます。`commandfor` 属性と `command="toggle-popover"` でも同じ操作になるので、ダイアログと書き方をそろえることもできます。`popover` 属性の要素はトップレイヤーに表示されるので、ほかの要素より手前に出すための `z-index` の調整も要りません。

`popover` 属性の値が `auto`（値を省略したとき）なら、外側をクリックするかEscキーを押すと閉じます。ほかの `auto` のポップオーバーを開くと、先に開いていたものは閉じます。自動で閉じてほしくない通知には、`popover="manual"` を指定します。開いている状態は `:popover-open` 擬似クラスで選べます。

注意したいのは、ボタンの隣に表示する位置の決め方です。アンカーポジショニングを使えばCSSだけでボタンの位置に合わせられますが、Safariは26から対応したので、本書の対象のすべてでは使えません（「[11-8 アンカーポジショニング](/layout-practice/anchor-positioning/)」）。対象のすべてが対応するまでは、未対応の環境でも内容に重ならない位置を基本にします。出現と退場の動かし方は、「[18-7 出現と退場](/motion/entry-and-exit/)」のデモにあります。

## `<details>` と `name` 属性によるアコーディオン

その場で開閉する項目は、`<details>` と `<summary>` で作ります。JavaScriptなしでキーボードでも開閉でき、対応したブラウザでは、ページ内検索で中身が見つかったときに自動で開きます。同じ `name` 属性を付けた `<details>` は、1つを開くとほかが閉じる、排他的なアコーディオンになります。

```html title="name 属性で1つだけ開くアコーディオン"
<section class="scoped faq-accordion" aria-labelledby="faq-accordion-heading">
  <h2 id="faq-accordion-heading">よくある質問</h2>
  <details name="faq-accordion" open>
    <summary>送料はかかりますか？</summary>
    <p>…</p>
  </details>
  <details name="faq-accordion">
    <summary>注文をキャンセルできますか？</summary>
    <p>…</p>
  </details>
</section>
```

<Baseline id="details-name" name="details の name 属性" />

`<summary>` の中に見出しの要素は入れません。`<summary>` の中では見出しの役割が失われ、見出しで移動するユーザーが項目にたどり着けなくなります。見出しの構造が必要なら、後で説明する `hidden="until-found"` の方法を使います。デフォルトの三角のマーカーは、kiso.cssが `summary` の `list-style-type` を空にして消しています。

開いているときのスタイルは、`[open]` 属性のセレクタで書きます。`:open` という擬似クラスもありますが、Safariは26.5から対応したので、本書の対象のすべてでは使えません。

開閉する部分を `::details-content` で選び、高さと不透明度を動かす方法は、「[18-7 出現と退場](/motion/entry-and-exit/)」で説明します。

## `hidden="until-found"` で隠すタブとアコーディオン

見出しの下で開閉するパネルやタブのパネルは、閉じているときに `hidden="until-found"` で隠します。`display: none` で隠したパネルの中身は、ページ内検索で見つかりません。`hidden="until-found"` なら、ページ内検索やページ内リンクで中身が見つかったとき、ブラウザが自動で `hidden` 属性を外して表示します。

```html title="見出しの下で開閉するパネル"
<section class="scoped shipping-section" aria-labelledby="shipping-heading">
  <h2 id="shipping-heading">
    <a href="#shipping-panel">配送について</a>
  </h2>
  <!-- 初期の HTML では隠さない。開閉の処理の初期化が成功してから隠す -->
  <div id="shipping-panel">
    <div class="_panel-inner">…</div>
  </div>
</section>
```

初期のHTMLでは、パネルを隠さずに表示しておきます。JavaScriptが無効な環境や、スクリプトの読み込みや実行に失敗した環境でも、中身を読めるようにするためです。開閉の処理の初期化が成功した時点で、JavaScriptからリンクに `role="button"`、`aria-expanded`、`aria-controls` を付け、パネルに `hidden="until-found"` を付けて閉じます。開閉のボタンを `href` を持つ `<a>` にしているのは、初期化の前でも、パネルへのページ内リンクとして働くようにするためです。

```js title="開閉の処理が動く状態になってから隠す"
const initializeDisclosure = (link) => {
  const panel = document.getElementById(link.hash.slice(1));
  if (!panel) return;
  link.setAttribute('role', 'button');
  link.setAttribute('aria-controls', panel.id);
  link.setAttribute('aria-expanded', 'false');
  panel.hidden = 'until-found';
  panel.addEventListener('beforematch', () => link.setAttribute('aria-expanded', 'true'));
  // クリックとキー操作での開閉は省略
};
```

ページ内検索などで自動で開いたときには `beforematch` イベントが発生するので、`aria-expanded` を更新します。見た目の状態は、「[17-3 状態を属性で表す](/interaction/state-attributes/)」で説明したように、`[aria-expanded="true"]` や `[aria-selected="true"]` をセレクタにして表します。

`hidden="until-found"` に対応したブラウザは、要素を `display: none` ではなく `content-visibility: hidden` で隠します。中身だけが隠れて要素自体は描画されるので、その要素の余白、枠線、背景は、閉じていても表示されます。これらは内側の要素に指定します。

```css title="🙆‍♂ Recommended: 余白と背景は、内側の要素に指定する" from="interaction/until-found-panel"
@scope (.scoped.shipping-section) to (.scoped) {
  ._panel-inner {
    padding: 16px;
    background-color: var(--background--base);
  }
}
```

次のデモは、上のHTMLに開閉の処理を加えたもので、パネルは閉じた状態で始まります。閉じたまま、Ctrl+F（macOSでは⌘F）で「置き配」を検索してみてください。パネルが自動で開き、見出しの記号が `aria-expanded` に合わせて「−」に変わります。見出しのリンクを押すか、フォーカスしてEnterキーかSpaceキーを押しても開閉できます。セクションの角丸は、ルートの `overflow: clip` で切り取らずに、見出しのリンクとパネルの内側の要素の角丸で合わせています。ルートで切り取ると、幅いっぱいに広げた見出しのリンクのフォーカスリングまで切り取られるからです。

Safariは、`hidden="until-found"` に対応していません。未対応の環境では通常の `hidden` として扱われ、閉じたパネルの中身はページ内検索で見つかりません。ただし、隠すのは初期化が成功した後なので、開閉の処理は動き、JavaScriptが動かない環境では最初から中身が表示されています。なお、リセットCSSに `[hidden] { display: none !important; }` と書くと、`until-found` まで `display: none` で隠れてしまいます。kiso.cssは、`until-found` をこの指定から外しています（「[8-1 壊さないリセット](/reset/kiso/)」）。

## 開閉するUIで確かめる状態

開閉するUIでは、JavaScriptが無効な場合と、JavaScriptは有効でも開閉の処理の初期化に失敗した場合を分けて確かめます。前者は最初からスクリプトが動かない状態で、後者はスクリプトの読み込みの失敗や、パネルのIDの誤りで処理が途中で止まった状態です。このページで説明した振る舞いから、確かめる状態を次の表にまとめました。

| 状態 | 確かめること | 期待する結果 |
| --- | --- | --- |
| JavaScriptが無効 | `hidden="until-found"` で隠すパネルを表示する | パネルの中身が最初から表示され、見出しのリンクはパネルへのページ内リンクとして働く |
| JavaScriptは有効だが初期化に失敗 | 開閉の処理のスクリプトを読み込めないようにする | パネルは隠されずに表示され、見出しのリンクに `role="button"` や `aria-expanded` が付かない |
| `hidden="until-found"` に対応したブラウザ | 閉じたパネルの中の語をページ内検索する | パネルが自動で開き、`aria-expanded` が `true` になる |
| Safari（`closedby` 属性と `hidden="until-found"` が未対応） | ダイアログを閉じ、閉じたパネルの中の語を検索する | Escキーと閉じるボタンでダイアログが閉じる。パネルの中身は検索で見つからないが、見出しのリンクで開ける |
| キーボードだけの操作 | ダイアログを開いて閉じ、`<summary>` と開閉する見出しのリンクを操作する | 開いたダイアログの外は操作できず、閉じると開く前のボタンにフォーカスが戻る。`<details>` もキーボードで開閉できる。フォーカスリングが祖先の `overflow` で切り取られずに見える |
| ドロワーを開いた状態 | Tabキーだけで操作し、Escキーを押す | フォーカスはヘッダーのボタンとドロワーのリンクに移り、背面の本文やフッターのリンクには止まらない。Escキーで閉じ、フォーカスが開閉のボタンに戻る |
| 動きを減らす設定 | ダイアログと `<details>` を開閉する | `<details>` の高さと不透明度は動かず、ダイアログのフェードだけが残る |
| 強制カラーモード | ダイアログを開き、開閉の状態を見比べる | ダイアログの範囲と、開いている項目が見分けられる |

JavaScriptの無効は、Chromeの開発者ツールのコマンドメニューで「Disable JavaScript」を実行すると再現できます。初期化の失敗は、ネットワークパネルでスクリプトのリクエストをブロックするか、パネルのIDを書き換えて再現します。動きを減らす設定と強制カラーモードは、「Rendering」パネルで再現できます。それぞれ「Emulate CSS media feature prefers-reduced-motion」と「Emulate CSS media feature forced-colors」を切り替えます。強制カラーモードでのダイアログと背景の見え方は、このページでは確かめていません。{/* 要検証: ブラウザ。強制カラーモードでの dialog と ::backdrop の見え方は未検証 */}
