本書の節のページは、共通の構成と記号で書いています。このページでは、節のページの構成、初めて読むときに読む節の見分け方、ルールの強度と性質、コード例のラベル、デモ、ブラウザの対応状況の表示、確かめた環境をまとめます。

## 節のページの構成

節のページは、冒頭の数段落でその節の結論を先に示し、最後に「ガイドライン」と「参考リンク」を置くという基本の構成を持っています。その間の進め方は、節の題材に合わせて選んでいます。コード例とデモは、説明する見出しの直下に置いています。

仕組みを理解する節は、実際に起きる表示から始め、どう表示されるかを予測したうえで仕組みを説明し、デモで確かめます。手法を選ぶ節は、満たしたい要件を挙げ、選択肢を比べてから、どれを選ぶかの判断を示します。実装する節は、完成形を先に見せ、組み立ての手順と表示の検証を経て、注意点を添えます。本書独自の規約を導入する節は、目的、約束の中身、例外、チームでの運用の順に書き、採用したときに増える手間も示します。このほか、よくある書き方の問題点から本書の解決策へ進む節もあります。

ページの最後にある「ガイドライン」は、その節で守るべきルールの一覧です。時間がないときは、ここだけを確認してもかまいません。ルールの理由を知りたいときは、本文に戻ってください。ただし、第I部でCSSや設計の考え方を述べる節（1-3〜1-7、2-1、2-2、第3章）にはルールを置いていないので、「ガイドライン」もありません。第I部でも、1-1、1-2、2-3にはルールを置いています。

第21章の演習の節は、別の形で進みます。各節で部品を作ったあと、途中で要件を1つ変え、直す場所を予想してから解説を読み、最後に判断を問う問題と答えで振り返ります。演習では新しいルールを置かず、「ガイドライン」の代わりに、その節で使ったルールを掲載ページへのリンク付きで並べています。

## 初めて読むときの順番

第1章から第20章の節には、タイトルの下に「基本」「応用」「参照」のどれかを示しています。「基本」は初めて読むときに読む節、「応用」は要件が出たときに通して読む節、「参照」は必要な見出しを引いて使う節です。Webのサイドバーでは応用と参照の節に、紙の書籍では目次のすべての節に、同じ区別の印を付けています。

初めて読むときは、各章の概要と「基本」の節を章の順に読めば、「[はじめに](/introduction/preface/#学ぶ順番と確かめ方)」で示した4つの単位の問いと課題まで進めます。応用と参照の節は、作るものが決まったときや、演習で知らないルールを見つけたときに読んでください。各章の概要にも、その章の基本の節を挙げています。次の3つの章だけは、読み方が異なります。

| 章 | 初めて読むとき |
|---|---|
| 第1〜3章（考え方の章） | 基本の節（1-1〜1-3、2-1、2-3、3-1）を読む。ルールを置いているのは、1-1、1-2、2-3だけ |
| 第20章「[AIにコーディングさせる](/ai-coding/)」 | AIを使う読者だけが、基本の節（20-1、20-2）を読む |
| 第21章「[コーポレートサイトを作る](/exercise/)」 | 21-1〜21-5を読む。各節の冒頭に、その節で使うルールを説明している節を並べている |

読み飛ばした節に戻るきっかけは、第21章の演習で作ります。演習の各節は、その節で使ったルールを掲載ページへのリンク付きで並べているので、知らないルールがあれば、そこから該当する節を読めます。

## ルールの強度と性質、ID

ルールには、「必須」「推奨」「非推奨」「禁止」の4段階の強度を付けています。「必須」と「禁止」は、各ルールの補足に書いた適用範囲と例外を除き、必ず守るルールです。補足の例外に当たるコードは違反ではないので、レビューやAIのチェックで指摘しません。「推奨」と「非推奨」は、基本的には従いますが、理由があれば外れてかまいません。外れるときは、その理由をコメントに残します。

強度とは別に、ルールの根拠がどこにあるかを「性質」として示しています。「仕様にもとづく制約」は、CSS・HTML・ブラウザの振る舞いやWCAGを根拠にしたルールで、適用する条件に当たる場面で守らないと、表示、操作、情報の伝わり方に問題が出ます。根拠が仕様や挙動にあるという意味で、その書き方を仕様が義務づけているとは限りません。問題が起きる条件を前もって避けるために、本書が条件より広く求めている場合もあり、そのときは補足に書いています。「実装上の判断」は、状況とトレードオフで決まるルールです。適用する条件は、補足や本文に書いています。「本書の規約」は、命名やレイヤーの順番のように、一貫性のために本書が選んだ約束です。自分の案件に持ち帰るときは、仕様にもとづく制約はそのまま使い、実装上の判断は条件が合うかを確かめ、本書の規約はチームの規約と見比べて選んでください。

本書が勧めない書き方の多くは、CSSとして正しく動きます。BEMの `.card__title`、`display: flex`、`margin-top`、`@media (min-width: 768px)` は、どれも有効なCSSで、ブラウザも問題なく表示します。本書がこれらを使わないのは、読みやすさや変更のしやすさ、多言語への対応のような保守の理由からです。そのため、本書の規約の「必須」や「禁止」は、本書を採用したプロジェクトの中での約束を表しており、CSSの仕様に反しているという意味ではありません。チームで使うときは、ルールの理由に納得したうえで、規約として合意することが前提になります。どこから取り入れるかは、「[19-6 既存のサイトに段階的に導入する](/operations/adoption/)」で現場の条件ごとに示しています。

各ルールには、`no-vw-vh` のような英語のIDを付けています。IDは章の構成が変わっても変えないので、レビューのコメントやAIへの指示で「`no-vw-vh` に違反しています」のように引用できます。すべてのルールは、付録A「[ルール一覧](/appendix/rules/)」にまとめています。

ルールによっては、「自動チェック」の欄にStylelintのルール名を書いています。本書のStylelintの設定を使えば、そのルールへの違反は機械的に見つけられます。設定の中身は「[19-1 Stylelintでルールを守る](/operations/stylelint/)」で説明します。

## コード例のラベル

コード例のタイトルには、2種類のラベルを付けています。`🙆‍♂ Recommended` は本書が勧める書き方で、`🙅‍♂ Not Recommended` は避けるべき書き方です。避けるべき書き方には、コードの先頭行にも同じラベルをコメントで入れています。コードだけを切り出して読んだときにも、避けるべき例だと分かるようにするためです。

`🙅‍♂ Not Recommended` には、タイトルの後ろに「動作の問題」か「規約との差」のどちらかを添えています。「動作の問題」は、表示、操作、アクセシビリティ、性能のどれかに問題が出る書き方で、内容や幅などの条件によって崩れるものも含みます。「規約との差」は、いまの表示は正しいものの、本書の規約や設計の判断と異なる書き方です。次の物理プロパティの例は後者で、横書きのページでは正しく表示されます。本書では、書字方向が変わっても同じ意味になるように論理プロパティにそろえているので、避ける例にしています。

```css title="🙅‍♂ Not Recommended: 物理プロパティで書く" issue="convention"
/* 🙅‍♂ Not Recommended */
._card {
  padding-top: 16px;
}
```

```css title="🙆‍♂ Recommended: 論理プロパティで書く"
._card {
  padding-block-start: 16px;
}
```

`🙆‍♂ Recommended` には、タイトルの後ろに、そのコードをどの単位で使えるかを添えています。

| 表示 | 意味 |
|---|---|
| 抜粋 | 説明している宣言と、それが働くのに要る宣言だけを残したもの。そのまま貼り付けても、部品の全体にはならない |
| 差分 | 前の状態から変えた箇所だけを示したもの。第21章の各節の後半と、手を動かす課題の答えで使う |
| 完成例 | そのファイルだけで動くもの（トークンなど、本文で示した前提を除く） |

抜粋と差分には、全体のあるファイルを「全体：デモ『…』」や「全体：配布ファイル …」のように添えています。デモを示しているときは、そのデモのCSSに、省いた宣言を含む全体があります。紙の書籍では、デモの番号（デモ6-3-2など）で示します。デモの下のタブに出すCSSは、デモの全体なので「完成例」です。

`🙆‍♂ Recommended` のCSSは、本書のStylelintの設定ですべて検証しています。ただし、Stylelintが確かめるのは記法と規約の一部で、表示や操作が正しいかまでは確かめません。表示と操作は、「[19-3 表示と操作を確かめる](/operations/verification/)」の手順に沿ってブラウザで確かめます。ラベルのないコード例は、勧めるかどうかを示すためではなく、仕組みや計算式を示すための例です。完全なCSSのものも、一部だけを抜き出したものもあります。

`🙆‍♂ Recommended` のCSSは、その節の主題に限らず、本書のすべての必須と禁止のルールに合うように書いています。ほかの章のルールに関わる記述を省いたときは、本文でそのことを断ります。

デモのCSSにも同じルールを当てていますが、ファイルの先頭の説明ブロック（「[9-10 コメントの書き方](/notation/comments/#ファイル先頭の説明ブロック)」）だけは、公開プロパティのないファイルでは省いています。そのデモが何のためのものかは、デモの直前と直後の本文で説明しているからです。公開プロパティを持つファイルには、`@prop` を書いた説明ブロックを付けています。第21章の演習のデモと配布ファイルには、すべて説明ブロックを付けています。

本文のコード例では、説明に関係しない記述を省略しています。とくにカスケードレイヤー（`@layer`）の記述は、ほとんどのコード例で省略しています。省略した箇所は `/* ... */` と書いています。クラス名が `._main-link` のように `_` で始まっている場合は、`@scope` の中に書く子要素のクラスです。命名の規則は「[9-1 命名規則](/notation/naming/)」で説明します。

省略した記述をそろえた全体の形は、「[最小の構成で始める](/introduction/quick-start/)」に1枚のカードを例にして示しています。その構成で定義しているトークンは、そのカードに必要な最小限のものだけです。本文のコード例を手元で試すときは、その構成のコンポーネントのファイルに貼り付け、コード例が参照するトークンを足してください。色や余白、イージングと再生時間のトークンは「[10-4 デザイントークン](/components/design-tokens/)」で定義しています。

トークンを足さずに貼り付けると、コード例が動かないように見えることがあります。たとえば `color: var(--foreground--muted);` だけを貼り付けると、`--foreground--muted` がどこにも定義されていないので、`var()` の参照が無効になります。このとき `color` はエラーにならず、親から継承した色のまま表示されます。説明している機能が動かないときは、まず参照しているトークンが定義されているかを確かめてください。

## デモの使い方

多くの節には、コードをその場で表示するデモがあります。デモは、ページとは切り離された枠（iframe）の中で表示しているので、デモのCSSがページに影響することはありません。枠の幅がそのままデモの画面幅になるので、メディアクエリも実際の画面と同じように動きます。

本文は、デモを操作しなくても結論が分かるように書いています。表示が幅で変わるデモについては、「幅を320pxにすると」「768pxのときは」のように、どの幅で何が変わるかを本文に書いています。操作で状態が変わるデモについては、何をすると、どこがどう変わるかを書いています。

Webでは、デモの上にあるボタンやスライダーで表示の幅を変えられます。本文の幅より広い値を選ぶと、デモを横にスクロールして確認できます。デモの下のタブでは、表示に使っているCSSとHTMLの全体を確認できます。

紙の書籍では、一部のデモを静止図で示し、ほかのデモは番号と補足サイトへの参照だけを載せます。静止図には撮った幅（320pxなど）を添えているので、本文の「幅を320pxにすると」は、その幅の図と対応します。紙面にない幅や、押す・動かすといった操作による変化は、[補足サイト](/book-support/index.html)からたどれるWeb版のデモで確かめてください。デモのCSSとHTMLの全体は、補足サイトのサンプル一式にも入っています。

デモには、特に断りがない限り、本書が勧めるリセットCSS（kiso.css）とカスケードレイヤーの順序の宣言を読み込んでいます。ブラウザのデフォルトスタイルそのものを見せるデモでは、これらを読み込んでいません。

## ブラウザの対応状況の表示

新しい機能を紹介する箇所には、ブラウザの対応状況を示す枠を置いています。表示は、Web標準の対応データ（web-features）の「Baseline」という指標にもとづいています。「広く利用可能」はすべての主要なブラウザで長く使えている機能、「新しく利用可能」は最近すべての主要なブラウザで使えるようになった機能、「一部のブラウザのみ」はまだ一部のブラウザでしか使えない機能です。

枠には、データのバージョンと確認した年月を書いています。本書が対象にしているブラウザ（Safariは現行から2つ前のメジャーバージョンの最終版以降、ほかの主要なブラウザは最新版）と、機能ごとの使い方の判断は、「[1-2 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」で説明します。

| 種類 | 名前と版 |

挙動を試したブラウザは、本文に名前を書いています。1つのブラウザでしか試していないことが結論に関わる箇所と、確かめた時期がこれと異なる箇所は、本文でそのことを断っています。第20章と付録JのAIツールの機能、デフォルト値、制限も、2026年10月の時点のものです。ブラウザとツールは更新されるので、採用を決める前に、最新の対応状況と仕様を確かめてください。

## AIで使う

本書のルールは、AIのコーディングエージェントにも読ませられる形で配布します。スキルとMCPサーバーは提供に向けて準備中で、提供の状況とツールごとの設定方法は付録J「[AIツールで使う](/appendix/ai-tools/#提供の状況)」に、読ませたうえで生成されたコードを確かめる手順は「[20-8 生成したコードを確かめ、教訓を残す](/ai-coding/verify-output/)」にあります。
