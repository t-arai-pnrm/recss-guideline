本書の書き方を手元で試すには、HTML、エントリーポイントのCSS、kiso.css、トークン、コンポーネントの5種類のファイルがあれば足ります。このページの前半では、この構成でお知らせのカードを表示し、見出しの色を1つ変えるところまでを試します。

構成には、カスケードレイヤー、トークンの階層、公開プロパティと内部プロパティ、本書独自の命名といった設計の要素が含まれています。課題では、それぞれの役割を一言で示すだけにとどめ、仕組みは本編で順に説明します。課題に出てくる名前の意味は、後半の「[命名の早見表](#命名の早見表)」で引けます。

## 課題1：お知らせのカードを表示する

本書と同じ版のファイルは、[補足サイトのサンプル一式](/book-support/index.html)から取得できます。ZIPを展開し、`quick-start/index.html` をブラウザで開きます。kiso.cssも含まれているので、別に取得する必要はありません。

自分でファイルを作る場合は、次のように置きます。kiso.cssは、kiso.cssの[GitHubのリポジトリ](https://github.com/tak-dcxi/kiso.css)から取得します。手元の表示を本書とそろえたい場合は、サンプルに記録した版を使ってください。

```text title="ファイルの配置"
index.html
css/
├── style.css           … エントリーポイント
├── kiso.css            … リセットCSS
├── tokens/
│   ├── colors.css      … 色のトークン
│   └── sizes.css       … 余白と角丸のトークン
└── components/
    └── news-card.css   … コンポーネント
```

HTMLは、エントリーポイントの `style.css` だけを読み込みます。カードのルートの要素には `class="scoped news-card"` を付けます。これがコンポーネントの目印です。

```html title="index.html"
<!doctype html>
<html lang="ja">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>最小の構成</title>
    <link rel="stylesheet" href="css/style.css">
  </head>
  <body>
    <article class="scoped news-card">
      <h2>サイトを公開しました</h2>
      <time datetime="2026-10-01">2026年10月1日</time>
      <p>最初のお知らせです。</p>
    </article>
  </body>
</html>
```

エントリーポイントには、レイヤーの順番の宣言と、各ファイルの読み込みだけを書きます。

```css title="🙆‍♂ Recommended: css/style.css でレイヤーの順番を宣言し、各ファイルを割り当てる" use="complete"
/**
 * サイト全体のスタイルの入り口。
 * レイヤーの順番を宣言し、各ファイルをレイヤーに割り当てる。
 */
@layer tokens, reset, base, vendors, compositions, pages, components, patterns, utilities;

@import url("kiso.css") layer(reset);
@import url("./tokens/colors.css") layer(tokens);
@import url("./tokens/sizes.css") layer(tokens);
@import url("./components/news-card.css") layer(components);
```

トークンのファイルには、サイト全体で使う色と余白の値を書きます。

```css title="🙆‍♂ Recommended: css/tokens/colors.css にプリミティブとセマンティクスの色を定義する" use="complete"
/**
 * 色のトークン。
 * プリミティブの色と、役割を表すセマンティクスの色を定義する。
 */
:root {
  --color--neutral--100: oklch(97% 0 0deg);
  --color--neutral--600: oklch(43.9% 0 0deg);
  --color--neutral--900: oklch(20.5% 0 0deg);
  --background--surface: var(--color--neutral--100);
  --foreground--base: var(--color--neutral--900);
  --foreground--muted: var(--color--neutral--600);
}
```

```css title="🙆‍♂ Recommended: css/tokens/sizes.css に余白を単位なしの数値で定義する" use="complete"
/**
 * 余白と角丸のトークン。
 * 余白はピクセル相当の数値で定義し、使う場所で単位に変換する。
 */
:root {
  --spacing--xxs: 8;
  --spacing--md: 24;
  --rounded--md: 8px;
}
```

コンポーネントのファイルには、カード1つ分のスタイルを書きます。

```css title="🙆‍♂ Recommended: css/components/news-card.css で、カード1つ分を @scope に閉じ込める" use="complete"
/**
 * お知らせのカード。
 * 一覧としての並べ方は、置く側のレイアウトが受け持つ。
 *
 * @prop {color} --news-card--accent [var(--foreground--base)] - 見出しの色
 *
 * @example
 * <article class="scoped news-card" style="--news-card--accent: oklch(50% 0.17 30deg)">
 *   ...
 * </article>
 */

@scope (.scoped.news-card) to (.scoped) {
  :scope {
    --_accent: var(--news-card--accent, var(--foreground--base));

    display: block grid;
    gap: calc(var(--spacing--xxs) * 1px);
    padding: calc(var(--spacing--md) * 1px);
    border-radius: var(--rounded--md);
    background-color: var(--background--surface);
  }

  h2 {
    color: var(--_accent);
    font-size: calc(20 / 16 * 1rem);
  }

  time {
    color: var(--foreground--muted);
  }
}
```

`index.html` をブラウザで開くと、淡い灰色の背景のカードに、濃い色の見出し、灰色の日付、本文が表示されます。背景色や見出しの色が付かないときは、開発者ツールのネットワークのパネルで、CSSのファイルがすべて読み込まれているかを確かめてください。

## 課題2：見出しの色を1つ変える

カードの見出しの色は、使う側から変えられるようにしてあります。`index.html` のカードの `article` 要素に、`style="--news-card--accent: oklch(50% 0.17 30deg)"` のように属性を足すと、そのカードの見出しだけが赤みのある色に変わります。コンポーネントのCSSは書き換えません。

次のデモは、この構成と同じCSSで、カードを2枚並べたものです。2枚目のカードにだけ、`style` 属性で `--news-card--accent` に値を渡しています。1枚目の見出しはトークンの文字色、2枚目の見出しは渡した赤みのある色で表示されます。

<Demo title="最小の構成で表示したお知らせのカード" html={quickStartHtml} css={quickStartCss} widths={[]} scheme="light" />

`--news-card--accent` は、このカードが外から値を受け取るために用意した公開プロパティです。値を渡さなかった1枚目は、コンポーネントに書いたデフォルトの色を使います。公開プロパティを用意した値だけを外から変え、それ以外の見た目はコンポーネントの中で決めるのが、本書の部品の作り方です（「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」）。

## 実装を終えたら確かめること

カードが表示できたら、表示が崩れない条件も確かめます。ブラウザの既定の文字サイズを200%（16pxから32px）にして、見出しと本文が欠けたり重なったりしないかを見ます。次に、ウィンドウの幅を320pxまで狭め、カードが横にはみ出さないかを見ます。最後に、見出しを3行に折り返すほど長い文に書き換え、カードの高さが内容に合わせて伸びるかを見ます。

どれも、カードの高さや幅を固定せず、文字の大きさをremで指定していれば、CSSを書き足さずに通ります。条件の再現のしかた（文字サイズを200%にする方法を含む）と、ほかに確かめる条件は「[19-3 表示と操作を確かめる](/operations/verification/)」で説明しています。第14章から第18章の概要にも、その章の実装を終えたときに確かめることを置いています。

ここまでで、本書の構成を手元で動かせました。このカードは第4・10・13・19章の概要にある「手を動かす課題」で続けて直すので、ファイルを残しておいてください。次は、第1章「[CSSのマインドセット](/principles/)」から読み始めます。このページの残りの見出しでは、この構成を実務の配信へ移す方法、構成の各部分の読み方、kiso.cssを読み込むほかの方法、命名の早見表を扱います。

## 実務の配信へ移す

学習用の構成を配信するときは、`@import` をビルド時に展開します。サンプルの `practical/` は、同じカードをViteでビルドする構成です。Node.js 22.12以降の環境で、このディレクトリに移動して次のコマンドを実行します。依存するViteの版は `package.json` に固定しています。

```sh title="実務用サンプルをビルドして確認する"
npm install
npm run build
npm run preview
```

`dist/index.html` と `dist/assets/` のCSSが配信用のファイルです。プレビューのURLを開き、学習用と同じカードが表示されることを確かめます。出力のCSSに `@import` が残らず、読み込んだファイルがレイヤーに入る仕組みは、「[4-3 カスケードレイヤーで順位を決める](/cascade/layers/)」で説明します。

## この構成の読み方

エントリーポイントの先頭の `@layer` 文は、9つのレイヤーの順番を決めています。その後ろの `@import` は、各ファイルを `layer()` で指定したレイヤーに割り当てます。レイヤーの順番は先頭の `@layer` 文で決まるので、`@import` を並べる順番には左右されません（「[4-3 カスケードレイヤーで順位を決める](/cascade/layers/)」）。`css` ディレクトリの中は、このレイヤーの分類に合わせてディレクトリを分けています。

コンポーネントのファイルには `@layer components { … }` を書いていません。エントリーポイントの `@import` に `layer(components)` を付けているので、ファイルの中身がすべて `components` レイヤーに入ります。`<head>` の中の `<style>` のように、`@import` で読み込まないCSSでは、`@layer` を自分で書きます。

トークンの色は、プリミティブ（`--color--…`）と、役割を表すセマンティクス（`--foreground--…` など）の2層にしています。余白のトークンは単位を付けずに定義し、使う場所で単位に変換します（「[10-4 デザイントークン](/components/design-tokens/)」）。

コンポーネントのスタイルは、`@scope (.scoped.<名前>) to (.scoped)` の中に書きます。子要素は `h2` や `time` のようなタイプセレクタで選ぶので、クラスを付けていません。`_` で始まる子クラスを付けるのは、同じ種類の要素を役割で区別するときと、`div` と `span` に役割を示すときだけです（「[10-2 コンポーネントの境界を守る](/components/boundaries/)」）。外から変えてよい見出しの色は、公開プロパティ `--news-card--accent` として受け取り、`:scope` で内部プロパティ `--_accent` に受けます。渡されなかったときのデフォルト値は、`var()` のフォールバックに書いています（「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」）。

デモのCSSは、本文のコード例と違い、省略のない全体です。トークンを `@layer tokens { … }` で、コンポーネントを `@layer components { … }` で包み、1つのファイルにまとめています。カードを並べるための余白は、置く側の `demo-layout` のスコープに書いています。デモの枠には、レイヤーの順番の宣言と、`reset` レイヤーに入れたkiso.cssを読み込んでいるので、デモのCSSにはエントリーポイントにあたる記述がありません。

この構成は、ビルドツールを用意せずに本書の書き方を試すための学習用です。エントリーポイントの `@import` をブラウザがそのまま読むので、各ファイルの読み込みが直列になり、最初の表示が遅れます。実務では、同じファイル構成のまま、ビルドツールで `@import` を展開して1つのCSSにしてから配信します。本書のルールの `import-resolved-at-build` も、この展開を求めています。学習や検証のため、ビルドせずに試す場合だけを例外にしています（「[4-3 カスケードレイヤーで順位を決める](/cascade/layers/#rule-import-resolved-at-build)」）。

## kiso.cssを読み込むほかの方法

本文では `@import url("kiso.css") layer(reset);` と書いていますが、ブラウザはこの `kiso.css` を、書いたCSSファイルと同じ場所にあるファイルのURLとして読みます。課題1でファイルを `style.css` の隣に置いたのは、そのためです。npmでパッケージをインストールしただけでは、`node_modules` の中のファイルは読まれません。

ファイルを置かずに、CDNのURLを直接書く方法もあります。kiso.cssのREADMEは、jsDelivrで配信しているファイルのURLを案内しています。URLにバージョンを書いておけば、kiso.cssが更新されても、知らないうちに見た目が変わることはありません。

```css title="🙆‍♂ Recommended: CDNのURLから reset レイヤーに読み込む"
@layer tokens, reset, base, vendors, compositions, pages, components, patterns, utilities;

@import url("https://cdn.jsdelivr.net/npm/kiso.css@1.2.4/kiso.css") layer(reset);
```

npmでインストールする場合（`npm install kiso.css`）は、CSSの `@import` でパッケージ名を解決するビルドツールが必要です。Viteは、CSSの `@import` を `postcss-import` で展開し、その過程で `node_modules` の中のパッケージも探します。{/* 要確認: 出典なし。Vite と postcss-import の解決順（相対パスを先に探す）を公式ドキュメントで確認する */} この場合は、エントリーポイントの `@import url("kiso.css") layer(reset);` が、パッケージに含まれる `kiso.css` を指します。

同じ `@import url("kiso.css")` でも、ブラウザが直接読むときは隣にあるファイルを、ビルドツールが処理するときはパッケージを指します。手元で試すときに `kiso.css` が読み込まれていないようなら、開発者ツールのネットワークのパネルで、どのURLを読みにいったのかを確かめてください。

## 命名の早見表

本書のコード例には、CSSの構文ではなく、本書の規約で決めている名前が多く出てきます。どれも先頭の記号で種類を見分けられるようにしています。接頭辞のないコンポジションとパターンは、配置の名前か役割の名前かで見分けます。各行の詳しい説明は、右の列のページにあります。

| 記法 | 例 | 意味 | 詳しい節 |
|---|---|---|---|
| `scoped <名前>` | `class="scoped news-card"` | コンポーネントのルート。`scoped` は、外側のスコープの下限にもなる | [9-4](/notation/scope-and-nesting/)、[9-1](/notation/naming/) |
| `scoped page-<スラッグ>` | `class="scoped page-about"` | ページ固有のスタイルのルート | [9-4](/notation/scope-and-nesting/) |
| `._<名前>` | `._main-link`、`._sub-link` | コンポーネントの子要素のうち、同じ種類の要素を役割で区別するものと、`div` と `span` の役割を示すもの。スコープの中だけで意味を持つ | [9-1](/notation/naming/)、[10-2](/components/boundaries/) |
| `.-<名前>` | `.-visually-hidden`、`.-fluid-text--md` | ユーティリティ。段階や種類は `--` で続ける | [9-1](/notation/naming/)、[10-3](/components/compositions-and-utilities/) |
| 接頭辞なし（配置の名前） | `.cluster`、`.switcher` | コンポジション（配置のパターン） | [9-1](/notation/naming/)、[10-3](/components/compositions-and-utilities/) |
| 接頭辞なし（役割の名前） | `.section-heading`、`.icon` | パターン（静的な見た目の断片）。コンポーネントが変える値は `--<パターン>--<プロパティ>` で受け取る | [9-1](/notation/naming/)、[10-3](/components/compositions-and-utilities/) |
| `--<分類>--<名前>` | `--color--neutral--600`、`--spacing--md` | デザイントークン | [10-4](/components/design-tokens/) |
| `--<役割>--<バリエーション>` | `--foreground--muted` | 役割を表す色のトークン | [10-4](/components/design-tokens/) |
| `--<コンポーネント>--<プロパティ>` | `--news-card--accent` | 公開プロパティ。外から値を渡してよい | [10-5](/components/custom-properties/) |
| `--_<名前>` | `--_accent` | 内部プロパティ。コンポーネントの中だけで使う | [10-5](/components/custom-properties/) |
| `--_<名前>--<状態>` | `--_background--hocus` | 状態やモードごとの値 | [10-5](/components/custom-properties/) |
| `--<名前>`（値として使う名前） | `@keyframes --fade-in` | 自分で付けて値として使う名前 | [9-1](/notation/naming/) |
| `data-variant` | `data-variant="featured"` | コンポーネントのバリエーション | [9-2](/notation/variants/) |
| 擬似クラス、ARIA属性 | `:checked`、`[aria-selected="true"]` | 状態。`.is-active` のような状態クラスは使わない | [17-3](/interaction/state-attributes/) |
| 9つのレイヤー名 | `tokens`、`components` | レイヤー名。値として使わないので `--` を付けない | [4-3](/cascade/layers/) |

内部プロパティの `--_` には、種類ごとの接頭辞もあります。コンポジションは `--_c--`、パターンは `--_p--`、ユーティリティは `--_u--`、ベーススタイルは `--_b--` で始めます。コンポーネントの内部プロパティと名前がぶつからないようにするためです。
