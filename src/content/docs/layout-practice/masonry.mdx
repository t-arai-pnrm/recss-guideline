高さの違う項目を、新着順のような横方向の順番を保ったまま隙間なく詰めるレイアウトは、`display: block grid-lanes` で書きます。Pinterestの一覧のような、いわゆるMasonry（石積み）のレイアウトです。Gridを拡張した仕様なので、列は `grid-template-columns` でそのまま指定できます。対応しているのはSafari 26.4以降だけなので、外側に通常のGridを書き、`@supports (display: block grid-lanes)` の中で切り替えます。

項目は、そのときいちばん短い列へ順に詰められます。見た目の順番は、おおむね左上から右下へ進みますが、HTMLの順番と完全には一致しません。上から下へ読む順番のリストを段に分けたいだけなら、`grid-lanes` ではなく、古くからある `columns` を使います。

## 高さの違う項目を並べたときの隙間

記事の一覧を、本文の長さが違うカードのまま並べる場面を考えます。通常のGridでは、同じ行のカードは行の高さを共有します。行の高さは、その行でいちばん高いカードに合わせて決まるので、短いカードの下には隙間ができます。カードの枠を行の高さまで伸ばせば隙間は見えなくなりますが、本文の下に空白が残ることに変わりはありません。

これまで、隙間を詰めるには2つの方法がありました。1つは `columns` による段組みです。段組みは、項目を1段目の上から下へ流し、段の下端に達したら2段目へ移ります。隙間は詰まりますが、並び順が縦になるので、新着順の一覧では、最新の記事が1段目の上から順に並び、2段目の先頭には中ほどの記事が来ます。

```css title="🙅‍♂ Not Recommended: 新着順の一覧を columns で詰め、順番を縦に流す" issue="behavior"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.post-list) to (.scoped) {
  :scope {
    columns: calc(240 / 16 * 1rem);

    & > li {
      break-inside: avoid;
    }
  }
}
```

もう1つは、JavaScriptのライブラリで各項目の位置を計算し、絶対配置で並べる方法です。横方向の順番は保てますが、画像の読み込みや幅の変化のたびに位置を計算し直す必要があり、計算が終わるまでは配置が定まりません。{/* 要確認: 出典なし */}レイアウトのためだけにスクリプトを読み込み、その実行を待つことになります。

`display: block grid-lanes` は、この配置をCSSだけで行います。Safari Technology Previewで試したとき、私はGridに慣れていれば簡単に使えると感じました。Gridを拡張した仕様だからです。列の指定、`gap`、項目の `grid-column` が、Gridのまま使えます。

## `display: block grid-lanes` の書き方

`grid-lanes` のコンテナでは、Gridと同じように `grid-template-columns` で列（仕様の用語ではレーン）を決めます。項目は、HTMLの順番に1つずつ、そのときいちばん短い列の下端へ置かれます。行のトラックはなく、各列の項目は上の項目のすぐ下に、`gap` の分だけ空けて積まれます。

```css title="🙆‍♂ Recommended: 外側に Grid を書き、対応している環境だけ grid-lanes にする"
@scope (.scoped.post-list) to (.scoped) {
  :scope {
    display: block grid;
    grid-template-columns: repeat(auto-fill, minmax(min(100%, calc(240 / 16 * 1rem)), 1fr));
    gap: 24px 16px;

    @supports (display: block grid-lanes) {
      display: block grid-lanes;
    }
  }
}
```

列の決め方は、通常のGridの一覧と同じです。`repeat(auto-fill, minmax(…))` で、使える幅に応じて列の数を変えています。`min(100%, …)` は、コンテナが最小幅より狭いときに1列がはみ出さないようにする指定です。`grid-template-columns` の代わりに `grid-template-rows` を指定すると、項目が横へ積まれるレンガ積みの向きになりますが、Webサイトの一覧で使う場面はほとんどありません。

`display` は、ほかの値と同じく2値構文で `block grid-lanes` と書きます。外側の表示形式が `block`、内側の表示形式が `grid-lanes` という組み合わせで、インラインに置くなら `inline grid-lanes` です。1語の `grid-lanes` と `inline-grid-lanes` も同じ意味の値ですが、本書の `display` の書き方（`display-two-value-syntax`）にそろえ、2値で書きます。

複数の列にまたがる項目も、Gridと同じく `grid-column: span 2` で作れます。`grid-column: -3 / -1` のような線の番号による配置も使えます。ただし、この2つは、後で説明する並び順の食い違いを起こしやすい指定です。

## `flow-tolerance` で配置の感度を決める

いちばん短い列を厳密に選ぶと、1pxしか違わない列のどちらに置くかで、項目が左右へ大きく飛ぶことがあります。見た目にはほぼ同じ高さなのに、2番目の項目が右端の列へ置かれるといった配置です。`flow-tolerance` は、列の高さの差がどこまでなら「同じ高さ」とみなすかを決めるプロパティです。同じ高さとみなした列が複数あれば、直前の項目を置いた列より後ろ（横書きなら右側）で最初の列が選ばれ、後ろになければ先頭の列に戻ります。

```css title="🙆‍♂ Recommended: 高さの差が 3em までの列は同じ高さとみなす"
@scope (.scoped.post-list) to (.scoped) {
  :scope {
    display: block grid;
    grid-template-columns: repeat(auto-fill, minmax(min(100%, calc(240 / 16 * 1rem)), 1fr));
    gap: 24px 16px;

    @supports (display: block grid-lanes) {
      display: block grid-lanes;
      flow-tolerance: 3em;
    }
  }
}
```

初期値の `normal` は `1em` として扱われます。値を大きくすると、項目は多少の高さの差を無視して、前の項目の隣の列へ順に置かれやすくなり、並び順は読みやすくなる代わりに、列の下端のそろい方は粗くなります。値を小さくすると、その逆になります。

`infinite` を指定すると、列の高さを一切見ずに、項目を1列ずつ順に置きます。仕様は、この値では隣り合う項目が縦に大きく離れた位置へ置かれ、読み手が混乱しうると注記し、`1em` では小さすぎる場合も `infinite` ではなく大きめの長さを指定するよう勧めています。そのため、まず初期値で並べ、項目が左右へ飛んで見えるときだけ値を大きくします。

`flow-tolerance` は `grid-lanes` のコンテナだけに適用されるプロパティです。未対応の環境では無視されるので、`@supports` で囲む必要はありませんが、`grid-lanes` の指定と一緒に消せるように同じブロックに書いています。

## 未対応の環境では通常のGridになる

`display: block grid-lanes` に対応していない環境では、この宣言が無効になります。外側に `display: block grid` を書いておけば、項目は通常のGridとして、行ごとに高さがそろった状態で並びます。隙間は残りますが、すべての項目が読めて操作でき、並び順も左上から右下へ進むので、プログレッシブ・エンハンスメントとして使える機能です。

次のデモは、本文の長さが違う8つの項目を、最初のコード例と同じ書き方で並べたものです。番号はHTMLに書いた順番です。`grid-lanes` に対応したSafariで見ると、項目が短い列へ詰められます。対応していないブラウザでは、行ごとに高さのそろった通常のGridとして表示されます。

<Demo title="対応している環境では項目を短い列へ詰め、未対応の環境では通常のGridで並べる" html={masonryHtml} css={masonryCss} />

対応していない環境では、短い項目の下に、同じ行でいちばん長い項目に合わせた隙間ができます。対応している環境では、この隙間に次の項目が入り、列ごとの下端の差も小さくなります。どちらの環境でも、項目の内容と、おおよその左から右への順番は変わりません。

フォールバックの書き方は2つあります。1つは最初のコード例のように、`@supports (display: block grid-lanes)` の中で切り替える方法です。もう1つは、同じルールに `display` を2つ並べ、未対応の環境では後の宣言が無効になることを利用する方法です。

```css title="🙅‍♂ Not Recommended: display を2つ並べ、誤記に見えるフォールバックにする" issue="convention"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.post-list) to (.scoped) {
  :scope {
    display: block grid;
    display: block grid-lanes;
    grid-template-columns: repeat(auto-fill, minmax(min(100%, calc(240 / 16 * 1rem)), 1fr));
    gap: 24px 16px;
  }
}
```

どちらも結果は同じですが、本書は `@supports` を選びます。宣言を2つ並べる書き方では、フォールバックの意図がコードに書かれていません。`display` を2つ並べても、どちらが未対応の環境のための値かはコードから読めず、誤記に見えるので、人やAIが整理するときに、どちらかを消してしまうおそれがあります。`@supports` なら条件が書かれているので、すべての対象のブラウザが対応した時点で、`@supports (display: block grid-lanes)` を検索して分岐を消せます。

もう1つの理由は、`grid-lanes` に合わせてほかの宣言も変えたい場面があることです。フォールバックの書き方を、宣言が無効になる時点と一緒に変える宣言の有無で選ぶ基準は、「[1-2 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」の「フォールバックの書き方を選ぶ」にまとめています。写真の一覧では、通常のGridのままだと縦長と横長の写真が同じ行に並び、行の高さがばらつきます。フォールバックでは写真を正方形に切り抜いてそろえ、`grid-lanes` の環境では元の縦横比で並べるのが自然です。

```css title="🙆‍♂ Recommended: フォールバックでは写真を正方形にそろえる"
@scope (.scoped.photo-gallery) to (.scoped) {
  :scope {
    display: block grid;
    grid-template-columns: repeat(auto-fill, minmax(min(100%, calc(200 / 16 * 1rem)), 1fr));
    gap: 8px;

    @supports (display: block grid-lanes) {
      display: block grid-lanes;
    }
  }

  img {
    /* stretch に未対応の環境のための値 */
    inline-size: -webkit-fill-available;
    inline-size: stretch;
    aspect-ratio: 1;

    @supports (display: block grid-lanes) {
      aspect-ratio: unset;
    }
  }
}
```

正方形の枠に違う比率の写真が入っても、本書のベーススタイルが画像に指定している `object-fit: cover` によって、写真は引き伸ばされずに切り抜かれます（「[16-1 画像の配置と比率](/decoration/images/)」）。`aspect-ratio: unset` は、フォールバックで指定した `1` を初期値の `auto` に戻し、画像の本来の縦横比で表示する指定です。宣言を2つ並べる書き方では、このように子要素の宣言を切り替えられません。新しい機能に合わせて既存の宣言も変えるときは、その宣言を `@supports` の中に書きます。この考え方は「[1-2 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」で説明しています。

## 並び順と読み上げ・フォーカスの順番

`grid-lanes` では、見た目の順番とHTMLの順番が、ずれることがあります。項目はいちばん短い列へ置かれるので、4番目の項目が3番目より上に表示されることがあるからです。読み上げとキーボードのフォーカスはHTMLの順番で進むので、見た目で追う順番と食い違います。

ずれが大きくなるのは、複数の列にまたがる項目や、線の番号で置いた項目を混ぜたときです。仕様には、次のような例が載っています。3列分にまたがる項目が、1行目に残った1列分の空きに収まらず、その下の位置へ置かれます。後続の1列分の項目は、残っていた空きへ置かれるので、HTMLでは後にあるのに、見た目ではまたがる項目より上に来ます。

そのため、順序に意味のある項目には `grid-lanes` で `span` や線の番号による配置を使いません。ランキングや手順のように順番そのものが内容になる一覧は、`grid-lanes` に向いていません。新着順の一覧のように、おおよその順番が伝われば足りる並びに使います。

仕様は、項目に固有の順番がない場合には、`reading-flow` プロパティで読み上げとフォーカスの順番を見た目に合わせる方法も挙げています。ただし、`reading-flow` に対応しているのはChrome系のブラウザだけで、`grid-lanes` に対応しているのはSafariだけです。両方を同時に使える環境はまだありません。`reading-flow` については「[11-12 表示順と読み上げ順を合わせる](/layout-practice/reading-flow/)」で説明しています。

## `columns` との使い分け

`columns` は、上から下へ読む1つのリストを、複数の段へ分けるときに使います。フッターのリンクの一覧のように、縦に並べたメニューを、幅に応じた数の段へ分けたい場面です。このようなメニューのレスポンシブは、IE10から使える `columns` プロパティで足ります。段組みは並び順が縦なので、HTMLの順番と読む順番がそろいます。

```css title="🙆‍♂ Recommended: 縦に並べたリンクの一覧を、幅に応じて段に分ける"
@scope (.scoped.footer-links) to (.scoped) {
  ul {
    column-gap: 32px;
    columns: calc(200 / 16 * 1rem) 4;

    & > li {
      break-inside: avoid;
    }
  }

  li {
    padding-block: 4px;
  }
}
```

`columns` に幅と数を両方書くと、幅は段の最小幅、数は段の上限になります。コンテナが指定の幅より狭いときは1段になり、段の幅はコンテナに合わせて縮みます。項目には `break-inside: avoid` を指定し、1つの項目が段の境目で分かれないようにします。

`columns` には、Gridの感覚で書くと失敗する点が2つあります。1つ目は、`column-width` に `%` を受け付けないことです。Gridの `minmax(min(100%, …), 1fr)` の癖で `column-width: min(100%, 15rem)` と書くと、値が不正になって宣言ごと無視されます。段の幅をコンテナの幅に比例させたいときは、`%` の代わりに名前付きのコンテナの `cqi` を使います。

2つ目は、段の境目に接する `margin` が切り取られることです。段の境目で分かれた場所に接する `margin` は、断片化の仕様で切り捨てられます。すべての項目に `margin-block-start` を付けると、1段目の先頭にだけ余白が残り、段の上端がそろいません。上のコード例では、項目の間隔を `margin` ではなく `padding-block` で空けています。

一方で、フッターのメニューが「見出しとリンクのまとまり」をいくつも並べたものなら、`grid-lanes` が向いています。数の決まっていないまとまりを、長さが違っても均一に並べられるからです。使い分けの基準は、項目を読む順番です。1つのリストを上から下へ読ませるなら `columns`、見出しとリンクのまとまりやカードを横方向の順番で並べながら高さの違いを詰めるなら `grid-lanes` を選びます。
