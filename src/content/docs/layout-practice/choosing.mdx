要素を並べる手法は、作るものの種類で選びます。見出しと段落が続く文章と、前後の要素の種類や有無で間隔が変わる縦の並びは、何も指定しない通常フローのまま組みます。文章でない部品の配置は、まず親の `grid-template` で子要素の位置と大きさを決められないかを検討し、タグやメニューのように中身の量で幅が決まる並びや、行ごとに並べ方を変える並びにはFlexboxを使います。

`float` は古い手法と見なされがちですが、文章を要素のまわりに回り込ませる配置では、今でもいちばん崩れにくい手法です。画像に文字を回り込ませる場面のほか、モーダルの閉じるボタンや右上の装飾の画像を文章の角に置く場面でも、私は `position: absolute` ではなく `float` を使います（「[11-14 floatで文章を回り込ませる](/layout-practice/float/)」）。

この節で新しく判断するのは、作るものの要件から、通常フロー、Grid、Flexbox、`float` のどれで組むかを選ぶことです。方式ごとにプロパティの意味が変わる仕組みは「[7-1 レイアウトの基礎](/layout/fundamentals/)」で、各方式の規則は7-2〜7-10で説明しています。

## 手法を選ばずに組むと起きること

FlexboxとGridが普及してから、要素を並べるときに、まず `display: flex` を書く人は少なくありません。AIが生成するコードにも同じ傾向があり、配置をFlexboxで組み、それで収まらない要素は `position: absolute` で位置を合わせがちです。どちらも見た目は再現できますが、手法の得意な配置と作るものの性質が合っていないと、内容や幅が変わったときに崩れます。

たとえば、カードを3列の格子状に並べるとき、Flexboxで書くと次のようになります。親で折り返しと間隔を指定し、子要素の幅は「親の幅から間隔の合計を引き、列数で割る」という計算で決めています。

```css title="🙅‍♂ Not Recommended: 格子状の並びを、子要素の幅の計算で作る" issue="convention"
/* 🙅‍♂ Not Recommended */
._card-list {
  display: block flex;
  flex-wrap: wrap;
  gap: 16px;

  & > * {
    flex-basis: calc((100% - 16px * 2) / 3);
  }
}
```

この書き方では、子要素が親の間隔と列数を知っている必要があります。間隔を24pxに変えたら、子要素の計算式も直さなければなりません。レイアウトを決める情報が親と子に分かれているので、どちらか一方だけを直して崩れる、という失敗が起きやすくなります。

位置指定でも、似たことが起きます。モーダルの右上に閉じるボタンを `position: absolute` で置くと、ボタンは通常フローから外れ、文章はボタンのある場所を避けません。広い画面では見出しの右に余白があって重なりませんが、狭い画面では長い見出しがボタンの下に潜り込み、読めなくなります。見出しの `padding-inline-end` でボタンを避けると、今度はボタンの大きさを変えるたびに、見出しの余白も直さなければなりません。

よく「1次元ならFlexbox、2次元ならGrid」と言われますが、この基準では、上のどちらの問題も避けられません。ナビゲーション、本文、サイドバーを横に並べるページの段組みは1次元のレイアウトですが、Gridのほうが簡潔に書けます。文章と閉じるボタンの関係は、そもそも次元の数では説明できません。手法は、配置を何が決めるのか（親の指定か、子の中身の量か、文章の流れか）で選ぶほうが、作るものの性質と食い違わないと私は考えています。

## よくある実装と選ぶ手法

私が手法を選ぶ順番は、次のとおりです。まず、作るものが文章か、間隔が前後の要素で変わる縦の並びかを確かめ、そうなら通常フローのまま組みます。そうでなければ、親の `grid-template` で配置と大きさを決められないかを検討し、子の中身の量で並べたいときと、行ごとに並べ方を変えたいときだけFlexboxに切り替えます。文章の中に要素を置き、文章をそのまわりに流したいときは `float` を使います。

| よくある実装 | 選ぶ手法 | 理由 |
|---|---|---|
| 見出しと段落が続く記事の本文 | 通常フロー | マージンの相殺と `float` の回り込みが働く |
| 前後の要素の種類や有無で間隔が変わる縦の並び | 通常フロー | 要素の関係ごとに書いた `margin` がそのまま働く |
| カードを格子状に並べる一覧 | Grid | 列の数と幅を親で決められる |
| 一部のタイルだけを大きくした一覧 | Grid | アイテムを複数の行と列にまたがらせられる |
| 1行なら中央に、複数行なら左に寄せる一覧 | Grid（Flexboxでも可） | 列の幅と中央寄せを親の指定だけで書ける |
| 並べたカードの中で、見出しやボタンの位置をそろえる | Grid（サブグリッド） | カードの中の行を、親の行にそろえられる（[7-9](/layout/grid-alignment/)） |
| ナビゲーション、本文、サイドバーの段組み | Grid | 各列の幅を親の1行で読める |
| ロゴ、ナビゲーション、ボタンを並べたヘッダー | Grid | 中央の要素をヘッダーの中央に置ける |
| 幅によって画像と本文の配置が変わるカード | Grid | エリアのテンプレートを書き換えるだけで済む |
| 横にスクロールさせるカードの列 | Grid | 縮み方を管理せずに、列の幅で並べられる（[17-8](/interaction/carousel/)） |
| 画像の上に文字を重ねる | Grid | 同じエリアに置くだけで重なる（[11-6](/layout-practice/layering/)） |
| タグの一覧やメニューの並び | Flexbox | 子の幅を決めずに、中身の量で並べて折り返せる |
| 最終行の端数を中央に寄せる格子状の一覧 | Flexbox | `justify-content` が1行ずつ適用される |
| 行ごとに列数の違う一覧（レンガ状） | Flexbox | 子ごとに列数を変えるだけで済む |
| 最後のリンクだけを行末へ寄せるナビゲーション | Flexbox | `auto` の `margin` が余った空間を吸収する |
| 部品の中の要素を同じ間隔で縦に積む | Flexbox | `gap` で間隔をそろえられる |
| 幅が足りなければ縦に積む、固定幅のサイドとメイン | Flexbox | クエリなしで縦に積める（[12-6](/compositions/sidebar/)） |
| 画像に文章を回り込ませる | `float` | 回り込みは `float` にしかできない |
| 文章の角に置く閉じるボタンや装飾の画像 | `float` | 文字が要素の下に隠れない |

## 縦に積む方法を間隔の決まり方で選ぶ

見出し、段落、リスト、図が続く記事の本文は、何も指定しない通常フローのまま組みます。通常フローでは、`float` による回り込みと、隣り合う `margin` の相殺が働きます。本文をFlexboxやGridにして `gap` で間隔を作ると、どちらも働かなくなります。

部品の中身でも、見出しの直後だけを詰める並びや、CMSの入力によってリード文が出力されない並びのように、前後の要素の種類や有無で間隔が変わるなら、通常フローのまま組みます。`gap` はすべての間に同じ値を空けるので、条件で変わる間隔を作るには子の `margin` を足したり打ち消したりすることになり、その `margin` は相殺されずに `gap` へ足されるからです。

一方、カードの中の番号、見出し、説明文、リンクのように、構成が決まっていて間隔を一律にしてよい部品の中身は、Flexboxで縦に積み、`gap` で間隔をそろえます。ただし、`gap` も配置の指定も書かずに `display: block flex` と `flex-direction: column` だけを書くと、通常フローで積んだときとほぼ同じ並びになり、マージンの相殺が止まるといった違いが増えるだけです。Flexboxに切り替えるときは、切り替えて何を得るのかを説明できるようにしておきます。

縦に積む方法は、間隔の決まり方で選びます。次の表の上から順に当てはまるかを確かめ、最初に当てはまった行の方法を使います。第12章の `stack` と `prose`、11-2の空のグリッドセル、第19章の `.wysiwyg` は、それぞれこの表の1行を受け持ちます。

| 間隔の決まり方 | 選ぶ方法 | 要素が欠けたとき | 場面の例 |
| --- | --- | --- | --- |
| CMSで編集者が入力する本文エリアの中 | `.wysiwyg` で、要素の種類ごとのセレクタに余白を書く（「[19-5 CMSのWYSIWYG本文にスタイルを当てる](/operations/wysiwyg/)」） | 残った要素の間にだけ空く | WYSIWYGで入力した記事の本文 |
| すべての間で同じ | `stack`（親の `gap`。「[12-1 stack](/compositions/stack/)」） | 残った要素の間にだけ空く | カードの中身、フォームの項目、お知らせの一覧 |
| 要素の種類と順番が決まっていて、間ごとに違う | 空のグリッドセル（`grid-template` の行。「[11-2 余白を設計する](/layout-practice/spacing/)」） | 余白の行だけが残る | 見出し、本文、ボタンの構成が決まったセクション |
| 前後の要素の種類や有無で変わる | 通常フローのまま、次兄弟結合子で選んだ子の `margin-block-start`。自分でHTMLを書く本文なら `prose`（「[12-2 prose](/compositions/prose/)」） | 残った要素の間にだけ空く | 自分で書く記事の本文、リード文が出ないことのあるカードの本文 |

迷いやすいのは、3行目と4行目です。空のセルは、余白の指定を1か所にまとめられる一方で、要素が欠けると余白の行だけが残ります。要素の有無が入力で変わるなら、4行目の通常フローを選びます。本文に回り込みの画像を置くときも、`float` が働くのは通常フローだけなので、4行目になります。4行目のセレクタの書き方と、本文をFlexboxで組んだときに起きることは、「[11-2 余白を設計する](/layout-practice/spacing/)」で説明しています。

## 配置を親で決めるならGrid

文章でない部品の配置は、まず親の `grid-template` で決められないかを検討します。Gridなら、列や行の数と大きさを親の指定だけで決められ、子要素の側に幅の計算や個別の指定を書かずに済みます。先ほどのカードの一覧も、ページの段組みも、親の指定だけで書けます。

```css title="🙆‍♂ Recommended: 列の数と幅を親で決める"
._card-list {
  display: block grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}

._page {
  display: block grid;
  grid-template-columns: calc(240 / 16 * 1rem) 1fr calc(320 / 16 * 1rem);
}
```

`grid-template-columns` を読めば、何列でどういう幅なのかが1行で分かります。子要素の側には、配置のための指定が何もありません。同じ段組みをFlexboxで書くと、両端の子には `flex-shrink: 0` と `flex-basis` を、真ん中の子には `flex-grow: 1` を指定することになり、3つの子のCSSを読み合わせないと全体の形が分かりません。

カードの一覧のような等分の列も、`flex: 1` では子の `padding` や `border` の違いで幅がずれるので、確実にそろえたいならGridで列を決めます（「[7-7 Flexboxの基礎](/layout/flexbox-basics/)」）。列の幅を `minmax(0, 1fr)` ではなく `1fr` と書いている理由は、「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/)」で説明しています。

Gridの利点が大きいもう1つの例は、ロゴ、ナビゲーション、ボタンを左端、中央、右端に置くヘッダーです。`grid-template-columns: 1fr auto 1fr` と書くと、左右の列が同じ幅になるので、中央の列はヘッダーのちょうど真ん中に置かれます。ただし、本書のベーススタイルはアイテムの最小幅を0にしているので（「[8-2 ベーススタイルに書くもの](/reset/base-styles/#rule-global-min-inline-size-zero)」）、`1fr` の列も0まで縮みます。中央のリンクが増えると、左右の列はロゴやボタンの文字が折り返されるところを越えて縮み、折り返せない中身は列からはみ出します。ベーススタイルがない環境では、`1fr` の列の最小幅は中身の最小幅（`min-content`）になり、文字が折り返されるところで止まります。左右の列の最小値を `max-content` にすれば、列の下限がアイテムの最小幅ではなく中身の幅で決まるので、中身は折り返されず、列も中身の幅より狭くなりません。

```css title="🙆‍♂ Recommended: 左右の列が中身より狭くならないようにする"
._header {
  display: block grid;
  grid-template-columns: minmax(max-content, 1fr) auto minmax(max-content, 1fr);

  & > :last-child {
    justify-self: end;
  }
}
```

左右が均等になるのは、ヘッダーの幅が「中央の列の幅＋左右の中身の大きいほうの幅×2」以上のときです。それより狭いと、大きいほうの列は中身の幅で固定され、残りが小さいほうの列に回るので、中央の列は小さいほうへずれます。3つの中身の合計より狭い画面でははみ出すので、狭い画面では別の配置に切り替える前提の書き方です。同じ配置をFlexboxの `justify-content: space-between` で書くと、左右の中身の幅が違うだけで、中央の要素が真ん中からずれます。

幅によって画像と本文の配置が変わるカードも、Gridで組みます。エリアに名前を付けたテンプレートを条件ごとに書き換えれば、子要素の配置の指定は1か所ずつで済みます。エリアの書き方は「[7-8 Gridの基礎](/layout/grid-basics/)」で、並べたカードの中の見出しやボタンの位置をサブグリッドでそろえる方法は「[7-9 Gridでアイテムをそろえる](/layout/grid-alignment/)」で説明しています。

一部のタイルだけを大きくする一覧も、Gridで組みます。4列の格子で、`:nth-child(5n + 1)` の子に `grid-area: span 2 / span 2` を指定すれば、5枚に1枚が2行2列にまたがり、ほかのタイルは空いたセルに順に入ります。Flexboxでは、1つのアイテムが複数の行にまたがれません。

1行に収まるときは中央へ、複数行になったら左へ寄せる一覧は、どちらの手法でも組めますが、Gridのほうが意図をそのまま書けます。列の幅を `fr` ではなく長さで決めた `auto-fit` は、アイテムのない列を幅0に畳むので、`justify-content: center` で残った列のまとまりが中央に寄ります。複数行になると、最終行のアイテムは列に従って左から並びます。Flexboxでも最初と最後の子に `auto` の `margin` を付ければ同じ見た目になりますが、その目的はコードから読み取りにくくなります。

```css title="🙆‍♂ Recommended: 列の幅を長さで決め、列のまとまりを中央に寄せる"
._list {
  --_column: 3;
  --_gap: 16px;

  display: block grid;
  grid-template-columns: repeat(auto-fit, calc((100% - var(--_gap) * (var(--_column) - 1)) / var(--_column)));
  gap: var(--_gap);
  justify-content: center;
}
```

## 中身の量や行ごとに並べるならFlexbox

GridはFlexboxの上位互換ではありません。タグの一覧やグローバルナビゲーションのリンクは、1つずつ文字数が違います。`repeat(4, 1fr)` のように親が列の幅を決めると、短いタグにも長いタグと同じ幅が割り当てられてしまいます。Flexboxなら、子要素の幅を決めずに並べるだけで、入りきらない要素は次の行へ折り返されます。この並び方は、コンポジション `cluster` にしています（「[12-3 cluster](/compositions/cluster/)」）。

Flexboxは、折り返した行を1行ずつ独立して並べます。そのため、格子状の一覧の最終行の端数を中央に寄せるなら、Flexboxのほうが簡潔です。子の幅を列数と間隔から計算し、親に `justify-content: center` を指定すれば、最終行に残ったアイテムが中央に寄ります。Gridのアイテムは親が決めた列に置かれるので、同じことをするには、数量クエリで端数のアイテムの開始位置をずらします（「[11-5 件数で配置を組み替える](/layout-practice/quantity-layouts/)」）。

```css title="🙆‍♂ Recommended: 列数から子の幅を計算し、最終行を中央に寄せる" from="layout-practice/last-row-center"
@scope (.scoped.product-list) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
  }

  ul {
    --_column: 1;
    --_gap: 16px;

    display: block flex;
    flex-wrap: wrap;
    gap: var(--_gap);
    justify-content: center;

    @container --scoped (inline-size >= calc(480 / 16 * 1rem)) {
      --_column: 2;
    }

    @container --scoped (inline-size >= calc(768 / 16 * 1rem)) {
      --_column: 3;
    }

    & > li {
      flex-basis: calc((100% - var(--_gap) * (var(--_column) - 1)) / var(--_column));
    }
  }
}
```

次のデモでは、上がこのFlexboxの一覧で、その下に先ほどのGridの一覧を、アイテムが2つのものと5つのものに分けて並べています。幅を1024pxにすると、Flexboxでは最終行の2つが中央に寄ります。Gridでは、1行に収まる2つのアイテムは中央に寄り、5つのアイテムの最終行は列にそろって左から並びます。560pxでは、Flexboxの最終行の1つが中央に寄ることを確かめられます。

<Demo title="Flexbox は最終行の端数を中央に寄せ、Grid は1行のときだけ中央に寄せる" html={lastRowCenterHtml} css={lastRowCenterCss} widths={[320, 560, 1024]} />

行ごとに列数の違うレンガ状の一覧も、同じ計算で組めます。2つ目以降の子と4つ目以降の子で `--_column` を上書きすれば、広い画面では1行目に1枚、2行目に2枚、3行目以降に3枚ずつ並びます。列数は親のクエリで決めるので、閾値は1か所で済みます。Gridで同じ形を作るには、1、2、3の公倍数の6列の格子を作り、子ごとにまたがる列の数を計算することになります。

```css title="🙆‍♂ Recommended: 子ごとに列数を上書きして、行ごとに枚数を変える"
@scope (.scoped.feature-list) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
  }

  ul {
    --_gap: 16px;
    --_second-row-column: 1;
    --_later-row-column: 1;

    display: block flex;
    flex-wrap: wrap;
    gap: var(--_gap);

    @container --scoped (inline-size >= calc(640 / 16 * 1rem)) {
      --_second-row-column: 2;
      --_later-row-column: 3;
    }

    & > * {
      --_column: 1;

      flex-basis: calc((100% - var(--_gap) * (var(--_column) - 1)) / var(--_column));
    }

    & > :nth-child(n + 2) {
      --_column: var(--_second-row-column);
    }

    & > :nth-child(n + 4) {
      --_column: var(--_later-row-column);
    }
  }
}
```

一部の要素だけを行末側へ寄せる場面も、Flexboxが得意です。フレックスアイテムの `auto` の `margin` は、余った空間をすべて吸収します。ヘッダーのナビゲーションで、最後のアカウントのリンクだけを右端へ寄せるなら、その要素に `margin-inline-start: auto` を指定します。

```css title="🙆‍♂ Recommended: auto の margin で、最後の要素だけを行末へ寄せる"
._global-nav {
  display: block flex;
  flex-wrap: wrap;
  gap: 8px 16px;

  & > ._account {
    margin-inline-start: auto;
  }
}
```

余白の吸収先が1か所に決まるので、ナビゲーションの項目が増減しても、アカウントのリンクは行末に残ります。空の要素を置いて `flex-grow` で押し広げる書き方は、要素が増えるだけなので使いません。全体を均等に散らす `justify-content: space-between` は、寄せる位置が要素の数で変わるので、この用途には向きません。余白がなくなると `auto` の `margin` は0として扱われ、`flex-wrap: wrap` を指定していれば、寄せた要素もほかのアイテムと同じように次の行へ折り返します。

固定幅のサイドと伸び縮みするメインの2カラムも、Flexboxが得意な配置です。メインの `flex-grow` をサイドよりはるかに大きくしておくと、幅に余裕があるうちは横に並び、足りなくなるとクエリなしで縦に積まれます。Gridでは、列の数を切り替えるためにクエリが必要です。この配置は、コンポジション `sidebar` にしています（「[12-6 sidebar](/compositions/sidebar/)」）。

## 文章を避けて置くならfloat

`float` の本来の用途は、要素を行の端に寄せ、その横と下に文章を回り込ませることです。この配置は、FlexboxやGridでは作れません。画像に文章を回り込ませる配置のほか、モーダルの閉じるボタンや装飾の画像を文章の角に置く配置も、`position: absolute` ではなく `float` で組めば、画面が狭くなっても文字が要素の下に隠れません。

回り込みの仕組みと、`float` の要素を `display: flow-root` で内側に収める書き方は、「[11-14 floatで文章を回り込ませる](/layout-practice/float/)」で説明しています。`position: sticky` と組み合わせた閉じるボタンや、行頭のアイコンを1行目にそろえる書き方も、同じ節にあります。
