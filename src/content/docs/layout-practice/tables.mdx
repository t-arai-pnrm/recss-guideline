表は、置かれた場所の幅に合わせて縮めません。`min-inline-size` で表の最小の幅を決め、それより狭い場所では、表を包む要素（スクロールのラッパー）の中で横にスクロールさせます。見出しのセルを `position: sticky` で留めるときは、表に `border-collapse: separate` を指定して、枠線をセルごとに持たせます。数値の列は、`font-variant-numeric: tabular-nums` で数字の幅をそろえ、末尾に揃えます。

行どうしを比べる必要がなく、1行ごとに完結した記録を並べる表は、狭い幅で縦に積む方法もあります。その場合は、`display` を変えた表が表として扱われなくなるブラウザが以前はあったので、古い環境に備えてHTMLに `role` を書き、表の意味を残します。この節では、表が崩れる理由、スクロールのラッパー、見出しのセルの留め方、数値の列のそろえ方、縦に積む方法、`table-layout: fixed` で列の幅を決める方法を順に説明します。

## 狭い場所で表が崩れる理由

表の列の幅は、既定の `table-layout: auto` では、セルの中身から決まります。表の幅は、各列の最小の幅（折り返せるところをすべて折り返した幅）の合計より狭くなりません。この最小の幅が、狭い画面で表が崩れるかどうかを決めます。

kiso.cssは、`:root` に `overflow-wrap: anywhere` を指定しています。この値は、単語の途中でも折り返せる位置として、列の最小の幅の計算にも使われます。そのため、表は1文字ずつ折り返せる幅まで縮み、狭い画面では各列が1〜2文字の幅になります。`12,100` のような数値も途中で折り返され、桁を読み取れなくなります。

反対に、折り返せない長い語や `white-space: nowrap` のセルがあると、表は最小の幅で止まり、親からはみ出します。はみ出した分はページ全体の横スクロールになり、ほかの内容まで横に動きます。どちらの崩れも、表の幅を置かれた場所の幅だけで決めていることが原因です。

対策は2つあります。1つは、表に読める最小の幅を決め、それより狭い場所では、ラッパーの中で表を横にスクロールさせる方法です。もう1つは、狭い幅で行を縦に積み、カードのような形に組み替える方法です。売上の推移のように行どうしを比べる表は、列が並んでいないと比べられないので、スクロールさせます。注文の履歴のように、1行ごとに完結した記録を並べる表は、縦に積んでも読めます。{/* 要確認: 出典なし */}

## スクロールのラッパーで包む

スクロールさせるときは、表を `<div>` で包み、この要素に `overflow-x: auto` を指定します。表には、すべての列が読める幅を `min-inline-size` で指定します。閾値と同じく、列の幅を足した式を `calc()` で書きます。文字が入る中身の幅はremに変換し、pxで指定したセルの `padding` と枠線は、remへ変換せず、pxのまま足します（「[13-2 ブレイクポイントの決め方](/responsive/breakpoints/)」）。

```css title="🙆‍♂ Recommended: 表に最小の幅を決め、包む要素の中で横にスクロールさせる"
@scope (.scoped.sales-table) to (.scoped) {
  :scope {
    overflow-x: auto;
  }

  table {
    inline-size: 100%;

    /*
     * 支店の列の中身 72px 相当と、数値の列の中身 64px 相当 × 7 に、
     * セルの左右の余白 12px × 2 を 8 列分と、支店の列の右の枠線 1px を足した幅
     */
    min-inline-size: calc(72 / 16 * 1rem + 64 / 16 * 1rem * 7 + 12px * 2 * 8 + 1px);
  }
}
```

表そのものの `display` を `block` に変えて、表自体をスクロールさせる書き方も見かけます。ラッパーが要らないので手軽ですが、MDNによれば、`table` の `display` を `block`、`grid`、`flex` に変えると、ブラウザによってはアクセシビリティツリーでの扱いが変わります。その結果、スクリーンリーダーが表として正しく読み上げなくなることがあります。この不具合は主要なブラウザで修正されましたが（縦に積む方法の見出しを参照）、修正前の環境では表の意味が失われます。表の構造はHTMLのまま残し、スクロールは外側の要素に任せます。

```css title="🙅‍♂ Not Recommended: 表の display を変えて、表自体をスクロールさせる" issue="behavior"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.sales-table) to (.scoped) {
  table {
    display: block flow;
    overflow-x: auto;
  }
}
```

ラッパーには、`role="region"`、`caption` を指す `aria-labelledby`、`tabindex="0"` を付けます。スクロールコンテナにキーボードでフォーカスできるかは、ブラウザによって違います。`tabindex="0"` があれば、どのブラウザでもTabキーで枠にフォーカスし、矢印キーでスクロールできます。フォーカスできる要素には名前が必要なので、`region` のランドマークにして、表の名前を `caption` から借ります。見出しのセルは `th` にし、列の見出しには `scope="col"` を、行の見出しには `scope="row"` を付けて、各セルがどの見出しに属するかを示します。

```html title="🙆‍♂ Recommended: スクロールする枠に、表のキャプションで名前を付ける"
<div class="scoped sales-table" role="region" aria-labelledby="sales-table-caption" tabindex="0">
  <table>
    <caption id="sales-table-caption">支店別の月間売上（2026年度上期、単位：千円）</caption>
    <thead>
      <tr>
        <th scope="col">支店</th>
        <th scope="col" class="_numeric">4月</th>
        <!-- ... -->
      </tr>
    </thead>
    <tbody>
      <tr>
        <th scope="row">札幌</th>
        <td>8,426</td>
        <!-- ... -->
      </tr>
    </tbody>
  </table>
</div>
```

スクロールの方向は、本書の論理プロパティの規約では `overflow-inline` で書きたいところです。しかし、`overflow-inline` に対応したのはSafari 26からなので、`overflow-x` を使います（「[9-9 論理プロパティと論理値](/notation/logical-properties/)」）。表の端が枠で切れて見えることも、横にスクロールできることの手がかりになります。端までスクロールしたら消える「→」の案内は、`scroll-state(scrollable: inline-end)` のコンテナクエリで作れます。現状はChrome系のブラウザだけの機能なので、案内がなくても使える前提で上乗せします（「[11-7 固定ヘッダー](/layout-practice/sticky-header/#留まっている間だけ見た目を変える)」）。

## 見出しのセルを留める

`position: sticky` は、いちばん近い祖先のスクロールコンテナを基準に留まります。そして、`overflow-x` に `auto` を指定すると、`overflow-y` の `visible` も `auto` として計算されます。ラッパーは縦方向でもスクロールコンテナになるので、列の見出しに `inset-block-start: 0` を指定しても、ページをスクロールしたときには留まりません。ラッパー自身は縦にスクロールしないからです。

列の見出しを留めたいときは、ラッパーに `max-block-size` を指定し、ラッパーの中で縦にもスクロールさせます。縦の上限を設けたくない表では、列の見出しは留めず、行の見出し（先頭の列）だけを `inset-inline-start: 0` で横方向に留めます。ラッパーには `scrollbar-gutter: stable` も指定します。スクロールバーが幅を取る環境では、行が増えて縦のスクロールバーが現れたときに表の幅が変わるからです。仕様上、`scrollbar-gutter` が確保するのは行の始めと終わりの辺の領域で、横のスクロールバーの領域は確保できません。

次に、枠線の持たせ方を変えます。kiso.cssは `table` に `border-collapse: collapse` を指定しています。`collapse` では、隣り合うセルが1本の枠線を共有するので、枠線はどちらか一方のセルのものではありません。留めたセルを動かしても、共有の枠線は元の位置に残ります。Chromeで確かめたところ、列の見出しを留めてスクロールすると、見出しの上下の枠線が見出しと一緒に動かず、見出しの下の線が消えたように見えました。{/* 要検証: ブラウザ。Firefox と Safari での見え方 */}

そこで、表に `border-collapse: separate` と `border-spacing: 0` を指定し、枠線を各セルに持たせます。`separate` では、セルの枠線はそのセルのボックスの一部なので、留めたセルと一緒に動きます。隣り合うセルの枠線が二重にならないよう、各セルには `border-block-end` のように1辺ずつ指定します。

```css title="🙆‍♂ Recommended: 枠線をセルに持たせ、列の見出しと行の見出しを留める"
@scope (.scoped.sales-table) to (.scoped) {
  :scope {
    overflow: auto;
    max-block-size: calc(320 / 16 * 1rem);
    isolation: isolate;
    scrollbar-gutter: stable;

    & thead th {
      position: sticky;
      inset-block-start: 0;
    }

    & thead th:first-child {
      inset-inline-start: 0;
      z-index: var(--z--forwards);
    }

    & tbody th {
      position: sticky;
      inset-inline-start: 0;
    }
  }

  table {
    border-collapse: separate;
    border-spacing: 0;
  }

  th,
  td {
    border-block-end: 1px solid var(--border--base);
  }

  th {
    &:is(thead *) {
      background-color: var(--background--base);
    }

    &:is(tbody *) {
      border-inline-end: 1px solid var(--border--base);
      background-color: var(--background--surface);
    }
  }
}
```

留めたセルには、不透明な背景色を指定します。背景がないと、下を通るセルの文字が透けて見えるからです。`z-index` を指定するのは、縦と横の両方に留める左上の角のセルだけです。列の見出しは横に、行の見出しは縦に動いて、どちらも角のセルの下にだけ入ります。角のセルを前に出せば、ほかの留めたセルどうしは重ならないため、`z-index` を指定せずDOMの順番どおりに描かせてかまいません。内部の要素に相対的な `z-index` を指定するため、ルートには `isolation: isolate` を指定します（「[10-2 コンポーネントの境界を守る](/components/boundaries/)」）。セルを留める `position: sticky` と `inset`、角のセルの `z-index` は、基準になるスクロールコンテナ（ルート）のネストに `& thead th` のように書きます。セルが留まる位置は、セル自身ではなく、スクロールさせるルートとの関係で決まるからです。留めたセルの背景色と枠線は、セル自身の見た目なので、セルのルールに書きます。

## 数値の列をそろえる

数値の列は、末尾に揃えます。桁数の違う値を並べたとき、1の位がそろうので、大きさを見比べられるからです。列の見出しのセルも、同じ列の数値に合わせて末尾に揃えます。kiso.cssは `th` の `text-align` を `unset` にしていて、見出しのセルは先頭に揃うからです。

末尾に揃えるだけでは、桁はそろいません。多くのフォントの数字はプロポーショナルで、`1` と `0` のように字によって幅が違います。そのため、同じ桁数の値でも、千の位の位置が行ごとにずれます。表に `font-variant-numeric: tabular-nums` を指定すると、数字が同じ幅になり、各桁が縦にそろいます。この指定は、フォントに等幅の数字（OpenTypeの `tnum` 機能）があるときだけ反映されます。

<Baseline id="font-variant-numeric" name="font-variant-numeric" />

```css title="🙆‍♂ Recommended: 数字の幅をそろえ、数値の列を末尾に揃える" from="layout-practice/table-scroll"
@scope (.scoped.sales-table) to (.scoped) {
  table {
    font-variant-numeric: tabular-nums;
  }

  td {
    text-align: end;
    white-space: nowrap;
  }

  ._numeric {
    text-align: end;
  }
}
```

この例の表は、データのセルがすべて数値なので、`td` にまとめて指定し、列の見出しには `._numeric` のクラスを付けています。本書は、明確な理由がない限り `white-space: nowrap` を指定しません（「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/)」）。スクロールのラッパーの中の数値は、その理由がある場面です。折り返しを止めると、列の最小の幅に数値全体の幅が入り、数値の途中で折り返さなくなります。はみ出した分は、ラッパーのスクロールで読めます。単位は各セルに繰り返さず、`caption` か列の見出しにまとめます。{/* 要確認: 出典なし */}

次のデモは、ここまでの指定をまとめた売上の表です。幅を320pxや480pxにすると、表は縮まずに枠の中で横にスクロールします。枠の中を縦にスクロールすると列の見出しが、横にスクロールすると支店の列が留まり、見出しの下の線も一緒に動きます。

<Demo title="最小の幅を決めた表を、包む要素の中でスクロールさせ、見出しのセルを留める" html={scrollHtml} css={scrollCss} />

数値はすべて末尾に揃い、`tabular-nums` で桁の位置が縦にそろっています。千円単位の表であることは `caption` に書き、各セルには数値だけを置いています。

## 狭いときに縦に積む

1行ごとに完結した記録を並べる表は、狭い幅で行をカードのように縦に積めます。表が複数の場所に置かれることを考え、切り替えはコンテナサイズクエリで書きます。ルートを `container: --scoped / inline-size` のコンテナにし、閾値には、各列の中身の最小の幅とセルの `padding` を足した式を書きます（「[13-3 コンテナサイズクエリ](/responsive/container-size-queries/)」）。

縦に積むには、`table`、`tbody`、`tr`、`td` の `display` を変える必要があります。`display` を変えた表は、以前は表として扱われなくなるブラウザがありました。この不具合は、Chromeは80、Firefoxは2022年、Safariは17で修正されています（表と `display` の不具合を追跡している記事で確認）。しかし、修正前のブラウザや、それと組み合わせた支援技術では、表の意味が失われます。MDNは、`display: grid` などで表の意味が上書きされる場合に、ARIAの表の `role` を書いて意味を加え直す方法を挙げています。そこで、HTMLの各要素に `role` を書きます。`table` には `role="table"`、`thead` と `tbody` には `role="rowgroup"`、`tr` には `role="row"` を書きます。見出しのセルには `role="columnheader"` か `role="rowheader"` を、データのセルには `role="cell"` を書きます。本書が対象にするブラウザは、どれも修正後の版です。それでも `role` を書くのは、古いブラウザと支援技術の組み合わせでも表として読めるようにするためで、書く手間は小さく済みます。

```css title="🙆‍♂ Recommended: 狭いときだけ、行をカードのように縦に積む" from="layout-practice/table-stack"
@scope (.scoped.order-table) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
  }

  table {
    --_density: --compact;

    display: block grid;
    gap: 8px;

    /*
     * 注文番号 72px・注文日 112px・商品 176px・数量 40px・金額 72px・状態 72px（どれも中身の幅で px 相当）に、
     * セルの左右の余白 12px × 2 を 6 列分足した幅
     */
    @container --scoped (inline-size >= calc((72 + 112 + 176 + 40 + 72 + 72) / 16 * 1rem + 12px * 2 * 6)) {
      --_density: --spacious;

      display: revert-layer;
    }
  }

  tr {
    @container style(--_density: --compact) {
      display: block grid;
      gap: 4px;
    }
  }

  td {
    /* 列の名前と値を1行の両端に並べるため、折り返さない */
    @container style(--_density: --compact) {
      display: block flex;
      gap: 16px;
      justify-content: space-between;
    }
  }

  ._label {
    display: none;

    @container style(--_density: --compact) {
      display: block flow;
    }
  }
}
```

閾値はルートの直下の `table` に1回だけ書き、`--_density` を、狭いときの `--compact` から広いときの `--spacious` に切り替えます。子孫の要素は、この値をスタイルクエリ（祖先の要素で宣言したカスタムプロパティの値を条件にするクエリ）で読みます。仕組みは「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」で説明しています。`table` 自身は、自分で宣言した `--_density` をスタイルクエリで読めないので、`display` の切り替えはコンテナサイズクエリの中に書きます。

子孫の要素では、縦に積む指定を `@container style(--_density: --compact)` の中に書いています。表は、表の形がブラウザの既定のスタイルで、縦に積む形のほうが指定の多い形です。縦積みの指定をクエリの外に書くと、広い幅ではその指定をひとつずつ打ち消して、表の形へ戻さなければなりません。狭いときの条件の中に書けば、広い幅では子孫の要素がブラウザの既定のスタイルのまま表の形になり、打ち消すのは `table` 自身の `display` だけで済みます。その `display` も `revert-layer` で、ブラウザの既定の表の形に戻します（「[4-1 カスケード・詳細度・継承](/cascade/cascade-basics/#rule-explicit-rollback-keyword)」）。

縦に積んだときは、各セルの値の前に列の名前を表示します。列の名前は、`::before` の `content` ではなく、HTMLの `<span class="_label" aria-hidden="true">` に書きます。意味のある文字はHTMLに書くという本書の方針に合わせるためです（「[5-8 生成コンテンツと装飾の擬似要素](/pseudo/generated-content/)」）。`aria-hidden` を付けるのは、`role` で残した列の見出しと重ねて読み上げないためです。`thead` を `display: none` で消すと、列の見出しとの関連づけまで失われるおそれがあります。そこで `thead` は、視覚的にだけ隠します。{/* 要確認: 出典なし */}

<Demo title="狭い場所では、注文の表の行をカードのように縦に積む" html={stackHtml} css={stackCss} />

幅を480px以下にすると、各行が枠で囲んだカードになり、列の名前と値が左右に並びます。768pxにすると、同じHTMLが表の形に戻ります。

## 列の幅を `table-layout: fixed` で決める

本書の表は、`min-inline-size` で最小の幅を決めたうえで、既定の `auto` のまま中身に合わせて列の幅を配らせます。ただし、`auto` では、ある行に長い文字列が入るとその列が広がり、ほかの列が狭くなります。CMSで行が追加されるたびに列幅が変わり、同じ表のデザインを保てません。{/* 要確認: 出典なし */}

列幅をデザインどおりに保ちたい表には、`table-layout: fixed` を指定します。2行目以降の中身を見ずに列の幅が決まるので、行の多い表でも描画が速くなります。列幅は、`<col>` 要素か最初の行のセルに指定した幅で決まり、指定のない列は残りの幅を分け合います。中身は列幅に影響しないので、長い文字列は、kiso.cssの `overflow-wrap: anywhere` によってセルの中で折り返します。{/* 要確認: 出典なし */}

```css title="🙆‍♂ Recommended: 列幅を中身ではなく、表の幅と列の指定で決める"
@scope (.scoped.order-table) to (.scoped) {
  table {
    inline-size: 100%;
    table-layout: fixed;
  }

  ._date-column {
    inline-size: calc(120 / 16 * 1rem);
  }
}
```

`table-layout: fixed` は、表の幅が `auto` のときには働きません。`inline-size` で表の幅を決めておきます。列の数が多く、狭い画面で列幅を保てない表は、「[スクロールのラッパーで包む](#スクロールのラッパーで包む)」と組み合わせます。

## 補足と注意点

縦に積む方法は、列が少なく、各行が独立した表に向いています。列が多い表を縦に積むと、1行のカードが長くなり、行どうしを見比べられなくなります。どちらにするか迷う表は、スクロールのラッパーで包みます。表の形と列の並びが保たれ、`role` の上書きも要らないからです。
