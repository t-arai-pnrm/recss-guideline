ヘッダーを画面の上に固定するのは、ビューポートの高さが十分なときだけにします。固定するときは、フォーカスした要素やページ内リンクの移動先がヘッダーの下に隠れないように、スクロールで見せる範囲からヘッダーの分を除きます。ヘッダーの高さはCSSに数値で書かず、JavaScriptで測って渡します。上端に留まっている間だけ見た目を変えるときは、`scroll` イベントではなく `scroll-state()` のコンテナクエリを使い、変えるのは色や影のように寸法の変わらないものに限ります。

この節は、`position: sticky` を前提にしています。`sticky` の要素は、通常フローの位置に置かれたまま、スクロールに合わせて、祖先のスクロールコンテナと包含ブロック（位置と大きさの基準になる領域）の範囲の中でずれます。値ごとの違い、包含ブロックの決まり方、`sticky` が留まらない原因は、「[7-10 positionの基礎](/layout/positioning/)」で説明しています。

ヘッダーの中のメニューやツールチップを、開いたボタンのすぐ下に表示する方法は、「[11-8 アンカーポジショニング](/layout-practice/anchor-positioning/)」で説明しています。未対応の環境でも内容を読める形を先に書き、対応した環境でだけボタンの近くに置く書き方です。

## 固定ヘッダーで起きる問題

ヘッダーを固定してまず問題になるのは、画面の広さです。横向きのスマートフォンでは、ビューポートの高さが400px前後しかなく、固定したヘッダーが画面の多くを覆って、本文を読める範囲が狭くなります。{/* 要確認: 出典なし */}拡大した画面でも同じことが起きます。拡大するとCSSピクセルで数えたビューポートの高さが縮むので、パソコンでも、固定したヘッダーが画面の多くを覆います。

固定したヘッダーは、フォーカスした要素も隠します。Shift+Tabで前の要素へフォーカスを戻すと、ブラウザはその要素が見えるようにスクロールしますが、要素はビューポートの上端にそろうので、ヘッダーの下に入ります。ページ内リンクで見出しへ移動したときも、見出しが上端にそろってヘッダーに隠れます。WCAG 2.2の達成基準2.4.11（レベルAA）は、キーボードでフォーカスした要素が、作成者の置いたコンテンツで完全に隠れないことを求めています。固定ヘッダーは、その典型的な原因として挙げられています。

上端に留まったときの見た目の切り替えも、問題になりやすいところです。留まったら影を付ける、背景を不透明にする、といった演出は、以前は `scroll` イベントでスクロール量を調べて、JavaScriptでクラスを付け替えて作っていました。スクロールのたびに位置を調べる処理が、見た目のためだけに動き続けます。

留まったときにヘッダーの高さを縮める演出は、さらに別の問題を起こします。`sticky` の要素は通常フローに場所を持つので、高さが縮むと後ろの内容が動き、ブラウザがスクロール位置を押し戻すことがあります。この問題は、節の最後の「留まったときに高さを変えない」で説明します。

## 固定ヘッダーと画面の高さ

ヘッダーを画面の上に固定するのは、ビューポートの高さが十分なときだけにします。固定の条件には、幅ではなく高さのメディアクエリを使います。問題は本文を読める範囲が縦に狭くなることなので、幅で判定すると、横向きのスマートフォンや拡大した画面を見分けられないからです。

```css title="🙆‍♂ Recommended: ビューポートの高さが十分なときだけ、ヘッダーを固定する"
@scope (.scoped.site-header) to (.scoped) {
  :scope {
    @media (height >= calc(600 / 16 * 1rem)) {
      position: sticky;
      inset-block-start: 0;
      z-index: var(--z--header);
    }
  }
}
```

閾値は、ほかのクエリと同じく `rem` で書きます（「[13-5 メディアクエリ](/responsive/media-queries/)」）。ユーザーがブラウザの文字サイズを大きくすると閾値も大きくなり、ヘッダーは早めに固定をやめます。600px相当は、横向きのスマートフォンや、200%に拡大したノートパソコンの画面で固定を外すための目安です。{/* 要確認: 出典なし */}`z-index` には数値を直接書かず、ページ全体の重なり順を決めるトークン `--z--header` を使います（「[10-4 デザイントークン](/components/design-tokens/)」）。固定しない画面では重なる相手がないので、`z-index` も条件の中に書いています。

固定には、`position: fixed` ではなく `sticky` を使います。`fixed` の要素は通常フローから外れるので、本文の先頭がヘッダーの下に隠れないように、ヘッダーの高さと同じ余白を別に空ける必要があります。`sticky` の要素は通常フローに場所を持ったまま留まるので、この余白が要らず、条件を外したときも、ヘッダーはそのまま文書の先頭に置かれます。{/* 要確認: 出典なし */}

`sticky` で留まるのは、ヘッダーの親の範囲の中だけです。ヘッダーを `<body>` の直下に置けば、ページの最後まで留まります。ヘッダーだけを包む要素を挟むと、親の高さがヘッダーと同じになり、ヘッダーがずれる余地はなくなります。留まらないときは「[7-10 positionの基礎](/layout/positioning/)」の原因を順に確かめます。

## フォーカスとページ内リンクの移動先を隠さない

固定しているときも、フォーカスした要素やページ内リンクの移動先がヘッダーの下に入ることはあります。「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」では、ルートに `scroll-padding-block-start` を指定し、スクロールで内容を見せる範囲からヘッダーの分を除いています。値は `var(--site-header--block-size, 4rlh)` です。仕様では、この指定は、フォーカスやページ内リンクによるスクロールと、Spaceキーなどで1画面ずつ送るときの送り幅に反映されるとされています。この節では、ヘッダーの高さを測って `--site-header--block-size` に渡し、指定をヘッダーを固定する条件に絞ります。

### ヘッダーの高さを測って渡す

ヘッダーの高さは、CSSに数値で書かず、`ResizeObserver` で測ってルート要素のカスタムプロパティに渡します。ヘッダーの高さは、ナビゲーションの文言、ユーザーの文字サイズ、折り返しで変わります。数値で書くと、高さが変わるたびに、ヘッダーのCSSとルートの値の2か所をそろえ直すことになります。

```js title="🙆‍♂ Recommended: ヘッダーの高さを測り、ルート要素のカスタムプロパティに渡す"
const header = document.querySelector(".site-header");

if (header) {
  new ResizeObserver(([entry]) => {
    const blockSize = Math.ceil(entry.borderBoxSize[0].blockSize);
    document.documentElement.style.setProperty("--site-header--block-size", `${blockSize}px`);
  }).observe(header);
}
```

`ResizeObserver` のコールバックは、監視を始めたときと、要素の大きさが変わったときにだけ呼ばれます。`scroll` や `resize` のイベントで測る書き方と違い、ヘッダーの高さが変わらない間は何も処理しません。Chromeで、高さ64pxのヘッダーに高さ50pxの要素を足すと、カスタムプロパティの値は `64px` から `114px` に変わりました。

`borderBoxSize` は、枠線と `padding` を含めた大きさです。`blockSize` はブロック方向の大きさで、横書きのページでは高さに当たります。`scroll-padding-block-start` と同じ方向の大きさなので、縦書きのページでもそのまま渡せます。値は `Math.ceil` で切り上げます。四捨五入で切り下がると、移動先の上端が1px未満だけヘッダーの下に入るからです。スクリプトは、ヘッダーより後で動くように、`type="module"` か `defer` で読み込みます。スクリプトが動かない環境では、8-2の代替値の `4rlh` が使われます。

### 固定する条件に合わせる

8-2の指定は、ヘッダーを固定するかどうかを知りません。この節のようにビューポートの高さが十分なときだけ固定するなら、ルートの指定も同じ条件の中に移します。

```css title="🙆‍♂ Recommended: ヘッダーを固定するときだけ、スクロールで見せる範囲からヘッダーの高さを除く"
@layer base {
  :root {
    @media (height >= calc(600 / 16 * 1rem)) {
      scroll-padding-block-start: var(--site-header--block-size, 4rlh);
    }
  }
}
```

閾値は、ヘッダーのクエリとそろえます。ヘッダーを固定しない画面で余白だけが残ると、移動先の上に意味のない空きができるからです。スクリプトは画面の高さにかかわらずヘッダーを測りますが、値を使うのはこの条件の中だけです。

`scroll-padding` を指定するのは、ページをスクロールさせているルートです。ページを入れ子のスクロールコンテナでスクロールさせていると、この指定は反映されません（「[11-10 ページのスクロールとルートスクローラー](/layout-practice/root-scroller/)」）。移動先の要素に `scroll-margin-block-start` を足すと、2つの余白は足し合わされます。8-2で説明したとおり、ヘッダーの高さを除くのは `scroll-padding` だけにします。

## 留まっている間だけ見た目を変える

上端に留まったときの見た目は、コンテナクエリの `scroll-state()` で切り替えます。`sticky` の要素が留まっているかどうかをCSSだけで判定できるので、スクロールのたびにJavaScriptで位置を調べる処理が要りません。

<Baseline id="container-scroll-state-queries" name="scroll-state() のコンテナクエリ" />

`sticky` の要素に `container-type: scroll-state` を指定します。ルートは幅の問い合わせのために `inline-size` のコンテナにしているので、`inline-size scroll-state` のように種類を並べて書きます（「[13-3 コンテナサイズクエリ](/responsive/container-size-queries/)」）。固定する条件は、前の見出しの例と同じく高さのメディアクエリの中に書きます。すると、その中の要素は `@container scroll-state(stuck: block-start)` の条件を使い、上端に留まっている間だけスタイルを変えられます。コンテナクエリなので、条件で変えられるのはコンテナの子孫だけです。ヘッダーそのものではなく、内側の要素に見た目を書きます。

`stuck` の値には、`top` や `bottom` のような物理キーワードと、`block-start` や `block-end` のような論理キーワードがあります。本書では、`inset-block-start` で留める位置を決めているのに合わせて、論理キーワードで書きます（「[9-9 論理プロパティと論理値](/notation/logical-properties/)」）。下端に留めるフッターなら `stuck: block-end` です。

```css title="🙆‍♂ Recommended: 上端に留まっている間だけ、ヘッダーの内側に境界線を付ける"
@scope (.scoped.site-header) to (.scoped) {
  :scope {
    container: --scoped / inline-size scroll-state;

    @media (height >= calc(600 / 16 * 1rem)) {
      position: sticky;
      inset-block-start: 0;
      z-index: var(--z--header);
    }
  }

  ._header-inner {
    border-block-end: 1px solid transparent;

    @container --scoped scroll-state(stuck: block-start) {
      border-block-end-color: var(--border--strong);
    }
  }
}
```

`scroll-state()` のクエリに対応しているのはChrome系のブラウザだけです。対応していない環境では条件が成り立たず、境界線がないまま留まります。ヘッダーの機能は損なわれないので、プログレッシブ・エンハンスメントとして使えます。反対に、留まったときにだけメニューを表示するような、見えないと操作できなくなる変化には使いません。

同じ仕組みで、横にスクロールできる表の案内を、`scroll-state(scrollable: inline-end)` が成り立つ間だけ表示できます（「[11-15 表を組む](/layout-practice/tables/)」）。

## 留まったときに高さを変えない

留まったときにヘッダーの高さを縮める演出には、別の問題があります。`sticky` の要素は通常フローに場所を持つので、高さが縮むと、後ろの内容がその分だけ上へ動きます。ブラウザは、見えている内容の位置を保つスクロールアンカリングの仕組みで、スクロール位置を縮んだ分だけ戻します。Chromeで、留まると高さが64px縮むヘッダーを置いて32pxスクロールすると、スクロール位置は0に戻り、ヘッダーも元の高さに戻りました。少しスクロールするたびにページが先頭へ押し戻され、ヘッダーが伸び縮みを繰り返します。

そのため、留まったときに変えるのは、色や影のように寸法の変わらないものにします。先ほどの例で、内側の要素の境界線の色だけを変えているのも、このためです。高さを変える必要があるなら、ルートに `overflow-anchor: none` を指定して、スクロールアンカリングを止めます。同じ条件で確かめると、スクロール位置は32pxのまま保たれました。

```css title="🙆‍♂ Recommended: 留まると高さが変わるヘッダーを置くときは、スクロールアンカリングを止める"
:root {
  overflow-anchor: none;
}
```

<Baseline id="overflow-anchor" />

この指定は、ページ全体のスクロールアンカリングを止めます。画面より上で画像が読み込まれて高さが変わったときなどに、見ている内容が押し下げられるようになるので、高さを変えずに済むなら、そのほうを選びます。`overflow-anchor` はSafari 27で対応し、2026年9月にBaselineの「新しく利用可能」になりました。対応していない環境では、指定が無視されるだけです。{/* 要確認: 出典なし */}
