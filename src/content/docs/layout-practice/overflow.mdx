ページに横スクロールが出たら、まず、はみ出している要素を特定して、その要素を直します。ルートで横方向のはみ出しを切り取るのは、そのうえでの備えです。はみ出しを切り取るときは、`overflow: hidden` ではなく `overflow: clip` を使います。`hidden` は要素をスクロールコンテナにするので、`position: sticky` やスクロール駆動アニメーションの基準を変えてしまうからです。`hidden` を使うのは、`0fr` で畳むアコーディオンの中身のように、スクロールコンテナであることが要る場面に限ります。

見出しと操作ボタンを残して本文だけをスクロールさせるパネルでは、Gridの本文の行を `minmax(0, 1fr)` にして、行の高さの下限を0にします。

中身を中央に寄せたスクロール領域では、中身がはみ出したときに先頭側が切れます。中央寄せには `safe` を付け、はみ出すときは先頭に寄せます。はみ出しを起こしにくい書き方（幅の上限、最小の長さ、アイテムの最小幅0）は、「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/)」で説明しています。

## 横スクロールの原因を特定する

ページに横スクロールが出たら、まず、はみ出している要素を特定します。DevToolsのコンソールで次のスクリプトを実行すると、すべての要素に枠線を付けたうえで、ビューポートの左右の端からはみ出した要素を一覧できます。幅だけを比べると、ビューポートより狭くても `translate` や負の `margin` で位置がずれてはみ出した要素を見落とすので、左右の端の位置を比べます。`$$()` は、DevToolsのコンソールで使える `querySelectorAll()` の省略形です。

```js title="DevTools のコンソールで、ビューポートの端からはみ出した要素を探す"
const windowWidth = document.documentElement.clientWidth;
$$('*').forEach((el) => {
  el.style.outline = '1px solid tomato';
  const { left, right } = el.getBoundingClientRect();
  if (left < 0 || windowWidth < right) console.log(el);
});
```

要素の外側の `margin` の領域は `getBoundingClientRect()` に含まれないので、`margin` の領域だけがはみ出している場合は、このスクリプトでは見つかりません。枠線を目で追って確かめます。原因が分かったら、その要素を直します。直し方は「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/)」にまとめています。

そのうえで、画面の端まで広げた装飾などが意図せずはみ出す場合に備えて、ベーススタイル（`base` レイヤー）で、ルートの横方向のはみ出しを切り取ることがあります。このとき、`overflow-x: hidden` ではなく `clip` を使います。理由は次の見出しで説明します。

```css title="🙆‍♂ Recommended: 横方向のはみ出しを clip で切り取る"
@layer base {
  :root,
  body {
    overflow-x: clip;
  }
}
```

<Baseline id="overflow-clip" />

`overflow: clip` は、本書の対象のすべてのブラウザで使えます。論理プロパティの `overflow-inline` は、Safariでは26から対応したので、本書の対象のブラウザでは物理の `overflow-x` で書きます（「[9-9 論理プロパティと論理値](/notation/logical-properties/)」）。はみ出しの対策に `contain: paint` を使う方法もありますが、中にある `position: fixed` の要素の基準が変わってしまうので使いません。この仕組みは「[7-10 positionの基礎](/layout/positioning/)」で説明します。

ルートでは、`clip` を選ぶ理由がもう1つあります。`html` と `body` の両方に `overflow-x: hidden` を指定すると、`body` がスクロールコンテナになり、ページのスクロールが `body` に移ることがあります（「[11-10 ページのスクロールとルートスクローラー](/layout-practice/root-scroller/)」）。

## `overflow: hidden` より `clip` を優先する

はみ出しを切り取るだけなら、場所を問わず、`overflow: hidden` ではなく `overflow: clip` を使います。どちらも、はみ出した中身を切り取る点は同じです。違うのは、要素がスクロールコンテナになるかどうかです。`hidden` の要素は、ユーザーのスクロール操作を受け付けないだけで、スクロールコンテナになります。CSS Overflow Module Level 3では、`hidden` の中身はプログラムからはスクロールできなければならないと定めています。`clip` は、プログラムからのスクロールも含めて、あらゆるスクロールを禁止し、スクロールコンテナを作りません。

スクロールコンテナになると、中身の位置がずれる場合もあります。`hidden` の要素の中で、はみ出した位置にある要素へフォーカスを移したり、ページ内リンクで移動したりすると、ブラウザはその要素を見せるために、`hidden` の要素の中身をスクロールさせます。スクロールバーがないので、ユーザーは元の位置に戻せません。JavaScriptの `scrollIntoView()` や `scrollTo()` も、同じように中身を動かします。`clip` の要素は、どの方法でもスクロールしません（フォーカス、ページ内リンク、`scrollIntoView()`、`scrollTo()` のそれぞれで確認）。

スクロールコンテナを探す仕組みにも影響します。`scroll()` で作るスクロール駆動アニメーションのタイムラインは、デフォルトでいちばん近い祖先のスクロールコンテナを基準にします。祖先に `hidden` の要素があると、そこが基準になり、ページをスクロールしてもアニメーションが進みません。スクロール駆動アニメーションは「[18-9 スクロールに合わせて動かす](/motion/scroll-driven/)」で説明しています。

同じ理由で、`position: sticky` も留まらなくなります。`sticky` の要素は、いちばん近い祖先のスクロールコンテナを基準に留まるからです。祖先が `hidden` だと、その要素は自身の中身の高さまで伸びているのでスクロールせず、ページをスクロールしても `sticky` の要素はその要素と一緒に流れていきます。`sticky` が動かない原因の切り分けは「[7-10 positionの基礎](/layout/positioning/)」にまとめています。

```css title="🙅‍♂ Not Recommended: はみ出した装飾を hidden で切り取る" issue="behavior"
/* 🙅‍♂ Not Recommended */
._section {
  overflow: hidden;
}
```

```css title="🙆‍♂ Recommended: はみ出した装飾を clip で切り取る" from="layout-practice/sticky-in-clip"
._section {
  overflow: clip;
}
```

次の2つのデモは、右上の装飾の円がはみ出すセクションに、`position: sticky` の見出しを置いたものです。デモの枠の中をスクロールすると、`hidden` で切り取った1つ目では、見出しが段落と一緒に流れていきます。`clip` で切り取った2つ目では、見出しが枠の上端に留まります。どちらも、円のはみ出しは同じように切り取られています。

<Demo title="overflow: clip で切り取ると、中の sticky の見出しが留まる" html={stickyClipHtml} css={stickyClipCss} widths={[]} height="360px" />

片方の軸だけを切り取りたいときも、`clip` を使います。`overflow-x: hidden` のように片方の軸を `hidden` にすると、もう片方の軸の `visible` は `auto` として計算され、要素はその軸でもスクロールコンテナになります。横のはみ出しを隠したつもりで縦にスクロールバーが出るのは、このためです。`clip` なら、もう片方の軸は `visible` のまま残ります。ただし、もう片方の軸を `auto` や `scroll` にすると、`clip` は `hidden` として計算されます。

`clip` には、`hidden` が作る新しいBFCを作らないという違いもあります。`overflow: hidden` で親子の `margin` の相殺を止めていた箇所を `clip` に変えると、相殺が戻ります。BFCが目的なら、`overflow` ではなく `display: flow-root` を使います（「[11-2 余白を設計する](/layout-practice/spacing/#rule-flow-root-for-margin-collapse)」）。切り取る位置を外側へ広げたり内容の辺へ寄せたりする `overflow-clip-margin` は、「[11-16 文字の切り詰めと読み込み中の表示](/layout-practice/truncation-and-skeletons/)」で扱います。

## `overflow: hidden` を使う場面

`overflow: hidden` を使うのは、スクロールコンテナであることが要る場面に限ります。代表的なのが、`grid-template-rows` を `0fr` と `1fr` で切り替えて、アコーディオンの中身を開閉する場合です。`fr` の値は補間できるので、`interpolate-size` に対応していないブラウザでも、高さをトランジションで動かせます。

この書き方では、中身を包んだグリッドアイテムを0の高さまで縮めます。ところが、グリッドアイテムの `min-block-size` の初期値 `auto` は、次の3つの条件をすべて満たすとき、中身の大きさから決まる最小サイズとして扱われます。この規則は、CSS Grid Layout Module Level 1の「グリッドアイテムの自動の最小サイズ」で定められています。1つ目は、`overflow` の算出値がスクロールできる値（`hidden`、`scroll`、`auto`）ではないことです。2つ目は、最小値が `auto` の行にまたがっていること、3つ目は、複数の行にまたがるなら、どれも `fr` の行ではないことです。`0fr` は `minmax(auto, 0fr)` の省略形なので、2つ目の条件を満たします。そのため、`overflow` が `visible` や `clip` のアイテムは、行が `0fr` になっても中身の高さより縮みません。

`overflow: hidden` のアイテムは1つ目の条件を外れるので、仕様のとおり最小サイズが0になり、行と一緒に0まで縮みます。はみ出した中身の切り取りと、最小サイズを0にすることを、1つの指定で済ませられます。本書のベーススタイルが0にしているのは `min-inline-size` だけなので（「[8-2 ベーススタイルに書くもの](/reset/base-styles/#rule-global-min-inline-size-zero)」）、高さの方向の最小サイズはここで外す必要があります。

```css title="🙆‍♂ Recommended: 0fr で畳む中身は overflow: hidden で最小サイズを0にする"
@scope (.scoped.disclosure) to (.scoped) {
  ._panel {
    display: block grid;
    grid-template-rows: 1fr;

    /* 閉じている間は、スクリプトで inert 属性を付ける */
    &[inert] {
      grid-template-rows: 0fr;
    }
  }

  ._body {
    overflow: hidden;
  }
}
```

`clip` で同じことをするなら、`min-block-size: 0` を別に書く必要があります。2つの指定の組み合わせは、片方を消すと開閉が正しく動かなくなるのに、それぞれの目的がコードから読み取りにくくなります。この場面では、スクロールコンテナになることが目的に合っているので、`hidden` を選びます。実際に、`::details-content` を `grid-template-rows` で開閉する方式では、Safari 18.4で `clip` のラッパーでは開閉が正しく動かず、`hidden` のラッパーが必要でした（2025年5月確認）。

スクロールコンテナになるので、前の見出しで説明したとおり、閉じた中身へフォーカスを移すと、中身の位置がずれる場合もあります。この例では、閉じている間はスクリプトで `inert` 属性を付け、中身にフォーカスが移らないようにしています。`<details>` の開閉に使う例は「[18-7 出現と退場](/motion/entry-and-exit/)」にあります。ほかに `hidden` が要るのは、モーダルを開いている間にルート要素のスクロールを止める場面です（「[8-2 ベーススタイルに書くもの](/reset/base-styles/#rule-modal-scroll-lock-root)」）。

## スクロールさせるときは `scroll` ではなく `auto` にする

中身がはみ出したときだけスクロールさせる要素には、`overflow: auto` を指定します。`overflow: scroll` は、中身が収まっていてもスクロールバーを常に表示する値だからです。表を包む要素やコードブロックのように、内容によってはみ出したり収まったりする場所では、`scroll` にすると、収まっているときにも使えないスクロールバーの帯が残ります。

```css title="🙅‍♂ Not Recommended: 中身が収まっていてもスクロールバーを表示する" issue="behavior"
/* 🙅‍♂ Not Recommended */
._table-scroller {
  overflow-x: scroll;
}
```

```css title="🙆‍♂ Recommended: はみ出したときだけスクロールバーを表示する"
._table-scroller {
  overflow-x: auto;
}
```

この違いは、開発の環境によっては見えません。macOSの初期設定のように、スクロールバーを操作するときだけ重ねて表示する環境では、`scroll` でも収まっているときにスクロールバーが出ないからです。Windowsや、スクロールバーを常に表示する設定にしたmacOSでは、スクロールバーの分だけ領域が狭くなります。{/* 要検証: ブラウザ。Windows の Chrome と Edge、常に表示する設定の macOS で、overflow: scroll のスクロールバーが常に表示されること */}

`auto` では、はみ出したときにスクロールバーが現れ、その分だけ中身の幅が変わる場合もあります。この揺れが気になる場所では、`scrollbar-gutter: stable` でスクロールバーの領域をあらかじめ確保します。本書のベーススタイルは、ページ全体のスクロールについてこの指定をしています（「[8-2 ベーススタイルに書くもの](/reset/base-styles/#rule-scrollbar-gutter-stable)」）。

## 見出しと操作ボタンを残して本文だけをスクロールさせる

ダイアログやドロワー、ドロップダウンのパネルで、見出しと操作ボタンを見せたまま本文だけをスクロールさせるときは、パネルに `max-block-size` で高さの上限を付けます。パネルを `grid-template-rows: auto minmax(0, 1fr) auto` で3つの行に分け、本文を `overflow-y: auto` でスクロールさせます。

```css title="🙆‍♂ Recommended: 見出しと操作ボタンの行を残し、本文の行だけを縮めてスクロールさせる"
@scope (.scoped.dialog-panel) to (.scoped) {
  :scope {
    grid-template-rows: auto minmax(0, 1fr) auto;
    max-block-size: calc(100svb - 32px * 2);

    &[open] {
      display: block grid;
    }
  }

  ._body {
    overflow-y: auto;
    overscroll-behavior-block: contain;
  }
}
```

高さを `max-block-size` で上限として書くのは、中身が少ないときはパネルを中身の高さまで縮めるためです。上限の基準には、ブラウザのUIが表示されている最も小さい領域を表す `svb` を使い、画面の上下に32pxずつの余白を残しています。UIの出入りで値が変わる `dvb` は、要素の大きさに使いません（「[6-2 ビューポート単位とコンテナ単位](/values/viewport-and-container-units/)」）。`<dialog>` のデフォルトの高さの上限はkiso.cssが解除しているので、上限はコンポーネントで決めます。この例のルートは `<dialog>` なので、`display` は開いた状態（`&[open]`）にだけ指定します。条件なしで `display: block grid` を書くと、閉じた `<dialog>` を隠すブラウザのデフォルトの `display: none` に勝ち、閉じたままのダイアログが表示されます。

Flexboxでも組めますが、本書ではGridを選びます。Gridなら、行の数と、どの行が残りの高さを受け取るかを、親の `grid-template-rows` の1行で読み取れます。Flexboxでは、どのアイテムが縮むかがアイテムごとの `flex-shrink` と最小サイズで決まり、親と子のCSSを読み合わせる必要があります（「[11-1 レイアウト手法の選び方](/layout-practice/choosing/)」）。

本文の行の `minmax(0, 1fr)` の `0` は、行の高さの下限です。単独の `1fr` は `minmax(auto, 1fr)` として扱われ、下限が `auto` の行は、その行に置かれたアイテムの自動の最小サイズより低くなりません（「[7-8 Gridの基礎](/layout/grid-basics/)」）。グリッドアイテムの `min-block-size` の初期値 `auto` は、スクロールコンテナでないアイテムでは、中身の高さとして扱われます。本書のベーススタイルが0にしているのは `min-inline-size` だけなので（「[8-2 ベーススタイルに書くもの](/reset/base-styles/#rule-global-min-inline-size-zero)」）、高さの方向ではこの下限が残ります。

例外は、行のアイテム自体がスクロールコンテナの場合です。上の例のように、`overflow-y: auto` の本文がそのまま行のアイテムなら、自動の最小サイズは0になるので、`1fr` でも本文は縮みます。崩れるのは、本文を包む別の要素が行のアイテムになったときです。たとえば、`<form method="dialog">` で本文と操作ボタンをまとめると、行のアイテムはスクロールコンテナでないフォームになります。行はフォームの中身の高さまで伸び、パネルが上限で止まったまま、フォームがパネルの外へはみ出します。

`minmax(0, 1fr)` と書いておけば、どの要素がその行に入っても、パネルの上限の中に収まります。列を分けるときに `minmax(0, 1fr)` ではなく `1fr` と書くのは（「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/#rule-fr-without-minmax-zero)」）、ベーススタイルが幅の方向の最小サイズを0にしているからです。高さの方向にはその前提がないので、スクロールさせる行には下限の0を明示します。Flexboxで組んだパネルでは、縮ませるアイテムに `min-block-size: 0` を指定します（「[7-7 Flexboxの基礎](/layout/flexbox-basics/)」）。

次のデモは、見出しと、本文と操作ボタンを包んだフォームを、高さの上限が `calc(280 / 16 * 1rem)` のパネルに入れたものです。フォームの行を `minmax(0, 1fr)` にした1つ目では、カテゴリーの一覧だけがスクロールし、見出しと「クリア」「適用」のボタンは見えたままです。`data-row-min="auto"` で行を `1fr` に戻した2つ目では、フォームがパネルの下の枠を越えてはみ出し、一覧はスクロールせず、ボタンもパネルの外に出ます。

<Demo title="本文を包むフォームの行を minmax(0, 1fr) にすると本文だけがスクロールし、1fr のままだとパネルの外へはみ出す" html={scrollBodyPanelHtml} css={scrollBodyPanelCss} widths={[]} />

本文がそのまま行のアイテムのときは、`1fr` でも `minmax(0, 1fr)` でも本文だけがスクロールしました。Flexboxで組んだ場合も、包む要素の `min-block-size` を0にすると収まりました（Chromeで確認）。{/* 要検証: ブラウザ。Safari と Firefox で、本文を包む要素の行が 1fr だとパネルの外へはみ出し、minmax(0, 1fr) で収まること */}

本文の `overscroll-behavior-block: contain` は、端までスクロールしたときに背面のページへスクロールが連鎖するのを止めます。kiso.cssは `<dialog>` と `[popover]` の要素自体にしか指定していないので、スクロールする本文にも指定します（「[17-6 開閉するUI](/interaction/disclosure/)」の「スクロールの連鎖を止める」）。

## 中央に寄せたスクロール領域の先頭が切れる

`justify-content: center` や `align-content: center` で中身を中央へ寄せ、`overflow: auto` でスクロールを付けた要素では、中身が要素より大きくなると先頭側が切れます。中央に寄せる計算は、はみ出した分を前後に均等に振り分けます。そのため、先頭側へはみ出した部分は、スクロールで戻れない位置に置かれるからです。モーダルの中身や、横にスクロールするカードの列でよく起きます。

`safe` キーワードを付けて `safe center` と書くと、中身が収まるときは中央に寄せ、はみ出すときは先頭に寄せます。先頭から読めるので、スクロールで末尾まで確かめられます。

```css title="🙆‍♂ Recommended: はみ出すときは先頭に寄せる"
@scope (.scoped.dialog-body) to (.scoped) {
  :scope {
    display: block grid;
    align-content: safe center;
    overflow-y: auto;
    max-block-size: calc(100svb - 32px * 2);
  }
}
```

`safe` は、Safariでは17.6から使えるので、本書の対象のブラウザはすべて対応しています。中身が要素に収まるかどうかがデザインカンプの時点で決まっていない場所では、中央寄せに `safe` を付けておきます。

開始側へはみ出した部分にスクロールで届かないのは、中央寄せに限りません。CSS Overflow Module Level 3は、スクロールの原点を、スクロールできる範囲のブロック方向とインライン方向の開始側の角に置き、原点より開始側にある領域を、スクロールで届かない領域と定めています。ブラウザはこの領域の中身を切り取ります。横書きでは左と上、右から左へ書く言語（`dir="rtl"`）では右と上が開始側です。スクロールできる範囲が広がるのは、終了側へのはみ出しだけです。Flexコンテナでは、主軸と交差軸の開始側が基準になるので、`flex-direction: row-reverse` では右側が開始側になります。

そのため、負の `margin` や `translate` で開始側へずらした要素は、スクロールコンテナの開始側の端で切れ、スクロールしても見えません。同じ量を終了側へずらした場合は、スクロールできる範囲が広がり、スクロールすれば見えます。横にスクロールするカードの列で、先頭のカードから左へはみ出させた装飾が切れるのは、このためです。開始側にも見せたいものがあるときは、ずらすのではなく、スクロールコンテナの開始側に `padding` を取って、その内側に収めます。{/* 要確認: 出典なし。開始側へはみ出す装飾をスクロールコンテナの padding の内側に収める方針 */}{/* 要検証: ブラウザ。負の margin と translate で開始側へずらした要素が、スクロールコンテナの開始側で切れ、dir="rtl" では右側で切れること */}
