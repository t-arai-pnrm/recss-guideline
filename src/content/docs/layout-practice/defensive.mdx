CSSを書くときは、「テキストが2倍の長さになったら」「画像がなかったら」「要素の数が変わったら」と、常に自問します。想定外の内容が入っても崩れないように書くCSSを、「ディフェンシブ（防衛的）なCSS」と呼びます。固定の長さには親の幅の上限を付け、高さは `block-size` で固定せずに `min-block-size` や `aspect-ratio` で決めます。フレックスアイテムとグリッドアイテムの最小幅はベーススタイルで0にし、要素の数が変わる並びは折り返させます。それでもはみ出したときの原因の探し方と、はみ出しの切り取り方は「[11-4 はみ出しとスクロール](/layout-practice/overflow/)」で説明します。

公開後も内容が更新されるWebサイトでは、デザインカンプにない長さの見出しや画像のない記事が入ってくることを前提にします（「[2-2 CSSで考えるための6つの視点](/design-mindset/css-mindset/#内容が変わる前提で書く)」）。守りの指定を書くのは、こうした実際に起こり得る変化に対してだけです。起こり得ない状態に備えた指定は、次の書き手に誤った前提を伝えるので書きません（「[2-3 保守しやすさを最優先にする](/design-mindset/maintainability/#aiがコードを書いても質が要る理由)」）。

## デザインカンプの内容だけを前提にした書き方

デザインカンプの見出しは、たいていちょうど良い長さで書かれています。しかし、実際に入る見出しは2倍の長さかもしれませんし、英語に翻訳されて単語が長くなるかもしれません。ユーザーが文字サイズを大きくすれば、同じ文章でも行数が増えます。次のコードは、カンプの内容だけを前提に書いた例です。

```css title="🙅‍♂ Not Recommended: デザインカンプの内容だけを前提にしたレイアウト" issue="behavior"
/* 🙅‍♂ Not Recommended */
._card-list {
  display: block grid;
  grid-template-columns: repeat(auto-fit, minmax(calc(360 / 16 * 1rem), 1fr));
}

._card-title {
  block-size: calc(48 / 16 * 1rem);
  white-space: nowrap;
}

._tag-list {
  display: block flex;

  & > * {
    flex-shrink: 0;
  }
}
```

カードの一覧は、親の幅が360px相当を下回るとはみ出します。見出しは高さが固定されているうえに折り返せないので、長くなるとカードの外へ突き抜けます。タグの一覧は、タグが増えると折り返せずに横へはみ出します。どれも、カンプの内容のままなら何も起きない問題です。

こうした不具合は、デザインの段階から「もし〜だったら」を織り込んでおけば、多くを防げます。書いたCSSは、長い見出し、画像のない記事、要素が1つだけの一覧や多すぎる一覧を入れて確かめます。既存のサイトの改修では、このあと説明する最小幅に起因するはみ出しを直す作業が、定期的に発生しています。書く段階で防いでおけば、あとから直す手間は少なくなります。

## 幅の上限と最小の長さ

幅や高さを固定値で決めない、というのが最初の守りです。幅は、`max-inline-size` で上限だけを決めます（「[13-1 検討する順番](/responsive/escalation/#rule-max-inline-size-over-fixed-width)」）。固定値の幅を許すのは、アイコンやチェックボックスのような小さなグラフィックの要素に限ります。高さの決め方は、次の節で説明します。

見落としやすいのが、最小の長さの指定です。`minmax(calc(360 / 16 * 1rem), 1fr)` の360px相当や、`min-inline-size: 320px` の320pxは、親がそれより狭くなってもその長さを保とうとするので、はみ出しの原因になります。最小の長さには、`min(100%, …)` で親の幅を上限にします。

```css title="🙆‍♂ Recommended: 最小の長さは、親の幅を超えないようにする"
._card-list {
  display: block grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, calc(360 / 16 * 1rem)), 1fr));
}

._search-field {
  min-inline-size: min(100%, 320px);
}
```

`min(100%, …)` は、2つの値のうち小さいほうを使う関数です。親が十分に広いときは360px相当が列の最小幅になり、親が狭いときは親の幅（`100%`）が最小幅になります。

## 要素の高さの決め方

要素の高さは、`block-size` で固定しません。一定の高さが要るときは `min-block-size` で下限を決め、縦横比が決まっている要素は `aspect-ratio` で、上限が要るときは `max-block-size` で決めます。高さを固定すると、内容が増えたときや、ユーザーが文字サイズを大きくしたとき、翻訳で文が長くなったときに、中身が要素の外へあふれます。

```css title="🙅‍♂ Not Recommended: 見出しと説明文を置く帯の高さを固定する" issue="behavior"
/* 🙅‍♂ Not Recommended */
._hero {
  display: block grid;
  align-content: center;
  block-size: calc(320 / 16 * 1rem);
}
```

デザインカンプでは、見出しと説明文が320px相当の帯にちょうど収まっています。しかし、見出しが2行になったり文字サイズが大きくなったりすると、中身は帯の高さを超え、下の要素に重なります。`min-block-size` に変えれば、中身が少ないうちは320px相当を保ち、収まらなくなったら帯のほうが伸びます。

```css title="🙆‍♂ Recommended: 高さの下限だけを決める" from="layout-practice/hero-height"
._hero {
  display: block grid;
  align-content: center;
  min-block-size: calc(320 / 16 * 1rem);
}
```

次の2つのデモは、見出しと説明文の長い帯の下に、お知らせのセクションを置いたものです。幅を320pxにすると、高さを固定した1つ目では、中身が帯の上下にはみ出します。`align-content: center` で中身を中央に寄せているので、はみ出しは帯の下だけでなく上にも出て、見出しの1行目とリンクの文字が、帯の外のページの背景にまぎれて読めなくなります。2つ目では帯が中身に合わせて伸びます。768pxでは、どちらも320px相当の高さに収まり、同じように見えます。

<Demo title="高さを固定した帯は、狭い幅で中身が上下にはみ出す" html={heroHeightHtml} css={heroHeightBadCss} variant="not-recommended" widths={[320, 768]} />

<Demo title="高さの下限だけを決めた帯は、中身に合わせて伸びる" html={heroHeightHtml} css={heroHeightCss} widths={[320, 768]} />

画像の枠や、擬似要素で描くアイコンのように縦横比が決まっている要素は、`aspect-ratio` で高さを決めます。幅だけを決めれば高さは比率から計算されるので、どの幅でも比率が保たれます。正方形のアイコンを `inline-size` と `block-size` に同じ値を書いて作ると、大きさを変えるときに2か所を直すことになり、片方を直し忘れると比率が崩れます。

```css title="🙆‍♂ Recommended: 縦横比が決まっている要素は、幅と aspect-ratio で大きさを決める"
._thumbnail {
  /* stretch に未対応の環境のための値 */
  inline-size: -webkit-fill-available;
  inline-size: stretch;
  aspect-ratio: 16 / 9;
}

._more {
  &::after {
    content: "";
    display: inline flow-root;
    inline-size: 1em;
    aspect-ratio: 1;
  }
}
```

`._thumbnail` に違う比率の画像が入っても、本書のベーススタイルが画像に指定している `object-fit: cover` によって、画像は引き伸ばされずに枠を埋めます（「[16-1 画像の配置と比率](/decoration/images/)」）。`._more` の擬似要素は幅と比率だけを決めた箱で、中にアイコンを描く方法は「[16-3 アイコンとSVG](/decoration/icons-and-masks/)」で説明しています。

上限が要るときは、`max-block-size` で決めます。選択肢の一覧やモーダルの本文のように、中身が多いときにスクロールさせる領域では、上限を超えた分だけがスクロールし、中身が少なければ領域は中身の高さまで縮みます。

```css title="🙆‍♂ Recommended: 高さの上限を決め、超えた分をスクロールさせる"
._options {
  overflow-y: auto;
  max-block-size: calc(320 / 16 * 1rem);
}
```

高さそのものが行数で決まる指定は、例外として `block-size` で書きます。チェックボックスを行の高さに合わせる `1lh`（「[17-7 フォーム部品](/interaction/forms/)」）や、読み込み中の表示で見出し2行分の場所を取る `2lh`（「[11-16 文字の切り詰めと読み込み中の表示](/layout-practice/truncation-and-skeletons/)」）です。どちらも文字サイズや行送りに合わせて変わるので、行の高さとずれません。

高さを `%` で決めるときは、別の落とし穴があります。幅は親の幅から決まりますが、高さは中身の高さから決まります。子が「親の高さの50%」と指定し、親の高さが子の中身に依存していると、どちらも相手を待つ循環になり、ブラウザは `%` を無視して `auto` として扱います。

親に明示した `block-size` があれば、子の `%` は解決されます。ただし、`min-block-size` は下限にすぎず、高さが決まったことにはなりません。親の高さに合わせて子を伸ばしたいだけなら、親をGridやFlexboxにして、子の `block-size: 100%` を書かずに済ませます（「[2-3 保守しやすさを最優先にする](/design-mindset/maintainability/)」）。

## `1fr` が押し広げられる理由

Gridで列を均等に分けるとき、`1fr` と書くことが多いと思います。`1fr` は `minmax(auto, 1fr)` の省略形で、列の最小幅は `auto` です。下限が `auto` の列は、その列に置かれたグリッドアイテムの最小幅（`min-inline-size`）より狭くなりません。グリッドアイテムの `min-inline-size` の初期値 `auto` は、0ではなく中身の最小幅として扱われます。そのため、途中で折り返せない長いURLや、ブラウザが最小幅を決めている `<input>` が入ると、その列だけが中身の幅まで押し広げられ、全体が親からはみ出します。

この対策として、列の最小値を0にした `minmax(0, 1fr)` がよく紹介されます。しかし、本書のベーススタイルでは、全称セレクタで全要素に `min-inline-size: 0` を指定しているので（「[8-2 ベーススタイルに書くもの](/reset/base-styles/#rule-global-min-inline-size-zero)」）、`minmax(0, 1fr)` は不要です。アイテムの最小幅がすでに0なので、`1fr` の列の下限も0になります。Chromeで確かめたところ、アイテムの最小幅が0なら、`1fr` の列は長いURLに押し広げられませんでした。

```css title="🙆‍♂ Recommended: ベーススタイルで最小幅を0にしてあれば、列は 1fr のまま分ける"
._cards {
  display: block grid;
  grid-template-columns: repeat(2, 1fr);
  gap: 16px;
}
```

```css title="🙅‍♂ Not Recommended: ベーススタイルで防いでいるはみ出しを、列ごとに防ぎ直す" issue="convention"
/* 🙅‍♂ Not Recommended */
._cards {
  display: block grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 16px;
}
```

`minmax(0, 1fr)` は、ベーススタイルと同じ守りをグリッドごとに書き足すだけで、表示は変わりません。そのうえ、`minmax()` が意図して下限を決めた列と、習慣で書いた列の区別がつかなくなります。`1fr` のままにしておけば、`minmax(min(100%, calc(360 / 16 * 1rem)), 1fr)` のように下限を決めた列だけが `minmax()` で書かれ、どの列に下限があるかがコードから読み取れます。

ただし、ベーススタイルが届かない場所では、この前提が成り立ちません。たとえば、文書の全称セレクタはShadow DOMの中の要素を選ばないので、Shadow DOMの中のグリッドアイテムの最小幅は `auto` のままです（「[10-8 Web Components](/components/web-components/)」）。こうした場所では、Shadow DOMのスタイルにも全称セレクタの `min-inline-size: 0` を書き、ベーススタイルと同じ前提をそろえます。

## 長い単語やURLで崩れないようにする

長い英単語やURLの折り返しには、`overflow-wrap: anywhere` を使います。本書で使う[kiso.css](/reset/kiso/)は、これを `:root` に指定しているので、個別に書く必要はありません。古い対策として知られる `overflow-wrap: break-word`（`word-wrap: break-word`）で上書きすることも避けます。

`break-word` と `anywhere` は、どちらも行に収まらない単語を途中で折り返します。違いは、途中の折り返しが要素の最小幅の計算に反映されるかどうかです。`anywhere` は反映するので、中身の最小幅が小さくなります。`break-word` は反映しないので、フレックスアイテムやグリッドアイテムの最小幅は、長いURLの幅のままです。通常のブロックの中では同じように見えるのに、FlexboxやGridの中では `break-word` だけがはみ出します。

次のデモは、2列のカードの片方に長いURLを入れたものです。1つ目は、カードに `min-inline-size: auto` を指定してベーススタイルの最小幅0がない状態を再現し、URLに `overflow-wrap: break-word` を指定しています。幅を320pxにすると、URLのある列が押し広げられ、カードが枠の外へはみ出します。

<Demo title="アイテムの最小幅が auto で overflow-wrap: break-word だと、長い URL が列を押し広げる" html={longUrlHtml} css={longUrlBadCss} variant="not-recommended" />

2つ目は、カードの最小幅をベーススタイルの0のままにし、折り返しはkiso.cssの `overflow-wrap: anywhere` に任せたものです。どの幅でも2つの列は同じ幅を保ち、URLは列の中で折り返します。

<Demo title="アイテムの最小幅0と overflow-wrap: anywhere で、長い URL を列の中で折り返す" html={longUrlHtml} css={longUrlCss} />

このデモでは、アイテムの最小幅と折り返しの2か所で守っています。どちらか一方でもURLのはみ出しは防げますが、`<input>` や横にスクロールさせる表のように、折り返しでは縮まない中身もあります。アイテムの最小幅を0にしておけば、こうした中身が入っても、列の幅は保たれます。`word-break: break-all` のように、収まる単語まで途中で折り返す指定は使いません。改行の制御は「[14-4 文字サイズと改行](/typography/size-and-line-breaks/)」で扱います。

## 縮ませたくない要素を守る

フレックスアイテムの `inline-size` や `flex-basis` は、Flowレイアウトの `inline-size` のような固定の制約ではなく、理想の大きさの提案です。親の幅が足りなければ、`flex-shrink` によって縮みます。`flex-basis` は主軸方向の大きさで、`flex-direction: column` なら高さにあたります。`flex-shrink: 0` は、この縮む過程から要素を外す指定です。

ベーススタイルで最小幅を0にしていなければ、長い文字を含む要素は中身の幅より縮まず、同じ行に並んだボタンを行の外へ押し出します。反対に、全称セレクタで最小幅を0にすると、今度はフレックスアイテムが縮みすぎる場合もあります。ボタンの中の「送信する」が「送信す／る」と折り返すような場合です。このとき、`flex-shrink: 0` で縮まないようにしたくなります。しかし、これは乱用されやすい指定です。`flex-shrink: 0` の要素は、親より長くなっても一切縮まないので、文字が長ければそのままはみ出します。

文字を含む要素には、まず `min-inline-size: fit-content` を検討します。フレックスアイテムの `fit-content` は、中身の幅（`max-content`）を、フレックスコンテナの中身の幅で頭打ちにした大きさです。ただし、折り返しても最も狭くなる幅（`min-content`）より小さくはならないので、長い単語や画像を含む要素では、親の幅を超えることがあります。これを最小幅にすると、親に余裕があるうちは中身の幅を保って折り返さず、親より長くなったときだけ親の幅で折り返します。縮まない指定に、はみ出しを防ぐ上限を加えた形です。

ただし、この上限はフレックスコンテナの中身の幅全体で、同じ並びのほかのアイテムや `gap` の分は差し引かれません。そのため、ボタンの中でアイコンと並ぶラベルに指定すると、はみ出すことがあります。中身の幅が160pxのボタンに、150pxのラベル、16pxのアイコン、8pxの `gap` を並べると、ラベルは150pxより縮まず、合計の174pxがボタンからはみ出します。`fit-content` は、ボタン全体を外側の並びのアイテムとして守るために指定し、ボタンの中のラベルは最小幅を0のままにして、アイコンと `gap` を除いた残りの幅で折り返させます。

```css title="🙆‍♂ Recommended: ボタン全体を fit-content で守り、中のアイコンだけ縮ませない"
._search-form {
  /* 入力欄を縮めてボタンと同じ行に収めるため、折り返さない */
  display: block flex;
}

._submit-button {
  display: inline flex;
  gap: 8px;
  align-items: start;
  min-inline-size: fit-content;

  & > ._icon {
    flex-shrink: 0;
    margin-block: calc((1lh - 1em) / 2);
  }
}

._icon {
  inline-size: 1em;
  aspect-ratio: 1;
}
```

この例では、検索の入力欄とボタンが `._search-form` の中に並びます。ボタンは、フォームに余裕があるうちは中身の幅を保ち、入力欄のほうが縮みます。ボタンの中のラベルには、全称セレクタの `min-inline-size: 0`（「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」）が指定されているので、ボタンが中身より狭くなったときは、アイコンの横の残りの幅で折り返します。ラベルが2行になってもアイコンが1行目にそろうように、ボタンを `align-items: start` にし、アイコンの上下に1行の高さとアイコンの差の半分の `margin` を付けています（「[11-13 アイコンを配置する](/layout-practice/icon-alignment/)」）。

アイコンのように、大きさが変わると困る要素には、`flex-shrink: 0` を指定します。縮ませないことが目的の要素と、折り返してもよいが縮みすぎては困る要素を、分けて考えます。同じ理由で、`white-space: nowrap` も明確な理由がない限り指定しません。折り返せない文字は、内容が長くなったときや画面が狭いときに、はみ出す原因になります。

## 画像を本文の高さに引き伸ばさない

Flexboxで画像と本文を横に並べるときは、画像へ `align-self: start` を指定して、交差軸の方向への引き伸ばしを止めます。`align-items` の初期値は `stretch` なので、画像は本文の高さに合わせて縦に伸びます。本文が長くなるほど、画像の比率がカンプから離れていきます。

```css title="🙅‍♂ Not Recommended: 画像を stretch のままにし、本文の高さまで伸ばす" issue="behavior"
/* 🙅‍♂ Not Recommended */
._media {
  display: block flex;

  & > ._thumbnail {
    flex-shrink: 0;
  }
}

._thumbnail {
  inline-size: 120px;
  aspect-ratio: 16 / 9;
}
```

この例では、`aspect-ratio` を指定していても、画像は本文の高さまで伸びます。Chromeで、幅120pxの画像の横に3行の本文を置くと、画像は16:9の約68pxではなく、本文と同じ120pxの高さになりました。本書のベーススタイルは画像に `object-fit: cover` を指定しているので、画像は歪まずに上下が切り取られますが、見える範囲はカンプと変わります（「[16-1 画像の配置と比率](/decoration/images/)」）。

```css title="🙆‍♂ Recommended: 画像を交差軸の始点に置き、比率を保つ"
._media {
  display: block flex;

  & > ._thumbnail {
    flex-shrink: 0;
    align-self: start;
  }
}

._thumbnail {
  inline-size: 120px;
  aspect-ratio: 16 / 9;
}
```

`flex-shrink` と `align-self` は親のFlexboxによって意味が決まる宣言なので、親のルールの中で直下の子にネストして書きます。並べるのがGridなら、この指定は要りません。グリッドアイテムは、縦横比を持つときは引き伸ばされず、始点に置かれるからです（「[7-9 Gridでアイテムをそろえる](/layout/grid-alignment/)」）。

## Flexboxでは折り返しを既定にする

Flexboxで要素を横に並べるときは、`flex-wrap: wrap` を既定にします。`flex-wrap` の初期値は `nowrap` なので、指定しなければ、入りきらない要素は1行の中で縮み、縮みきると親からはみ出します。ヘッダーのサイト名とアカウントの表示のように、カンプでは余裕のある並びもあります。それでも、文字が長くなったときや、ユーザーが文字を大きくしたとき、狭い場所に置かれたときには入りきらなくなります。

```css title="🙅‍♂ Not Recommended: 折り返しを指定せず、狭いと1行の中で押しつぶされる" issue="behavior"
/* 🙅‍♂ Not Recommended */
._header {
  display: block flex;
  gap: 16px;
}
```

折り返しの指定があれば、入りきらない要素だけが次の行へ移ります。ブレイクポイントを決めなくても、実際の幅に応じて並びが組み替わります。折り返した後の行と行の間隔は、`gap` の1つ目の値（`row-gap`）で決まるので、`gap: 8px 16px` のように行の間隔と要素の間隔を分けて書きます。1つの値だけを書くと、折り返したときに、行の間隔が要素の間隔と同じ広さになります。

```css title="🙆‍♂ Recommended: 折り返しを既定にし、行の間隔を分けて書く"
._header {
  display: block flex;
  flex-wrap: wrap;
  gap: 8px 16px;
}
```

アカウントの表示のように行末へ寄せたい要素は、`justify-content` ではなく、その要素の `margin-inline-start: auto` で寄せます。`auto` の `margin` は行に余った空間を受け取るので、折り返して次の行に移った後も、その要素は行末に寄ったままです（「[11-1 レイアウト手法の選び方](/layout-practice/choosing/#rule-flex-auto-margin-for-end-items)」）。

`nowrap` のままにするのは、1行に収める理由がある並びだけです。ボタンの中のアイコンとラベルは、アイコンだけが次の行に落ちると意味が崩れるので、折り返さず、ラベルの中で改行させます（前の見出しの例）。タブのように、折り返すと選んでいる項目の位置が分かりにくくなる並びは、折り返さず、横スクロールで見せる選択もあります。どちらの場合も、折り返さない理由をコメントに残します。

## 要素の数や有無の変化に備える

要素の数が変わる場所でも、同じ折り返しが守りになります。タグやボタンの並びは、カンプでは2〜3個でも、運用が始まると増えていきます。この守りを毎回書き忘れないように、本書ではコンポジション `cluster` に組み込んでいます（「[12-3 cluster](/compositions/cluster/)」）。

要素の有無でレイアウトを変えたいときは、`:has()` で判定します。次の例は、画像がない記事では、本文だけの1列に切り替えるものです。JavaScriptで状態のクラスを付ける必要はありません。`:has()` の使い方は、第5章「[5-3 :has() で祖先と前の兄弟を選ぶ](/pseudo/has/)」で説明しています。

```css title="🙆‍♂ Recommended: 画像がないときは、テンプレートを1列に切り替える"
._layout {
  display: block grid;
  reading-flow: grid-rows;
  grid-template: "--body --media" / 1fr 1fr;

  &:not(:has(> ._media)) {
    grid-template: "--body" / 1fr;
  }

  & > ._body {
    grid-area: --body;
  }

  & > ._media {
    grid-area: --media;
  }
}
```

画像の上に文字を重ねるレイアウトでは、画像を読み込めなかったとき、背景と文字の色が近いと文字を読めなくなります。画像の後ろに、文字と十分なコントラストを持つ背景色を用意しておきます。画像の扱いは「[16-1 画像の配置と比率](/decoration/images/)」で説明します。

件数そのものを条件に、最終行の端数を中央に寄せたり、区画の配置を組み替えたりする方法は、「[11-5 件数で配置を組み替える](/layout-practice/quantity-layouts/)」で説明します。入りきらない文字を折り返さずに「…」で打ち切る方法と、読み込み中の表示を読み込み後と同じ寸法にする方法は、「[11-16 文字の切り詰めと読み込み中の表示](/layout-practice/truncation-and-skeletons/)」で説明します。
