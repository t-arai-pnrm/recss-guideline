この付録は、CSSをレビューするときの確認項目をまとめたチェックリストです。項目は、「[19-2 レビューの進め方](/operations/review/)」で定めた確認の順番に並べています。上にあるものほど、プロジェクト全体への影響が大きい項目です。レビューの前に目を通し、関係する項目だけを拾って使ってください。

各項目には、関係するルールのIDを添えています。指摘するときは、IDを引用すると、理由と詳しい説明をすぐに示せます。項目に当てはまらない記述でも、意図が読み取れないものは誤りと決めつけずに `Q` で質問します。反対に、プロジェクトで合意していない規約を求める指摘は `IMO` にとどめます。

インデントやプロパティの並び順は、この一覧に入れていません。整形はフォーマッターに、並び順はStylelintに任せているので、レビューで指摘するのは、自動化が機能していないときだけです。Stylelintで検出できるルールは、各ページのガイドラインの「自動チェック」の欄で分かります。このチェックリストでは、Stylelintが通ったことを前提に、人が確かめる項目を中心に挙げています。

コードを読む確認とは別に、ブラウザで条件を再現して表示と操作を確かめる手順は「[19-3 表示と操作を確かめる](/operations/verification/)」に、崩れの原因を開発者ツールで調べる手順は「[19-4 表示の崩れを開発者ツールで調べる](/operations/devtools/)」にまとめています。

## レビューの前に

- [ ] Stylelintを実行し、エラーが残っていないか（[`run-stylelint-before-done`](/operations/stylelint/#rule-run-stylelint-before-done)）
- [ ] エラーや警告を消すためだけに、ルールを無効にしていないか（[`no-disabling-to-silence`](/operations/stylelint/#rule-no-disabling-to-silence)）
- [ ] ルールを無効にする場合は、1行と1つのルールに絞り、理由を書いているか（[`disable-one-line-with-reason`](/operations/stylelint/#rule-disable-one-line-with-reason)）
- [ ] 警告を放置していないか（[`resolve-warnings`](/operations/stylelint/#rule-resolve-warnings)）
- [ ] AIが生成したCSSを、lintとレビューの両方で確かめたか（[`verify-ai-output`](/ai-coding/roles/#rule-verify-ai-output)）

## 指摘の書き方

- [ ] 指摘に、理由と解決策をセットで書いているか（[`review-reason-and-solution`](/operations/review/#rule-review-reason-and-solution)）
- [ ] `MUST`、`IMO`、`Q` のラベルで深刻度を分けているか（[`review-severity-labels`](/operations/review/#rule-review-severity-labels)）
- [ ] 合意のない好みの指摘を、`IMO` にとどめているか（[`review-preferences-as-imo`](/operations/review/#rule-review-preferences-as-imo)）
- [ ] 意図が読み取れない記述を、`Q` で質問しているか（[`review-ask-unclear-intent`](/operations/review/#rule-review-ask-unclear-intent)）
- [ ] 本書のルールに関わる指摘で、ルールのIDを添えているか（[`cite-rule-ids`](/operations/review/#rule-cite-rule-ids)）

`MUST` は、仕様やコーディング規約に反するもの、バグが起きているもの、将来深刻な問題になりそうなもの、使いやすさやアクセシビリティを損なうものに付けます。レビューを通したコードには、レビュアーも責任を負います。承認するときは、自分が書いたコードと同じ基準で見ます。

## 1. 仕様とプロジェクトの規約

プロジェクトでコーディングガイドラインが定められている場合は、それを守れているかを最優先で確かめます。本書の規約を採用しているプロジェクトなら、次の項目が対象です。

### 命名とスコープ

- [ ] コンポーネントのルートに `scoped` クラスを付け、スタイルを `@scope (.scoped.<名前>) to (.scoped)` の中に書いているか（[`scoped-class-on-root`](/notation/scope-and-nesting/#rule-scoped-class-on-root)、[`scope-with-donut`](/cascade/scope/#rule-scope-with-donut)）
- [ ] 子要素は `._`、ユーティリティは `.-` で始め、コンポジションとパターンは接頭辞なしにしているか（[`child-class-underscore`](/notation/naming/#rule-child-class-underscore)、[`utility-class-hyphen`](/notation/naming/#rule-utility-class-hyphen)、[`composition-class-plain`](/notation/naming/#rule-composition-class-plain)）
- [ ] 名前が、見た目ではなく役割を表しているか。コンポジションは配置の名前、パターンは役割の名前にしているか（[`name-by-role`](/notation/naming/#rule-name-by-role)）
- [ ] `container` や `button` のような語を、別の意味の名前に使っていないか（[`no-redefining-web-terms`](/notation/naming/#rule-no-redefining-web-terms)）
- [ ] `wrapper` や `module` のように、責務を表さない名前を使っていないか（[`no-vague-names`](/notation/naming/#rule-no-vague-names)）
- [ ] `@keyframes`、グリッドの線とエリア、アンカー、コンテナの名前と、スタイルクエリで問い合わせるフラグの値を `--` で始めているか（[`dashed-ident-names`](/notation/naming/#rule-dashed-ident-names)、[`container-name-dashed-ident`](/responsive/container-size-queries/#rule-container-name-dashed-ident)）

### カスケードとセレクタ

- [ ] IDセレクタでスタイルを指定していないか（[`no-id-selector`](/cascade/selectors/#rule-no-id-selector)）
- [ ] `.a.a` や祖先のクラスを足すような、詳細度を上げるためだけのセレクタがないか（[`no-specificity-hacks`](/cascade/selectors/#rule-no-specificity-hacks)）
- [ ] `:hover` や `[aria-expanded="true"]` のような状態のセレクタを、`:where()` で包んでいないか。まとめるときは `:is()` を使っているか（[`is-for-state-selectors`](/pseudo/is-where-not/#rule-is-for-state-selectors)）
- [ ] 詳細度や読み込み順の競争に勝つための `!important` がないか（[`no-important-for-specificity`](/cascade/cascade-basics/#rule-no-important-for-specificity)）
- [ ] レイヤーを使うプロジェクトで、読み込むCSSの先頭で9つのレイヤーの順序を宣言しているか（[`layer-order-declaration`](/cascade/layers/#rule-layer-order-declaration)）
- [ ] レイヤーを使うプロジェクトで、`@layer` の外にスタイルを書いていないか（[`no-unlayered-styles`](/cascade/layers/#rule-no-unlayered-styles)）
- [ ] ページ固有のセクションを `pages` に、使い回すコンポーネントを `components` に書いているか（[`layer-by-role`](/cascade/layers/#rule-layer-by-role)）
- [ ] CMSのように外部のCSSと共存する環境で、`@layer` を使っていないか（[`no-layers-with-unlayered-css`](/cascade/layers/#rule-no-layers-with-unlayered-css)）
- [ ] `:has()` の直前に起点を書き、引数を `>` や `+` で絞っているか（[`no-unanchored-has`](/pseudo/has/#rule-no-unanchored-has)、[`has-narrow-anchor`](/pseudo/has/#rule-has-narrow-anchor)）
- [ ] 対応が分かれる擬似クラスを、`:is()` か `:where()` の中でほかのセレクタと並べているか（[`forgiving-list-for-partial-support`](/pseudo/basics/#rule-forgiving-list-for-partial-support)）

### ネストと記法

- [ ] セレクタのネストが2層までで、ネストしたセレクタが `&` で始まっているか（[`nesting-depth-one`](/notation/nesting/#rule-nesting-depth-one)、[`nested-selector-ampersand`](/notation/nesting/#rule-nested-selector-ampersand)）
- [ ] 要素自身の擬似クラス・擬似要素・属性の状態を、`[popover]:popover-open` のように主語へ連結せず、`&:popover-open` とネストしているか（[`nest-own-states`](/notation/nesting/#rule-nest-own-states)）
- [ ] `&__title` のように、`&` に文字をつなげていないか（[`no-nesting-concatenation`](/notation/nesting/#rule-no-nesting-concatenation)）
- [ ] `@media`、`@container`、`@supports` を、各セレクタの中に書いているか（[`conditions-inside-rules`](/notation/nesting/#rule-conditions-inside-rules)）
- [ ] 直下の子へのネストに、親のレイアウトで意味が決まる宣言だけを書いているか（[`nest-child-placement-only`](/notation/nesting-criteria/#rule-nest-child-placement-only)）
- [ ] 詳細度の違うセレクタリストの中で、セレクタをネストしていないか（[`no-nesting-under-selector-list`](/notation/nesting-criteria/#rule-no-nesting-under-selector-list)）
- [ ] 寸法、余白、位置を論理プロパティで書いているか（[`logical-properties`](/notation/logical-properties/#rule-logical-properties)）
- [ ] `display` を2値構文で、変形を `translate` などの個別のプロパティで書いているか（[`display-two-value-syntax`](/notation/modern-syntax/#rule-display-two-value-syntax)、[`individual-transform-properties`](/notation/modern-syntax/#rule-individual-transform-properties)）
- [ ] 色の関数をスペース区切りで書き、`rgba()` を使っていないか（[`color-space-separated`](/notation/modern-syntax/#rule-color-space-separated)、[`no-rgba-hsla`](/notation/modern-syntax/#rule-no-rgba-hsla)）
- [ ] 必要のないベンダープレフィックスがないか（[`no-vendor-prefix`](/notation/modern-syntax/#rule-no-vendor-prefix)）

### 単位

- [ ] `font-size` をremで指定し、pxを使っていないか。ルートの文字サイズを計算のために変えていないか（[`font-size-in-rem`](/values/px-and-rem/#rule-font-size-in-rem)、[`no-root-font-size-change`](/values/px-and-rem/#rule-no-root-font-size-change)）
- [ ] `line-height` を単位のない数値で指定しているか（[`unitless-line-height`](/values/px-and-rem/#rule-unitless-line-height)）
- [ ] 文字サイズの `clamp()` で、最小値と最大値をremにし、推奨値をremと相対単位の和にしているか（[`clamp-rem-bounds`](/values/math-functions/#rule-clamp-rem-bounds)）

### フラグとスタイルクエリ

- [ ] 同じ閾値で変わる子要素が2つ以上あるとき、コンテナサイズクエリをフラグを宣言する1つのルールだけに書き、ほかの子孫はスタイルクエリで切り替えているか（[`density-via-style-query`](/components/style-queries/#rule-density-via-style-query)）
- [ ] ホバーとフォーカスで子要素や擬似要素を変えるとき、`--_hocus` を立ててスタイルクエリで切り替えているか（[`hocus-via-style-query`](/components/style-queries/#rule-hocus-via-style-query)）
- [ ] フラグの値を `--` で始め、2値の状態を `--true` と `--false` にそろえているか（[`state-flag-values`](/components/style-queries/#rule-state-flag-values)）

## 2. デザイントークン

- [ ] トークンとして定義されている値を、数値や色で直接書いていないか（[`use-defined-tokens`](/components/design-tokens/#rule-use-defined-tokens)）
- [ ] z-indexを数値ではなくトークンで指定しているか（[`z-index-tokens-only`](/components/boundaries/#rule-z-index-tokens-only)）
- [ ] トランジションの再生時間とイージングに、トークンを使っているか（[`transition-longhand-with-tokens`](/motion/transitions-and-keyframes/#rule-transition-longhand-with-tokens)）
- [ ] 新しいトークンが `--<分類>--<名前>` の形になっているか（[`token-naming-category-first`](/components/design-tokens/#rule-token-naming-category-first)）
- [ ] 1回しか使わない値や、特定のコンポーネント専用の値をトークンにしていないか（[`no-single-use-token`](/components/design-tokens/#rule-no-single-use-token)）
- [ ] 派生させた色のために、トークンやRGBの値を別に用意していないか（[`derive-colors-from-base`](/color-media/relative-color/#rule-derive-colors-from-base)）

余白のトークンは、レスポンシブの環境では `%` や `cqi` が絡み、二者択一で片付かないことが多いので、使っていなくてもあまり細かく指摘しません。

## 3. 対象のブラウザ

- [ ] 新しい機能が、対象のSafari（現行から2つ前のメジャーバージョンの最終版）で使えるか（[`browser-support-target`](/principles/browser-support/#rule-browser-support-target)、[`check-safari-support-first`](/principles/browser-support/#rule-check-safari-support-first)）
- [ ] 一部のブラウザしか対応していない機能を、未対応の環境でも内容を読めて操作できる範囲で使っているか（[`progressive-enhancement-if-harmless`](/principles/browser-support/#rule-progressive-enhancement-if-harmless)）
- [ ] アンカーポジショニングのような未対応の環境があるレイアウトの機能を、レイアウトの要にしていないか（[`no-unsupported-layout-features`](/principles/browser-support/#rule-no-unsupported-layout-features)）
- [ ] 新しい機能に合わせて既存の宣言も変える場合に、`@supports` で分岐しているか（[`supports-for-dependent-declarations`](/principles/browser-support/#rule-supports-for-dependent-declarations)）
- [ ] 対象のすべてが対応した機能のフォールバックが、残っていないか（[`remove-unneeded-fallbacks`](/principles/browser-support/#rule-remove-unneeded-fallbacks)）
- [ ] JavaScriptで表示を切り替える前提のスタイルを、`@media (scripting: enabled)` の中に書き、初期化に成功したJavaScriptが付ける属性を条件にしているか。開閉するパネルを、初期のHTMLで隠していないか（[`scripting-for-js-dependent-styles`](/principles/browser-support/#rule-scripting-for-js-dependent-styles)、[`hide-panels-after-init`](/interaction/disclosure/#rule-hide-panels-after-init)）
- [ ] ブロックレイアウトの要素に `justify-self` を指定していないか（[`no-justify-self-in-block-layout`](/principles/browser-support/#rule-no-justify-self-in-block-layout)）
- [ ] 単位のついた値での割り算を、Firefoxの安定版で宣言が無効になっても内容を読める場面で使っているか（[`typed-arithmetic-to-unitless`](/values/advanced-math-functions/#rule-typed-arithmetic-to-unitless)）
- [ ] Chromeだけでなく、Safari（iOSを含む）とFirefoxでも表示を確かめたか（[`no-chrome-only-check`](/principles/browser-support/#rule-no-chrome-only-check)）

## 4. 不要な記述と副作用のある上書き

- [ ] どの宣言も、なぜ必要かを説明できるか（[`explainable-declarations`](/design-mindset/maintainability/#rule-explainable-declarations)）
- [ ] 何にでも `width: 100%` や `height: 100%` を指定していないか（[`no-redundant-width-100`](/design-mindset/maintainability/#rule-no-redundant-width-100)、[`stretch-over-height-100`](/layout/sizing/#rule-stretch-over-height-100)）
- [ ] 幅いっぱいに広げる指定が要る要素に、`100%` ではなく `-webkit-fill-available` と `stretch` をこの順に書いているか（[`stretch-over-width-100`](/layout/sizing/#rule-stretch-over-width-100)）
- [ ] 初期値、デフォルトスタイル、リセットやベーススタイルで決まっている値を、指定し直していないか（[`no-redundant-defaults`](/design-mindset/maintainability/#rule-no-redundant-defaults)）
- [ ] 中央寄せに `margin: 0 auto` ではなく `margin-inline: auto` を使っているか（[`margin-inline-auto-centering`](/layout/box-model/#rule-margin-inline-auto-centering)）
- [ ] 一部だけを変えるのに、`background` のような影響範囲の広いショートハンドを使っていないか（[`longhand-for-partial-change`](/design-mindset/maintainability/#rule-longhand-for-partial-change)）
- [ ] kiso.cssで0になっているマージンを、`margin: 0` や `margin-block: 8px 0` で打ち消していないか。片側だけ付けるならロングハンドで書いているか（[`no-redundant-defaults`](/design-mindset/maintainability/#rule-no-redundant-defaults)、[`longhand-for-partial-change`](/design-mindset/maintainability/#rule-longhand-for-partial-change)）
- [ ] 前の値を打ち消すときに、`0` や `none` ではなく、戻したい先に合うキーワード（`revert` など）を選んでいるか（[`explicit-rollback-keyword`](/cascade/cascade-basics/#rule-explicit-rollback-keyword)）
- [ ] 継承されるプロパティを、子要素ごとに指定し直していないか（[`inherit-from-root`](/cascade/cascade-basics/#rule-inherit-from-root)）

## 5. グローバルのCSS

リセットやベーススタイルの変更は、すべてのページに影響します。変更があったときは、とくに丁寧に確かめます。

- [ ] ベーススタイルを `base` レイヤーに素のセレクタで書いているか。レイヤーを使えない環境では、セレクタを `:where()` で包み、詳細度を0にしているか（[`where-for-base-selectors`](/cascade/selectors/#rule-where-for-base-selectors)、[`no-heavy-specificity-in-global`](/reset/global-pitfalls/#rule-no-heavy-specificity-in-global)）
- [ ] 要素全体に `display` や `position` のようなレイアウトのプロパティを指定していないか（[`no-layout-properties-in-base`](/reset/global-pitfalls/#rule-no-layout-properties-in-base)）
- [ ] `* { margin: 0; padding: 0; }` や `input { appearance: none; }` のような、機能を一律に消すリセットがないか（[`reset-no-destructive-reset`](/reset/kiso/#rule-reset-no-destructive-reset)）
- [ ] `outline: none` でフォーカスリングを消していないか（[`no-outline-none`](/reset/global-pitfalls/#rule-no-outline-none)）
- [ ] フォーカスリングを `box-shadow` だけで描いていないか（[`focus-ring-not-box-shadow-only`](/reset/base-styles/#rule-focus-ring-not-box-shadow-only)）
- [ ] リストのマーカーを `list-style: none` ではなく `list-style-type: ""` で消しているか（[`list-style-type-empty-string`](/reset/global-pitfalls/#rule-list-style-type-empty-string)）
- [ ] ベースの `line-height` が1.5以上で、`line-height: 1` がないか（[`base-line-height-min`](/typography/line-height/#rule-base-line-height-min)、[`no-line-height-one`](/typography/line-height/#rule-no-line-height-one)）
- [ ] `scroll-behavior: smooth` を無条件に指定していないか（[`no-global-smooth-scroll`](/reset/base-styles/#rule-no-global-smooth-scroll)）
- [ ] ダークモードに対応しないのに `color-scheme: light dark` を指定していないか（[`no-color-scheme-without-dark-mode`](/reset/global-pitfalls/#rule-no-color-scheme-without-dark-mode)）

## 6. 内容の変化への耐性

テキストが2倍の長さになったら、画像がなかったら、要素の数が変わったら、と考えながら見ます。

- [ ] 長い見出し、画像のない記事、要素の数が違う一覧で、表示を確かめたか（[`design-for-content-changes`](/layout-practice/defensive/#rule-design-for-content-changes)）
- [ ] 幅を固定値で決めず、`max-inline-size` で上限を決めているか（[`max-inline-size-over-fixed-width`](/responsive/escalation/#rule-max-inline-size-over-fixed-width)）
- [ ] 高さを `block-size` で固定せず、`min-block-size` や `aspect-ratio` で決めているか（[`min-block-size-over-fixed-height`](/layout-practice/defensive/#rule-min-block-size-over-fixed-height)）
- [ ] 縦の `margin` を、`* + *` で選んだ後ろの要素の `margin-block-start` に付けているか（[`block-margin-with-sibling-combinator`](/layout-practice/spacing/#rule-block-margin-with-sibling-combinator)）
- [ ] `minmax()` や `min-inline-size` の固定の最小値を、`min(100%, …)` で包んでいるか（[`minmax-min-capped-at-100-percent`](/layout-practice/defensive/#rule-minmax-min-capped-at-100-percent)）
- [ ] ベーススタイルで全称セレクタに `min-inline-size: 0` を指定したうえで、列を `minmax(0, 1fr)` ではなく `1fr` で分けているか（[`fr-without-minmax-zero`](/layout-practice/defensive/#rule-fr-without-minmax-zero)）
- [ ] 要素の数が変わるFlexboxに `flex-wrap: wrap` を指定しているか（[`flex-wrap-for-variable-items`](/layout-practice/defensive/#rule-flex-wrap-for-variable-items)）
- [ ] 列数を子要素の数ではなく、`auto-fit` やコンテナサイズクエリで切り替えているか（[`quantity-query-for-count-conditions`](/pseudo/quantity-queries/#rule-quantity-query-for-count-conditions)）
- [ ] 理由のない `white-space: nowrap` がないか（[`no-nowrap-without-reason`](/layout-practice/defensive/#rule-no-nowrap-without-reason)）
- [ ] はみ出しを切り取るのに、`hidden` ではなく `clip` を使っているか（[`overflow-clip-over-hidden`](/layout-practice/overflow/#rule-overflow-clip-over-hidden)）
- [ ] 横スクロールを隠す前に、はみ出している要素を特定して直したか（[`find-overflow-source-first`](/layout-practice/overflow/#rule-find-overflow-source-first)）
- [ ] 画像の上の文字に、画像が表示されなくても読める背景色があるか（[`text-on-image-fallback-background`](/decoration/images/#rule-text-on-image-fallback-background)）
- [ ] ブラウザの文字サイズの設定を大きくして、表示を確かめたか（[`verify-with-text-scaling`](/values/px-and-rem/#rule-verify-with-text-scaling)）

## 7. コンポーネントの境界

- [ ] 見た目が似ているだけのものを、1つのコンポーネントにまとめていないか（[`component-split-by-role`](/components/what-is-a-component/#rule-component-split-by-role)、[`rule-of-three`](/design-mindset/maintainability/#rule-rule-of-three)）
- [ ] コンポーネントごとにCSSのファイルを分け、複数のコンポーネントのCSSを1つのファイルに混ぜていないか（[`one-component-per-file`](/components/boundaries/#rule-one-component-per-file)）
- [ ] コンポーネントのルートに、`margin` や `grid-area` のような外部関連型のレイアウトを指定していないか（[`no-external-layout-on-root`](/components/boundaries/#rule-no-external-layout-on-root)）
- [ ] 子のコンポーネントの配置と外側の余白を、親の `gap` やOuterで決めているか（[`parent-owns-child-placement`](/components/boundaries/#rule-parent-owns-child-placement)）
- [ ] ほかのコンポーネントのルートや内部の要素を、セレクタで選んで上書きしていないか（[`no-other-component-internals`](/components/boundaries/#rule-no-other-component-internals)）
- [ ] パターンに、重ねるコンポーネントが指定するプロパティを書いていないか。コンポーネントの側で変える値を公開プロパティで受け取っているか（[`pattern-leaves-component-properties`](/components/compositions-and-utilities/#rule-pattern-leaves-component-properties)）
- [ ] コンポーネントの中の要素をタイプセレクタで選び、子クラスは同じ種類の要素を役割で区別するときと、`div` と `span` に役割を示すときだけ付けているか。`a:hover` のような擬似クラス付きのタイプセレクタで、子クラスのスタイルを打ち消していないか（[`type-selector-in-scope`](/components/boundaries/#rule-type-selector-in-scope)）
- [ ] 外から変えてよい値を `--<コンポーネント>--<プロパティ>` の公開プロパティにし、内部で使う値を `--_` で始めているか（[`public-property-naming`](/components/custom-properties/#rule-public-property-naming)、[`internal-property-prefix`](/components/custom-properties/#rule-internal-property-prefix)）
- [ ] 公開プロパティを自分で宣言せず、内部プロパティで受けてフォールバックにデフォルト値を書いているか（[`receive-public-property-with-fallback`](/components/custom-properties/#rule-receive-public-property-with-fallback)）
- [ ] ルートには絶対的なz-indexだけを、内部には相対的なz-indexだけを指定しているか（[`z-index-absolute-root-relative-inside`](/components/boundaries/#rule-z-index-absolute-root-relative-inside)）
- [ ] 内部で相対的なz-indexを使うコンポーネントは、重なりを閉じ込めるルートか内部の区画に `isolation: isolate` があるか（[`isolation-for-relative-z-index`](/components/boundaries/#rule-isolation-for-relative-z-index)）

## 8. レスポンシブ

- [ ] 「静的 → イントリンシック → コンテナサイズクエリ → メディアクエリ」の順に検討し、不要なクエリを書いていないか（[`responsive-escalation-order`](/responsive/escalation/#rule-responsive-escalation-order)）

- [ ] `cqi` を、名前付きのコンテナがあると言い切れる要素でだけ使っているか（[`cqi-needs-named-container`](/responsive/container-units-and-side-effects/#rule-cqi-needs-named-container)）

- [ ] ブレイクポイントを、デバイスの幅ではなくレイアウトが崩れる幅から決めているか（[`breakpoint-from-content`](/responsive/breakpoints/#rule-breakpoint-from-content)）
- [ ] `sp` や `pc` のようなデバイスの名前を使っていないか（[`no-device-names`](/responsive/breakpoints/#rule-no-device-names)）
- [ ] メディアクエリの条件と、コンテナサイズクエリの条件の中で `var()` を使っていないか（[`no-var-in-query`](/responsive/breakpoints/#rule-no-var-in-query)）
- [ ] `vw`、`vh`、`vi`、`vb`、`vmin`、`vmax` を使っていないか（[`no-vw-vh`](/values/viewport-and-container-units/#rule-no-vw-vh)）

## 9. コメント

## あわせて確かめる項目

次の項目は、確認の順番の9つには含まれていません。しかし、使いやすさやアクセシビリティを損なうものは `MUST` の対象です。関係するスタイルがあれば、あわせて確かめます。

- [ ] ホバーを `&:any-link:hover` や `&:enabled:hover` のように操作できる状態に限り、`@media (any-hover)` の中に書いているか（[`hover-operable-in-any-hover`](/interaction/states-and-focus/#rule-hover-operable-in-any-hover)）。`:focus-visible` にも同じ見た目を指定しているか（[`hover-with-focus-visible`](/interaction/states-and-focus/#rule-hover-with-focus-visible)）
- [ ] 状態を `.is-active` のようなクラスではなく、擬似クラスやARIA属性で表しているか（[`state-by-pseudo-class-or-aria`](/interaction/state-attributes/#rule-state-by-pseudo-class-or-aria)）
- [ ] 動きに目的があり、高い頻度で触るUIに装飾的な動きを足していないか（[`motion-needs-purpose`](/motion/purpose/#rule-motion-needs-purpose)）
- [ ] 装飾的な動きのうちフェード以外を `@media (prefers-reduced-motion: no-preference)` の中で指定しているか（[`motion-only-with-no-preference`](/motion/reduced-motion/#rule-motion-only-with-no-preference)）
- [ ] 機能的な動きの大きな変動を、動きを減らす設定でフェードに置き換えているか。DevToolsで `prefers-reduced-motion: reduce` をエミュレートして確かめたか（[`simplify-large-motion-when-reduced`](/motion/reduced-motion/#rule-simplify-large-motion-when-reduced)）
- [ ] 機能的な動きの再生時間が300ms以下（大きなUIでも500ms以下）か。イージングは標準のキーワードではなくトークンで、現れる動きと出ていく動きは `ease-out` 系、画面の上にあるものの移動は `ease-in-out` 系か。`ease-in` 系を使っていないか（[`functional-motion-under-300ms`](/motion/easing-and-duration/#rule-functional-motion-under-300ms)、[`no-ease-in-for-ui`](/motion/easing-and-duration/#rule-no-ease-in-for-ui)）
- [ ] 拡大して現れる動きを `scale: 0` から始めず、`transform-origin` をトリガーのある側に向けているか（[`scale-in-from-near-one`](/motion/easing-and-duration/#rule-scale-in-from-near-one)）
- [ ] キーボードでフォーカスを受けた要素の見た目を、動きを付けずに一度で切り替えているか（[`no-motion-on-focus-visible`](/interaction/states-and-focus/#rule-no-motion-on-focus-visible)）
- [ ] キーボードショートカットで開閉するUIに、出現と退場の動きを付けていないか（[`no-motion-on-keyboard-shortcut`](/motion/purpose/#rule-no-motion-on-keyboard-shortcut)）
- [ ] 途中で取り消される動きをトランジションで書き、続けて押されるUIの動きを短くするか省いているか（[`interruptible-with-transition`](/motion/transitions-and-keyframes/#rule-interruptible-with-transition)）
- [ ] レイアウトの変わるプロパティを動かしていないか。`clip-path`、`background-color`、`filter` を動かすときは、描き直しが起きないことをDevToolsで確かめたか。影を `box-shadow` ではなく `filter: drop-shadow()` で動かしているか。`will-change` をCSSに書いたままの状態にしていないか（[`animate-composite-properties`](/motion/performance/#rule-animate-composite-properties)、[`no-animate-layered-shadow`](/decoration/surfaces/#rule-no-animate-layered-shadow)、[`will-change-temporarily`](/motion/performance/#rule-will-change-temporarily)）
- [ ] `content-visibility: auto` を最初の画面より下のブロックにだけ指定しているか。`contain-intrinsic-block-size: auto <長さ>` を組で書いているか（[`content-visibility-with-intrinsic-size`](/motion/performance/#rule-content-visibility-with-intrinsic-size)）
- [ ] `@keyframes` の名前が `--` で始まり、中間のフレームを持つものをコンポーネントのCSSに置いているか。一度だけ再生する演出で、`@keyframes` の外に `opacity: 0` などを重ねて書いていないか（[`keyframes-local-naming`](/motion/keyframes/#rule-keyframes-local-naming)、[`reveal-once-with-style-query`](/motion/scroll-driven/#rule-reveal-once-with-style-query)）
- [ ] `transition: all` を使っていないか（[`no-transition-all`](/motion/transitions-and-keyframes/#rule-no-transition-all)）
- [ ] 開閉するUIを、`<dialog>`、`popover` 属性、`<details>` のようなHTMLの機能で作っているか（[`native-disclosure-elements`](/interaction/disclosure/#rule-native-disclosure-elements)）
- [ ] リンクや入力エラーのような情報を、色の違いだけで伝えていないか（[`no-color-only-information`](/color-media/forced-colors/#rule-no-color-only-information)、[`grayscale-check`](/color-media/forced-colors/#rule-grayscale-check)）
- [ ] 文字と背景のコントラスト比が、WCAG 2.1のAAを満たしているか（[`text-contrast-aa`](/color-media/forced-colors/#rule-text-contrast-aa)）
- [ ] 枠線を `border: none` ではなく `border-color: transparent` で消しているか（[`transparent-border-over-none`](/color-media/forced-colors/#rule-transparent-border-over-none)）
- [ ] 要素の境界を `box-shadow` だけで描いていないか。切り抜いた図形の色を、`--background--current` から受け取っているか（[`no-box-shadow-only-boundary`](/color-media/forced-colors/#rule-no-box-shadow-only-boundary)、[`background-current-for-shapes`](/color-media/forced-colors/#rule-background-current-for-shapes)）
- [ ] 操作する要素に、24px相当の押せる範囲を確保しているか（[`hit-area-min-size`](/interaction/hit-area-and-touch/#rule-hit-area-min-size)）
- [ ] `grid-template-areas` や `*-reverse` で並べ替えたルールに、`reading-flow` を指定しているか（[`reading-flow-when-reordered`](/layout-practice/reading-flow/#rule-reading-flow-when-reordered)）
- [ ] 必須の印や単位のように読み手が知る必要のある文字を、`content` で入れていないか（[`no-meaningful-generated-content`](/pseudo/generated-content/#rule-no-meaningful-generated-content)）
- [ ] `::placeholder` の文字と背景のコントラスト比が4.5:1以上か（[`placeholder-color-contrast`](/pseudo/form-states/#rule-placeholder-color-contrast)）
- [ ] 入力欄の文字サイズが1rem以上で、ズームを止める指定がないか（[`input-font-size-min-1rem`](/interaction/forms/#rule-input-font-size-min-1rem)、[`no-maximum-scale`](/interaction/forms/#rule-no-maximum-scale)）
- [ ] `<img>` に `width` と `height` の属性があり、ファーストビューの画像を遅延読み込みにしていないか（[`img-width-height-attributes`](/decoration/images/#rule-img-width-height-attributes)、[`no-lazy-loading-first-view`](/decoration/image-loading/#rule-no-lazy-loading-first-view)）

## AIが生成したコードを見るとき

AIが生成したCSSでは、Stylelintで検出できない誤りが残りやすくなります。重点的に確かめるのは、各ページのガイドラインの「注意」の欄に、AIが誤りやすいと書いたルールです。付録Bでは、「AI」の列に印のある行に当たります。よく見かける古い書き方と置き換え先は、付録B「[モダンな書き方への置き換え表](/appendix/modernize/)」にまとめています。

- [ ] 名前のないコンテナや、コンテナにした要素そのものを条件にしたクエリがないか（[`container-name-required`](/responsive/container-size-queries/#rule-container-name-required)）
- [ ] ブレイクポイントが `768px` のような慣習の値ではなく、レイアウトが成り立つ条件から決めた値になっているか（[`breakpoint-from-content`](/responsive/breakpoints/#rule-breakpoint-from-content)、[`threshold-as-formula`](/responsive/breakpoints/#rule-threshold-as-formula)）
- [ ] 閾値の式が「列の最小幅×列数」で終わらず、列数から決まる隙間（`gap`）の数や、`padding` と `border` まで含んでいるか（[`threshold-includes-gap-and-padding`](/responsive/breakpoints/#rule-threshold-includes-gap-and-padding)）
- [ ] 何にでも付いた `width: 100%` や、中央寄せの `margin: 0 auto` がないか（[`no-redundant-width-100`](/design-mindset/maintainability/#rule-no-redundant-width-100)、[`margin-inline-auto-centering`](/layout/box-model/#rule-margin-inline-auto-centering)）
- [ ] 上書きが効かない原因を調べずに足した `!important` がないか（[`no-important-for-specificity`](/cascade/cascade-basics/#rule-no-important-for-specificity)）
- [ ] `._list` や `._link` のように、要素の種類を言い換えただけの子クラスをすべての要素に付けていないか（[`type-selector-in-scope`](/components/boundaries/#rule-type-selector-in-scope)）
- [ ] 宣言を1つずつ言い換えたコメントが付いていないか（[`comments-why-only`](/notation/comments/#rule-comments-why-only)）
- [ ] `DESIGN.md` に色や余白の値を書き写さず、値で表せない判断だけを書いて、トークンを名前で参照しているか（[`design-md-without-values`](/ai-coding/setup/#rule-design-md-without-values)）
- [ ] AIの出力を直した内容を、プロジェクトの規約の文書に書き足したか（[`record-ai-corrections`](/ai-coding/verify-output/#rule-record-ai-corrections)）
- [ ] 既存のCSSの監査では、AIに一覧を作らせるだけにし、直す項目を人が選んでから直したか（[`audit-list-before-fix`](/ai-coding/audit/#rule-audit-list-before-fix)）
- [ ] 作業を並行させたとき、同じファイルを2つのエージェントに書き換えさせていないか（[`single-writer-per-file`](/ai-coding/audit/#rule-single-writer-per-file)）
