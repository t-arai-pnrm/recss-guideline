この付録は、本書で使う用語の一覧です。CSSの仕様の用語に加えて、「外部関連型のレイアウト」のように、本書や著者の資料で名前を付けた考え方も含めています。意味は本文での説明に合わせて短くまとめ、詳しく説明しているページへのリンクを添えました。

用語は分野ごとの表に分けています。知らない用語に出会ったときの確認に使うほか、AIに本書を読ませるときの用語の対応表としても使えます。本書の中では、同じものを表すときは、この一覧の語を使うようにしています。

表記の揺れやすい語は、最後の「[表記の決まり](#表記の決まり)」にまとめています。原稿の表記は、textlintの辞書（`prh.yml`）で検証しています。

## 考え方とブラウザ対応

| 用語 | 意味 | 詳しい説明 |
| --- | --- | --- |
| 提案書としてのCSS | CSSはブラウザへの命令書ではなく提案書だという考え方です。実装者は上限、下限、比率のような条件を決め、具体的な値の計算はブラウザに任せます。 | [1-1](/principles/browser-suggestion/) |
| ピクセルパーフェクト | デザインカンプと、カンプと同じ幅のような限られた環境でのブラウザの表示を、1pxのずれもなく一致させることです。表示の環境が無数にあるWebでは、すべての環境でこの一致を保てないので、本書はこれを目指しません。 | [1-1](/principles/browser-suggestion/)、[3-1 ピクセルではなく意図を再現する](/design-reproduction/intent/) |
| 合格点 | 限られた環境での満点（ピクセルパーフェクト）ではなく、どの環境で見てもデザインの意図が伝わり、内容を読めて操作できる状態です。「デザインの意図パーフェクト」とも言います。 | [1-1](/principles/browser-suggestion/) |
| イントリンシック（intrinsic） | 「本来備わっている」という意味です。要素の中身やレイアウトの仕組みが持つ伸び縮みの性質を活かし、計算をブラウザに任せる設計を、イントリンシック・デザインと呼びます。 | [1-1](/principles/browser-suggestion/)、[13-1](/responsive/escalation/) |
| デフォルト値 | 本書では、CSSの初期値、ブラウザのデフォルトスタイル、リセットCSSの値、ベーススタイルの値をまとめてこう呼びます。表記は、このページの最後の表のとおりです。 | [2-3](/design-mindset/maintainability/) |
| プログレッシブ・エンハンスメント | 未対応の環境でも内容を読めて操作でき、対応した環境ではより良い体験になる範囲で、新しい機能を使うことです。中黒を入れて書きます。 | [1-2](/principles/browser-support/) |
| Baseline | web-featuresのデータで、機能がどれだけのブラウザで使えるかを示す指標です。「広く利用可能」「新しく利用可能」「一部のブラウザのみ」の3段階で表示します。 | [1-2](/principles/browser-support/) |

## カスケードとセレクタ

| 用語 | 意味 | 詳しい説明 |
| --- | --- | --- |
| カスケード | 同じ要素の同じプロパティに複数の値があるとき、使う値を決める手順です。オリジンと重要度、`style` 属性、レイヤー、詳細度、スコープの近さ、出現順などを決まった順に比べます。 | [4-1](/cascade/cascade-basics/) |
| 詳細度 | セレクタの強さです。IDの数、クラス・属性・擬似クラスの数、タイプセレクタ・擬似要素の数の3つで表し、本書では「0.1.1」のようにドットでつないで書きます。 | [4-1](/cascade/cascade-basics/)、[4-2](/cascade/selectors/) |
| カスケードレイヤー | `@layer` で分けたスタイルのまとまりです。通常の宣言では後ろのレイヤーほど強く（`!important` の宣言では逆になります）、詳細度より先に比べられます。本書の基本は `tokens` から `utilities` までの9つです。略して「レイヤー」と書きます。 | [4-3](/cascade/layers/) |
| スコープ | `@scope` で、スタイルが当たる範囲をルートと下限の間に限る仕組みです。ルートは `:scope` で選びます。 | [4-4](/cascade/scope/) |
| ドーナツスコープ | `@scope (.scoped.<名前>) to (.scoped)` のように下限を付け、入れ子になった別のコンポーネントを範囲から外したスコープです。穴の開いたドーナツにたとえた呼び名です。 | [4-4](/cascade/scope/) |

## 擬似クラスと擬似要素

| 用語 | 意味 | 詳しい説明 |
| --- | --- | --- |
| 擬似クラス | `:hover` や `:checked` のように、要素の状態や位置を条件にして要素そのものを選ぶセレクタです。コロン1つで書き、詳細度は原則としてクラスと同じ0.1.0です。`:is()`、`:not()`、`:has()` は引数の詳細度になり、`:where()` は0です。 | [5-1](/pseudo/basics/) |
| 擬似要素 | `::before` や `::first-line` のように、要素の一部や、CSSが生成した箱を選ぶセレクタです。コロン2つで書き、詳細度はタイプセレクタと同じ0.0.1です。 | [5-1](/pseudo/basics/) |
| 寛容なセレクタリスト | 解釈できないセレクタがあっても、それだけを無視して残りを有効にするセレクタリストです。`:is()` と `:where()` の引数がこれに当たり、普通のセレクタリストと `:not()`・`:has()` の引数は当たりません。 | [5-1](/pseudo/basics/) |
| 起点（`:has()` の） | `A:has(B)` の `A` のように、`:has()` の直前に書いてスタイルを当てる要素です。本書では起点のない `:has()` を禁止しています。 | [5-3](/pseudo/has/) |
| 数量クエリ | 子要素の数に応じてスタイルを切り替える手法です。本書では、親や兄弟の見た目を変えるときは `&:has(> :nth-child(3))` のように親を起点にした `:has()` で書き、数えた子要素そのものを変えるときは `:nth-child()` と `:nth-last-child()` を組み合わせて書きます。 | [5-5](/pseudo/quantity-queries/) |
| 生成コンテンツ | `::before` と `::after` の `content` プロパティで、CSSが要素の前後に入れる文字や箱です。 | [5-8](/pseudo/generated-content/) |

## 値と単位

| 用語 | 意味 | 詳しい説明 |
| --- | --- | --- |
| スモールビューポート、ラージビューポート、ダイナミックビューポート | ブラウザのUIが表示されているときの最も小さい領域、UIが引っ込んだときの最も大きい領域、そのときどきで見えている領域です。単位は `sv*`、`lv*`、`dv*` で始まります。 | [6-2](/values/viewport-and-container-units/) |
| コンテナ単位 | コンテナの大きさを基準にした単位です。本書で使うのは、コンテナのインライン方向のサイズの1%を表す `cqi` です。 | [6-2](/values/viewport-and-container-units/)、[13-4](/responsive/container-units-and-side-effects/) |
| 流体的な値 | `clamp()` などで、幅に応じて最小値と最大値の間を連続的に変わる値です。文字サイズに使うものを流体的な文字サイズと呼びます。 | [6-3](/values/math-functions/)、[14-4](/typography/size-and-line-breaks/) |

## リセットと記法

| 用語 | 意味 | 詳しい説明 |
| --- | --- | --- |
| リセットCSS | ブラウザごとに異なるデフォルトスタイルをそろえるためのCSSです。本書では、著者が公開しているkiso.cssを使います。 | [8-1](/reset/kiso/) |
| ベーススタイル | リセットの上に、フォーカスリングや色、フォントのような、プロジェクト全体の既定を書くスタイルです。`base` レイヤーに置きます。 | [8-2](/reset/base-styles/) |
| フォーカスリング | キーボードで操作するユーザーに、いまどこにフォーカスがあるかを伝える表示です。本書では、`outline` と `box-shadow` を重ねた二重のリングにします。 | [8-2](/reset/base-styles/) |
| 論理プロパティ | 上下左右ではなく、書字方向を基準に方向を表すプロパティです。`width` の代わりに `inline-size`、`margin-top` の代わりに `margin-block-start` と書きます。 | [9-9](/notation/logical-properties/) |
| 2値構文 | `display` の値を、外側の表示と内側の表示の2つで書く構文です。`display: flex` は `block flex` と書きます。 | [9-8](/notation/modern-syntax/) |
| `<dashed-ident>` | `--` で始まる名前のことです。本書では、`@keyframes`、グリッドの線とエリア、アンカー、コンテナ、スタイルクエリの値のように、自分で付けて値として使う名前をこの形にします。 | [9-1](/notation/naming/) |

## コンポーネントとカスタムプロパティ

| 用語 | 意味 | 詳しい説明 |
| --- | --- | --- |
| コンポーネント | HTMLの構造や属性、振る舞いを1つの定義から管理する部品です。ルートに `class="scoped <名前>"` を付け、スタイルは `@scope` の中に書きます。 | [10-1](/components/what-is-a-component/)、[10-2](/components/boundaries/)、[9-1](/notation/naming/) |
| 外部関連型のレイアウト | `margin`、`position: absolute` と `inset`、`grid-area` のように、周りの要素との関係で成り立つレイアウトの指定です。著者の造語で、コンポーネントのルートには書きません。 | [10-2](/components/boundaries/) |
| 内部関連型のレイアウト | `padding` や `grid-template` のように、自分のスタイルだけで完結するレイアウトの指定です。コンポーネントのルートに書いてかまいません。 | [10-2](/components/boundaries/) |
| Outer | 親のコンポーネントが、子のコンポーネントを包むために置く要素です。子の配置や特別な余白を、親の側で決めます。単独のコンポーネントにはしません。 | [10-2](/components/boundaries/) |
| コンポジション | `stack`、`cluster`、`switcher` のように、コンポーネントに依存しない配置を受け持つクラスです。配置だけを持ち、見た目は持ちません。 | [10-3](/components/compositions-and-utilities/) |
| ユーティリティ | `.-visually-hidden` のように、どこに付けても同じ意味を持つ単機能のクラスです。最後の `utilities` レイヤーに置きます。 | [10-3](/components/compositions-and-utilities/) |
| デザイントークン | 色、余白、イージング、z-indexのように、サイト全体で意味を持つ値に名前を付けたものです。`--<分類>--<名前>` の形で `:root` に定義します。略して「トークン」と書きます。 | [10-4](/components/design-tokens/) |
| プリミティブ、セマンティクス | 色のトークンの2つの層です。プリミティブは明るさの段階で並べた生の色、セマンティクスは背景や文字のような色の役割を表すトークンです。 | [10-4](/components/design-tokens/) |
| 公開プロパティ | コンポーネントが、外から変えてよい値として用意するカスタムプロパティです。`--<コンポーネント>--<プロパティ>` の形にします。 | [10-5](/components/custom-properties/) |
| 内部プロパティ | コンポーネントの中だけで使うカスタムプロパティです。`--_` で始めます。 | [10-5](/components/custom-properties/) |
| 状態の接尾辞 | 状態やモードで変わる値を、`--_background--hocus` のように `--` で区切って名前の後ろに付けた部分です。`hocus` はホバーとフォーカスをまとめた語です。 | [10-5](/components/custom-properties/) |

## レイアウト

| 用語 | 意味 | 詳しい説明 |
| --- | --- | --- |
| レイアウトの方式 | 子の大きさと位置を決める規則のまとまりです。通常フロー、Flexbox、Grid、位置指定などがあり、親の `display` の内側の値と、要素自身の `position` で決まります。同じプロパティでも、方式によって働き方が変わります。レイアウトモードとも言います。 | [1-3](/principles/layout-algorithms/)、[7-1](/layout/fundamentals/) |
| 通常フロー | FlexboxやGridを指定していない要素が従う、既定のレイアウトの方式です。ブロックレベルのボックスはブロック方向に積まれ、インラインレベルのボックスは行の中をインライン方向に流れます。 | [7-2](/layout/normal-flow/) |
| ブロック整形コンテキスト | 通常フローのブロックを並べる、閉じた範囲です。中の `float` を内側に収め、外とのマージンの相殺を止めます。本書では `display: flow-root` で作ります。 | [7-2](/layout/normal-flow/)、[7-6](/layout/margin-collapse/) |
| 読み上げ順 | スクリーンリーダーが読み上げ、キーボードでフォーカスが移る順番です。DOMの順番で決まり、`reading-flow` を指定したコンテナでは見た目の順番に合わせられます。 | [11-12](/layout-practice/reading-flow/) |
| サブグリッド | `grid-template-rows: subgrid` のように、親のグリッドの行や列をそのまま使う仕組みです。並べたカードの中の行をそろえるときに使います。 | [7-9](/layout/grid-alignment/) |
| ガター | ページのコンテンツの左右に置く、余白のための列です。画面幅いっぱいに広げたい要素は、この列まで広げます。 | [11-2](/layout-practice/spacing/) |
| 次兄弟結合子 | `h2 + p` の `+` のように、直前の兄弟要素を条件にして要素を選ぶ結合子です。本書では、要素の間のブロック方向の `margin` を、`& > * + *` のようにこの結合子で選んだ後ろの要素の `margin-block-start` に付けます。 | [11-2](/layout-practice/spacing/) |
| ディフェンシブCSS | テキストが長くなったら、画像がなかったら、要素の数が変わったらと考え、想定外の内容が入っても崩れないように書くCSSです。 | [11-3](/layout-practice/defensive/) |
| 包含ブロック | 要素の大きさや位置を計算するときの基準になる領域です。`inset` やパーセントの値も、この領域を基準に解決されます。絶対配置では、包含ブロックを形成する最も近い祖先が基準です。`position` が `static` 以外の祖先や、`transform` などを指定した祖先が該当します。該当する祖先がなければ初期包含ブロックが基準になります。 | [7-10](/layout/positioning/) |
| スタッキングコンテキスト | 重なり順を決める単位です。z-indexは、同じスタッキングコンテキストの中の要素どうしでしか比べられません。 | [11-6](/layout-practice/layering/) |
| トップレイヤー | `<dialog>` のモーダルや `popover` 属性の要素が表示される層です。本来は、z-indexと関係なく最前面に描かれます。 | [10-2](/components/boundaries/)、[17-6](/interaction/disclosure/) |
| アンカーポジショニング | ある要素（アンカー）の位置を基準に、別の要素を配置する仕組みです。本書の対象のブラウザではまだレイアウトの要にしません。 | [7-11](/layout/anchor-basics/) |

## レスポンシブ

| 用語 | 意味 | 詳しい説明 |
| --- | --- | --- |
| 検討の順番 | レスポンシブ対応を「静的 → イントリンシック → コンテナサイズクエリ → メディアクエリ」の順に検討し、上の段階で解決できるなら下の段階を使わないという本書の原則です。 | [13-1](/responsive/escalation/) |
| コンテナクエリ | `@container` で、祖先の要素（コンテナ）の状態を条件にするクエリの総称です。サイズを調べるコンテナサイズクエリ、カスタムプロパティの値を調べるスタイルクエリ、スクロールの状態を調べるスクロール状態クエリの3つを含みます。 | [13-3](/responsive/container-size-queries/) |
| コンテナサイズクエリ | ビューポートではなく、コンテナの大きさで条件を判定するコンテナクエリです。`container: --scoped / inline-size` でコンポーネントのルートをコンテナにし、`@container --scoped (inline-size >= …)` のように書きます。 | [13-3](/responsive/container-size-queries/) |
| スタイルクエリ | コンテナのカスタムプロパティの値を条件にするコンテナクエリです。`@container style(--color-scheme--current: --dark)` のように書きます。 | [6-5](/values/if-and-attr/)、[13-3](/responsive/container-size-queries/)、[15-4](/color-media/dark-mode/) |
| スクロール状態クエリ | `sticky` の要素が留まっているか、スクロールスナップで止まっているかのような、スクロールの状態を条件にするコンテナクエリです。`@container scroll-state(stuck: block-start)` のように書きます。 | [11-7](/layout-practice/sticky-header/)、[17-8](/interaction/carousel/) |
| ブレイクポイント | レイアウトを切り替える幅です。デバイスの幅ではなく、レイアウトが崩れる幅から決め、remの式で書きます。 | [13-2](/responsive/breakpoints/) |
| 範囲構文 | `min-width` の代わりに、`(width >= …)` のように不等号でクエリの条件を書く構文です。 | [13-5](/responsive/media-queries/) |
| モバイルファースト | 狭い画面向けのスタイルを基本に書き、広い画面で必要な差分だけを `width >=` の条件の中に足す書き方です。 | [13-5](/responsive/media-queries/) |
| フルリキッド | カンプの幅に対する比率で、ページ全体の文字サイズや余白を拡大・縮小する組み方です。本書では使わず、拡大・縮小させたい局所だけをコンテナ単位で組みます。 | [13-7](/responsive/design-comp-pattern/) |

## タイポグラフィ

| 用語 | 意味 | 詳しい説明 |
| --- | --- | --- |
| ハーフレディング | 行の高さが文字の大きさより大きいとき、その差が文字の上と下に半分ずつ配分された余白です。中黒を入れずに書きます。 | [14-3](/typography/line-height/) |
| ベタ組み | 全角の文字を1文字ずつ同じ幅の枠に収め、詰めずに並べる組み方です。本書では、和文の本文をベタ組みにします。 | [14-2](/typography/japanese-typesetting/) |

| 約物 | 括弧や句読点のような記号です。開き括弧、閉じ括弧、読点、句点は、全角の幅の中に、半分ほどのアキを含んでいます。 | [14-2](/typography/japanese-typesetting/) |
| `palt` | フォントが持つ文字ごとの幅の情報（プロポーショナルメトリクス）を使い、仮名や約物の周りのアキを詰めるOpenTypeの機能です。見出しと表の `caption` にだけ使います。 | [14-2](/typography/japanese-typesetting/) |
