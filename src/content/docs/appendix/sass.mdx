本書のコード例は、すべて素のCSSで書いています。かつてSassが必要だった変数、ネスト、計算、色の加工は、いまはCSSの標準の機能で書けます。この付録では、Sassでよく使う機能ごとに、本書での書き方を対応させます。

まず次の一覧表で置き換え先を確かめ、詳しくは各見出しの説明と、リンク先の本文を読んでください。1対1で置き換わる機能ばかりではありません。mixinや `@extend` のように、同じ結果をCSSの設計の側で実現するものもあります。表の「詳しい説明」の列には、その書き方を説明している本文のページを挙げています。

私も2020年ごろは、ブレイクポイントのmapとmixin、pxをremに変換する関数などをSassで用意していました。本書の書き方は、それらを標準の機能に置き換えたものです。Sassの書き方をそのまま持ち込んだコードは、AIの出力にもよく見られます。見分け方は付録B「[モダンな書き方への置き換え表](/appendix/modernize/)」とあわせて確かめてください。

## 変数はカスタムプロパティにする

Sassの変数は、カスタムプロパティに置き換えます。色や余白のように、サイト全体で意味を持つ値は、`--<分類>--<名前>` の形のトークンにして `:root` に置きます。トークンは分類ごとのファイルに分け、`tokens` レイヤーに読み込みます。命名と置き場所は「[10-4 デザイントークン](/components/design-tokens/)」で説明しています。

1つのコンポーネントの中だけで使う値は、`--_` で始まる内部プロパティにします。外から変えてよい値は、`--<コンポーネント>--<プロパティ>` の公開プロパティとして受け取ります。Sassの `!default` のように「指定がなければこの値」を表すときは、公開プロパティを内部プロパティで受け、デフォルト値を `var()` のフォールバックに書きます。

```scss title="Sass：変数と !default"
$color-accent: #1f6feb;
$card-radius: 8px !default;

.card {
  border-radius: $card-radius;
  background-color: $color-accent;
}
```

まず、変数をカスタムプロパティに移すだけの段階を示します。名前の付け方と値の参照の仕方は、Sassのときのままです。

```css title="Sassの変数を、そのままカスタムプロパティに移す（規約にはまだ合わせていない）"
:root {
  --color--accent--500: oklch(52% 0.16 250deg);
  --card--radius: 8px;
}

.card {
  border-radius: var(--card--radius);
  background-color: var(--color--accent--500);
}
```

この段階でも値はブラウザの中で使えますが、コンポーネントが色の段階（`500`）を直接参照しているので、ダークモードのように色の役割ごとに値を切り替えたいとき、使う場所をすべて探すことになります。`!default` の意味も失われ、半径の値が `:root` に出ています。本書の設計に整えると、次のようになります。

```css title="🙆‍♂ Recommended: 色はセマンティクスのトークンを通し、半径はフォールバック付きの公開プロパティで受ける"
:root {
  --color--accent--500: oklch(52% 0.16 250deg);
  --background--accent: var(--color--accent--500);
}

@scope (.scoped.card) to (.scoped) {
  :scope {
    --_radius: var(--card--radius, 8px);

    border-radius: var(--_radius);
    background-color: var(--background--accent);
  }
}
```

変えたのは3点です。色は、プリミティブの `--color--accent--500` をセマンティクスの `--background--accent` で参照し、コンポーネントからはセマンティクスだけを使います（「[10-4 デザイントークン](/components/design-tokens/#色のトークンの層)」）。`!default` だった半径は、`:root` に置かず、公開プロパティ `--card--radius` を内部プロパティで受けて、デフォルト値を `var()` のフォールバックに書きます。セレクタは `@scope` で閉じ、ルートを `.scoped.card` にします。

Sassの変数はビルドの時点で値に置き換わりますが、カスタムプロパティはブラウザの中で継承され、使う場所で値が決まります。そのため、状態やクエリによって値を切り替えられます。`--_background--hocus` のような接尾辞で状態ごとの値を持つ書き方は「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」で説明しています。

反対に、サイズの条件の閾値には、カスタムプロパティを使いません。メディアクエリの条件は、仕様上 `var()` を受け付けません。コンテナサイズクエリの条件は、仕様の草案では `var()` を認めていますが、対象のブラウザで実装がそろっていないので、本書では使いません（「[13-2 ブレイクポイントの決め方](/responsive/breakpoints/#rule-no-var-in-query)」）。`@container style(--theme: dark)` のようなスタイルクエリはカスタムプロパティを条件にできますが、比べられるのはプロパティの値で、幅の閾値の代わりにはなりません。本書では、サイズ条件の閾値にリテラル値を書き、ブレイクポイントのmapは変数に置き換えず、後の「メディアクエリのmixinは、条件をそのまま書く」のように書きます。z-indexの一覧を変数のリストで管理していた場合は、100刻みの絶対的な値と、`--z--forwards` と `--z--backwards` の相対的な値のトークンに置き換えます。

## ネストはネイティブのネストで書く

`&:hover` のような擬似クラスのネストや、セレクタの中の `@media` は、素のCSSのネストでもそのまま書けます。本書では、セレクタを2層（親と、その中の1段）までにして、ネストしたセレクタは必ず `&` で始めます。宣言はネストしたルールより前に書きます。規約は「[9-5 ネストの書き方](/notation/nesting/)」で説明しています。

Sassと大きく違うのは、`&__title` のように `&` に文字をつなげてクラス名を作れないことです。素のCSSではこれが無効なセレクタになり、ルールごと無視されます。そのため、つなげて作っていたクラス名は、ネストから出して完全な名前で書きます。

```scss title="Sass：&__ と &-- で名前を作る"
.media-card {
  &__title {
    font-weight: 700;
  }

  &--featured {
    border-color: $color-accent;
  }
}
```

まず、クラス名と宣言を変えずに、素のCSSへ移します。`$color-accent` は、前の見出しの色のトークンに置き換えています。クラス名の付け方はBEMのままなので、この段階のコードは、まだ本書の規約には合わせていません。

```css title="Sassのネストを、クラス名を変えずに素のCSSへ移す（規約にはまだ合わせていない）"
.media-card__title {
  font-weight: 700;
}

.media-card--featured {
  border-color: var(--color--accent--500);
}
```

本書の設計に整えると、次のようになります。

```css title="🙆‍♂ Recommended: BEMの修飾子を、@scope の子要素と data-variant 属性に置き換える"
@scope (.scoped.media-card) to (.scoped) {
  :scope {
    border: 1px solid transparent;

    &[data-variant="featured"] {
      border-color: var(--border--base);
    }
  }

  h2 {
    font-size: calc(20 / 16 * 1rem);
  }
}
```

変えたのは5点です。1つ目に、ブロックのクラスを `.scoped.media-card` にして、スタイルの範囲を `@scope` で閉じ込めました。2つ目に、`__title` の要素にはクラスを付けず、`@scope` の中で `h2` のタイプセレクタで選ぶようにしました。同じ種類の要素を役割で区別するときと、`div` と `span` に役割を示すときだけ、`._main-link` のような短いクラス名を付けます。

3つ目に、`--featured` の修飾子を `data-variant="featured"` の属性に置き換え、バリエーションで色だけを変えられるように、ルートに透明な枠線を置きました。BEMの修飾子で表していたほかのバリエーションも、`data-variant` のような属性か、公開プロパティで表します。4つ目に、`font-weight: 700` は書き写さず、`h2` のルールには見出しの文字の大きさだけを書きました。`h2` はブラウザのデフォルトスタイルで太字になるので、同じ値を指定し直す必要がないからです（[`no-redundant-defaults`](/design-mindset/maintainability/#rule-no-redundant-defaults)）。

5つ目に、移行途中の例で直接参照していたプリミティブの `--color--accent--500` を、枠線の役割を表すセマンティクスの `--border--base` に置き換えました。前の見出しで整理したとおり、コンポーネントからはセマンティクスだけを使います。

HTMLの階層をそのままネストで写す書き方も、Sassからよく持ち込まれます。ネストが深くなるほど詳細度が上がり、HTMLの構造を変えただけでスタイルが当たらなくなります。独自のスタイルを持つ子要素は、親のルールに入れず、同じ階層に並べます。スコープの考え方は「[4-4 @scopeでスタイルを閉じ込める](/cascade/scope/)」で、子要素の命名は「[9-1 命名規則](/notation/naming/)」で説明しています。

## mixinは、コンポジションとユーティリティにする

mixinは、置き換え先が用途によって分かれます。要素を積む、並べて折り返すといった配置のmixinは、コンポジション（`stack`、`cluster`、`switcher` など）にします。コンポジションはHTMLにクラスとして付け、間隔や列数は公開プロパティで受け取ります。HTMLのクラス名を見るだけで、子の並び方が分かるようになります。

視覚的に隠す、行数を制限するといった単機能のmixinは、`.-visually-hidden` や `.-line-clamp` のようなユーティリティにします。行数のような値は、`style="--line-clamp--limit: 2"` のように公開プロパティで渡します。どちらも「[10-3 コンポジションとユーティリティ](/components/compositions-and-utilities/)」で説明しています。

```html title="🙆‍♂ Recommended: mixin の代わりに、ユーティリティのクラスと公開プロパティを使う"
<p class="_excerpt | -line-clamp" style="--line-clamp--limit: 2">…</p>
```

ホバーのmixinは、置き換えるというより、書き方そのものを変えます。以前の私のmixinは、`(hover: hover) and (pointer: fine)` で判定していました。本書では `@media (any-hover)` の中にホバーを書き、同じ見た目を `:focus-visible` にも指定します。条件はmixinにまとめず、各セレクタの中に直接書きます（「[17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)」）。色は、プリミティブの段階（`600`、`700`）を使い分けず、文字色で塗るセマンティクスの `--background--inverse` を、`color-mix()` でページの背景に寄せた色をホバーとフォーカスに使います。

```css title="🙆‍♂ Recommended: ホバーのmixinの代わりに、条件をセレクタの中に書く"
@scope (.scoped.save-button) to (.scoped) {
  :scope {
    --_background: var(--background--inverse);
    --_background--hocus: color-mix(in oklab, var(--background--inverse) 80%, var(--background--base));

    background-color: var(--_background);
    color: var(--foreground--inverse);

    &:focus-visible {
      background-color: var(--_background--hocus);
    }

    &:enabled:hover {
      @media (any-hover) {
        background-color: var(--_background--hocus);
      }
    }
  }
}
```

ハーフレディングを打ち消すmixinは、`text-box-trim` に置き換えます。行の高さをmixinへ渡す必要がなくなります（「[14-3 行の高さとハーフレディング](/typography/line-height/)」）。フォーカスリングのように全体で共通の見た目は、ベーススタイルに一度だけ書きます（「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」）。

## 関数は calc() の式にする

pxをremに変換する関数は、`calc(24 / 16 * 1rem)` の式に置き換えます。式にしておけば、デザインカンプの「24px」がコードからそのまま読み取れます。`clamp()`、`min()`、`max()` の中では、`calc()` を省いて `24 / 16 * 1rem` と書けます。変換の考え方は「[6-1 pxとremを使い分ける](/values/px-and-rem/)」で説明しています。

```css title="🙆‍♂ Recommended: 変換の関数の代わりに、式を書く"
@scope (.scoped.article-body) to (.scoped) {
  h2 {
    font-size: calc(32 / 16 * 1rem);
  }

  :scope {
    & > h2 + * {
      margin-block-start: calc(24 / 16 * 1rem);
    }
  }
}
```

`math.div()` の割り算も、`calc()` で書けます。このとき、`calc(40px / 1280px * 100svi)` のように単位のついた値どうしを割る必要はありません。単位を外す関数の代わりに、余白のトークンをはじめから単位のない数値で持ち、使う場所で `* 1px` や `/ 16 * 1rem` を掛けます。

流体的な値の傾きと切片を計算する関数も、カスタムプロパティと `calc()` で書けます。基準の幅と値を単位のない数値で持てば、計算はブラウザに任せられます。組み立て方は「[6-3 計算関数で根拠を式に残す](/values/math-functions/)」で説明しています。CSSで関数を定義する `@function` は、Chrome系のブラウザしか対応していないので、本書ではまだ使いません。

## @extend の代わりに、トークンとクラスを共有する

`@extend` やプレースホルダは、似た見た目のセレクタをまとめるために使われてきました。本書では `@extend` を使わず、余白や色のような値はトークンで、配置はコンポジションで、単機能の指定はユーティリティで共有します。見た目が似ているだけのものを共通化しない理由は「[2-3 保守しやすさを最優先にする](/design-mindset/maintainability/#共通化のタイミング)」で、別のコンポーネントのままトークンで見た目をそろえる方法は「[10-1 何をコンポーネントにするか](/components/what-is-a-component/#見た目が似ているコンポーネントを共通化してよいか)」で説明しています。

## ループの代わりに、公開プロパティで値を渡す

`@each` や `@for` で、`.gap-sm` や `.gap-lg` のような段階ごとのクラスを量産するのはやめます。本書では、コンポジションの間隔や列数を修飾のクラスで増やさず、公開プロパティで受け取ります。値は、呼び出し側の `style` 属性で渡します。

```html title="🙆‍♂ Recommended: 段階ごとのクラスを作らず、style 属性で値を渡す"
<ul class="cluster" style="--cluster--gap: calc(var(--spacing--xxs) / 16 * 1rem)">
  <li>…</li>
</ul>
```

こうすれば、使う値はトークンの中から選ぶだけで、段階を増やしてもCSSを書き足す必要がありません。値がタグと同じ場所に書かれるので、どの要素の値なのかも一目で分かります。`style` 属性で渡す理由は「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」で説明しています。

トークンそのものは、ループで生成せず、分類ごとのファイルに1行ずつ書きます。段階のあるユーティリティも、`.-fluid-text--md` のように必要な段階だけを書きます（「[14-4 文字サイズと改行](/typography/size-and-line-breaks/)」）。

## 色の関数は、相対カラー構文と color-mix() にする

`darken()` や `lighten()`、`rgba($color, 0.1)` のように1つの色を加工する関数は、相対カラー構文に置き換えます。`oklch(from 元の色 l c h)` と書くと、元の色の明度・彩度・色相が `l`、`c`、`h` に入り、変えたい値だけを書き換えられます。`l` は0から1までの数値なので、明度を下げるときは `calc(l - 0.15)` のように書きます。

2つの色を混ぜる `mix()` は、`color-mix()` に置き換えます。補間の色空間には `oklab` を指定します。私は、1つの色の成分を変えるときは相対カラー構文を、2つの色の間を取るときは `color-mix()` を使います。どちらも「[15-2 相対カラー構文で派生色を作る](/color-media/relative-color/)」で説明しています。

```scss title="Sass：色を加工する関数"
.tag {
  border: 1px solid rgba($color-text, 0.1);
  background-color: darken($color-surface, 5%);
}
```

```css title="🙆‍♂ Recommended: 相対カラー構文と color-mix() で、元の色から作る"
._tag {
  border: 1px solid oklch(from var(--foreground--base) l c h / 10%);
  background-color: oklch(from var(--background--surface) calc(l - 0.05) c h);
}

._badge {
  background-color: color-mix(in oklab, var(--foreground--base) 12%, var(--background--base));
}
```

`._tag` は、相対カラー構文で1つの色の成分を変えています。`._badge` は、`color-mix()` で文字色とページの背景の間を取り、淡い背景を作っています。混ぜる2つの色がどちらも不透明なので、結果も不透明な色になり、重ねる面によって色が変わりません。文字色は、半透明の色で薄くせず、背景に合わせた不透明なセマンティクスのトークンから選びます（「[14-5 文字の役割と色](/typography/text-roles/)」）。

Sassの色の関数はビルドの時点で値を計算しますが、相対カラー構文と `color-mix()` はブラウザの中で計算されます。元の色のトークンを1か所直せば、派生させた色もすべて追従し、`light-dark()` で切り替わる色からも派生色を作れます。なお、Sassの `darken()` はHSLの明度を変える関数なので、同じ数値を書いても同じ色にはなりません。見た目はブラウザで確かめます。

## ファイルの分割は @import … layer() にする

Sassの `@use` や `@import` で分けていたパーシャルは、CSSの `@import` で読み込みます。Sassがビルドでファイルを1つにまとめていたように、エントリーポイントの `@import` もビルドで展開します（「[4-3 カスケードレイヤーで順位を決める](/cascade/layers/#rule-import-resolved-at-build)」のルール `import-resolved-at-build`）。エントリーポイントのファイルの先頭で、レイヤーの順番を `@layer` 文で宣言し、各ファイルを `@import url("…") layer(…)` で割り当てます。ファイルの中で `@layer` を書く必要はなく、どのファイルがどのレイヤーに入るのかを1か所で確認できます。

```css title="🙆‍♂ Recommended: ビルドの入力にするエントリーポイントで、ファイルをレイヤーに割り当てる"
@layer tokens, reset, base, vendors, compositions, pages, components, patterns, utilities;

@import url("kiso.css") layer(reset);
@import url("./tokens/colors.css") layer(tokens);
@import url("./base/generic.css") layer(base);
@import url("./compositions/cluster.css") layer(compositions);
@import url("./utilities/a11y.css") layer(utilities);
```

ディレクトリは、9つのレイヤーの分類に合わせて分けます。レイヤーの役割と順番は「[4-3 カスケードレイヤーで順位を決める](/cascade/layers/)」で説明しています。CMSのように、レイヤーに入っていない外部のCSSと共存する環境では、`layer()` を付けずに、同じ分類の順番で `@import` を並べます。

## メディアクエリのmixinは、条件をそのまま書く

ブレイクポイントのmapとmixinは、各セレクタの中へ条件をそのまま書く形に置き換えます。条件は `min-width` ではなく範囲構文で書き、値は `calc(768 / 16 * 1rem)` のようにremへの変換の式にします。メディアクエリの条件では仕様上カスタムプロパティを参照できないので、ブレイクポイントを変数にまとめることはできません。

```scss title="Sass：ブレイクポイントの mixin"
.layout {
  display: grid;

  @include mq(lg) {
    grid-template-columns: 200px 1fr 240px;
  }
}
```

```css title="🙆‍♂ Recommended: 範囲構文とremの式を、セレクタの中に書く"
@scope (.scoped.page-about) to (.scoped) {
  ._layout {
    display: block grid;
    gap: 32px;

    /* ナビゲーション 200px 相当 + 本文の最小幅 560px 相当 + サイドバー 240px 相当 + 隙間 32px × 2 */
    @media (width >= calc(200 / 16 * 1rem + 560 / 16 * 1rem + 240 / 16 * 1rem + 32px * 2)) {
      grid-template-columns: calc(200 / 16 * 1rem) 1fr calc(240 / 16 * 1rem);
    }
  }
}
```

名前の付いたブレイクポイントを使い回す代わりに、閾値は「ナビゲーションの幅＋本文の最小幅＋サイドバーの幅＋隙間」のように、レイアウトが成り立つ条件の式で書きます。メインとサイドの2つを並べるだけなら、閾値を書かずに「[12-6 sidebar](/compositions/sidebar/)」で組みます。pxで指定した隙間は、remへ換算せず、pxのまま足します。値の根拠がコードに残り、どこを直せばよいかも分かります（「[13-2 ブレイクポイントの決め方](/responsive/breakpoints/)」）。コンポーネントの中の切り替えには、メディアクエリではなくコンテナサイズクエリを使います（「[13-3 コンテナサイズクエリ](/responsive/container-size-queries/)」）。

カンプ上のピクセル値をSassの関数で `vw` へ換算し、ページ全体の寸法を決めていたコードは、素のCSSへ移すときにそのまま置き換えず、書き直します。カンプの幅に対する比率で全体を拡大・縮小すると、狭い画面で文字が読めなくなり、ズームや文字サイズの設定も反映されにくくなるからです。理由と代わりの方法は「[13-7 カンプの幅で全体を拡大・縮小しない](/responsive/design-comp-pattern/)」で説明しています。

## コメントは /* */ で書く

Sassでは `//` で1行のコメントを書けますが、素のCSSでは `//` はコメントとして扱われません。Sassから移したコードに `//` が残っていないかを確かめ、コメントはすべて `/* */` で書きます。コメントに書く内容は「[9-10 コメントの書き方](/notation/comments/)」で説明しています。
