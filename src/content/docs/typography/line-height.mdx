行の高さ（`line-height`）は、ベーススタイルで1.5以上にして各要素に継承させ、`line-height: 1` は使いません。値はトークンから選び、和文の本文は1.7〜2、見出しは1.25〜1.5を目安にします。デザインの都合で文字の上下の余白を詰めたいときは、行の高さを小さくするのではなく、`text-box-trim` でハーフレディングを取り除きます。ボタンのラベルを上下の中央に置くときも同じで、Flexboxのボタンでは、ボタン自身ではなくラベルの要素に指定します。

`line-height` を単位のない数値で書く理由は、「[6-1 pxとremを使い分ける](/values/px-and-rem/)」で説明しています。

## ハーフレディングとデザインカンプの差

CSSの行は、`line-height` の高さを持つ箱として並びます。行の高さが文字の大きさより大きいとき、その差は文字の上と下に半分ずつ配分されます。この上下の余白を「ハーフレディング」と呼びます。仕様では、行の高さとフォントのアセントとディセントの合計との差からハーフレディングを求めるので、正確な量はフォントによって変わります。本書では、文字の大きさ（`1em`）を基準にした量を目安にします。16pxの文字で `line-height` が1.75なら、行の高さは28pxで、1emを基準にすると文字の上下に6pxずつのハーフレディングができます。

行と行の間では、上の行の下側と下の行の上側のハーフレディングが合わさり、行間になります。問題は、1行目の上と最後の行の下にも、同じ量の余白が残ることです。見出しの上や段落の下の余白を測ると、CSSで指定した `margin` より、ハーフレディングのぶんだけ広くなります。

デザインツールによって、この余白の扱いが異なります。Figmaは、テキストの上下のトリミングを設定していなければ、ハーフレディングを含めた位置から余白を測ります。一方、Adobe XDやIllustratorなどのAdobe製のツールは、ハーフレディングを含めずに余白を測ります。Adobe製のツールで作ったデザインカンプの余白をそのまま `margin` に書くと、実装の余白が広く見えるのはこのためです。

デザインカンプとの見た目の差を指摘されたとき、原因の多くはこのハーフレディングにあると私は見ています。そこで、余白を詰めるために `line-height: 1` を指定したくなりますが、これは後で説明するとおり避けます。ハーフレディングを取り除く手段は、別に用意されています。

## ベースの行の高さ

ベースの `line-height` は1.5以上にします。WCAG 2.1の達成基準1.4.8（レベルAAA）は、段落の中の行送りを文字の大きさの1.5倍以上にした表示を、達成できる仕組みがあることを求めています。この基準は、ユーザーが表示を調整できる手段の提供を求めるもので、初期のCSSを常に1.5以上にすることまでは求めていません。行の間が狭いと読んでいる行を目で追いにくくなるので、本書はユーザーが調整しなくても読みやすいように、ベースの値そのものを1.5以上にします（kiso.cssも、`:root` の `line-height` を1.5にしています）。

そのうえで、見出しや本文には、それぞれに合った値を指定します。目安は、和文の本文が1.7〜2、英文の本文が1.5〜1.8です。見出しは文字が大きいぶん行の間も広がるので、和文で1.25〜1.5、英文で1.2〜1.4ほどに狭めます。

もう1つ、達成基準1.4.12（テキストの間隔、レベルAA）も関係します。こちらは、作り手が1.5倍にすることを求める基準ではありません。ユーザーが行の高さを文字の大きさの1.5倍以上、段落の後ろの余白を2倍以上、字間を0.12倍以上、語間を0.16倍以上に上書きしても、内容や機能が失われないことを求めます。行の高さを固定した高さの要素に収めていたり、`overflow: hidden` で切っていたりすると、ユーザーが行間を広げた時点で文字が切れます。ベースを1.5以上にしておけば、上書きされたときの変化が小さくなり、この基準も満たしやすくなります。高さを固定せず、中身に任せる書き方は「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/#rule-min-block-size-over-fixed-height)」で説明しています。

見出しの行の高さは、1行で収まっているうちは見た目にほとんど影響しません。差が出るのは、狭い画面や長い文言で2行以上に折り返したときです。見出しの値を決めるときは、表示の幅を狭めて、折り返した状態の行の間を確かめます。

これらの値は、トークンにして段階ごとに名前を付けます。私のテンプレートでは、`tight`、`snug`、`normal`、`relaxed`、`loose` の5段階にしています。数値ではなく名前で選べば、本文や見出しに使う値が、サイトの中でそろいます。

```css title="🙆‍♂ Recommended: 行の高さのトークンを段階で定義し、要素ごとに選ぶ"
:root {
  --leading--tight: 1.25;
  --leading--snug: 1.4;
  --leading--normal: 1.6;
  --leading--relaxed: 1.75;
  --leading--loose: 2;
  --text--body--leading: var(--leading--relaxed);
  --text--title--leading: var(--leading--snug);
}

@layer base {
  :root {
    line-height: var(--leading--normal);
  }
}

@scope (.scoped.article-body) to (.scoped) {
  :scope {
    line-height: var(--text--body--leading);
  }

  h2 {
    line-height: var(--text--title--leading);
  }
}
```

コンポーネントからは、段階のトークンを直接参照せず、本文や見出しのような役割のトークン（`--text--body--leading` など）を参照します。役割に段階を割り当てておけば、見出しの行の高さを変えるときに、直すのは役割の定義の1か所で済みます。役割のトークンは「[14-5 文字の役割と色](/typography/text-roles/)」で説明しています。

デザインの中で1か所だけ使われている `1.8` のような値は、トークンに加えず、その場に直接書きます。トークンを増やしすぎると、一覧から選ぶだけで取り決めに沿えるという利点が失われるからです。トークンの粒度は「[10-4 デザイントークン](/components/design-tokens/)」で説明しています。

## line-height: 1 の問題

`line-height: 1` は使いません。ボタンやラベルのように1行で表示する前提の要素でも、指定しないようにします。コーディングしやすいからと、ベーススタイルの `line-height` を1にする方法もありますが、これも避けます。

```css title="🙅‍♂ Not Recommended: ハーフレディングをなくすために行の高さを1にする" issue="behavior"
/* 🙅‍♂ Not Recommended */
._submit-button {
  line-height: 1;
}
```

デザインの上では1行でも、実際の表示では改行が起こりえます。ラベルの文言が変わったとき、画面の幅が狭いとき、ユーザーが文字を大きくしたとき、機械翻訳で文章が長くなったときです。`line-height: 1` のまま改行すると、行と行の間がなくなり、フォントによっては文字が重なって読めなくなります。

この指定は、アクセシビリティも損ないます。行の間が極端に狭いと、認知に障害のある人を含め、多くの人が文字を目で追いにくくなります。本書のStylelintの設定では、`line-height` に単位を付けていないかに加えて、`1` という値も `declaration-property-value-disallowed-list` で警告します。

やりたいことが「文字の上下の余白をなくすこと」なら、行の高さはそのままにして、ハーフレディングだけを取り除きます。これには `text-box-trim` を使います。

## text-box-trimでハーフレディングを取り除く

`text-box-trim` は、要素の1行目の上と最後の行の下にあるハーフレディングを取り除くプロパティです。行と行の間の行送りは変わりません。`line-height: 1` の代わりに使えば、改行したときの読みやすさを保ったまま、デザインカンプの余白に合わせられます。

```css title="🙆‍♂ Recommended: ハーフレディングを取り除くユーティリティ" from="typography/text-box-trim"
.-trim-both {
  text-box-trim: trim-both;

  &:lang(en) {
    text-box-edge: cap alphabetic;
  }
}
```

`text-box-trim` には、上下の両方を削る `trim-both`、上だけを削る `trim-start`、下だけを削る `trim-end` があります。ハーフレディングをなくしたいなら `trim-both` を使います。画像と見出しを横に並べて上端をそろえたいときは、`trim-start` だけで足ります（このページの後半で説明します）。

どこまで削るかは `text-box-edge` で決めます。デフォルト値の `auto` は `text` として扱われ、フォントの文字の領域（アセントとディセント）の上端と下端で切り取ります。英文では、大文字の上端とベースラインで切り取る `cap alphabetic` が適していますが、和文に使うと詰まりすぎるので、和文はデフォルト値のままにします。上のユーティリティは、英語の要素でだけ `text-box-edge` を変えています。{/* 要検証: ブラウザ。Firefoxで、英文の text-box-edge: cap alphabetic が大文字の上端とベースラインで切り取るか（web-features の text-box は、cap と alphabetic の値に Firefox の対応を載せていない） */}

次のデモでは、同じバッジと段落を、ハーフレディングが残った状態と、`.-trim-both` で取り除いた状態で並べています。背景色の範囲を比べると、上下の余白が `padding` の値だけになっているのが分かります。英語のバッジは、大文字の上端とベースラインで切り取られるので、和文のバッジより低くなります。

## ボタンのラベルを上下の中央に置く

ボタンのラベルを、上下の `padding` を同じ値にしたまま文字の見た目の中央に置くときも、`text-box-trim` を使います。ボタンの中の行の箱は、フォントのアセントとディセントにハーフレディングを足した高さを持ち、文字はその中に置かれます。英語の大文字だけのラベルは、ベースラインより下のディセントの領域に文字がありません。そのうえ、大文字の上端からアセントまでの空きとディセントの大きさはフォントごとに違うので、`padding` を上下で同じにしても、ラベルは上か下に寄って見えます。

英語のラベルに `text-box: trim-both cap alphabetic` を指定すると、行の箱が大文字の上端とベースラインで切り取られます。`padding` が大文字の字面からの距離になるので、上下の値が同じなら、大文字はボタンの上下の中央に来ます。`g` や `p` のようなディセンダーのある小文字は、ベースラインより下の `padding` にはみ出しますが、大文字とベースラインを基準にそろえるのが欧文の組版の慣習なので、そのままにします。

### Flexboxのボタンではラベルの要素に指定する

アイコンとラベルを並べるボタンは、ボタン自身を `display: inline flex` にすることが多くあります。このボタン自身に `text-box` を指定しても、何も削られません。

```css title="🙅‍♂ Not Recommended: Flexboxのボタン自身に text-box を指定する" issue="behavior"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.action-button) to (.scoped) {
  :scope {
    display: inline flex;
    gap: 8px;
    align-items: center;
    padding-block: 12px;
    padding-inline: 20px;
    text-box: trim-both cap alphabetic;
  }
}
```

CSS Inline Layout Module Level 3では、`text-box-trim` を指定できるのは、ブロックコンテナ、段組みのコンテナ、インラインの箱だけです。仕様は、`::first-line` と同じく、Flexbox、Grid、表の整形文脈には適用されず、その中を通って子に伝わることもないと定めています。フレックスコンテナの中の行は、ボタン自身の行ではなく、各フレックスアイテムの中にあるからです。Chromeで確かめたところ、Flexboxのボタン自身に指定しても高さは変わらず、ラベルの要素に指定すると、ボタンが低くなりました。{/* 要検証: ブラウザ。SafariとFirefoxでの同じ比較 */}

そこで、`text-box-trim` はラベルの `span` に指定します。`span` はインライン要素ですが、フレックスアイテムになるとブロック化され、ブロックコンテナとして扱われるので、1行目の上と最後の行の下が削られます。言語による切り替えは、`.-trim-both` のユーティリティと同じく、和文はデフォルト値のまま、英文だけ `cap alphabetic` にします。

```html title="🙆‍♂ Recommended: アイコンとラベルを別の要素にする"
<button class="scoped action-button" type="button" lang="en">
  <svg class="_icon" aria-hidden="true"><!-- ... --></svg>
  <span class="_label">Download</span>
</button>
```

```css title="🙆‍♂ Recommended: ハーフレディングをボタンではなくラベルの要素で取り除く"
@scope (.scoped.action-button) to (.scoped) {
  :scope {
    display: inline flex;
    gap: 8px;
    align-items: center;
    padding-block: 12px;
    padding-inline: 20px;
  }

  ._label {
    text-box-trim: trim-both;

    &:lang(en) {
      text-box-edge: cap alphabetic;
    }
  }
}
```

ラベルの要素には `padding` や `border` を付けず、余白はボタンの側で持ちます。ラベル自身に付けても、`text-box-trim` は中の行のハーフレディングを削ります。Chromeで、10pxの `padding` と2pxの `border` を付けたラベルも、ハーフレディングの分だけ低くなりました。それでも付けないのは、ボタンの大きさを決める余白を1か所にまとめるための、設計上の判断です。削られなくなるのは、`text-box-trim` を指定した要素と、その中の行の間に、`padding` や `border` を持つ要素を挟んだ場合です。枠線を付けた要素は、ラベルの中で入れ子にしません。また、ハーフレディングを削ったぶん、ボタンは低くなります。操作に必要な最小の高さは `min-block-size` で確保し（「[17-2 押せる範囲とタッチ操作](/interaction/hit-area-and-touch/)」）、`align-items: center` でラベルを中央に置けば、高さが増えても上下の空きは同じになります。

### 和文のラベルで切り取る位置

和文のラベルに `cap alphabetic` は使いません。漢字や仮名の字面は、大文字の上端より上とベースラインより下にはみ出すので、`padding` に食い込み、上下が詰まって見えます。はみ出す量も上下で同じではありません。macOSのChromeで、システムフォントの「送信する」を比べたところ、字面は上に約2px、下に約1pxはみ出し、ラベルが上に寄って見えました。

和文のラベルには、デフォルト値の `text` のまま `text-box-trim` を指定します。ハーフレディングはなくなりますが、切り取る位置はフォントのアセントとディセントなので、字面がボタンの正確な中央に来るとは限りません。欧文フォントを先に指定していれば、この位置は欧文フォントのアセントとディセントで決まることもあります。使われるフォントはOSによって変わるので、ずれ方も環境ごとに変わります。{/* 要検証: ブラウザ。欧文フォントを先に指定したとき、OSごとの和文の字面の位置 */}本書では、ある環境のフォントの見え方を基準にして、上下の `padding` を変えることはしません。別の環境では、その調整が逆向きのずれになるからです。

仕様には、和文の字面に合う値もあります。`ideographic` は漢字や仮名の文字の枠（仮想ボディ）の上端と下端を、`ideographic-ink` は字面の上端と下端を、切り取る位置にする値です。ただし、Chromeはどちらにも対応していません。`text-box: trim-both ideographic` は宣言全体が無効になり、ハーフレディングも残りました。{/* 要検証: ブラウザ。Safariでの ideographic の対応 */}対応が広がるまでは使いません。`ex` は小文字の `x` の高さを切り取る位置にする値で、上側にしか指定できません。大文字や和文の字面がはみ出すので、ラベルには使いません。

## 画像と並べた文章の上端をそろえる

画像と文章を2カラムで横に並べるときは、文章の側の先頭の要素に `text-box-trim: trim-start` を指定して、画像の上端と文字の上端をそろえます。グリッドで画像と見出しを同じ行に置いても、見出しの1行目の上にはハーフレディングが残るので、文字の上端は画像の上端より下がります。28pxの見出しで `line-height` が1.4なら、1emを基準にして約5.6pxのずれです。見出しの文字が大きいほど、このずれは目立ちます。

次の例では、HTMLを見出し、画像、本文の順に書き、狭い幅では縦に積みます。コンテナの幅が画像の列とテキストの列の最小幅を足した値を超えたら、`--_density` のフラグを `--spacious` に切り替え、画像を左の列の2行分に置きます。見出しの文字サイズも、フラグが `--spacious` のときに20pxから28pxにします。本文の行を `1fr` にしているので、見出しの行は見出しの高さだけになり、見出しが画像の上端の横に来ます。ハーフレディングを取り除くのは、見出しに付けた `.-trim-start` です。

```html title="🙆‍♂ Recommended: 画像の横に来る見出しに .-trim-start を付ける"
<article class="scoped media-text">
  <div class="_body">
    <h2 class="_heading | -trim-start">見出し</h2>
    <img class="_image" width="480" height="360" alt="" src="…">
    <div class="_paragraphs">
      <p>本文</p>
    </div>
  </div>
</article>
```

```css title="🙆‍♂ Recommended: 2カラムで画像と文章を並べ、文章の先頭のハーフレディングを取り除く" from="typography/media-text-trim"
@scope (.scoped.media-text) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
  }

  /* コンテナサイズクエリを書くのは、フラグを宣言するこの要素だけ */
  ._body {
    --_density: --compact;

    display: block grid;
    reading-flow: grid-rows;
    grid-template:
      "--heading"
      "--image"
      "--paragraphs";
    gap: 1rlh 24px;

    /* 画像の列 240px 相当・隙間 24px・テキストの列 240px 相当が並ぶ幅 */
    @container --scoped (inline-size >= calc(240 / 16 * 1rem + 24px + 240 / 16 * 1rem)) {
      --_density: --spacious;

      grid-template:
        "--image --heading"
        "--image --paragraphs" 1fr
        / minmax(min(100%, calc(240 / 16 * 1rem)), 2fr) minmax(min(100%, calc(240 / 16 * 1rem)), 3fr);
      align-content: start;
    }

    & > ._heading {
      grid-area: --heading;
    }

    & > ._image {
      grid-area: --image;
    }

    & > ._paragraphs {
      grid-area: --paragraphs;
    }
  }

  ._heading {
    font-size: calc(var(--text--title--font-size) / 16 * 1rem);
    line-height: var(--text--title--leading);

    @container style(--_density: --spacious) {
      font-size: calc(var(--text--display--font-size) / 16 * 1rem);
    }
  }
}

.-trim-start {
  text-box-trim: trim-start;

  &:lang(en) {
    text-box-edge: cap alphabetic;
  }
}
```

次のデモでは、上の見出しにハーフレディングが残り、下の見出しは `.-trim-start` で取り除いています。幅を768px以上にし、2カラムの幅で比べると、下の見出しだけ、文字の上端が画像の上端と同じ高さにあります。狭い幅では見出しがコンポーネントの先頭に来るので、取り除いても見出しの上の余白が詰まるだけで、ほかの配置は変わりません。

<Demo title="画像の横の見出しにハーフレディングが残った状態と、.-trim-start で取り除いた状態" html={mediaTextHtml} css={mediaTextCss} variant="neutral" />

そろうのは、字面の上端ではなく、フォントの文字の領域の上端です。`text-box-edge` のデフォルト値の `auto` は、仕様では `text` として扱われ、上側は「text-over baseline」で切り取ります。これは、CSS 2で行内の要素の内容の領域の上端に使うフォントのアセントの位置です。和文フォントによっては、アセントが漢字の上端より上にあり、そのぶんの差が残ります。{/* 要確認: 出典なし */}それでも、行の高さで増えたハーフレディングのずれはなくなります。英文の見出しでは、`.-trim-start` が `text-box-edge: cap alphabetic` に切り替えるので、大文字の上端が画像の上端にそろいます。

`trim-both` ではなく `trim-start` にするのは、そろえたいのが上端だけだからです。見出しの下のハーフレディングまで削ると、見出しと本文の間が `gap` で指定した値より狭く見えるようになります。テキストの列の下端は画像の下端とそろえる対象ではないので、残しておいて困ることはありません。

`text-box-trim` は、ブロックの要素に指定すると、その中の最初の行に作用します。見出しと本文を1つの要素で包んでテキストの列にしている場合は、包んでいる要素に `trim-start` を付ければ、先頭の要素がどれでも上端がそろいます。ただし、包んでいる要素と最初の行の間に `padding` や `border` があると、何も削られません。`text-box-trim` に対応していない環境では、指定が無視され、見出しがハーフレディングのぶん下がるだけで、レイアウトは崩れません。
