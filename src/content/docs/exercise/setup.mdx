21-2から21-13は、1つの節で1つの部品を作ります。どの節も単体で取り組めるように、配布ファイルの開始版には、その節で使うほかの部品の完成版を入れています。21-14で部品をページに組み上げ、21-15で組み上げたページを確かめ、別の人が書いたコードをレビューします。

## 題材のサイト

サイトには、トップページ、サービス、コラム一覧と記事、料金、よくある質問、お問い合わせのページがあります。どのページにも、上に固定ヘッダーが、下に紺のフッターがあり、狭い画面ではヘッダーのナビゲーションをドロワーで開きます。

各節で作る部品と、その部品を主に置くページは、次のとおりです。

| 21-2 | ボタンの見た目のリンク、セクションの見出し | すべてのページ |

| 21-4 | 記事のリストと、カテゴリーの絞り込み | トップページ、コラム一覧 |
| 21-5 | フッター | すべてのページ |

同じ部品を、幅や背景の違う複数の場所に置くことが、この演習の前提です。各節の後半で加わる要件の多くは、部品を別の場所に置くことか、部品に入る内容が変わることです。部品のCSSに置き場所を前提にした値が入っていると、置き場所が増えるたびに部品を直すことになります（「[10-2 コンポーネントの境界を守る](/components/boundaries/)」）。

## カンプとトークンの対応

カンプは、紺とティールを基調に描かれています。演習のデモと配布ファイルは、本書のデモの共通トークンと同じ名前のトークンに、このサイトの値を入れて使います（「[付録I デモの共通トークン](/appendix/demo-tokens/)」）。部品のCSSでは、色や文字の大きさを直接書かず、次のトークンを参照します（「[10-4 デザイントークン](/components/design-tokens/)」）。

| カンプの色 | 使う場所 | トークン |
|---|---|---|
| 淡いグレー | ページの背景 | `--background--base` |
| 白 | カード、パネル、ページの背景と区別したい面 | `--background--surface` |
| 紺 | 文字、主ボタンの面 | `--foreground--base`、`--background--inverse` |
| グレー | 日付やリード文のような控えめな文字 | `--foreground--muted` |
| ごく淡い線 | 枠線と区切り線 | `--border--base` |
| ティール | リンクの文字、フォーカスリング、選んだ状態 | `--foreground--accent` |
| ティール | 英字の小見出し、カテゴリーのラベル | `--foreground--brand`、`--background--brand-subtle` |

ティールには、2つの役割があります。1つは、リンクやフォーカスリングのように、操作できることを示す色です。もう1つは、英字の小見出しやカテゴリーのラベルのように、操作できない飾りに使うブランドの色です。カンプではどちらも同じ系統のティールですが、トークンを分けておけば、飾りの色を変えたときにリンクの色まで変わることはありません。

文字の大きさと行の高さは、役割のトークンを組で参照します（「[14-5 文字の役割と色](/typography/text-roles/)」）。セクションの見出しの48px相当（広い画面での最大）は `display` です。カードの見出しの18px相当は `title`、16px相当の太字は `subtitle`、本文は `body`、日付やラベルの12px相当は `caption` です。料金の数字の36px相当は料金表でしか使わないので、トークンにせず、料金表のCSSに直接書きます（ルール [`no-single-use-token`](/components/design-tokens/#rule-no-single-use-token)）。見出し、英字の小見出し、日付、料金の数字は、欧文の書体のInterを `--font-family--latin` で指定します。Interは欧文だけを収めているので、和文は後ろの総称ファミリーの書体で表示されます。角丸は、ラベルの6pxが `--rounded--sm`、画像の12pxが `--rounded--md`、カードの28pxが `--rounded--lg`、丸いボタンが `--rounded--full` です。余白は、本書のデモと同じく、カンプのpxの値をそのまま書きます。

## 演習の進め方

21-2から21-13の各節は、2つの段階に分かれています。前半では、最初の要件で部品を作ります。後半では、途中で要件が1つ変わり、前半で作った部品を直します。どちらの段階も、要件、予想する、合格条件、解説の順に進みます。最後に、2つの段階を通した振り返りと、判断の問いがあります。

要件を読んだら、解説を読み進める前に、自分ならどのファイルのどこを直すかを書き出してみてください。部品のCSS、コンポジションの `compositions.css`、パターンの `patterns.css`、ページのCSSとHTMLのどれを直すのか、何行くらいになりそうかを予想します。合格条件には、その段階を終えた時点のデモと、何が満たされれば完成かを書いています。

振り返りでは、自分の予想と見比べます。見比べるのは、直す場所の数だけではありません。変更を受け持つ場所を変更の内容から予測できたか、直したときに影響が及ぶ範囲を確かめられたか、直した結果として条件分岐が複雑になっていないかも確かめます。直す場所の数を減らす書き方が、ほかの3つを損なうことがあるからです（「[2-3 保守しやすさを最優先にする](/design-mindset/maintainability/)」）。

本文のコード例は、変えた箇所だけを抜き出しています。省いた部分は `/* ... */` と書き、どのルールの中を変えたのかが分かるようにしています。各段階のデモは、その段階を終えた時点の全体です。差分の前後をつなげて読みたいときは、デモのCSSの全体か、配布ファイルのCSSを読んでください。

## 手元で進める準備

演習のファイルは、[補足サイトのサンプル一式](/book-support/index.html)から、本書と同じ版のZIPで取得します。ZIPを展開すると、`exercise/` の下に、全節で共通の `base.css` と、欧文の書体のファイルを入れた `fonts/` と、節ごとのディレクトリがあります。節のディレクトリの名前は、節のURLの末尾と同じです（21-2なら `buttons`）。

節のディレクトリには、`start/`（開始版）、`middle/`（前半を終えた時点の中間版）、`finished/`（後半を終えた時点の完成版）の3つがあります。後半の要件の変更から取り組みたいときは、中間版から始めます。どの段階も、`index.html` と、そのページが読み込むCSSとJavaScriptのファイルが同じディレクトリにあり、ディレクトリの構成を保ったまま開けば、HTMLが読み込むファイルもそろいます。

CSSは、本文の説明と同じく、責任ごとにファイルを分けています。コンポーネントは、1つにつき1つのファイルです（`action-control.css` や `article-cards.css` など）。ほかに、コンポジションの `compositions.css`、パターンの `patterns.css`、ページのCSSがあります。21-6からは、ページのスクロールのように、ルートの要素に指定する `base` レイヤーの追加を `site-base.css` に置きます。開始版では、その節で作るファイルが空の `@layer` だけになっていて、ほかの部品は完成しています。各ファイルの中身は、本書のデモと同じ `@layer` で包んであり、レイヤーの順序は `base.css` の先頭で宣言しています。

`base.css` には、レイヤーの順序の宣言、本書のデモの共通トークン、この演習のサイトのトークン、リセットCSSのkiso.css、ベーススタイル、Interの `@font-face` が入っていて、演習では変えません。`@font-face` は、`base.css` と同じ階層の `fonts/` から書体のファイルを読み込みます。ベーススタイルには、第8章と第14章で決めた和文のカーニング、見出しの詰めと折り返し、下線の位置、二重のフォーカスリングを含めています（「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」）。HTMLは、`<link>` で `../../base.css` を読み込んだあと、そのページで使うCSSのファイルを読み込みます。21-9のすべての段階と21-12の完成版は、CSSだけでは作れない状態の切り替えのために、`<script>` で `script.js` も読み込みます。21-7と21-14のすべての段階の `script.js` は、ドロワーを開く `command` 属性と、ドロワーの外を押して閉じる `closedby` 属性に対応していないブラウザのために、ポリフィルをCDNから読み込みます。画像はHTMLに `data:` URIのSVGとして埋め込んであるので、用意する画像のファイルはありません。

同じファイルは、このサイトの `/exercise-files/` にも、ZIPの `exercise/` と同じ構成で置いてあります。たとえば、共通のファイルは [base.css](/exercise-files/base.css)、21-2の開始版は [index.html](/exercise-files/buttons/start/index.html) です。ZIPを使わずに1つずつ保存する場合は、HTMLの `<link>` と `<script>` に書かれたファイル名で保存し、`base.css` を節のディレクトリの親に置きます。書体のファイルを保存しない場合、見出しや日付は総称ファミリーの書体で表示されます。`script.js` を保存し忘れると、21-9では絞り込みのボタンが表示されず、21-12の完成版では、誤りを支援技術に伝える属性が切り替わりません。21-7と21-14では、`command` 属性に対応していないブラウザで、メニューのボタンを押してもドロワーが開きません。21-12の完成版のスクリプトは、[script.js](/exercise-files/contact-form/finished/script.js) です。

HTMLはブラウザで直接開けるので、開発用のサーバーは要りません。幅による切り替えは、ブラウザのウィンドウの幅を変えるか、開発者ツールのデバイスモードで幅を指定して確かめます。

演習で編集するHTMLは、テンプレートやフレームワークが出力した後のHTMLに当たります。CSSの責任の範囲を確かめるために、生成の手前を省いています。実務で同じ部品を繰り返し使うときは、HTMLの構造と属性を、テンプレートやコンポーネントのファイルの1つの定義に集め、記事の見出しや日付のような入力から、同じ構造のHTMLを出力します（「[10-1 何をコンポーネントにするか](/components/what-is-a-component/#コンポーネントの定義)」）。CSSのファイルを1つにまとめても、HTMLの構造は1か所で管理されません。演習で同じ部品のHTMLを複数の場所に書き写すときは、その1つ1つが、実務では1つの定義から出力されるインスタンスだと考えてください。

## 判断の問い

カンプでは、英字の小見出しと、文字のリンクの矢印が、どちらも同じ系統のティールで描かれています。小見出しの色を、リンクの文字色の `--foreground--accent` で指定してよいですか。

<details>
{/* textlint-disable ja-technical-writing/ja-no-mixed-period */}
<summary>答えと解説</summary>
{/* textlint-enable ja-technical-writing/ja-no-mixed-period */}

指定しません。小見出しは操作できない飾りで、リンクの色は操作できることを示す色です。今は同じ系統の色でも、役割が違うので、ブランドの色の `--foreground--brand` を使います。

同じトークンを使うと、2つの役割が値でつながります。リンクの色を背景とのコントラストのために濃くすれば、小見出しの色も一緒に変わります。読む人にとっても、ティールの文字のうち、どれが押せるのかを色で見分けられなくなります。値が同じでも、変える理由が違うものは、別のトークンにしておきます（`color-token-two-layers`）。

</details>

## この節で使ったルール

- [`use-defined-tokens`](/components/design-tokens/#rule-use-defined-tokens)：トークンとして定義されている値は、数値や色を直接書かずにトークンを参照します。
- [`color-token-two-layers`](/components/design-tokens/#rule-color-token-two-layers)：色のトークンはプリミティブとセマンティクスの2層で定義します。
- [`typography-token-two-layers`](/components/design-tokens/#rule-typography-token-two-layers)：文字のトークンは、コンポーネントから役割を参照します。
- [`two-text-colors`](/typography/text-roles/#rule-two-text-colors)：文字色は、重要度の段階を表す不透明なトークンから選び、リンクやエラーには意味を表す別のトークンを使います。
