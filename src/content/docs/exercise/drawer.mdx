狭い画面のナビゲーションを作ります。ヘッダーの幅が、ロゴ、ナビゲーション、お問い合わせのボタンを1行に並べられないほど狭いときは、ナビゲーションとお問い合わせのボタンを隠し、代わりに「メニュー」のボタンを置きます。メニューのボタンは、21-2で作った副ボタンです（「[21-2 ボタンとセクション見出しを作る](/exercise/buttons/)」）。

メニューのボタンを押すと、画面の右から、幅360px相当のドロワーが、大きな影を落として現れます。ドロワーには、閉じるボタン、縦に並べたナビゲーション、お問い合わせのボタンを置きます。縦に並べたナビゲーションのリンクは、16px相当の文字で、上下に16pxの余白を取ります。

ドロワーを開いている間は、背面のページの操作とスクロールを止めます。Escキー、閉じるボタン、ドロワーの外のどれを押しても閉じます。ドロワーは開くときと閉じるときに右から動かし、動きを減らす設定ではフェードだけにします。ヘッダーそのものは、21-6で作った固定ヘッダーです（「[21-6 固定ヘッダーを作る](/exercise/sticky-header/)」）。

手元で進めるときは、開始版（[index.html](/exercise-files/drawer/start/index.html)）から始め、中間版（[index.html](/exercise-files/drawer/middle/index.html)）と見比べます。後半の要件の変更は、中間版から始めて、完成版（[index.html](/exercise-files/drawer/finished/index.html)）と見比べます。サンプル一式のZIPでは、それぞれ `exercise/drawer/start/`、`exercise/drawer/middle/`、`exercise/drawer/finished/` にあります。準備は「[21-1 題材と準備](/exercise/setup/#手元で進める準備)」で説明しています。

## 予想する

本文を読む前に、メニューのボタンに切り替える条件を考えてみてください。スマートフォンとタブレットの境目としてよく使われる768pxにするのか、ほかの値にするのか、そもそも幅の値を書くのかを予想します。切り替えで変わるのは、ナビゲーション、お問い合わせのボタン、メニューのボタンの3つです。その条件を何か所に書くかも数えます。

ドロワーを作る要素も予想します。`div` をJavaScriptで開閉するのか、HTMLの開閉の機能を使うのか。ドロワーのナビゲーションに、ヘッダーと同じ `global-nav` を使うかどうかも決めてから読み進めます。

## 1行に収まらなくなったことを条件にする

メニューのボタンに切り替える幅を、画面の幅768pxのようなデバイスの幅で決めると、ナビゲーションの項目や文言が変わったときに合わなくなります。切り替える必要があるのは、ヘッダーの中身が1行に収まらなくなる幅で、それは中身の幅で決まるからです（「[13-2 ブレイクポイントの決め方](/responsive/breakpoints/)」）。

```css title="🙅‍♂ Not Recommended: デバイスの幅で、3つの要素をそれぞれ切り替える" issue="behavior"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.site-header) to (.scoped) {
  ._actions {
    @media (width < calc(768 / 16 * 1rem)) {
      display: none;
    }
  }

  ._menu {
    @media (width >= calc(768 / 16 * 1rem)) {
      display: none;
    }
  }
}
```

この書き方には、もう1つの問題があります。同じ閾値が、隠す側と表示する側の2か所に書かれていて、片方だけを直すと、ナビゲーションとメニューのボタンが両方とも表示されたり、両方とも消えたりする幅ができます。

ロゴ、ナビゲーション、お問い合わせのボタンの幅を足した式を閾値にすれば、中身から決められます。ただ、その式は、項目や文言を変えるたびに測り直して直す必要があります。知りたいのは「1行に収まるか」なので、ここでは閾値を書かず、ナビゲーションとお問い合わせのボタンの並び `._actions` が溢れたこと自体を条件にします（「[13-9 収まらなくなったらナビゲーションを折りたたむ](/responsive/overflow-collapse/)」）。

```css title="🙆‍♂ Recommended: 並びが溢れている間だけフラグを --true にし、3つの要素はフラグを読んで切り替える" from="exercise/drawer-1"
@keyframes --site-header--detect-overflow {
  from,
  to {
    --_overflowing: --true;
  }
}

@scope (.scoped.site-header) to (.scoped) {
  :scope {
    --_overflowing: --false;

    animation: --site-header--detect-overflow linear both;
    animation-timeline: --actions;
    timeline-scope: --actions;
  }

  ._header-inner {
    & > ._end {
      flex-grow: 1;
    }
  }

  ._end {
    display: block grid;

    & > * {
      grid-area: 1 / 1;
    }

    & > ._menu {
      justify-self: end;
    }
  }

  ._actions {
    contain: inline-size;
    display: block grid;
    grid-auto-columns: max-content;
    grid-auto-flow: column;
    justify-content: safe end;
    overflow-x: auto;
    scrollbar-width: none;
    scroll-timeline: --actions inline;

    @container style(--_overflowing: --true) {
      visibility: hidden;
    }
  }

  ._menu {
    @container style(--_overflowing: --false) {
      visibility: hidden;
    }
  }
}
```

`._actions` を横方向へスクロールできる要素にし、スクロールタイムライン `--actions` を作ります。スクロールタイムラインは、スクロールできるはみ出しがない間は無効で、それに結び付けたルートのアニメーションも効果を持ちません。並びが1行に収まらず溢れている間だけ、アニメーションがフラグ `--_overflowing` を `--true` にします。ルートの `timeline-scope` は、子孫の `._actions` が作ったタイムラインを、ルートから参照するための指定です。条件を書いたのは `._actions` の溢れの1つだけで、3つの要素は同じフラグを読むので、切り替えが食い違う幅はできません。

隠すときは、`display: none` ではなく `visibility: hidden` を使います（`hide-overflow-source-with-visibility`）。`display: none` にすると溢れが消えてフラグが `--false` に戻り、表示されるとまた溢れるので、表示と非表示を繰り返します。`visibility: hidden` の要素は場所を残すので、溢れたままの状態が続きます。

HTMLでは、`._actions` とメニューのボタン（`._menu`）を `._end` で包み、`._actions` から21-6で付けた `cluster` を外します。並びは折り返さずに溢れてほしいので、`cluster` ではなくGridの1行で組みます。`._actions` と `._menu` は、`._end` のGridの同じセルに重ねます。`._end` は、21-6の `apart` の中でロゴの横に残った幅をすべて受け取り、`._actions` はその幅の中に並びます。`._actions` に `contain: inline-size` を指定すると、その中身の幅が `._end` の幅の計算に入らなくなります。そのため `._end` は、狭い画面でもメニューのボタンの幅があれば、ロゴの横に並びます。ボタンも入らない幅では、21-6と同じように、ロゴの下へ回ります。

`justify-content` に `safe` を付けたのは、溢れた分を行末の側に出し、スクロールできるはみ出しにするためです。`safe` を付けずに `end` で寄せると、溢れた分が行頭の側に出ます。行頭側へのはみ出しはスクロールできないので、タイムラインが無効のまま残ります。Chromeで確かめたところ、`end` で寄せた並びは、溢れても `scrollWidth` が `clientWidth` と同じで、フラグは `--false` のままでした。`scrollbar-width: none` は、スクロールバーが場所を取る環境で、溢れた瞬間にヘッダーの高さが変わらないようにする指定です。ルートのコンテナは、21-6と同じ `scroll-state` だけで、幅のコンテナは要りません。

## ドロワーは dialog をモーダルで開く

ドロワーは `<dialog>` で作り、メニューのボタンの `command="show-modal"` でモーダルとして開きます。`showModal()` を呼ぶ処理を自分で書く必要はありません（「[17-6 開閉するUI](/interaction/disclosure/)」）。

```html title="🙆‍♂ Recommended: command 属性でドロワーをモーダルとして開き、閉じる" from="exercise/drawer-1"
<div class="_menu">
  <button class="scoped action-control" type="button" data-variant="secondary" commandfor="site-drawer" command="show-modal">メニュー</button>
</div>

<dialog class="scoped site-drawer" id="site-drawer" aria-label="メニュー" closedby="any">
  <div class="_drawer-header">
    <button class="scoped action-control" type="button" data-variant="secondary" commandfor="site-drawer" command="close">閉じる</button>
  </div>
  <div class="_navigation">
    <nav class="scoped global-nav" aria-label="メイン">…</nav>
  </div>
  <a class="scoped action-control" href="#contact">お問い合わせ</a>
</dialog>
```

ただし、`command` 属性と `commandfor` 属性に対応したのはSafari 26.2からで、本書が対象にするSafari 18.6では、メニューのボタンを押してもドロワーが開きません。狭い画面ではナビゲーションにたどり着けなくなります。ドロワーの外を押して閉じる `closedby` 属性には、Safariがまだ対応していないので、Safariではドロワーの外を押しても閉じません。どちらも要件に関わるので、対応していないブラウザでだけ、それぞれのポリフィルを読み込みます（`dialog-command-attributes`、「[17-6 開閉するUI](/interaction/disclosure/)」）。デモと配布版の `script.js` は、この2つの処理だけを書いたファイルです。

```js title="🙆‍♂ Recommended: command 属性と closedby 属性に対応していないブラウザでだけ、ポリフィルを読み込む" use="complete" from="exercise/drawer-1"
// command 属性と commandfor 属性に対応していないブラウザでは、メニューのボタンでドロワーを開けるようにポリフィルを読み込む
if (!('command' in HTMLButtonElement.prototype)) {
  import('https://cdn.jsdelivr.net/npm/invokers-polyfill@1.0.4/invoker.min.js');
}

// closedby 属性に対応していないブラウザでは、ドロワーの外を押して閉じられるようにポリフィルを読み込む
if (!('closedBy' in HTMLDialogElement.prototype)) {
  import('https://cdn.jsdelivr.net/npm/dialog-closedby-polyfill@1.3.0/index.min.js');
}
```

モーダルとして開いたダイアログは、外側の要素をすべて操作できなくし、フォーカスもダイアログの中だけを移ります。Escキーで閉じ、閉じたあとはフォーカスが開いたボタンへ戻ります。どれもブラウザの機能なので、フォーカスを閉じ込める処理を自分で書きません（`no-custom-focus-trap`）。ドロワーの外を押して閉じる動作は、`closedby="any"` に任せます。`closedby` 属性に対応していないブラウザでは、上で読み込んだポリフィルが同じ動作を補います。背面のスクロールは、ベーススタイルの `:root:has(:modal)` で止めます（「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」）。

開閉の動きは、`@starting-style` と `transition-behavior: allow-discrete` で付けます（「[18-7 出現と退場](/motion/entry-and-exit/#ダイアログの開閉を動かす)」）。

```css title="🙆‍♂ Recommended: 動き始めの位置を変数にし、動きを減らす設定ではフェードだけにする" from="exercise/drawer-1"
@scope (.scoped.site-drawer) to (.scoped) {
  :scope {
    --_translate-from: 0;

    z-index: var(--z--top);
    transition-duration: var(--duration--slow);
    transition-property: display, overlay, opacity, translate;
    transition-timing-function: var(--ease--out-quint);
    transition-behavior: allow-discrete;

    @media (prefers-reduced-motion: no-preference) {
      --_translate-from: 100% 0;
    }

    &:modal {
      @starting-style {
        opacity: 0;
        translate: var(--_translate-from);
      }
    }

    &:not(:modal) {
      opacity: 0;
      translate: var(--_translate-from);
    }
  }
}
```

動き始めの位置を `--_translate-from` にまとめ、動きを減らす設定のときは0のままにします。画面の端から大きく動くパネルは、動きを減らす設定ではフェードに置き換えます（`simplify-large-motion-when-reduced`）。

## 同じナビゲーションを縦に並べる

ドロワーのナビゲーションには、ヘッダーと同じ `global-nav` を使います。リンクの中身はどちらも同じで、違うのは並べ方だけだからです。並べ方の違いは、置き場所の違いなので、置く側のドロワーが公開プロパティのフラグを渡し、`global-nav` がそれを読みます（「[10-7 置き場所と子の状態を伝える](/components/placement-and-child-states/)」）。

```css title="🙆‍♂ Recommended: ドロワーは包む要素でフラグを渡し、ナビゲーションは内部プロパティに受けて読む" from="exercise/drawer-1"
@scope (.scoped.site-drawer) to (.scoped) {
  ._navigation {
    --global-nav--stacked: --true;

    overflow-y: auto;
    overscroll-behavior-block: contain;
  }
}

@scope (.scoped.global-nav) to (.scoped) {
  :scope {
    --_stacked: var(--global-nav--stacked, --false);
  }

  ul {
    --cluster--gap: 0;

    @container style(--_stacked: --true) {
      flex-direction: column;
    }
  }

  a {
    @container style(--_stacked: --true) {
      padding-block: 16px;
      font-size: calc(var(--text--subtitle--font-size) / 16 * 1rem);
      line-height: var(--text--subtitle--leading);
    }
  }
}
```

ヘッダーは何も渡さないので、ナビゲーションは横に並んだままです。渡せる公開プロパティは、`global-nav` のCSSの先頭の説明ブロックに、`@prop` で型とデフォルト値を書いておきます（「[9-10 コメントの書き方](/notation/comments/)」）。ドロワーのナビゲーションは、項目が増えて画面に収まらなくなると、`._navigation` の中だけがスクロールし、その端で背面へスクロールが連鎖しないようにしています（`overscroll-contain-in-overlay`）。

## CSSは直さない

CSSは直していません。直したのは、ヘッダーとドロワーのナビゲーションのHTMLに、「よくある質問」の項目を足したことだけです。

項目が増えると、`._actions` の並びが長くなり、前より広い幅で溢れるようになります。切り替える幅は、約840pxから約950pxへ、項目の分だけ自然に広がりました。幅を足した式を閾値にしていたなら、ナビゲーションの文字の幅と余白の数を直す必要がありました。直し忘れると、約840pxから約950pxの間で、ナビゲーションが1行に収まらず、ヘッダーが2行に折り返します。768pxで切り替える書き方では、項目の数にかかわらず、770pxから950pxの間で同じことが起きます。

ドロワーのCSSも直していません。ドロワーのナビゲーションは縦に並ぶので、項目が増えても列に収まり、収まらなくなれば `._navigation` の中がスクロールします。

## 振り返り

直したのは、2つのナビゲーションのHTMLだけです。切り替える条件は、ヘッダーの中身が溢れたかどうかで、どこにも幅の値を書いていないので、項目の数に関わりませんでした。条件を書いたのは `._actions` の溢れの1か所だけなので、ナビゲーションとメニューのボタンの切り替えが食い違う幅もできません。

直さずに済んだのは、ヘッダー、ドロワー、`global-nav`、お問い合わせのボタンのCSSです。ドロワーの開閉はブラウザの機能に任せ、縦の並びは置く側から渡したフラグで決めていたので、項目の数には関わりませんでした。

予想と見比べたら、自分の変更を次の3つの点で見直します。

- 切り替える条件を、画面の幅ではなく、ヘッダーの中身が1行に収まるかどうかで決められたか。768pxのようなデバイスの幅で書いていたなら、項目が増えたときに折り返す幅を挙げられるか。
- 条件を書いた場所は1か所か。隠す側と表示する側に分けて書いていたなら、片方だけを直したときに何が起きるかを説明できるか。
- ドロワーのナビゲーションを縦に並べる条件を、ドロワーのCSSから `global-nav` の中を選んで書いていないか。

## 判断の問い

### 問い1

ヘッダーのナビゲーションを `visibility: hidden` ではなく `display: none` で隠すと、何が起きますか。

<details>
{/* textlint-disable ja-technical-writing/ja-no-mixed-period */}
<summary>答えと解説</summary>
{/* textlint-enable ja-technical-writing/ja-no-mixed-period */}

`._actions` を `display: none` にすると、並びがレイアウトから消えて溢れもなくなるので、スクロールタイムラインが無効に戻り、フラグが `--false` になります。するとナビゲーションが再び表示されて溢れ、フラグが `--true` に戻ります。この切り替えが続き、狭い幅でナビゲーションとメニューのボタンが定まりません。溢れを測る要素は、場所を残したまま隠す `visibility: hidden` で隠します（`hide-overflow-source-with-visibility`）。

</details>

### 問い2

ドロワーを `<dialog>` のモーダルではなく、`popover` 属性で開くパネルにしてもよいですか。

このドロワーには向きません。`popover` で開いた要素はモーダルにならないので、背面のページを操作できたままになり、フォーカスもパネルの外へ出ます。画面の高さいっぱいに広がり、背面を覆うドロワーは、モーダルの `<dialog>` で作ります。`popover` は、ボタンの近くに出す小さなメニューやツールチップのように、背面を操作できたままでよい表示に使います（`native-disclosure-elements`）。

</details>

## この節で使ったルール

- [`breakpoint-from-content`](/responsive/breakpoints/#rule-breakpoint-from-content)：ブレイクポイントはデバイスの幅ではなく、レイアウトが崩れる幅から決めます。
- [`collapse-nav-on-overflow`](/responsive/overflow-collapse/#rule-collapse-nav-on-overflow)：項目の数や文言が変わる横並びを、1行に収まらなくなったらメニューのボタンに切り替えるときは、横並び自身の溢れを検知したフラグで切り替えます。
- [`hide-overflow-source-with-visibility`](/responsive/overflow-collapse/#rule-hide-overflow-source-with-visibility)：溢れを検知して隠す要素は、`visibility: hidden` で隠し、`display: none` にしません。
- [`state-flag-values`](/components/style-queries/#rule-state-flag-values)：オンとオフの2値のフラグは、`--true` と `--false` にそろえます。
- [`native-disclosure-elements`](/interaction/disclosure/#rule-native-disclosure-elements)：開閉するUIは、`<dialog>` や `popover` 属性のようなHTMLの機能で作ります。
- [`dialog-command-attributes`](/interaction/disclosure/#rule-dialog-command-attributes)：モーダルの開閉は、`command` 属性と `commandfor` 属性で行い、対応していないブラウザのためにポリフィルを読み込みます。
- [`dialog-closedby-any`](/interaction/disclosure/#rule-dialog-closedby-any)：背景のクリックで閉じるモーダルは、`closedby="any"` で作ります。
- [`no-custom-focus-trap`](/interaction/disclosure/#rule-no-custom-focus-trap)：モーダルに、独自のフォーカストラップを実装しません。
- [`modal-scroll-lock-root`](/reset/base-styles/#rule-modal-scroll-lock-root)：モーダル表示中の背面のスクロールは、`:root:has(:modal)` で止めます。
- [`overscroll-contain-in-overlay`](/interaction/disclosure/#rule-overscroll-contain-in-overlay)：ドロワーの中でスクロールする要素には、スクロールの連鎖を止める指定をします。
- [`starting-style-for-entry`](/motion/entry-and-exit/#rule-starting-style-for-entry)：`display: none` から表示する要素の出現と退場は、`@starting-style` と `transition-behavior: allow-discrete` で動かします。
- [`simplify-large-motion-when-reduced`](/motion/reduced-motion/#rule-simplify-large-motion-when-reduced)：大きな動きは、動きを減らす設定のときにフェードへ置き換えます。
- [`placement-via-public-flag`](/components/placement-and-child-states/#rule-placement-via-public-flag)：置き場所によって見た目を変えるときは、置く側が公開プロパティのフラグを渡します。
- [`top-layer-z-index-top`](/components/boundaries/#rule-top-layer-z-index-top)：トップレイヤーに表示する `<dialog>` にも、`z-index: var(--z--top)` を指定します。
