三角形のような図形は、`border` の組み合わせではなく `clip-path` で描き、`polygon()` の値は `--shape--triangle-bottom` のような名前のトークンにします。`clip-path` は要素の見える範囲を図形で決め、`mask-image` は画像の不透明度で決めます。どちらも要素の大きさと位置を変えないので、見える範囲を変えてもレイアウトは変わりません。

選んだタブの背景色と文字色を変えるときは、選んだときの色で描いた列を通常の列に重ね、上の列を選んだタブの範囲だけ `clip-path` で切り抜きます。切り抜く範囲を `transition` で動かせば、選んだ色が隣のタブへ滑って移ります。スクロールできる領域の端で続きを示すときは、スクロールコンテナの `mask-image` に両端が透明になるグラデーションを指定し、スクロール駆動アニメーションで、まだスクロールできる側の端だけを薄くします。アバターに重ねたバッジの周りに隙間を見せるときは、バッジに背景色の縁を付けず、奥のアバターを `radial-gradient()` のマスクで円く切り抜きます。

単色のアイコンをマスクで描く方法は「[16-3 アイコンとSVG](/decoration/icons-and-masks/)」で、`clip-path` の `shape()` で輪郭を描く方法と、マスクの合成で枠線やドーナツグラフを描く方法は「[16-9 輪郭と枠線を描く](/decoration/outlines/)」で説明しています。

## 図形は clip-path で描く

吹き出しの三角形のような図形は、`clip-path` で描きます。以前は、透明な `border` を組み合わせて三角形を作る方法がよく使われていました。

```css title="🙅‍♂ Not Recommended: border を組み合わせて三角形を作る" issue="convention"
/* 🙅‍♂ Not Recommended */
._tooltip {
  &::after {
    --_size: 16px;

    content: "";

    /* ... */
    border-block-start: calc(var(--_size) / 2 * tan(60deg)) solid;
    border-inline-start: calc(var(--_size) / 2) solid transparent;
    border-inline-end: calc(var(--_size) / 2) solid transparent;
  }
}
```

この方法では、三角形の大きさを3つの `border` の幅から逆算する必要があり、どの向きの三角形なのかもコードから読み取りにくくなります。`clip-path` なら、要素の幅と縦横比を決めて、形で切り抜くだけです。

```css title="🙆‍♂ Recommended: 形をトークンにして、clip-path で切り抜く" from="decoration/clip-path-triangle"
:root {
  --shape--triangle-top: polygon(50% 0, 100% 100%, 0 100%);
  --shape--triangle-bottom: polygon(0 0, 100% 0, 50% 100%);
  --shape--triangle-right: polygon(0 0, 100% 50%, 0 100%);
  --shape--triangle-left: polygon(0 50%, 100% 0, 100% 100%);
}

._tooltip {
  position: relative;

  &::after {
    --_size: 16px;

    content: "";

    /* ツールチップの下端の中央から、下へ突き出す */
    position: absolute;
    inset-block-start: 100%;
    inset-inline-start: 50%;
    clip-path: var(--shape--triangle-bottom);
    inline-size: var(--_size);
    aspect-ratio: 2 / tan(60deg);
    background-color: inherit;
    translate: -50% 0;
  }
}
```

<Demo title="形のトークンで切り抜いた三角形と、下向きの三角形を付けたツールチップ" html={triangleHtml} css={triangleCss} />

デモの上は、下端の中央に下向きの三角形を付けたツールチップです。その下には、4つの形のトークンで正方形を切り抜き、上、下、右、左を向いた三角形を並べています。

三角形は、ツールチップの本体を基準に絶対配置します。絶対配置した擬似要素はブロックの箱になるので、`display` を指定しなくても、`inline-size` と `aspect-ratio` で大きさが決まります。`translate: -50% 0` で三角形の幅の半分だけ戻し、本体の中央にそろえます。

`polygon()` の値は直接書かず、トークンとして定義します。`polygon(0 0, 100% 0, 50% 100%)` という値を見て、下向きの三角形だとすぐに気づく人は多くないでしょう。`--shape--triangle-bottom` という名前なら、形がすぐに分かります。縦横比を `2 / tan(60deg)` にすると、正三角形になります（Chromeで確認）。{/* 要検証: ブラウザ。Safari 18 と Firefox で、aspect-ratio の比に書いた tan() が効くか */}

切り抜いた形に影を付けるときは、`clip-path` を指定した要素ではなく、親の要素に `filter: drop-shadow()` を指定します。`clip-path` は、要素の背景だけでなく、要素の外に描かれる `box-shadow` も切り取るからです。同じ要素に指定した `filter` の影も、切り抜きの前に描かれるので一緒に切り取られます（Filter Effects Module Level 1）。`drop-shadow()` は、要素の箱ではなく描かれた形の不透明な部分に沿って影を付けるので、親に指定すれば、切り抜いた後の三角形の輪郭どおりに影が付きます。

```css title="🙆‍♂ Recommended: 三角形を含むツールチップ全体に、親の filter で影を付ける"
._tooltip {
  filter: var(--drop-shadow--sm);
}
```

ツールチップの三角形は擬似要素なので、`._tooltip` に指定した `filter` は、本体と三角形を合わせた形に1つの影を付けます。Chromeで確かめたところ、`clip-path` で切り抜いた要素自身に指定した `box-shadow` と `drop-shadow()` はどちらも表示されず、親に指定した `drop-shadow()` は三角形の形に沿って表示されました。`drop-shadow()` のトークンと、`box-shadow` との違いは「[16-5 面・影・角丸](/decoration/surfaces/#影を動かすときは-drop-shadow-を動かす)」で説明しています。

## 2つの層を重ねて、選んだ範囲だけを切り抜く

`clip-path` は、図形を描くだけでなく、同じ大きさの層を2つ重ねて、上の層の一部だけを見せる使い方もできます。横に並んだタブで、選んだタブの背景色と文字色を変える場面で考えます。通常の色で描いたタブの列の上に、選んだときの色で描いた同じ列を重ね、上の列を選んだタブの範囲だけ切り抜きます。{/* 要確認: 出典なし */}

```css title="🙆‍♂ Recommended: 選んだときの色で描いた列を重ね、選んだタブの範囲だけを切り抜く" from="decoration/segmented-tabs"
@scope (.scoped.segmented-tabs) to (.scoped) {
  :scope {
    --_count: 3;
    --_index: 0;

    display: block grid;

    &:has(._tab:nth-child(2)[aria-selected="true"]) {
      --_index: 1;
    }

    &:has(._tab:nth-child(3)[aria-selected="true"]) {
      --_index: 2;
    }

    & > ._list,
    & > ._highlight {
      grid-area: 1 / 1;
    }
  }

  ._list,
  ._highlight {
    display: block grid;
    grid-auto-columns: 1fr;
    grid-auto-flow: column;
  }

  ._highlight {
    /* xywh() の位置は左端から数えるので、右から左へ書く言語では、選んだタブが左から何番目かに数え直す */
    --_clip-start: calc(var(--_index) * 100% / var(--_count));
    --_background: var(--background--accent);

    clip-path: xywh(var(--_clip-start) 0 calc(100% / var(--_count)) 100% round var(--rounded--full));
    background-color: var(--_background);
    color: var(--foreground--on-accent);
    pointer-events: none;

    /* 強制カラーモードでは背景色がページの背景色に置き換わるので、帯を選んだ状態のシステムカラーで塗る */
    @media (forced-colors: active) {
      --_background: SelectedItem;

      color: SelectedItemText;
    }

    &:dir(rtl) {
      --_clip-start: calc((var(--_count) - 1 - var(--_index)) * 100% / var(--_count));
    }
  }
}
```

<Baseline id="rect-xywh" compatKey="css.types.basic-shape.xywh" name="xywh()" />

上の列の背景色は、内部プロパティ `--_background` から受け取ります。強制カラーモードでは、`background-color` がページの背景色に置き換わり、帯と文字色の差がどちらも消えて、どのタブを選んだかが分からなくなります。そこで、強制カラーモードでは `--_background` を選んだ状態のシステムカラー `SelectedItem` に、文字色を `SelectedItemText` に切り替えます（「[15-5 強制カラーモードとコントラスト](/color-media/forced-colors/)」）。{/* 要検証: ブラウザ。強制カラーモードで、切り抜いた帯が SelectedItem で表示されるか */}

下の列（`._list`）は、`role="tab"` を付けた `<button>` を並べた、操作するためのタブです。上の列（`._highlight`）は見た目のためだけの複製なので、`aria-hidden="true"` で読み上げから外し、中身は `<span>` にしてフォーカスを受けないようにします。`pointer-events: none` で、クリックは下のタブに通します。どのタブを選んでいるかは、`aria-selected` から `:has()` で読み取り、`--_index` に入れています。

次のデモでは、タブを選ぶとスクリプトが `aria-selected` を付け替え、`:has()` で決まる `--_index` が変わります。上の列を切り抜く範囲が選んだタブへ滑って移り、帯が通った部分から背景と文字の色が切り替わります。キーボードでは、左右の矢印キーでタブを移れます。パネルの中身は文章だけでフォーカスできる要素がないので、パネルに `tabindex="0"` を付け、選んだタブからTabキーでパネルへ移れるようにしています（WAI-ARIA APGのタブのパターン）。切り抜く範囲を動かす書き方は、次の見出しで説明します。

<Demo title="選んだときの色で描いた列を重ね、選んだタブの範囲だけを切り抜いて見せる" html={segmentedHtml} css={segmentedCss} js={segmentedJs} />

この方法では、選んだときの見た目を1つの列としてまとめて描けます。角丸の帯をタブの区切りと関係なく置くことも、列全体に掛けたグラデーションのうち選んだ範囲だけを見せることもできます。選択が変わったときに変わるのは、切り抜く範囲だけです。`xywh()` の位置は、書字方向に関係なく左端から数えます。右から左へ書く言語では、Gridの列は右から並ぶのに切り抜く範囲は左から数えたままなので、何もしないと、1つ目のタブを選んだときに左端の3つ目のタブが青くなります。そこで、切り抜く範囲の始まりを `--_clip-start` に分け、`:dir(rtl)` では `--_count - 1 - --_index` 番目の位置から数え直しています。矢印キーも、右から左へ書く言語では、左の矢印キーで次のタブに移るように、見た目の向きに合わせています。

### 選んだ色を隣のタブへ滑らせる

切り抜く範囲は `clip-path` の値なので、`transition` で動かせます。選択が変わると、上の列の見える範囲が前のタブから選んだタブへ移り、帯が通り過ぎた部分から文字色が切り替わります。文字色を切り替えるタイミングを別に指定する必要はありません。帯の端と文字色の境目は、同じ切り抜きの端なので、いつも一致します。

```css title="🙆‍♂ Recommended: 切り抜く範囲の変化を、短いトランジションで動かす"
@scope (.scoped.segmented-tabs) to (.scoped) {
  ._highlight {
    @media (prefers-reduced-motion: no-preference) {
      transition-duration: var(--duration--press);
      transition-property: clip-path;
      transition-timing-function: var(--ease--in-out-quint);
    }
  }
}
```

前の見出しのデモの `._highlight` には、この3つの宣言を足しています。タブは続けて押されるUIなので、`@keyframes` ではなくトランジションで書きます（「[18-4 トランジションの基本と中断](/motion/transitions-and-keyframes/)」）。再生時間は、続けて押されるUIの目安の100〜150msに収まる `--duration--press`（120ms）にしています。トランジションは、動いている途中でほかのタブを押すと、その時点の範囲から新しいタブへ向かい直します。Chromeで、帯が移っている途中に別のタブを押すと、切り抜く範囲が途中の値から新しいタブへ向かうことを確かめました。イージングは、画面の上にある帯の移動なので `in-out` 系のトークンを選んでいます（「[18-3 イージングと再生時間](/motion/easing-and-duration/)」）。

帯が横に移る動きは、色の変化ではなく位置の変化です。トランジションの指定は `@media (prefers-reduced-motion: no-preference)` の中に書き、動きを減らす設定では、切り抜く範囲が一度で切り替わります（「[18-2 動きを減らす設定に対応する](/motion/reduced-motion/)」）。帯が動かなくても、どのタブを選んだかは帯の色で伝わり、強制カラーモードでもシステムカラーの帯が残るので、動きを省いても情報は欠けません。Chromeで、動きを減らす設定を模したときにトランジションが起きないことも確かめました。

`clip-path` のアニメーションでは、レイアウトは起きず、ブラウザと値によっては描き直しも避けられます。切り抜く範囲が変わっても、上の列の大きさと位置は変わらないので、ほかの要素の配置にも影響しません。Chromeで、帯が移る間の切り抜きのトランジションがコンポジタのスレッドで進み、押した直後を除いて描き直しが起きないことを、パフォーマンスのトレースで確かめました。動かすプロパティと負荷の関係は、「[18-10 動きの負荷を抑える](/motion/performance/)」で説明しています。{/* 要検証: ブラウザ。Firefox と Safari で、clip-path のトランジションで描き直しが起きるか、進行がコンポジタのスレッドに移るか */}

項目から項目へ背景を移す表現は、アンカーポジショニングでも作れます。「[11-8 アンカーポジショニング](/layout-practice/anchor-positioning/)」では、ホバーした項目をアンカーにして、背景の位置と大きさをその項目に合わせています。アンカーを基準にすれば、幅のそろわない項目にも背景の大きさが合います。一方、背景は文字の後ろに置く1つの要素なので、帯に重なった部分だけ文字色を変えることはできず、`anchor()` の値の変化を補間できるブラウザも限られます。この見出しの方法は、タブの幅をそろえる必要があるかわりに、帯と文字色の境目が一致します。幅のそろったタブで選んだ色を見せるならこの方法を、幅のそろわない項目へ背景を追従させるならアンカーポジショニングを選びます。

## スクロールできる領域の端をマスクで薄くする

横にスクロールできるタグやタブの列では、続きがあることを見た目で示します。端に線や影を付ける方法は、そこで区切られているように見え、続きがあることは伝わりにくくなります。背景と同じ色のグラデーションを端に重ねる方法は、背景が写真や別の色になると色がずれて、帯が浮いて見えます。{/* 要確認: 出典なし */}

端を薄くするときは、スクロールコンテナの `mask-image` に、両端が透明になるグラデーションを指定します。マスクは要素の中身そのものを透かすので、背景が何色でも、端の項目が途中で薄れて、続きがあるように見えます。マスクに使われるのはグラデーションの不透明度だけなので、`#000` は「そのまま見せる」範囲を表しているだけです。

タグの列は、Gridの `grid-auto-flow: column` で1列に並べ、`grid-auto-columns: max-content` で各タグを文字の幅のまま並べています。横にスクロールさせる並びの組み方は、「[12-12 reel](/compositions/reel/)」で説明しています。

```css title="🙆‍♂ Recommended: スクロールコンテナの両端を、マスクのグラデーションで薄くする"
@scope (.scoped.tag-scroller) to (.scoped) {
  ul {
    --_fade: 24px;

    display: block grid;
    grid-auto-columns: max-content;
    grid-auto-flow: column;
    gap: 8px;
    overflow-x: auto;
    mask-image: linear-gradient(to right, transparent, #000 var(--_fade), #000 calc(100% - var(--_fade)), transparent);
  }
}
```

グラデーションの向きには、`to inline-end` のような論理方向のキーワードがありません。Chromeでは、`CSS.supports()` で `linear-gradient(to inline-end, …)` が無効と判定されました。そこで、両端を同じ幅で薄くして、グラデーションを左右対称にします。右から左へ書く言語でも、同じ見た目になります。マスクのプロパティは、2023年12月までにすべての主要なブラウザが接頭辞なしで対応したので、`-webkit-` の接頭辞は要りません。

<Baseline id="masks" name="マスク（mask-image など）" />

マスクは、要素の境界の外に描かれるものも切り取ります。Chromeで確かめたところ、マスクを指定したスクロールコンテナの `outline` は表示されませんでした。中にリンクのないスクロールコンテナは、キーボードでフォーカスを受けることがあり、そのときのフォーカスリングも見えなくなります。この場合は、親の要素に `&:has(> ul:focus-visible)` でリングを出します。リングを親に出す書き方は、「[17-4 カード全体をリンクにする](/interaction/card-link/)」の例と同じです。

### スクロールできる側の端だけを薄くする

上の例は、中身が収まっていてスクロールできないときも両端を薄くし、先頭にいるときも先頭の側を薄くします。端を薄くするのは続きがあることを示すためなので、薄くするのは、その方向にまだスクロールできる端だけにします。そのためには、薄くする幅をスクロールの位置に合わせて変えます。スクロールの位置を進み具合にして値を変える仕組みが、スクロール駆動アニメーションです（「[18-9 スクロールに合わせて動かす](/motion/scroll-driven/)」）。

```css title="🙆‍♂ Recommended: スクロールの位置に合わせて、スクロールできる側の端だけを薄くする" from="decoration/scroll-fade-edges"
@property --tag-scroller--fade-start {
  syntax: "<length>";
  inherits: false;
  initial-value: 0;
}

@property --tag-scroller--fade-end {
  syntax: "<length>";
  inherits: false;
  initial-value: 0;
}

@keyframes --tag-scroller--leave-start {
  to {
    --tag-scroller--fade-start: var(--_fade);
  }
}

@keyframes --tag-scroller--reach-end {
  from {
    --tag-scroller--fade-end: var(--_fade);
  }
}

@scope (.scoped.tag-scroller) to (.scoped) {
  :scope {
    --_fade: 32px;
    --_direction: to right;

    display: block grid;
    grid-auto-columns: max-content;
    grid-auto-flow: column;
    gap: 8px;
    overflow-x: auto;

    @supports (animation-timeline: scroll()) and (animation-range: 0 32px) {
      mask-image: linear-gradient(var(--_direction), transparent, #000 var(--tag-scroller--fade-start), #000 calc(100% - var(--tag-scroller--fade-end)), transparent);
      animation-name: --tag-scroller--leave-start, --tag-scroller--reach-end;
      animation-timing-function: linear;
      animation-fill-mode: both;
      animation-timeline: scroll(self inline);
      animation-range: 0 var(--_fade), calc(100% - var(--_fade)) 100%;
    }

    &:dir(rtl) {
      --_direction: to left;
    }
  }
}
```

<Baseline id="scroll-driven-animations" />

マスクのグラデーションは、2つのカスタムプロパティを、先頭の側と末尾の側で薄くする幅として参照します。`animation-timeline: scroll(self inline)` は、要素自身のインライン方向のスクロールを進み具合にします。`scroll()` は、何も指定しなければ最も近い祖先のスクロールコンテナを測るので、スクロールコンテナ自身に指定するときは `self` を書きます。

2つのアニメーションは、`animation-range` で受け持つ範囲を分けています。`--tag-scroller--leave-start` は、先頭から32pxスクロールする間に、先頭の側の幅を0から32pxに広げます。`--tag-scroller--reach-end` は、末尾の手前の32pxの間に、末尾の側の幅を32pxから0に狭めます。`animation-fill-mode: both` を指定しているので、範囲の前後では、それぞれの端の値が残ります。その結果、先頭にいるときは末尾の側だけが、途中では両側が、末尾に着いたときは先頭の側だけが薄くなります。幅はスクロールの位置に合わせて少しずつ変わるので、端に着いたところで薄さが急に消えることもありません。

中身が収まっていてスクロールできない要素では、どちらの端も薄くなりません。スクロールできる範囲が0なので、スクロールのタイムラインが非アクティブになるからです（Scroll-driven Animations Level 1）。非アクティブなタイムラインでは、アニメーションの現在の時間が決まらないので、`animation-fill-mode: both` を指定していても、アニメーションは当たりません。2つの幅は登録した初期値の0のままになり、グラデーションは端まで不透明になります。中身を減らしてはみ出さなくなったときも、同じように薄さが消えました。

幅は、`@property` で `<length>` 型に登録します。登録していないカスタムプロパティは、キーフレームの間で値が補間されず、進み具合の途中で切り替わるだけです。`inherits: false` で登録し、`@property` を `@scope` の外に書く理由は、「[18-5 トランジションを応用する](/motion/transition-techniques/#複数の値を1つのカスタムプロパティで一緒に動かす)」で説明しています。継承しないので、2つの幅を参照する `mask-image` は、アニメーションを指定した要素自身に書きます。

次のデモの2つの列は、同じCSSで、タグの数だけが違います。1つ目の列はタグがはみ出すので、最初は右端だけが薄くなっています。スクロールすると左端も薄くなり、末尾まで送ると右端の薄さが消えます。2つ目の列はタグが2つで収まり、どちらの端も薄くなりません。

<Demo title="はみ出す列ではスクロールできる側の端だけを薄くし、収まる列では薄くしない" html={scrollFadeHtml} css={scrollFadeCss} />

グラデーションの向きには論理方向のキーワードがないので、片側だけを薄くするときは、右から左へ書く言語で向きを反転させます。一方、`scroll(self inline)` の進み具合は、書字方向の先頭から数えます。右から左へ書く言語では、右端にいるときが進み具合の0%です。そのため、アニメーションはそのままにして、`:dir(rtl)` で `--_direction` を `to left` に変えるだけで済みます（Chromeで `dir="rtl"` の列を確認）。{/* 要検証: ブラウザ。Safari 26 で、非アクティブなタイムラインのときにアニメーションが当たらないことと、右から左へ書く列の進み具合の向き */}

マスクとアニメーションは、一緒に `@supports` の中に書きます。スクロール駆動アニメーションに対応していない環境（Firefox）では、マスクが付かず、端が薄くならないだけです。続きがあることは見た目で示せなくなりますが、スクロールすれば続きを見られるので、操作は損なわれません。

このアニメーションは、動きを減らす設定の条件で囲みません。変わるのは端を薄くする範囲だけで、要素の位置と大きさは変わらないからです。中身が動くのはユーザー自身がスクロールしたからで、アニメーションが中身を動かしているわけではありません。「[18-2 動きを減らす設定に対応する](/motion/reduced-motion/)」の目安では、位置と大きさの変わらない変化は大きな変動にあたらず、スクロールに合わせた変形にもあたりません。スクロールに合わせてヘッダーの背景をフェードインさせる18-6の例と同じ扱いです。

スクロールできる方向は、`scroll-state(scrollable: inline-end)` のコンテナクエリでも判定できます（「[11-7 固定ヘッダー](/layout-practice/sticky-header/#留まっている間だけ見た目を変える)」）。しかし、コンテナクエリで変えられるのはコンテナの子孫だけなので、スクロールコンテナ自身の `mask-image` は切り替えられません。条件が成り立つかどうかで切り替わるので、端に近づくにつれて幅を狭めることもできません。`scroll-state()` のクエリに対応しているのはChrome系のブラウザだけです。端を薄くするのには、スクロール駆動アニメーションを使います。

## 重なった要素の周りをマスクで切り抜く

アバターの右下に重ねた状態のバッジや、少しずつ重ねて並べたアバターでは、手前の要素の周りに細い隙間を見せて、奥の要素と見分けられるようにします。よく使われるのは、手前の要素に、背景と同じ色の `border` や `box-shadow` で縁を付ける方法です。{/* 要確認: 出典なし。アバターとバッジの隙間をマスクで切り抜く方法 */}

```css title="🙅‍♂ Not Recommended: ページの背景と同じ色の影で、バッジの縁を描く" issue="behavior"
/* 🙅‍♂ Not Recommended */
._badge {
  /* ... */
  box-shadow: 0 0 0 3px var(--background--base);
}
```

この縁は、透明な隙間ではなく、背景の色で塗った輪です。置いた場所の背景がページの背景と同じ色のときだけ、隙間に見えます。カードやダイアログの面に置くと、縁の色が面の色からずれます。ライトモードでは面がどれも白に近く目立ちませんが、ダークモードでは高い面ほど背景を明るくするので、暗い輪が浮きます（「[16-5 面・影・角丸](/decoration/surfaces/)」）。背景が写真やグラデーションなら、どの色を選んでも合いません。

縁を塗る代わりに、奥の要素の、手前の要素と重なる部分を `mask-image` で切り抜きます。切り抜いた部分は透明になるので、そこには置いた場所の背景がそのまま見えます。円く切り抜くマスクは、中心から一定の半径までが透明な `radial-gradient()` で書けます。

```css title="🙆‍♂ Recommended: バッジの大きさと隙間の幅から、アバターを切り抜く円を計算する"
@scope (.scoped.status-avatar) to (.scoped) {
  :scope {
    --_size: 40px;
    --_badge-size: 12px;
    --_gap: 3px;

    /* バッジの中心。バッジはアバターの右下の角に、外接する正方形の角を合わせて置く */
    --_badge-x: calc(var(--_size) - var(--_badge-size) / 2);
    --_badge-y: calc(var(--_size) - var(--_badge-size) / 2);

    /* 切り抜く円の半径。バッジの半径に、見せたい隙間の幅を足す */
    --_cutout-radius: calc(var(--_badge-size) / 2 + var(--_gap));

    position: relative;
    display: inline grid;
    inline-size: var(--_size);
    aspect-ratio: 1;

    & > ._badge {
      position: absolute;
      inset-block-end: 0;
      inset-inline-end: 0;
    }

    &:dir(rtl) {
      --_badge-x: calc(var(--_badge-size) / 2);
    }
  }

  ._avatar {
    mask-image: radial-gradient(circle at var(--_badge-x) var(--_badge-y), transparent var(--_cutout-radius), #000 calc(var(--_cutout-radius) + 1px));
    border-radius: var(--rounded--full);
  }

  ._badge {
    inline-size: var(--_badge-size);
    aspect-ratio: 1;
    border-radius: var(--rounded--full);
  }
}
```

切り抜く円の中心と半径は、バッジの大きさと隙間の幅から決まる値です。計算した結果の `34px` や `9px` を書かず、式のまま書いて、それぞれの値にカスタムプロパティで名前を付けます（「[6-3 計算関数で根拠を式に残す](/values/math-functions/#rule-name-calc-operands)」）。バッジを大きくしたり、隙間を広げたりしても、切り抜く円が一緒に変わります。透明から黒への境目を1pxずらしているのは、円の縁をなめらかにするためです（「[16-8 角の形を変える](/decoration/shapes/)」の反り返るタブのマスクと同じ書き方です）。

`radial-gradient()` の中心の位置は、左上から数えます。バッジは `inset-inline-end` で書字方向の末尾の側に置いているので、右から左へ書く言語では左下に移ります。そこで、`:dir(rtl)` で中心の横の位置だけを、左端からバッジの半径の位置に変えます。

<Demo title="背景色の影で描いた縁は面によって浮き、マスクで切り抜いた隙間はどの面にもなじむ" html={avatarCutoutHtml} css={avatarCutoutCss} />

デモの各段の左は、ページの背景と同じ色の影でバッジとアバターの縁を描き、右は奥のアバターをマスクで切り抜いています。1段目のページの背景の上では、左右の見た目は変わりません。2段目のカードの面の上では、ダークモードにすると、左だけ縁が暗い輪として見えます。3段目のグラデーションの上では、ライトモードとダークモードのどちらでも左の縁が浮き、右の隙間にはグラデーションが透けて見えます（Chromeで確認）。

重ねて並べたアバターも、同じ考え方で切り抜きます。各アバターの末尾の側に、次のアバターと重なる部分を、次のアバターの半径に隙間の幅を足した円で切り抜きます。最後のアバターには重なる相手がいないので、マスクを指定しません。

```css title="🙆‍♂ Recommended: 次のアバターと重なる部分を、各アバターから切り抜く"
@scope (.scoped.avatar-stack) to (.scoped) {
  :scope {
    --_size: 32px;
    --_overlap: 10px;
    --_gap: 3px;

    /* 次のアバターの中心。自分の幅から重なりを引いた位置に、次のアバターの半径を足す */
    --_next-x: calc(var(--_size) - var(--_overlap) + var(--_size) / 2);

    /* 切り抜く円の半径。次のアバターの半径に、見せたい隙間の幅を足す */
    --_cutout-radius: calc(var(--_size) / 2 + var(--_gap));

    display: block flex;

    & > * + * {
      margin-inline-start: calc(var(--_overlap) * -1);
    }

    &:dir(rtl) {
      --_next-x: calc(var(--_overlap) - var(--_size) / 2);
    }
  }

  ._avatar {
    inline-size: var(--_size);
    aspect-ratio: 1;
    border-radius: var(--rounded--full);

    &:not(:last-child) {
      mask-image: radial-gradient(circle at var(--_next-x) 50%, transparent var(--_cutout-radius), #000 calc(var(--_cutout-radius) + 1px));
    }
  }
}
```

マスクは、切り抜いた要素の `outline` と `box-shadow` も切り取ります（前の見出しで、スクロールコンテナのフォーカスリングが消えたのと同じです）。アバターをリンクにしてフォーカスリングを出すときは、リングを切り抜かない要素に出すか、`outline-offset` を負の値にして、リングを切り抜いていない範囲の内側に収めます。{/* 要検証: ブラウザ。負の outline-offset のリングがバッジの切り抜きに掛かったときの見え方 */}
