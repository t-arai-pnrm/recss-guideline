画像の縦横比は `aspect-ratio` で決め、中身は `object-fit` の `cover` か `contain` で収めます。初期値の `fill` のまま、画像を引き伸ばさないようにします。`<img>` には `width` と `height` の属性を書き、画像を読み込む前から表示する場所を確保します。

入稿される画像を受ける箱には、面の背景色と内側の線を付け、読み込む前や読み込みに失敗したときにも範囲が見えるようにします。写真を背景に敷くときも、`background-image` ではなく、`object-fit` を指定した `<img>` を本文と同じグリッドのエリアに置きます。同じ構図の2枚の画像を比べるUIは、2枚を同じエリアに重ね、上の画像を `clip-path` で切り抜いて作ります。

画像の形式、`srcset` と `sizes` による出し分け、遅延読み込みと読み込みの優先度は、「[16-2 画像の形式と読み込み](/decoration/image-loading/)」で説明しています。アイコンの描き方は「[16-3 アイコンとSVG](/decoration/icons-and-masks/)」で、`clip-path` で描く図形は「[16-4 clip-pathとマスクで見せる範囲を決める](/decoration/clipping-and-masks/)」で、影や角丸、すりガラスの背景は「[16-5 面・影・角丸](/decoration/surfaces/)」で扱います。

## 古い書き方で比率を保つと起きること

`aspect-ratio` が使えなかった頃は、`padding-top` に割合を指定して、縦横比を保っていました。`padding` の割合は親要素の幅を基準に計算されるので、`9 / 16 * 100%` を指定すれば、幅に対して16:9の高さを作れます。

```css title="🙅‍♂ Not Recommended: padding-top の割合で比率を作る" issue="convention"
/* 🙅‍♂ Not Recommended */
.frame {
  position: relative;

  &::after {
    content: "";
    display: block;
    padding-top: calc(9 / 16 * 100%);
  }
}

.frame img {
  position: absolute;
  inset: 0;
  width: 100%;
  height: 100%;
  object-fit: cover;
}
```

この書き方では、比率を作るための擬似要素と、中身を重ねるための絶対配置が必要です。中身は枠から外れた状態になるので、テキストが増えても枠は伸びません。コードを読んでも、`padding-top` が比率のための指定だとすぐには分かりません。

画像の側にも、よくある問題があります。枠の大きさに合わせようとして、画像へ `width: 100%` と `height: 100%` だけを指定すると、比率の違う画像が縦や横に引き伸ばされます。CMSで編集者が画像を差し替えるサイトでは、どのような比率の画像が入るかを事前に決められません。

## aspect-ratio で比率を決める

縦横比は `aspect-ratio` で指定します。幅が決まれば、高さは比率から計算されます。擬似要素と絶対配置は要りません。

```css title="🙆‍♂ Recommended: aspect-ratio で比率を決め、object-fit で収める" from="decoration/aspect-ratio"
._thumbnail {
  inline-size: -webkit-fill-available;
  inline-size: stretch;
  aspect-ratio: 16 / 9;
  object-fit: cover;
}

._avatar {
  inline-size: 32px;
  aspect-ratio: 1;
  border-radius: var(--rounded--full);
  object-fit: cover;
}
```

<Demo title="元の画像の比率が違っても、サムネイルは16:9に、アバターは正円にそろう" html={aspectRatioHtml} css={aspectRatioCss} />

デモには、元の比率が16:9、3:4、3:1の3枚の画像を並べています。どの画像も、サムネイルは16:9の枠に、キャプションの横のアバターは正円に収まり、枠からはみ出した部分は切り取られます。

サムネイルの幅は、`100%` ではなく、`-webkit-fill-available` と `stretch` をこの順に書いて親の幅いっぱいに広げます（「[7-4 大きさの決まり方](/layout/sizing/#rule-stretch-over-width-100)」）。正方形や正円にしたいときは、`aspect-ratio: 1` と書きます。`aspect-ratio` は `<img>` だけでなく、動画や `<iframe>`、背景を持つ `<div>` のような、縦横比が決まっている要素なら何にでも使えます。高さを固定したくなったら、まず `aspect-ratio` で表せないかを考えます。高さの決め方は「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/#rule-min-block-size-over-fixed-height)」でも取り上げています。

`<img>` には、画像の実際の大きさを `width` と `height` の属性で書きます。ブラウザは、この2つの属性から縦横比を計算し、画像を読み込む前から表示する場所を確保します。属性がないと、画像が読み込まれた瞬間に高さが決まり、下にある文章がずれて、読んでいた位置を見失います。

```html
<img src="thumbnail.avif" width="800" height="450" alt="" />
```

属性に書いた値が、そのまま表示の大きさになるわけではありません。kiso.cssは、画像に `max-inline-size: 100%` と `block-size: auto` を指定しています。枠より大きな画像は枠の幅まで縮み、高さは属性の比率を保ったまま決まります。

## object-fit は cover か contain にする

大きさを決めた画像には、`object-fit` を指定します。初期値の `fill` は、画像を枠いっぱいに引き伸ばすので、比率の違う画像が歪みます。`fill` が望ましい場面は、ほとんどありません。

<Demo title="16:9の画像を正方形の枠に入れたときの、object-fit の違い" html={objectFitHtml} css={objectFitCss} variant="neutral" />

デモでは、円を描いた16:9の画像を、`fill`、`cover`、`contain` の順に正方形の枠に入れています。`fill` では円が縦長の楕円に歪み、`cover` では画像の左右が切り取られ、`contain` では画像の上下に枠の灰色の背景が残ります。

`cover` は、比率を保ったまま枠を覆うように拡大し、はみ出した部分を切り取ります。写真のサムネイルやメインビジュアルのように、枠を埋めることを優先する画像に向いています。`contain` は、画像全体が枠に収まるように縮めます。ロゴや図版のように、切り取られると困る画像に使います。

私のテンプレートでは、ベーススタイルで `<img>` と `<video>` を `cover` にしています。`contain` が必要な画像だけ、コンポーネントで上書きします。切り取る位置は `object-position` で調整できます。人物の顔が写真の上のほうにあるなら、`object-position: 50% 20%` のように上寄りにすれば、顔が切れにくくなります。

```css title="🙆‍♂ Recommended: 画像と動画は cover を既定にする" from="decoration/object-fit"
@layer base {
  img,
  video {
    object-fit: cover;
  }
}
```

### 隣の要素の高さに合わせる

グリッドの中で、画像の高さを隣の本文の高さに合わせたい場合があります。画像に `block-size: 100%` を指定すると、画像の元の高さで行が押し広げられ、本文の下に余白ができて間延びします。この場合は、`block-size: 0` と `min-block-size: 100%` を組み合わせます。

<Demo title="block-size: 100% では、画像の元の高さで行が伸び、本文の下が空く" html={fitHeightHtml} css={fitHeightBadCss} variant="not-recommended" />

```css title="🙆‍♂ Recommended: 画像の高さを、同じ行の本文の高さに合わせる" from="decoration/fit-height"
img {
  inline-size: -webkit-fill-available;
  inline-size: stretch;
  block-size: 0;
  min-block-size: 100%;
  object-fit: cover;
}
```

<Demo title="画像の高さが本文の高さに合い、はみ出した部分は切り取られる" html={fitHeightHtml} css={fitHeightCss} />

`block-size: 0` で画像が行の高さを押し広げないようにし、`min-block-size: 100%` でセルの高さまで広げています。行の高さは本文だけで決まり、画像はその高さに合わせて `cover` で切り取られます。

### 画像の上の文字には背景色を用意する

画像や動画の上に文字を載せるときは、画像が表示されなかった場合に備えて、文字と対になる背景色を指定しておきます。通信の状態によって画像を読み込めないと、白い背景の上に白い文字だけが残り、読めなくなるからです。

```css title="🙆‍♂ Recommended: 画像がなくても白い文字が読める背景色を敷く" from="decoration/hero-header"
@scope (.scoped.hero-header) to (.scoped) {
  :scope {
    display: block grid;
    grid-template-areas: "--pile";
    background-color: oklch(from currentColor sign(0.7 - l) 0 h);
    background-color: contrast-color(currentColor);
    color: oklch(100% 0 0deg);

    & > img,
    & > ._body {
      grid-area: --pile;
    }
  }

  img {
    inline-size: -webkit-fill-available;
    inline-size: stretch;
    block-size: 0;
    min-block-size: 100%;
    object-fit: cover;
  }
}
```

<Demo title="画像を表示できなくても、背景色の上で白い文字が読める" html={heroHeaderHtml} css={heroHeaderCss} />

デモの1つ目は画像を表示できたとき、2つ目は画像を表示できなかったときのヒーローです。2つ目では、画像の代わりに黒の背景色が見え、白い文字が読めます。

背景色は、画像の平均的な色ではなく、文字色とのコントラストが取れる色にします。このコード例では、白い文字に対して黒を敷いています。文字色を変えても背景色を書き直さずに済みます。`contrast-color(currentColor)` だけでは、対応していない環境（Safari 18系）で背景色が付かず、画像が表示されないときに白い文字が読めなくなります。そこで、`sign()` で書いた同じ意味の宣言を先に置いています（「[15-3 背景から文字色を決める](/color-media/contrast-text/)」）。画像と本文は同じグリッドのエリアに重ね、画像の高さは前の項目と同じ方法で本文に合わせています。

## 白い背景の画像に縁を付ける

商品の写真やスクリーンショットのように、背景が白い画像を白いページに置くと、画像の縁が背景と見分けられず、どこまでが画像なのかが分からなくなります。CMSで画像を差し替えられる場所では、どの画像が入るかを前もって決められないので、画像の内側に細い線を引いておきます。線は、負の `outline-offset` を付けた `outline` で描きます。

```css title="🙆‍♂ Recommended: 画像の内側に outline で線を引き、白い背景の画像の縁を示す"
._thumbnail {
  outline: 1px solid var(--border--base);
  outline-offset: -1px;
}
```

`box-shadow: inset` では、この線を描けません。内側の影は要素の背景の上、中身の下に描かれるので、`<img>` の画像に覆われて見えなくなります。`outline` は中身より手前に描かれ、`outline-offset` を負の値にすれば、画像の大きさを変えずに内側へ引けます。Chromeで、不透明な画像に指定した `box-shadow: inset` は見えず、`outline` の線は画像の上に表示されることを確かめました。FirefoxとSafariでも、負の `outline-offset` の `outline` は画像の上に表示されました。`border` で描くと、`box-sizing: border-box` の画像では線の分だけ画像が小さくなるので、使いません。

線の色は、枠線のトークンから選びます。濃い色にすると、白くない画像では枠が目立ちすぎます。強制カラーモードでは、`outline` の色はシステムカラーに置き換わります（「[15-5 強制カラーモードとコントラスト](/color-media/forced-colors/)」）。

### 読み込む前と読み込めなかったときの箱

入稿される画像を受ける箱には、線に加えて、`<img>` に面の背景色を付けておきます。比率と切り取り方を `aspect-ratio` と `object-fit: cover` で決めても、画像が描かれていない間は、箱の中に何も見えないからです。背景色があれば、読み込む前も読み込みに失敗したときも、箱の範囲が面として見え、読み込んだ後と同じ形のまま並びます。

```css title="🙆‍♂ Recommended: 画像の箱に面の背景色と内側の線を付け、画像がなくても範囲を示す" from="decoration/image-placeholder"
._thumbnail {
  inline-size: -webkit-fill-available;
  inline-size: stretch;
  aspect-ratio: 4 / 3;
  object-fit: cover;
  background-color: var(--background--surface);
  outline: 1px solid var(--border--base);
  outline-offset: -1px;
}
```

<Demo title="背景色と線がないと、読み込めなかった画像の場所が穴に見える" html={imagePlaceholderHtml} css={imagePlaceholderCss} />

デモの上段は背景色と線を付けない画像、下段は付けた画像で、左から、読み込んだ画像、代替テキストのある画像の読み込みに失敗したとき、`alt=""` の画像の読み込みに失敗したときです。上段では、ライトのテーマで白い背景の写真の縁がページの背景と見分けられず、読み込めなかった画像は代替テキストだけが空いた場所に浮かびます。下段では、3つとも同じ大きさの面と線に収まり、読み込めたかどうかにかかわらず箱の並びがそろって見えます。

背景色は、画像の後ろに描かれます。不透明な写真を読み込めば隠れ、表示されるのは読み込む前と失敗したときだけです。透過のあるPNGやSVGでは背景色が透けるので、ロゴのような画像を受ける箱では、背景色を周りの面と同じ色にするか、付けずにおきます。遅延読み込みの画像は、スクロールで近づくまで読み込まれないので、この面だけを表示する時間が長くなります（遅延読み込みの判断は「[16-2 画像の形式と読み込み](/decoration/image-loading/)」）。

読み込みに失敗した `<img>` の中には、ブラウザが壊れた画像のアイコンと代替テキストを描きます。Chromeでは、`aspect-ratio` で決めた大きさのまま、箱の左上にアイコンと `alt` の文字が表示され、`alt=""` の画像には文字が表示されませんでした。背景色と `outline` はどちらにも描かれ、代替テキストは `<img>` の文字色で描かれました。代替テキストが面の上で読めるように、背景色は文字色と対になる面のトークンから選びます。{/* 要検証: ブラウザ。読み込み中の箱の表示と、Firefox と Safari での読み込みに失敗した画像の表示（aspect-ratio の大きさ、背景色、outline、代替テキスト） */}

## 背景の写真も `<img>` で置く

前の項目のヒーローのように写真を背景に敷くときは、`background-image` ではなく、`object-fit` を指定した `<img>` を背景に置きます。`background-image` を使うのは、小さな画像を繰り返して敷き詰めるパターン画像や、内容と関係のない細かな装飾に限ります。

```css title="🙅‍♂ Not Recommended: 背景の写真を background-image で敷く" issue="behavior"
/* 🙅‍♂ Not Recommended */
._hero {
  background-image: url("hero.avif");
  background-position: center;
  background-size: cover;
}
```

`<img>` にする理由は4つあります。1つ目は、`<picture>` や `srcset` と `sizes` で、画面の幅や解像度に合った画像を読み込めることです。`background-image` でも `image-set()` で解像度ごとの候補は書けますが、画像がレイアウトの中で表示される幅をブラウザに伝える手段はありません。`srcset` と `sizes` の決め方は「[16-2 画像の形式と読み込み](/decoration/image-loading/)」で説明しています。2つ目は、画像だけを加工しやすいことです。背景画像の要素に指定した `opacity` や `filter` は中の文字にも及ぶので、画像だけを薄くするには擬似要素を足すことになります。`<img>` なら、画像に直接指定できます。

3つ目は、`alt` 属性で画像の意味を伝えられることです。内容を伝える写真には代替テキストを書き、装飾なら `alt=""` にして読み上げから外します。カードのサムネイルのように、隣の見出しのリンクと同じ内容を繰り返すだけの画像も `alt=""` にします。背景画像には代替テキストを付ける手段がありません。4つ目は、読み込みの早さです。ブラウザのプリロードスキャナーは、HTMLを解析する段階で `<img>` を見つけて先に要求しますが、CSSの中の `background-image` は対象外で、スタイルシートを読み込んで適用するまで見つかりません。その画像がLCPの候補なら、見つかるまでの分だけ表示が遅れます。

```html title="🙆‍♂ Recommended: 背景の写真を、本文と同じエリアに重ねる img で置く"
<div class="scoped hero-header">
  <img
    src="hero-800.avif"
    srcset="hero-800.avif 800w, hero-1600.avif 1600w"
    sizes="100vw"
    width="1600"
    height="900"
    alt=""
    fetchpriority="high"
  />
  <div class="_body">
    <!-- ... -->
  </div>
</div>
```

背景の `<img>` は絶対配置にせず、前の項目のコード例のように、本文と同じグリッドのエリアに置きます。重ねるだけの入れ物なら、コンポジションの「[12-10 pile](/compositions/pile/)」（すべての子を同じセルに重ねる）を使えます。どちらも、本文が増えれば枠が伸び、画像はその高さに合わせて `cover` で切り取られます。画像をHTMLで先に書けば、`z-index` を使わなくても本文が手前に描かれます。このヒーローの写真はLCPの候補になるので、`fetchpriority="high"` を指定しています（「[16-2 画像の形式と読み込み](/decoration/image-loading/#rule-no-lazy-loading-first-view)」）。テキストの下に敷くLCPの候補の写真は、JPEG XLを優先する画像でもあります。`<picture>` でAVIFを代わりに添える書き方は、同じ16-2の「[画像の形式](/decoration/image-loading/#画像の形式)」で説明しています。

`<img>` を `<picture>` で包むときは、属性を変えるだけでは済まず、CSSも直します。グリッドのアイテムになるのは `<picture>` になり、`& > img` のセレクタは `<img>` に一致しなくなるからです。`<img>` は本文と別の行に置かれ、`block-size: 0` のまま高さが0になって、写真が消えます。`<picture>` を本文と同じエリアに置いてエリアの高さに合わせ、`<img>` はその `<picture>` の高さいっぱいに広げます。

```css title="🙆‍♂ Recommended: picture で包んだ写真を、本文と同じエリアに重ねる"
@scope (.scoped.hero-header) to (.scoped) {
  :scope {
    & > picture,
    & > ._body {
      grid-area: --pile;
    }
  }

  picture {
    block-size: 0;
    min-block-size: 100%;
  }

  img {
    inline-size: -webkit-fill-available;
    inline-size: stretch;
    block-size: 100%;
    object-fit: cover;
  }
}
```

Chromeで、前のデモの `<img>` を `<picture>` で包み、このCSSに変えたところ、写真はヒーローと同じ大きさで表示され、本文を増やしてヒーローが高くなると、写真も同じ高さに伸びました。

```css title="🙆‍♂ Recommended: 敷き詰めるパターンは background-image で描く"
._section {
  background-image: url("dots.svg");
  background-size: 24px;
}
```

1枚だけ置く装飾の画像には、`background-repeat: no-repeat` を明示します。初期値の `repeat` のままだと、要素が画像より大きくなったとき、画像が繰り返して並びます。カンプの大きさでは繰り返しが見えなくても、文字が増えて要素が伸びると現れます。

```css title="🙆‍♂ Recommended: 1枚だけ置く装飾は、繰り返しを止める"
._notice {
  background-image: url("corner-ornament.svg");
  background-size: 48px;
  background-repeat: no-repeat;
}
```

装飾の画像とパターンを1つの要素に重ねるときは、`background-image` に画像をカンマで区切って並べます。先に書いた画像ほど手前に描かれ、リストの先頭が最前面になります。`background-color` は、すべての画像の後ろに1色だけ敷かれます。`background-position` や `background-size` にも同じ順で値をカンマで並べ、何番目の値が何番目の画像に当たるかを、画像のリストとそろえます。

```css title="🙆‍♂ Recommended: 手前に置く飾りを先に書き、各プロパティの値を画像の順に並べる"
._notice {
  background-image: url("corner-ornament.svg"), url("dots.svg");
  background-position: right top, left top;
  background-size: 48px, 24px;
  background-repeat: no-repeat, repeat;
}
```

一括指定の `background` では、層ごとに `url("corner-ornament.svg") right top / 48px no-repeat` のように、位置の後ろにスラッシュで区切って大きさを書きます。大きさは位置の直後にしか書けず、位置を省いて大きさだけを書くことはできません。本書では、背景の画像を指定するときは一括指定を使わず、個別のプロパティで書きます。一括指定は、書かなかったサブプロパティと `background-color` を初期値に戻すので、ほかの場所で指定した背景色を消すことがあるからです（[`longhand-for-partial-change`](/design-mindset/maintainability/#rule-longhand-for-partial-change)）。方眼のように多くの層を重ねる例は「[16-6 グラデーションを描く](/decoration/gradients/)」にあります。{/* 要確認: 出典なし。背景の画像を重ねる順序と、一括指定を使わない書き方 */}

単色やグラデーションだけの背景は、画像のファイルを読み込まず、意味も持たないので、`background-image` で足ります。パターン画像も、内容を伝えず、表示される幅に合わせて出し分ける必要がないので、`<img>` にする利点がありません。やむを得ずLCPの候補の写真を `background-image` で敷く場合は、`<link rel="preload">` でその画像を先に読み込ませます。

## 2枚の画像を重ねて比べる

加工前と加工後のように、同じ構図の2枚の画像を比べるUIは、2枚の `<img>` を同じグリッドのエリアに重ね、上の画像を `clip-path` で切り抜いて作ります。境界の位置は `<input type="range">` で操作し、入力の値はスクリプトでカスタムプロパティに書き込みます。範囲の入力は画像の下に置き、ブラウザの標準の見た目のまま使います。{/* 要確認: 出典なし */}

```css title="🙆‍♂ Recommended: 重ねた上の画像を、境界の位置から右だけ切り抜く" from="decoration/comparison-slider"
@scope (.scoped.comparison-slider) to (.scoped) {
  :scope {
    --_position: var(--comparison-slider--position, 50%);
  }

  ._images {
    display: block grid;

    & > ._after,
    & > ._before {
      grid-area: 1 / 1;
    }
  }

  ._before {
    clip-path: inset(0 calc(100% - var(--_position)) 0 0);
  }
}
```

`inset()` の4つの値は、上、右、下、左から切り取る量です。右から `100% - 境界の位置` を切り取るので、上に重ねた加工前の画像は、左端から境界の位置までだけが見え、その右には下の加工後の画像が見えます。HTMLでは加工後の画像を先に、加工前の画像を後に書くので、加工前の画像が上に描かれます。

境界を動かすのに、上の画像の幅を変えないのは、レイアウトと画像の切り取り方を変えないためです。幅を変えると、`object-fit: cover` で収めた画像は幅に合わせて拡大率と切り取る位置が変わり、2枚の構図がずれます。`clip-path` は見える範囲を決めるだけで、要素の大きさと位置は変わらないので、値が変わってもレイアウトは起こらず、2枚はいつも同じ位置に重なったままです。デモでは、境界の線も `::after` を `clip-path` で細く切り抜いて描いています。同じ大きさの層を重ねて上の層の一部だけを見せる方法は、選んだタブの色を描く例として「[16-4 clip-pathとマスクで見せる範囲を決める](/decoration/clipping-and-masks/)」でも説明しています。

範囲の入力の値は、CSSから読めません。`attr()` で読める `value` は、HTMLに書いた属性の値で、ユーザーがつまみを動かしても変わりません。Chromeで、キーボードで値を65に変えたあとも、`value` 属性と `attr(value type(<number>))` の値は50のままでした。入力の現在の値を表す擬似クラスやプロパティもないので、値を `clip-path` に渡すにはスクリプトが要ります。

```js title="範囲の入力の値を、カスタムプロパティに書き込む"
const root = document.querySelector('.scoped.comparison-slider');
const range = root.querySelector('._range');

const update = () => {
  root.style.setProperty('--comparison-slider--position', `${range.value}%`);
};

range.addEventListener('input', update);
update();
```

`input` イベントは、つまみを動かしている間も値が変わるたびに発生するので、境界はつまみに合わせて動きます。最後に一度 `update()` を呼ぶのは、再読み込みのときにブラウザが入力の値を復元し、HTMLの `value` と現在の値の食い違う場合に備えるためです。書き込むカスタムプロパティは、外から値を受け取る入り口なので、公開用の名前（`--comparison-slider--position`）にし、CSSの中では内部用の `--_position` に受けて使います。

範囲の入力は、透明にして画像全体に重ねる作り方もありますが、本書では画像の下に置きます。重ねると画像のどこを押しても境界が動きますが、透明にしたつまみとフォーカスリングは見えなくなるので、境界の線やフォーカスの表示を `:has(._range:focus-visible)` などで描き直すことになります。強制カラーモードでの見え方も自分で確かめる必要があります。下に置けば、見えるラベル、左右の矢印キーでの操作、ブラウザのフォーカスリングが、標準の範囲の入力のまま手に入ります。

<Demo title="範囲の入力で、重ねた2枚の画像の境界を動かす" html={comparisonSliderHtml} css={comparisonSliderCss} js={comparisonSliderJs} />

デモでは、灰色の補正前の画像を、色を補正した後の画像に重ねています。スライダーを右へ動かすと、境界の線が右へ移り、補正前の画像の見える範囲が広がります。スライダーにフォーカスして左右の矢印キーを押すと、境界が1%ずつ動きます。Chromeでは、Page Upを押すと10%動きました。{/* 要検証: ブラウザ。Firefox と Safari での範囲の入力のキーボード操作と、強制カラーモードでの表示 */}
