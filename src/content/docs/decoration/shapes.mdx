角の形は、`border-radius` で角丸の大きさを決め、`corner-shape` でその角をどんな曲線で結ぶかを決めます。Appleの画面にあるようななめらかな角や、タブの下の端が外側へ反り返る形は、以前は画像や複数の擬似要素、マスクの重ね合わせで作っていました。`corner-shape` なら、1つの宣言で書けます。

ただし、`corner-shape` に対応しているブラウザは、まだ限られています。未対応の環境で「形が少し素朴になるだけ」で済むなら、そのまま書きます。「部品が崩れて見える」なら、`@supports` で従来の書き方に切り替えます。この節では、そのうえで、要素が画面いっぱいに広がったときだけ角丸を消す `sign()` の書き方も説明します。輪郭そのものを描く `shape()` と、枠線を塗る `border-area` は「[16-9 輪郭と枠線を描く](/decoration/outlines/)」で扱います。

## 角丸だけでは作れない形

`border-radius` で作れるのは、四分円か四分楕円の角だけです。実際のデザインには、ここから外れる形がよく出てきます。直線から曲線へなめらかにつながる角（スクワークル）、角を斜めに切り落とした形、下の端が外側へ反り返るように広がるタブなどです。

これらは、これまで別の手段で作ってきました。反り返るタブなら、左右に擬似要素を1つずつ置き、`radial-gradient()` のマスクで角を削ります。動きはしますが、形を作るための要素と、半径から逆算した位置の値が増え、コードから形を読み取れなくなります。

新しい仕様では、こうした角をプロパティで直接書けるようになりました。一方で、新しい書き方を選ぶときは、未対応の環境での見え方を見分ける必要があります。この考え方は「[1-2 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」で説明しています。

## corner-shape で角の形を変える

`corner-shape` は、`border-radius` で決めた角の領域を、どんな曲線で結ぶかを指定するプロパティです。初期値の `round` が従来の角丸で、`squircle` にするとスクワークルになります。ほかに、外側から内側へえぐる `scoop`、角を直線で切り落とす `bevel`、角を四角く切り欠く `notch` があります。キーワードは `superellipse()` の値の別名です。計算された値は、`squircle` が `superellipse(2)`、`round` が `superellipse(1)` です。`bevel` は `superellipse(0)`、`scoop` は `superellipse(-1)` になります。

<Demo title="border-radius: 24px の正方形に、corner-shape のキーワードを指定したとき" html={keywordsHtml} css={keywordsCss} variant="neutral" />

このデモでは、同じ角丸の正方形を5つ並べ、それぞれに `round`、`squircle`、`bevel`、`scoop`、`notch` を指定しています。対応している環境（Chrome）では、四隅が順に、円弧の角丸、スクワークル、斜めの切り落とし、内側へのえぐれ、四角い切り欠きになります。このデモは、`corner-shape` に対応していない環境では、5つとも同じ角丸で表示されます。`notch` のように角丸から最も離れた形でも、未対応の環境では角丸に戻るだけです。

```css title="🙆‍♂ Recommended: 錠剤型のボタンに corner-shape を1行足す" from="decoration/squircle-button"
@scope (.scoped.button) to (.scoped) {
  :scope {
    border-radius: var(--rounded--full);
    corner-shape: squircle;
  }
}
```

<Demo title="錠剤型のボタンと、corner-shape: squircle を足したボタン" html={squircleHtml} css={squircleCss} frame={squircleFrame} variant="neutral" />

デモの1つ目は `corner-shape` を初期値に戻した錠剤型のボタン、2つ目は `corner-shape: squircle` を足したボタンです。対応している環境（Chrome）では、2つ目のボタンの左右の端が、半円より角張った曲線になります。

私は、スクワークルのボタンを作るときに、錠剤型のボタンへ `corner-shape: squircle` を1行足すだけにしています。対応していない環境では、この宣言が無視され、錠剤型のボタンとして表示されます。形は少し変わりますが、ボタンとしての見え方は崩れないので、`@supports` で囲む必要はありません。`border-radius` の値に `calc(infinity * 1px)` を使う理由は、「[16-5 面・影・角丸](/decoration/surfaces/)」で説明しています。

`corner-shape` は、`border-radius` が0の角の形を変えません。描くのは `border-radius` で決めた領域の中の曲線だけなので、角丸の大きさは必ず `border-radius` で指定します。枠線、影、`outline` も、`corner-shape` で変えた輪郭に沿って描かれます。

未対応の環境で別の角丸にしたい場合は、`@supports` で分岐します。たとえば、対応している環境ではスクワークルに、対応していない環境では小さめの角丸にするとします。この場合は `border-radius: var(--rounded--md)` を基本に書きます。そして、`@supports (corner-shape: squircle)` の中で `border-radius` と `corner-shape` を一緒に指定します。新しい機能に合わせて既存の宣言まで変える場合に、その宣言を `@supports` の中に入れる書き方です。

### スクワークルの角丸の大きさを合わせる

スクワークルは、同じ `border-radius` でも、円弧の角丸より角が小さく見えます。直線から曲線へ移る位置は同じでも、曲線が角の近くまで直線に寄ってから曲がるからです。角丸のデザインをスクワークルへ置き換えるとき、半径をそのままにすると、角が締まって見えます。見た目の大きさを合わせるには、`border-radius` を大きくします。

どれだけ大きくするかは、半径によって変わります。私は、半径から倍率と角の形を決めるユーティリティを使っています。倍率と、大きい半径で `superellipse()` の値を変える境目は、CodePenを作るうえで参考にした記事の値です。記事では、ふつうの角丸とスクワークルを並べて、見た目が合う値を半径ごとに決めています（参考リンクを参照）。

```css title="🙆‍♂ Recommended: 対応した環境だけ、半径に応じて border-radius を大きくする" from="decoration/squircle-radius"
.-corner-squircle {
  --_u--radius: var(--corner-squircle--radius, 24px);
  --_u--radius-ratio: 1;

  border-radius: calc(var(--_u--radius) * var(--_u--radius-ratio));

  /* corner-shape と if() に対応した環境だけ */
  @supports (corner-shape: if(style(--test: 1): squircle)) {
    --_u--radius-ratio: if(
      style(--_u--radius >= 32px): 1.5;
      style(--_u--radius >= 24px): 1.67;
      style(--_u--radius >= 8px): 2;
      style(--_u--radius >= 6px): 1.6;
      style(--_u--radius >= 4px): 1.2;
      style(--_u--radius >= 2px): 1.25;
      else: 1
    );

    corner-shape: if(
      style(--_u--radius >= 32px): superellipse(1.5);
      style(--_u--radius >= 24px): superellipse(1.75);
      style(--_u--radius >= 0): squircle;
      else: round
    );
  }
}
```

<Demo title="左は border-radius の角丸、右は同じ半径を .-corner-squircle に渡したもの" html={squircleRadiusHtml} css={squircleRadiusCss} frame={squircleRadiusFrame} variant="neutral" />

デモでは、半径8px、24px、32pxのそれぞれで、左に `border-radius` の角丸、右に `.-corner-squircle` の正方形を並べています。`corner-shape`、`if()`、スタイルクエリの範囲の比較に対応している環境（Chrome）では、右の角は大きい半径のスクワークルで描かれ、角の見た目の大きさが左に近くなります。未対応の環境では、右も左と同じ角丸になります。

使う側は、角丸の半径を `--corner-squircle--radius` に渡します。半径が8px以上24px未満のときは2倍の `squircle`、24px以上32px未満のときは1.67倍の `superellipse(1.75)`、32px以上のときは1.5倍の `superellipse(1.5)` になります。大きい半径では、倍率を下げるのと合わせて、`squircle`（`superellipse(2)`）より円弧に近い値へ切り替えています。`if()` は条件を上から順に調べるので、大きい半径の条件から書きます。

`@supports` の条件には、`corner-shape` と `if()` を使った値を書きます。カスタムプロパティは、どんな値でも構文の誤りにならないので、`if()` に未対応の環境でも `--_u--radius-ratio` に `if(…)` の文字列がそのまま入ります。それを `calc()` で使うと `border-radius` の宣言が無効になり、角丸が消えます。`@supports` で囲めば、未対応の環境では倍率が1のままになり、ふつうの角丸で表示されます。

スタイルクエリの範囲の比較に対応しているかは、`@supports` では判定できません。`if()` の条件は、解釈できない中身も未知の条件として受け付け、偽として評価するからです（CSS Values and Units Module Level 5）。Chromeで確かめたところ、`style()` の中に解釈できない式を書いても、`@supports` の条件は真になりました。そこで、範囲の比較に未対応の環境では、`if()` の中で `else` の値が選ばれることを使います。倍率の `else` は1です。角の形は、どの半径でも真になる `style(--_u--radius >= 0)` で `squircle` を選び、`else` には通常の角丸の `round` を書きます。範囲の比較を解釈できない環境では、すべての条件が偽になるので、倍率が1の通常の角丸で表示されます（Chromeで、`style()` の中を解釈できない式にして確認）。{/* 要検証: ブラウザ。if() と corner-shape に対応し、範囲の比較に未対応の Chrome 139〜141 で、通常の角丸になること */}

「[6-5 if()とattr()で条件と属性を値にする](/values/if-and-attr/)」では、`if()` を、要素自身のカスタムプロパティを `style()` で調べる場面に限り、条件1つと `else` の形で使うとしています。このユーティリティは、要素自身の半径を調べる点では6-5の範囲に収まりますが、条件は複数です。1つの長さを倍率に置き換える対応表で、状態の分岐ではないので、例外として扱っています。

### 下の端が反り返るタブ

下の端が外側へ反り返るタブは、`corner-shape: scoop` で書けます。タブの背面に、左右へ角丸の半径だけはみ出した擬似要素を置き、上の2つの角をえぐります。擬似要素の上の角がえぐれることで、タブの両脇の外側に、内側へ反った曲線が残ります。

```css title="🙆‍♂ Recommended: 対応している環境だけ、scoop で反り返りを付ける" from="decoration/scoop-tab"
@scope (.scoped.category-navigation) to (.scoped) {
  ._tab {
    --_radius: var(--category-navigation--radius, 12px);

    position: relative;
    border-start-start-radius: var(--_radius);
    border-start-end-radius: var(--_radius);
    isolation: isolate;

    @supports (corner-shape: scoop) {
      &::before {
        content: "";
        position: absolute;
        inset-inline: calc(var(--_radius) * -1);
        inset-block-end: 0;
        z-index: var(--z--backwards);
        block-size: var(--_radius);
        border-start-start-radius: var(--_radius);
        border-start-end-radius: var(--_radius);
        corner-shape: scoop;
        background-color: inherit;
      }
    }

    &[aria-current="page"] {
      background-color: var(--background--base);
    }
  }
}
```

<Demo title="選んでいるタブの下の端が、scoop で外側へ反り返る" html={scoopTabHtml} css={scoopTabCss} frame={scoopTabFrame} />

このデモでは、選んでいるタブにだけ背景色を付けています。擬似要素は `background-color: inherit` でタブの背景色を受け取るので、選んでいないタブには反り返りも描かれません。選んでいるかどうかは、背景色に加えて文字の太さでも示します。タブの文字色はどれも本文と同じ色にし、色の付いた面の上でもコントラスト比を保ちます。

幅が足りないときは、タブの列を横にスクロールさせます。デモのCSSでは、`ul` に `overflow-x: auto` を指定し、`li` を `flex: none` で縮まないようにしています。タブが縮むと、文字が1文字ずつ折り返した縦長のタブになるからです。スクロールコンテナは中身をパディングボックスの端で切り取るので、上に6pxの余白を取り、タブのフォーカスリングを残します。

この擬似要素は、`@supports` で囲みます。`corner-shape` に対応していない環境では、擬似要素の上の角が外側へふくらむ通常の角丸になり、タブの両脇にこぶのような出っ張りが出てしまうからです。`@supports` で囲めば、未対応の環境では、上だけが角丸のタブとして表示されます。タブには `isolation: isolate` を指定し、`z-index` を負にした擬似要素が、タブの外の背景より後ろへ回らないようにしておきます。

すべての環境で反り返りを付けたい場合は、従来どおり、左右に1つずつ擬似要素を置き、`radial-gradient()` のマスクで角を削ります。マスクの値は `radial-gradient(circle farthest-side at 0 0, transparent 100%, #000 calc(100% + 1px))` のように書きます。透明から黒への境目を `calc(100% + 1px)` にして1px分ずらすのは、境目を一点で切り替えると、曲線の縁がギザギザに見えるためです。

## 画面いっぱいのときだけ角丸を消す

カードや画像を、広い画面では角丸で余白の中に置き、狭い画面では画面の端まで広げるデザインはよくあります。画面の端まで広がったときに角丸が残ると、画面の角だけが欠けて見えます。この切り替えをメディアクエリで書くと、角丸を消す幅を、要素の幅ではなくビューポートの幅で決めることになります。

```css title="🙅‍♂ Not Recommended: ビューポートの幅で角丸を付け外しする" issue="behavior"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.hero-card) to (.scoped) {
  :scope {
    @media (width >= calc(640 / 16 * 1rem)) {
      border-radius: 40px;
    }
  }
}
```

この書き方では、要素がいつ画面いっぱいになるかを、ブレイクポイントとして別に知っておく必要があります。余白や最大幅を変えると、画面いっぱいになる幅もずれ、角丸を消す幅と合わなくなります。

ここでは、横書きのページで、中央に配置したカードが狭い画面では画面の端まで広がる場面を考えます。次のコードは、カードの幅とビューポートの幅の差から、角丸を付けるかどうかを決めます。角丸の大きさを40px、差の許容幅を20pxとすると、画面幅とカード幅に応じて、角丸は次の表のようになります。

| 画面幅（`100lvi`） | カード幅（`100%`） | 差から20pxを引いた値 | 結果の角丸 |
| --- | --- | --- | --- |
| 1200px | 800px | 380px | 40px |
| 800px | 784px | -4px | 0 |
| 390px | 390px | -20px | 0 |
| 1280px（スクロールバーの15pxを含む） | 1265px | -5px | 0 |

2行目のように、左右の余白の合計が20px以下だと、画面いっぱいでなくても角丸は消えます。差がちょうど20pxのときも、`sign()` が0を返すので、角丸は0になります。

```css title="🙆‍♂ Recommended: 要素の幅がビューポートの幅とほぼ等しいときだけ、角丸を0にする" from="decoration/full-bleed-radius"
@scope (.scoped.hero-card) to (.scoped) {
  :scope {
    --_radius: var(--hero-card--radius, 40px);
    --_tolerance: 20px;

    border-radius: calc(sign(100lvi - 100% - var(--_tolerance)) * var(--_radius)) / var(--_radius);
  }
}
```

<Demo title="カードが画面いっぱいに広がったときだけ、角丸が消える" html={fullBleedHtml} css={fullBleedCss} bleed="inline" />

このデモでは、カードを置く側が最大幅を720pxにして中央に置いています。768pxのときは左右に余白ができて角丸が付き、320pxのときは、カードが画面の端まで広がって角丸が消えます。式では、画面の幅がカードの最大幅に許容幅を足した740pxを超えると角丸が付きます。

`border-radius` の水平方向の半径に書いた `%` は、要素の幅を基準にします。`100lvi - 100%` は、ビューポートの幅と要素の幅の差です。要素が画面いっぱいなら差は0になり、そこから `--_tolerance` を引いた値は負になるので、`sign()` は-1を返します。負の半径は0として扱われるので、角丸が消えます。差が `--_tolerance` より大きいときは1を返し、`--_radius` の角丸になります。

`/` のあとの垂直方向の半径を、別に書いているのには理由があります。値を1つだけ書くと、垂直方向の半径にも同じ式が使われ、その `%` は要素の高さを基準にします。すると、高さがビューポートの幅を超える要素（スマートフォンで縦に長いカードなど）では、垂直方向の半径が0になり、画面いっぱいでなくても角丸が消えます。角は、水平と垂直のどちらかの半径が0なら直角になるので、垂直方向は固定の半径にし、水平方向の式だけで角丸を切り替えます。

`--_tolerance` を引くのは、スクロールバーの幅の分です。スクロールバーが幅を取る環境（WindowsやmacOSの「スクロールバーを常に表示」）では、`100lvi` はスクロールバーを含み、`100%` は含まないので、画面いっぱいでもスクロールバーの幅だけ差が残ります。ルートに `scrollbar-gutter: stable` を指定した場合も、`100lvi` はスクロールバーの幅を含んだままでした（Chromeで、スクロールバーに幅を持たせて確認）。{/* 要検証: ブラウザ。実際のWindowsのスクロールバーと、Chrome以外のブラウザ */} `--_tolerance` には、スクロールバーの幅より少し大きい値を入れておきます。

元の書き方は `100vw` を使ったものですが、本書は `vw` を使わない方針なので、`100lvi` で書いています。`lvi` は、ブラウザのツールバーが縮んだときの、最も大きいビューポートのインライン方向の大きさです。

## 未対応の環境での見え方

`corner-shape` を使ったら、未対応の環境での見え方を、ブラウザを替えるか、開発者ツールで宣言を外して確かめます。錠剤型のボタンに足した `corner-shape: squircle` は、宣言が無視されても錠剤型のボタンのままなので、`@supports` は要りません。反り返るタブの擬似要素のように、未対応の環境で通常の角丸に戻ると形が崩れるものだけを、`@supports` で囲みます。

`@supports` の条件には、実際に使う値の形を書きます。`@supports (corner-shape: scoop)` のようにキーワードまで書くと、プロパティにだけ対応していて値に対応していない環境も、未対応として扱えます。
