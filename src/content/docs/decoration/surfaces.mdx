面の背景は、ページ、カード、ダイアログ、メニューの役割で決めた4段階のトークンから選びます。影は、光源の向きをそろえ、段階が上がるほどオフセットとぼかしを倍にした層を足して作ります。ライトモードでは面の高さを影だけで表し、影の見えにくいダークモードでは、高い面ほど背景を明るくします。影を動かすときは、`box-shadow` ではなく `filter: drop-shadow()` を動かします。角丸も、段階を決めたトークンから選び、入れ子にした内側の角丸は、外側の角丸から間の余白を引いた値にします。

すりガラスの背景は、半透明の背景に `backdrop-filter: blur()` を重ねて作ります。ぼかしに混ざるのは、要素の真後ろにある色だけです。

どれも要素の表面に付ける装飾なので、作るものに合わせて必要な見出しだけを読めば足ります。番号付きリストの番号、文字の縁取り、見出しの行ごとの背景のような文字の装飾は、「[16-7 文字とリストの装飾](/decoration/text-ornaments/)」で説明しています。画像は「[16-1 画像の配置と比率](/decoration/images/)」と「[16-2 画像の形式と読み込み](/decoration/image-loading/)」で扱います。アイコンは「[16-3 アイコンとSVG](/decoration/icons-and-masks/)」で、`clip-path` で描く図形は「[16-4 clip-pathとマスクで見せる範囲を決める](/decoration/clipping-and-masks/)」で扱います。背景に敷くグラデーションの描き方は、「[16-6 グラデーションを描く](/decoration/gradients/)」で説明しています。

## 面の背景は役割で4段階に分ける

画面には、高さの違う面が重なります。本書のデモでは、面の背景を4つの役割ごとのセマンティクスのトークンにしています。ページは `--background--base`、カードは `--background--surface` です。ダイアログは `--background--overlay`、メニューやポップオーバーは `--background--raised` です。コンポーネントは、自分の役割に合うトークンを1つ選んで背景に指定します。

ライトモードでは、`--background--base` 以外をすべて白にし、面の高さは影だけで表します。ダークモードでは、暗い背景の上で影がほとんど見えないので、高い面ほど背景を明るくします。明るい背景は、ページの背景のプリミティブ（`--color--neutral--900`）から、相対カラー構文で明度を足して作ります。

```css title="🙆‍♂ Recommended: 面の背景を役割で決め、ダークモードでは高い面ほど明るくする"
:root {
  --color--neutral--50: oklch(98.5% 0 0deg);
  --color--neutral--900: oklch(20.5% 0 0deg);
  --background--base: light-dark(var(--color--neutral--50), var(--color--neutral--900));
  --background--surface: light-dark(oklch(100% 0 0deg), oklch(from var(--color--neutral--900) calc(l + 0.05) c h));
  --background--overlay: light-dark(oklch(100% 0 0deg), oklch(from var(--color--neutral--900) calc(l + 0.085) c h));
  --background--raised: light-dark(oklch(100% 0 0deg), oklch(from var(--color--neutral--900) calc(l + 0.12) c h));
}
```

`--background--raised` を `--background--overlay` より明るくしているのは、メニューがダイアログの中でも開くからです。2つが同じ背景なら、ダイアログの中で開いたメニューは、ダークモードでダイアログと見分けがつかなくなります。メニューを最も明るくしておけば、ページの上でもダイアログの上でも、メニューは置かれた面より明るく表示されます。

置かれた面より1段上の背景を選ぶ、相対的な高さの作り方もあります。祖先が宣言した高さの値をスタイルクエリで読み、1段上の値に切り替える方法です。本書はこの方法を採りません。コンポーネントが外側のコンポーネントの値を問い合わせることになり、外側のコンポーネントのコンテナを問い合わせないという本書の約束（[`container-name-required`](/responsive/container-size-queries/#rule-container-name-required)）に例外が増えるからです。役割で固定すれば、どこに置かれても同じトークンを参照するだけで済みます。

<Demo title="ページ、カード、ダイアログ、ダイアログの中のメニューを重ねたとき" html={surfaceHtml} css={surfaceCss} scheme="auto" />

デモでは、ページの上にカードとダイアログを置き、ダイアログの中にメニューを開いています。影は、カードに `--shadow--sm`、ダイアログに `--shadow--lg`、メニューに `--shadow--xl` を付けています。背景が明るい順（カード、ダイアログ、メニュー）に、影も大きい段階にしています。デモは本のページのテーマに合わせて切り替わります。ライトモードでは、カード、ダイアログ、メニューはどれも白い背景で、影の大きさだけが違い、メニューの影がもっとも大きく落ちます。ダークモードでは、カード、ダイアログ、メニューの順に背景が明るくなり、ダイアログの中のメニューも、ダイアログより明るい面として見分けられます。

## 影は層を足して高さを表す

影も、段階的に高くなるスケールとしてトークンにします。画面の光源は1つに決め、どのトークンも同じ向きの影にします。本書の例は真上からの光なので、水平方向のオフセットは0です。斜めの光にするなら、水平と垂直のオフセットの比を、すべての層でそろえます。

段階が上がるごとに、前の段階の影に層を足します。足す層のオフセットとぼかしは1、3、6、12、24、48pxと、おおむね倍にしていき、広がり（4つ目の値）はその半分を負の値で指定します。負の広がりで影を要素より小さくすると、下にずらした影が要素の左右からはみ出しません。どの層も不透明度は同じです。要素の近くほど層が重なって影が濃くなり、段階が高いほど薄い影が遠くまで落ちるので、段階ごとに不透明度を調整しなくても、高さの違いが読み取れます。

```css title="🙆‍♂ Recommended: 段階が上がるごとに、オフセットとぼかしを倍にした層を足す"
:root {
  --shadow--xs:
    inset 0 1px 0 0 var(--shadow--highlight-color),
    inset 0 0 0 1px var(--shadow--highlight-color),
    0 0 0 1px var(--shadow--ring-color);
  --shadow--sm:
    var(--shadow--xs),
    0 1px 1px -0.5px var(--shadow--color),
    0 3px 3px -1.5px var(--shadow--color);
  --shadow--md:
    var(--shadow--sm),
    0 6px 6px -3px var(--shadow--color),
    0 12px 12px -6px var(--shadow--color);
  --shadow--lg:
    var(--shadow--md),
    0 24px 24px -12px var(--shadow--color);
  --shadow--xl:
    var(--shadow--lg),
    0 48px 48px -24px var(--shadow--color);
}
```

最も低い `--shadow--xs` は、ぼかしのない1pxの縁取りです。`border` と違って要素の大きさに加わらないので、通常の表示ではカードの縁取りに使えます。強制カラーモードでは `box-shadow` が消えるので、操作できる範囲や情報の区切りを示す境界に使うときは、そこで同じ太さの `outline` を描きます（[ルール `no-box-shadow-only-boundary`](/color-media/forced-colors/#rule-no-box-shadow-only-boundary)）。上の段階はどれも `--shadow--xs` を含むので、影を付けた面には必ず縁取りが付きます。枠線を `border` で引くときは、`--border--base` の色を使います。値は `color-mix(in oklab, var(--foreground--base) 12%, transparent)` です。文字色を透明と混ぜているので、どの面の上でも同じようになじみます（「[15-2 相対カラー構文で派生色を作る](/color-media/relative-color/)」）。

<Demo title="同じ影のトークンを、ライトモードとダークモードの背景に置いたとき" html={shadowHtml} css={shadowCss} />

デモでは、ライトモードとダークモードの背景に、`--shadow--xs` から `--shadow--xl` までの影を付けたカードを並べています。ライトモードでは、段階が上がるほど影が濃く、下に長く伸びます。ダークモードでは段階の違いがほとんど見えず、カードの端は、内側の縁取りと上辺の細いハイライトで分かります。ダークモードで高さを背景の明るさで表すのは、このためです。

影の色は、色のトークン（`--shadow--color`、`--shadow--ring-color`、`--shadow--highlight-color`）にして、`light-dark()` でライトとダークの値を持たせます。`light-dark()` は色の値しか切り替えられず、`box-shadow` の値そのものをライトとダークで書き分けられないからです。影の形は1組だけ定義し、各層の色だけをテーマで切り替えます。ダークモードで足す上辺のハイライトと内側の縁取りは、ライトモードでは使わないので `transparent` にしています。

```css title="🙆‍♂ Recommended: 影の形は1組にし、各層の色を light-dark() で切り替える"
:root {
  --shadow--color: light-dark(oklch(0% 0 0deg / 6%), oklch(0% 0 0deg / 18%));
  --shadow--ring-color: light-dark(oklch(0% 0 0deg / 6%), oklch(0% 0 0deg / 24%));
  --shadow--highlight-color: light-dark(transparent, oklch(100% 0 0deg / 4%));
}
```

影の色は、ダークモードでも黒のままにし、不透明度を上げます。暗い背景で白い影を付けると、影ではなく光って見えるからです。上辺のハイライトは白ですが、外に落ちる影ではなく、光の当たる面の縁として内側に1pxだけ描くものです。影は強制カラーモードでは消えるので、要素の境界は影だけで表しません。

本書のデモの背景は無彩色なので、ライトモードの影も黒です。色のある背景に影を落とすなら、影の色を背景の色相に寄せ、明度と彩度を下げた色にします。灰色がかった黒の影を色のある背景に重ねると、背景がくすんで見えるからです。

## 影を動かすときは drop-shadow() を動かす

ホバーで面を持ち上げるように影を変えるときは、`box-shadow` をトランジションさせず、`filter: drop-shadow()` の値を動かします。`box-shadow` を動かすと、動いている間は毎フレーム影を描き直します。ぼかしを含む影は描く計算が重く、層を重ねた段階の高い影ほど計算が増えるので、性能の低い端末ではかくつきます。

```css title="🙅‍♂ Not Recommended: box-shadow のトークンをそのままトランジションさせる" issue="behavior"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.article-card) to (.scoped) {
  :scope {
    box-shadow: var(--shadow--sm);
    transition-duration: var(--duration--base);
    transition-property: box-shadow;
    transition-timing-function: var(--ease--out-quint);

    &:any-link:hover {
      @media (any-hover) {
        box-shadow: var(--shadow--md);
      }
    }
  }
}
```

影のトークン `--shadow--*` は `box-shadow` の値なので、`drop-shadow()` にはそのまま渡せません。`drop-shadow()` は広がり（4つ目の値）と `inset` を持たず、複数の影は関数を並べて書くからです。そこで、高さを表す影を `drop-shadow()` の並びにしたトークン（`--drop-shadow--sm`、`--drop-shadow--md`、`--drop-shadow--lg`）を別に用意し、`filter` に指定して動かします。縁取りの `--shadow--xs` は、`box-shadow` に置いたまま動かしません。

```css title="🙆‍♂ Recommended: 縁取りは box-shadow に残し、高さを表す層を drop-shadow() で動かす"
@scope (.scoped.article-card) to (.scoped) {
  :scope {
    box-shadow: var(--shadow--xs);
    filter: var(--drop-shadow--sm);
    transition-property: filter;

    /* キーボードのフォーカスでは一度で持ち上げるので、トランジションはフォーカスリングのないときだけ掛ける */
    &:not(:focus-visible) {
      transition-duration: var(--duration--base);
      transition-timing-function: var(--ease--out-quint);

      /* 強制カラーモードでは影が消えるので、縁を outline で描く。フォーカスリングは上書きしない */
      @media (forced-colors: active) {
        outline: 1px solid;
      }
    }

    &:focus-visible {
      filter: var(--drop-shadow--md);
    }

    &:any-link:hover {
      @media (any-hover) {
        filter: var(--drop-shadow--md);
      }
    }
  }
}
```

<Demo title="box-shadow を動かすカードと、drop-shadow() を動かすカード" html={shadowLiftHtml} css={shadowLiftCss} />

デモの上の段は、左のカードが `box-shadow` を、右のカードが `filter` の `drop-shadow()` を動かします。どちらのカードも、ポインターを重ねると、影が `sm` の段階から `md` の段階へ変わり、面が持ち上がったように見えます。キーボードでフォーカスしたときも同じ影にしますが、トランジションは `&:not(:focus-visible)` の中に書いてあるので、一度で切り替わります（「[17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)」）。見た目の変化はほぼ同じで、違うのは動いている間の描き直しの量です。下の段は、持ち上げた後の影を止めたまま並べたものです。右の `drop-shadow()` の影は、左の `box-shadow` の影より少し濃く、左右にもわずかに広がります。この違いは、後の段落で説明します。

Chromeで、2つの例のトランジションを1秒に延ばし、パフォーマンスのトレースで比べました。ここでいう描き直しは、DevToolsのPaintの記録です。`box-shadow` の例は毎フレーム描き直され、`drop-shadow()` の例は、ホバーした直後を除いて描き直されませんでした。一方、トランジションの進行は、どちらの例もメインスレッドで計算されます。Chromeは、`drop-shadow()` のように画素を動かすフィルターのアニメーションをコンポジタに移さないので、メインスレッドが詰まると影の変化も止まります。描き直しがなくなっても、GPUでフィルターを当てる処理の負荷は残ります。ほかのブラウザでは確かめていないので、ブラウザ共通の振る舞いとしては扱いません（「[18-10 動きの負荷を抑える](/motion/performance/)」）。{/* 要検証: ブラウザ。Firefox と Safari で、drop-shadow() のトランジションが描き直しなしで処理されるか */}

`--drop-shadow--sm` と `--drop-shadow--md` は、`--shadow--sm` と `--shadow--md` で足す2つの層のオフセットをそのまま使い、ぼかしを半分にしています。`--drop-shadow--lg` は、`--shadow--md` で足す層の大きいほうと `--shadow--lg` で足す層を組にしたものです。色は `box-shadow` の影と同じ `--shadow--color` を参照するので、ダークモードでは `light-dark()` で影の色だけが切り替わります。

```css title="🙆‍♂ Recommended: drop-shadow() の影は、関数の数をそろえた別のトークンにする"
:root {
  --drop-shadow--sm: drop-shadow(0 1px 0.5px var(--shadow--color)) drop-shadow(0 3px 1.5px var(--shadow--color));
  --drop-shadow--md: drop-shadow(0 6px 3px var(--shadow--color)) drop-shadow(0 12px 6px var(--shadow--color));
  --drop-shadow--lg: drop-shadow(0 12px 6px var(--shadow--color)) drop-shadow(0 24px 12px var(--shadow--color));
}
```

`drop-shadow()` の3つ目の長さは、ガウスぼかしの標準偏差です。Chromeで同じぼかしの値を比べると、`drop-shadow()` の影は `box-shadow` の約2倍の距離までぼけました。ぼかしを半分にすると、`box-shadow` とほぼ同じ広がりになります。`box-shadow` のぼかしの値はガウスぼかしの標準偏差の2倍に当たり、`drop-shadow()` の値は標準偏差そのものとして扱われるからです。{/* 要検証: ブラウザ。Firefox と Safari で、drop-shadow() のぼかしが box-shadow の約2倍に広がること */}

トランジションの前後では、関数の数をそろえます。関数は前から順に組になって補間されるので、数がそろっていれば、それぞれの層が対応する層へ滑らかに変わります。そのため、どの段階も関数を2つにし、`--shadow--*` のように前の段階の層を含めて増やすことはしていません。

`drop-shadow()` は、要素の箱ではなく、描かれた不透明な部分の輪郭に沿って影を描きます。背景を塗ったカードなら影の形は角丸の箱とほぼ同じですが、背景が透明な要素では、文字やアイコンの形に影が付きます。並べた関数は、前の関数の影も含めた結果に次の影を付けるので、`box-shadow` の層を同じ数だけ並べると影が濃くなります。広がりで影を絞れないので、左右の端からわずかに影がはみ出し、角丸の外側のぼけ方も `box-shadow` と少し変わります。このため、`--drop-shadow--*` は `--shadow--*` の同じ名前の段階と同じ見た目にはなりません。Chromeで並べると、`--drop-shadow--md` と `--drop-shadow--lg` の影は、同じ名前の `--shadow--*` より濃く、左右にも広がりました。動かす部品では、動かす前と後の影を `box-shadow` の影と並べて確かめます。

`filter` に `none` 以外の値を指定した要素は、重ね合わせコンテキストを作り、`position: absolute` と `position: fixed` の子孫の包含ブロックにもなります。カードの中にカードの外へはみ出す要素を置くときは、その要素の位置と重なり順が変わらないかを確かめます。

## 角丸はトークンから選ぶ

角丸は、`--rounded--sm`（4px）、`--rounded--md`（8px）、`--rounded--lg`（12px）の段階と、完全な角丸の `--rounded--full` をトークンにしています。`--rounded--full` の値は `calc(infinity * 1px)` です。`999px` のような大きな値を書く方法もありますが、「十分に大きい値」という意図は `infinity` のほうが正確に伝わります。角の曲線そのものを変える `corner-shape` や、画面いっぱいのときだけ角丸を消す書き方は、「[16-8 角の形を変える](/decoration/shapes/)」で説明しています。

```css title="🙆‍♂ Recommended: 内側の角丸は、外側の角丸から余白を引いた値にする"
@scope (.scoped.account-menu) to (.scoped) {
  :scope {
    --_radius: var(--rounded--lg);
    --_padding: 4px;

    padding: var(--_padding);
    border-radius: var(--_radius);
  }

  li {
    border-radius: calc(var(--_radius) - var(--_padding));
  }
}
```

<Demo title="内側の角丸を外側と同じにすると、角の部分だけ余白が広く見える" html={nestedRadiusHtml} css={nestedRadiusCss} variant="neutral" />

デモの1つ目は内側にも外側と同じ16pxを、2つ目は16pxから余白の8pxを引いた8pxを指定したメニューです。選んでいる項目の背景の角を見比べると、1つ目では外側の角との間が辺の部分より広く空き、2つ目では同じ幅にそろいます。

角丸の要素の中に、角丸の要素を入れ子にする場合は、内側の角丸を「外側の角丸から間の余白を引いた値」にします。外側と内側に同じ値を指定すると、角の部分だけ余白が広く見えてしまいます。本書のデモでは、外側のパネルに `--rounded--lg` を、余白4pxの内側の項目に `--rounded--md` を使っていて、12pxから4pxを引いた8pxになります。影や角丸の値をpxで指定する理由は、「[6-1 pxとremを使い分ける](/values/px-and-rem/)」で説明しています。

## すりガラスの背景は、真後ろの色だけが混ざる

`backdrop-filter: blur()` で、要素の背後をぼかしたすりガラスの背景を作れます。効果を見せるには、要素の背景を半透明にします。ぼかしの対象になるのは、その要素の真後ろにあるピクセルだけです。固定ヘッダーの少し下にある色付きの要素は、ヘッダーに重なるまでぼかしに混ざらず、スクロールの途中で急に色が現れます。

```css title="🙆‍♂ Recommended: 半透明の背景に backdrop-filter を重ねる" from="decoration/frosted-header"
._header {
  position: sticky;
  inset-block-start: 0;
  background-color: oklch(from var(--background--base) l c h / 70%);
  backdrop-filter: blur(12px);
}
```

<Demo title="スクロールすると、ヘッダーの真後ろにある色だけがぼかされて混ざる" html={frostedHtml} css={frostedCss} height="320px" bleed />

デモの枠の中をスクロールすると、色の付いたブロックがヘッダーの後ろを通ります。ヘッダーに重なった部分の色だけがぼかされて透け、まだ重なっていないブロックの色はヘッダーに混ざりません。

`-webkit-` の接頭辞は書きません。Safariは18から接頭辞なしで対応しています。`backdrop-filter` は、固定配置の子孫の包含ブロックにもなるので、子に `position: fixed` を置くと、期待した位置になりません。詳しくは「[7-10 positionの基礎](/layout/positioning/)」で説明しています。祖先に `opacity` や `mask`、`clip-path` があると、ぼかしの対象がその祖先の内側に限られる点にも注意します。

固定ヘッダーの背景色を、スクロール位置のセクションに合わせて切り替えたいときは、ヘッダーの背景を書き換える代わりに、ヘッダーの後ろに `position: sticky` の色付きの要素（ブロッカー）を置く方法があります。ブロッカーは、自分の入っているセクションの外へは追従しないので、セクションを抜けると次のセクションの色に入れ替わります。ただし、各セクションの先頭に、ヘッダーと同じ高さの余白が必要です。ヘッダーを高さのあるときだけ固定する場合（「[11-7 固定ヘッダー](/layout-practice/sticky-header/)」）は、ブロッカーも同じ条件の中に書き、余白が取れない場面では別の方法を選びます。
