`@scope` は、セレクタが当たる範囲を、スコープのルートから下限までの間に限る仕組みです。`@scope (.media-card) to (.author-note)` と書くと、スタイルは `.media-card` の中に当たり、入れ子にした `.author-note` の手前で止まります。この形を「ドーナツスコープ」と呼びます。

本書では、この仕組みを `@scope (.scoped.<名前>) to (.scoped)` の形で使います。すべてのコンポーネントのルートに `scoped` のクラスを付けておけば、下限に `.scoped` と書くだけで、何を入れ子にしてもスコープが止まるからです。この規約は、仕組みを説明したあとの「本書の書き方：下限を `.scoped` にする」で示します。

この節では、`@scope` の仕様上の動作を説明します。下限の有無による違い、ネストや `:where()` との比較、詳細度が同じときに勝つ側を決める「スコープの近接度」、`<style>` 要素に書く前置きのない `@scope`、`@scope` が防がないものを順に扱います。ルートと子要素の名前の付け方や、`:scope` と `&` の使い分けのような規約は、第9章「[9-4 @scopeとネストの使い分け](/notation/scope-and-nesting/)」で説明します。

## クラス名の工夫で範囲を限る従来の方法

CSSのセレクタは、ページ全体のどの要素にも当てはまる可能性があります。そのため、コンポーネントのスタイルがほかのコンポーネントに漏れないように、これまではクラス名を工夫してきました。代表的なのが、BEMのようにコンポーネント名を接頭辞にする命名です。

```css title="🙅‍♂ Not Recommended: 子孫セレクタで範囲を限ろうとする" issue="behavior"
/* 🙅‍♂ Not Recommended */
.news-card .title {
  color: var(--foreground--accent);
}
```

子孫セレクタで範囲を限ろうとすると、カードの中に置いた別のコンポーネントの `.title` にもスタイルが当たります。詳細度も0.2.0に上がります。BEMのように `.news-card__title` と名前で区別すれば漏れは防げますが、名前が長くなり、すべての子要素に同じ接頭辞を付け続ける必要があります。

`@scope` は、この問題をセレクタが当てはまる範囲そのもので解決します。スコープのルートと下限を指定すれば、その間にある要素にだけスタイルが当たります。ほかのコンポーネントもすべて `@scope` の中に書かれているなら、子要素のクラス名がほかのコンポーネントと同じでも、スタイルはぶつかりません。この条件が成り立たない場合は、「外から入ってくるスタイルは防げない」で説明します。

## `@scope` の基本形

`@scope` の後ろの括弧に、スコープのルートを書きます。下限は `to` の後ろの括弧に書きますが、次の見出しで説明します。

```css title="スコープのルートだけを書いた @scope"
@scope (.news-card) {
  :scope {
    padding: 16px;
  }

  h2 {
    font-size: calc(20 / 16 * 1rem);
  }
}
```

```html title="index.html"
<article class="news-card">
  <h2>お知らせの見出し</h2>
</article>
```

`@scope` の中のセレクタは、先頭に「`:scope` と子孫結合子」が省略されたものとして扱われます。`h2` は `:scope h2` と同じ意味で、スコープのルートの子孫にだけ当てはまります。スコープのルートそのものを選ぶときは、`:scope` と書きます。

詳細度の数え方は、ネストと違います。`@scope` の括弧の中のセレクタは、中のルールの詳細度に加わりません。`h2` は0.0.1、`._main-link` のような子クラスは0.1.0のままです。`:scope` は擬似クラス1つ分の0.1.0です。`@scope` の直下に書いた `&` もルートを選びますが、仕様では `:where(:scope)` と同じ扱いで、詳細度は0になります。本書が `&` ではなく `:scope` でルートを選ぶ理由は、「[9-4 @scopeとネストの使い分け](/notation/scope-and-nesting/)」で説明します。

## ドーナツスコープで入れ子のコンポーネントを除く

`to` の後ろの括弧に書くのは、スコープの下限です。ルートの子孫のうち、下限のセレクタに当てはまる要素とその中身は、スコープから外れます。下限の要素そのものも、スコープの外です。ルートから下限までの間だけにスタイルが当たるので、穴の開いたドーナツにたとえて「ドーナツスコープ」と呼ばれます。

```css title="入れ子にしたコンポーネントを、下限でスコープから外す"
@scope (.media-card) to (.author-note) {
  p {
    color: var(--foreground--accent);
  }
}
```

この例では、`.media-card` の中の `p` が青くなり、入れ子にした `.author-note` の中の `p` は青くなりません。タイプセレクタで選んだスタイルも、下限で止まります。

## 本書の書き方：下限を `.scoped` にする

ここからは、本書の規約です。下限に入れ子のコンポーネントの名前を並べると、カードの中に置く部品が増えるたびに、外側の `@scope` を書き直すことになります。そこで本書では、すべてのコンポーネントのルートに `scoped` のクラスを付け、`@scope (.scoped.<名前>) to (.scoped)` と書きます。下限の `.scoped` は、ルートの内側にある別のコンポーネントのルートすべてに当てはまるので、何を入れ子にしても、外側のスタイルはそこで止まります。

```css title="🙆‍♂ Recommended: すべてのコンポーネントを、下限を .scoped にした @scope で書く" from="cascade/donut-scope"
@scope (.scoped.media-card) to (.scoped) {
  p {
    color: var(--foreground--accent);
  }
}

@scope (.scoped.author-note) to (.scoped) {
  p {
    font-size: calc(var(--text--body-compact--font-size) / 16 * 1rem);
  }
}
```

```html title="index.html"
<article class="scoped media-card">
  <p>外側のコンポーネントの段落</p>
  <aside class="scoped author-note">
    <p>入れ子のコンポーネントの段落</p>
  </aside>
</article>
```

この書き方で範囲が閉じるのは、入れ子にするコンポーネントのルートにも `scoped` が付いているときです。既存のサイトに `@scope` を少しずつ入れる段階では、`scoped` の付いていない古い部品の中まで外側のスタイルが届きます。導入の順番は「[19-6 既存のサイトに段階的に導入する](/operations/adoption/)」で説明しています。ルートを `.scoped.<名前>` とクラス2つで選ぶ理由と、`:scope` と `&` の使い分けは、第9章「[9-4 @scopeとネストの使い分け](/notation/scope-and-nesting/)」で説明します。

<Figure src="cascade/donut-scope" alt="入れ子のコンポーネントを含むHTMLの木と、外側の@scopeの範囲に各要素が入るかを示した表。木は、article.scoped.media-cardを根とし、その子にh2、p、aside.scoped.author-noteがあり、asideの子にh3とpがある。右の2列は、to (.scoped) で下限を書いた場合と、省いた場合。下限ありでは、articleとh2とpだけが範囲に入り、aside、h3、その中のpは範囲から外れる。下限なしでは、6つの要素すべてが範囲に入る。.scopedを持つarticleとasideは、色を付けて強調している。" />

下限を書かなかった場合と比べてみます。次のデモは、外側の `@scope` から `to (.scoped)` を消しただけのものです。入れ子のコンポーネントの段落も、青い文字になります。

このデモでは、文字の大きさにだけ入れ子のコンポーネントの指定が使われています。どちらの `p` のルールも詳細度は0.0.1なので、この節の後半で説明するスコープの近接度によって、ルートに近い入れ子のコンポーネントの指定が勝つからです。しかし、入れ子のコンポーネントが指定していない色には、外側のスタイルがそのまま当たります。

## 下限のない `@scope` とネストの違い

下限のない `@scope` が当てはまる範囲は、ネストで書いた子孫セレクタと変わりません。次の3つのルールは、どれも `.section` の子孫のすべての `p` に当たり、入れ子になった別のコンポーネントの `p` も除きません。

```css title="下限のない @scope と、同じ範囲に当たるネストの書き方"
@scope (.section) {
  p {
    color: green; /* 詳細度 0.0.1 */
  }
}

.section {
  p {
    color: green; /* 詳細度 0.1.1 */
  }
}

:where(.section) {
  p {
    color: green; /* 詳細度 0.0.1 */
  }
}
```

違いは、まず詳細度です。ネストでは、`p` は `.section p` として扱われ、親のクラスの分だけ詳細度が上がります。`@scope` ではルートのセレクタが詳細度に加わらないので、`p` の0.0.1のままです。この差は、ネストの親を `:where()` で包めば再現できます。反対に、`.section { :where(p) { … } }` と書けば、親のクラスだけが残って0.1.0になります。

もうひとつの違いは、`@scope` の中のルールにだけ、次に説明するスコープの近接度が働くことです。ただし、近接度が働くのは、同じ要素の同じプロパティに、詳細度の同じ宣言が複数あるときだけです。上のデモで外側の色が入れ子のコンポーネントに届いたように、入れ子のコンポーネントが指定していないプロパティには、外側の指定がそのまま当たります。範囲を閉じ込めるという `@scope` の目的は、下限を書いて初めて果たせます。

## スコープの近接度

スコープの近接度は、CSS Cascading and Inheritance Level 6で、カスケードの比較の段階に加わった基準です。カスケードは、オリジンと重要度、コンテキスト、`style` 属性、レイヤー、詳細度、スコープの近接度、出現順の順に比べ、先の段階で決まらなかったときだけ次の段階に進みます。近接度は、詳細度の後、出現順の前です。

近接度で比べるのは、スコープのルートから、スタイルが当たる要素までの距離です。仕様は、ルートが違う宣言どうしでは、要素からルートまでの世代や兄弟の数（ホップ数）の少ないほうが勝つと定めています。近接度は詳細度の後に比べるので、詳細度の高いルールは、ルートが遠くても勝ちます。近接度が順位を決めるのは、詳細度が同じときだけです。

次の例では、ライトとダークの配色を入れ子にしています。どちらのルールも詳細度は0.0.1なので、近接度で比べます。

```css title="詳細度が同じなら、ルートに近いスコープの指定が勝つ"
@scope ([data-theme="dark"]) {
  a {
    color: oklch(80% 0.1 250deg);
  }
}

@scope ([data-theme="light"]) {
  a {
    color: oklch(45% 0.15 250deg);
  }
}
```

```html title="index.html"
<div data-theme="light">
  <div data-theme="dark">
    <a href="/">リンク</a>
  </div>
</div>
```

リンクから見ると、ダークのルートは1つ上、ライトのルートは2つ上にあります。ダークのルールは先に書かれていますが、ルートが近いので勝ち、リンクは明るい色になります。出現順で決まるなら、後に書いたライトの色になるところです。

次のデモは、この例に背景色と余白を足したものです。ダークの中のリンクは、後に書いたライトの濃い青ではなく、ダークの明るい青になります。

<Demo title="詳細度が同じなら、ルートに近い @scope の指定が勝つ" html={proximityHtml} css={proximityCss} scheme="light" variant="neutral" widths={[]} />

`@scope` の外に書いたルールは、近接度が無限大として扱われます。そのため、詳細度が同じなら、`@scope` の中のルールが、後に書いた `@scope` の外のルールにも勝ちます。`@scope (.s) { :scope { … } }` と、その後ろに書いた `.s { … }` は、どちらも0.1.0ですが、`:scope` の側が勝ちます。

この性質は、レイヤーを使わない環境で問題になります。本書のユーティリティとパターンは `@scope` の外の素のクラスなので、レイヤーがなければ、コンポーネントの子要素のクラス（0.1.0）と同じプロパティを指定したときに、後から読み込んでも近接度で負けます。レイヤーを使えば、レイヤーの順番が詳細度と近接度より先に比べられるので、この問題は起きません。レイヤーを使わない構成での約束は「[4-3 カスケードレイヤーで順位を決める](/cascade/layers/#cmsでのレイヤー)」で説明しています。

## `<style>` に前置きのない `@scope` を書く

`@scope` は、ルートのセレクタ（前置き）を省いて書くこともできます。仕様では、前置きのない `@scope` のルートは、そのスタイルシートを持つ要素の親要素になります。`<style>` 要素の中に書けば、`<style>` を置いた親要素がスコープのルートです。

```html title="index.html"
<section>
  <style>
    @scope {
      :scope {
        padding: 16px;
      }

      p {
        color: var(--foreground--accent);
      }
    }
  </style>
  <p>この段落にだけ当たります。</p>
</section>
```

この例では、`<section>` がルートになり、`p` のスタイルはこの `<section>` の中にだけ当たります。ルートを選ぶクラス名が要らないので、テンプレートの中にその場限りのスタイルを書く用途を想定した仕組みです。

次のデモでは、2つの `<section>` のうち、1つ目にだけ `<style>` を置いています。2つ目の段落は、同じ `p` でも青くなりません。デモのCSSは枠線を付けるためのもので、前置きのない `@scope` はデモのHTMLの `<style>` の中にあります。

<Demo title="前置きのない @scope は、style 要素を置いた section の中にだけ当たる" html={preludeLessHtml} css={preludeLessCss} variant="neutral" widths={[]} />

本書では、この書き方を規約として勧めません。コンポーネントのスタイルがテンプレートのHTMLに散らばると、コンポーネントごとのCSSファイルにまとまらず、Stylelintでも検証できなくなります。同じコンポーネントをページに3つ置けば、同じ内容の `<style>` も3つ出力されます。本書は、コンポーネントのCSSをファイルに分け、ルートに付けたクラスでスコープを作ります。

## 外から入ってくるスタイルは防げない

`@scope` が制限するのは、`@scope` の中に書いたルールが当たる範囲です。スコープの中のスタイルが外へ漏れることは防げますが、`@scope` の外に書かれたルールがスコープの中の要素に当たることは防げません。

この違いは、自分で書いていないCSSと共存するときに表れます。CMSが本文エリアに `.entry-content h2 { border-inline-start: 4px solid; }` のようなスタイルを出力していると、本文エリアに置いたコンポーネントの `h2` にも枠線が付きます。ライブラリのCSSが `.title` のような汎用的なクラス名にスタイルを指定していれば、同じ名前の子クラスにも当たります。子要素のクラス名がほかのコンポーネントと同じでもかまわないのは、ページのCSSがすべて `@scope` で範囲を閉じているときに限ります。

外から入ってくるスタイルへの対処は、レイヤーとCSSの読み込み方の問題です。外部のCSSを自分で読み込めるなら、`vendors` レイヤーに入れ、コンポーネントの指定が勝つようにします（[4-3 カスケードレイヤーで順位を決める](/cascade/layers/)）。ただし、レイヤーで決まるのは同じプロパティを指定したときの優劣なので、コンポーネントが指定していないプロパティには、外部のCSSが当たり続けます。CMSの本文エリアのように読み込み方を変えられないCSSがある環境では、レイヤーを使わず、読み込む順番で優先順位を保ちます。その判断の基準も4-3で説明しています。{/* CMSの節を公開したらリンクする: /operations/cms/ */}

次のデモでは、本文エリアのCSSを `vendors` レイヤーに入れ、`.entry-content h2` に色と線を指定しています。コンポーネントが指定した `color` はレイヤーの順番で勝ちますが、指定していない `border-inline-start` と `padding-inline-start` は、スコープの中の見出しにも当たります。

<Demo title="@scope の中の見出しにも、外に書いたルールが当たる" html={outerStylesHtml} css={outerStylesCss} variant="neutral" widths={[]} />

値の継承も、スコープの境界を越えます。`@scope` が制限するのはセレクタの適用範囲なので、外側の要素に指定した `color` や `font-size`、カスタムプロパティの値は、下限の内側にも継承されます。継承されるカスタムプロパティの扱いは「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」で説明しています。

外のスタイルを境界で止める仕組みには、Shadow DOMがあります。`@scope` はLight DOM（ページの通常のDOMツリー）の中で自分のルールが当たる範囲を区切るだけなので、外に書いたルールと継承する値の両方が中に届きます。一方、Shadow DOMでは、境界の外に書いた通常のセレクタは内側の要素に当たりません。届くのは、`color` やカスタムプロパティのような継承する値と、部品が `part` 属性で公開した要素に `::part()` で指定するスタイルです。本書では、`::part()` による公開を基本の設計には使いません。その代わり、ページのリセットCSS（kiso.css）やユーティリティクラスも内側には届きません。本書では、カスタム要素で部品を作るときもLight DOMのまま `@scope` で書くのを基本にし、ページから子要素を受け取らず、中身をすべて自分で描く部品に限ってShadow DOMを使います。使い分けの基準と書き方は、第10章「[10-8 Web Components](/components/web-components/)」で説明します。

このため、`@scope (.scoped.<名前>) to (.scoped)` の形には、本書の中で3つの例外があります。1つ目は、カスタム要素で作る部品です。名前のクラスを付けず、要素名を前置きにして `@scope (<要素名>.scoped) to (.scoped)` と書きます。2つ目は、Shadow DOMの中のCSSで、境界がすでにあるので `@scope` を使いません。この2つは「[10-8 Web Components](/components/web-components/)」で説明しています。3つ目は、CMSのWYSIWYGが出力する本文エリアです。編集者は `scoped` のクラスを付けられないので、`@scope (.wysiwyg)` をルートにし、独自のブロックの手前を下限にします（「[19-5 CMSのWYSIWYG本文にスタイルを当てる](/operations/wysiwyg/)」）。どの例外も、下のガイドラインのルールの補足から、該当するルールをたどれます。

## 対応状況と注意点

`@scope` の対応状況は、どの範囲を見るかで2通りに読めます。まず、基本の動作から確認します。

<Baseline id="scope" compatKey="api.CSSScopeRule" name="@scope（基本の動作）" />

`@scope` の基本の動作は、Chrome 118、Safari 17.4、Firefox 146から使えます。すべての主要なブラウザで使えるようになったのは、Firefoxが対応した2025年12月です。本書の対象のブラウザ（Safari 18系の最終版以降と、ほかのブラウザの最新版）では、この節で紹介した形を使えます。ただし、次に説明するとおり、Safari 26.0から26.3には入力欄だけの例外があります。

<Baseline id="scope" name="@scope（機能全体）" />

一方、web-featuresは、`@scope` の機能全体を2026年3月に「新しく利用可能」になったものとして扱っています。MDNのブラウザ互換性データによると、Safari 26.0から26.3には、`@scope` の中のルールが `<input>` と `<textarea>` に当たらない不具合がありました。この不具合はSafari 26.4で直っています。Safari 18系には、この不具合はありません。機能全体のChromeのバージョンが143になっているのは、`@scope` の直下の `&` を `:where(:scope)` として扱う動作を含むためです。

Safari 26.0から26.3を使い続けているユーザーには、スコープの中で指定した入力欄のスタイルが当たりません。次の例では、`input` の枠線の色と角の丸みが、これらのバージョンでは使われません。

```css title="Safari 26.0〜26.3 で当たらない、スコープの中の入力欄の指定"
@scope (.scoped.search-form) to (.scoped) {
  input {
    border-color: var(--border--strong);
    border-radius: 4px;
  }
}
```

ただし、kiso.cssはスコープの外で入力欄に枠線を付けているので、入力欄が見えなくなるわけではありません。

`@scope` は、プログレッシブ・エンハンスメントとしては使いにくい機能です。対応していないブラウザでは `@scope` の中のスタイルがすべて無視され、コンポーネントの見た目がまったく付かないからです。本書の対象のブラウザはすべて基本の動作に対応しているので、本書では前提の機能として使います。対象のブラウザの考え方は、第1章「[1-2 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」で説明します。
