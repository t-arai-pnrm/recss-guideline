CSSのネストは、スタイルのルールの中に別のルールを書き、親のセレクタを `&` で参照する仕組みです。見た目はSassのネストと似ていますが、セレクタを文字列としてつなげる機能ではありません。`&` は、親のセレクタを `:is()` で包んだものとして要素に一致し、詳細度もそれに従って決まります。

`@scope` とネストは、どちらもコンポーネントのスタイルをまとめる道具ですが、得意なことが違います。`@scope` はBEMにおけるblockとelementの関係を、ネストはelementとmodifierの関係を表すのに向いています。この節ではネストの仕様上の動作を説明し、2つを組み合わせる規約は第9章「[9-4 @scopeとネストの使い分け](/notation/scope-and-nesting/)」で説明します。

## Sassのネストと同じだと考えて書く問題

ネストは、長くSassやLessのようなプリプロセッサーの機能でした。プリプロセッサーは、ネストしたセレクタを親のセレクタと文字列としてつなげ、普通のCSSに展開します。`.card { &__title { … } }` から `.card__title` を作れるのも、文字列の展開だからです。

素のCSSのネストは、この展開をしません。ブラウザは、ネストしたルールを親のルールとの関係として解釈し、`&` を「親のセレクタに一致する要素」として扱います。そのため、Sassと同じ形で書いても、無効になるものや、当たる要素と詳細度の変わるものがあります。

次のデモでは、1つ目の見出しをSassと同じ `&__title` で、2つ目の見出しを `& ._title` で指定しています。`&__title` のルールは無効なので捨てられ、1つ目の見出しには、色と大きさのどちらの指定も当たりません。

<Demo title="Sass の &__title は、素の CSS では無効なルールになる" html={sassSuffixHtml} css={sassSuffixCss} variant="not-recommended" widths={[]} />

この違いは、書いた人が気づきにくい形で表れます。`&__title` は無効なセレクタなので、ルールごと無視されますが、エラーは表示されません。詳細度や当たる要素の違いは、多くの場合は見た目に差が出ず、別のスタイルとぶつかったときに初めて表れます。Sassの書き方に慣れていると、素のCSSのネストも展開後のセレクタを想像して読んでしまい、こうした違いを見落とします。AIが生成するコードでも、`&__title` のようなSassの書き方を見かけます。

## ネストの基本の書き方

ネストしたルールのセレクタは、親のセレクタとの関係を表す「相対セレクタ」です。`&` を書けば、その位置に親のセレクタが入ります。`&` を書かなければ、先頭に `&` と子孫結合子が省略されたものとして扱われます。

```css title="& を省いた書き方と、同じ意味の書き方"
.card {
  /* & h2 と同じ（.card h2） */
  h2 {
    font-size: calc(20 / 16 * 1rem);
  }

  /* & > img と同じ（.card > img） */
  > img {
    inline-size: 100%;
  }

  /* .card[data-variant="featured"] */
  &[data-variant="featured"] {
    border: 2px solid;
  }
}
```

`&` は、複合セレクタのどの位置にも書けます。`&[open]` と `[open]&` は同じ要素に一致します。ただし、タイプセレクタは複合セレクタの先頭に書くという決まりがあるので、`&div` は無効で、`div&` と書く必要があります。

`&` を省いた書き方は、2023年12月より前の実装では使えませんでした。Chrome 112〜119とSafari 16.5〜17.1では、ネストしたセレクタを `&` や `.`、`>` のような記号で始める必要があり、`h2` のようにタイプセレクタで始めると無効になりました。

本書では、どのセレクタも `&` で始めます。現在の仕様では、`&` を省いた `.card { ._title { … } }` は、先頭に `&` と子孫結合子を補った `.card ._title` として扱われます。省いても動きますが、先頭に `&` があれば、ネストしたセレクタが親とどういう関係にあるのか（`&:hover` なら自身の状態、`& > img` なら直下の子、`& ._title` なら子孫）を、セレクタの先頭を見ただけで読み取れます。ネストが長くなって親のルールの先頭が画面から外れても、`&` が親を指していることは変わらないので、どのセレクタが親との関係を表しているのかを読み違えにくくなります。規約としては第9章「[9-5 ネストの書き方](/notation/nesting/)」で扱います。

## `&` は `:is()` と同じように働く

仕様は、`&` の詳細度を、親のセレクタリストの中でいちばん高い詳細度と定めています。これは、親のセレクタリストを `:is()` で包んだときと同じ決まり方です。親が1つのセレクタなら、展開した結果と詳細度は変わりません。違いが出るのは、親がセレクタリストのときです。

```css title="親のセレクタリストは :is() で包まれる"
.news, #pickup {
  & ._title {
    /* :is(.news, #pickup) ._title と同じで、詳細度は 1.1.0 */
    color: var(--foreground--muted);
  }
}
```

Sassなら、このルールは `.news ._title, #pickup ._title` に展開され、`.news` の中の `._title` は0.2.0のままです。素のCSSでは、`.news` の中の `._title` にも1.1.0が付きます。Chromeで、このルールと後ろに書いた `.news ._title` を比べると、このルールが勝ちました。次のデモでは、ネストしたルールで文字を灰色に、後ろのルールで青くしています。見出しは灰色になり、後ろのルールからは、ネストしたルールが指定していない文字の大きさだけが使われます。

<Demo title="セレクタリストの中にネストすると、.news の中の見出しにも 1.1.0 が付く" html={isListHtml} css={isListCss} variant="not-recommended" widths={[]} />

詳細度の違うセレクタリストの中にネストしない規約は、第9章のルール `no-nesting-under-selector-list` です。

当たる要素が変わるのは、`&` を後ろに置いて祖先を足すときです。`.a .b { .c & { … } }` の `&` は `:is(.a .b)` になるので、全体は `.c :is(.a .b)` です。これは「`.c` の子孫で、かつ `.a` の子孫である `.b`」を意味し、`.c` と `.a` の上下を問いません。Sassの展開した `.c .a .b` と違い、`.a` の中に `.c` がある `.a .c .b` の並びにも当てはまります。

`&` は、`:is()` と同じく擬似要素を表せません。`._link::after { &[aria-current] { … } }` のように、擬似要素のルールの中にネストしたルールは、どの要素にも当たりません。擬似要素を選ぶときは、要素のルールの中で `&::after` や `&[aria-current]::after` のように、`&` の後ろに書きます。

`&` に文字をつなげる書き方は、どの位置でも使えません。仕様は、ネストを構文の変換ではなく、親のセレクタに実際に一致する要素にもとづく仕組みとして定めています。`.card { &__title { … } }` は無効なルールとして取り除かれ、Chromeでは中身のない `.card { }` だけが残りました。

## 条件付きのアットルールをネストする

`@media`、`@container`、`@supports` は、スタイルのルールの中にも書けます。中に直接書いた宣言は、親のセレクタに当たります。条件を満たしたときの指定を、元の要素のルールの中に置けるので、ひとつの要素のスタイルが1か所にまとまります。次のデモで幅を320pxにすると、画像の下に本文が並び、見出しは20pxです。480pxでも、カードの内側の幅は398pxで400pxに届かないので、同じ並びのままです。768pxでは、カードの内側の幅が400px以上になるので、画像と本文が横に並び、見出しが28pxに大きくなります。

<Demo title="条件付きのアットルールを、要素のルールの中に書く" html={nestingContainerHtml} css={nestingContainerCss} widths={[320, 480, 768]} />

`._layout` は、カードの幅をコンテナサイズクエリで問い合わせ、広いときにフラグ `--_density` を `--spacious` に切り替えます。子孫の `._title` は、そのフラグをスタイルクエリで読みます。どちらの `@container` も、スタイルを変える要素のルールの中に書いています（フラグの仕組みは「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」で説明します）。

ネストした `@container` の中の宣言は、`._layout` と同じ詳細度の0.1.0で、元の宣言より後ろにあります。そのため、条件を満たすと、出現順で元の宣言を上書きします。`@media` や `@container` をセレクタの外にまとめて先に書くと、後ろに来た元のルールが同じ詳細度で勝ち、条件の側の指定は使われなくなります。条件付きのアットルールを各セレクタの中に書く規約は、第9章のルール `conditions-inside-rules` です。

条件付きのアットルールの中には、宣言のほかに、ネストしたルールも書けます。`._layout` の中の `@container` に `& > img { … }` を書けば、条件を満たしたときだけ直下の画像に当たります。アットルールの中に書いたルールの `&` も、外側のスタイルのルール（ここでは `._layout`）を指します。アットルールはセレクタではないので、`&` が指す要素と詳細度を変えません。

## ネストしたルールの後ろに書いた宣言

ネストしたルールの後ろにも、宣言を書けます。現在の仕様では、ネストしたルールの間に続く宣言は、親と同じ要素に同じ詳細度で当たる「ネストした宣言のルール」としてまとめられ、書いた位置の順番を保ちます。JavaScriptからは `CSSNestedDeclarations` として見えます。

```css title="ネストしたルールの後ろに書いた宣言"
.notice {
  & {
    color: red;
  }

  /* 書いた位置の順番を保つので、こちらが勝つ */
  color: green;
}
```

この動作は、2024年12月にすべての主要なブラウザが対応した、比較的新しいものです。それより前の実装（Chrome 129以前、Firefox 131以前、Safari 18.1以前）では、後ろに書いた宣言も親のルールの先頭に移されたものとして扱われ、上の例では `red` が勝ちました。Chromeでは `green` になることを確かめました。次のデモは、同じ順番で赤と緑を指定したものです。本書の並び順の規約には反する書き方なので、悪い例として示します。新しい動作に対応したブラウザでは段落の文字が緑になり、古い実装では赤になります。

本書の対象のブラウザ（Safari 18系の最終版以降と、ほかのブラウザの最新版）は、どれも新しい動作に対応しています。ただし、本書ではルールの中を宣言、条件付きのアットルール、ネストしたルールの順に書くので、どちらの動作でも結果は変わりません。並び順の規約は、第9章のルール `block-content-order` です。

## `@scope` とネストの役割の違い

`@scope` とネストは、BEMの3つの単位のうち、違う関係を表します。BEMのblockは独立したコンポーネント、elementはその部品、modifierはblockやelementの状態や種類です。`@scope` は、ルートと下限でblockの範囲を区切り、その中の部品（element）を短いセレクタで選ぶ仕組みです。ネストは、ひとつの要素のルールの中に、その要素自身の状態や種類（modifier）を `&` でまとめる仕組みです。次のデモでは、2枚のカードのうち `data-variant="featured"` を付けた2枚目だけが、ネストした指定によって濃い2pxの枠線と28pxの見出しになります。

<Demo title="@scope で部品を、ネストで状態や種類を表す" html={scopeAndNestingHtml} css={scopeAndNestingCss} frame={scopeAndNestingFrame} widths={[]} />

BEMで書けば、`.news-card`、`.news-card__title`、`.news-card--featured` に当たる3つの関係が、それぞれ `@scope` のルート、スコープの中の `h2`、`&` を使ったネストで表されます。ネストで部品の階層をたどる書き方（`:scope { h2 { … } }`）もできますが、`@scope` があれば、部品はスコープの直下に並べられます。ネストを要素自身の状態に使い、部品の選択を `@scope` に任せる規約と、その理由は「[9-4 @scopeとネストの使い分け](/notation/scope-and-nesting/)」で説明します。`@scope` の仕様は「[4-4 @scopeでスタイルを閉じ込める](/cascade/scope/)」で説明しています。
