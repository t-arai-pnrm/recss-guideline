セレクタは、要素を選ぶと同時に、そのルールの詳細度を決めます。本書では、ベーススタイルを `base` レイヤーに素のセレクタで書き、コンポーネントの中はクラス1つ分（0.1.0）を基本にそろえます。ベーススタイルのセレクタを `:where()` で包んで詳細度を0にするのは、レイヤーを使えない場合に限ります。IDセレクタと、詳細度を上げるためだけのセレクタは使いません。

`:is()`、`:not()`、`:has()`、`of S` を付けた `:nth-child()` は、引数によって詳細度が変わります。詳細度の数え方と、カスケードの中での位置付けは「[4-1 カスケード・詳細度・継承](/cascade/cascade-basics/)」で説明しています。

この節のコード例も、詳細度の仕組みを見せるために素のクラスで書いています。コンポーネントのスタイルを `@scope` に閉じ込める本書の書き方は、「[4-4 @scopeでスタイルを閉じ込める](/cascade/scope/)」で示します。

## 詳細度がばらばらなセレクタ

詳細度の問題は、多くの場合、上書きしたい側ではなく、上書きされる側の書き方から始まります。次の例では、フォームのボタンと見出しのスタイルを上書きしようとして、うまくいきません。

```css title="🙅‍♂ Not Recommended: 詳細度の高いベーススタイルを、クラスで上書きできない" issue="behavior"
/* 🙅‍♂ Not Recommended */
input[type="submit"] {
  background-color: var(--background--accent);
}

/* 0.1.0 なので、上の 0.1.1 に負ける */
.submit-button {
  background-color: var(--background--surface);
}

#news h2 {
  font-size: calc(24 / 16 * 1rem);
}

/* 0.2.0 なので、上の 1.0.1 に負ける */
.news-list .title {
  font-size: calc(20 / 16 * 1rem);
}
```

`input[type="submit"]` は、タイプセレクタと属性セレクタで0.1.1になります。ボタンに `.submit-button` を付けても、0.1.0なので背景色を変えられません。見出しの例では、IDセレクタを含む `#news h2` が1.0.1になり、クラスをいくつ重ねても勝てなくなっています。

原因は、上書きされる側のセレクタが、必要以上に高い詳細度を持っていることです。上書きする側で工夫しても、さらに高い詳細度が必要になるだけです。そのため、詳細度はセレクタを書く最初の段階で低くそろえておきます。

## IDセレクタと詳細度を上げる技

IDセレクタでは、スタイルを指定しません。詳細度が1.0.0になり、クラスをいくつ重ねても上書きできないからです。オリジンと重要度とレイヤーが同じなら、IDセレクタで指定したスタイルを変えられるのは、別のIDセレクタか `style` 属性、あるいは `!important` だけです。後のレイヤーに書けば詳細度に関係なく上書きできますが、IDのスタイルを変えるたびにレイヤーを分けることになります。本書のStylelintの設定では、`selector-max-id` でIDセレクタを検出しています。

`id` 属性そのものは使います。JavaScriptから要素を参照するとき、`aria-labelledby` などのARIAの属性から参照するとき、ページ内リンクの移動先にするときです。スタイルはクラスで指定し、`id` 属性はこうした用途のために残しておきます。

私は2020年に、`!important` を使わずに上書きする方法として、次のようなセレクタを紹介していました。同じクラスを連結する、`[class]` を足す、存在しないIDを `:not()` に入れる、といった技です。当時はセレクタのほかに詳細度を調整する手段がなく、既存のCSSを直せない場面での最終手段として使っていました。

```css title="🙅‍♂ Not Recommended: 詳細度を上げるためだけのセレクタ" issue="convention"
/* 🙅‍♂ Not Recommended */
.lead-text.lead-text {
  font-size: calc(24 / 16 * 1rem);
}

.lead-text[class] {
  font-size: calc(24 / 16 * 1rem);
}

.lead-text:not(#_) {
  font-size: calc(24 / 16 * 1rem);
}
```

いまは、こうした技を使いません。セレクタから意図が読み取れないうえ、次に上書きする人はさらに詳細度を上げる必要があるからです。祖先のクラスを足す書き方（`.top-page .lead-text`）や、タイプセレクタを足す書き方（`p.lead-text`）も同様です。どちらもHTMLの構造に依存するので、コンポーネントを別の場所で使いにくくなります。

上書きが必要になったら、先に次の手段を検討します。優先順位の問題なら、レイヤーの順番で解決します（[4-3 カスケードレイヤーで順位を決める](/cascade/layers/)）。上書きされる側の詳細度が高すぎるなら、`:where()` で下げます。親のコンポーネントから子のコンポーネントの見た目を変えたいなら、子が公開しているカスタムプロパティに値を渡します（[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)）。

## セレクタには、要素を選ぶのに必要な部分だけを書く

上書きのためでなくても、セレクタには、外しても選ぶ要素が変わらない部分を書きません。クラスで選べる要素にタイプセレクタを連結した `a.nav-link`（過剰修飾）や、祖先をたどって書いた `.site-header .nav .nav-link` が、その例です。

```css title="🙅‍♂ Not Recommended: 選ぶ要素は変わらないのに、タイプセレクタと祖先を足す" issue="convention"
/* 🙅‍♂ Not Recommended */
.site-header .nav a.nav-link {
  color: var(--foreground--base);
}
```

`.nav-link` がこのリンクにしか付いていないなら、ほかの部分を外しても選ぶ要素は変わりません。足した部分は、要素を選ぶ役に立たないまま、詳細度を0.3.1に上げ、HTMLの構造への依存を増やします。リンクを `<button>` に替えたり、ナビゲーションをヘッダーの外へ移したりすると、選ぶ要素は同じ役割のままなのに、セレクタが当たらなくなります。

```css title="🙆‍♂ Recommended: 要素を選ぶのに必要なクラスだけを書く"
.nav-link {
  color: var(--foreground--base);
}
```

セレクタの各部分は、外すと選ぶ要素が変わるかで確かめます。状態の擬似クラスや、同じクラスの要素を置き場所で区別する祖先のように、外すと意味が変わる部分は必要な部分です。本書では、コンポーネントのスタイルを `@scope` の中に書くので、祖先をたどって範囲を限る必要もありません（「[4-4 @scopeでスタイルを閉じ込める](/cascade/scope/)」）。

## ベーススタイルの詳細度と `:where()`

ベーススタイルのように、あらゆる場所で上書きされる前提のスタイルは、`base` レイヤーに素のセレクタで書きます。`base` レイヤーは `components` レイヤーより前にあるので、`a:any-link`（0.1.1）のように、コンポーネントのクラス（0.1.0）より詳細度の高いセレクタでも、クラス1つで上書きできます。レイヤーの順番は詳細度より先に比べられるからです。

```css title="🙆‍♂ Recommended: ベーススタイルは base レイヤーに素のセレクタで書く"
@layer base {
  a {
    &:any-link {
      color: var(--foreground--accent);
    }
  }
}
```

リンクの色は、`a:link, a:visited` ではなく、`a` のルールの中に `&:any-link` とネストして書きます（展開すると `a:any-link` です）。`:any-link` は `href` 属性を持つリンクすべてに当てはまる擬似クラスで、`:link` と `:visited` をまとめて書くのと同じ意味です。リンクで作ったボタンにクラスを付ければ、`components` レイヤーのそのクラスだけで文字色を上書きできます。

レイヤーを使えない環境では、この前提が成り立ちません。CMSのテーマのCSSと共存するために自分のCSSもレイヤーなしで書く場合は、読み込む順番と詳細度だけで優先順位が決まります。このときは、ベーススタイルのセレクタを `:where()` で包みます。`:where()` は、引数にどのようなセレクタを書いても詳細度が0になる擬似クラスで、`:where(a:any-link)` の詳細度は0.1.1から0になります。{/* CMSの節を公開したらリンクする: /operations/cms/ */}

```css title="🙆‍♂ Recommended: レイヤーを使えないときは、ベーススタイルのセレクタを :where() で包む"
:where(a:any-link) {
  color: var(--foreground--accent);
}
```

私が作ったリセットCSSのkiso.cssも、全称セレクタなどの一部を除き、セレクタを `:where()` で書いています。kiso.cssは配布物なので、カスケードレイヤーを使えない環境でも、どのクラスやタイプセレクタからでも上書きできるようにしています。反対に、`:where()` を使っていないリセットCSSをレイヤーなしで読み込むと、リセットCSSのタイプセレクタの詳細度が上回り、ベーススタイルの指定を打ち消すことがあります。リセットCSSを選ぶときも、詳細度が下げられているかを確認します。kiso.cssの設計は、第8章「[8-1 壊さないリセット](/reset/kiso/)」で説明します。

`:where()` は、コンポーネントの中でも使えます。親のルールの中にネストして直下の子を選ぶと、詳細度は0.2.0に上がります。`& > :where(.contact-heading)` と書けば、子を選ぶ部分の詳細度が0になり、全体は0.1.0のままです。子の要素のルールと詳細度がそろうので、書いた順番どおりに上書きできます。

```css title="🙆‍♂ Recommended: 直下の子を選ぶときに詳細度を上げない"
.contact-layout {
  display: block grid;
  reading-flow: grid-rows;
  grid-template-areas:
    "--heading"
    "--body";

  & > :where(.contact-heading) {
    grid-area: --heading;
  }
}
```

グリッドのエリアのように、親との関係で決まるプロパティは、親のルールの中に書くと構造が読み取りやすくなります。そのときに詳細度まで上がらないようにするのが、`:where()` の役割です。

## イレギュラーな擬似クラスの詳細度

擬似クラスの詳細度は、ふつうはクラスと同じ0.1.0です。ただし、セレクタを引数に取る擬似クラスのうち、次の5つは決まり方が違います。表の「引数の最大」は、引数に書いたセレクタのうち、いちばん詳細度の高いものの詳細度という意味です。

| 擬似クラス | 詳細度の決まり方 | 例 | 例の詳細度 |
| --- | --- | --- | --- |
| `:is()` | 引数の最大 | `:is(h2, ._title)` | 0.1.0 |
| `:not()` | 引数の最大 | `p:not(._note)` | 0.1.1 |
| `:has()` | 引数の最大 | `._card:has(> img)` | 0.1.1 |
| `:nth-child(An+B of S)` | 0.1.0に、Sの最大を足す | `:nth-child(2n of ._item)` | 0.2.0 |
| `:where()` | 引数に関係なく0 | `:where(#news h2)` | 0 |

`:is()`、`:not()`、`:has()` は、自分の0.1.0を持ちません。引数の最大がそのまま擬似クラス全体の詳細度になります。引数の最大は、要素に実際に一致したセレクタではなく、引数に書いたすべてのセレクタから選びます。そのため、`:is(#news, ._card)` は、`._card` に当てはまった要素でも1.0.0です。`:nth-last-child()` も、`of S` を付けたときは `:nth-child()` と同じく、0.1.0にSの最大を足します。`of S` を付けなければ、ほかの擬似クラスと同じ0.1.0です。

`:not()` は否定の擬似クラスですが、詳細度は引数の分だけ加わります。`p:not(._note)` は0.1.1で、`p._note` と同じ詳細度です。引数をカンマで並べると、引数の最大の1つ分だけが加わります。`p:not(._note, ._lead)` は0.1.1、同じ要素を選ぶ `p:not(._note):not(._lead)` は0.2.1です。2020年の上書きの技 `:not(#_)` で詳細度を上げられたのも、この決まり方によるものでした。存在しないIDを引数に書くだけで、`:not()` の詳細度がIDセレクタと同じ1.0.0になるからです。

次のデモの2つのカードでは、段落を灰色にするルールの後ろで、`._lead` を青くしています。`p:not(._note)` は0.1.1なので、後ろにある `._lead` のルールより強くなります。同じ条件を `:where()` で包むと詳細度は0.0.1まで下がり、`._lead` の青が使われます。

<Demo title=":not() は引数の分だけ詳細度が上がり、後に書いたクラスに勝つ" html={pseudoSpecificityHtml} css={pseudoSpecificityCss} widths={[]} />

詳細度が引数で決まるので、意味の違うセレクタが同じ詳細度になることがあります。`._card:has(:not(img))` と `._card:not(:has(img))` は、意味が逆なのに、どちらも0.1.1です。詳細度の差から誤りに気づくことはできないので、入れ子の順序は意味から確かめます。

それぞれの擬似クラスの使い方と、`:not()` の引数の書き分けは、第5章「[5-2 :is()・:where()・:not()](/pseudo/is-where-not/)」で説明しています。`of S` で数える対象を絞る書き方は「[5-4 子要素の位置で選ぶ](/pseudo/child-index/)」で、`:has()` の使いどころは「[5-3 :has() で祖先と前の兄弟を選ぶ](/pseudo/has/)」で説明しています。

## 引数に詳細度の高いセレクタを混ぜない

`:is()` は、複数のセレクタをまとめて書くための擬似クラスです。引数の最大が全体の詳細度になるので、引数にIDセレクタや長いセレクタを1つ混ぜるだけで、ほかの引数に当てはまった要素まで高い詳細度になります。

```css title="🙅‍♂ Not Recommended: 引数に詳細度の高いセレクタを混ぜる" issue="behavior"
/* 🙅‍♂ Not Recommended */
:is(#sidebar, .card) ._title {
  font-size: 1rem;
}
```

この例では、`.card` の中の `._title` にも、1.1.0という高い詳細度が付きます。まとめるセレクタの詳細度をそろえるか、詳細度を加えたくないときは `:where()` を使います。`:not()` と `:has()` の引数も同じです。

詳細度が引数で決まることは、状態のスタイルを書くときには役に立ちます。画像があるときだけ2列にするカードで、`:scope` のルールの中にネストした `&:has(> img)` は、`:scope` の0.1.0に `img` の0.0.1が加わり、0.1.1です。`@scope` の直下に書いた `&` は詳細度が0なので、そこに書けば0.0.1になります。状態のスタイルは元のスタイルより詳細度が高くなるので、書く位置に関係なく元のスタイルを上書きできます。引数を短く保てば、こうした上書きの関係も読み取りやすくなります。

## 祖先の状態を `:is()` で書く

`:is()` が特に役立つのは、祖先の状態によって変わるスタイルを、子のルールの中に書くときです。次の例では、`<details>` が開いているときだけ、中のアイコンを回転させています。

```css title="🙆‍♂ Recommended: 祖先の状態による変化を、子のルールの中に書く"
.faq-icon {
  &:is(.faq-item[open] *) {
    rotate: 180deg;
  }
}
```

`&:is(.faq-item[open] *)` は、「開いている `.faq-item` の子孫である、この要素」という意味です。`.faq-item` は `<details class="faq-item">` で、開いているときだけ `open` 属性を持ちます。アイコンのスタイルが `.faq-icon` のルールにまとまるので、状態による変化を探しやすくなります。`@scope` の中では、`.faq-item[open]` の代わりにスコープのルートを指す `:scope[open]` と書けます（「[4-4 @scopeでスタイルを閉じ込める](/cascade/scope/)」）。

同じ指定は、`.faq-item[open] .faq-icon` という別のルールとしても書けます。しかし、`.faq-icon` のルールの中にネストして書くなら、ネストしたセレクタを `&` で始めるという本書の規約から、この形になります。ネストの仕組みは「[4-5 CSSネストの基礎](/cascade/nesting/)」で、規約は第9章「[9-5 ネストの書き方](/notation/nesting/)」で説明します。
