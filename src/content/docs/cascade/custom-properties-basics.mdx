カスタムプロパティは、`--` で始まる名前を付けて任意の値を宣言し、ほかのプロパティの値から `var()` で参照する仕組みです。宣言は、ふつうのプロパティと同じくカスケードで勝ち負けが決まり、子孫に継承されます。`var()` は、それを書いた要素でのカスタムプロパティの値に置き換わります。未定義などで、カスタムプロパティの値が保証された無効値になっているときは、2つ目の引数に書いたフォールバックの値が使われます。参照した値がそれを使うプロパティに合わなくても、フォールバックへは置き換わりません。

`var()` を含む宣言は、置き換えるまで有効かどうかが分かりません。置き換えた後で無効と分かった宣言は、前に書いた同じプロパティの宣言には戻らず、「計算値の時点で無効」になって `unset` と同じ結果になります。そのため、`var()` を使う宣言の前に同じプロパティの値を書いても、フォールバックの代わりにはなりません。

この節で扱うのは、CSSの機能としてのカスタムプロパティです。本書では、名前の形でカスタムプロパティの役割（サイト全体のトークン、外から値を受け取る公開プロパティ、コンポーネントの中だけで使う内部プロパティ）を分けます。この命名は本書独自の約束で、「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」で決めます。この節のコード例に出てくる `--foreground--accent` はトークンの名前、`--_accent` のように `--_` で始まる名前は内部プロパティの名前ですが、仕組みの説明では、どちらもただのカスタムプロパティとして読んでください。

## 宣言と参照

カスタムプロパティは、名前を `--` で始めるプロパティです。ふつうのプロパティと同じく、ルールの中に `名前: 値` の形で宣言し、どの要素に当たるかはセレクタで、どの宣言が勝つかはカスケードで決まります。名前は大文字と小文字を区別するので、`--rounded--md` と `--Rounded--md` は別のプロパティです。値は、宣言した時点では型を検査されず、ほとんどどのような値でも受け付けられます。

値を使うときは、ほかのプロパティの値の中に `var(--名前)` と書きます。`var()` は、その要素でのカスタムプロパティの値に置き換わり、置き換えた後の値が、そのプロパティの値として解釈されます。

```css title="🙆‍♂ Recommended: :root で宣言した値を、var() で参照する"
:root {
  --rounded--md: 12px;
}

@scope (.scoped.notice) to (.scoped) {
  :scope {
    border-radius: var(--rounded--md);
  }
}
```

この例では、`border-radius` の値が `12px` に置き換わります。角丸を変えるときは `:root` の1か所を直せば、`--rounded--md` を参照しているすべての宣言が変わります。`var()` を書けるのはプロパティの値の中だけで、セレクタやプロパティの名前、メディアクエリの条件には書けません。

置き換えは、文字列をつなげる操作ではありません。`--_size: 16` のような単位のない数値に `var(--_size)px` と書いて単位を足すことはできず、`16` と `px` が別々の値として並ぶので、宣言は無効になります。単位のない数値を長さにするときは、`calc(var(--_size) / 16 * 1rem)` のように、単位の付いた値を掛けます。

## 継承されるのは置き換えた後の値

カスタムプロパティは、継承されるプロパティです。祖先で宣言した値は、子孫で宣言し直さない限り、そのまま受け継がれます。`:root` で宣言した値をどの要素からでも参照できるのは、このためです。子孫で同じ名前を宣言すれば、その要素から下では値が変わる点も、`color` などの継承と同じです。

```css title="🙆‍♂ Recommended: 祖先で宣言した値を、子孫で参照する"
@scope (.scoped.notice) to (.scoped) {
  :scope {
    --_accent: var(--foreground--base);

    &[data-variant="danger"] {
      --_accent: var(--foreground--danger);
    }
  }

  ._title {
    color: var(--_accent);
  }
}
```

`._title` は自分では `--_accent` を宣言していないので、ルートの値を継承します。ルートに `data-variant="danger"` を付けるとルートの値が変わり、`._title` のルールを変えなくても、`._title` の文字色は赤になります。

注意が要るのは、カスタムプロパティの値に `var()` を書いた場合です。その `var()` は、宣言した要素の上で置き換えられてから子孫に継承されます。次の例では、`._title` で `--_accent` を変えても、下線の色は変わりません。

```css title="🙅‍♂ Not Recommended: 置き換え済みの値を、子孫で参照先を変えて変えようとする" issue="behavior"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.notice) to (.scoped) {
  :scope {
    --_accent: var(--foreground--base);
    --_rule: 2px solid var(--_accent);
  }

  ._title {
    --_accent: var(--foreground--danger);

    border-block-end: var(--_rule);
  }
}
```

`--_rule` の値は、ルートで `2px solid` と文字色に置き換えられ、その結果が `._title` に継承されます。`._title` で宣言した赤の `--_accent` は、すでに置き換えの済んだ `--_rule` には反映されないので、下線はルートの文字色のままです。子孫ごとに変わる値を使いたいときは、`border-block-end: 2px solid var(--_accent)` のように、変わる部分を参照する宣言を子孫のルールに書きます。

単位を含む値は、置き換えのときに計算されません。`--_size: 1em` は `1em` という並びのまま継承され、`var(--_size)` を書いた要素で長さに計算されます。`@property` で型を登録すると、この振る舞いが変わります（「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」）。

## フォールバックが使われる条件

`var()` には、カンマで区切った2つ目の引数に、フォールバックの値を書けます。フォールバックが使われるのは、参照したカスタムプロパティの値が「保証された無効値（guaranteed-invalid value）」のときです。カスタムプロパティの初期値はこの値なので、どこにも宣言されていない名前を参照すると、フォールバックが使われます。

```css title="🙆‍♂ Recommended: 未定義のときの値を、var() の2つ目の引数に書く" from="cascade/custom-property-fallback"
@scope (.scoped.accent-cases) to (.scoped) {
  ._item {
    border-inline-start: 6px solid var(--_accent, var(--border--strong));
  }
}
```

フォールバックの中には、この例のように、さらに `var()` を書けます。最初のカンマから閉じ括弧の手前までがフォールバックなので、`var(--_font, "Noto Sans JP", sans-serif)` のようにカンマを含む値も、そのまま書けます。

一方、カスタムプロパティに値があれば、その値がプロパティに合わなくても、フォールバックは使われません。`var()` が置き換わるのは参照先の値で、置き換えた結果がプロパティに合うかは、置き換えた後で初めて確かめられるからです。

次のデモでは、3つの枠の違いは `--_accent` の宣言だけです。1つ目の枠は親の `._case` で赤を宣言しているので、子の `._item` は継承した赤で線を引きます。2つ目の枠はどこにも宣言していないので、フォールバックの灰色になります。3つ目の枠は `--_accent: 20px` を宣言しているので、フォールバックは使われません。`border-inline-start` の値が `6px solid 20px` という合わない値になり、線が消えます。

## 値が決まるまでの段階

プロパティの値は、宣言を読み込んでから表示に使われるまでに、次の図の6つの段階を通ります。

<Figure src="cascade/value-pipeline" alt="宣言から使用値までの6つの段階を、上から順に矢印でつないだ図。1は構文解析で、var()を含む宣言は検査を先送りする。右の枠に、合わない宣言はここで捨てられ、前の宣言が使われると書いてある。2はカスケードで、当たる宣言から1つを選ぶ。3は継承と初期値で、宣言がなければ親の値か初期値で補い、指定値にする。4はvar()の置き換えで、カスタムプロパティの値を代入する。この段は色を付けて強調し、右の枠に、合わなければ計算値の時点で無効になり、unsetと同じになると書いてある。5は計算値で、emなどを絶対的な値にし、この値を子孫へ継承する。6は使用値で、レイアウトから%などの値を解決する。凡例は、色を付けた段が、var()を含む宣言が無効と分かる段であることを示す。" />

1つ目の構文解析では、宣言ごとに、値がそのプロパティの構文に合うかを確かめます。合わない宣言はここで捨てられ、カスケードに参加しません。同じプロパティの宣言を前に書いていれば、そちらが使われます。ただし、`var()` を含む宣言は、置き換えるまで値が分からないので、検査を先送りして通します。

2つ目のカスケードでは、要素に当たる宣言のうち1つが選ばれます。この章の「[4-1 カスケード・詳細度・継承](/cascade/cascade-basics/)」から「[4-4 @scopeでスタイルを閉じ込める](/cascade/scope/)」で扱った比べ方は、すべてこの段階のものです。3つ目では、選ばれた宣言がないプロパティに、継承されるなら親の計算値を、継承されないなら初期値を補います。ここで決まった値を「指定値」と呼びます。

4つ目で指定値の中の `var()` を置き換え、5つ目で `em` のような相対的な値を、決められる範囲で絶対的な値にします。こうして決まる値が「計算値」で、子孫に継承されるのはこの値です。6つ目の「使用値」は、レイアウトを決めた後で、`%` で書いた幅のように計算値の段階では決まらなかった値を解決したものです。単位のない数値のカスタムプロパティを `calc()` で長さに変える「[6-3 計算関数で根拠を式に残す](/values/math-functions/)」の例も、4つ目で置き換えた値を、5つ目で計算しています。

`var()` を含む宣言が無効と分かるのは、4つ目の段階です。このとき、カスケードはもう終わっています。

## 前の宣言がフォールバックにならない理由

`--_accent` に色ではない値が入ったときに備えて、同じプロパティの値を前の宣言に書いておく、という書き方を考えます。ふつうの宣言を重ねて、未対応のブラウザに従来の値を使わせるときと同じ発想です。

```css title="🙅‍♂ Not Recommended: var() を使う宣言の前に、同じプロパティの値を書いてフォールバックにする" issue="behavior"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.accent-cases) to (.scoped) {
  ._item {
    border-inline-start: 6px solid currentcolor;
    border-inline-start: 6px solid var(--_accent, var(--border--strong));
  }
}
```

`--_accent` が `20px` のとき、2つ目の宣言の値は `6px solid 20px` という合わない値になります。ふつうの宣言の重複と同じように考えると、無効な2つ目が捨てられ、1つ目の文字色の線が残ると予想できます。しかし、Chromeで確かめたところ、線は残らず、`border-inline-start` は太さ0、スタイル `none` の初期値になりました。

前の図の段階に当てはめると、理由が分かります。2つ目の宣言は `var()` を含むので、構文解析の検査を先送りされて通り、カスケードで出現順によって1つ目に勝ちます。1つ目はここで負けているので、もう使われません。その後、4つ目の段階で置き換えた値が合わないと分かり、2つ目の宣言は「計算値の時点で無効（invalid at computed-value time）」になります。

計算値の時点で無効になった宣言は、`unset` を指定したのと同じ結果になります。継承されるプロパティなら親の値を、継承されないプロパティなら初期値を使います。`border-inline-start` は継承されないので初期値に戻り、線が消えます。`color` のように継承されるプロパティなら、前の宣言の色ではなく、親から継承した色になります。

カスタムプロパティ自身の宣言が計算値の時点で無効になったときは、結果が少し違います。たとえば `--_gap: var(--_unit)` で、`--_unit` がどこにも宣言されていなければ、`--_gap` は保証された無効値になります。保証された無効値は未定義と同じ扱いなので、`gap: var(--_gap, 8px)` のように参照する側では、フォールバックの `8px` が使われます。

前の宣言はフォールバックにならないので、未定義に備える値は `var()` の2つ目の引数に書きます。合わない値が入ることに備えたいときは、値を宣言する側で型を保証します。外から値を受け取るカスタムプロパティを `@property` で登録し、型に合わない値を受けたときにカスタムプロパティ自身の初期値に戻す方法は、「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」で扱います。ブラウザが対応していない関数を `var()` と一緒に使うときは、宣言を `@supports` の中に書きます（「[1-2 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」）。

## 開発者ツールで確かめる

計算値の時点で無効になった宣言は、構文の段階では正しいので、開発者ツールのスタイルのペインでは、取り消し線のない、勝った宣言として表示されます。前に書いた同じプロパティの宣言には、負けた宣言の取り消し線が付きます。{/* 要検証: ブラウザ。値が合わない（未定義ではない）カスタムプロパティを参照した宣言が、Chrome、Firefox、Safariのスタイルのペインで、取り消し線と警告のない状態で表示されること */}勝っているのに表示が変わらない宣言に `var()` が含まれていたら、`var()` の中の名前にカーソルを合わせて値を確かめ、置き換えた結果がそのプロパティに合うかを見ます。

スタイルのペインで `--_accent` の値を書き換えると、CSSのファイルを変えずに、どの値で宣言が無効になるかを試せます。宣言が効かないときの切り分けの全体は、「[19-4 表示の崩れを開発者ツールで調べる](/operations/devtools/)」の「宣言が効かない」で説明しています。
