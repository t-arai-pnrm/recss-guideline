装飾的な動きのうちフェード以外は、`@media (prefers-reduced-motion: no-preference)` の中で指定します。動きを「減らす設定のときに止める」のではなく、「設定がないときにだけ付ける」書き方です。機能的な動きでも、画面の大部分を占める要素の移動や回転のような大きな変動は、動きを減らす設定のときにフェードへ置き換えます。大きな変動にあたるかどうかには、本書の目安の数値を置いています。目安にあたらない小さな移動や拡大を残すのは本書の判断で、WCAG 2.3.3（レベルAAA）の求めることとは分けて考えます。

対応は、無効化、簡素化、短縮、維持の4段階から、動きごとに選びます。全称セレクタと `!important` で全体の動きを一律に止める書き方には頼りません。状態の変化を伝えるフェードや、処理中を示すスピナーまで止まってしまうからです。

## 動きを減らす設定とは

OSには、画面の動きを減らす設定があります。macOSとiOSでは「視差効果を減らす」、Windowsでは「アニメーション効果」のオフがこれにあたります。{/* 要確認: 出典なし */} CSSでは、この設定を `prefers-reduced-motion` メディア特性で調べられます。設定をしていなければ `no-preference`、設定をしていれば `reduce` に当てはまります。

この設定が必要なのは、画面の大きな動きが一部のユーザーの体調に直接影響するからです。内耳の平衡感覚に関わる前庭障害のあるユーザーは、画面の中の大きな移動や拡大を見ると、実際には体が動いていないのに動いたように感じます。目からの情報と体の感覚が食い違うことで、めまいや吐き気、頭痛が起き、その後しばらく画面を見られなくなる場合もあります。乗り物酔いをしやすい人や、片頭痛のある人にも同じことが起こりえます。{/* 要確認: 出典なし */}

一方で、設定をしているユーザーが、すべての動きを嫌っているわけではありません。問題になるのは大きな変動で、位置や大きさの変わらないフェードは、多くの場合は問題になりません。むしろ、ダイアログが一瞬で現れると、何が起きたのか分かりにくくなります。動きを減らす設定への対応は、動きを「なくす」ことではなく、体調に影響する動きを取り除きながら、状態の変化は伝え続けることです。

## WCAG 2.3.3が求めること

WCAG 2.2の達成基準2.3.3「インタラクションによるアニメーション」は、操作をきっかけに起きる動きのアニメーションを、無効にできるようにすることを求めています。対象から外れるのは、その動きが機能や伝える情報にとって本質的な場合だけです。本質的とは、取り除くと内容の情報や機能が根本から変わり、ほかの適合する方法でも同じ情報や機能を実現できないことを指します。この達成基準はレベルAAAなので、レベルAAまでを適合の目標にするサイトでは、満たすことを求められません。

達成基準の解説は、`prefers-reduced-motion` で動きを止める方法を、十分な達成方法の1つに挙げています。サイトの中に動きを止めるスイッチを置く方法もありますが、ユーザーがすでにOSで表明している設定に従うほうが、ユーザーの手間はかかりません。本書では、レベルAAを目標にするサイトでも、この設定への対応を動きを足すときに必ず考える項目として扱います。対応を怠ったときに影響を受けるのは体調で、対応の手間は条件を1つ書くことにとどまるからです。

達成基準の「動きのアニメーション」には、要素の大きさ、形、位置が変わって見えない色や不透明度の変化は含まれません。位置と大きさの変わらないフェードは、この達成基準の対象ではありません。

そのため、移動や拡大をフェードへ置き換えれば、位置と大きさの変化がなくなるので、この達成基準の「動きのアニメーション」を無効にできます。一方で、移動や拡大の再生時間を50msまで短くしても、動きそのものは残るので、この達成基準を満たしたとはいえません。AAAに適合させるなら、本質的でない移動や拡大は、大きさを問わず無効にするか、フェードへ置き換えます。

また、達成基準は、どの大きさや再生時間から動きを無効にすべきかを数値で定めていません。後の「動きごとに4段階で対応を決める」で挙げる数値は、本書が対応を決めるために置いた目安です。

## 自動で動き続ける表示にはWCAG 2.2.2も関わる

操作をきっかけにせず、自動で始まる動きには、別の達成基準も関わります。WCAG 2.2の達成基準2.2.2「一時停止、停止、非表示」は、自動で始まって5秒を超えて続き、ほかの内容と並んで表示される動きに対して、一時停止や停止の手段を求めています。この達成基準はレベルAです。`prefers-reduced-motion` は設定をしているユーザーにしか働かないので、この達成基準を満たす手段にはなりません。

本書では、自動で始まる装飾的な動きは5秒以内に終わらせます。マーキーや自動で回るカルーセルのように5秒を超えて動き続けるものには、止めるボタンを置きます（「[17-8 CSSでカルーセルを作る](/interaction/carousel/)」）。読み込み中のスピナーやスケルトンのように、処理の間だけ動いて終われば止まる表示は、達成基準の解説が本質的な動きとして認める場合があるので、扱いを分けます。

## 全称セレクタで全体の動きを止める書き方の問題

動きを減らす設定への対応として、全称セレクタと `!important` で、すべての要素の動きを止める書き方がよく使われています。以前の私も、この書き方をしていました。再生時間を0ではなく `1ms` にするのは、JavaScriptの `transitionend` のイベントを発火させるための工夫です。トランジションは再生時間と遅延が0だと始まらず、`transitionend` も発火しないからです（`animationend` は、`animation-duration` が `0s` でも発火します）。

```css title="🙅‍♂ Not Recommended: 全称セレクタと !important で、すべての動きを止める" issue="behavior"
/* 🙅‍♂ Not Recommended */
@media (prefers-reduced-motion: reduce) {
  *,
  ::before,
  ::after {
    transition-duration: 1ms !important;
    animation-duration: 1ms !important;
    animation-iteration-count: 1 !important;
  }
}
```

この書き方の1つ目の問題は、止めてはいけない動きまで止めることです。読み込み中を示すスピナーは1回転もせずに止まり、処理が続いているのか固まったのかが分からなくなります。状態の変化を伝えるフェードも消えるので、ダイアログやトーストは一瞬で現れ、ユーザーは何が起きたのかを見落としやすくなります。サードパーティのスクリプトが作る動きも、意図を確かめないまま一律に止まります。

2つ目の問題は、`transition-property` の初期値が `all` であることに関わります。トランジションを指定していない要素でも、`transition-property` は `all` なので、この書き方で再生時間だけを与えると、すべての要素のすべてのプロパティが1msのトランジションの対象になります。もともと動かない設計だった要素でもトランジションが起き、`transitionend` イベントが発火します。イベントは親要素へ伝わるので、親要素でこのイベントを待っているJavaScriptが、想定していない要素のイベントで動いてしまう可能性があります。{/* 要確認: 出典なし */}

3つ目の問題は、`!important` がカスケードの設計を崩すことです。動きを残したい要素があっても、さらに `!important` を重ねなければ上書きできません。動きを1つずつ条件の中に書けば、何を止めて何を残すかを、動きごとに判断できます。

## 動きごとに4段階で対応を決める

動きを減らす設定のときの対応は、次の4段階から選びます。選ぶ基準は、その動きが機能的なものと装飾的なもののどちらなのかと、大きな変動にあたるかどうかの2つです。機能的な動きと装飾的な動きの区別は、「[18-1 動かすかどうかを決める](/motion/purpose/)」で説明しています。

| 対応 | 内容 | 対象の例 |
| --- | --- | --- |
| 無効化 | `no-preference` の中でだけ指定する | パララックス、自動で回るカルーセル、マーキー、スクロールに合わせた変形 |
| 簡素化 | 移動や拡大をやめ、フェードだけにする | ページ遷移のView Transitions、ダイアログやドロワーのような大きなUIの出現と退場 |
| 短縮 | 位置と大きさが変わらない動きの再生時間を短くする（本書の目安は50ms以下） | ツールチップやポップオーバーのフェードイン |
| 維持 | 変えない | スピナー、プログレスバー、フォーカスリングの表示 |

本書の「機能的な動き」は、WCAGの「本質的な動き」と同じ意味ではありません。機能的な動きは、状態の変化や操作の結果を伝える動きです。本質的な動きは、その動きがないと機能や情報が成り立たないものです。画面の端から滑り込むドロワーは、開いたことを伝える機能的な動きですが、その場でフェードしても開いたことは伝わるので、本質的ではありません。機能的な動きの多くはこのように本質的ではないので、操作をきっかけに起きるなら、WCAG 2.3.3の対象になりえます。本質的な動きにあたるのは、アニメーションを作るツールのプレビューのように、動きそのものが内容であるものです。

この区別を踏まえて、本書は動きの種類ごとに対応を決めています。装飾的な動きは、フェード以外をすべて `no-preference` の中に書きます。なくても情報が欠けないので、体調に影響するおそれのある動きを残す理由がありません。機能的な動きは、なくすと状態の変化が伝わりにくくなるので、残したうえで、大きな変動にあたるものだけを、動きを減らす設定のときにフェードへ置き換えます。スピナーのように、動きそのものが「処理中」という情報を伝えているものは、回転を伴っていても維持します。WCAG 2.3.3は、操作をきっかけに起きる動きを無効にできるようにすることを求めますが、機能や情報に欠かせない本質的な動きは除いています。本書は、スピナーの回転をこの本質的な動きとして扱います。ただし、維持するのは、小さな要素で、処理が終われば止まるものに限ります。

大きな変動にあたるかどうかは、本書では次の目安で判断します。画面の3分の1以上を占める要素の移動、画面の3分の1以上の範囲で切り抜きを変える動き、回転を伴う動き（スピナーを除く）、`scale` の変化量が0.5以上の拡大や縮小、スクロールに合わせた変形、揺れや振動です。たとえば、ポップオーバーを `scale: 0.95` から拡大する動きは変化量が0.05なので目安にはあたりませんが、画面の端から全幅のドロワーを滑り込ませる動きはあたります。フェードを短くするときの目安は、50ms以下です。

これらの数値はWCAGが定める基準ではなく、目安を下回れば配慮が要らないという意味でもありません。小さな動きでも、何度も繰り返し現れるものや、画面の広い範囲で同時に起きるものは、体調に影響する可能性があります。{/* 要確認: 出典なし */}目安は対応が必ず要る動きを見落とさないために使い、目安にあたらない動きも、設定を切り替えて確かめたうえで判断します。

## 段階ごとの書き方

ここからは、4段階のそれぞれをコード例で示します。どの例も、動きを減らす設定のときに何が残るかを、コードを読むだけで分かるように書いています。トランジションの書き方そのものは「[18-4 トランジションの基本と中断](/motion/transitions-and-keyframes/)」で、`@keyframes` の書き方は「[18-6 @keyframesを設計する](/motion/keyframes/)」で、トークンの値は「[18-3 イージングと再生時間](/motion/easing-and-duration/)」で説明しています。

### 無効化：no-preferenceの中だけで定義する

ヒーローの背景画像を、ページを開いたときにゆっくり拡大する演出は、装飾的で、画面の大部分を占める要素の大きさが変わります。こうした動きは、アニメーションの指定をすべて `no-preference` の中に書きます。自動で始まる動きなので、再生時間はWCAG 2.2.2の5秒以内に収めます。

```css title="🙆‍♂ Recommended: 装飾的な動きは、no-preference の中だけで定義する"
@keyframes --hero--zoom {
  to {
    scale: 1.1;
  }
}

@scope (.scoped.hero) to (.scoped) {
  ._image {
    @media (prefers-reduced-motion: no-preference) {
      animation-name: --hero--zoom;
      animation-duration: 5s;
      animation-timing-function: var(--ease--out-quad);
      animation-fill-mode: both;
    }
  }
}
```

条件の外には動きに関わる指定が何もないので、動きを減らす設定のときは、画像は最初から最後まで静止したままです。止めるための指定を別に書く必要がなく、条件を書き忘れて、止めるはずの動きが残ることもありません。パララックスやスクロールに合わせた変形も同じ考え方で書きます。スクロールに合わせた動きの作り方は「[18-9 スクロールに合わせて動かす](/motion/scroll-driven/)」で説明しています。

### 簡素化：移動をやめ、フェードだけにする

画面の端から滑り込むドロワーは、開いたことを伝える機能的な動きですが、画面の3分の1以上を占める要素が移動します。動きを減らす設定のときは移動をやめ、フェードだけを残します。

```css title="🙆‍♂ Recommended: 動きを減らす設定のときは、移動をやめてフェードだけにする" from="motion/drawer-reduced"
@scope (.scoped.site-drawer) to (.scoped) {
  :scope {
    --_translate-from: 0;

    z-index: var(--z--top);
    transition-duration: var(--duration--slow);
    transition-property: display, overlay, opacity, translate;
    transition-timing-function: var(--ease--out-drawer);
    transition-behavior: allow-discrete;

    @media (prefers-reduced-motion: no-preference) {
      --_translate-from: 100% 0;
    }

    &:modal {
      @starting-style {
        opacity: 0;
        translate: var(--_translate-from);
      }
    }

    &:not(:modal) {
      opacity: 0;
      translate: var(--_translate-from);
    }
  }
}
```

この例では、移動の起点だけを内部用のカスタムプロパティにし、`no-preference` の中で値を変えています。動きを減らす設定のときは、起点が `0` のままなので位置は変わらず、`opacity` のトランジションだけが残ります。トランジションの指定を1つにまとめたまま、残す動きと止める動きを分けられます。`@starting-style` を使った出現と退場の書き方は「[18-7 出現と退場](/motion/entry-and-exit/)」で説明しています。デモのCSSでは、18-7のダイアログと同じく、背景の `::backdrop` もドロワーと同時にフェードさせ、Safariのために `position: fixed` と `inset: 0` を明示しています。グリッドの並びは開いた状態ではなく基本のルールに書き、閉じる途中で中身の位置が変わらないようにしています。

次のデモでは、ボタンでドロワーを開きます。ふだんの設定では右端から滑り込み、動きを減らす設定ではその場でフェードします。開発者ツールで設定を切り替えると、2つの動きを比べられます（後述の「設定を再現して確かめる」）。デモでは、ダイアログを開く処理をJavaScriptで書かずに済むよう、ボタンに `command` 属性を指定しています。`command` 属性に対応していないブラウザのためにだけ、ポリフィルを読み込みます（「[17-6 開閉するUI](/interaction/disclosure/)」）。

ページ遷移のView Transitionsも、簡素化にあたります。デフォルトの動きは画面全体のクロスフェードで、位置や大きさが変わらないので、動きを減らす設定でもそのまま残せます。要素に名前を付けて移動させる独自の動きだけを `no-preference` の中に書く方法は、「[18-11 View Transitionsで画面の切り替えをつなぐ](/motion/view-transitions/)」で説明しています。

### 短縮：再生時間を短くする

ツールチップのフェードインは、位置と大きさが変わらないので、大きな変動にはあたらず、WCAG 2.3.3の対象でもありません。ただし、ポインターを動かすたびに何度も現れるので、動きを減らす設定のときは再生時間を本書の目安の50ms以下に短くし、ほぼ即座に表示します。

```css title="🙆‍♂ Recommended: 動きを減らす設定のときは、フェードの再生時間を短くする"
@scope (.scoped.tooltip) to (.scoped) {
  :scope {
    z-index: var(--z--top);
    transition-duration: var(--duration--base);
    transition-property: display, overlay, opacity;
    transition-timing-function: var(--ease--out-quad);
    transition-behavior: allow-discrete;

    @media (prefers-reduced-motion: reduce) {
      transition-duration: var(--duration--instant);
    }

    &:popover-open {
      @starting-style {
        opacity: 0;
      }
    }

    &:not(:popover-open) {
      opacity: 0;
    }
  }
}
```

短縮は、WCAG 2.3.3の対象外の変化（不透明度）を、止めずに目立たなくする方法です。160msのフェードが50msになると、ほとんど一瞬の表示に見えますが、表示と非表示の切り替わりは急に見えにくくなります。本書では、短縮を選ぶのは、このように位置と大きさが変わらない動きに限ります。大きな変動にあたらない移動や拡大を短くして残す方法もありますが、動きは残るので、選べるのはAAAを目標にしないサイトだけです。値は、50msの `--duration--instant` のトークンで指定します（「[10-4 デザイントークン](/components/design-tokens/)」）。

### 維持：スピナー、プログレスバー、フォーカスリング

読み込み中を示すスピナーは回転を伴いますが、回っていること自体が「処理が続いている」という情報です。止めると、画面が固まったのか処理中なのかを区別できなくなるので、条件の外に書きます。

```css title="🙆‍♂ Recommended: 動きそのものが情報を伝えるスピナーは、条件の外に書く"
@keyframes --loading-spinner--rotate {
  to {
    rotate: 1turn;
  }
}

@scope (.scoped.loading-spinner) to (.scoped) {
  :scope {
    animation-name: --loading-spinner--rotate;
    animation-duration: 1s;
    animation-timing-function: linear;
    animation-iteration-count: infinite;
  }
}
```

プログレスバーの伸びも、進み具合という情報そのものなので維持します。フォーカスリングは、そもそもトランジションで動かさず、フォーカスが移った瞬間に表示します。キーボードで操作するユーザーは、フォーカスリングの位置で現在地を把握しているので、表示が遅れると操作の対象を見失います。フォーカスリングの書き方は「[17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)」で説明しています。

## 設定を再現して確かめる

動きを減らす設定は、OSの設定を切り替えなくても、開発者ツールで再現できます。ChromeのDevToolsでは、コマンドメニューから「Rendering」パネルを開き、「Emulate CSS media feature prefers-reduced-motion」で `reduce` を選びます。

確かめるのは、無効化した動きが止まっているか、簡素化した動きでフェードが残っているか、維持すべき動きが動き続けているかの3点です。特に、簡素化と短縮では、位置と大きさが変わっていないことと、フェードまで消えていないことを確かめます。ダイアログが一瞬で現れるなら、フェードまで条件の中に入れてしまっている可能性があります。

`no-preference` の状態に戻し、動きが戻ることも確かめます。設定の切り替えはページを読み込み直さなくても反映されるので、2つの状態を交互に切り替えながら比べられます。

## CSSの外の動きにも設定を反映する

動きを減らす設定は、CSSのトランジションとアニメーションだけでなく、JavaScriptで作る演出にも関わります。JavaScriptでは `matchMedia('(prefers-reduced-motion: reduce)')` で設定を調べられます。スクロールに合わせて段落を入れ替えるような演出では、JavaScriptがルートに `data-motion-mode` を付け、設定がないときは `motion`、設定があるときは `reduced` にします。演出のためのスタイルは `motion` のときだけ当てるので、動きを減らす設定のときは要素がすぐに表示されます。この書き方は「[18-9 スクロールに合わせて動かす](/motion/scroll-driven/)」で説明しています。

スクロールで画面に入った時点で一度だけ再生する演出も、動きを減らす設定では無効化するか、フェードに簡素化します。動きを無効化するときは、要素を隠すための指定も `no-preference` の中に書き、要素が最初から表示されるようにします。

View Transitionsでも、独自の動きと要素ごとの名前は `no-preference` の中で指定し、デフォルトのクロスフェードだけを残します。どの仕組みで動かす場合でも、動きを減らす設定のときに伝える情報と操作の結果が、設定がないときと同じになることを確かめます。
