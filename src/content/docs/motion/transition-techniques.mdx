トランジションは、変化したあとの状態のルールに書いた再生時間で動きます。そのため、入る側の状態に短い再生時間を書けば、押したときは素早く、戻るときはゆっくり動かせます。入る側の状態にだけトランジションを書けば、長押しで確定するボタンのように、押し続けた時間を進み具合で見せ、離したらすぐに0へ戻す動きも作れます。

同じ場所で2つの要素を入れ替えるクロスフェードは、不透明度に小さなぼかしを加えると、途中の二重写りが目立たなくなります。複数のプロパティを同じ進み方で動かすときは、`@property` で型を登録したカスタムプロパティを1つだけトランジションさせ、各プロパティの値をその値から計算します。どの書き方も、動かすプロパティをロングハンドで絞り、再生時間とイージングをトークンで書く「[18-4 トランジションの基本と中断](/motion/transitions-and-keyframes/)」の書き方を前提にしています。

## 入るときと外れるときで再生時間を変える

トランジションは、変化したあとの状態に指定された再生時間とイージングで動きます。そのため、基本のルールに長い再生時間を、入る側の状態のルールに短い再生時間を書けば、入るときは素早く、戻るときはゆっくり動きます。押した反応の速さと、戻るときの自然さの両方を取れます。どちらの値もトークンから選びます。

```css title="🙆‍♂ Recommended: 押したときは素早く、戻るときはゆっくり変える"
@scope (.scoped.like-button) to (.scoped) {
  :scope {
    --_background: var(--color--accent--600);
    --_background--pressed: var(--color--accent--700);

    background-color: var(--_background);

    @media (prefers-reduced-motion: no-preference) {
      transition-duration: var(--duration--slow);
      transition-property: background-color;
      transition-timing-function: var(--ease--out-quint);
    }

    &[aria-pressed="true"] {
      --_background: var(--_background--pressed);

      @media (prefers-reduced-motion: no-preference) {
        transition-duration: var(--duration--fast);
      }
    }
  }
}
```

入る側の `transition-duration` も、動きを減らす設定の条件の中に書きます。`transition-property` の初期値は `all` なので、条件の外に再生時間だけを書くと、動きを減らす設定のときにも、すべてのプロパティがその再生時間で動いてしまいます。

## 長押しで確定するボタン

前の見出しと同じ仕組みで、入る側の状態にだけトランジションを書くと、入るときだけ動き、外れるときは一瞬で戻ります。これを使うのが、押し続けている間だけ進み具合が伸び、一定の時間押し続けてから離すと確定するボタンです。削除のような取り消せない操作を、一度押しただけでは実行しないようにする場面で使います。入る側（押している状態）に確定までの時間と `linear` を書き、基本のルールにはトランジションを書きません。押している間は一定の速さで進み、離すとすぐに0に戻ります。

前の見出しの例と違って戻る動きを付けないのは、進み具合の広がりが、押し続けた時間そのものを表すからです。前の例のボタンの色は押したかどうかを伝えるだけなので、戻る途中で押し直されても、伝える内容は食い違いません。長押しは、利用者が意図して時間をかける操作で、離すと押し続けた時間の判定は最初からやり直しになります。戻る動きを付けると、戻る途中で押し直したときに、判定は0から始まるのに表示は途中から広がり、表示と確定までの残りの時間が食い違います。そのため、入る側は確定までの時間をかけて一定の速さで進め、離したら表示も判定と同じく0に戻します。

```css title="🙆‍♂ Recommended: 押している間は一定の速さで広げ、離したらすぐに0へ戻す"
@scope (.scoped.hold-button) to (.scoped) {
  :scope {
    --_holding: --false;
    --_duration: var(--hold-button--duration, 2s);

    display: inline grid;

    & > ._label,
    &::before {
      grid-area: 1 / 1;
    }

    &::before {
      content: attr(data-label) / "";
      clip-path: inset(0 100% 0 0);
      background-color: var(--foreground--danger);

      @container style(--_holding: --true) {
        clip-path: inset(0);
        transition-duration: var(--_duration);
        transition-property: clip-path;
        transition-timing-function: linear;
      }
    }

    &[data-holding="true"] {
      --_holding: --true;
    }
  }
}
```

ボタンの文字と同じ文字を `data-label` 属性から擬似要素に入れ、危険を表す色で塗った層として、文字と同じグリッドのセルに重ねます。`clip-path: inset(0 100% 0 0)` は右から幅の100%を切り落とすので、押す前の層は見えません。押している間は、後で説明するJavaScriptがボタンに `data-holding="true"` を付け、`--_holding` が `--true` になります。擬似要素は `@container style()` でその値を問い合わせて、`inset(0)` まで左から広がります。押している状態を `:active` で受け取らないのは、マウスのボタンを押したままボタンの外へ動かしても `:active` が当たり続けるからです。外へ出た時点で判定を中止しても、`:active` で広げていると進み具合は伸び続けます。擬似要素の見た目を要素の状態で切り替えるときに、状態のフラグを立てる書き方は「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」で説明しています。

2秒は、このデモのために選んだ例示の値であり、一般に推奨する長さではありません。UIの動きの速さではなく、確定までに押し続けてもらう時間なので、誤って押したときに離す余裕と、待たされる長さの兼ね合いで、操作の重さに合わせて決めます。値はボタンの公開用のカスタムプロパティ `--hold-button--duration` で受け取り、使う側から変えられるようにしています。受け取った値は内部用の `--_duration` に入れ、トランジションの再生時間と、JavaScriptの判定の両方がそこから読みます。進み具合の動きは、機能的な動きの再生時間の上限と、`linear` を一定の速さで続く動きに限るルールの例外です。どちらもルールの補足に書いています（「[18-3 イージングと再生時間](/motion/easing-and-duration/)」）。

この例では、進み具合の表示を動きを減らす設定でも残すので、トランジションを条件の外に書いています。進み具合は、小さなボタンの中で、あとどれだけ押し続ければ確定できるかという残りの時間を伝える情報で、なくすと押している間に何も手がかりがなくなるからです。「[18-2 動きを減らす設定に対応する](/motion/reduced-motion/)」で、プログレスバーの表示を変えないのと同じ扱いです。ボタン自体の位置と大きさは変わらず、移動や拡大も足しません。`transition-property` を `clip-path` に絞っているので、ほかのプロパティは動きません。

Chromeで、このデモのボタンを押し続けている間をパフォーマンスのトレースで記録しました。擬似要素の切り抜きのトランジションはコンポジタのスレッドで進み、DevToolsのPaintは、押し始めと押し切った時点を除いて記録されませんでした。ほかのブラウザでの扱いは確かめていません（「[18-10 動きの負荷を抑える](/motion/performance/)」）。{/* 要検証: ブラウザ。Firefox と Safari で、clip-path のトランジションに描き直しが起きるか、進行をどのスレッドで計算するか */}

### 長押しで確定する処理と、ほかの操作の方法

CSSで作れるのは進み具合の表示までで、削除の確定にはJavaScriptが要ります。押し切った時点では削除せず、確定できる状態にするだけにして、ボタンの上で離したときに削除します。WCAG 2.2の達成基準2.5.2（ポインターのキャンセル）は、満たし方として、押し下げた時点で処理を実行しないことや、離した時点で完了させ、完了の前に中止する手段を用意することを挙げています。達成基準の解説も、長押しで操作する要素の例として、指を要素の内側で離したときに結果を実行するものを挙げています。このボタンは後者に当たり、ボタンの外へポインターを動かしてから離せば中止できます。押したまま確定すると、押し切ってから誤りに気付いても、取り消す手段がありません。

途中で離したとき、ボタンの外で離したときは中止します。ブラウザが `pointercancel` で操作を取り消したとき（タッチでスクロールが始まった場合など）と、ボタンがフォーカスを失ったときも同じです。中止したら表示と判定を最初に戻し、押し直したときは0から数え直します。確かめたいのは、連続して2秒押したことだからです。

経過時間は、押し始めに始めたJavaScriptのタイマーで測ります。進み具合の層のトランジションが終わったときに起きる `transitionend` で判定すれば、時間をCSSだけに書けますが、確定できるかどうかが表示のトランジションの有無に左右されます。ユーザースタイルシートや拡張機能でトランジションを止めている環境では、`transitionend` が起きず、長押しで確定できなくなります。時間は、CSSの `--_duration` を `getComputedStyle()` で読み、表示と判定に同じ値を使います。次の例の `toMilliseconds()` は、`2s` や `2000ms` の形の値をミリ秒の数に直す関数です。

```js title="押し続けた時間をタイマーで測り、ボタンの上で離したときに確定する JavaScript の例"
const start = () => {
  ready = false;
  button.dataset.holding = 'true';
  const duration = toMilliseconds(getComputedStyle(button).getPropertyValue('--_duration'));
  holdTimer = setTimeout(() => {
    ready = true;
    status.textContent = '離すと削除します。';
  }, duration);
};

// 中止する。進み具合の表示も、判定も、最初に戻す
const cancel = () => {
  clearTimeout(holdTimer);
  ready = false;
  delete button.dataset.holding;
};

// 離したときに、押し切っていれば削除を確定する
const finish = () => {
  const wasReady = ready;
  cancel();
  if (wasReady) remove();
};

button.addEventListener('pointerdown', start);
button.addEventListener('pointerup', finish);
button.addEventListener('pointerleave', cancel);
button.addEventListener('pointercancel', cancel);
button.addEventListener('blur', cancel);
```

ボタンの外へポインターを動かすと、その時点で `pointerleave` が起きて中止されるので、外で離しても削除されません。タッチの操作では、押した要素がポインターを捕捉し、指が外へ出ても `pointerleave` が起きません。デモでは、`pointerdown` で `releasePointerCapture()` を呼んで捕捉を外しています。押し切ったときは、状態のメッセージで「離すと削除します。」と伝えます。

キーボードでは、ボタンにフォーカスしてSpaceキーを押し続ける操作を、同じ判定で扱います。`keydown` で `start()` を、`keyup` で `finish()` を呼びます。押し続けている間に繰り返し起きる `keydown` は、`event.repeat` で除きます。一方、Enterキーは押した時点で `click` を起こすので、長押しの判定を始めません。スクリーンリーダーでボタンを押す操作は、多くの場合 `click` だけを起こし、押し続ける状態を作れません。{/* 要検証: ブラウザ。Firefox と Safari で、Space キーを押し続けたときの keydown、keyup、click の順序。iOS の Safari と Android の Chrome で、タッチの長押しが pointercancel や contextmenu で中断されないこと */}

長押しだけを確定の手段にすると、Enterキーやスクリーンリーダーの利用者は削除できません。そのため、押してすぐに離したときや、Enterキーやスクリーンリーダーでボタンを押したときは、確認のダイアログを開いて、そこから削除できるようにします。デモでは、ボタンに `command="show-modal"` を付けてダイアログを開き、押し切って離したあとに起きる `click` だけを `preventDefault()` で取り消しています。ボタンの下には、2つの操作の方法を書いた説明を置き、`aria-describedby` でボタンに結び付けています。

次のデモでは、ボタンを押し続けると、赤い層が左から2秒かけて広がり、広がりきると「離すと削除します。」と表示されます。そのままボタンの上で離すと「下書きを削除しました。」と表示されます。広がりきってからボタンの外へポインターを動かすと、層は消え、離しても削除されません。途中で離すと層はすぐに消えて確認のダイアログが開き、押し直すと層は左端から広がり直します。Spaceキーを押し続けても同じように広がり、Enterキーで押すとダイアログが開きます。動きを減らす設定でも、層は同じように広がります。

## ぼかしでクロスフェードの重なりを目立たなくする

2つの要素を同じ場所に重ね、片方を消しながらもう片方を出すクロスフェードでは、途中で両方が半透明になり、二重に写って見えます。コピーのボタンのアイコンを、押したあとにチェックの印へ切り替えるような場面です。消える側と現れる側に `filter: blur()` を数pxだけ掛けると、途中の重なりがぼけて、1つの形が別の形に変わったように見えます。{/* 要確認: 出典なし。ぼかしで二重写りを目立たなくする技法 */}

```css title="🙆‍♂ Recommended: 切り替わるアイコンに、不透明度と小さなぼかしを組み合わせる"
@scope (.scoped.copy-button) to (.scoped) {
  :scope {
    display: inline grid;

    & > ._copy-icon,
    & > ._copied-icon {
      grid-area: 1 / 1;
    }
  }

  ._copy-icon,
  ._copied-icon {
    transition-duration: var(--duration--fast);
    transition-property: opacity, filter;
    transition-timing-function: var(--ease--out-quint);
  }

  ._copied-icon {
    opacity: 0;
    filter: blur(4px);

    &:is(:scope[data-copied="true"] *) {
      opacity: 1;
      filter: none;
    }
  }

  ._copy-icon {
    &:is(:scope[data-copied="true"] *) {
      opacity: 0;
      filter: blur(4px);
    }
  }
}
```

2つのアイコンは、グリッドの同じセルに置いて重ねています。`filter` の `none` と `blur(4px)` の間は、`blur(0)` から補間されます。位置と大きさを変えない変化なので、フェードと同じく、動きを減らす設定の条件の外に書いています。ぼかしの半径を大きくすると描画の負荷が増えるので、数pxにとどめます（「[18-10 動きの負荷を抑える](/motion/performance/)」）。

次のデモでは、ボタンを押すと `data-copied` 属性が `true` になり、コピーのアイコンがチェックの印に切り替わって、1.5秒後に戻ります。デモのボタンは属性を切り替えるだけで、実際には何もコピーしません。左のボタンは不透明度だけを、右のボタンは不透明度とぼかしを動かしています。左は切り替えの途中で四角とチェックの印が重なって見え、右は輪郭がぼけて、1つの形が別の形に変わったように見えます。比べるために、ぼかしの半径を公開用のカスタムプロパティで受け取り、左のボタンだけ0にしています。

## 複数の値を1つのカスタムプロパティで一緒に動かす

ホバーしたカードを持ち上げ、同時に影を濃くし、枠線の色を変えるときは、3つのプロパティを別々にトランジションさせるより、`@property` で `<number>` 型に登録したカスタムプロパティを1つだけ動かすほうが管理しやすくなります。0から1へ進む値を1つ用意し、`translate`、`filter`、`border-color` の値をその値から計算します。影は、`box-shadow` ではなく `filter: drop-shadow()` で描きます（「[16-5 面・影・角丸](/decoration/surfaces/)」）。トランジションの対象は登録したカスタムプロパティだけなので、3つの値は同じ再生時間とイージングで、同じ進み方をします。

プロパティごとにトランジションさせる書き方では、状態の値が状態のセレクタごとに散らばります。次の例では、ホバーとフォーカスの2つのセレクタに、同じ3つの値を書き並べています。持ち上げる距離を変えるときは両方を直し、動かすプロパティを足すときは `transition-property` の並びも直します。

```css title="🙅‍♂ Not Recommended: 状態の値を、プロパティごとに状態のセレクタへ書き並べる" issue="convention"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.link-card) to (.scoped) {
  :scope {
    border: 1px solid var(--border--base);
    transition-duration: var(--duration--base);
    transition-property: translate, filter, border-color;
    transition-timing-function: var(--ease--out-quint);

    &:any-link:hover {
      @media (any-hover) {
        border-color: var(--foreground--accent);
        filter: drop-shadow(0 8px 12px var(--shadow--color));
        translate: 0 -4px;
      }
    }

    &:focus-visible {
      border-color: var(--foreground--accent);
      filter: drop-shadow(0 8px 12px var(--shadow--color));
      translate: 0 -4px;
    }
  }
}
```

カスタムプロパティを1つにまとめるには、型の登録が欠かせません。登録していないカスタムプロパティは文字の並びとして扱われるので、0と1の間の値が補間されず、値が変わった時点で切り替わります。`transition-behavior: allow-discrete` を指定しても、再生時間の半分の時点で切り替わるだけです。`@property` の記述子と、登録する場面の判断は「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」で説明しています。

```css title="🙆‍♂ Recommended: 登録した1つの値から、3つのプロパティの値を計算する" from="motion/registered-progress"
@property --link-card--progress {
  syntax: "<number>";
  inherits: false;
  initial-value: 0;
}

@scope (.scoped.link-card) to (.scoped) {
  :scope {
    --_lift: 0px;

    border: 1px solid color-mix(in oklab, var(--foreground--accent) calc(var(--link-card--progress) * 100%), var(--border--base));
    filter: drop-shadow(0 calc(var(--link-card--progress) * 8px) calc(var(--link-card--progress) * 12px) color-mix(in oklab, var(--shadow--color) calc(var(--link-card--progress) * 100%), transparent));
    translate: 0 calc(var(--link-card--progress) * var(--_lift));
    transition-duration: var(--duration--base);
    transition-property: --link-card--progress;
    transition-timing-function: var(--ease--out-quint);

    @media (prefers-reduced-motion: no-preference) {
      --_lift: -4px;
    }

    &:any-link:hover {
      @media (any-hover) {
        --link-card--progress: 1;
      }
    }

    &:focus-visible {
      --link-card--progress: 1;
    }
  }
}
```

状態のセレクタが書き換えるのは `--link-card--progress` の1つだけです。3つのプロパティの値は、進み具合を掛けた式として基本のルールに1回ずつ書くので、持ち上げる距離や影の大きさを変えるときに直す場所は1か所です。動きに加わるプロパティを足しても、`transition-property` は変えずに済みます。

動きを減らす設定には、移動の距離を係数にして対応します。`--_lift` は `0px` を基本にし、`prefers-reduced-motion: no-preference` のときだけ `-4px` にします。動きを減らす設定のときは、カードは持ち上がらず、影と枠線の色だけが変わります。影と枠線の変化は要素の位置と大きさを変えないので、トランジションは条件の外に書いています。1つの値で動かす書き方では、プロパティごとにトランジションを外せないので、移動や拡大に当たる値だけをこのように係数で止めます（「[18-2 動きを減らす設定に対応する](/motion/reduced-motion/)」）。

次のデモは、上のCSSをそのまま使っています。カードにポインターを乗せるか、キーボードでフォーカスすると、カードが4px持ち上がり、影が濃くなり、枠線が青に変わります。3つの変化は同時に始まり、同時に終わります。ポインターを途中で外すと、3つがそろって途中の状態から戻ります。

### 1つの値で動かすときの注意点

動かすカスタムプロパティは、`inherits: false` で登録します。継承するカスタムプロパティを動かすと、その値を受け継ぐ子孫の要素すべてで、スタイルの計算がフレームごとに繰り返されるからです（「[18-10 動きの負荷を抑える](/motion/performance/)」）。継承しないので、値を参照できるのは、値を宣言した要素自身だけです。上の例では、計算に使う3つのプロパティをすべてカードのルートに書いています。

`translate` や `filter` をカスタムプロパティを介して動かすと、合成の処理だけでは済まず、値の計算がフレームごとにメインスレッドで行われます。Chromeで、このデモの動きをパフォーマンスのトレースで記録すると、スタイルの計算は毎フレーム起き、描き直しは `border-color` の変化の分だけ毎フレーム起きました。この書き方を選ぶのは、枠線の色のように、もともと描画のやり直しが必要な値を一緒に動かす場合です。動かすのが `translate`、`opacity`、`filter` だけなら、ルール [`animated-property-no-inherit`](/components/custom-properties/#rule-animated-property-no-inherit) のとおり、カスタムプロパティを介さずに直接トランジションさせます。

`@property` による登録は、書いた場所を問わず、文書全体に適用されます。`@scope` の中で登録しても、型と初期値は範囲の外の要素まで適用されました（Chromeで確認）。{/* 要検証: ブラウザ。Firefox と Safari で、@scope の中に書いた @property が範囲の外にも適用されること */}そのため、`@property` は `@scope` の外のトップレベルか、グローバルな定義を置く `base` レイヤーに書きます（「[4-3 カスケードレイヤーで順位を決める](/cascade/layers/)」）。同じ名前を2つのレイヤーで登録したときは、スタイルシートに現れた順ではなく、レイヤーの順序で後のレイヤーの登録が有効になりました（Chromeで確認）。{/* 要検証: ブラウザ。Firefox と Safari で、同じ名前の @property がレイヤーの順序で決まること */}

名前は、コンポーネントの中でだけ使う値でも、内部用の `--_progress` ではなく、`--link-card--progress` のように公開プロパティの形にします。登録は文書全体に及ぶので、短い内部用の名前を登録すると、同じ名前を別の意味で使うほかのコンポーネントにも型が適用されるからです（「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」）。一方、`--_lift` のように登録せず、動かさない値は、これまでどおり内部用の名前にします。
