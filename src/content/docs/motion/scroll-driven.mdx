スクロールに合わせた動きは、値の変わり方で作り方を選びます。スクロール位置に合わせて連続して変わる値には、CSSのスクロール駆動アニメーションを使い、`animation-range` で範囲を明示します。画面に入った時点で1回だけ変わる演出は、`view()` のタイムラインでカスタムプロパティを切り替え、`@container style()` で時間で進むアニメーションを再生して作ります。Firefoxでも演出を出したいときと、スクロールを戻しても再生を止めたくないときは、`IntersectionObserver` で属性を付けます。JavaScriptで毎フレーム同期するのは、それでも作れない複雑な分岐が必要なときだけです。

どの方法でも、演出に対応していない環境では、要素を動き始める前の見た目で待たせません。CSSだけの方法は、`@supports (animation-timeline: view()) and (animation-range: entry)` で囲みます。JavaScriptを使う方法は、準備を終えてルートに `data-motion-mode="motion"` を付けたときだけ待たせます。印刷のようにスクロールしない媒体でも待たせないように、待機の指定は `screen` のメディアに限ります。待機中の見た目は `@keyframes` の `from` に任せ、`opacity: 0` を別に書きません。演出が動かない環境でも、動きを減らす設定の環境でも、すべての内容を読めるようにするためです。

初めて読むときは、「連続した変化か、1回の変化か」で手段の選び方を押さえ、「スクロール駆動アニメーションで値を連続して変える」と「画面に入ったら1回だけ再生する」を読みます。`IntersectionObserver` で属性を切り替える方法は、Firefoxでも演出を出すときに読みます。横に流れるセクションとJavaScriptで毎フレーム同期する方法は、その演出を作る場面が来てから戻ってください。

## スクロールのたびに位置を計算する問題

以前は、スクロールに合わせた動きを `scroll` イベントで作るのが一般的でした。スクロールのたびに `scrollTop` や `getBoundingClientRect()` で位置を読み、その値からスタイルを書き換えます。

```js title="🙅‍♂ Not Recommended: scroll イベントのたびに位置を読み、スタイルを書き換える" issue="behavior"
/* 🙅‍♂ Not Recommended */
window.addEventListener('scroll', () => {
  for (const item of document.querySelectorAll('.feature-list li')) {
    const { top } = item.getBoundingClientRect();
    item.style.opacity = top < window.innerHeight * 0.8 ? '1' : '0';
  }
});
```

この処理には、2つの負担があります。1つ目は、スクロールのたびにJavaScriptがメインスレッドで動くことです。スクロールの位置は先に進んでも、見た目を変えるのはこの処理なので、メインスレッドがほかの処理で忙しいと、スクロールの位置と見た目がずれ、動きがかくつきます。

2つ目は、位置の読み取りとスタイルの書き換えを交互に行うことです。`getBoundingClientRect()` は、まだ反映していないスタイルやレイアウトの変更があると、その場で計算を済ませてから値を返します。この例が書き換える `opacity` は寸法を変えないので、やり直しになるのはスタイルの計算までです。しかし、高さやレイアウトに関わるクラスを書き換えると、要素ごとにレイアウトの計算がやり直しになります（layout thrashing）。

もう1つの問題は、JavaScriptが動かなかったときの見た目です。透明にする処理だけが動き、戻す処理が動かなければ、要素は見えないままになります。上の例はスクリプトが読み込まれなければ何もしませんが、透明にする指定をCSSに常に書いておく作り方では、内容がまるごと読めなくなります。

## 連続した変化か、1回の変化か

スクロールに合わせた動きを作る手段には、優先順位があります。最初に選ぶのは、CSSだけで作る方法です。次が、`IntersectionObserver` で状態を切り替え、CSSのトランジションやアニメーションで動かす方法です。JavaScriptで毎フレーム同期する方法は、本当に必要な場合に限ります。

どれを選ぶかは、スクロール位置と値の関係で決まります。パララックスや読んだ量の表示のように、スクロール位置に合わせて値が連続して変わるなら、スクロール駆動アニメーションです。要素が画面に入った時点で一度だけ見た目が変わるなら、スクロール駆動アニメーションは再生のきっかけにだけ使い、見た目の変化は時間で進むアニメーションに任せます。Firefoxでも演出が必要なら、きっかけを `IntersectionObserver` で作ります。スクロール量に応じて表示する内容を入れ替えるような、複雑な分岐が必要な場合は、JavaScriptで `requestAnimationFrame` を使って制御します。

| 値の変わり方 | 手段 | 例 |
| --- | --- | --- |
| スクロール位置に合わせて連続して変わる | スクロール駆動アニメーション | パララックス、スクロールした量に応じたヘッダーの背景、縦のスクロールで横に流れるセクション |
| 画面に入ったときに一度だけ変わる | `view()` のタイムラインとスタイルクエリ（Firefoxでも出すなら `IntersectionObserver`）で、CSSのアニメーションを再生する | 見出しやカードが現れる演出 |
| スクロール量に応じて複雑に分岐する | `requestAnimationFrame` で制御するJavaScript | 段落を入れ替えながら進む演出 |

スクロール駆動アニメーションでは、ブラウザがスクロールの位置をそのままアニメーションの進み具合として使います。`opacity` や `translate` のような合成だけで済むプロパティなら、メインスレッドが忙しいときにもスクロールに追従しやすくなります（「[18-10 動きの負荷を抑える](/motion/performance/)」）。`IntersectionObserver` も、交差したときにだけコールバックが呼ばれるので、スクロールのたびに位置を読む必要がありません。

## スクロール駆動アニメーションで値を連続して変える

スクロール駆動アニメーションは、`animation-timeline` に時間の代わりのタイムラインを指定する仕組みです。`scroll()` はスクロールコンテナのスクロール量を、`view()` は要素がスクロールポートのどこにあるかを、進み具合として使います。時間で進まないので、`animation-duration` は指定しません。進み具合とスクロール位置を比例させるために、`animation-timing-function` には `linear` を指定します。

<Baseline id="scroll-driven-animations" />

Firefoxはスクロール駆動アニメーションに対応していません。対応していない環境では `animation-timeline` が無視され、時間で進む普通のアニメーションとして扱われます。再生時間が0なので、一瞬で終わった状態になります。そこで、`@supports` で対応している環境に限って指定します。

`@supports` の条件には、`animation-timeline` だけでなく `animation-range` も加えます。2つに別々の版で対応したブラウザはありません（MDNのブラウザ互換性データで確認）。しかし、2つは別々のプロパティなので、`animation-timeline` にだけ対応した実装があれば、範囲の指定が無視されてタイムラインの全体で動き、見せたいタイミングとずれます。条件には、実際に使う値を書きます。`view()` のタイムラインなら `(animation-timeline: view()) and (animation-range: entry)` です。`scroll()` のタイムラインで長さの範囲を使うなら、`(animation-timeline: scroll()) and (animation-range: 0 80px)` と書きます。

次の例は、ページを80pxスクロールするまでの間に、ヘッダーの背景をフェードインさせます。背景は擬似要素に描き、その `opacity` をスクロール量に合わせて変えます。ヘッダーは、ビューポートの高さが十分なときだけ固定します（「[11-7 固定ヘッダー](/layout-practice/sticky-header/)」）。

```css title="🙆‍♂ Recommended: スクロールした量に合わせて、ヘッダーの背景を表示する" from="motion/scroll-header"
@scope (.scoped.site-header) to (.scoped) {
  :scope {
    z-index: var(--z--header);
    isolation: isolate;

    @media (height >= calc(600 / 16 * 1rem)) {
      position: sticky;
      inset-block-start: 0;
    }

    &::after {
      content: "";
      position: absolute;
      inset: 0;
      z-index: var(--z--backwards);
      background-color: var(--background--base);

      @supports (animation-timeline: scroll()) and (animation-range: 0 80px) {
        animation-name: --fade-in;
        animation-timing-function: linear;
        animation-fill-mode: both;
        animation-timeline: scroll();
        animation-range: 0 80px;
      }
    }
  }
}
```

`animation-range` を指定しない（`normal`）と、範囲はタイムラインの全体になります。`scroll()` ではページの先頭から末尾まで、`view()` では要素が画面に入り始めてから出終わるまで（`cover`）です。見せたいタイミングとずれやすいので、範囲は明示します。上の例では長さで範囲を指定し、80pxスクロールしたところで背景が表示されきります。範囲を過ぎたあとも背景を残すために、`animation-fill-mode: both` を指定しています。指定しないと、範囲の外ではアニメーションが当たらず、もとの見た目に戻ります。

次のデモでは、枠の中をスクロールすると、80pxまでの間にヘッダーの背景が現れ、上へ戻すと薄くなります。スクロール駆動アニメーションに対応していない環境では、アニメーションが当たらないので、背景は最初から表示されています。

<Demo title="スクロールした量に合わせて、ヘッダーの背景をフェードインする" html={headerHtml} css={headerCss} frame={headerFrame} scheme="light" height="640px" />

`view()` では、範囲を名前で指定できます。`entry` は要素が画面に入る間、`exit` は出ていく間、`contain` は要素の全体が画面に収まっている間（要素が画面より高いときは、要素が画面を覆っている間）です。`animation-range: entry 0% entry 100%` のように、名前と割合を組み合わせて細かく絞ることもできます。範囲を絞ると、その前後にアニメーションの当たらない区間ができるので、ここでも `animation-fill-mode: both` を指定します。

次の例は、ヒーローの背景をパララックスで動かします。要素が画面に入り始めてから出終わるまでの全体を使うので、範囲は `cover` です。既定の範囲と同じでも、意図を示すために書いておきます。

```css title="🙆‍♂ Recommended: スクロール駆動アニメーションを、対応した環境でだけ動かす"
@keyframes --hero--parallax {
  from {
    translate: 0 -80px;
  }

  to {
    translate: 0 80px;
  }
}

@scope (.scoped.hero) to (.scoped) {
  ._background {
    @supports (animation-timeline: view()) and (animation-range: cover) {
      @media (prefers-reduced-motion: no-preference) {
        animation-name: --hero--parallax;
        animation-timing-function: linear;
        animation-fill-mode: both;
        animation-timeline: view();
        animation-range: cover;
      }
    }
  }
}
```

2つの例で、動きを減らす設定への扱いが違います。ヘッダーの背景はフェードだけなので、条件の外に書いています。パララックスは、スクロールに合わせて要素を移動させる大きな変動にあたるので、`no-preference` の中でだけ指定し、設定があるときは無効化します。判断の4段階は「[18-2 動きを減らす設定に対応する](/motion/reduced-motion/)」で説明しています。

## 画面に入ったら1回だけ再生する

画面に入った時点で1回だけ再生する演出は、CSSだけで作れます。スクロール駆動アニメーションは「画面に入った」ことを知らせるきっかけにだけ使い、見た目の変化は時間で進む普通のアニメーションで再生します。スクロール駆動アニメーションで `opacity` を直接動かすと、進み具合がスクロールの位置で決まるので、スクロールを止めた位置で表示が途中のまま残り、スクロールの速さで動きの速さも変わるからです。

きっかけには、カスタムプロパティを使います。ルートの `view()` のタイムラインで `--_in-view` を `--false` から `--true` に切り替えます。子は、一時停止したアニメーションを `@container style(--_in-view: --true)` の中で再生します。

```css title="🙆‍♂ Recommended: view() のタイムラインで切り替えた値を、スタイルクエリで問い合わせて再生する" from="motion/reveal-on-view"
@keyframes --reveal-card--in-view {
  from {
    --_in-view: --false;
  }

  to {
    --_in-view: --true;
  }
}

@scope (.scoped.reveal-card) to (.scoped) {
  :scope {
    --_in-view: --false;

    @supports (animation-timeline: view()) and (animation-range: entry) {
      animation-name: --reveal-card--in-view;
      animation-timing-function: linear;
      animation-fill-mode: both;
      animation-timeline: view();
      animation-range: entry 0% entry 60%;
    }
  }

  ._body {
    --translate-from--y-value: 24px;

    @media screen {
      @supports (animation-timeline: view()) and (animation-range: entry) {
        animation-name: --fade-in;
        animation-duration: var(--duration--reveal);
        animation-timing-function: var(--ease--out-quint);
        animation-fill-mode: both;
        animation-play-state: paused;

        @container style(--_in-view: --true) {
          animation-play-state: running;
        }

        @media (prefers-reduced-motion: no-preference) {
          animation-name: --fade-in, --translate-from;
        }
      }
    }
  }
}
```

<Demo title="画面に入ったカードが、1回だけフェードインする" html={revealHtml} css={revealCss} frame={revealFrame} height="360px" />

デモの枠の中を下へスクロールすると、3枚のカードが画面に入ったところで1枚ずつ現れます。上へ戻してからもう一度スクロールしても、再生を終えたカードは表示されたままです。スクロール駆動アニメーションに対応していない環境と印刷では、カードは最初から表示されています。

ルートは、`view()` のタイムラインで自分の位置を測るだけで、自分は動きません。`--_in-view` は `@property` で登録していないので、キーフレームの間を補間できず、進み具合の50%の時点で `--false` から `--true` に切り替わります（CSS Custom Properties Level 1）。`linear` を指定しているので、切り替わるのは範囲のちょうど中間です。この例の範囲は `entry 0%` から `entry 60%` なので、`entry` の範囲の30%の位置で `--true` になります。このデモのように要素が表示領域より小さい場合は、要素の30%が画面に入った位置です。要素が表示領域より大きい場合は、`entry` の範囲は要素が表示領域を覆った時点で終わるので、表示領域の高さの30%まで入った位置になり、要素全体の30%ではありません（Scroll-driven Animations）。`animation-fill-mode: both` を指定しているので、範囲を過ぎたあとも `--true` のまま残ります。

子の `._body` は、`animation-play-state: paused` で止めているので、`@keyframes` の `from` の見た目のまま待機します。遅延のないアニメーションは、止めている間も時刻0の最初のフレームが当たるからです。`animation-fill-mode: both` は、再生を終えたあとに最後のフレームを保つために書いています。`--_in-view` が `--true` になると、`@container style()` の中の `running` が当てはまり、アニメーションが最後まで再生されます。`opacity: 0` を別に書かないので、開始の見た目を変えたいときは、`@keyframes` に渡すカスタムプロパティだけを変えればすみます。再生時間の `--duration--reveal`（600ms）は、機能的な動きの上限（300ms）を超えます。ページを読み進める間に一度だけ再生する、頻度の低い装飾なので、例外として扱います。

`@container style()` は、名前を指定しなければ、いちばん近い祖先の要素の値を問い合わせます。要素は自分自身の値を問い合わせられないので、値を切り替える要素（ルート）と、再生する要素（`._body`）を分けています。`--fade-in` と `--translate-from` はサイト全体で使う `@keyframes` で、定義は「[18-6 @keyframesを設計する](/motion/keyframes/)」で説明しています。一方、`--_in-view` はコンポーネントの内部用のカスタムプロパティなので、それを切り替える `@keyframes` には、コンポーネントの名前を付けます。

### スクロールを戻したときと、対応していない環境

範囲より手前までスクロールを戻すと、`--_in-view` は `--false` に戻り、`._body` のアニメーションは再び一時停止します。再生を終えていれば、見た目は終わった状態のまま変わりません。しかし、再生の途中で戻すと、その位置で止まり、巻き戻りません。次に範囲に入ると、止まった位置から再生を続けます。半透明のまま止まるのを避けたい場合は、次の `IntersectionObserver` の方法を使います。

待機させる `._body` の指定は、`@supports` に加えて `@media screen` で囲みます。印刷のようにスクロールしない媒体では、最初の画面より下の要素が画面に入ることがないので、待機の見た目のまま透明で印刷されるからです。

スクロール駆動アニメーションはChrome 115以降とSafari 26以降が対応し、Firefoxは対応していません。スタイルクエリは、Firefoxも151から使えます。`@supports` で囲まないと、Firefoxでは `animation-timeline` が無視され、ルートのアニメーションは再生時間が0の普通のアニメーションになります。読み込んだ直後から `--_in-view` が `--true` なので、`._body` のアニメーションは画面の外で再生を終えます。`@supports` で囲めば、Firefoxでは演出なしで最初から表示されます。

動きを減らす設定には、フェードだけで表示して対応しています。`--fade-in` は条件の外に書き、移動の `--translate-from` だけを `prefers-reduced-motion: no-preference` の中で加えます。フェードは、動きを減らす設定でも残してよい動きだからです（「[18-2 動きを減らす設定に対応する](/motion/reduced-motion/)」）。

### IntersectionObserver で属性を切り替える

Firefoxでも演出を出したいときと、スクロールを戻しても再生を途中で止めたくないときは、`IntersectionObserver` で属性を付けます。属性は、JavaScriptが外さない限り残るので、一度再生を始めたアニメーションは、スクロールの位置にかかわらず最後まで再生されます。

この方法でも、`animation-play-state: paused` と `animation-fill-mode: both` を組み合わせます。遅延のないアニメーションは、一時停止していても `from` のキーフレームが当たるので、要素は動き始める前の見た目で待機します。`both` は、再生を終えたあとの見た目を保つためのものです。要素が画面に入り、JavaScriptが `data-revealed` を付けたら、`animation-play-state: initial` で一時停止を取り消して再生します。

```css title="🙆‍♂ Recommended: 一時停止したアニメーションを、画面に入ったら再生する"
@scope (.scoped.feature-list) to (.scoped) {
  li {
    --translate-from--y-value: 24px;

    &:is(:scope[data-motion-mode="motion"] *) {
      @media screen and (prefers-reduced-motion: no-preference) and (scripting: enabled) {
        animation-name: --fade-in, --translate-from;
        animation-duration: var(--duration--reveal);
        animation-timing-function: var(--ease--out-quint);
        animation-fill-mode: both;
        animation-play-state: paused;
      }
    }

    &[data-revealed]:is(:scope[data-motion-mode="motion"] *) {
      animation-play-state: initial;
    }
  }
}
```

待機中の見た目は、CSSだけの方法と同じく `@keyframes` の `from` が決めています。

属性はJavaScriptで付けます。要素の10%が画面に入ったら `data-revealed` を付けます。`rootMargin` で判定の範囲を狭める方法は、ページの末尾にある小さな要素が範囲に入らず、透明のまま残ることがあるので使いません。`data-motion-mode` は、`IntersectionObserver` で監視を始めたあとに付けます。

```js title="画面に入った要素に data-revealed を付ける JavaScript の例"
const root = document.querySelector('.feature-list');
const reduced = window.matchMedia('(prefers-reduced-motion: reduce)').matches;

if (root && !reduced) {
  const observer = new IntersectionObserver(
    (entries) => {
      for (const entry of entries) {
        if (!entry.isIntersecting) continue;
        entry.target.setAttribute('data-revealed', '');
        observer.unobserve(entry.target);
      }
    },
    { threshold: 0.1 },
  );
  for (const item of root.querySelectorAll('li')) observer.observe(item);
}

// 監視を始めたあとで付ける。途中で処理が止まれば属性は付かず、内容は見えたまま
root?.setAttribute('data-motion-mode', reduced ? 'reduced' : 'motion');
```

待機の条件を `@media (scripting: enabled)` だけにすると、スクリプトの読み込みや初期化に失敗した環境で、要素が透明のまま止まります。この条件はJavaScriptが有効なことしか表さないからです。`data-motion-mode="motion"` は監視を始めたあとにしか付かないので、処理が途中で止まれば待機のスタイルは当たらず、内容はそのまま読めます。`scripting` メディア特性と、透明を戻す処理が動かないときの問題は、「[1-2 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」で説明しています。再生のセレクタにも同じ属性の条件を書くのは、待機の宣言より詳細度を高くして、確実に上書きするためです。

動きを減らす設定のときは、JavaScriptが `reduced` を付けて監視をしないので、要素は最初から表示されます。CSSの側も `no-preference` の条件で囲んでいるので、ページを開いたあとに設定を変えた場合も、待機のスタイルは外れます。演出を無効化せず、フェードだけに簡素化するなら、JavaScriptは設定にかかわらず監視して `motion` を付けます。CSSでは、移動の `--translate-from` だけを `no-preference` の中で追加します。

```css title="🙆‍♂ Recommended: 動きを減らす設定のときは、フェードだけで表示する"
@scope (.scoped.feature-list) to (.scoped) {
  li {
    --translate-from--y-value: 24px;

    &:is(:scope[data-motion-mode="motion"] *) {
      @media screen and (scripting: enabled) {
        animation-name: --fade-in;
        animation-duration: var(--duration--reveal);
        animation-timing-function: var(--ease--out-quint);
        animation-fill-mode: both;
        animation-play-state: paused;
      }

      @media screen and (prefers-reduced-motion: no-preference) and (scripting: enabled) {
        animation-name: --fade-in, --translate-from;
      }
    }

    &[data-revealed]:is(:scope[data-motion-mode="motion"] *) {
      animation-play-state: initial;
    }
  }
}
```

ここまでが、スクロールに合わせた動きを作るための基本の道筋です。続く2つの見出しは応用です。セクションを画面に留めて中の列を横に流す演出を作るときと、CSSだけでは作れない分岐をJavaScriptで制御するときに読んでください。

## 縦のスクロールで横に流れるセクション

縦にスクロールする間だけセクションを画面に留め、中の列を横に流す演出も、スクロール駆動アニメーションで作れます。セクションの高さを横に並んだ列の全体の幅と同じだけ取り、その高さをスクロールする間に、列を `translate` で左へ動かします。動く量はスクロールした量で決まるので、スクロールを止めれば列も止まり、上へ戻せば右へ戻ります。

この演出は、外側の `._body` と、列を横に並べた `ul` の2つの要素で作ります。`._body` には `view-timeline-name` でタイムラインの名前を付け、`min-block-size` に列の全体の幅を指定します。`ul` は `position: sticky` と `inset-block-start: 0` で画面の上端に留め、`animation-timeline` にそのタイムラインの名前を指定して動かします。`._body` が画面の上端を越えている間、`ul` は画面に留まったまま横へ動き、`._body` の下端が来ると一緒に上へ流れていきます。

```css title="🙆‍♂ Recommended: 縦のスクロールに合わせて、留めた列を横に動かす" from="motion/horizontal-pin"
@keyframes --translate-to {
  to {
    translate: var(--translate-to--x-value, 0) var(--translate-to--y-value, 0);
  }
}

@scope (.scoped.horizontal-pin) to (.scoped) {
  :scope {
    --_column-width: var(--horizontal-pin--column-width, min(calc(640 / 16 * 1rem), 100cqi));
    --_column-count: var(--horizontal-pin--column-count, 6);
    --_column-gap: var(--horizontal-pin--column-gap, 24px);
    --_scroller-width: calc(var(--_column-width) * var(--_column-count) + var(--_column-gap) * (var(--_column-count) - 1));

    container: --scoped / inline-size;
  }

  ._body {
    overflow-x: auto;
    overscroll-behavior-inline: contain;

    @supports (animation-timeline: view()) and (animation-range: contain) {
      @media screen and (prefers-reduced-motion: no-preference) {
        overflow: clip;
        min-block-size: var(--_scroller-width);
        view-timeline-name: --horizontal-pin;
      }
    }
  }

  ul {
    display: block grid;
    grid-auto-columns: var(--_column-width);
    grid-auto-flow: column;
    column-gap: var(--_column-gap);

    @supports (animation-timeline: view()) and (animation-range: contain) {
      @media screen and (prefers-reduced-motion: no-preference) {
        --translate-to--x-value: calc(-100% + 100cqi);

        position: sticky;
        inset-block-start: 0;
        align-content: center;
        min-inline-size: var(--_scroller-width);
        min-block-size: 100svb;
        animation-name: --translate-to;
        animation-timing-function: linear;
        animation-fill-mode: both;
        animation-timeline: --horizontal-pin;
        animation-range: contain 0% contain 100%;
      }
    }
  }
}
```

範囲の `contain 0% contain 100%` は、要素が画面より高いときは、要素の上端が画面の上端に達してから、下端が画面の下端に達するまでを表します。これは `ul` が画面に留まっている間と同じなので、列は、留まり始めた位置から動き始め、ページとともに流れ出す直前で止まります。移動の量は `calc(-100% + 100cqi)` です。`translate` の `%` は要素自身の幅が基準なので、列の全体の幅からルートのコンテナの幅を引いた分だけ左へ動き、最後の列がコンテナの右端にそろって止まります。`._body` の高さを列の全体の幅にしているので、縦にスクロールする量と横に動く量は、画面の高さとコンテナの幅の差の分だけずれますが、ほぼ対応します。

`--translate-to` は、「[18-6 @keyframesを設計する](/motion/keyframes/)」のサイト全体で使う `--translate-from` と対になる `@keyframes` です。`translate` だけを変え、`from` を省いて、もとの位置から `--translate-to--x-value` で渡した位置まで動かします。中間のフレームも、同時に動かすほかのプロパティもないので、コンポーネントの名前は付けず、`base/keyframes.css` に置きます。

列は画面より広いので、`._body` ではみ出しを切り取ります。ここで `overflow: hidden` を使うと、`._body` がスクロールコンテナになり、`ul` が留まる基準は、ページではなく `._body` になります。`._body` は中身の高さまで伸びていてスクロールしないので、列は留まらずにページと一緒に流れていきます。`overflow: clip` はスクロールコンテナを作らないので、`sticky` の基準をページのスクロールに保ったまま、はみ出しだけを切り取れます。`contain: paint` でも切り取れますが、中の `position: fixed` の基準を変えてしまうので使いません（「[11-4 はみ出しとスクロール](/layout-practice/overflow/)」）。

`ul` の高さは `min-block-size: 100svb` で、画面の高さを最小値にしています。コンポーネントの中でビューポート単位を使うのは例外ですが、この列は `sticky` で画面に留めるので、高さの基準も画面です。`dvb` を使うと、スクロール中にブラウザのUIが出入りするたびに高さが変わり、留めた列が上下にずれます（「[6-2 ビューポート単位とコンテナ単位](/values/viewport-and-container-units/)」）。

留める指定と動かす指定は、どちらも `@supports` と `screen and (prefers-reduced-motion: no-preference)` の中にまとめます。スクロールに合わせた横の移動は、画面の大部分を占める要素の移動なので、大きな変動にあたります（「[18-2 動きを減らす設定に対応する](/motion/reduced-motion/)」）。条件に合わないときは、`._body` が `overflow-x: auto` で横スクロールの領域となり、列を指やスクロールバーで動かして見ます。`sticky` と `._body` の高さを条件の外で指定すると、動かない環境では、列の先頭だけが留まって見えたまま、列の幅の分だけ縦のスクロールが続き、後ろの列を見る手段がなくなります。

列の画像には、フォーカスできる要素がありません。キーボードでもスクロールできるよう、`._body` へ3つの属性を付けます。`role="region"`、`tabindex="0"`、区画の見出しを指す `aria-labelledby` です（「[12-12 reel](/compositions/reel/#キーボードで操作できるようにする)」）。留めて動かしている間も `._body` はTabキーで止まりますが、名前を読み上げるだけで、操作の妨げにはなりません。印刷ではスクロールで列が動かないので、留める指定は `screen` に限り、印刷のときは `@media print` で列を縦に並べます。

<Demo title="縦のスクロールに合わせて、留めた画像の列が横に流れる" html={pinHtml} css={pinCss} frame={pinFrame} height="480px" />

デモの枠の中を下へスクロールすると、画像の列が枠の上端に留まり、右から左へ流れます。最後の画像が右端にそろうと、列は次の段落と一緒に上へ流れていきます。`--_column-count` は、列の数と一致させる必要があります。列の数を変えたら、`--horizontal-pin--column-count` に新しい数を渡します。

## JavaScriptで毎フレーム同期する場合

スクロールに合わせて段落を入れ替えながら進むような凝った演出は、CSSだけでは作れず、JavaScriptで制御することがあります。このときも、`scroll` イベントの処理の中でスタイルを書き換えません。イベントでは「位置が変わった」ことだけを記録し、`requestAnimationFrame` で描画の直前に1回だけ位置を読んで、スタイルを書き換えます。

今のブラウザでは、`scroll` イベント自体が描画のたびに1回ほどにまとめられるので、この書き方で処理の回数が大きく減るとは限りません。この書き方の目的は、読み取りと書き換えの順序を整えることです。位置を読む処理をまとめ、書き換える処理をそのあとにまとめれば、強制的なレイアウトの計算は、起きても最初の読み取りの1回で済みます。ただし、JavaScriptがメインスレッドで動く負担は残るので、CSSで作れる動きはCSSで作ります。

```js title="requestAnimationFrame で1フレームに1回だけ更新する JavaScript の例"
let ticking = false;

const update = () => {
  ticking = false;
  /* 位置を読む処理をまとめてから、スタイルを書き換える処理をまとめる */
};

window.addEventListener(
  'scroll',
  () => {
    if (ticking) return;
    ticking = true;
    requestAnimationFrame(update);
  },
  { passive: true },
);
```

演出のためのスタイル（要素を重ねる、最初は隠しておくなど）を常に当てておくと、JavaScriptが動かない環境で内容が読めなくなります。そこで、`IntersectionObserver` で1回だけ再生する演出と同じく、演出のためのスタイルは `data-motion-mode="motion"` のときだけ当てます。基本のスタイルは、JavaScriptがないときと動きを減らす設定のときの、最終的な状態として書きます。印刷ではスクロールで場面が切り替わらないので、演出のためのスタイルは `screen` に限ります。

```css title="🙆‍♂ Recommended: 演出のためのスタイルを、motion のときだけ当てる"
@scope (.scoped.story-section) to (.scoped) {
  ._steps {
    display: block grid;
    gap: 48px;

    &:is(:scope[data-motion-mode="motion"] *) {
      @media screen and (scripting: enabled) {
        grid-template-areas: "--step";
        gap: initial;

        & > ._step {
          grid-area: --step;
        }
      }
    }
  }

  ._step {
    &:is(:scope[data-motion-mode="motion"] *) {
      @media screen and (scripting: enabled) {
        opacity: 0;
      }
    }
  }
}
```

この例では、JavaScriptが動かなければ、段落は縦に並んで、すべて読めます。JavaScriptが準備を終えて `motion` を付けると、段落が同じ場所で重なり、スクロールに合わせて1つずつ表示されます。動きを減らす設定のときは `reduced` を付け、段落を重ねず、並べたままにします。どちらの状態でも、伝える情報は同じです。

## 補足と注意点

画面に入ったら1回だけ動かす演出も、CSSだけで書ける仕様が出てきています。`timeline-trigger` で「ビュー進行タイムラインのどの範囲に入ったか」を引き金として定義し、`animation-trigger` で、その引き金が引かれたときにアニメーションを再生します。スクロール駆動アニメーションと違い、再生はスクロール量に連動しないので、スクロールを戻しても逆再生されません。ただし、対応しているのはChrome系のブラウザ（Chrome 146以降）だけです。対応していない環境では `animation-trigger` が無視され、アニメーションは読み込んだ直後に画面の外で再生を終えます。そのため本書では、`view()` のタイムラインとスタイルクエリで再生を切り替える方法を基本とします。

動き始める前の要素を隠すのに、`visibility: hidden` や `display: none` を使わないでください。スクリーンリーダーで読めなくなったり、ページ内検索で見つからなくなったりします。`opacity` で透明にした要素は、見えなくても読み上げと検索の対象に残ります。

アニメーションは、略記の `animation` ではなく、ロングハンドで書きます。略記は `animation-timeline` と `animation-range` もリセットするので、略記をあとに書くと、先に指定したスクロール駆動の設定が消えます（「[18-6 @keyframesを設計する](/motion/keyframes/)」）。
