トランジションは `transition: all` を使わず、動かすプロパティだけをロングハンドで書き、再生時間とイージングにはトークンを使います。途中で取り消されることがある動きは、`@keyframes` ではなくトランジションで作ります。トランジションは、取り消された時点の状態から逆向きに戻るからです。タブのように続けて押されるUIでは、動きを短くするか省きます。

動きの手段は、トランジションを基本にし、要件に合わせて `@keyframes` と `@starting-style` を選びます。この節では、トランジションの書き方と、取り消される動きの扱い、手段の選び方を説明します。トランジションの応用は「[18-5 トランジションを応用する](/motion/transition-techniques/)」で、`@keyframes` の命名と設計は「[18-6 @keyframesを設計する](/motion/keyframes/)」で扱います。

## まとめて書いたトランジションの問題

`transition: all` は手軽ですが、関係のないプロパティまでアニメーションします。たとえば、ブレイクポイントをまたいで余白が変わったときや、ダークモードに切り替えたときにも、要素がゆっくりと変化します。動かす必要のないプロパティまで毎フレーム補間するので、描画の負荷も増えます。

```css title="🙅‍♂ Not Recommended: すべてのプロパティを対象にし、値を直接書く" issue="behavior"
/* 🙅‍♂ Not Recommended */
._card {
  transition: all 0.3s ease;
}
```

この書き方には、再生時間とイージングを直接書いている問題もあります。`0.3s` や `ease` がコンポーネントごとに散らばると、サイトの中で動きの速さと質感がそろいません。「全体をもう少し速くしたい」と思っても、すべてのファイルを探して書き換えることになります。

## トランジションをロングハンドとトークンで書く

トランジションは、`transition-duration`、`transition-property`、`transition-timing-function` のロングハンドで書きます。動かすプロパティが一目で分かり、再生時間とイージングにはトークンを渡せます。複数のプロパティを動かすときは、カンマ区切りで、プロパティごとにイージングを選び分けられます。

```css title="🙆‍♂ Recommended: 動かすプロパティを絞り、トークンで書く"
@scope (.scoped.menu-button) to (.scoped) {
  ._icon {
    color: var(--foreground--muted);

    @media (prefers-reduced-motion: no-preference) {
      transition-duration: var(--duration--base);
      transition-property: rotate, color;
      transition-timing-function: var(--ease--in-out-quint), var(--ease--out-quad);
    }

    &:is(:scope[aria-expanded="true"] *) {
      color: var(--foreground--accent);
      rotate: 0.5turn;
    }
  }
}
```

`transition-behavior: allow-discrete` も、略記の `transition` に含めず、ロングハンドで書きます。略記の値の中に解釈できないキーワードがあると、宣言全体が無効になります。`allow-discrete` を解釈できないブラウザでは、`display` だけでなく、`opacity` などのトランジションもまとめて失われます。ロングハンドなら、無効になるのは `transition-behavior` の宣言だけです。

この例では、メニューを開いたボタンのアイコンを半回転させ、色も変えています。回転は画面の上にあるものの動きなので `in-out` 系、色の変化は `out` 系のイージングを選んでいます。トランジションのプロパティを `prefers-reduced-motion: no-preference` の中に書いているのは、回転が動きを減らす設定で避けたい動きだからです。動きを減らす設定のときは、状態は変わっても、その途中は見せません（「[18-2 動きを減らす設定に対応する](/motion/reduced-motion/)」）。トークンの値と、イージングの選び方は「[18-3 イージングと再生時間](/motion/easing-and-duration/)」で説明しています。

動かすプロパティは、`opacity` と、`translate`、`scale`、`rotate` を優先します。これらは条件が合えば描画をやり直さずに合成だけで動かせるので、滑らかに動きます。`clip-path`、`background-color`、`filter` は、ブラウザと値によって扱いが変わります。Chromeでは、この3つのトランジションでフレームごとの描き直し（DevToolsのPaint）は起きませんでした。ただし、アニメーションの進行をコンポジタのスレッドで計算したのは、`clip-path`、`background-color` と、画素の位置を動かさない `filter` の関数だけです。`blur()` と `drop-shadow()` の進行は、メインスレッドで計算されました。{/* 要検証: ブラウザ。Firefox と Safari で、clip-path、background-color、filter のアニメーションに描き直しが起きるか、進行をどのスレッドで計算するか */}この例の `color` は描画のやり直しが必要ですが、小さな部品の状態の変化なら許容できます。どのプロパティがどの処理を起こすかは「[18-10 動きの負荷を抑える](/motion/performance/)」で説明しています。

`transition-property` に書いたプロパティは、状態の変化だけでなく、メディアクエリやコンテナクエリで値が切り替わったときにもアニメーションします。トランジションは、値がどの理由で変わったかを区別しないからです。Chromeで、幅のメディアクエリで `padding-inline` を、コンテナサイズクエリで `color` を切り替え、両方を `transition-property` に入れて確かめました。ビューポートの幅を変えると、どちらも動きました。

一方、読み込んだ直後の表示では、どちらも動きませんでした。最初のスタイルの計算には変化の前の値がないので、トランジションは起きません。ただし、読み込んだ後にコンテナの幅が変わる場合は、クエリが切り替わって動く可能性があります。{/* 要検証: ブラウザ。読み込み後にスクロールバーの出現などでコンテナの幅が変わったとき、コンテナクエリの切り替えでトランジションが起きるか。Firefox と Safari での挙動 */}

そのため、`transition-property` には、状態の変化で変えるプロパティだけを書き、クエリで切り替えるプロパティは入れません。上の例なら、状態で変えるのは `rotate` と `color` で、余白や大きさはクエリに任せ、トランジションの対象から外します。同じプロパティを状態とクエリの両方で変えるなら、トランジションを状態のセレクタの側にだけ書く方法があります。動くのは状態に入るときだけで、状態から外れるときと、状態の外でクエリが切り替わったときは、すぐに値が変わります。{/* 要確認: 出典なし。クエリで切り替える値をトランジションの対象から外す方針と、状態のセレクタの側にだけ書く対処 */}

トランジションは、変化したあとの状態のルールに書いた再生時間とイージングで動きます。この性質を使って、入るときと外れるときで再生時間を変える書き方は「[18-5 トランジションを応用する](/motion/transition-techniques/)」で説明しています。

## 途中で取り消される動き

UIの動きは、最後まで再生されるとは限りません。ホバーした直後にポインターが離れる、開いたダイアログをすぐに閉じる、といった操作は日常的に起こります。動きの手段によって、取り消されたときの振る舞いが違うので、次の表のように、起こりうる操作から手段を選びます。

| 操作 | 望ましい振る舞い | 手段 |
| --- | --- | --- |
| ホバーしてすぐに外す | 途中の状態から逆向きに戻る | トランジションなら自動 |
| ダイアログを開いてすぐに閉じる | 途中の状態から閉じる動きに移る | `@starting-style` とトランジションなら自動。`@keyframes` ではJavaScriptでの制御が必要 |
| タブを続けて押す | 短い動きで切り替えるか、動きを省く | 再生時間を80〜160msにしたトランジション。View Transitionsなら、新しい切り替えが前の切り替えを自動で打ち切る |
| スクロールの方向が急に変わる | 今の位置から新しい方向に追従する | スクロール駆動アニメーションなら自動 |

トランジションは、値が変わった時点の状態を起点に、新しい値へ向かって動きます。途中で元の状態に戻されれば、その位置から逆向きに戻るので、値は飛びません。一方、`@keyframes` のアニメーションは、適用が外れた瞬間に要素本来の値へ切り替わり、逆向きの動きもありません。そのため、取り消されることがある動きはトランジションで作ります。

`@keyframes` で作った動きを途中で取り消すには、JavaScriptのWeb Animations APIで、今の位置から逆向きに再生し直す制御が要ります（「[18-6 @keyframesを設計する](/motion/keyframes/#keyframes-の再生をjavascriptで制御する)」）。退場も動かすダイアログやポップオーバーなら、`@starting-style` とトランジションを使えばCSSだけで済むので、「[18-7 出現と退場](/motion/entry-and-exit/)」の方法で作ります。

タブやセグメンテッドコントロールのように続けて押されるUIでは、動きが操作に追いつかないことがあります。こうしたUIでは、再生時間を `--duration--fast`（80ms）から `--duration--base`（160ms）までに短くするか、動きを省きます。ページの中の切り替えにView Transitionsを使うときは、新しい切り替えを始めると、前の切り替えは残りの動きを飛ばして自動で終わります。前の切り替えを待たずに次の状態へ移れるので、続けて押されても動きは重なりません（「[18-11 View Transitionsで画面の切り替えをつなぐ](/motion/view-transitions/)」）。

## `@keyframes`、トランジション、`@starting-style` の使い分け

手段は次の表のように選びます。基本はトランジションです。状態に入るときと外れるときの両方が動き、途中で取り消されても自然に戻ります。`@keyframes` は、出現だけを動かす場合、中間のフレームが要る場合、再生を止めておく場合に使います。

| 要件 | 手段 |
| --- | --- |
| `display: none` から現れ、消えるときも動かしたい | トランジションと `@starting-style`、`transition-behavior: allow-discrete` |
| 現れるときだけ動かし、消えるときはすぐでよい | `@keyframes` |
| 中間のフレーム（`25%`、`50%` など）が要る | `@keyframes` |
| JavaScriptから一時停止、逆再生、取り消しをしたい | Web Animations API |
| 途中で取り消されることが多い | トランジション |
| 複数のプロパティを時間をずらして動かしたい | `@keyframes`、または `transition-delay` の組み合わせ |
| 画面に入るまで止めておき、入ったら一度だけ再生する | `@keyframes` と `animation-play-state` |

`@keyframes` を使うと決めたあとの命名、置き場所、起点の渡し方は「[18-6 @keyframesを設計する](/motion/keyframes/)」で説明しています。`@starting-style` は、要素が表示されたときの開始値を指定する規則で、`display: none` から表示された要素もトランジションで動かせます。出現と退場の書き方と、`@starting-style` の値が開始値にならない条件は「[18-7 出現と退場](/motion/entry-and-exit/)」で説明しています。
