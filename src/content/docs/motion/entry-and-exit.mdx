`display: none` から表示する要素の出現と退場は、`@starting-style` と `transition-behavior: allow-discrete` で動かします。表示された瞬間の見た目を `@starting-style` で指定し、`display` と `overlay` をトランジションの対象に加えれば、ポップオーバーやダイアログの開閉の両方をCSSだけで動かせます。`@starting-style` の宣言は通常のカスケードで競うので、元の規則の中に書きます。退場を動かす必要がなければ、`@keyframes` の `from` で出現だけを動かすほうが、開始値がほかの規則で上書きされずに済みます。

DOMに追加した要素も `@starting-style` の値から動き始めますが、`remove()` で削除した要素の退場はCSSだけでは動かせません。`<details>` の開閉は、`::details-content` の高さと不透明度をトランジションで動かします。ページの上に重ねて出すパネル、要素をずらして出す演出、ツールチップの表示の遅延は、「[18-8 重ねて出すパネルと順に出す要素](/motion/overlays-and-stagger/)」で扱います。

## `display: none` の要素は現れる瞬間を動かせない

`display: none` の要素には、ボックスがありません。表示に切り替わった瞬間、ブラウザは最終的なスタイルでボックスを作るので、トランジションの開始値になる「直前の見た目」が存在しません。`opacity` を0から1へ動かすつもりで書いても、要素は最初から `opacity: 1` で現れます。

退場にも別の問題があります。`display` は途中の値を持たないプロパティなので、閉じた瞬間に `none` へ切り替わり、`opacity` を下げるトランジションが始まる前に要素が消えます。ポップオーバーやモーダルのダイアログはトップレイヤーに表示されますが、閉じた瞬間にトップレイヤーからも外れるので、消えていく途中の姿をほかの要素の上に残せません。

これまでは、JavaScriptでクラスを付けるタイミングを調整していました。表示したあとに1フレーム待ってから「開いた」クラスを付け、閉じるときは `transitionend` イベントを待ってから `display: none` に戻す、といった方法です。開閉を素早く繰り返すと、クラスの状態とアニメーションがずれやすい方法でした。

## `@starting-style` で表示された瞬間の見た目を決める

`@starting-style` は、要素が表示された最初のフレームで使う、トランジションの開始値を指定する規則です。この値から通常のスタイルの値へトランジションが起きるので、出現を動かせます。`@starting-style` は、開いた状態のセレクタの中に書きます。

退場は、`transition-behavior: allow-discrete` で動かします。この指定は、`display` のように途中の値がないプロパティもトランジションの対象にするものです。`transition-property` に `display` を加えると、閉じるときは `opacity` と `scale` の変化が終わるまで `display: none` への切り替えが待たされます。`overlay` も加えると、閉じる途中の要素がトップレイヤーに残ります。

```css title="🙆‍♂ Recommended: 開いた瞬間の見た目を @starting-style で指定する" from="motion/popover-entry"
@scope (.scoped.notice) to (.scoped) {
  :scope {
    --_scale-from: 1;

    z-index: var(--z--top);
    transform-origin: 50% 100%;
    transition-duration: var(--duration--base);
    transition-property: opacity, scale, display, overlay;
    transition-timing-function: var(--ease--out-quint);
    transition-behavior: allow-discrete;

    @media (prefers-reduced-motion: no-preference) {
      --_scale-from: 0.96;
    }

    &:popover-open {
      @starting-style {
        opacity: 0;
        scale: var(--_scale-from);
      }
    }

    &:not(:popover-open) {
      opacity: 0;
      scale: var(--_scale-from);
    }
  }
}
```

閉じた状態（`:not(:popover-open)`）の値は、退場の終了地点になります。開いた状態の `@starting-style` の値は出現の開始地点なので、2つを同じ値にすると、現れるときと消えるときが同じ経路をたどります。イージングは、開閉のどちらも `--ease--out-quint` です。退場でも、操作の直後に大きく変化してから落ち着くほうが、操作への反応が速く見えます。

拡大の起点は、0.95〜0.98の範囲にします。`scale: 0` から広がる動きは、何もない点から要素が生まれるように見えて不自然です。`transform-origin` はトリガーのある側に向けます。この例のパネルは画面の下端に固定して表示するので、下端を起点にしています。起点の値と向きの決め方は、「[18-3 イージングと再生時間](/motion/easing-and-duration/)」で説明しています。

動きを減らす設定のときは、拡大の起点を1にして、フェードだけを残します。「[18-2 動きを減らす設定に対応する](/motion/reduced-motion/)」の4段階のうちの「簡素化」です。ポップオーバーが一瞬で現れると何が起きたのか分かりにくいので、位置と大きさを変えないフェードは残します。次のデモで、ボタンを押して動きを確かめられます。「お知らせを表示する」を押すと、画面の下端に出るパネルが、下端を起点に96%の大きさから広がりながらフェードインします。「閉じる」を押すと、同じ動きを逆にたどって消えます。

Firefoxは `display: none` へのトランジションに対応していません。開くときは動きますが、閉じるときは一瞬で消えます。閉じる機能は損なわれないので、プログレッシブ・エンハンスメントとして許容します。`overlay` に対応しているのはChrome系のブラウザだけなので、閉じる途中でほかの要素の下に潜り込まないように、`z-index: var(--z--top)` も指定しておきます（「[10-2 コンポーネントの境界を守る](/components/boundaries/)」）。

## `@starting-style` とカスケード

`@starting-style` の中の宣言は、特別に優先されるわけではありません。通常のカスケードでほかの規則と競い合い、同じ要素の同じプロパティに詳細度の高い規則やインラインスタイルが値を指定していると、そちらが勝って開始値になりません。開始値と最終的な値が同じになるので、トランジションは起きません。

`@starting-style` そのものは詳細度を持たず、中の宣言は、囲んでいるセレクタの詳細度で比べられます。開いた状態のセレクタの中に書けば元の規則と同じ詳細度になり、後に書いた `@starting-style` がソース順で優先されます。元の規則から離して別のセレクタで書くと、そのセレクタの詳細度で比べられるので、より詳細度の高い規則に開始値を上書きされることがあります。

開始値が使われないときに、`!important` や詳細度を上げるセレクタで解決しようとすると、ほかの状態のスタイルまで上書きしてしまいます。競合している規則を見つけ、`@starting-style` を元の規則の中に移すほうが確実です。詳細度の設計は「[4-2 セレクタで詳細度を設計する](/cascade/selectors/)」で説明しています。

出現だけを動かせば足りるなら、`@keyframes` の `from` を使うほうが安全です。アニメーションの値は、通常の宣言よりカスケードで優先されるので、ほかの規則に開始値を上書きされません。退場も動かしたいとき、つまり `display: none` へ戻る動きまで扱うときに、`@starting-style` を使います。

```css title="🙆‍♂ Recommended: 出現だけを @keyframes で動かす"
@scope (.scoped.toast) to (.scoped) {
  :scope {
    animation-name: --fade-in;
    animation-duration: var(--duration--base);
    animation-timing-function: var(--ease--out-quint);
    animation-fill-mode: both;
  }
}
```

この例の `--fade-in` は、ベーススタイルに置いたグローバルな `@keyframes` です（「[18-6 @keyframesを設計する](/motion/keyframes/)」）。位置と大きさを変えないフェードなので、動きを減らす設定の条件の外に書いています。

この例は、取り消されることがある動きをトランジションで書くルール（[`interruptible-with-transition`](/motion/transitions-and-keyframes/#rule-interruptible-with-transition)）と矛盾しません。トーストは出現だけを動かし、閉じるときは動かさず、即座に消します。出現の途中で閉じられても、アニメーションごと要素が消えるだけなので、キーフレームを逆向きに再生する必要はありません。トーストを続けて出したときも、アニメーションは新しく追加した要素や表示し直した要素で最初から始まるので、前のトーストの動きとは干渉しません。一方、トグルやパネルのように同じ要素を何度も開閉し、閉じるときも動かすUIは、取り消された位置から逆向きに戻れるトランジションで書きます。

## DOMに追加した要素と削除した要素

`@starting-style` の値が開始値になるのは、`display: none` から表示に切り替わったときだけではありません。JavaScriptの `append()` などでDOMに追加した要素も、最初のスタイル計算では直前の見た目を持たないので、`@starting-style` の値から動き始めます。追加する項目の基本のルールに書いておけば、状態のクラスを付け替えなくてもフェードインします。

```css title="🙆‍♂ Recommended: 追加した項目を @starting-style の値からフェードインさせる" from="motion/list-insert"
@scope (.scoped.invite-list) to (.scoped) {
  ._item {
    --_translate-from: 0;

    transition-duration: var(--duration--base);
    transition-property: opacity, translate;
    transition-timing-function: var(--ease--out-quint);

    @media (prefers-reduced-motion: no-preference) {
      --_translate-from: 0 8px;
    }

    @starting-style {
      opacity: 0;
      translate: var(--_translate-from);
    }
  }
}
```

退場は事情が違います。`remove()` で削除した要素は、その時点でDOMからなくなり、スタイルを計算する対象が残らないので、トランジションは起きず、その場で消えます。退場を動かす方法は2つあります。View Transitionsで削除の前後をつなぐ方法（「[18-11 View Transitionsで画面の切り替えをつなぐ](/motion/view-transitions/)」）と、JavaScriptで閉じた状態の属性を付け、退場のトランジションが終わってから削除する方法です。

次のデモで「メンバーを招待する」を押すと、追加した項目が8px下からフェードインします。「取り消す」を押した項目は、動かずにすぐ消えます。ページを読み込んだときにある項目も、最初のスタイル計算なので同じように動きます。

<Demo title="append() した項目を @starting-style でフェードインさせ、remove() した項目はすぐに消す" html={listInsertHtml} css={listInsertCss} frame={listInsertFrame} js={listInsertJs} height="20rem" />

追加と削除を動かすかどうかは、その一覧を操作する頻度で決めます。招待したメンバーのようにときどき増える一覧なら、出現を短く動かせます。ToDoのように1回の作業で何度も追加と削除を繰り返す一覧は、「[18-1 動かすかどうかを決める](/motion/purpose/)」の頻度の目安に従い、動かさないか最小限にします。

## ダイアログの開閉を動かす

ダイアログも、ポップオーバーと同じ方法で動かします。`display` と `overlay` を `transition-behavior: allow-discrete` でトランジションの対象にし、開いたときの開始地点を `@starting-style` で指定します。背景の `::backdrop` にも同じ開始地点と終了地点を指定します。

```css title="🙆‍♂ Recommended: ダイアログと背景をフェードさせる"
@scope (.scoped.site-dialog) to (.scoped) {
  :scope {
    position: fixed;
    inset: 0;
    z-index: var(--z--top);
    transition-duration: var(--duration--slow);
    transition-property: display, overlay, opacity;
    transition-timing-function: var(--ease--out-quint);
    transition-behavior: allow-discrete;

    &::backdrop {
      transition-duration: inherit;
      transition-property: opacity;
      transition-timing-function: inherit;
    }

    &:modal,
    &:modal::backdrop {
      @starting-style {
        opacity: 0;
      }
    }

    &:not(:modal),
    &:not(:modal)::backdrop {
      opacity: 0;
    }
  }
}
```

開くときと閉じるときのイージングが同じなので、基本のルールに1回だけ書けば足ります。トランジションは変化したあとの状態のルールの値で動くので、方向ごとに変える場合だけ、開いた状態のルールにも書きます。背景は、ダイアログの再生時間とイージングを `inherit` で受け取るので、ダイアログと同じ動きになります。

この例では、ダイアログと背景を不透明度だけで変化させています。画面の大部分を覆うUIが一瞬で現れると、何が起きたのか分かりにくくなるからです。位置と大きさを変えないフェードなので、動きを減らす設定でも条件の外に置いて残します。大きなUIの出現を、動きを減らす設定でフェードだけにする「簡素化」を、最初からフェードだけで作った形です。拡大を加えるなら、ダイアログの起点は0.85〜0.92にし、ポップオーバーの例と同じく拡大の起点だけを `no-preference` の中で変えます。

`position: fixed` と `inset: 0` は、Safariで表示が崩れる不具合（2025年5月の時点で確認されていたもの）を避けるために明示しています。モーダルを開いている間の背面の固定は「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」で、`z-index` のトークンは「[10-2 コンポーネントの境界を守る](/components/boundaries/)」で説明しています。ダイアログを開閉するHTMLは「[17-6 開閉するUI](/interaction/disclosure/)」にあります。

## `<details>` の開閉を動かす

`<details>` の開閉する部分は、`::details-content` 擬似要素で選べます。以前は、余白を付けたり高さを動かしたりするために、中身を `div` で包む必要がありました。`::details-content` を使えば包む要素は要らず、閉じる動きまでCSSだけで書けます。

```css title="🙆‍♂ Recommended: 開閉する部分の高さと不透明度を動かす" from="motion/details-accordion"
@scope (.scoped.faq-accordion) to (.scoped) {
  details {
    &::details-content {
      overflow: clip;

      @media (prefers-reduced-motion: no-preference) {
        transition-duration: var(--duration--slow);
        transition-property: content-visibility, block-size, opacity;
        transition-timing-function: var(--ease--out-quint);
        transition-behavior: allow-discrete;
      }
    }

    &:not([open])::details-content {
      block-size: 0;
      opacity: 0;
    }
  }
}
```

高さと不透明度は閉じているとき（`:not([open])`）だけ0にするので、開いているときに初期値の `auto` と `1` を書き直す必要はありません。閉じた `<details>` の中身は、`content-visibility: hidden` で隠されます。`content-visibility` を `allow-discrete` でトランジションの対象にすると、閉じるときも、高さと不透明度が変わり終わるまで中身が表示されたままになります。

`block-size: 0` から `auto` への変化は、`interpolate-size: allow-keywords` があるときに限って補間されます。本書ではこの指定を、動きを減らす設定がないときだけ、ベーススタイルで `:root` に書いています（「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」）。開閉を示す矢印の回転も、回転は「大きな変動」にあたるので `no-preference` の中に書きます。次のデモでは、`name` 属性で同時に1つだけを開くようにしています。質問を押すと、答えの高さと不透明度が変わりながら開き、右端の矢印が回転します。別の質問を開くと、開いていた質問は同じ動きで閉じます。

`interpolate-size` に対応しているのは、Chrome系のブラウザだけです。ほかのブラウザでは高さが一瞬で切り替わり、開くときは不透明度だけが変化します。Firefoxは `content-visibility` のトランジションに対応していないので、閉じるときは一瞬で消えます。どちらの場合も、開閉の機能は損なわれません。高さを動かすとレイアウトの計算が毎フレーム起きますが、アコーディオンでは開閉の位置関係を伝えるために許容します。レイアウトを起こす動きの負荷は、「[18-10 動きの負荷を抑える](/motion/performance/)」で説明しています。

高さを補間する方法には、`calc-size()` もあります。`block-size: calc-size(auto, size)` のように、補間したい宣言ごとに書く関数です。対応しているのは、`interpolate-size` と同じくChrome系のブラウザだけです。未対応の環境では宣言ごと無視されるので、多くの場合は直前に普通の値を書いて保険にします。`:root` に一度書けば済む `interpolate-size` より記述が増えるので、本書は現状では採用していません。

<Baseline id="calc-size" />

SafariとFirefoxでも高さを動かすよう求められた場合に限り、`::details-content` をグリッドにして、`grid-template-rows` を `0fr` と `1fr` で切り替えます。`fr` の値は、`interpolate-size` がなくても補間されます。この方法では、行の高さを0まで縮めるために、中身を1つの要素で包みます。

```html title="中身を1つの要素で包む HTML の例"
<details name="faq-accordion">
  <summary>注文をキャンセルできますか？</summary>
  <div class="_answer">
    <p>発送の準備が始まる前であれば、マイページの注文履歴からキャンセルできます。</p>
  </div>
</details>
```

```css title="🙆‍♂ Recommended: grid-template-rows で高さを動かす"
@scope (.scoped.faq-accordion) to (.scoped) {
  details {
    &::details-content {
      display: block grid;
      grid-template-rows: 1fr;

      @media (prefers-reduced-motion: no-preference) {
        transition-duration: var(--duration--slow);
        transition-property: content-visibility, grid-template-rows, opacity;
        transition-timing-function: var(--ease--out-quint);
        transition-behavior: allow-discrete;
      }
    }

    &:not([open])::details-content {
      grid-template-rows: 0fr;
      opacity: 0;
    }
  }

  ._answer {
    overflow: hidden;
  }
}
```

グリッドアイテムの最小の高さは、デフォルトでは中身の高さになり、行を `0fr` にしても中身の高さより縮みません。`._answer` に `overflow: hidden` を指定すると、アイテムがスクロールコンテナになって最小の高さが0になり、行と一緒に縮みます。はみ出した中身の切り取りも、この指定で済みます。本書では切り取りに `clip` を優先しますが、この場面はスクロールコンテナになることが目的に合っている例外です（「[11-4 はみ出しとスクロール](/layout-practice/overflow/#overflow-hidden-を使う場面)」）。Firefoxは、`content-visibility` のトランジションにも対応していないので、閉じる動きは一瞬です。包む要素が増えるので、私はこの方法を、すべてのブラウザで高さを動かす必要があるときだけ使っています。
