メガメニューのようにページの上に重ねて出すパネルは、高さを変えずに `clip-path: inset()` の切り抜きを動かして現し、閉じたら `visibility: hidden` で隠します。後ろの内容を押し下げないので高さを動かす理由がなく、切り抜きの変化ならレイアウトも起きません。

並んだ要素を少しずつずらして出す動きは、初回の案内のように頻度の低いUIに限り、`sibling-index()` で30〜80msの短い間隔を付けます。ツールチップは、初回の表示だけを300〜500ms遅らせ、続けて操作している間はすぐに表示します。どれも、出現と退場をトランジションや `@keyframes` で動かす書き方（「[18-7 出現と退場](/motion/entry-and-exit/)」）を、UIの置き方と見る頻度に合わせて調整したものです。

## 重ねて出すパネルを `clip-path` で現す

メガメニューやドロップダウンのパネルのように、ページの上に重ねて出すパネルは、高さではなく `clip-path: inset()` の切り抜きを動かして、上端から下へ巻き取るように現します。「[18-7 出現と退場](/motion/entry-and-exit/#details-の開閉を動かす)」の `<details>` のアコーディオンは、開いた分だけ後ろの内容を押し下げ、その動きで開閉の位置関係を伝えていました。重ねて出すパネルは後ろの内容を動かさないので、高さを動かす理由がありません。切り抜きを変えてもパネルの大きさは変わらないので、レイアウトは起きず、本文の位置もそのまま保たれます。

隠し方も、パネルの置き方で変わります。`popover` 属性のパネルは閉じると `display: none` になるので、18-7のポップオーバーやダイアログと同じく、`display` と `overlay` を `allow-discrete` でトランジションの対象にします。ただし、トップレイヤーに出すポップオーバーをヘッダーの下端に合わせて置くには、アンカー位置指定が要ります。アンカー位置指定はBaselineになっていないので、ここではパネルをヘッダーの中に絶対配置で置き、開閉の状態をボタンの `aria-expanded` で表します。この置き方では、閉じている間も `display` は変わらないので、`visibility: hidden` で隠します。

初期のHTMLでは、ボタンに `hidden` を付けて隠し、`aria-expanded` も書きません。パネルのリンクは通常の流れに並ぶので、スクリプトが動かない環境でもたどれます。初期化のスクリプトがボタンを出して `aria-expanded="false"` を付けたときだけ、パネルを重ねて置き、閉じた状態で隠します。初期のHTMLで内容を隠さず、操作の部品を後から出す考え方は、「[17-6 開閉するUI](/interaction/disclosure/)」のドロワーと同じです。

```css title="🙆‍♂ Recommended: 切り抜きを上端から広げ、閉じたパネルを visibility で隠す" from="motion/mega-menu-clip"
@scope (.scoped.mega-header) to (.scoped) {
  :scope {
    position: relative;

    & ._panel:is(._menu-button[aria-expanded] + *) {
      position: absolute;
      inset-inline: 0;
      inset-block-start: 100%;
    }
  }

  ._panel {
    --_clip-from: inset(0 -24px -24px);

    clip-path: inset(0 -24px -24px);
    box-shadow: var(--shadow--md);
    transition-duration: var(--duration--slow);
    transition-property: clip-path, opacity, visibility;
    transition-timing-function: var(--ease--out-quint);

    @media (prefers-reduced-motion: no-preference) {
      --_clip-from: inset(0 -24px 100%);
    }

    &:is(._menu-button[aria-expanded="false"] + *) {
      visibility: hidden;
      clip-path: var(--_clip-from);
      opacity: 0;
    }
  }
}
```

`inset()` は、上、右、下、左の順に、要素の各辺から内側へ切り取る量を指定する関数です。閉じた状態では下から100%を切り取るので、見える範囲は上端の高さ0の帯になり、開くと下の辺が下がって全体が見えます。左右と下を負の値にしているのは、`clip-path` が影まで含めて切り取るからです。開いた状態を `none` にしないのも、`none` と `inset()` の間は補間されず、一瞬で切り替わるからです。

絶対配置の基準はパネルの親の `li` ではなくヘッダーなので、`position: absolute` と `inset` は、基準になるヘッダーのルートのネストに `& ._panel` で書いています。

`clip-path` で見えなくしただけでは、パネルの中のリンクはフォーカスと読み上げの対象に残ります。Tabキーを押すと見えないリンクにフォーカスが移り、キーボードの利用者にはフォーカスが消えたように見えます。`visibility: hidden` を指定すると、中の要素はフォーカスを受け取らず、アクセシビリティツリーからも外れます（隠し方の比較は「[17-5 要素を隠す方法を選ぶ](/interaction/hiding-elements/)」）。

`visibility` は、`display` と違い、`allow-discrete` がなくてもトランジションの対象になります。`visibility` には途中の値の決め方が定められていて、片方の値が `visible` なら、トランジションの間はずっと `visible` として扱われるからです。開くときはトランジションの始まりと同時に `visible` へ切り替わり、閉じるときは切り抜きが閉じ終わるまで `visible` が続き、最後に `hidden` へ切り替わります。

動きの負荷は、高さを動かす方法より小さくなります。切り抜きを変えてもレイアウトは起きず、ブラウザと値によっては描き直しも避けられるからです（「[18-10 動きの負荷を抑える](/motion/performance/)」）。Chromeで、このデモのパネルを開くと、切り抜きのトランジションはコンポジタのスレッドで進み、動き出すときを除いて描き直しが起きないことを、パフォーマンスのトレースで確かめました。再生時間は、全幅のパネルが画面を大きく横切る動きなので、ダイアログと同じ `--duration--slow`（240ms）にします。{/* 要検証: ブラウザ。Firefox と Safari で、clip-path のトランジションで描き直しが起きるか、進行がコンポジタのスレッドに移るか */}

全幅のパネルの下端が画面を縦に横切る動きは、画面の3分の1以上の範囲で切り抜きを変えるので、18-2の目安では「大きな変動」にあたります。動きを減らす設定のときは、18-7のポップオーバーの例と同じく切り抜きを変えず、フェードだけを残します（「[18-2 動きを減らす設定に対応する](/motion/reduced-motion/)」の「簡素化」）。次のデモで「製品」を押すと、パネルがヘッダーの下端から下へ広がり、本文の上に重なります。本文の位置は変わりません。閉じた状態でTabキーを押すと、フォーカスは「製品」「料金」「サポート」から本文のリンクへ進み、パネルの中のリンクには移りません。開いた状態でEscキーを押すと、パネルが閉じてフォーカスは「製品」に戻ります。{/* 要検証: ブラウザ。デモの開閉の動き、負の値の inset() で影が切り取られないこと、閉じたパネルにフォーカスが移らないこと */}

## 頻度の低いUIで要素をずらして出す

並んだ要素を少しずつずらして出す動き（スタッガー）は、頻度の高いUIでは待ち時間を増やすだけです（「[18-1 動かすかどうかを決める](/motion/purpose/)」）。一方で、初回の案内や、LPで一度だけ開く一覧のように、まれにしか見ないUIでは、要素の並びの順番を伝える演出として使えます。このときも、ずらす間隔は30〜80msと短くし、全体が現れ終わるまでの時間を延ばしすぎないようにします。{/* 要確認: 出典なし。30〜80msという間隔 */}

ずらす量は、`sibling-index()` で要素の順番から計算します。`sibling-index()` は、兄弟の中で何番目かを1から数えた整数を返す関数です。順番から決める仕組みは「[5-4 子要素の位置で選ぶ](/pseudo/child-index/)」でも説明しています。動きそのものは、サイト全体で使う `--fade-in` と `--translate-from` を組み合わせ、移動の起点を `--translate-from--y-value` で渡しています（「[18-6 @keyframesを設計する](/motion/keyframes/)」）。

```css title="🙆‍♂ Recommended: 初回の案内の項目を、短い間隔でずらして出す" from="motion/stagger-steps"
@scope (.scoped.onboarding-steps) to (.scoped) {
  li {
    --_stagger: 50ms;
    --translate-from--y-value: 8px;

    @media (prefers-reduced-motion: no-preference) {
      animation-name: --fade-in, --translate-from;
      animation-duration: var(--duration--base);
      animation-timing-function: var(--ease--out-quint);
      animation-fill-mode: both;

      @supports (z-index: sibling-index()) {
        animation-delay: calc(min(sibling-index() - 1, 5) * var(--_stagger));
      }
    }
  }
}
```

`min()` で順番の上限を5にしているので、項目がいくつあっても、最後の項目が動き始めるのは250ms後です。項目が多いと、間隔が短くても最後の項目が現れるまでの時間が延びるからです。ずらしている間も、現れた項目はクリックできるようにしておきます。全体が現れ終わるまで `pointer-events: none` などで操作を止めると、演出の時間がそのまま操作の遅れになります。

次のデモでは、7つの項目を50msの間隔でずらして出します。順番の上限が5なので、6つ目と7つ目は同時に動き始めます。「はじめての方への案内を開く」を押すと、案内が開きます。案内は `popover` 属性で表示しているので、開くたびに `display: none` から表示され、項目のアニメーションも最初から再生されます。

`sibling-index()` は、2026年8月にBaselineの「新しく利用可能」になったばかりです。未対応の環境では、`@supports` の中の `animation-delay` が適用されず、初期値の0になるので、すべての項目が同時に現れます。ずらすのは装飾なので、この違いは許容できます。古い環境でもずらしたいときは、`sibling-index()` の代わりに、テンプレートで各項目の `style` 属性に `--_index` を書き、`calc(var(--_index) * var(--_stagger))` で計算します。このときの `--_index` は、コンポーネントが自分の子に書く値なので、内部用の名前にしています。

## ツールチップの表示を遅らせる

ツールチップは、出現の動きよりも、表示を始めるまでの時間が使い心地を左右します。ポインターが通り過ぎただけでツールチップが次々に現れると、意図しない表示が画面を覆います。そこで、初回の表示は300〜500ms遅らせ、ポインターが留まったときだけ表示します。

一方で、ツールバーのボタンを順になぞるように、続けて操作している間（ウォームアップ）にも毎回待たせると、操作が遅く感じられます。1つ目のツールチップが表示されたあとは、0〜50msですぐに表示します。トリガーから離れたあとも300〜500msのクールダウンを設け、その間に別のトリガーに触れたら、遅延なしで表示を続けます。

CSSで書けるのは、初回の遅延だけです。表示した状態のルールに `transition-delay` を書くと、表示するときだけ遅れ、非表示に戻るときは基本のルールの値ですぐに消えます。トランジションは変化したあとの状態のルールの値で動くからです。遅延は動きではないので、動きを減らす設定の条件の外に書きます。{/* 要確認: 出典なし */}

ウォームアップとクールダウンは、JavaScriptが必要です。どのトリガーにも属さない「直前までツールチップを表示していたか」という状態を、時間とともに覚えておく必要があるからです。JavaScriptでタイマーを管理し、ウォームアップ中だけルートなどに属性を付けて、CSSではその属性があるときに `transition-delay` と `transition-duration` をどちらも0にします。

ウォームアップ中に遅延だけを0にすると、隣のボタンに移るたび、新しいツールチップがフェードや拡大で現れ、前のツールチップの退場と重なります。続けて操作している間は、出現の動きそのものが待ち時間に見えるので、再生時間も0にして一度で切り替えます。{/* 要確認: 出典なし。ウォームアップ中に再生時間も0にする */}

次の例は、ツールバーのボタンのツールチップです。表示する状態は、JavaScriptが項目に付ける `data-open` 属性で、ウォームアップ中であることは、ツールバーのルートに付ける `data-warm` 属性で表します。遅延と再生時間は内部用のカスタムプロパティにまとめ、ウォームアップ中はルートで両方を0に差し替えます。

```css title="🙆‍♂ Recommended: 初回の表示だけを遅らせ、ウォームアップ中は遅延も動きもなくす" from="motion/tooltip-delay"
@scope (.scoped.format-toolbar) to (.scoped) {
  :scope {
    --_tooltip-delay: 400ms;
    --_tooltip-duration: var(--duration--base);

    @media (prefers-reduced-motion: reduce) {
      --_tooltip-duration: var(--duration--instant);
    }

    &[data-warm] {
      --_tooltip-delay: 0s;
      --_tooltip-duration: 0s;
    }
  }

  ._tooltip {
    transition-duration: var(--_tooltip-duration);
    transition-property: opacity;
    transition-timing-function: var(--ease--out-quad);

    &:not(:is(._item[data-open] *)) {
      opacity: 0;
    }

    &:is(._item[data-open] *) {
      transition-delay: var(--_tooltip-delay);
    }
  }
}
```

`transition-delay` は、`data-open` が付いた状態のルールにだけ書いています。表示するときは400ms待ってからフェードし、`data-open` が外れたときは、基本のルールの遅延0ですぐに消えます。隠す値は閉じた状態の `:not()` の側に書き、表示するときは要素本来の不透明度に戻します。フェードの再生時間は、18-3の表のツールチップと同じ160msです。動きを減らす設定のときは、50msに短くします（「[18-2 動きを減らす設定に対応する](/motion/reduced-motion/)」）。

次のデモでは、ボタンの上でポインターを止めると、400ms後にツールチップが現れます。そのまま隣のボタンへ移ると、遅延なしで一度に切り替わります。ボタンから離れて400ms以上たつと、ウォームアップが終わり、次は再び遅れて現れます。JavaScriptは、遅延が明けて表示が始まった時点（`transitionstart`）で `data-warm` を付け、最後に離れてからクールダウンの時間がたった時点で外します。Tabキーでフォーカスしたときにも表示し、Escキーで閉じられます。

<Demo title="ツールバーのツールチップを、初回だけ400ms遅らせ、続けて触れている間はすぐに表示する" html={tooltipHtml} css={tooltipCss} js={tooltipJs} widths={[]} />

表示の条件は、ホバーとフォーカスを別々に覚え、どちらもなくなったときに閉じます。Tabキーでフォーカスして開いたツールチップは、あとからポインターが通ってその項目を離れても、フォーカスが残っていれば閉じません。ツールチップの上へポインターを動かして読み続けられるよう、`pointer-events: none` は閉じている間だけにし、ボタンとの隙間も擬似要素でツールチップの一部にしています。ツールチップは項目の子孫なので、ボタンからツールチップへ移っても、項目の `pointerleave` は起きません。Escキーを押すと、ホバーやフォーカスが続いていても閉じ、入り直すまで開きません。この3つの動きは、WCAG 2.2の達成基準1.4.13が求める条件に対応します。追加で表示される内容へポインターを動かして読めること、Escで閉じられること、表示のきっかけが残る間は消えないことです。

ツールチップをホバーで表示するHTMLの仕組みには `interestfor` 属性がありますが、Chrome系のブラウザだけが対応しているので、本書では扱っていません（「[第5章 擬似クラスと擬似要素](/pseudo/)」）。そのため、デモでは、表示の状態もJavaScriptで切り替えています。

## ガイドライン

この節の書き方は、ほかの節のルールを組み合わせたもので、この節だけのルールは置いていません。使ったルールは次のとおりです。

- [`motion-needs-purpose`](/motion/purpose/#rule-motion-needs-purpose)：アニメーションを足す前に、状態の変化や操作の結果を伝えるという目的があるかを確かめ、目的のない動きは入れません。
- [`motion-only-with-no-preference`](/motion/reduced-motion/#rule-motion-only-with-no-preference)：装飾的な動きのうちフェード以外は、`@media (prefers-reduced-motion: no-preference)` の中で指定します。
- [`simplify-large-motion-when-reduced`](/motion/reduced-motion/#rule-simplify-large-motion-when-reduced)：機能的な動きでも大きな変動は、動きを減らす設定のときにフェードへ置き換えます。
- [`functional-motion-under-300ms`](/motion/easing-and-duration/#rule-functional-motion-under-300ms)：操作に応じる機能的な動きの再生時間は300ms以下にします。
- [`transition-longhand-with-tokens`](/motion/transitions-and-keyframes/#rule-transition-longhand-with-tokens)：トランジションはロングハンドで書き、再生時間とイージングにはトークンを使います。
- [`keyframes-single-property`](/motion/keyframes/#rule-keyframes-single-property)：グローバルな `@keyframes` は1つにつき1つのプロパティだけを変え、複数の動きは `animation-name` のカンマ区切りで組み合わせます。
- [`keyframes-api-properties`](/motion/keyframes/#rule-keyframes-api-properties)：動きの起点や方向は、`@keyframes` の中で参照するカスタムプロパティに、使う側から値を渡して変えます。
- [`animate-composite-properties`](/motion/performance/#rule-animate-composite-properties)：動かすプロパティは `opacity` と変形を優先し、`clip-path` は描き直しが起きないことを確かめたうえで使います。
