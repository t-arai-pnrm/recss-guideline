同じ見た目を作れる書き方が複数あるときは、新しい記法にそろえます。寸法や余白は `width` ではなく `inline-size` のような論理プロパティで、`display` は `block flex` のような2値構文で書きます。変形は `transform` の関数ではなく、`translate`、`rotate`、`scale` の個別のプロパティで書きます。

色の関数は `rgb(0 0 0 / 80%)` のようにスペースで区切り、`rgba()` やカンマ区切りは使いません。色相には `deg` を付けます。ベンダープレフィックスは、接頭辞なしでは動かないものを除いて書きません。メディアクエリの範囲構文もこの仲間ですが、ルールは第13章で扱います。

どれも、新しいことができるようになる書き方ではありません。目的は、コードの書き方をそろえ、読んだときに意図が伝わるようにすることです。ほとんどは本書のStylelintの設定で検出できるので、全部を覚えなくても、ツールの指摘に従えば守れます。

## 古い記法が混ざったコード

次のコードは、昔の記事やAIの出力でよく見かける書き方です。どれも動きますが、物理的な方向の指定、1値の `display`、`transform` の関数、カンマ区切りの `rgba()` が混ざっています。

```css title="🙅‍♂ Not Recommended: 物理プロパティ、1値の display、transform の関数で書く" issue="convention"
/* 🙅‍♂ Not Recommended */
.modal {
  position: fixed;
  top: 50%;
  left: 50%;
  display: flex;
  width: 90%;
  max-width: 600px;
  background-color: rgba(0, 0, 0, 0.8);
  transform: translate(-50%, -50%);
}
```

書き方が混ざると、同じことを表すコードが人によって違う形になり、読む人は毎回頭の中で変換することになります。古い記法には、ほかの書き方と組み合わせにくいものもあります。たとえば `rgba()` のカンマ区切りは、`oklch()` のような新しい色の関数では使えません。

AIは、学習したコードの量が多い古い記法を選びがちです。本書の記法を指示しておき、生成されたコードに古い記法が残っていないかを確認してください。

## 寸法と余白の論理プロパティ

論理プロパティは、上下左右ではなく、書字方向を基準に方向を表すプロパティです。横書きでは、インライン方向（文字が並ぶ方向）が左右、ブロック方向（行が積み重なる方向）が上下にあたります。`width` は `inline-size`、`margin-top` は `margin-block-start`、`top` は `inset-block-start` になります。

| 物理プロパティ | 論理プロパティ |
|---|---|
| `width`、`height` | `inline-size`、`block-size` |
| `max-width`、`min-height` | `max-inline-size`、`min-block-size` |
| `margin-top`、`margin-bottom` | `margin-block-start`、`margin-block-end` |
| `padding-left`、`padding-right` | `padding-inline`（まとめて指定） |
| `top`、`right`、`bottom`、`left` | `inset` と `inset-block-start` など |

論理プロパティにそろえる理由は、多言語への対応よりも、FlexboxやGridのような主要なレイアウトの仕組みが書字方向を基準に動いているからです。理由の詳細と、物理でしか書けないものとの混在、`margin-inline` を左右の余白として扱ってよいか、右から左へ書く言語と縦書きでの振る舞いは、「[9-9 論理プロパティと論理値](/notation/logical-properties/)」で説明します。

## `display` の2値構文

`display` の値は、本来2つの情報からできています。要素が周りに対してブロックとインラインのどちらで振る舞うか（外側の表示）と、子要素をどう並べるか（内側の表示）です。`display: flex` は、外側がブロックで内側がフレックスという意味の、`block flex` の省略形です。

| 1値の構文 | 2値構文 |
|---|---|
| `block` | `block flow` |
| `flow-root` | `block flow-root` |
| `inline-block` | `inline flow-root` |
| `flex`、`inline-flex` | `block flex`、`inline flex` |
| `grid`、`inline-grid` | `block grid`、`inline grid` |

2値構文にしても、できることは増えません。それでも2値構文を使うのは、要素の振る舞いが値から読み取れるからです。`inline-block` が「インラインとして並び、中は新しいブロック整形コンテキストになる」ことは、`inline flow-root` と書けばそのまま分かります。通常のフローも `block flow` と明示できるので、レイアウトの仕組みを人に説明するときにも役立ちます。

```css title="🙆‍♂ Recommended: 外側と内側の表示を両方書く"
._actions {
  display: block flex;
}

._badge {
  display: inline flow-root;
}
```

`none` や `contents` のように、2値構文のない値はそのまま書きます。本書のStylelintの設定では、著者が公開しているプラグインの `plugin/display-multi-keyword-syntax` で1値の構文を検出し、自動修正もできます。

## 個別の変形プロパティ

移動、回転、拡大・縮小には、`transform` の関数ではなく、`translate`、`rotate`、`scale` の個別のプロパティを使います。いちばんの利点は、変形ごとに値を変えられることです。矢印を45度回転させておき、ホバーとフォーカスで右に少し動かす例で比べます。

```css title="🙅‍♂ Not Recommended: 動かすたびに回転も書き直す" issue="convention"
/* 🙅‍♂ Not Recommended */
._more-link {
  &::after {
    content: "" / "";

    /* ... */
    transform: rotate(45deg);
  }

  &:not(:focus-visible)::after {
    @media (prefers-reduced-motion: no-preference) {
      transition-duration: var(--duration--fast);
      transition-property: transform;
    }
  }

  &:focus-visible::after {
    transform: translateX(4px) rotate(45deg);
  }

  &:any-link:hover::after {
    @media (any-hover) {
      transform: translateX(4px) rotate(45deg);
    }
  }
}
```

`transform` はすべての変形を1つの値で持つので、移動を足すだけでも回転を書き直さなければなりません。書き忘れると、ホバーした瞬間に矢印の向きが戻ります。トランジションも `transform` 全体に掛かるので、どの変形を動かしたいのかがコードから読み取れません。

```css title="🙆‍♂ Recommended: 回転はそのままに、移動だけを変える"
._more-link {
  --_hocus: --false;

  &:focus-visible {
    --_hocus: --true;
  }

  &:any-link:hover {
    @media (any-hover) {
      --_hocus: --true;
    }
  }

  &::after {
    content: "" / "";

    /* ... */
    rotate: 45deg;

    @container style(--_hocus: --true) {
      translate: 4px 0;
    }
  }

  &:not(:focus-visible)::after {
    @media (prefers-reduced-motion: no-preference) {
      transition-duration: var(--duration--fast);
      transition-property: translate;
    }
  }
}
```

個別のプロパティなら、ホバーとフォーカスで変えるのは移動の値だけです。トランジションの対象も `translate` に絞れます。値の書き方は、`translate: 4px 0`（横と縦）、`rotate: 45deg`、`scale: 1.1` のようにシンプルです。なお、どちらの例も、キーボードでフォーカスしたときは一度で動かすために、トランジションを `:not(:focus-visible)` の中に書いています（「[17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)」）。

2つ目の例では、リンクのホバーとフォーカスを、フラグのカスタムプロパティ `--_hocus` で `::after` に伝えています。リンクの状態のセレクタで `--_hocus: --true` を立て、`::after` の中の `@container style(--_hocus: --true)` で移動を切り替えます。擬似要素の名前なしの `style()` は、元の要素（ここではリンク）を問い合わせます。リンクにデフォルト値の `--_hocus: --false` を明示しているのは、外側の要素で立てたフラグを継承して動いてしまわないようにするためです。この書き方は「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」で説明しています。

`transform` を使うのは、個別のプロパティがない `skewX()` などの変形、X軸とY軸の回転を重ねるような3Dの複合指定、個別のプロパティでは表せない順番で変形を重ねる場合だけです。`rotate` プロパティは1つの軸の回転しか表せません。順番については、次に説明する合成の決まりがあります。

## 個別の変形プロパティを合成する順番

個別のプロパティは、宣言を書いた順に関係なく、仕様が定める順番に従って合成されます。CSS Transforms Level 2の仕様は、要素の変形の行列を、`translate`、`rotate`、`scale`、`transform` の順に掛け合わせて求めると定めています。後から掛けた行列ほど先に作用するので、見た目の上では、要素はまず `transform` の関数で変形され、次に `scale`、`rotate`、`translate` の順に変形されます。そのため、拡大・縮小と回転は `transform-origin` を中心に行われ、移動は回転の影響を受けず、画面の向きのまま行われます。

この順番は、アニメーションやトランジションで値を変えている間も変わりません。`@keyframes` で `rotate` と `translate` を動かしても、要素はその場で回転し、移動は常に画面の向きに沿います。そのため、「回転してから、回転した向きに移動する」動きは、個別のプロパティでは作れません。中心の周りを回る軌道の動きがその例です。

決まった順番から外れる変形をアニメーションさせるときは、`transform` に関数を並べて書いてかまいません。次の例では、`rotate()` で回転した向きに `translate()` で24px動かすので、点は半径24pxの円を描きます。

```css title="🙆‍♂ Recommended: 回転した向きに移動する軌道の動きは transform で書く"
@keyframes --loading-orbit--revolve {
  from {
    transform: rotate(0deg) translate(24px);
  }

  to {
    transform: rotate(360deg) translate(24px);
  }
}

@scope (.scoped.loading-orbit) to (.scoped) {
  ._dot {
    @media (prefers-reduced-motion: no-preference) {
      animation-name: --loading-orbit--revolve;
      animation-duration: 1.2s;
      animation-timing-function: linear;
      animation-iteration-count: infinite;
    }
  }
}
```

`from` と `to` で関数の並びをそろえているので、ブラウザは関数ごとに値を補間します。`rotate()` が0度から360度まで回る間、`translate()` の24pxは変わりません。並びがそろっていないと、行列に変換してから補間するので、0度と360度の回転が同じ行列になり、点は回りません。`transform-origin` を要素の外にずらし、`rotate` だけで回す方法もあります。ただ、その場合は回転の中心を要素の大きさから逆算することになり、軌道の半径を値として読み取れません。{/* 要確認: 出典なし。行列での補間の説明は仕様の補間の規則から */}

一方で、「1行で書きたいから」は `transform` を使う理由にしません。変形の順番が決まった順番と同じなら、個別のプロパティで書いても見た目は変わらず、変形ごとに値を変えられる利点も残るからです。`transform` を選ぶのは、上に挙げたように、個別のプロパティでは表せない変形がある場合に限ります。

## クエリの範囲構文

メディアクエリとコンテナサイズクエリの条件は、`min-width: 768px` ではなく `width >= 768px` のような範囲構文で書きます。不等式としてそのまま読めて、境界の値を含むかどうかも明確になるからです。書き方と理由は「[13-5 メディアクエリ](/responsive/media-queries/)」で説明しています。

## 色の関数の書き方

色の関数は、`rgb(0 0 0 / 80%)` のように値をスペースで区切り、不透明度は `/` の後ろに書きます。`rgba()` と `hsla()` は使わず、`rgb()` と `hsl()` にそろえます。色相には `210deg` のように単位を付けます。

```css title="🙅‍♂ Not Recommended: 色の値をカンマで区切り、不透明度を rgba() で付ける" issue="convention"
/* 🙅‍♂ Not Recommended */
._overlay {
  background-color: rgba(0, 0, 0, 0.6);
  color: hsl(210, 20%, 98%);
}
```

```css title="🙆‍♂ Recommended: 値をスペースで区切り、不透明度を / の後ろに書く"
._overlay {
  background-color: rgb(0 0 0 / 60%);
  color: hsl(210deg 20% 98%);
}
```

スペース区切りにそろえる理由は、`oklch()`、`lab()`、`hwb()` のような新しい色の関数が、スペース区切りしか受け付けないからです。カンマ区切りを使えるのは古い `rgb()` と `hsl()` だけなので、そちらをスペース区切りに合わせれば、すべての色の関数を同じ形で書けます。

`rgba()` は、仕様上は `rgb()` の別名で、古い書き方として廃止されたわけではありません。ただ、`rgb()` でも不透明度を指定できるので、同じ意味の関数を2つ使い分ける理由がありません。不透明度はパーセントで書き、色相の `deg` も省略しません。数値が角度だとはっきりし、明度や彩度の値と見分けやすくなるからです。

本書のStylelintの設定では、これらを4つのルールで検出し、自動修正もできます。対象のルールは、`color-function-notation`、`color-function-alias-notation`、`alpha-value-notation`、`hue-degree-notation` です。`white` のような色の名前（`color-named`）と、`#00000080` のような不透明度付きの16進数（`color-hex-alpha`）も禁止しています。どの色の関数を選ぶかは、「[15-1 色の形式と色空間](/color-media/color/)」で扱います。

## ベンダープレフィックス

`-webkit-` のようなベンダープレフィックスは、接頭辞なしでは対象のブラウザで動かないものを除いて書きません。本書の対象のブラウザ（Safari 18系の最終版以降と、ほかの主要なブラウザの最新版）は、ほとんどの機能に接頭辞なしで対応しています。たとえば `backdrop-filter` は、Safari 18から接頭辞なしで使えます。

書く必要があるのは、`-webkit-font-smoothing` のように標準のプロパティがないものと、Safariがまだ接頭辞なしに対応していないものです。`box-decoration-break` と `user-select` がこれにあたります。後者はStylelintの `property-no-vendor-prefix` に検出されるので、無効化のコメントと理由を添えて書きます。

```css title="🙆‍♂ Recommended: 必要なプレフィックスには理由を残す"
._marker {
  /* Safari は接頭辞なしの box-decoration-break に対応していない */
  /* stylelint-disable-next-line property-no-vendor-prefix */
  -webkit-box-decoration-break: clone;
  box-decoration-break: clone;
}
```

接頭辞が必要かどうかは、記憶ではなく、そのときのブラウザの対応状況で判断します。理由をコメントに残しておけば、Safariが対応した時点で、どの行を消せばよいかがすぐに分かります。`box-decoration-break: clone` で見出しの行ごとに背景を敷く例は、「[16-7 文字とリストの装飾](/decoration/text-ornaments/)」にあります。
