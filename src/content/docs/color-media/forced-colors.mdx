強制カラーモードでは、ブラウザがページの色を、ユーザーが選んだ少数のシステムカラーに置き換えます。背景色や影で表していた境界や図形は、この置き換えで消えてしまうことがあります。枠線は `border: none` にせず、透明にして残します。`background-color` で描いたアイコンは、カスタムプロパティを経由して、システムカラーにフォールバックさせます。

色の違いだけで情報を伝えないことも必要です。実装を終えたら、グレースケールの表示に切り替えて、リンクや入力エラーのような状態を見分けられるかを確かめます。文字と背景のコントラスト比は、WCAGのAAを満たすようにします。

## 強制カラーモードで起きること

強制カラーモードは、Windowsの「コントラスト テーマ」などを有効にしたときの表示モードです。ユーザーが選んだ配色（黒地に白い文字など）で、すべてのページが表示されます。WebAIMが視力の弱い人に行った調査（2018年）では、回答者の約半数が、なんらかの高コントラストの表示を使っていると答えています。視力の弱い人にとっては、少数の特殊な設定ではなく、ページを読むための日常の手段です。

ブラウザにも、似た機能が広がっています。Edge 130にはページの配色を指定する設定が、Firefox 138にはコントラストを制御する設定が入りました。Windowsだけの特殊な環境だと考えて、対応を後回しにする理由はありません。

強制カラーモードでは、`color`、`background-color`、`border-color`、`outline-color`、`text-decoration-color` などの色が、システムカラーに置き換わります。`box-shadow` と `text-shadow` は `none` になり、URLで指定した画像以外の `background-image`（グラデーションなど）も表示されなくなります。`color-scheme` は `light dark` として扱われ、`scrollbar-color` は `auto` に戻ります。

問題になるのは、色だけで何かを表していた部分です。背景色だけで範囲を示していたボタンは、背景色が置き換わると、ただの文字になります。`background-color` に `currentColor` を指定して描いたアイコンは、背景色がページの背景と同じ色に置き換わり、見えなくなります。

## システムカラーで色を指定し直す

強制カラーモードに合わせて色を指定し直すときは、システムカラーを使います。システムカラーは、ユーザーの配色の設定から決まる色のキーワードです。よく使うのは、次の組み合わせです。

- `Canvas` と `CanvasText`：ページの背景色と文字色
- `LinkText`：リンクの文字色
- `ButtonFace` と `ButtonText`：ボタンの背景色と文字色
- `GrayText`：無効な要素の文字色
- `Highlight` と `HighlightText`：選択した部分の背景色と文字色

入力欄やボタンの枠線を描き直す場面では、ほかのシステムカラーも使えます。`Field` と `FieldText` は入力欄の背景色と文字色、`ButtonBorder` はボタンの枠線の色、`AccentColor` と `AccentColorText` はチェックボックスの選択色のような強調の色とその上の文字色を表します。`ButtonBorder` は、Safariが対応していないので、`ButtonText` などで代用します。

<Baseline id="system-color" compatKey="css.types.color.system-color.buttonborder" name="システムカラー ButtonBorder" />

kiso.cssでは、強制カラーモードのときだけ、`<mark>` の色を `Highlight` と `HighlightText` にしています。強制カラーモードでは `<mark>` の色が変わらない場合もあり、蛍光ペンで強調したという意味を伝えられなくなるからです。

```css title="🙆‍♂ Recommended: 強制カラーモードのときだけ、システムカラーで指定し直す"
:where(mark) {
  @media (forced-colors: active) {
    background-color: Highlight;
    color: HighlightText;
  }
}
```

システムカラーは、強制カラーモード以外でも使えます。「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」で紹介したフォーカスリングは、`Canvas` と `CanvasText` の2色を重ねているので、強制カラーモードでもそのまま見えます。

要素ごとに強制カラーモードを無効にする、`forced-color-adjust: none` というプロパティもあります。ただし、ユーザーが自分で選んだ配色を打ち消す指定なので、本書では、システムカラーに置き換えると図として成り立たないグラフのような要素に限って使います（「[16-9 輪郭と枠線を描く](/decoration/outlines/)」のドーナツグラフ）。Safariも対応していません。

## 枠線は消さずに透明にする

背景色で範囲を示すボタンやカードでも、枠線を `border: none` で消さないようにします。代わりに `border-color: transparent` で、枠線を透明にしておきます。

```css title="🙅‍♂ Not Recommended: 枠線を消し、強制カラーモードでボタンの範囲を失う" issue="behavior"
/* 🙅‍♂ Not Recommended */
._primary-button {
  border: none;
  background-color: oklch(52% 0.16 250deg);
  color: oklch(100% 0 none);
}
```

```css title="🙆‍♂ Recommended: 枠線を透明にして残す"
._primary-button {
  border-color: transparent;
  background-color: oklch(52% 0.16 250deg);
  color: oklch(100% 0 none);
}
```

通常の表示では、2つのボタンの見た目は変わりません。違いが出るのは強制カラーモードのときです。`border-color` はシステムカラーに置き換わるので、透明にしておいた枠線に色が付きます。背景色が消えても枠線が残るので、クリックできる範囲が分かります。

kiso.cssは、ボタンやフォームの部品に `1px` の実線の枠線を付けています。デザインで枠線を消したいときも、kiso.cssのREADMEのとおり、`border: none` ではなく `border-color: transparent` で上書きします。kiso.cssの方針は「[8-1 壊さないリセット](/reset/kiso/)」で説明しています。

フォーカスリングを `box-shadow` などで描き直すときも、`outline` は消さず、透明にして残します。通常の表示では、透明な `outline` は見えず、`box-shadow` の表現だけが見えます。強制カラーモードでは `outline-color` がシステムカラーに置き換わるので、キーボードで操作している位置が見えます。`outline: none` で消すと、強制カラーモードでもリングが消えます。

```css title="🙆‍♂ Recommended: フォーカスリングを描き直すときは、outline を透明にして残す"
._field {
  &:focus-visible {
    box-shadow: 0 0 0 3px oklch(52% 0.16 250deg);
    outline-color: transparent;
  }
}
```

同じ理由で、要素の境界を `box-shadow` だけで描かないようにします。`box-shadow` で描いた枠線は、強制カラーモードでは `none` になって消えます。フォーカスリングを `box-shadow` だけで描かないことは、「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」で説明しています。

## 背景色で描いた図形をフォールバックさせる

`mask-image` や `clip-path` で形を切り抜き、`background-color` で色を塗るアイコンは、背景色を文字色（前景色）のように使っています。強制カラーモードでは、この背景色がページの背景色に置き換わるため、アイコンが見えなくなります。

そこで、背景色をカスタムプロパティ `--background--current` から受け取るようにします。通常は `currentColor` を、強制カラーモードでは文脈に合ったシステムカラーを入れておきます。

```css title="🙆‍♂ Recommended: 強制カラーモードでは、文脈に合ったシステムカラーにする" from="color-media/forced-colors-fallback"
@layer base {
  :root {
    --background--current: currentColor;

    @media (forced-colors: active) {
      --background--current: CanvasText;
    }
  }

  :any-link {
    @media (forced-colors: active) {
      --background--current: LinkText;
    }
  }

  button {
    &:enabled {
      @media (forced-colors: active) {
        --background--current: ButtonText;
      }
    }
  }

  :disabled {
    @media (forced-colors: active) {
      --background--current: GrayText;
    }
  }
}
```

通常の文字の中では `CanvasText`、リンクの中では `LinkText`、有効なボタンの中では `ButtonText`、無効な要素の中では `GrayText` になります。アイコンは、周りの文字と同じシステムカラーで描かれます。これらの指定は `base` レイヤーに書くので、コンポーネントの側で文脈を足したいときは、クラス1つで上書きできます。レイヤーを使えない環境では、セレクタを `:where()` で包んで詳細度を0にします（[4-2 セレクタで詳細度を設計する](/cascade/selectors/)）{/* CMSの節を公開したらリンクする: /operations/cms/ */}。

アイコンを描く側では、`background-color` に `var(--background--current)` を指定するだけです。`--chevron--rightward` は、矢印のSVGをdata URIにしたトークンです（「[16-3 アイコンとSVG](/decoration/icons-and-masks/)」）。

```css title="🙆‍♂ Recommended: アイコンの色を --background--current から受け取る"
._more {
  &::after {
    content: "";

    /* 空の擬似要素はインラインになり、幅と高さが効かないので、箱を作る */
    display: inline flow-root;
    mask-image: var(--chevron--rightward);
    mask-repeat: no-repeat;
    mask-position: center;
    mask-size: contain;
    inline-size: 1em;
    aspect-ratio: 1;
    background-color: var(--background--current);
  }
}
```

`background-color` のフォールバックは、一度 `:root` に定義しておけば、あとは `currentColor` の代わりに `var(--background--current)` と書くだけで済みます。

次のデモでは、前の見出しの透明な枠線と、この見出しの `--background--current` を使い、ボタンとリンクを「対策なし」と「対策あり」の2列で並べています。通常の表示では、2列の見た目は同じです。

<Demo title="通常の表示では同じでも、強制カラーモードでは差が出るボタンとリンク" html={forcedHtml} css={forcedCss} variant="neutral" />

強制カラーモードの見え方は、ChromeのDevToolsで確かめられます。「Rendering」パネルの「Emulate CSS media feature forced-colors」で `forced-colors: active` を選ぶと、ページ全体が強制カラーモードで描画されます。「対策なし」の列では、ボタンの範囲が分からなくなり、矢印のアイコンが消えます。この節の冒頭の図は、このエミュレーションで表示したものです。

### グラデーションを重ねる方法

グローバルなカスタムプロパティに頼らず、1つのコンポーネントの中で済ませたい場合は、グラデーションを重ねる方法もあります。`background-image` に単色のグラデーションを、`background-color` にシステムカラーを指定します。

```css title="🙆‍♂ Recommended: グラデーションが消えると、下のシステムカラーが見える"
._crumb {
  &::before {
    content: "";

    /* 空の擬似要素はインラインになり、幅と高さが効かないので、箱を作る */
    display: inline flow-root;
    mask-image: var(--chevron--rightward);
    mask-repeat: no-repeat;
    mask-position: center;
    mask-size: contain;
    inline-size: 0.75em;
    aspect-ratio: 1;
    background-image: conic-gradient(currentColor 0 0);
    background-color: CanvasText;
  }
}
```

通常の表示では、グラデーションが `currentColor` で上を塗りつぶすので、下の `CanvasText` は見えません。強制カラーモードではグラデーションが消え、`CanvasText` が見えます。私は最近の案件で、パンくずリストの区切りの矢印をこの方法で描きました。

ただし、この方法では、リンクの中でも色は `CanvasText` のままです（Chromeのエミュレーションで確認）。パンくずリストの区切りのように、通常の文字の文脈でしか使わない図形に向いています。リンクやボタンの中のアイコンには、`--background--current` を使います。

## インラインSVGと画像のアイコン

インラインSVGの色は、強制カラーモードでも置き換わるとは限りません。Firefox 138のコントラストの設定では、`currentColor` がシステムカラーに置き換わらない場合があります。Chromeのエミュレーションでも、`fill` 属性やCSSで指定したSVGの色は、元の色のままでした。そこで、強制カラーモードのときは、プロジェクトで管理している単色のアイコンに限って、`fill` と `stroke` をシステムカラーに固定します。

対象を見分けるために、単色のアイコンは `svg` 要素に `fill="currentColor"`（塗りで描く場合）か `stroke="currentColor"`（線で描く場合）を書き、図形の要素には色を書かないことにします。塗りで描くアイコンには `fill` だけを、線で描くアイコンには `stroke` だけを補正します。両方をすべての `svg` に指定すると、もともと線のない塗りのアイコンにも、`svg` 要素から継承した線が描かれてしまいます。`stroke` の初期値は `none` で、`fill` と `stroke` はどちらも継承するからです（SVG 2）。

```css title="🙆‍♂ Recommended: 単色のアイコンの色を、文脈に合ったシステムカラーに固定する"
@layer base {
  svg {
    @media (forced-colors: active) {
      --_b--svg-foreground: CanvasText;
    }

    /* 塗りで描くアイコン */
    &[fill="currentColor" i] {
      @media (forced-colors: active) {
        fill: var(--_b--svg-foreground) !important;
      }
    }

    /* 線で描くアイコン */
    &[stroke="currentColor" i] {
      @media (forced-colors: active) {
        stroke: var(--_b--svg-foreground) !important;
      }
    }

    &:is(:any-link *) {
      @media (forced-colors: active) {
        --_b--svg-foreground: LinkText;
      }
    }

    &:is(button:enabled *) {
      @media (forced-colors: active) {
        --_b--svg-foreground: ButtonText;
      }
    }

    &:is(:disabled *) {
      @media (forced-colors: active) {
        --_b--svg-foreground: GrayText;
      }
    }
  }
}
```

ここで `!important` を使うのは、ベーススタイルが `components` レイヤーより前の `base` レイヤーにあるからです。コンポーネントの側で `svg` 要素の色を指定していると、`!important` がなければ後のレイヤーにあるそちらが勝ち、システムカラーになりません。`!important` を付けた宣言は、レイヤーの順番が逆になり、前のレイヤーにあるものが勝ちます。`!important` を使ってよい場面は、「[4-1 カスケード・詳細度・継承](/cascade/cascade-basics/)」で整理しています。

ただし、この指定が補正できるのは、`svg` 要素に書いた色と、それを継承する図形だけです。図形の要素に `fill` や `stroke` を属性やCSSで書くと、その値が継承した値より優先されるので、システムカラーには置き換わりません。CSSの `fill: currentColor` で色を決めるアイコンも、属性のセレクタには当てはまらないので、そのコンポーネントの中で同じ補正を書きます。`fill="none"` のように描かない部分は、もとの `none` のまま残ります。

ロゴやイラストのような多色のSVGは、この補正の対象にしません。1色に置き換えると、色の違いで描き分けていた部分の区別がなくなるからです。多色のSVGは、次の `<img>` のアイコンと同じく、強制カラーモードの背景に溶け込まないかを確かめます。{/* 要確認: 出典なし */}

`<img>` で表示するアイコンは、強制カラーモードの影響を受けません。強制カラーモードでは配色が `light dark` として扱われるので、黒いアイコンは黒い背景に、白いアイコンは白い背景に溶け込むおそれがあります。単色のアイコンなら、`filter` で背景と反対の色に塗りつぶします。

```css title="🙆‍♂ Recommended: 単色の画像のアイコンを、背景と反対の色に塗りつぶす"
._icon {
  @media (forced-colors: active) and (prefers-color-scheme: light) {
    filter: brightness(0);
  }

  @media (forced-colors: active) and (prefers-color-scheme: dark) {
    filter: brightness(0) invert(1);
  }
}
```

## 強制カラーモードで崩れる装飾を分ける

強制カラーモードでは意味が変わってしまう装飾は、`@media (forced-colors: none)` の中に書きます。たとえば、画像の上に大きな `outline` を内側へずらして重ね、半透明のオーバーレイにする方法があります。強制カラーモードでは `outline` の色が不透明なシステムカラーに置き換わり、画像全体が塗りつぶされてしまいます（Chromeのエミュレーションで確認）。

```css title="🙆‍♂ Recommended: 強制カラーモードでないときだけ、オーバーレイを重ねる"
._image {
  @media (forced-colors: none) {
    outline: 100lvmax solid oklch(0% 0 none / 60%);
    outline-offset: -100lvmax;
  }
}
```

スクロールバーの色も同じです。強制カラーモードでは指定した色のせいでスクロールバーを見失うおそれがあるので、変えるなら `forced-colors: none` の中に限ります。スクロールバーの扱いは「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」で説明しています。

以前の私は、この条件を `@media not (forced-colors: active)` と書いていました。いまは `@media (forced-colors: none)` にそろえています。否定の `not` を使わずに条件を書けるので、読み間違いが起きにくくなります。

## 色だけで情報を伝えない

色の見え方は人によって違います。色覚の特性がある人や、年齢とともに色を見分けにくくなった人にとって、色の違いだけで示された情報は伝わりにくくなります。電子ペーパーの端末を使う人や、スマートフォンの使いすぎを防ぐために、あえてグレースケールで表示している人もいます。色だけに頼る表現は、WCAG 2.2のレベルAの達成基準（色の使用）にも反します。

そこで、実装後の確認の項目に「グレースケール表示での確認」を入れておきます。とくに見るのは、本文の中のリンク、フォーカスやホバーの状態、入力エラーのように、色の変化で状態を表しがちな部分です。グレースケールで見分けられなければ、下線、太さ、アイコン、文言のような、色以外の手がかりを足します。

<Demo title="グレースケールにすると、色だけで区別したリンクと入力エラーが見分けられなくなる" html={grayscaleHtml} css={grayscaleCss} variant="neutral" scheme="light" />

チェックボックスをオンにすると、2つの列がグレースケールで表示されます。左の列では、リンクが周りの文字と区別できず、入力エラーの枠線も通常の枠線と見分けられません。右の列では、リンクに下線があり、エラーの枠線は太く、エラーの内容も文章で表示されています。

確認には、OSのグレースケール表示を使うのが基本です。macOSとWindowsには、画面全体をグレースケールにする設定があります。手早く確かめたいときは、DevToolsで `body` に `filter: grayscale(1)` を一時的に書き足します。

```css
body {
  filter: grayscale(1);
}
```

濃い赤のように、グレースケールにしても見分けにくい色もあります。必要に応じて、DevToolsの「Rendering」パネルにある色覚のエミュレーションも使います。色以外の手がかりを足すときは、下線を足す、アイコンを添える、形を変えるといった、手間の少ない方法から始めるとよいでしょう。どの方法にするかは、デザイナーと相談して決めます。

## コントラスト比を確かめる

文字と背景のコントラスト比は、WCAG 2.2のAAを満たすようにします。通常の大きさの文字では4.5:1以上、大きな文字では3:1以上が基準です。確認には、WebAIMのContrast Checkerや、DevToolsのカラーピッカーに表示されるコントラスト比を使います。計算した比は四捨五入せずに比べるので、4.49:1は4.5:1の基準を満たしません。

ここでいう「大きな文字」は、[WCAGの定義](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)では18ポイント以上、太字なら14ポイント以上の文字です。CSSの単位に直すと、約24px以上、太字なら約18.7px以上になります。和文の場合は、これと同じ大きさに見える文字が該当します。見出しのつもりで大きくした文字でも、太字でない20pxの文字は通常の文字として扱うので、4.5:1が必要です。

「補足の文字」のような薄い文字色のトークンは、基準に届きにくくなります。たとえば `oklch(55.6% 0 none)` のグレーは、`oklch(97% 0 none)` の背景の上ではコントラスト比が約4.3:1になり、AAに届きません。本書のデモの `--foreground--muted` も、ライトモードではこのグレーと同じ値なので、ホバーや選択の重ね色の上には置きません。トークンを定義するときは、組み合わせる背景のトークンごとに確かめます。私の案件でも、図のキャプションの色をAAを満たす値に調整し、その理由をコメントに残しました。

文字でない部分にも基準があります。WCAG 2.2の[達成基準1.4.11（非テキストのコントラスト）](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)では、ボタンや入力欄のようなUIコンポーネントの範囲と状態を示す部分に、隣り合う色との3:1以上のコントラスト比を求めています。入力欄の枠線、チェックボックスのオンとオフの違い、フォーカスリングが対象です。ボタンの文字やアイコンのように、範囲を示すほかの手がかりがあれば、枠線そのものは3:1に届かなくてもかまいません。

この基準には例外もあります。無効にしたコンポーネントと、ブラウザのデフォルトの見た目から変えていないコンポーネントは対象外です。逆にいえば、`accent-color` や枠線の色を変えた時点で、その色は自分で3:1を確かめる必要があります。淡いグレーの枠線だけで入力欄の範囲を示すデザインは、白い背景の上では基準に届かないことが多いので、トークンを決める段階で確かめます。{/* 要確認: 出典なし */}

AIにデザインを実装させると、薄いグレーの文字や、淡い色の上の白い文字をそのまま出力することがあります。色の値を受け取ったら、コントラスト比を確かめるところまでを1つの作業にします。
