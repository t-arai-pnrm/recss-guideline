ダークモードに対応するときは、セマンティクスのトークンの値を `light-dark()` で書き、`<meta name="color-scheme" content="light dark">` で両方の配色に対応することを宣言します。配色の切り替えはトークンの側で済ませ、コンポーネントには `prefers-color-scheme` のメディアクエリを書きません。

サイトの中でテーマを選べるようにする場合も、このメタ要素の `content` を書き換えるだけで済みます。色の切り替えはすべて `light-dark()` に任せ、CSSの側でテーマの属性を参照しないので、切り替えの仕組みが1か所にまとまります。

## コンポーネントごとにダークモードの色を書くと起きること

ダークモードへの対応でよく見るのは、コンポーネントごとに `prefers-color-scheme` のメディアクエリを書き、ダーク用の色を指定し直す書き方です。

```css title="🙅‍♂ Not Recommended: コンポーネントごとにダークモードの色を書く" issue="convention"
/* 🙅‍♂ Not Recommended */
._card {
  background-color: var(--color--neutral--100);
  color: var(--color--neutral--950);

  @media (prefers-color-scheme: dark) {
    background-color: var(--color--neutral--900);
    color: var(--color--neutral--50);
  }
}
```

この書き方では、ダークモードの色がサイトのあちこちに散らばります。ダーク用の値を書き忘れたコンポーネントだけが明るいまま残る、といった不具合も起きがちです。ダークモードの色を調整したくなったときは、すべてのコンポーネントのメディアクエリを探して直すことになります。AIにダークモードへの対応を頼むと、この形のコードが出てくることが多いので注意してください。

テーマを手動で切り替えられるようにすると、問題はさらに増えます。メディアクエリはOSの設定しか見ないので、サイトの中で選んだテーマに合わせるには、`[data-theme="dark"]` のようなセレクタでも同じ色を書くことになります。ダーク用の色がメディアクエリと属性セレクタの2か所に分かれ、どちらかを直し忘れると、切り替えの方法によって色が変わります。

## light-dark() でトークンに両方の値を持たせる

ダークモードの色は、セマンティクスのトークンに `light-dark()` で両方の値を持たせます。`light-dark(ライトの色, ダークの色)` と書くと、要素に適用されている配色に合わせて、どちらか一方の値になります。

```css title="🙆‍♂ Recommended: セマンティクスのトークンに、両方の配色の値を持たせる" from="color-media/theme-tokens"
:root {
  --background--base: light-dark(var(--color--neutral--50), var(--color--neutral--900));
  --foreground--base: light-dark(var(--color--neutral--900), var(--color--neutral--100));
  --foreground--muted: light-dark(var(--color--neutral--500), var(--color--neutral--400));
}
```

コンポーネントは、これらのセマンティクスのトークンを参照するだけです。配色による切り替えはトークンの側で済んでいるので、コンポーネントに `prefers-color-scheme` のメディアクエリを書く必要はありません。ダークモードの色を調整するときも、見直すのはトークンの定義だけです。

プリミティブのトークン（`--color--neutral--100` など）には、`light-dark()` を使いません。プリミティブは「明度97%のグレー」のような色そのものを表し、どの配色で使うかはセマンティクスの層で決めるからです。トークンの2層の設計は「[10-4 デザイントークン](/components/design-tokens/)」で扱います。

本書の対象のブラウザでは、`light-dark()` が受け取れるのは色だけです。画像を配色で切り替える書き方がすべての主要なブラウザで使えるようになったのは、Safari 27が出た2026年9月です。本書の対象のブラウザではまだ使えません。

次のデモでは、同じカードをライトとダークの2つの配色で並べています。比べやすいように要素ごとに `color-scheme` を指定していますが、実際のサイトでは、次の見出しで説明するメタ要素が配色を決めます。

<Demo title="同じトークンから、ライトとダークの配色を作る" html={themeHtml} css={themeCss} />

カードの側では、配色を一切切り替えていません。枠線は文字色から相対カラー構文で、背景は `color-mix()` で作っています。ボタンの文字色は、背景の明度から `sign()` で決めています。ダークの配色ではボタンの背景が明るいグレーに替わるので、ボタンの文字は黒になります。派生色の作り方は「[15-2 相対カラー構文で派生色を作る](/color-media/relative-color/)」で、文字色の決め方は「[15-3 背景から文字色を決める](/color-media/contrast-text/)」で説明しています。

## meta 要素で配色を宣言する

`light-dark()` を使うには、ページが両方の配色に対応していることを宣言する必要があります。宣言がないと、OSがダークモードでも `light-dark()` は常にライトの値になります。私のテンプレートでは、CSSの `color-scheme` プロパティではなく、HTMLのメタ要素で宣言しています。

```html
<meta name="color-scheme" content="light dark" />
```

メタ要素で宣言すると、スクロールバーやフォームの部品といったブラウザの部品も、ページと同じ配色で描画されます。CSSを読み込む前から配色が決まるので、読み込みの途中で背景が白く光ることも防げます。

反対に、ダークモードに対応していないサイトでは、この宣言を書きません。色を指定していない部分だけが暗い配色になり、文字を読めなくなることがあるからです。詳しくは「[8-3 グローバルに書いてはいけないもの](/reset/global-pitfalls/)」で説明しています。

## 一部のコンポーネントだけを暗い配色にする

ライトの配色のページの中で、フッターのような一部のコンポーネントだけを暗い配色にしたい場合があります。そのときは、コンポーネントのルートに `color-scheme: dark` を指定します。`color-scheme` は継承するプロパティなので、コンポーネントの中の `light-dark()` はダークの値になり、フォームの部品やスクロールバーも暗い配色で描画されます。

ただし、`color-scheme` を指定しただけでは、そのコンポーネントの文字色と背景色は切り替わりません。親から継承した `color` は、親の要素でライトの値に計算された色だからです。背景も、指定しなければ透明のままで、親の明るい背景が透けて見えます。`color-scheme` を指定した要素では、`color` と `background-color` をセマンティクスのトークンで指定し直します。

```css title="🙆‍♂ Recommended: color-scheme を指定した要素で、文字色と背景色を指定し直す"
@scope (.scoped.site-footer) to (.scoped) {
  :scope {
    color-scheme: dark;
    background-color: var(--background--base);
    color: var(--foreground--base);
  }
}
```

コンポーネントの中で、トークンを参照している宣言は指定し直さなくても切り替わります。登録していないカスタムプロパティは、`light-dark()` を含む値のまま継承されるので、`var()` で参照した要素の配色で色が決まるからです。

この仕組みは、トークンを `@property` で `<color>` 型として登録すると成り立ちません。登録したプロパティは、値を定義した `:root` の時点で色に計算され、その色が子孫に継承されます。`:root` がライトの配色なら、`color-scheme: dark` のコンポーネントの中でもライトの色のままです。

```css title="🙅‍♂ Not Recommended: light-dark() で値を持たせるトークンを、色の型で登録する" issue="behavior"
/* 🙅‍♂ Not Recommended */
@property --foreground--base {
  syntax: "<color>";
  inherits: true;
  initial-value: oklch(0% 0 none);
}
```

本書がトークンの定義に `@property` を使わないのは、このように振る舞いが変わるからです（「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」）。色をアニメーションさせるために登録が必要なら、トークンではなく、コンポーネントの名前を含むプロパティを登録し、コンポーネントの中でトークンを受け取ります。値はその要素の配色で計算されるので、`light-dark()` の切り替えも保たれます。

`::placeholder` や `::selection` のような擬似要素の色も、`light-dark()` を含むトークンで指定します。擬似要素は元の要素の配色を引き継ぐので、トークンを使えば一緒に切り替わります。色を直接書くと、暗い配色のコンポーネントの中で、プレースホルダーや選択範囲の色だけがライトの配色のまま残ります。

`<iframe>` で埋め込んだ文書は、`<iframe>` 要素の `color-scheme` を引き継ぎません。埋め込まれた文書の配色は、その文書のmeta要素や `color-scheme` で決まります。仕様では、`<iframe>` 要素と埋め込まれた文書の配色が食い違うと、ブラウザは埋め込まれた文書に不透明な背景を敷くことになっています。FirefoxとSafariでも、`color-scheme: dark` の `<iframe>` に配色を指定していない文書を埋め込むと、埋め込まれた文書に不透明な白い背景が敷かれました。

## テーマを手動で切り替える

OSの設定とは別に、サイトの中でテーマを選べるようにする場合も、メタ要素の `content` を書き換えます。私のテンプレートでは「ライト」「ダーク」「OSの設定に合わせる」の3つを選べるようにし、それぞれ `light only`、`dark only`、`light dark` を設定しています。選んだ値はlocalStorageに保存し、次にページを開いたときに読み戻します。

```html
<meta name="color-scheme" content="light dark" />
<script>
  (() => {
    try {
      const stored = localStorage.getItem('color-scheme');
      const meta = document.querySelector('meta[name="color-scheme"]');
      if (stored && meta) meta.content = stored;
    } catch {
      // Cookie を無効にしている環境では、localStorage にアクセスすると例外が発生する
    }
  })();
</script>
```

このスクリプトは `<head>` の中に直接書き、ページの描画より前に実行します。外部のファイルにして後から読み込むと、保存したテーマに切り替わるまでの一瞬、OSの配色で表示されてしまいます。localStorageは、Cookieを無効にしている環境では例外を投げるので、必ず `try` で囲みます。

JavaScriptが無効な環境では、スクリプトが動かないので、メタ要素の元の値（`light dark`）のまま、OSの設定に従って表示されます。読み出しの失敗も同じ結果になります。

`only` を付けた値は、ページがその配色にしか対応していないことを表します。ブラウザが独自にページを暗くする機能を持っていても、`only` があれば、ページの配色はそのまま保たれます。

以前の私は、`<html>` の `data-theme` 属性とメタ要素の両方を書き換えていました。いまはメタ要素だけを書き換え、色はすべて `light-dark()` に任せています。CSSの側でテーマの属性を参照しないので、切り替えの仕組みが1か所にまとまります。

### 色以外のスタイルを配色で変える

画像の明るさや影の強さのように、色以外のスタイルを配色で変えたい場合もあります。テンプレートでは、メタ要素の値から `--color-scheme--current` というカスタムプロパティを決めておき、スタイルクエリで分岐できるようにしています。

```css title="🙆‍♂ Recommended: meta 要素の値から、いまの配色をカスタムプロパティにする" from="color-media/theme-switch"
:root {
  &:has(meta[name="color-scheme"][content="light only"]) {
    --color-scheme--current: --light;
  }

  &:has(meta[name="color-scheme"][content="dark only"]) {
    --color-scheme--current: --dark;
  }

  &:has(meta[name="color-scheme"][content="light dark"]) {
    --color-scheme--current: --light;

    @media (prefers-color-scheme: dark) {
      --color-scheme--current: --dark;
    }
  }
}
```

使う側では、`@container style(--color-scheme--current: --dark)` のように条件を書きます。値を `--` で始めるのは、自分で付けた名前だと分かるようにするためです。スタイルクエリは2026年5月にすべての主要なブラウザで使えるようになったので、本書の対象のブラウザでは問題なく動作します。ただし、色の切り替えは `light-dark()` で足りるので、このフラグを使う場面は多くありません。

次のデモでは、ラジオボタンで選んだ値をメタ要素の `content` に書き込み、ラジオボタンの下に `--color-scheme--current` の値を表示しています。「ダーク」を選ぶと、カードの文字色、背景色、影は `light-dark()` のトークンで切り替わり、イラストの明るさはスタイルクエリで抑えられます。「OSの設定に合わせる」を選んだ状態では、OSの外観の設定を変えると、表示も一緒に変わります。

<Demo title="選んだテーマをメタ要素に書き込み、トークンの色とスタイルクエリで表示を切り替える" html={themeSwitchHtml} css={themeSwitchCss} js={themeSwitchJs} scheme="light dark" />

テーマを切り替える瞬間に、View Transitionで画面を上から塗り替える実装例は、「[18-11 View Transitionsで画面の切り替えをつなぐ](/motion/view-transitions/)」で説明します。切り替えの処理は、`types` に `theme-toggle` を指定して `document.startViewTransition()` に渡します。CSSの側では、`:active-view-transition-type(theme-toggle)` でアニメーションを定義します。動きを減らす設定のときは、塗り替える動きを付けず、View Transitionsのデフォルトの短いクロスフェードに簡素化します。

## 案件でのダークモード

私が担当する案件では、ダークモードに対応せず、ライトの配色だけで作ることがほとんどです。デザインがライトの配色しか用意していないなら、無理に対応する必要はありません。

ダークモードに対応するなら、すべての色をセマンティクスのトークンで管理していることが前提になります。16進数の色がコンポーネントに直接書かれていると、その部分だけが切り替わりません。CMSで編集者が本文の文字に色を付けられる場合は、その色がダークモードの背景で読めるかどうかまでは保証できません。

影の色も、配色によって変えます。暗い背景に白い影を付けると、影ではなく光って見えるので、ダークモードでは影を黒のままにし、不透明度を上げて奥行きを表します。影のトークンの作り方は「[16-5 面・影・角丸](/decoration/surfaces/)」で説明しています。
