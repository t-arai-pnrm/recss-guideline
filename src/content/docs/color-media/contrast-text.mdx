背景色から文字色を黒か白に決めるときは、`color: contrast-color(var(--_background));` と書きます。`contrast-color()` は、渡した色に対してブラウザが黒か白を選んで返す関数です。Safariが対応したのはバージョン26からなので、この書き方を使うのは、対象の環境がSafari 26以上の場合です。また、不透明で、選ばれる文字色とのコントラスト比を確認済みの背景色に使います。

Safari 18系にも対応する場合や、切り替える明度や色を自分で決めたい場合は、相対カラー構文と `sign()` で書きます。式は `color: oklch(from var(--_background) sign(0.7 - l) 0 h);` です。背景の明度が0.7より低ければ白に、0.7以上なら黒になります。画像の上の文字に敷く、画像が表示されなかったときの背景色は、文字色から決めます。まず `sign()` で書き、`contrast-color(currentColor)` に対応する環境ではそれで上書きします。

## 背景色ごとに文字色を指定すると起きること

ボタンやバッジのように、色のバリエーションを持つ部品を考えます。バリエーションを足すたびに、背景色と文字色の組み合わせを1つずつ決めることになります。

```css title="🙅‍♂ Not Recommended: バリエーションごとに文字色を指定する" issue="convention"
/* 🙅‍♂ Not Recommended */
._badge {
  &[data-variant="info"] {
    background-color: var(--color--accent--600);
    color: oklch(100% 0 none);
  }

  &[data-variant="warning"] {
    background-color: var(--color--accent--400);
    color: oklch(0% 0 none);
  }
}
```

このコードでは、背景色を変えるたびに文字色も見直す必要があります。`--color--accent--400` を少し暗い段階に替えたら、黒い文字のままでよいのか、白にすべきかを、誰かが判断しなければなりません。ダークモードで背景色の段階が替わる場合も同じで、配色ごとに文字色の組み合わせが増えます。

背景色がCSSの外から来る場合は、さらに困ります。CMSで編集者がラベルの色を選べる場合、選べる色を確認済みの候補に限っていても、どの候補が使われるかはCSSを書く時点では分かりません。この節で扱うのは、コントラスト比を確認済みの限られた背景色について、文字色を背景色から自動で決める書き方です。どのような色が来ても読みやすさを保証する方法ではありません。

## contrast-color() で黒か白を選ぶ

`contrast-color()` は、色を1つ受け取り、その色に対してブラウザが選んだ黒か白を返す関数です。背景色を渡せば、その上に置く文字色が決まります。

```css title="🙆‍♂ Recommended: 背景色から文字色を黒か白に決める（対象の環境がSafari 26以上のとき）"
@scope (.scoped.badge) to (.scoped) {
  :scope {
    --_background: var(--badge--background, var(--color--accent--600));

    background-color: var(--_background);

    /* Safari 26より前の環境では宣言が無効になる */
    color: contrast-color(var(--_background));
  }
}
```

この節の例は、背景色の明度と文字色の関係を見せるので、デフォルトの背景色に色の段階（`--color--accent--600` のようなプリミティブ）を直接書いています。コンポーネントのデフォルト値には、ふつうはセマンティクスのトークンを使います（「[10-4 デザイントークン](/components/design-tokens/#色のトークンの層)」）。

バリエーションの側では、`--badge--background` に背景色を渡すだけです。文字色は背景色から決まるので、色を1つ選べばバリエーションが1つ増えます。CMSから来る色を `style` 属性で渡す場合も、同じ指定で文字色が決まります。ただし、編集者やユーザーが任意の色を選べると、選ばれた文字色がコントラスト比の基準に届かない色も来るので、選べる色をコントラスト比を確認済みの候補に限っておきます。{/* 要確認: 出典なし */}

この書き方を使うのは、対象の環境がSafari 26以上の場合です。`contrast-color()` に対応していない環境では `color` の宣言が無効になり、文字色は親から継承した色のままになります。本文の濃い文字色を継承すれば、濃い背景のバッジの上で文字が背景に溶け込みます。`contrast-color()` は2026年4月にすべての主要なブラウザで使えるようになりましたが、Safariが対応したのはバージョン26からです。

黒と白のどちらが選ばれるかは、ブラウザが使うコントラストの計算方法で決まります。CSS Color Module Level 5は、計算方法をブラウザに任せています。ただし、主要なブラウザはWCAG 2.xのコントラスト比で選んでいます（Safariは公式のブログ、Firefoxはソースコードで確認）。明度0.57の青（`oklch(57% 0.16 255deg)`）では、WCAG 2.xのコントラスト比は白が約4.5:1、黒が約4.7:1なので、比の高い黒が選ばれます。

一方、知覚にもとづくコントラストのモデルであるAPCAでは、同じ青に対する評価が逆になります。コントラスト値（Lc）の絶対値は白が約76、黒が約33で、白い文字のほうが適切とされます。MDNも、この明度に近い青の背景に黒い文字を置くと、小さな文字では読みにくいと注意しています。中間の明度の色では、WCAG 2.xのコントラスト比の差がわずかなので、比の高いほうが読みやすいほうとは限りません。

そのため、`contrast-color()` で決めた文字色は、実際の表示で読みやすさを確かめます。読みにくい色が選ばれる背景色は、背景のトークンから除くか、次の見出しの `sign()` で切り替える明度を自分で決めます。

`contrast-color()` が返すのは、黒か白だけです。文字色に背景と同じ色味を加えたいときは、`color-mix()` と組み合わせ、返された黒か白に背景色を少し混ぜます。

```css title="🙆‍♂ Recommended: 黒か白に背景色を混ぜて、文字色に色味を加える（対象の環境がSafari 26以上のとき）"
@scope (.scoped.badge) to (.scoped) {
  :scope {
    --_background: var(--badge--background, var(--color--accent--600));

    background-color: var(--_background);
    color: color-mix(in oklab, contrast-color(var(--_background)) 85%, var(--_background));
  }
}
```

背景色を15%混ぜると、白い文字は背景の色相を帯びた淡い色に、黒い文字は背景の色相を帯びた濃い色になります。混ぜた分だけ文字と背景の明度が近づき、コントラスト比は下がります。次のデモの中の段では、5色のどれも15%混ぜて4.5:1以上でした。混ぜる割合を増やすときや背景色を替えるときは、組み合わせごとに確かめます。

このデモでは、明度の違う5つの背景色に対して、3つの書き方で文字色を決めています。上の段が `contrast-color()`、中の段がその黒か白に背景色を15%混ぜたもの、下の段が次の見出しで説明する閾値0.7の `sign()` です。

<Demo title="背景色から、文字色が黒か白に決まる" html={contrastHtml} css={contrastCss} scheme="light" />

どの色見本でも、CSSの側で指定しているのは背景色だけです。書き方によって結果が分かれるのは明度0.57の青で、`contrast-color()` の段では黒い文字に、`sign()` の段では白い文字になります。デモの色は、どの書き方で選ばれた文字色とのコントラスト比も4.5:1以上になるものを選んでいます。Safari 26より前のブラウザでは、上と中の段の文字色が親から継承した色になります。

## contrast-color() で足りないとき

対象の環境にSafari 18系が含まれる場合と、黒と白を切り替える明度や切り替えた先の色を自分で決めたい場合は、`contrast-color()` では足りません。どちらの場合も、相対カラー構文と `sign()` で書きます。

```css title="🙆‍♂ Recommended: 背景色の明度から、文字色を黒か白に決める（Safari 18系に対応するとき）"
@scope (.scoped.badge) to (.scoped) {
  :scope {
    --_background: var(--badge--background, var(--color--accent--600));

    background-color: var(--_background);
    color: oklch(from var(--_background) sign(0.7 - l) 0 h);
  }
}
```

`sign()` は、中の値が正なら1を、負なら-1を、0なら0を返す関数です。これを相対カラー構文の明度の位置に書くと、元の色の明度によって、明度が1か、0以下の色を作れます。

背景の明度が0.7より低いと、`0.7 - l` が正になり、明度は1、つまり白になります。0.7以上なら明度は0か-1になります。`oklch()` の明度は0より小さくならないので、-1は0に切り詰められ、どちらも黒になります。彩度を0にしているので色相は見た目に影響せず、元の色の `h` をそのまま渡しています。

`sign()` は、2025年6月にすべての主要なブラウザで使えるようになりました。相対カラー構文もSafari 18から使えるので、本書の対象のブラウザ（Safari 18系の最終版以降）でこの書き方が動きます。なお、`sign()` を相対カラー構文の中で使う書き方は、Chrome 153と154でだけ確認しています。{/* 要検証: ブラウザ。Safari 18.6 と 26 で、相対カラー構文の中の sign() が働くか */}

<Baseline id="abs-sign" name="sign()" />

切り替える明度（閾値）は、式の中の0.7を書き換えて決められます。本書が0.7にする理由は、次の見出しで説明します。切り替えた先の色も決められます。ブランドの濃い色や、少しだけ色味のある白を文字色にしたいときは、`sign()` の結果を明度の段階に置き換えます。

```css title="🙆‍♂ Recommended: 文字色を、明度0.2と0.95の色味のある色で切り替える"
@scope (.scoped.badge) to (.scoped) {
  :scope {
    --_background: var(--badge--background, var(--color--accent--600));

    background-color: var(--_background);
    color: oklch(from var(--_background) calc(0.2 + 0.75 * max(sign(0.7 - l), 0)) 0.02 h);
  }
}
```

`max(sign(0.7 - l), 0)` は、背景の明度が0.7より低ければ1に、0.7以上なら0になります。これを0.75倍して0.2を足すので、文字色の明度は0.95か0.2になり、彩度0.02で背景の色相を少しだけ帯びます。`color-mix()` で混ぜる方法と違い、文字色の明度と彩度が背景色によらず決まるので、コントラスト比を見積もりやすくなります。{/* 要確認: 出典なし */}ただし、式が長くなるので、決まった組み合わせが少ないなら、トークンで組み合わせを決めたほうが読みやすくなります。

## 閾値を0.7にする理由

閾値は、`sign()` の式で、どの明度から黒い文字にするかの境目です。0.7は読みやすさを優先した本書の方針で、WCAG 2.xのコントラスト比の高いほうを選ぶ値ではありません。コントラスト比の高いほうを選ぶなら、無彩色の背景では、白とのコントラスト比と黒とのコントラスト比が等しくなる明度0.56あたりが閾値になります。本書はこれより上の0.7に置き、中間の明度の色では白を選びます。

0.56にしないのは、中間の明度では、WCAG 2.xのコントラスト比が実際の読みやすさと一致しないことがあるからです。「[contrast-color() で黒か白を選ぶ](#contrast-color-で黒か白を選ぶ)」で見た明度0.57の青では、比の高い黒が選ばれますが、APCAとMDNは白い文字のほうを適切としています。この例は0.7という数値の根拠ではなく、閾値を0.56より上に置くのは、中間の明度の色では白い文字のほうを読みやすく感じることが多いという本書の判断によります。どの色相や文字サイズでも0.7が最適とは限らないので、使う背景色ごとに表示を確かめます。

その代わり、0.7で白が選ばれる色の一部は、通常の大きさの文字の基準（4.5:1）に届きません。本書のルールでは、文字と背景のコントラスト比はWCAG 2.2のAAを満たす必要があります。そこで、文字を載せる背景のトークンを選ぶ段階で、選ばれる文字色とのコントラスト比を確かめ、基準に届かない色を除きます。無彩色の背景では、次のようになります。

| 背景の明度（無彩色） | 選ばれる文字色 | コントラスト比 | 背景のトークンに |
|---|---|---|---|
| 0.55 | 白 | 約4.9:1 | 使える |
| 0.6 | 白 | 約3.9:1 | 使わない |
| 0.65 | 白 | 約3.2:1 | 使わない |
| 0.69 | 白 | 約2.8:1 | 使わない |
| 0.7 | 黒 | 約7.9:1 | 使える |
| 0.75 | 黒 | 約9.4:1 | 使える |

明度がおよそ0.57から0.7までの色は、白が選ばれて基準を下回るので、背景のトークンに使いません。この範囲が使えないのは色そのものの性質ではなく、本書の閾値で白が選ばれるからです。明度0.69の灰色でも、黒を選べばコントラスト比は約7.6:1あります。有彩色では範囲の境目が色相によって少し動くので、実際のトークンごとに確かめます。

どちらの書き方も、黒と白のうちどちらかを選ぶだけで、選んだ色が基準を満たすことまでは保証しません。最後は、実際の背景色と文字色の組み合わせでコントラスト比を確かめます。コントラストの基準と確かめ方は「[15-5 強制カラーモードとコントラスト](/color-media/forced-colors/)」で説明しています。知覚にもとづくコントラストのモデルであるAPCAで0.7を比べた結果は、ページの最後の「[閾値をAPCAで比べる](#閾値をapcaで比べる)」にまとめています。

## 文字色から背景色を決める

`contrast-color()` は、背景色から文字色を決めるだけでなく、向きを逆にして、文字色から背景の色を決めるのにも使えます。文字色が先に決まる部品では、文字色と対比する黒か白を求め、文字色を少しだけ混ぜて背景色にします。

```css title="🙆‍♂ Recommended: 文字色と対比する黒か白に、文字色を混ぜて背景色を作る（対象の環境がSafari 26以上のとき）"
@scope (.scoped.toast) to (.scoped) {
  :scope {
    --_foreground: var(--toast--foreground, var(--foreground--base));
    --_contrast: contrast-color(var(--_foreground));

    background-color: color-mix(in oklab, var(--_foreground), var(--_contrast) 90%);
    color: var(--_foreground);
  }
}
```

`--_contrast` が、文字色と対比する黒か白です。背景色は、その黒か白に文字色を10%だけ混ぜて作ります。暗い文字色なら淡い背景に、明るい文字色なら暗い背景になります。枠線や種類ごとの色の切り替えを含めたトーストの完成例は、「[15-2 相対カラー構文で派生色を作る](/color-media/relative-color/)」の「文字色1つからトーストの配色を作る」で説明しています。この節で扱うのは、`contrast-color()` が受け持つ2つの宣言だけです。

Safari 26より前の環境でも、未登録のカスタムプロパティ `--_contrast` は、未対応の関数を含む値をそのまま保持します。無効になるのは、その値を `var()` で代入した `background-color` を色として計算する段階です。計算値は無効になり、初期値の `transparent` になるので、背景色が付きません。文字色は残りますが、読めるかどうかはページの背景で決まります。Safari 18系に対応するときは、`--_contrast` の値を `oklch(from var(--_foreground) sign(0.7 - l) 0 h)` に替えます。背景色が付くので、この置き換えは必須です。背景に文字色を混ぜるとコントラスト比は下がるので、色ごとに確かめます。

## 画像が表示されなかったときの背景色

画像の上に文字を載せる部品では、画像が表示されなかった場合に備えて、文字色と対比する背景色を敷きます。文字色は先に決まっているので、背景色はその文字色から求めます。`contrast-color(currentColor)` に未対応の環境では宣言が無効になるので、同じ値を `sign()` で先に書いておきます。

```css title="🙆‍♂ Recommended: 画像が表示されなかった場合の背景色を、文字色から決める" from="color-media/image-fallback"
@scope (.scoped.image-banner) to (.scoped) {
  :scope {
    --_foreground: var(--image-banner--foreground, oklch(100% 0 none));

    display: block grid;
    grid-template-areas: "--pile";
    background-color: oklch(from currentColor sign(0.7 - l) 0 h);
    background-color: contrast-color(currentColor);
    color: var(--_foreground);

    & > img,
    & > ._body {
      grid-area: --pile;
    }
  }
}
```

`currentColor` は、その要素の `color` の値です。白い文字なら黒い背景が、濃い文字なら白い背景が敷かれるので、画像に合わせて文字色を変えても、背景色を書き直す必要がありません。1つ目の宣言が、Safari 18系を含む環境で背景色を保証します。2つ目の `contrast-color(currentColor)` に対応する環境では、後ろの宣言が前の宣言を上書きし、対応しない環境では無効になって1つ目が残ります。画像が表示されれば、背景色は画像に隠れて見えません。画像と本文をグリッドの同じエリアに重ねる方法と、写真を `<img>` で置く理由は、「[16-1 画像の配置と比率](/decoration/images/)」で説明しています。

次のデモでは、画像の上に文字を載せたバナーで、画像を表示できなかった場合の背景色を文字色から決めています。

<Demo title="画像を表示できなくても、文字色と対比する背景色の上で文字が読める" html={imageFallbackHtml} css={imageFallbackCss} />

白い文字のバナーには黒い背景が、濃い文字のバナーには白い背景が敷かれます。CSSで指定しているのは文字色だけで、背景色は書いていません。

`contrast-color(currentColor)` だけを書くと、Safari 18系では背景色が付かず、白い文字が明るいページの背景に溶け込みます。画像が読み込めなかったときに文字が読めなくなるので、「画像が失敗したときだけの問題」として省くことはできません。`sign()` の式を先に置くのは、そのためです。画像の上の文字には、画像のどの部分とも対比するよう白や黒に近い色を選ぶので、WCAG 2.xとAPCAで判定が分かれる中間の明度の色は、ふつう渡されません。{/* 要確認: 出典なし */}

## 背景色と文字色の組をトークンにする方法と比べる

バリエーションの数が少なく、背景色がどれも自分たちのトークンで決まっているなら、文字色を自動で決めずに、背景色と文字色の組をトークンにする方法も正しく動きます。「[背景色ごとに文字色を指定すると起きること](#背景色ごとに文字色を指定すると起きること)」のNot Recommendedの例との違いは、組を部品のCSSではなくトークンのファイルで、名前を付けて管理することです。

```css title="背景色と文字色の組を、セマンティクスのトークンにする"
:root {
  --background--info: var(--color--accent--600);
  --foreground--on-info: oklch(100% 0 none);
  --background--warning: var(--color--accent--400);
  --foreground--on-warning: oklch(0% 0 none);
}
```

部品は、`--background--warning` と `--foreground--on-warning` を名前で参照するだけです。背景色の段階を替えるときは、トークンのファイルで隣にある文字色も見直し、組ごとのコントラスト比を確かめます。ダークモードでも、組ごとに値を決めます。本書のデモの共通トークンでも、accentの背景の `--background--accent` と、その上に載せる文字色の `--foreground--on-accent`（白）を組にしています。白の文字と4.5:1以上の差を保つため、`--background--accent` はダークモードでもライトモードと同じ段階の色にしています。

この方法では、文字色を1色ずつ決められ、ブラウザの対応状況の差も、WCAG 2.xとAPCAで判定が分かれる中間の明度の問題も起きません。代わりに、背景色を1つ足すたびに文字色のトークンも1つ足し、確かめる組が増えます。そのため、決まった数のバリエーションにはトークンの組を使い、背景色の候補が多いときや、CMSのように背景色がCSSの外から来るときに、この節の書き方で文字色を決めます。{/* 要確認: 著者の判断。トークンの組と、背景色から文字色を決める書き方の使い分け */}

## 背景色から文字色を決めるときの注意

`contrast-color()` も `sign()` の式も、背景色が不透明であることを前提にしています。仕様は、渡された色を不透明な背景として使ったときの対比で白か黒を選ぶと定めています。Chromeで確かめたところ、`contrast-color()` は渡された色の透明度を無視し、ほとんど透明な黒（`rgb(0 0 0 / 0.1)`）にも白を選びました。半透明の背景色では、下にある色と重なった色が実際の背景になるので、白い文字が明るいページの上に載ることがあります。半透明の背景に文字を載せるときは、重なったあとの色で確かめます。

背景のトークンの値がライトとダークの配色で変わると、選ばれる文字色も配色ごとに変わります。これは背景色から文字色を決める書き方の利点ですが、確かめる組み合わせも配色の数だけ増えます。中間の明度に近い段階の色は、両方の配色で表示を確かめます。

文字以外の要素にも、同じ書き方を使えます。アイコンや枠線のように、背景の上に描く部品の色を決めるときも、背景色から黒か白を選べます。非テキストのコントラスト比の基準は、文字とは異なり3:1です。

## 閾値をAPCAで比べる

`sign()` の式に採用した0.7を、知覚にもとづくコントラストのモデルであるAPCAでも比べてみました。この比較は0.7を決めた根拠ではなく、決めた後に確かめたものです。計算にはAPCAのバージョン0.0.98G-4gの定数を使い、背景をOKLCHの色、文字を白（`#fff`）と黒（`#000`）として、コントラスト値（Lc）の絶対値を比べました。

無彩色の背景では、白い文字と黒い文字のLcの絶対値が等しくなるのは明度0.72あたりです。有彩色では色相によって少し動き、彩度0.12の色ではおよそ0.70から0.73の間でした。「[contrast-color() で黒か白を選ぶ](#contrast-color-で黒か白を選ぶ)」で挙げた明度0.57の青のLcも、同じ定数で計算した値です。0.7は、WCAG 2.xの交点の0.56よりも、APCAの交点の近くにあります。

sRGBで表示できる色を、OKLCHの彩度0から0.4、色相2度刻みで標本にして調べました。調べた範囲では、黒い文字のLcが白い文字を上回る最も低い明度は約0.69、白い文字のLcが黒い文字を上回る最も高い明度は約0.74でした。明度0.69未満の色では、APCAでも白い文字のほうが適切とされるので、0.7で白を選んでもAPCAの評価と食い違いません。一方、明度0.7から0.74までの色では、色相と彩度によっては白い文字のほうが適切とされますが、`sign()` の式は黒を選びます。閾値を0.69から0.74のどこに置いても、APCAの評価と食い違う色は残ります。{/* 要確認: 出典なし。0.7 の採用経緯は著者の資料にない。Lc と交点は 2026年10月6日に APCA 0.0.98G-4g の定数で再計算し、本文の値と一致した。0.69 と 0.74 は 2026年10月12日に同じ定数で、sRGB の色域の色（OKLCH の彩度0〜0.4、色相2度刻み）を調べた値。計算スクリプトは本文に添付していない */}

ほかの資料では、0.6前後のような別の閾値を見かけることもあります。閾値は、0.56に近いほどWCAG 2.xのコントラスト比に、0.72に近いほどAPCAの評価に従います。その間の値は、両者の中間で白と黒を切り替えるものです。APCAはまだWCAGの基準として採用されていないので、本書は、WCAG 2.2のAAを満たすかどうかを背景のトークンを選ぶ段階で確かめ、黒と白を切り替える明度はAPCAの交点の近くにしています。
