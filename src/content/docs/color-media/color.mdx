色は `oklch()` で定義します。`oklch()` は明度、彩度、色相の3つの値で色を表し、明度が見た目の明るさに近くなるように作られています。値から色の性質を読み取れ、色相を変えても明度をそろえれば同じくらいの明るさに見えるので、段階的なパレットを組み立てやすくなります。

16進数、`rgb()`、`hsl()` は、どれもsRGBという色空間の色を表す書き方です。sRGBの外にある、広色域の画面でしか表示できない鮮やかな色は表せません。グラデーションも、どの色空間で中間の色を作るかによって見え方が変わるので、補間の色空間を書きます。

## 16進数と hsl() で色を管理すると起きること

16進数の `#e4a153`（`rgb(228 161 83)` と同じ色）は、赤、緑、青の3つのチャンネルの強さを、それぞれ0から255までの値で書いたものです。値を見ても、どのくらい明るい色なのか、どの色相に近いのかは読み取れません。各チャンネルの値はガンマで符号化されていて、光の量にも、見た目の明るさにも比例しないからです。デザインの調整で「もう少し暗く」と頼まれても、3つの値をどう変えればよいかが分からず、カラーピッカーで選び直すことになります。

`hsl()` は、色相、彩度、明度で色を表します。色相を色相環の角度で、彩度と明度を割合で書くので、16進数より直感的に扱えます。しかし、HSLの明度は、人の目に見える明るさと一致しません。同じ明度50%でも、黄色は明るく、青は暗く見えます。色相だけを変えて段階をそろえたつもりでも、明るさがばらつきます。

デザインツールから受け取る値にも注意が要ります。多くのデザインツールは、HSLではなくHSB（色相、彩度、明るさ）で色を表示します。HSBの明るさとHSLの明度は別の尺度なので、数値をそのまま `hsl()` に書き写すと、違う色になります。

このほかに、`white` のような色の名前と、`#00000080` のような不透明度付きの16進数もあります。本書のStylelintの設定では、どちらも禁止しています（「[9-8 モダンな記法にそろえる](/notation/modern-syntax/)」）。

## oklch() で色を定義する

`oklch()` は、明度（L）、彩度（C）、色相（H）の3つの値で色を表します。明度は0%から100%、彩度は0から始まる数値、色相は角度です。明度が見た目の明るさに近くなるように設計されているので、色相が違っても、明度が同じならおおむね同じ明るさに見えます。

```css title="🙆‍♂ Recommended: 明度の段階を oklch() でそろえる"
:root {
  --color--neutral--100: oklch(97% 0 none);
  --color--neutral--500: oklch(55.6% 0 none);
  --color--neutral--900: oklch(20.5% 0 none);
  --color--accent--400: oklch(70% 0.15 260deg);
  --color--accent--500: oklch(62% 0.19 260deg);
  --color--accent--700: oklch(48% 0.2 260deg);
}
```

本書のデモのトークンでは、グレーを50から950までの11段階、アクセントカラーを400から700までの4段階で定義しています。グレーは彩度を0にして、明度だけを変えています。グレーの色相を `none` にする理由は、「[無彩色の色相を none にする](#無彩色の色相を-none-にする)」で説明します。アクセントカラーは色相を260deg（青）に固定し、明度を下げながら、中間の段階ほど彩度が高くなるように、山なりに値を変えています。トークンの一覧は、付録I「[デモの共通トークン](/appendix/demo-tokens/)」にあります。

`oklch()` を選ぶいちばんの理由は、値がそのまま色の性質を表していることです。`#c9853a` という値を見ても、元の色より暗いのかどうかは分かりません。`oklch(52% 0.16 250deg)` なら明度52%の青だと読み取れ、「もう少し明るく」という調整も明度の数値を上げるだけです。

似た書き方に `lch()` があります。`lch()` はCIE Labという色空間をもとにしていますが、青の領域では、彩度や明度を変えると色相が紫の側にずれる問題が知られています。`oklch()` のもとになったOklabは、この問題を改善する目的で2020年に作られた色空間です。本書は `lch()` ではなく `oklch()` を使います。

色の関数をスペースで区切ることや、色相に `deg` を付けることは、「[9-8 モダンな記法にそろえる](/notation/modern-syntax/)」で説明しています。色のトークンをプリミティブとセマンティクスの2層で持つ設計は、「[10-4 デザイントークン](/components/design-tokens/)」で扱います。

## 色空間と広色域

色空間は、画面で表せる色の範囲と、その中の色の表し方を決めたものです。ウェブで長く使われてきたsRGBは、人の目に見える色のうち、一部しか表せません。最近のスマートフォンやノートパソコンの多くは、Display P3という、sRGBより広い色空間の色を表示できます。

16進数、`rgb()`、`hsl()` は、sRGBの色しか表せません。値の上限がsRGBの範囲に合わせて決まっているからです。広色域の画面でも、これらで書いた色はsRGBの範囲を超えません。

`oklch()` の彩度には上限がないので、sRGBの外の色も書けます。同じ値でも、広色域の画面ではより鮮やかに表示され、sRGBの画面ではブラウザが表示できる色に置き換えて描画します。Display P3の色空間の値を直接書くときは、`color(display-p3 1 0.5 0)` のように `color()` 関数を使います。`color()` の各チャンネルは、0から255ではなく0から1の数値で書きます。

<Baseline id="color-function" name="color()" />

表示できる範囲を超えた色は、ブラウザが近い色に置き換えます。この置き換えをガマットマッピングといいます。置き換えたあとの色はブラウザが決めるので、デザインツールで見た色と画面の色が違って見えることがあります。デザインツールから受け取った色を `oklch()` に変換したら、彩度が上がりすぎていないかを確かめます。sRGBを超える彩度を使うかどうかは、デザイナーと合意して決めます。

## グラデーションは補間の色空間を指定する

グラデーションの途中の色は、2色のあいだを補間して作られます。補間の色空間を書かないときに使われる色空間は、色の書き方で決まります。`#rrggbb` や `rgb()`、`hsl()` のような旧来の書き方の色だけをつなぐと、互換性のためにsRGBのチャンネルごとに補間され、彩度の高い2色の中間が灰色にくすみます。`oklch()` などの新しい書き方の色を含むと、既定の色空間はOklabになります。

本書では、色の書き方にかかわらず、`in oklch` のように補間の色空間を書きます。既定に任せると、色の書き方を変えただけで中間の色が変わり、どの補間を意図したのかがコードから読み取れないからです。`oklch` で補間すると、知覚に近い明度、彩度、色相で中間の色が作られます。黄色と青のように色相が離れた2色でも、中間が灰色にくすみません。

```css title="🙆‍♂ Recommended: グラデーションに補間の色空間を書く"
._hero {
  background-image: linear-gradient(in oklch, oklch(85% 0.17 95deg), oklch(55% 0.2 260deg));
  background-color: oklch(85% 0.17 95deg);
}
```

次のデモでは、同じ黄色と青を、3つの色空間で補間しています。1本目の `in srgb` は、16進数や `rgb()` の色だけをつないだときの既定と同じ補間です。

<Demo title="同じ2色を、sRGB、Oklab、Oklch で補間したグラデーション" html={gradientHtml} css={gradientCss} variant="neutral" scheme="light" />

`in srgb` の帯は、中央が灰色に近くなります。sRGBでは赤、緑、青のチャンネルを別々に補間するので、黄色と青の中間で3つのチャンネルが近い値になり、彩度が失われるからです。`in oklab` では中央のくすみが和らぎ、`in oklch` では色相環を回るので、緑を通って彩度を保ったまま青に変わります。

デモの3本は、どれも `oklch()` で書いた同じ2色をつないでいます。色の書き方は同じでも、補間の色空間を変えると中間の色も変わります。

`oklch` のような極座標の色空間では、色相の補間の経路が2通りあります。`shorter hue` が初期値で、色相環の短いほうを通ります。長いほうを通したいときは `in oklch longer hue` と書きます。`color-mix()` で使う `oklab` は、色相ではなく明度と2つの色の軸で補間するので、色相の経路を選ぶ必要がありません。ただし、色相が離れた2色では、中間の彩度が下がることもあります。グラデーションには彩度を保ちやすい `oklch` を勧めます。中間のくすみを気にしない組み合わせなら、`oklab` でも構いません。

色空間の指定に対応していないブラウザは、`in oklch` を書いた `background-image` の宣言を丸ごと無視します。上のコード例のように `background-color` を用意しておけば、背景が何も表示されない状態を避けられます。

<Baseline id="gradient-interpolation" />

グラデーションの種類の選び方、境界をくっきり分ける停止位置、繰り返す模様の描き方は、「[16-6 グラデーションを描く](/decoration/gradients/)」で説明しています。

## 無彩色の色相を none にする

グレーのような無彩色を `oklch()` で書くときは、色相を `0deg` ではなく `none` にします。`none` は、その成分の値が欠落していることを表すキーワードです。彩度が0の色は色相を変えても見た目が変わらないので、`oklch(90% 0 0deg)` と `oklch(90% 0 none)` は同じグレーに見えます。違いが出るのは、ほかの色との間を補間するときです。

```css title="🙅‍♂ Not Recommended: グレーの色相を 0deg と書いて、青と oklch で混ぜる" issue="behavior"
/* 🙅‍♂ Not Recommended */
._badge {
  background-color: color-mix(in oklch, oklch(90% 0 0deg), oklch(55% 0.2 260deg));
}
```

```css title="🙆‍♂ Recommended: グレーの色相を none にして、青の色相のまま混ぜる"
._badge {
  background-color: color-mix(in oklch, oklch(90% 0 none), oklch(55% 0.2 260deg));
}
```

`in oklch` の補間では、明度、彩度、色相を成分ごとに補間します。グレーの色相を `0deg` と書くと、その0が値として使われ、青の260degとの間で色相も動きます。初期値の `shorter hue` は色相環の短いほうを通るので、色相は360degから260degへ、赤紫と紫を経由します。彩度も0から上がっていくため、中間の色は紫みを帯びます。色相を `none` にすると、欠落した色相は補間の相手の値で補われ、中間の色は260degの青のまま、明度と彩度だけが変わります。

次のデモでは、明度90%のグレーと青を、`color-mix(in oklch, …)` で青の割合を0%、25%、50%、75%、100%にして混ぜています。上の段はグレーの色相を `0deg` で、下の段は `none` で書いています。上の段の中間の3色は紫みを帯び、50%の色の色相は310degになります。下の段は、どの色も色相が260degのままで、グレーから青へ変わります。

<Demo title="色相を 0deg と none で書いたグレーを、青と oklch で混ぜた色" html={achromaticHtml} css={achromaticCss} variant="neutral" scheme="light" />

この違いが出るのは、色相を成分に持つ色空間で補間するときです。`color-mix()` を `in oklab` で書くと、色相ではなく明度と2つの色の軸で補間するので、`0deg` でも `none` でも同じ色になります。トランジションとアニメーションの色も既定ではOklabで補間され、どちらで書いても途中の色は変わりませんでした。16進数や `rgb()` で書いたグレーは、`oklch` へ変換した時点で色相が欠落した値になるので、`color-mix(in oklch, #e5e5e5, …)` は青の色相のまま混ざります。問題になるのは、`oklch()` で色相を数値として書いたときです。

グラデーションの `in oklch` は、Chromeでは `0deg` と `none` で同じ描画になり、紫みは出ませんでした。ただし、ほかのブラウザで同じになるかは確かめていません。{/* 要検証: ブラウザ。Safari と Firefox で、色相を 0deg で書いたグレーを含む in oklch のグラデーションと color-mix(in oklch, …) の中間の色 */} 結果がブラウザの扱いで変わらないように、無彩色のトークンは、補間での使われ方を問わず `none` で書きます。

相対カラー構文で、グレーから有彩色を作るときは別の注意が要ります。相対カラー構文では、元の色の欠落した成分は0として扱われます。`oklch(from var(--color--neutral--100) l 0.1 h)` のようにグレーに彩度を足すと、色相は0degになり、赤紫がかった色になります。グレーから有彩色を作るときは、色相を `h` で受け取らず、数値で書きます。相対カラー構文の使い方は「[15-2 相対カラー構文で派生色を作る](/color-media/relative-color/)」で説明しています。

## 色の形式を選ぶときの注意

`oklch()` の彩度の上限は、色相と明度によって変わります。明度が0%や100%に近い色は、彩度を上げても鮮やかになりません。範囲を超えた値を書いてもエラーにはならず、ブラウザが表示できる色に置き換えるだけなので、値が範囲内かどうかはコードからは分かりません。カラーピッカーなどのツールで、sRGBとDisplay P3の範囲を確かめながら値を決めます。

既存のサイトで16進数の色を使っているなら、トークンの定義から `oklch()` に書き換えます。値の変換はツールで行い、変換した値の小数点以下は、見た目が変わらない範囲で丸めます。コンポーネントに直接書かれた16進数の色も、セマンティクスのトークンに置き換えます。{/* 要確認: 出典なし */}

この節で扱ったのは、色そのものの書き方です。元の色から透過させた色や暗い色を作る方法は「[15-2 相対カラー構文で派生色を作る](/color-media/relative-color/)」で、背景色から文字色を決める方法は「[15-3 背景から文字色を決める](/color-media/contrast-text/)」で、ダークモードの配色は「[15-4 ダークモード](/color-media/dark-mode/)」で説明します。
