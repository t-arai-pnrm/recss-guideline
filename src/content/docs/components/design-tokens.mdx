色、余白、イージング、z-indexのように、サイト全体で意味を持つ値は「デザイントークン」として名前を付け、`:root` のカスタムプロパティにまとめます。名前は `--color--neutral--500` や `--spacing--md` のように `--<分類>--<名前>` の形にします。

色と文字の役割のトークンだけは、生の値のプリミティブと、役割を表すセマンティクスの2層に分けます。余白のトークンは単位なしのピクセル相当の数値で持ち、使う場所で `px` や `rem` に変換します。反対に、1回しか使わない値や、特定のコンポーネント専用の値はトークンにしません。何でもトークンにすると、CSSから参照できるデザインの取り決めとしての意味が薄れます。

## 値に名前がないと起きること

トークンを用意せずに、値を直接書いたCSSを考えます。

```css title="🙅‍♂ Not Recommended: デザインの値を直接書く" issue="convention"
/* 🙅‍♂ Not Recommended */
.site-header {
  z-index: 9999;
  background-color: #f5f5f5;
  transition-duration: 300ms;
  transition-property: background-color;
  transition-timing-function: cubic-bezier(0.22, 1, 0.36, 1);
}

.site-footer {
  background-color: #f4f4f4;
}
```

このコードからは、値の意味が読み取れません。`9999` はほかの要素とどういう関係の値なのか、`cubic-bezier()` はどのくらいの強さの動きなのかが、数字を見ても分かりません。ヘッダーとフッターの背景色がわずかに違うのが、意図したものなのか、書き写したときの誤りなのかも判断できません。

値を変えるときにも困ります。「グレーの背景を少し明るくしたい」という依頼が来たら、ファイルをまたいで同じような値を探し、1つずつ直すことになります。z-indexでは、ほかの要素より手前へ出そうとして、`9999` や `10000` のような値の積み増しが始まりがちです。

デザイントークンは、こうした値に名前を付けて1か所にまとめたものです。トークンの一覧は、CSSから参照できるデザインガイドとして機能します。コードを書く人は、一覧の値から選ぶだけで、デザインの取り決めどおりのスタイルが書けます。

## トークンの名前の付け方

トークンの名前は、先頭に分類を置いた `--<分類>--<名前>` の形にします。分類には、`color`（色）、`spacing`（余白）、`rounded`（角丸）、`shadow`（影）などを使います。文字サイズの `font-size`、行の高さの `leading`、文字の太さの `font-weight`、イージングの `ease`、再生時間の `duration`、重なり順の `z` も分類の例です。

```css title="🙆‍♂ Recommended: 分類を先頭に置いて名前を付ける"
:root {
  --color--neutral--100: oklch(97% 0 none);
  --color--neutral--900: oklch(20.5% 0 none);
  --color--accent--600: oklch(54% 0.22 260deg);
  --spacing--xxs: 8;
  --spacing--sm: 16;
  --spacing--md: 24;
  --spacing--xxl: 64;
  --rounded--md: 8px;
  --rounded--full: calc(infinity * 1px);
  --font-size--md: 16;
  --font-weight--bold: 700;
  --ease--out-quint: cubic-bezier(0.22, 1, 0.36, 1);
  --duration--base: 160ms;
  --z--header: 200;
}
```

区切りに `--` を使うのは、`font-weight` や `out-quint` のように、分類や名前そのものにハイフンが入るからです。`--` で区切っておけば、どこまでが分類でどこからが名前なのかを見分けられます。分類を先頭に置くと、エディタの入力補完でも同じ分類のトークンがまとまって表示されます。サイズの段階には、`xxxs`、`xxs`、`xs`、`sm`、`md`、`lg`、`xl`、`xxl`、`xxxl` の名前を使っています。

色のように、デザインの中での役割を表すトークンは、`--<役割>--<バリエーション>` の形にします。`--background--base` や `--foreground--muted` のように、先頭に `background`（背景）や `foreground`（文字やアイコン）といった役割を置きます。文字の役割は、`--text--body--font-size` のように `--text--<役割>--<プロパティ>` の形にします（後の「文字のトークンの層」）。コンポーネントの公開プロパティも `--card--radius` のように `--` で区切りますが、こちらは先頭がコンポーネントの名前です。公開プロパティの命名は「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」で説明します。

## 余白のトークン

余白のトークンは、単位を付けずに、ピクセル相当の数値で定義します。使う場所で `calc(var(--spacing--md) * 1px)` や `calc(var(--spacing--md) / 16 * 1rem)` のように、そのときに適した単位へ変換します。

```css title="🙆‍♂ Recommended: 余白のトークンを、使う場所で単位に変換する"
@scope (.scoped.media-object) to (.scoped) {
  :scope {
    display: block grid;
    gap: calc(var(--spacing--sm) * 1px);
    padding: calc(var(--spacing--md) * 1px);
  }
}
```

単位を固定しないのは、同じ大きさの余白でも、使う場所によって選ぶべき単位が違うからです。たとえば `padding` は `px` で指定します。ユーザーが文字サイズを大きくしたとき、`padding` まで広がると1行の文字数がさらに減り、読みにくくなるからです。段落の間の余白は、文字サイズに合わせて広がるほうが自然なので `rem` にします。単位の選び方は「[6-1 pxとremを使い分ける](/values/px-and-rem/)」で説明しています。

レスポンシブな環境では、余白が `%` やコンテナ単位と組み合わさることも多く、`px` と `rem` の二択では片付けられません。トークンを単なる数値にしておけば、`calc(var(--spacing--md) * 1px)` でpxに、`calc(var(--spacing--md) / 16 * 1rem)` でremに変換できます。`clamp()` の最小値や最大値の式にも、そのまま使えます。Tailwind CSSの作者も、単位付きで余白のスケールを設計したことを後悔していると述べています。

余白のスケールは、`xxxs` の4から `xxxl` の80まで、4、8、12、16、24、32、40、64、80の9段階にしています。スケールに沿う余白は、トークンで書きます。ただし、`%` や `cqi` と組み合わせて計算する余白は、その場に直接書いてかまいません（ルール `use-defined-tokens`）。レスポンシブな余白には、こうした組み合わせが多いからです。

## 色のトークンの層

色は、プリミティブ、セマンティクス、ユニークの3層で考えます。プリミティブは生の色の値で、`--color--neutral--50` から `--color--neutral--950` のように、色相ごとの明るさの段階として定義します。セマンティクスは、背景、文字、枠線、リンク、フォーカスリングのように、デザインの中での色の意味を表すトークンです。

グローバルなトークンとして定義するのは、プリミティブとセマンティクスの2層だけです。デザインで定義されていない固有の色（ユニーク）は、コンポーネントの内部プロパティか、直接書いた値で扱います。

次の例は、本書のデモで使っている色のトークンの一部です。プリミティブのneutralには、Tailwind CSSのneutralの50〜950と同じoklchの値を使っています。セマンティクスは、背景の `--background--*`、文字の `--foreground--*`、枠線の `--border--*` に分け、それぞれがプリミティブを参照します。

```css title="🙆‍♂ Recommended: セマンティクスのトークンから、プリミティブを参照する"
:root {
  --color--neutral--50: oklch(98.5% 0 none);
  --color--neutral--100: oklch(97% 0 none);
  --color--neutral--400: oklch(70.8% 0 none);
  --color--neutral--500: oklch(55.6% 0 none);
  --color--neutral--900: oklch(20.5% 0 none);
  --background--base: light-dark(var(--color--neutral--50), var(--color--neutral--900));
  --background--surface: light-dark(oklch(100% 0 none), oklch(from var(--color--neutral--900) calc(l + 0.05) c h));
  --foreground--base: light-dark(var(--color--neutral--900), var(--color--neutral--100));
  --foreground--muted: light-dark(var(--color--neutral--500), var(--color--neutral--400));
  --border--base: color-mix(in oklab, var(--foreground--base) 12%, transparent);
}
```

セマンティクスの層があると、ライトモードとダークモードのような切り替えを、`light-dark()` を使ってトークンの側で吸収できます。コンポーネントからは、意味の分かるセマンティクスのトークンを参照するのが基本です。こうしておけば、配色を変えるときもトークンの定義を直すだけで済みます。色の書き方は「[15-1 色の形式と色空間](/color-media/color/)」で、`light-dark()` は「[15-4 ダークモード](/color-media/dark-mode/)」で扱います。

背景のセマンティクスは、面の役割ごとに固定した4段階です。ページの `--background--base`、カードの `--background--surface`、メニューやポップオーバーの `--background--raised`、ダイアログの `--background--overlay` です。面の段階と影の組み合わせ方は「[16-5 面・影・角丸](/decoration/surfaces/)」で説明します。

枠線の `--border--base` は、プリミティブを選ばずに、`color-mix()` で文字色を12%だけ混ぜた半透明の色にしています。半透明の枠線は、下にある面の色と重なって見えるので、`--background--base` の上でも `--background--surface` の上でも、背景より少し濃い線になります。文字色がライトとダークで切り替われば枠線も追従するので、枠線のために面ごと、テーマごとの値を用意する必要がありません。

## 文字のトークンの層

文字の大きさと行の高さも、色と同じくプリミティブとセマンティクスの2層に分けます。プリミティブは `--font-size--*` と `--leading--*` の段階で、文字サイズは余白のトークンと同じく、単位なしのピクセル相当の数値で持ちます。セマンティクスは、`--text--<役割>--font-size` と `--text--<役割>--leading` の組です。役割には、display、title、subtitle、body、body-compact、captionの6つを使っています。

```css title="🙆‍♂ Recommended: 文字の役割ごとに、文字サイズと行の高さを組にする"
:root {
  --font-size--xs: 12;
  --font-size--sm: 14;
  --font-size--md: 16;
  --font-size--xl: 20;
  --font-size--xxxl: 28;
  --leading--tight: 1.25;
  --leading--snug: 1.4;
  --leading--normal: 1.6;
  --leading--relaxed: 1.75;
  --text--display--font-size: var(--font-size--xxxl);
  --text--display--leading: var(--leading--tight);
  --text--title--font-size: var(--font-size--xl);
  --text--title--leading: var(--leading--snug);
  --text--subtitle--font-size: var(--font-size--md);
  --text--subtitle--leading: var(--leading--snug);
  --text--body--font-size: var(--font-size--md);
  --text--body--leading: var(--leading--relaxed);
  --text--body-compact--font-size: var(--font-size--sm);
  --text--body-compact--leading: var(--leading--normal);
  --text--caption--font-size: var(--font-size--xs);
  --text--caption--leading: var(--leading--normal);
}
```

コンポーネントからは役割のトークンを参照し、文字サイズは使う場所で `rem` に変換します。文字サイズと行の高さは、同じ役割の組から取ります。

```css title="🙆‍♂ Recommended: 役割のトークンを参照し、文字サイズを使う場所で rem に変換する"
@scope (.scoped.notice) to (.scoped) {
  ._title {
    font-size: calc(var(--text--title--font-size) / 16 * 1rem);
    font-weight: var(--font-weight--bold);
    line-height: var(--text--title--leading);
  }

  ._body {
    font-size: calc(var(--text--body--font-size) / 16 * 1rem);
    line-height: var(--text--body--leading);
  }
}
```

役割の層を挟むのは、1つの文字サイズを複数の役割が使うからです。上の例では、subtitleとbodyがどちらも16の大きさで、行の高さだけが違います。コンポーネントが `--font-size--md` を直接参照していると、本文だけを15に変えたいとき、見出しの側まで変わってしまいます。役割を参照していれば、`--text--body--font-size` の参照先を変えるだけで済みます。大きな文字ほど行の高さを詰めるので、文字サイズと行の高さを組にしておくと、役割を選ぶだけで両方がそろいます。

文字サイズを単位なしにするのは、余白と同じく、使う場所で単位を選べるようにするためです。`clamp()` で流体的な文字サイズを作るときも、最小値と最大値を数値のまま計算できます。それぞれの役割をどこに使うか、和文の見出しと本文の大きさの決め方は、第14章「[タイポグラフィと和文組版](/typography/)」で扱います。

## 層を分けるトークンと分けないトークン

プリミティブとセマンティクスの2層に分けるのは、色（面、文字、枠線、重ね色、影の色）と文字の役割だけです。この2つには、層を分ける理由が2つあります。1つは、同じプリミティブを複数の役割が使うことです。neutralの900は、ライトモードの文字色にもダークモードの背景色にも使われます。もう1つは、ライトモードとダークモードの切り替えを、セマンティクスの側の `light-dark()` で吸収できることです。

余白、角丸、影の形、モーションは、1層のスケールのままにします。これらに役割の層を作ると、`--spacing--card-padding` や `--rounded--dialog` のように、1つのコンポーネントでしか使わない名前が増えます。1回しか使わない値をトークンにしないという基準（この節の後の「トークンにするもの、しないもの」）に反し、一覧から選ぶだけで取り決めに沿えるという利点も失われます。角丸なら、外側のパネルには `--rounded--lg`、内側の項目には `--rounded--md` を使う、という選び方の取り決めで足ります。

影は、形と色で扱いを分けます。`light-dark()` は色の値にしか使えないので、`box-shadow` の値全体をライトとダークで切り替えることはできません。そこで、オフセットとぼかしの形をスケールのトークンにし、各層の色だけをセマンティクスのトークンにして、形のトークンから参照します。次の例は、ダークモードで足す上辺のハイライトを省いて示しています。

```css title="🙆‍♂ Recommended: 影の形はスケールにし、各層の色だけをセマンティクスにする"
:root {
  --shadow--color: light-dark(oklch(0% 0 none / 6%), oklch(0% 0 none / 18%));
  --shadow--ring-color: light-dark(oklch(0% 0 none / 6%), oklch(0% 0 none / 24%));
  --shadow--sm:
    0 0 0 1px var(--shadow--ring-color),
    0 1px 1px -0.5px var(--shadow--color),
    0 3px 3px -1.5px var(--shadow--color);
}
```

色の値が `light-dark()` で切り替わるので、形のトークンはライトとダークで書き分けずに済みます。`filter` の `drop-shadow()` に渡す影は、`box-shadow` と値の書き方とぼかしの意味が違うので、同じ色のトークンを参照する別の形のトークンにします。段階ごとに層を足していく影の作り方は「[16-5 面・影・角丸](/decoration/surfaces/)」で説明します。

本書のデモは、この節で示した値のトークンを共通で読み込んで使っています。トークンの全文は「[付録I デモの共通トークン](/appendix/demo-tokens/)」にあります。

## イージングと再生時間

トランジションやアニメーションのイージングも、トークンにします。名前は `--ease--<方向>-<種類>` の形で、種類は動きの強さを表します。弱いものから順に `sine`、`quad`、`cubic`、`quart`、`quint`、`expo` と並び、ほかに加速と減速がゆるやかな `circ` や、少し行き過ぎてから戻る `back` があります。方向は、`in`（だんだん速く）、`out`（だんだん遅く）、`in-out`（両方）です。

```css title="🙆‍♂ Recommended: 動きの強さと方向が分かる名前を付ける"
:root {
  --ease--out-quad: cubic-bezier(0.25, 0.46, 0.45, 0.94);
  --ease--out-quint: cubic-bezier(0.22, 1, 0.36, 1);
  --ease--out-expo: cubic-bezier(0.16, 1, 0.3, 1);
  --ease--in-out-quint: cubic-bezier(0.86, 0, 0.07, 1);
  --ease--in-out-expo: cubic-bezier(0.87, 0, 0.13, 1);
  --duration--instant: 50ms;
  --duration--fast: 80ms;
  --duration--press: 120ms;
  --duration--base: 160ms;
  --duration--slow: 240ms;
  --duration--reveal: 600ms;
}
```

再生時間も、`--duration--fast`、`--duration--base`、`--duration--slow` のような段階のトークンにします。サイトの中で動きの速さがそろい、「全体的にもう少しゆっくりにしたい」という調整もトークンの値を変えるだけで済みます。本書では、`--duration--fast`（80ms）をホバー、`--duration--base`（160ms）をメニュー、`--duration--slow`（240ms）をダイアログに使います。続けて押すタブの切り替えには、`--duration--fast` から `--duration--base` までの値を選びます。キーボードのフォーカスでは動かしません。画面に現れる動きと出ていく動きには `out` 系、画面の上にあるものの移動には `in-out` 系を使います（「[18-3 イージングと再生時間](/motion/easing-and-duration/)」）。`--duration--instant` は動きを減らす設定で再生時間を短くするとき、`--duration--press` はボタンを押したときの縮小に使います。`--duration--reveal` は、要素が画面に入った時点で一度だけ再生する演出のための、長めの値です。弾むような動きのように `cubic-bezier()` で表せないイージングは、`linear()` 関数で定義し、再生時間とセットでトークンにします。

ドロワーやボトムシートのように、画面の端から大きく滑り込むUIには、専用のイージングを1つ用意します。`--ease--out-drawer: cubic-bezier(0.32, 0.72, 0, 1)` のように、出だしが速く、終わりにかけて長く減速する曲線にすると、移動する距離が長くても、操作にすぐ応じて動き出したように見えます。名前の種類の部分には、強さの代わりに用途を入れています。イージングのトークンの一覧と使い分けは、「[18-3 イージングと再生時間](/motion/easing-and-duration/)」にあります。

トランジションを書くときは、`transition-duration: var(--duration--base)` のように、個別のプロパティにトークンを渡します。動きを減らす設定への対応を含めたモーションの書き方は、第18章「[モーション](/motion/)」で説明します。

## z-indexのトークン

z-indexのトークンは、絶対的な値と相対的な値に分けて定義します。絶対的な値は、ヘッダーやフッターのようにページ全体で重なり順を保証する要素のためのもので、100の倍数で定義します。間を空けておけば、後から新しい要素を間に差し込めます。

```css title="🙆‍♂ Recommended: 絶対的な値は100刻み、相対的な値は1と-1にする"
:root {
  --z--forwards: 1;
  --z--backwards: -1;
  --z--footer: 100;
  --z--header: 200;
  --z--top: calc(infinity);
}
```

相対的な値は、コンポーネントの中で前後を入れ替えるための `--z--forwards`（1）と `--z--backwards`（-1）の2つだけです。`--z--top` は、スキップリンクやモーダル、読み込み中の表示のように、あらゆる要素より手前に出す必要があるものに使います。コンポーネントのどこにどの値を指定するかは「[10-2 コンポーネントの境界を守る](/components/boundaries/)」で説明しています。

`--z--top` の値を `calc(infinity)` にしておくのは、サードパーティのCSSへの保険でもあります。埋め込みのウィジェットや広告のCSSが大きなz-indexを指定していても、数値を積み増して競うことなく、モーダルや読み込み中の表示を手前に出せます。ただし、祖先のスタッキングコンテキストの順位までは超えられません。

ある要素を、ヘッダーのすぐ手前に重ねたいこともあります。そのときは、数値を直接書かず、トークンを基準にした計算で表します。こうすれば、ヘッダーの値を変えても関係が保たれます。

```css title="🙆‍♂ Recommended: トークンを基準にして、すぐ手前に重ねる"
@scope (.scoped.reading-progress) to (.scoped) {
  :scope {
    position: fixed;
    z-index: calc(var(--z--header) + 1);
  }
}
```

## トークンにするもの、しないもの

トークンにするのは、サイト全体で意味を持つ値だけです。1回しか使わない値や、特定のコンポーネントだけで使う値は、グローバルなトークンにしません。ただし、1つのコンポーネントの中で意味を持つ値は、内部プロパティ（`--_` で始まるカスタムプロパティ）にして名前を付けます。

たとえば、デザインの中で1か所だけ `line-height: 1.8` が使われていても、それを新しいトークンとして追加はしません。トークンに定義されている値ならトークンを使い、定義されていない特殊な値なら、その場に直接書きます。トークンが増えすぎると、一覧から選ぶだけで取り決めに沿うという、トークンの利点が失われます。

トークンは、分類ごとのファイル（`tokens/colors.css`、`tokens/sizes.css` など）に分けて書き、すべて `:root` に定義します。読み込むときは `tokens` レイヤーに入れます。

トークンの定義に `@property` は使いません。`@property` で型を登録すると、値が定義した要素で計算されてしまうなど、ふつうのカスタムプロパティとは振る舞いが変わるからです。`@property` の使いどころは「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」で説明します。

z-indexのトークンについては、`inherits: false` の `@property` で登録する方法を、私自身が登壇で勧めたことがあります。継承しない登録にしておけば、どこかで同じ名前を不意に上書きされても、影響がその要素だけにとどまるからです。本書ではこの方法を採らず、ほかのトークンと同じく、ふつうのカスタムプロパティで `:root` に定義します。z-indexのトークンだけ書き方を変えるより、`@property` は型やアニメーションが必要な場合に限るという線引きをそろえるほうを優先しました。

## 補足と注意点

トークンの規約を採用すると、CSSを書く人は、名前の2つの形（`--<分類>--<名前>` と `--<役割>--<バリエーション>`）、色の3つの層のうちどれをグローバルに置くか、サイズの段階の名前を覚えることになります。2層に分けるのが色と文字の役割だけであることも、覚えておく必要があります。単位なしの余白のトークンは、使うたびに `calc()` で単位を付ける手間も増えます。`gap: var(--spacing--md)` のように単位を付け忘れると、値が `24` になって宣言が無効になり、`gap` は初期値に戻ります。

トークンは `:root` にだけ定義するので、宣言は `tokens/` のファイルを `--spacing--md:` で、参照は `var(--spacing--md` で検索すれば見つかります。色はセマンティクスのトークンからプリミティブを参照しているので、実際の値に行き着くまで2回たどります。ブラウザの開発者ツールでは、スタイルの欄の `var()` から、参照しているカスタムプロパティの値を確かめられます。{/* 要検証: ブラウザ。Chrome、Firefox、Safariの開発者ツールで、var() の参照先の値をスタイルの欄から確認できること */}

トークンを作る手間に見合わないのは、この節の基準のとおり、1回しか使わない値と特定のコンポーネントだけで使う値です。デザインの側で段階が決まっていない値を、コードの側だけでトークンにすると、デザイナーと合意していない取り決めが増えます。{/* 要確認: 出典なし */}

チームに導入するときは、色とz-indexのトークンから始めます。{/* 要確認: 出典なし */}色は書き写しによるわずかな違いが起きやすく、z-indexは値の積み増しが起きやすいので、トークンにした効果がすぐに分かります。単位なしの余白は、変換の書き方を説明してから使い始め、イージングと再生時間は、動きを付けるコンポーネントが増えた段階で足します。
