コンポーネントの中で、置かれた場所の幅や操作の状態に合わせて複数の子要素の見た目を変えるときは、状態をカスタムプロパティのフラグとして1か所で立て、子孫の要素は `@container style()` で問い合わせます。幅による切り替えは `--_density: --compact` と `--spacious`、ホバーとフォーカスは `--_hocus: --false` と `--true` で表します。コンテナサイズクエリと状態のセレクタを書くのは、フラグを立てる要素のルールだけになります。

幅のフラグを使うのは、同じ閾値で見た目の変わる子要素が2つ以上あるときです。変わる要素が1つだけなら、その要素のルールにコンテナサイズクエリを直接書けば足ります。ホバーとフォーカスのフラグは、変わる子要素や擬似要素が1つでも立てますが、要素自身の見た目だけが変わるなら、状態のセレクタに直接書きます。この基準と、フラグを導入したときに増える概念は、「[補足と注意点](#補足と注意点)」で説明します。

この節は3つの段階で進めます。最初に、幅によって1つの要素の配置だけを変えるコンテナサイズクエリの基本を確かめます。次に、同じ幅で複数の子要素をそろって変えるために、幅のフラグを立てます。最後に、同じ形をホバーとフォーカスの状態に当てはめます。フラグを立てた要素自身はそのフラグを問い合わせられないという制約は、3つの段階を終えた後に、スタイルクエリがどの要素を問い合わせるかという仕組みから説明します。置き場所によって外からフラグを渡す方法と、子から親へ状態を伝えるときの `:has()` との使い分けは、「[10-7 置き場所と子の状態を伝える](/components/placement-and-child-states/)」で説明します。

## コンテナサイズクエリの基本

コンテナサイズクエリは、祖先の要素の幅を条件にして、スタイルを切り替える仕組みです。条件にできるのは、`container` プロパティでコンテナに指定した要素の幅だけです。本書では、コンポーネントのルートで `container: --scoped / inline-size` と書きます。`--scoped` はコンテナの名前で、`inline-size` はインライン方向の幅を問い合わせられるコンテナにする指定です。

```css title="🙆‍♂ Recommended: ルートをコンテナにし、子孫でその幅を問い合わせる"
@scope (.scoped.media-card) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
  }

  ._body {
    display: block grid;

    @container --scoped (inline-size >= calc(560 / 16 * 1rem)) {
      grid-template-columns: calc(240 / 16 * 1rem) 1fr;
    }
  }
}
```

子孫の要素は、`@container --scoped (inline-size >= …)` と書いて、`--scoped` という名前を持ついちばん近い祖先のコンテナの幅を問い合わせます。条件が成り立つ間だけ、中のスタイルが適用されます。ビューポートではなくコンテナの幅を調べるので、同じカードでも、広いメインエリアでは横並びに、狭いサイドバーでは縦積みになります。コンテナには必ず名前を付け、どのコンポーネントのルートでも `--scoped` にそろえます。名前と種類は `container` ショートハンドで1つの宣言にまとめ、条件には書字方向に依存しない `inline-size` を使います。閾値の式は、ユーザーの文字サイズが変わっても追従するよう、remで書きます。これらの規約の理由は、「[13-3 コンテナサイズクエリ](/responsive/container-size-queries/)」で詳しく説明しています。

ただし、コンテナ自身の見た目は、そのコンテナのサイズクエリでは変えられません。コンテナの幅を条件にコンテナ自身の幅や配置を変えられるとすると、変えた結果で幅が変わり、条件の成否が変わって、また見た目が変わるという循環が起こります。そのため `@container` は、コンテナの子孫のスタイルにだけ条件を付けます。ルートの `:scope` に `@container --scoped (…)` を書くと、ルート自身ではなく、さらに外側にある `--scoped` のコンテナ（外側のコンポーネントのルート）を問い合わせます。

```css title="🙅‍♂ Not Recommended: ルート自身のスタイルで、ルートの幅を問い合わせる" issue="behavior"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.media-card) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
    display: block grid;

    @container --scoped (inline-size >= calc(560 / 16 * 1rem)) {
      grid-template-columns: calc(240 / 16 * 1rem) 1fr;
    }
  }
}
```

そこで、コンテナサイズクエリは、最初の例の `._body` のようなルートの子孫に書きます。要素が自分自身を問い合わせられないという同じ形の制約は、スタイルクエリにもあり、フラグを立てた要素自身はそのフラグを問い合わせられません。この制約と、それに合わせた見た目の書き分けは、「[スタイルクエリが問い合わせる要素](#スタイルクエリが問い合わせる要素)」で説明します。

最初の段階で押さえるのは、2点です。1つは、子孫の `@container --scoped (…)` が、いちばん近い `--scoped` のルートの幅を問い合わせることです。もう1つは、そのクエリをルート自身ではなくルートの子孫のルールに書くことです。この2点を説明できれば、次の段階に進めます。

## 閾値が子要素に散らばる問題

画像と見出しを並べたカードで、置かれた場所が広いときに、配置、画像の縦横比、見出しの文字サイズをそろって変えたい場面を考えます。基本の書き方のまま、最初の例の `._body` と同じ形で `._thumbnail` と `._title` にもコンテナサイズクエリを書くと、同じ閾値が要素の数だけ並びます。

```css title="🙅‍♂ Not Recommended: 子要素ごとに同じ閾値のコンテナサイズクエリを書く" issue="convention"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.media-card) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
  }

  ._body {
    display: block grid;

    @container --scoped (inline-size >= calc(560 / 16 * 1rem)) {
      grid-template-columns: calc(240 / 16 * 1rem) 1fr;
    }
  }

  ._thumbnail {
    aspect-ratio: 16 / 9;

    @container --scoped (inline-size >= calc(560 / 16 * 1rem)) {
      aspect-ratio: 1;
    }
  }

  ._title {
    font-size: calc(18 / 16 * 1rem);

    @container --scoped (inline-size >= calc(560 / 16 * 1rem)) {
      font-size: calc(24 / 16 * 1rem);
    }
  }
}
```

閾値を変えるときは、この3か所をすべて直します。1か所でも直し忘れると、配置は横並びになったのに見出しは小さいままといった、どの幅のデザインにもない中間の状態ができます。閾値の式をカスタムプロパティに入れて共有する方法も採れません。コンテナサイズクエリの条件では `var()` を使わないのが本書のルールだからです（「[13-2 ブレイクポイントの決め方](/responsive/breakpoints/)」のルール `no-var-in-query`）。

## 幅の状態をフラグにして子孫に伝える

この重複は、幅の状態を1つの要素でカスタムプロパティのフラグとして立て、子孫の要素がそのフラグを問い合わせる形に変えれば解消します。`@container style(--_density: --spacious)` は、祖先の要素の `--_density` の計算値が `--spacious` のときにだけ、中のスタイルを適用する書き方です。カスタムプロパティは継承するので、フラグを立てた要素の子孫なら、どの深さの要素からでも同じ値を読めます。

```css title="🙆‍♂ Recommended: 閾値はフラグを宣言する要素に1回だけ書き、子孫はスタイルクエリで切り替える"
@scope (.scoped.media-card) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
  }

  ._body {
    --_density: --compact;

    display: block grid;

    @container --scoped (inline-size >= calc(560 / 16 * 1rem)) {
      --_density: --spacious;

      grid-template-columns: calc(240 / 16 * 1rem) 1fr;
    }
  }

  ._thumbnail {
    aspect-ratio: 16 / 9;

    @container style(--_density: --spacious) {
      aspect-ratio: 1;
    }
  }

  ._title {
    font-size: calc(18 / 16 * 1rem);

    @container style(--_density: --spacious) {
      font-size: calc(24 / 16 * 1rem);
    }
  }
}
```

コンテナサイズクエリを書くのは、フラグを宣言する `._body` のルールだけです。`._body` はデフォルト値の `--compact` をクエリの外に書き、クエリの中で `--spacious` に切り替えます。ほかの子孫は、狭い幅の見た目をクエリなしで書き、広い幅の見た目だけを `@container style(--_density: --spacious)` の中に書きます。閾値を変えるときに直すのは、`._body` の1か所です。3段階の切り替えが要るときだけ、`._body` に2つ目のクエリを足して、`--compact`、`--regular`、`--spacious` の順に切り替えます。

次のデモでは、同じイベントのカードをメインエリアとサイドバーに置いています。コンテナサイズクエリを書いているのは、フラグを宣言する `._layout` だけです。メインエリアのカードだけが閾値を超え、日付の位置、日の数字、見出し、説明の文字サイズがそろって切り替わります。デモのページは、720px以上で2つの領域を2対1の横並びにします。これは幅が768pxか1024pxのときの表示です。320pxでは2枚とも日付を見出しの上に置いたままで、480pxでは2つの領域が縦に積まれて2枚とも閾値を超え、1280pxではサイドバーのカードも閾値を超えるので、どちらのカードも切り替わった見た目になります。

<Demo title="1つのフラグで、日付の配置と文字サイズをそろえて切り替えるカード" html={densityHtml} css={densityCss} frame={densityFrame} />

`._date` の中の `._day` は、`._layout` から見て孫の要素ですが、`--_density` が継承されているので同じ形で問い合わせられます。`._layout` 自身の列と余白は、`--_density` を切り替えるのと同じサイズクエリの中で変えています。閾値の式は、日付の列、隙間、本文の最小幅に、切り替えた後の左右の `padding` を足した `calc(80 / 16 * 1rem + 24px + 240 / 16 * 1rem + 24px * 2)` です。文字サイズが標準なら392pxになります。`padding` を式から省くと、切り替えた直後の幅で本文の列が240pxに届きません（「[13-2 ブレイクポイントの決め方](/responsive/breakpoints/)」）。

2つ目の段階で押さえるのは、閾値を書くのがフラグを宣言する1つのルールだけになることと、ほかの子孫は狭い幅の見た目をクエリなしで書き、広い幅の見た目だけを `@container style()` の中に書くことです。閾値を変えるときに直す場所を1か所と答えられれば、次の段階に進めます。

## ホバーとフォーカスの状態をフラグにする

ホバーとフォーカスでも、幅と同じ形の重複が起こります。リンクにホバーしたとき、中のアイコンを動かし、ラベルに下線を引くとします。従来は、親の状態のセレクタの後ろに子孫結合子で子を続けて選んでいました。

```css title="🙅‍♂ Not Recommended: 親の状態のセレクタから、子孫結合子で子を選ぶ" issue="convention"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.link-menu) to (.scoped) {
  a {
    &:any-link:hover ._icon {
      @media (any-hover) {
        translate: 4px;
      }
    }

    &:focus-visible ._icon {
      translate: 4px;
    }

    &:any-link:hover ._label {
      @media (any-hover) {
        text-decoration-line: underline;
      }
    }

    &:focus-visible ._label {
      text-decoration-line: underline;
    }
  }
}
```

この書き方では、ホバーとフォーカスの2つの条件を、変えたい子要素の数だけ書き写すことになります。`a:any-link:hover ._icon` の詳細度は0.3.1で、`._icon` 自身のルールの0.1.0より高くなります。アイコンの見た目をあとで別の状態で変えたいときは、`._icon` に状態を足したセレクタでは勝てず、同じ詳細度のセレクタを後ろに書くか、さらに詳細度を上げることになります。アイコンの見た目も、自身のルールと親のルールの2か所に分かれ、`._icon` のルールを読むだけでは、どの状態でどう変わるのかが分かりません。

幅のフラグと同じく、状態を1か所でフラグにします。リンクやボタンの状態のセレクタで `--_hocus: --true` を立て、子要素と擬似要素は `@container style(--_hocus: --true)` で切り替えます。ホバーを `@media (any-hover)` の中に書き、`:focus-visible` にも同じ変化を付けるという2つの条件は、フラグを立てる1か所にだけ書けば済みます（「[17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)」）。

```css title="🙆‍♂ Recommended: ホバーとフォーカスでフラグを立て、子と擬似要素で問い合わせる" from="components/hocus-arrow-link"
@scope (.scoped.link-menu) to (.scoped) {
  :scope {
    --_background: transparent;
    --_background--hocus: var(--background--hover);
  }

  a {
    --_hocus: --false;

    background-color: var(--_background);

    &:any-link:hover {
      @media (any-hover) {
        --_hocus: --true;

        background-color: var(--_background--hocus);
      }
    }

    &:focus-visible {
      --_hocus: --true;

      background-color: var(--_background--hocus);
    }

    &::after {
      content: "";

      @container style(--_hocus: --true) {
        translate: 4px;
      }
    }
  }

  ._label {
    @container style(--_hocus: --true) {
      text-decoration-line: underline;
    }
  }
}
```

フラグの値には、`--compact` や `--true` のように `--` で始まる識別子を使い、自分で付けた名前だと分かるようにします（「[9-1 命名規則](/notation/naming/)」）。状態のフラグの値は、どのコンポーネントでも `--true` と `--false` にそろえます。スタイルクエリは値が一致するかどうかを調べるだけなので、`--true` と `1` や `true` が混ざっていると、`style(--_hocus: 1)` と書き間違えても条件が成り立たないだけで、構文の誤りにはなりません。値をそろえておけば、この取り違えが起こりません。

次のデモは、ホバーとフォーカスで矢印が右へ動くリンクの一覧です。リンク自身の背景色は状態のセレクタに直接書き、`::after` の矢印とラベルの下線は `--_hocus` を問い合わせて切り替えています。キーボードのTabキーでフォーカスを移しても、同じように変わります。

<Demo title="ホバーとフォーカスで、矢印が動き、ラベルに下線が引かれるリンク" html={hocusHtml} css={hocusCss} />

矢印の上下の位置は、`margin-block: calc((1lh - var(--_icon-size)) / 2)` で決めています。`1lh` はその要素の行の高さなので、ラベルが2行に折り返しても、矢印は1行目の高さの中で上下の中央にそろいます（「[11-14 floatで文章を回り込ませる](/layout-practice/float/)」）。矢印のトランジションは装飾的な動きなので、`prefers-reduced-motion: no-preference` の中に書いています。

3つ目の段階で押さえるのは、`@media (any-hover)` と `:focus-visible` の2つの条件を書くのがフラグを立てるリンクのルールだけになり、子と擬似要素は `--_hocus` を読むだけになることです。リンク自身の背景色だけは、フラグを読まずに状態のセレクタへ直接書いています。その理由が、次の見出しで説明する制約です。

## スタイルクエリが問い合わせる要素

スタイルクエリを使うのに、`container` の指定は要りません。仕様では、`container-type` の初期値 `normal` の要素も、サイズの問い合わせには使えない一方で、スタイルの問い合わせには使えるコンテナとされています。つまり、すべての要素がスタイルクエリのコンテナです。

名前を書かない `@container style()` は、条件を書いた要素の最も近い祖先のコンテナを問い合わせます。すべての要素がコンテナなので、問い合わせ先は実質的に親の要素です。親より上の要素で立てたフラグも、継承によって親の計算値になっているので、子孫のどの深さからでも読めます。サイズの条件と違い、スタイルクエリに `--scoped` のような名前を付けずに済むのは、このためです。`@container --scoped style(…)` のように名前を付けると、問い合わせ先がルートに変わり、ルートの子孫で宣言したフラグを読めなくなります。

擬似要素（`::before`、`::after`、`::marker`）は、元の要素を問い合わせます。仕様は、擬似要素のクエリのコンテナになれる要素を、元の要素とその祖先と定めています。そのため、リンク自身に立てた `--_hocus` で、リンクの `::after` の矢印を切り替えられます。

一方で、要素は自分自身を問い合わせられません。`@container` は、コンテナの子孫のスタイルに条件を付ける仕組みだからです。`._body` に `@container style(--_density: --spacious)` を書くと、`._body` 自身の値ではなく親の値を調べるので、`._body` の配置は切り替わりません。そのため、フラグを宣言した要素自身の見た目は、フラグを切り替えるのと同じサイズクエリの中に書きます。ホバーとフォーカスでも同じで、リンク自身の背景色は `&:any-link:hover` と `&:focus-visible` の中に直接書きます。値は `--_background--hocus` のような接尾辞の内部プロパティで受けます（「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」）。

フラグのデフォルト値（`--compact`、`--false`）を明示するのは、カスタムプロパティが継承するからです。デフォルト値を書かないと、このコンポーネントを別のコンポーネントの中に置いたとき、外側で同じ名前のフラグが立っていれば、その値を受け継ぎます。外側のリンクにホバーしただけで、内側のコンポーネントの矢印まで動くことになります。同じ理由で、フラグはルートの `:scope` ではなく、`._body` のようなルートの子孫に置きます。`:scope` に書いた `@container --scoped (…)` は、ルート自身ではなく外側のコンポーネントのルートを問い合わせるからです（「[コンテナサイズクエリの基本](#コンテナサイズクエリの基本)」）。

## 1つのクエリに子のルールをまとめる方法と比べる

閾値を1か所に集めるだけなら、フラグを使わない方法もあります。コンポーネントの末尾にコンテナサイズクエリを1つだけ置き、広い幅で変わる子のルールをその中にまとめる書き方です。

```css title="本書では採らない書き方：1つのコンテナサイズクエリに子のルールをまとめる"
@scope (.scoped.media-card) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
  }

  ._body {
    display: block grid;
  }

  ._thumbnail {
    aspect-ratio: 16 / 9;
  }

  ._title {
    font-size: calc(18 / 16 * 1rem);
  }

  @container --scoped (inline-size >= calc(560 / 16 * 1rem)) {
    ._body {
      grid-template-columns: calc(240 / 16 * 1rem) 1fr;
    }

    ._thumbnail {
      aspect-ratio: 1;
    }

    ._title {
      font-size: calc(24 / 16 * 1rem);
    }
  }
}
```

この書き方もCSSとして正しく動き、閾値は1か所にまとまります。スタイルクエリを使わないので、コンテナサイズクエリに対応した環境ならどこでも同じ表示になり、フラグの名前と値の組も覚えずに済みます。本書の規約で書かないプロジェクトや、スタイルクエリに対応していないブラウザでも同じ表示が要るプロジェクトでは、まずこの方法を検討します。

本書がこの書き方を採らない理由は2つあります。1つ目は、1つの要素の見た目が、要素のルールと末尾のクエリの2か所に分かれることです。`._title` のルールを読んでも、広い幅で文字が大きくなることは分からず、ファイルの末尾まで探すことになります。2つ目は、クエリのブロックを置く位置で結果が変わることです。同じ詳細度のルールでは後に書いたほうが勝つので、クエリのブロックを元のルールより前に置くと、切り替えが反映されません。`@media` と `@container` を各セレクタの中に書くルール（`conditions-inside-rules`）は、この順番の誤りを構造で防ぐためのものです。

フラグの書き方は、この2つを解消する代わりに、次の「補足と注意点」で挙げる3つの概念を増やします。どちらを採るかは、1つの要素の見た目を1つのルールで読み切れることと、覚える概念が少ないことの、どちらを優先するかで決まります。本書は、人やAIがコンポーネントの一部のルールだけを読んで直す場面を考え、前者を優先しています。{/* 要確認: 著者の判断。代案を採らない理由の優先順位 */}ホバーとフォーカスでは、子のルールをまとめると、「[ホバーとフォーカスの状態をフラグにする](#ホバーとフォーカスの状態をフラグにする)」のNot Recommendedの例と同じく状態のセレクタの下に子を書く形になり、詳細度も上がります。そのため、フラグとの差は幅の場合より大きくなります。

## 補足と注意点

フラグを立てた要素自身の値を、そのフラグで切り替えたい場面もあります。その選択肢が `if()` で、`if(style(--_density: --spacious): 24px; else: 12px)` のように、要素自身に定義したカスタムプロパティの値で1つの値を切り替えられます。ただし、`if()` に対応しているのはChrome 137以降とEdgeだけで、FirefoxとSafariは対応していません。仕様もCSS Values 5のEditor's Draftの段階です。使うなら、「[6-5 if()とattr()で条件と属性を値にする](/values/if-and-attr/)」のルールに従い、前に従来の宣言を書いて、条件1つと `else` の形にとどめます。

<Baseline id="if" name="if()" />

スタイルクエリは、Chrome 111、Safari 18、Firefox 151で使えるようになり、2026年5月にBaselineの新しく利用可能（Newly available）になりました。本書の対象のSafari 18でも動きます。一方、`style(--_columns > 2)` のような範囲の比較は、ChromeとFirefoxが対応しているもののSafariが対応していないので、使いません。フラグは値が一致するかどうかだけで判定できる識別子にしておけば、範囲の比較は要りません。

<Baseline id="style-query-range-syntax" name="スタイルクエリの範囲の比較" />

スタイルクエリに対応していない環境では、`@container style()` の中のスタイルが適用されず、デフォルトの見た目だけが残ります。子孫のデフォルトの見た目をモバイルファーストの狭い幅に合わせて書いておけば、フラグを宣言する要素の配置だけが広い幅に切り替わり、子孫は狭い幅の見た目のまま表示されます。ホバーとフォーカスでは、子の変化がなくなっても、リンク自身の背景色の変化は残ります。

フラグは見た目を切り替えるためのもので、状態そのものを支援技術に伝えるものではありません。開閉や選択のように、意味を持つ状態は、`aria-expanded` や `aria-selected` のような属性でHTMLに表し、CSSはその属性を読みます（「[17-3 状態を属性で表す](/interaction/state-attributes/)」）。CSSのフラグとして立てるのは、ホバーや幅のように、HTMLに属性として書かない状態に限ります。

フラグの規約を採用すると、チームの覚える概念が3つ増えます。1つ目は、カスタムプロパティを値ではなく条件として使うことです。2つ目は、フラグを立てた要素自身と子孫とで、見た目を書く場所が分かれることです。3つ目は、フラグの名前と値の組（`--_density` と `--compact`／`--spacious`、`--_hocus` と `--false`／`--true`）を固定することです。どれもこの節の仕組みから来ていますが、コンテナサイズクエリと状態のセレクタだけで書いてきた人には、1つのコンポーネントの中に2通りの書き方が並んでいるように見えます。

フラグを宣言している場所と読んでいる場所は、コンポーネントのCSSファイルを文字列で検索して確かめます。読んでいるルールは `style(--_density` を検索すると見つかり、宣言は `--_density:` で始まる行です。フラグの名前はどのコンポーネントでも同じなので、検索はプロジェクト全体ではなく、そのコンポーネントのファイルに絞ります。ブラウザの開発者ツールでは、子孫の要素を選ぶと、当てはまった `@container style(…)` のルールが条件とともにスタイルの欄に並び、フラグの値は祖先から継承した宣言として確認できます。{/* 要検証: ブラウザ。Chrome、Firefox、Safariの開発者ツールが、当てはまったスタイルクエリのルールと継承したカスタムプロパティをこのように表示すること */}ホバーで変わる見た目は、要素の状態を開発者ツールから `:hover` に固定すれば、フラグが立った状態のまま調べられます。

幅のフラグを使わないのは、見た目の変わる要素が1つだけの場合です。サイズクエリを書く要素が1つで、フラグを読む子孫がなければ、その要素のルールにコンテナサイズクエリを直接書き、フラグは宣言しません（ルール `density-via-style-query`）。同じ閾値で変わる要素が2つ以上あると、閾値を書く場所も2か所以上になり、直し忘れると中間の状態ができます。そのため、2つ目の要素が同じ閾値で変わるようになった時点で、フラグを立てます。ホバーとフォーカスの基準はこれと違い、変わる子要素や擬似要素が1つでも `--_hocus` を立てます。子を状態のセレクタから選ぶと、1つの子でも2つの条件を書くことになり、詳細度も上がるからです。要素自身の見た目だけが変わるなら、状態のセレクタに直接書けば済みます。

チームに導入するときは、幅のフラグから始めます。{/* 要確認: 出典なし */}同じ閾値のコンテナサイズクエリが複数の子要素に並んでいるコンポーネントを1つ選んで `--_density` に書き換えれば、閾値を1か所で直せるという利点を、既存のコードとの差分で示せます。次に `--_hocus` を使い、最後に、置き場所によって外からフラグを渡す書き方（「[10-7 置き場所と子の状態を伝える](/components/placement-and-child-states/)」）に進みます。{/* 要確認: 出典なし */}フラグの値の組は、最初の段階で決めておきます。値を取り違えても構文の誤りにはならず、表示を確かめるまで気付きにくいからです。
