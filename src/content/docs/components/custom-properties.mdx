コンポーネントのカスタムプロパティは、名前で役割を分けます。外から変えてよい値は `--<コンポーネント>--<プロパティ>` の「公開プロパティ」にし、コンポーネントの中だけで使う値は `--_` で始まる「内部プロパティ」にします。状態やモードによって変わる値は、`--_background--hocus` のように、`--` で区切った接尾辞を付けて表します。

公開プロパティはコンポーネント自身では宣言せず、`:scope` で内部プロパティに受けて、デフォルト値を `var()` のフォールバックに書きます。値は、できるだけ呼び出し側の `style` 属性で渡します。`@property` による登録は、型の指定やアニメーションが必要なカスタムプロパティにだけ使います。

公開プロパティを作るのは、コンポーネントを複数の場所へ置き、外から値を変える必要が実際に生じたときです。外から変えない値は、公開プロパティにせず、トークンを参照するか宣言に直接書けば足ります。内部プロパティも、状態で切り替える値や何か所かで使う値に限ります。この線引きの理由は、「[補足と注意点](#補足と注意点)」で説明します。

## 外から変えてよい値と、中だけで使う値

情報カードを、お知らせの一覧と注意事項の欄の2か所に置き、注意事項の欄でだけ、枠線と見出しを赤系の色にしたいと言われた場面で考えます。枠線と見出しの色は、置く側が決めてよい値です。一方で、枠線の太さや内側の余白は、カードの中の都合で決まる値なので、置く側には変えさせません。

置く側は、カードの名前を含む `--info-card--accent` で色だけを渡します。カードは、その値を `:scope` で `--_accent` という短い名前に受け、枠線と見出しは、この内部の名前だけを参照します。

```html title="🙆‍♂ Recommended: 置く側は、公開プロパティで色だけを渡す"
<article class="scoped info-card" style="--info-card--accent: var(--foreground--danger)">…</article>
```

```css title="🙆‍♂ Recommended: カードは公開プロパティを内部プロパティに受けて使う"
@scope (.scoped.info-card) to (.scoped) {
  :scope {
    --_accent: var(--info-card--accent, var(--foreground--muted));

    padding: 16px;
    border: 2px solid var(--_accent);
  }

  h3 {
    color: var(--_accent);
  }
}
```

2つの名前は、誰が値を書くかを表しています。`--info-card--accent` はカードの外の要素が書くので、ほかのコンポーネントに渡す値と衝突しないよう、コンポーネントの名前を含めます。これが公開プロパティです。`--_accent` はカードの中でしか書かないので短くてよく、先頭の `_` が、子要素のクラス名 `._title` の `_` と同じく「外から触れない」という印になります。これが内部プロパティです。枠線の太さと余白は公開していないので、置く側がカードの見た目を変えられるのは、色の1か所だけです。

この形を保つための約束は2つあります。公開プロパティをカード自身では宣言しないことと、受けるときにデフォルト値を `var()` のフォールバックに書くことです。

## 公開プロパティは内部プロパティで受ける

公開プロパティは、コンポーネント自身では宣言しません。次の例は、公開プロパティのデフォルト値を、ルートの宣言として書いています。

```css title="🙅‍♂ Not Recommended: 公開プロパティをコンポーネント自身で宣言する" issue="behavior"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.info-card) to (.scoped) {
  :scope {
    --info-card--accent: var(--foreground--muted);

    border: 2px solid var(--info-card--accent);
  }
}
```

カスタムプロパティは継承されますが、要素自身に宣言があれば、継承した値よりその宣言が使われます。この書き方では、親がまとめて渡した `--info-card--accent` は、カードのルートの宣言に上書きされ、使われません。値を変えられるのは、カードの `style` 属性に直接書いたときだけになり、公開プロパティとして半分しか機能しません。

公開プロパティは、`:scope` で内部プロパティに受け、デフォルト値を `var()` のフォールバックに書きます。こうすれば、親の要素から継承した値も、`style` 属性で渡した値も、同じように受け取れます。

```css title="🙆‍♂ Recommended: :scope で内部プロパティに受け、デフォルト値をフォールバックに書く"
/**
 * 情報カード。
 *
 * @prop {color}  --info-card--accent [var(--foreground--muted)]   - 枠線と見出しの色
 * @prop {length} --info-card--radius [var(--rounded--md)]          - 角丸の半径
 */
@scope (.scoped.info-card) to (.scoped) {
  :scope {
    --_accent: var(--info-card--accent, var(--foreground--muted));
    --_radius: var(--info-card--radius, var(--rounded--md));

    border: 2px solid var(--_accent);
    border-radius: var(--_radius);
  }

  h3 {
    color: var(--_accent);
  }
}
```

`:scope` の先頭に受けておくと、そのコンポーネントが外から受け取る値の一覧が1か所で読めます。公開プロパティの長い名前は受け取る1行にしか出てこず、中のスタイルは短い内部プロパティで書けます。角丸の内側の半径のように、受け取った値から計算する値も、`--_inner-radius: calc(var(--_radius) - var(--_padding))` のように内部プロパティにすれば、数値の意味を名前で説明できます。ファイルの先頭には、JSDocの `@prop` で公開プロパティの一覧を書いておきます。

内部プロパティも継承されることには注意が必要です。内側に置いた別のコンポーネントが、自分では定義していない `--_accent` を参照すると、外側のカードの値を継承して使ってしまいます。内部プロパティは、参照するコンポーネント自身の中で必ず定義します。ふつうは `:scope` に置き、コンテナサイズクエリで切り替えるフラグは、クエリを書く要素に置きます（「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」）。

## 名前で役割を分ける

カスタムプロパティは、どれも `--` で始まる同じ見た目の名前です。名前の形を決めておかないと、ある値がサイト全体のトークンなのか、コンポーネントが外部に公開している値なのか、内部の計算用なのかを、宣言を追いかけないと判断できません。本書では、ここまでの公開プロパティと内部プロパティに、トークンと、コンポジションなどの内部プロパティを加えた次の形で、役割を見分けます。

| 種類 | 名前の形 | 例 | 値を定義する場所 |
|---|---|---|---|
| トークン | `--<分類>--<名前>` | `--spacing--md` | `:root` |
| セマンティクスのトークン | `--<役割>--<バリエーション>` | `--foreground--muted` | `:root` |
| 公開プロパティ | `--<コンポーネント>--<プロパティ>` | `--card--radius` | 呼び出し側（`style` 属性など） |
| 内部プロパティ | `--_<プロパティ>` | `--_background--hocus` | コンポーネントの `:scope`（サイズクエリで切り替えるフラグは、クエリを書く要素） |
| コンポジションなどの内部プロパティ | `--_c--`、`--_p--`、`--_u--`、`--_b--` で始める | `--_c--threshold` | コンポジション、パターン、ユーティリティ、ベースのスタイル |

公開プロパティの名前には、必ずコンポーネントの名前を付けます。`--foreground` のような汎用的な名前にすると、1つの要素に複数のコンポーネントの公開プロパティが渡されたとき、どれがどのコンポーネントのものかが分からなくなります。トークンの命名は「[10-4 デザイントークン](/components/design-tokens/)」で説明しています。

コンポジション、パターン、ユーティリティ、ベースのスタイルでは、内部プロパティをそれぞれ `--_c--`、`--_p--`、`--_u--`、`--_b--` で始めます。コンポジションやパターンのクラスは、コンポーネントのルートや子要素と同じ要素に付くことがあります。接頭辞を分けておけば、コンポーネントの `--_gap` とコンポジションの `--_c--gap` が衝突しません。

## 状態やモードは接尾辞で表す

ホバーや選択中のように、状態によって変わる値は、内部プロパティの名前の後ろに `--` で区切った接尾辞を付けて表します。デフォルトの状態には接尾辞を付けません。`hocus` は、ホバー（hover）とフォーカス（focus）をまとめて表す言葉です。

```css title="🙆‍♂ Recommended: 状態ごとの値を :scope にまとめ、状態のセレクタでは参照だけする"
@scope (.scoped.toggle-button) to (.scoped) {
  :scope {
    --_background: transparent;
    --_background--hocus: var(--background--hover);
    --_border-color: var(--border--base);
    --_border-color--selected: var(--foreground--accent);
  }

  button {
    border: 2px solid var(--_border-color);
    background-color: var(--_background);

    &:enabled:hover {
      @media (any-hover) {
        background-color: var(--_background--hocus);
      }
    }

    &:focus-visible {
      background-color: var(--_background--hocus);
    }

    &[aria-pressed="true"] {
      border-color: var(--_border-color--selected);
    }
  }
}
```

状態ごとの値は、すべて `:scope` の先頭に並べます。状態のセレクタの中では、どの内部プロパティを使うかを切り替えるだけにします。こうしておくと、そのコンポーネントがどんな状態を持ち、それぞれで何色になるのかを、先頭の数行で確認できます。配色を変えるときも、直すのは先頭の値だけです。

この例では、押した状態を枠線で、ホバーとフォーカスを背景で表し、変えるプロパティを分けています。押した状態でも背景を変えると、詳細度の高い `&:enabled:hover`（`0.2.1`）が `&[aria-pressed="true"]`（`0.1.1`）に勝ち、押した直後にポインターが残っているボタンは押していない見た目になります。ホバーの書き方は「[17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)」で、状態の表し方は「[17-3 状態を属性で表す](/interaction/state-attributes/)」で説明します。

公開プロパティにも、同じ形の接尾辞を使います。たとえば、置かれた場所の幅に応じてコンテナサイズクエリで隙間を変えるコンポーネントなら、広いときの値を `--media-card--gap--spacious` のように接尾辞を付けた別の公開プロパティとして受け取ります。デフォルトの値を受け取る `--media-card--gap` には、接尾辞を付けません。接尾辞の名前は、幅で立てるフラグの値（「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」の `--compact` と `--spacious`）にそろえます。

```css title="🙆‍♂ Recommended: 幅による値の違いを、接尾辞を付けた公開プロパティで受ける"
@scope (.scoped.media-card) to (.scoped) {
  :scope {
    --_gap: var(--media-card--gap, 12px);
    --_gap--spacious: var(--media-card--gap--spacious, 24px);

    container: --scoped / inline-size;
  }

  ._layout {
    display: block grid;
    gap: var(--_gap);

    @container --scoped (inline-size >= calc(400 / 16 * 1rem)) {
      gap: var(--_gap--spacious);
    }
  }
}
```

## style 属性で値を渡す

公開プロパティの値は、できるだけ呼び出し側の `style` 属性で渡します。`style` 属性は優先度が高いので避けられがちですが、公開プロパティに値を渡す手段として使うなら、安全で分かりやすい方法です。

```html
<article class="scoped info-card" style="--info-card--radius: 24px">…</article>
```

`style` 属性で渡す理由は4つあります。1つ目は、値がコンポーネントのタグと同じ場所に書かれることです。CSSで渡すと、どの要素に値が届くのかを、離れた場所のセレクタから読み解かなければなりません。2つ目は、セレクタが要らないことです。子のクラス名や構造に依存しないので、子の中身を作り直しても、渡す側を直さずに済みます。

3つ目は、詳細度の問題が起きないことです。同じ重要度（`!important` の有無）の宣言どうしでは、`style` 属性の宣言がレイヤーや詳細度より先に比較されて優先されるので、詳細度の競争に巻き込まれません。4つ目は、値がどの要素に適用されるのかが一目で分かることです。ページごとに少しだけ値を変えたいときも、修飾のクラスを増やさずに `style` 属性で渡せば済みます。

ただし、次のような場合は、CSSの側で公開プロパティに値を渡してかまいません。

- 同じ値を、複数の子のコンポーネントにまとめて渡したい場合（親の要素に定義して、継承させる）
- メディアクエリやコンテナサイズクエリで、値を切り替えたい場合
- `:hover` や `:has()` のように、状態によって値を変えたい場合

最後の場合の例として、親のヘッダーが、メニューを開いた状態に合わせて子のナビゲーションの色を変えるコードを示します。状態ごとの値は先頭に並べ、状態のセレクタでは、子の公開プロパティにつなぐ内部プロパティを切り替えるだけです。親は自分の内部プロパティを、子の公開プロパティにつないでいるだけで、子のナビゲーションはヘッダーの中に置かれていることに依存しません。

```css title="🙆‍♂ Recommended: 親の内部プロパティを、子の公開プロパティにつなぐ"
@scope (.scoped.site-header) to (.scoped) {
  :scope {
    --_background: var(--background--surface);
    --_background--expanded: var(--background--inverse);
    --_foreground: var(--foreground--base);
    --_foreground--expanded: var(--foreground--inverse);
    --global-nav--foreground: var(--_foreground);

    background-color: var(--_background);

    &:has([aria-expanded="true"]) {
      --global-nav--foreground: var(--_foreground--expanded);

      background-color: var(--_background--expanded);
    }
  }
}
```

次のデモでは、セクションの中に置いた3枚のカードが、`--info-card--accent` を受け取っています。セクションは、カードを並べる自分の `ul` に値を定義して、継承でまとめて渡しています。3枚目のカードだけは、`style` 属性で色と角丸を上書きしています。

## 公開プロパティに無効な値を渡したときのフォールバック

`var()` のフォールバックが使われるのは、参照したカスタムプロパティが定義されていないときだけです。公開プロパティに、プロパティに合わない値が渡されたときには使われません。たとえば `style="--info-card--radius: large"` と渡すと、`var(--info-card--radius, var(--rounded--md))` は `large` に置き換わります。`border-radius: large` という合わない値になり、`var(--rounded--md)` は使われません。

このとき宣言は「計算値の時点で無効」になり、`border-radius` は初期値の `0` になります。`var()` を含む宣言は、前に書いた同じプロパティの宣言にも戻りません。この仕組みは「[4-6 カスタムプロパティの基礎](/cascade/custom-properties-basics/)」で説明しています。

登録していない公開プロパティでは、渡された値の型をCSSの側で確かめる手段がありません。JSDocの `@prop` に型を書き、呼び出し側が正しい値を渡せるようにしておきます。型の確認が欠かせない値は、次の見出しの `@property` で登録すると、無効な値を受けたときにカスタムプロパティ自身の初期値や継承した値に戻せます。

## @property を使う場面

`@property` は、カスタムプロパティに型と継承の有無と初期値を登録するアットルールです。登録していないカスタムプロパティは、ただの文字の並びとして扱われます。値は `var()` で参照された場所で初めて解釈され、アニメーションでは途中の値を補間できません。

<Baseline id="registered-custom-properties" name="@property" />

`@property` を使うのは、型の指定やアニメーションが必要な場合だけです。代表的なのは、カスタムプロパティの値そのものをトランジションやアニメーションで変化させたい場合です。次の例は、進み具合を表すバーの値を `<number>` 型で登録し、値が変わったときに滑らかに伸び縮みさせています。

```css title="🙆‍♂ Recommended: 値の変化をトランジションさせるために型を登録する"
@property --progress-bar--value {
  syntax: "<number>";
  inherits: false;
  initial-value: 0;
}

@scope (.scoped.progress-bar) to (.scoped) {
  :scope {
    min-block-size: 8px;
    background-image: linear-gradient(to right, var(--background--accent) calc(var(--progress-bar--value) * 1%), var(--background--surface) 0);

    @media (prefers-reduced-motion: no-preference) {
      transition-duration: var(--duration--slow);
      transition-property: --progress-bar--value;
      transition-timing-function: var(--ease--out-quint);
    }
  }
}
```

型を登録しておくと、数値ではない値が渡されたときは無効になり、初期値の `0` が使われます。公開プロパティを受け取る時点で、型に合わない値を無効にできます。

仕様では、`syntax` と `inherits` は必須の記述子で、どちらかが欠けると `@property` のルールごと無効になります。`initial-value` も、`syntax` が `"*"` 以外なら必須です。その値は、要素の文字サイズやほかのカスタムプロパティによらず計算できる、計算上独立した値でなければならず、`em` や `var()` を含む値を書くと、やはりルールごと無効になります。`syntax` が `"*"` のときだけは `initial-value` を省略できますが、本書ではこの場合も省略せず、3つの記述子をすべて書きます。読む人が、初期値をほかの場所で探さなくて済むからです。

もう1つは、値を型に沿って計算させたい場合です。`<length>` 型で登録したプロパティは、値を指定した要素の時点で絶対的な長さに計算され、子孫にはその長さが引き継がれます（あとで説明する `1em` の例を参照）。また、`style` 属性で要素ごとに渡した値が、さらに内側の要素へ継承されては困るときは、`inherits: false` で登録すれば継承を止められます。

アニメーションさせるカスタムプロパティは、この例のように `inherits: false` で登録します。継承するカスタムプロパティの値が変わると、その値を受け継ぐ子孫の要素すべてでスタイルが計算し直されます。アニメーションでは、この計算がフレームごとに繰り返されるので、`:root` のように多くの要素の祖先で値を動かすと、ページ全体の処理が重くなり、スマートフォンでは発熱の原因にもなります。また、`opacity: var(--_opacity)` のようにカスタムプロパティを介して動かすと、`opacity` を直接動かす場合と違い、アニメーションの進行はコンポジタのスレッドに移りません。値の計算がフレームごとにメインスレッドで行われます。動かす値が `opacity` や `translate` だけなら、カスタムプロパティを介さずにそのプロパティを直接アニメーションさせます。

反対に、トークンのように、型の指定とアニメーションのどちらも要らない値は登録しません。登録すると振る舞いが変わるからです。たとえば `<length>` 型で登録して `:root` に `1em` を指定すると、`:root` の文字サイズで計算した値（16px）が子孫に継承されます。登録していなければ `var()` を書いた場所で `1em` として計算されるので、文字サイズが32pxの要素では32pxになります。

登録した名前は、文書全体に適用されます。`--_value` のような短い内部プロパティの名前を登録すると、同じ名前を別の意味で使っているほかのコンポーネントにも型が適用されます。同じ名前を2つの `@property` で登録した場合も、両方が使い分けられるわけではなく、スタイルシートの中で後に現れた登録だけが有効になります。登録する名前は、上の例の `--progress-bar--value` のように、コンポーネントの名前を含むものにしておくと安全です。例外は、どのコンポーネントでも同じ意味で使う名前を、共通のスタイルシートで1回だけ登録する場合です。「[13-4 コンテナの副作用とコンテナ単位](/responsive/container-units-and-side-effects/)」の `--_root-cqi` は、「そのコンポーネントのルートの幅の1%」という意味だけに使うので、コンポーネントごとに名前を分けずに共有しています。

## 補足と注意点

この規約を採用すると、CSSを書く人は、最初の表の5つの名前の形と、公開プロパティを `:scope` で内部プロパティに受けるという手順を覚えることになります。コンポジション、パターン、ユーティリティ、ベースのスタイルの接頭辞（`--_c--` など）や、状態の接尾辞（`--hocus`）も、名前を読むときに知っておく必要があります。

公開プロパティの宣言は、CSSファイルではなく、呼び出し側のHTMLの `style` 属性にあることが多いので、`--info-card--accent:` での検索はテンプレートのファイルも対象にします。参照はコンポーネントの `:scope` で受ける1行だけなので、そこからは内部プロパティの名前で、同じファイルの中を `var(--_accent` で検索します。内部プロパティの値が想定と違うときは、開発者ツールで、その値がどの祖先から継承されたものかを確かめます。内側のコンポーネントが自分で定義していない内部プロパティを、外側から受け継いでいる場合があるからです。{/* 要検証: ブラウザ。Chrome、Firefox、Safariの開発者ツールで、継承したカスタムプロパティの宣言元の要素が表示されること */}

コンテンツセキュリティポリシー（CSP）で `style-src-attr` や `style-src` に `'unsafe-inline'` を許可していないサイトでは、`style` 属性に書いた宣言は適用されません。その場合も、CSPを緩めて `style` 属性を通すことはしません。外側のコンポーネントのCSSで、カードを包む自分の子要素にクラスを付け、そこで公開プロパティに値を渡します。値は継承でカードに届くので、カードのCSSは変わりません。

```html
<li class="_pickup">
  <article class="scoped info-card">…</article>
</li>
```

```css title="🙆‍♂ Recommended: style 属性を使えないときは、外側のCSSで自分の子要素から渡す"
@scope (.scoped.card-section) to (.scoped) {
  ._pickup {
    --info-card--radius: 24px;
  }
}
```

カードのルートではなく、外側のコンポーネントの `li` に書くのは、`@scope` の下限の `.scoped` に当たるカードのルートが、外側のスコープに含まれないからです。値を渡す場所はテンプレートからCSSへ移るので、`--info-card--radius:` で検索するときは、CSSファイルも対象にします。

公開プロパティは、外から変える必要が実際に生じてから足します。使われない公開プロパティは、名前とデフォルト値とJSDocの記述を保守する手間だけを残すからです。{/* 要確認: 出典なし */}内部プロパティも、1か所でしか使わず、状態で切り替えもしない値なら、宣言に直接書けば済みます。{/* 要確認: 出典なし */}

チームに導入するときは、内部プロパティと状態の接尾辞から始めます。{/* 要確認: 出典なし */}状態ごとの値を `:scope` の先頭に並べる書き方は、1つのコンポーネントの中だけで完結し、ほかの部品へ影響を与えずに試せるからです。公開プロパティは、コンポーネントを複数の場所へ置き始めたら導入します。`@property` は、型やアニメーションが必要なときだけ使います。
