型付きの `attr()` を使うと、HTMLの属性値を数値や長さ、名前として、`content` 以外のプロパティで使えます。`if()` は、1つのプロパティの値を、条件によって切り替える関数です。どちらもSafariが対応していないので、従来の宣言を外に書き、対応した環境でだけ新しい値が使われるようにします。`attr()` は `var()` と組み合わせることが多いので、宣言を `@supports` の中に書きます。

使う場面も限ります。`attr()` で読むのは、`<textarea>` の `rows` のように、HTMLがすでに持っている属性の値です。`if()` は、要素自身に定義したカスタムプロパティで値を分岐するときにだけ、条件1つと `else` の形で書きます。未対応の環境でも同じ表示が要る分岐は、`if()` が使えるようになるまで、スペーストグルで書きます。この節は第6章の発展の内容で、初めて読むときは飛ばしてかまいません。

## HTMLの属性値をCSSの値にできなかった理由

これまでの `attr()` は、`content` プロパティでしか使えず、属性値を文字列として返すだけでした。印刷のときにリンクのURLを添えるような使い方はできても、属性に書いた数値を高さや列の数に使うことはできません。そのため、HTMLの値をCSSに渡すときは、`style` 属性でカスタムプロパティを渡す方法を使ってきました。この方法は「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」で説明しています。

```css title="🙆‍♂ Recommended: 従来の attr() で、印刷するときにリンクのURLを添える"
@scope (.scoped.article-body) to (.scoped) {
  a {
    &[href^="http"]::after {
      @media print {
        content: " (" attr(href) ")";
      }
    }
  }
}
```

印刷のスタイルの書き方は、第16章の「印刷のスタイル」で説明します。{/* 第16章の執筆後にリンクする：/decoration/print/ */}

困るのは、同じ値をHTMLがすでに属性として持っている場合です。`<textarea>` に `field-sizing: content` を指定すると、入力欄は入力した量に合わせて伸び縮みします。その代わり、`rows` 属性で決めていた高さが使われなくなり、空の入力欄は1行分の高さに縮みます。本文の入力欄に `rows="6"` を指定して6行分の高さを用意していても、その高さは失われます。

```html title="🙅‍♂ Not Recommended: rows と同じ値を style 属性でも渡す" issue="convention"
<!-- 🙅‍♂ Not Recommended -->
<textarea rows="6" style="--comment-form--min-rows: 6"></textarea>
```

最小の高さを残そうとして、`rows` と同じ値を `style` 属性でも渡すと、1つの値を2か所で管理することになります。片方だけを書き換えると、`field-sizing` に対応した環境と未対応の環境で、入力欄の高さが食い違います。CSSが `rows` 属性を直接読めれば、値は1か所で済みます。

## 型付きのattr()で属性値を読む

型付きの `attr()` は、属性値を指定した型として解釈して返します。`attr(rows type(<number>), 3)` と書くと、`rows` 属性の値を数値として読み、属性がないときや数値として読めないときは、第2引数の `3` を返します。型には `<number>`、`<integer>`、`<length>`、`<color>`、`<custom-ident>` などを指定でき、`attr(data-gap px, 16px)` のように単位を付けて読む書き方もあります。

```css title="🙆‍♂ Recommended: rows 属性の行数を、入力欄の最小の高さにする" from="values/textarea-rows"
@scope (.scoped.comment-form) to (.scoped) {
  textarea {
    --_max-rows: 10lh;

    box-sizing: unset;

    /* 型付きの attr() に未対応の環境で使う、3行分の高さ */
    min-block-size: 3lh;
    padding: 1em;

    @supports (min-block-size: calc(attr(rows type(<number>), 3) * 1lh)) {
      min-block-size: calc(attr(rows type(<number>), 3) * 1lh);
    }

    @supports (field-sizing: content) {
      max-block-size: var(--_max-rows);
      field-sizing: content;
    }
  }
}
```

`attr()` 以外の指定は、「[17-7 フォーム部品](/interaction/forms/)」の推奨スタイルをもとに、行数に関わるものだけを書いています。最大の高さは、伸びる様子を確かめやすいように、17-7より大きい10行にしています。`box-sizing` を `content-box` に戻しているので、`attr()` で読んだ行数に `padding` を足さずに済みます。

次のデモには、`rows="1"` の件名と、`rows="6"` の本文の入力欄があります。型付きの `attr()` に対応したブラウザでは、入力欄の最小の高さがそれぞれ1行と6行になり、入力した量に合わせて最大10行まで伸びます。未対応のブラウザでは、どちらも最小の高さが3行になります。件名の欄が少し高くなるだけで、入力するという目的は損なわれません。このように、未対応の環境で値が少し変わるだけで済む箇所が、型付きの `attr()` を使える場面です。

<Demo title="rows 属性の行数を、伸び縮みする入力欄の最小の高さにする" html={rowsHtml} css={rowsCss} widths={[]} />

`attr()` を使う宣言は、型付きの `attr()` を条件にした `@supports` の中に書きます。外に書いた3行分の `min-block-size` は、未対応の環境で使う値です。第2引数の `3` は、`attr()` に対応した環境で属性がないときにしか使われないので、未対応の環境のフォールバックにはなりません。

同じプロパティを2回書き、未対応の環境では後の宣言が捨てられることに頼る書き方は、`attr()` を `var()` と組み合わせた宣言では成り立ちません。宣言に `var()` が含まれていると、ブラウザは構文の検査を値の計算まで先送りするからです。未対応の関数があると分かるのは計算値を求める時点なので、宣言は「計算値の時点で無効」になり、前の宣言には戻らずに初期値が使われます。`min-block-size` の初期値は `auto` で、`field-sizing: content` の空の入力欄は1行分の高さに縮みます。`var()` を含む宣言で、未知の関数を使って試すと、`min-block-size` は前に書いた値ではなく0pxになりました。型付きの `attr()` に未対応のブラウザでは、`attr()` だけを含み `var()` を含まない宣言は、構文の時点で捨てられて前の宣言に戻るはずです。{/* 要検証: ブラウザ。Safari で、var() を含まない min-block-size: calc(attr(rows type(<number>), 3) * 1lh) が構文の時点で捨てられ、前の宣言に戻ること */}それでも `@supports` の中に書くのは、`var()` と組み合わせる場合と書き方をそろえ、どの宣言が未対応の環境で使われるかをコードから読み取れるようにするためです。`field-sizing` と `lh` 単位で入力欄の高さを行数で決める書き方は、「[17-7 フォーム部品](/interaction/forms/)」で扱っています。

第2引数は省略しません。対応した環境で属性がなかったり、値を型として読めなかったりすると、宣言は「計算値の時点で無効」になり、前に書いた宣言ではなくプロパティの初期値が使われます。`z-index: 5` の後に `z-index: attr(data-layer type(<integer>))` と書き、属性値を `abc` にして試しました。`z-index` は `5` ではなく `auto` になります。

列の数や、グリッドのエリアの名前を `data-*` 属性で渡し、`grid-area: attr(data-area type(<custom-ident>), auto)` のように読む書き方もあります。本書では、この書き方を使いません。HTMLが意味を持たせていない属性に値を書くと、同じ値を属性と `style` 属性の2つの経路で渡せることになります。エリアの名前のようなCSSの命名の規則も、HTMLの側に現れます（ルール `attr-for-html-attributes`）。命名の規則は「[9-1 命名規則](/notation/naming/)」で説明しています。

## style属性の公開プロパティとの使い分け

型付きの `attr()` が使えるなら、カスタムプロパティを `style` 属性で渡す方法が要らなくなるのではないでしょうか。本書では、コンポーネントに値を渡す手段は、`style` 属性の公開プロパティのままにします。`attr()` を使うのは、`rows` のようにHTMLが意味を持たせた属性の値を、CSSでも使いたいときです。{/* 要確認: 出典なし */}`data-variant="featured"` のように、選択肢から1つを選ぶバリエーションは、複数のプロパティをまとめて変えることが多いので、これまでどおり属性セレクタで書きます。

こう分けるのは、2つの方法に性質の違いがあるからです。`style` 属性で渡したカスタムプロパティは、子孫の要素に継承されます。`attr()` が読むのは、その要素自身の属性だけです。また、`style` 属性の方法は本書の対象のすべてのブラウザで動きますが、型付きの `attr()` はSafariで動きません。

HTMLに書いた値そのものは、CSSで書き換えられません。属性の値はCSSから変えられず、`style` 属性で渡したカスタムプロパティは、同じ要素へのCSSの宣言より優先されます（「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」）。一方、その値を読むプロパティの宣言は、ふつうの宣言としてカスケードで比べられます。`padding-inline: attr(data-gap type(<length>), 16px)` の後に、メディアクエリの中で `padding-inline: 24px` と書けば、属性はそのままで余白だけが変わります。

```css title="属性値を読む宣言も、メディアクエリの中の宣言で上書きできる（仕組みを見せる例）"
@scope (.scoped.info-box) to (.scoped) {
  :scope {
    padding-inline: 16px;

    @supports (padding-inline: attr(data-gap type(<length>), 16px)) {
      padding-inline: attr(data-gap type(<length>), 16px);
    }

    @media (width >= calc(768 / 16 * 1rem)) {
      padding-inline: 24px;
    }
  }
}
```

`@media` の宣言は `@supports` の宣言より後にあり、詳細度も同じなので、768px以上では、`data-gap` の値によらず余白は24pxです。`data-gap` は仕組みを見せるための例で、本書では余白を `data-*` 属性で渡しません。

`style` 属性のカスタムプロパティを `var()` で読む宣言も、同じように上書きできます。ただし、変わるのは読む側の宣言だけで、`style` 属性で渡した公開プロパティの値は変わりません。状態や画面の幅で変える値は、CSSの側で公開プロパティに渡します。HTMLから状態ごとの値を渡したいときは、`--card--background--hocus` のように接尾辞を付けた公開プロパティでモードごとの値を渡し、どれを使うかはコンポーネントの内部で選びます。

この分け方は、Safariが型付きの `attr()` に対応したら見直します。すべてのブラウザで使えるなら、対応の差という理由はなくなるからです。そのときは、コンポーネントや小さな汎用の部品の上書きを `attr()` で行い、コンポジションとユーティリティは公開プロパティのままにする、という分け方を候補にしています。

ルートの要素で、カスタムプロパティに `attr()` を代入するときは注意が必要です。本書では使わない書き方ですが、`:scope` に `--_columns: attr(data-columns type(<integer>), 1)` と書くと、値はルートの属性で計算されてから子孫の要素に継承されます。子孫の要素が同じ名前の属性を持っていても、使われるのはルートの値です。

## if()で1つの値を条件で切り替える

`if()` は、条件と値の組をセミコロンで区切って並べ、最初に成り立った条件の値を返します。条件には、カスタムプロパティの値を調べる `style()`、メディアクエリの `media()`、機能の対応を調べる `supports()` を書けます。どの条件も成り立たなかったときのために、最後に `else` の値を書きます。

```css title="🙆‍♂ Recommended: ルート自身の余白を、ルートで決めたモードで切り替える" from="values/if-density"
@scope (.scoped.site-header) to (.scoped) {
  :scope {
    --_density: --compact;

    /* if() に未対応の環境で使う値 */
    padding-block: 12px;
    padding-block: if(style(--_density: --spacious): 24px; else: 12px);

    @media (width >= calc(768 / 16 * 1rem)) {
      --_density: --spacious;
    }
  }

  ._logo {
    inline-size: 120px;

    @container style(--_density: --spacious) {
      inline-size: 150px;
    }
  }
}
```

次のデモは、この例をヘッダーとして表示したものです。768px以上では、`if()` でルート自身の上下の余白が24pxになり、スタイルクエリでロゴが150pxに広がります。`if()` に未対応のブラウザでは、ロゴだけが広がり、上下の余白は12pxのままです。

<Demo title="ルートで決めたモードを、ルート自身は if() で、ロゴはスタイルクエリで読む" html={densityHtml} css={densityCss} widths={[480, 768]} />

この例で `if()` を使っているのは、ルート自身の `padding-block` だけです。スタイルクエリ（`@container style()`）は、親の要素に定義されたカスタムプロパティを調べるので、`--_density` を定義したルート自身には当たりません。`if()` の `style()` は、その要素自身の値を調べます。同じ要素に `--_pressed: --true` を定義して試すと、スタイルクエリの色は変わらず、`if()` の色は変わりました。

`if()` がなければ、ルートの余白のためにメディアクエリをもう1つ書くことになり、モードの判定が2か所に分かれます。判定をルートの1か所に集め、子孫の要素はスタイルクエリで分岐する書き方では、ルート自身だけが分岐できません。`if()` は、ルート自身を分岐させるために使います。モードをメディアクエリではなくコンテナサイズクエリの閾値で決めるときは、ルートは自分のサイズを問い合わせられないので、ルートの子孫の要素で `--_density` を宣言します。この要素自身の見た目は同じサイズクエリの中で変えられるので、`if()` は要りません。フラグの立て方とスタイルクエリの問い合わせ先は、「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」で説明しています。

## if()の条件の書き方と評価のタイミング

条件は書いた順に調べられ、`else` は常に成り立つので、`else` は最後に書きます。`style()` では `and`、`or`、`not` で条件を組み合わせられ、Chrome 142以降は `style(--_columns > 2)` のような範囲の比較も書けます。ただし、複数のカスタムプロパティを組み合わせると状態の掛け合わせを値の中で表すことになるので、本書では使いません。{/* 要確認: 出典なし */}

<Baseline id="style-query-range-syntax" name="スタイルクエリの範囲の比較" />

`if()` は、ショートハンドの一部や `calc()` の中にも書けます。変わる部分だけを `if()` で書けば、変わらない部分を条件ごとに書き写す必要がなくなります。

```css title="🙆‍♂ Recommended: ショートハンドのうち、線の太さだけを切り替える"
@scope (.scoped.site-header) to (.scoped) {
  :scope {
    --_density: --compact;

    /* if() に未対応の環境で使う値 */
    border-block-end: 1px solid;
    border-block-end: if(style(--_density: --spacious): 2px; else: 1px) solid;
  }
}
```

`if()` は `var()` と同じく、値を計算する時点で条件を調べて置き換わる関数です。そのため、カスタムプロパティの値に `if()` を書くと、条件は定義した要素で一度だけ調べられ、子孫の要素には選ばれた値が継承されます。子孫の要素で条件のカスタムプロパティが変わっても、値は選び直されません。要素ごとに条件を調べたいときは、`if()` をプロパティの値に直接書きます。

## if()を使う場面を限る

`if()` は、どのプロパティの値の中にも書け、入れ子にもできます。そのため、メディアクエリや状態のセレクタで書いていた分岐を、すべて値の中に書けてしまいます。私は2025年5月から7月にかけて `if()` を試し、便利すぎて使う場面を抑えられなくなると感じました。時短のために使えば、コードが破綻するという考えです。そこで、条件1つと `else` の形で書ける場面に限って、`if()` を使います。

```css title="🙅‍♂ Not Recommended: クエリと状態の分岐を値の中に詰め込む" issue="behavior"
/* 🙅‍♂ Not Recommended */
._action-button {
  padding-inline: if(media(width >= calc(768 / 16 * 1rem)): 24px; else: 16px);
  background-color: if(
    style(--_variant: --primary): if(style(--_hocus: --true): var(--color--accent--700); else: var(--color--accent--600));
    style(--_variant: --danger): var(--color--red--600);
    else: var(--color--neutral--50)
  );
}
```

このコードには前に書いた宣言がないので、`if()` に未対応の環境では、背景色と余白のどちらも指定されません。また、メディアクエリは各セレクタの中の `@media` に、状態ごとの値は `--_background--hocus` のような接尾辞の内部プロパティに書くのが本書の規約です。値の中に条件を書くと、コンポーネントがどんな状態を持つのかを、`:scope` の先頭の数行から読み取れなくなります。状態の表し方は、「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」の「状態やモードは接尾辞で表す」で説明しています。

`media()` と `supports()` も使いません。1つの値だけを切り替える場面でも、`@media` か `@supports` で書けば、未対応の環境で宣言ごと捨てられる心配はありません。`if()` を使うのは、要素自身に定義したカスタムプロパティを `style()` で調べる場面だけです。{/* 要確認: 出典なし */}

## 未対応の環境での振る舞いと制約

`if()` に対応しているのは、Chrome 137以降とEdgeだけで、FirefoxとSafariは対応していません。未対応の環境では `if()` を含む宣言が構文の誤りとして捨てられるので、必ず前に従来の宣言を書きます。前の宣言が使われても表示が崩れない値、つまりコンパクトなモードのような基本の値を前に書きます。

ただし、前の宣言に戻るのは、`if()` を含む宣言に `var()` がない場合だけです。`if()` の値に `var()` を書くと、`attr()` の例と同じく宣言は計算値の時点で無効になり、前の宣言ではなく初期値か継承した値が使われます。`var()` を使う値を `if()` で切り替えたいときは、`@supports` の中に書くか、`if()` を使わずにスタイルクエリや状態のセレクタで書きます。どの書き方でフォールバックを用意するかの判断は、「[1-2 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」の「フォールバックの書き方を選ぶ」にまとめています。

対応した環境では、前の宣言はフォールバックになりません。どの条件も成り立たず、`else` を書いていないとき、`if()` は何も返さず（空の値になり）、宣言は計算値の時点で無効になります。親の文字色が緑の要素に、`color: blue` と `color: if(style(--_flag: --true): red)` を続けて書いて試しました（`--_flag` は定義していません）。文字色は青ではなく、継承した緑になります。そのため、`if()` には必ず `else` を書きます。

```css title="🙅‍♂ Not Recommended: var() を含む if() を前の宣言に頼って書き、else も書かない" issue="behavior"
/* 🙅‍♂ Not Recommended */
.status-badge {
  color: var(--foreground--base);
  color: if(style(--_status: --error): var(--foreground--danger));
}
```

```css title="🙆‍♂ Recommended: var() を含む if() は @supports の中に書き、else を付ける"
@scope (.scoped.status-badge) to (.scoped) {
  :scope {
    --_status: --default;

    color: var(--foreground--base);

    @supports (color: if(style(--_status: --error): red; else: blue)) {
      color: if(style(--_status: --error): var(--foreground--danger); else: var(--foreground--base));
    }
  }
}
```

前者は、未対応の環境では宣言が計算値の時点で無効になって継承した色になり、対応した環境でも `--_status` が `--error` でなければ同じく継承した色になります。後者は、未対応の環境では外の宣言が使われ、対応した環境ではどちらの状態でも色が決まります。

`attr()` の値は、URLとしては使えません。属性には、スクリプトが使うトークンのように、スタイルのためではない値が入っていることがあります。その値を外部に送るURLを組み立てられると危険だからです。`image-set()` に `attr()` の文字列を渡す形と、カスタムプロパティを経由する形を試すと、どちらも `background-image` は `none` でした。引用符のない `url(attr(data-src))` は、`url(` の後ろの中身がそのままURLの文字として読まれるので、そもそも `attr()` として解釈されず、構文の時点で捨てられます。CMSから背景画像を渡すときは、これまでどおり `style` 属性で、`url()` を含む公開プロパティを渡します。

```css title="🙅‍♂ Not Recommended: 属性値から画像のURLを組み立てる" issue="behavior"
/* 🙅‍♂ Not Recommended */
.hero {
  background-image: url(attr(data-src));
}
```

```css title="🙆‍♂ Recommended: style 属性で渡した url() を、公開プロパティで受け取る"
@scope (.scoped.hero) to (.scoped) {
  :scope {
    --_background-image: var(--hero--background-image, none);

    background-image: var(--_background-image);
  }
}
```

HTMLの側では、`style="--hero--background-image: url(/images/hero.jpg)"` のように、`url()` まで含めた値を渡します。

対応を `@supports` で調べるときは、`content` 以外のプロパティに型付きの `attr()` を書きます。入力欄のコード例とデモでは、`min-block-size: calc(attr(rows type(<number>), 3) * 1lh)` を条件にしています。型を付けない `attr()` を条件にすると、従来の `attr()` だけに対応した環境でも成り立つので、判別できません。条件の中には `var()` を書きません。`@supports` は条件の宣言を構文として調べるので、`var()` があると、どの環境でも成り立ってしまいます。{/* 要確認: 出典なし */}

## if()に未対応の環境でも同じ表示にする

ルート自身の分岐を、`if()` に未対応の環境でも同じ表示にする必要があるときは、スペーストグルで書きます。スペーストグルは、カスタムプロパティの値を空白にするか `initial` にするかで、`var()` の第2引数を使うかどうかを切り替える書き方です。`if()` が登場する前から使われてきた方法で、すべての主要なブラウザで動きます。ただし、ハックの色が強いので、`if()` がすべての主要なブラウザで使えるようになったら、`if()` に置き換えます。

```css title="🙆‍♂ Recommended: ルート自身の余白を、スペーストグルで切り替える" from="values/space-toggle-density"
@scope (.scoped.site-header) to (.scoped) {
  :scope {
    --_density: --compact;
    --_if-spacious: ;
    --_if-compact: initial;

    /* TODO: if() がすべての主要なブラウザで使えるようになったら、if() に置き換える */
    padding-block: var(--_if-spacious, 24px) var(--_if-compact, 12px);

    @media (width >= calc(768 / 16 * 1rem)) {
      --_density: --spacious;
      --_if-spacious: initial;
      --_if-compact: ;
    }
  }
}
```

`initial` を指定したカスタムプロパティは、値を持たない状態になるので、`var()` は第2引数を使います。空白1文字を指定したカスタムプロパティは、空の値を持つので、`var()` は何も返しません。768px未満では、`var(--_if-spacious, 24px)` が空になり、`var(--_if-compact, 12px)` が12pxになるので、`padding-block` は12pxです。768px以上では2つの変数の値が入れ替わり、24pxになります。

次のデモは、「[if()で1つの値を条件で切り替える](#ifで1つの値を条件で切り替える)」のヘッダーを、スペーストグルで書き直したものです。768px以上で上下の余白が24pxに、ロゴが150pxになります。`if()` のデモと違い、`if()` に未対応のSafariとFirefoxでも、768px以上では余白が24pxになります。

<Demo title="ルートで決めたモードを、ルート自身はスペーストグルで、ロゴはスタイルクエリで読む" html={toggleHtml} css={toggleCss} widths={[480, 768]} />

スペーストグルの変数は、`--_if-` の後ろにフラグの値の名前を付け、1つの状態に「その状態のとき」と「そうでないとき」の2つを用意します。2つの変数は、フラグの `--_density` と同じ `@media` の中で切り替えるので、判定は1か所に集まったままです。子孫の要素は、これまでどおりスタイルクエリでフラグを読み、トグルの変数は使いません。

この書き方を使うのは、2値の分岐だけです。3段階の切り替えや、複数の条件の組み合わせを書くと、変数の数が増え、どの組み合わせで何が返るかを読み取れなくなります。また、空白1文字の値に意味があるので、整形ツールやCSSの圧縮で `--_if-spacious: ;` の値が消えたり、宣言ごと消されたりしないことを確かめます。整形ツールのPrettier 3.9は整形しても、圧縮ツールのLightning CSS 1.33とesbuild 0.28は圧縮しても、空白を1つ残しました。

余白が少し狭いだけで済むなら、これまでどおり、`if()` の前に従来の宣言を書く方法を使います。スペーストグルは、未対応の環境で値が変わると困る場合に限ります。`if()` がすべての主要なブラウザで使えるようになったら、`padding-block: if(style(--_density: --spacious): 24px; else: 12px);` に置き換え、トグルの変数を消します。
