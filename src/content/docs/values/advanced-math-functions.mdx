計算関数は、根拠を式に残すだけでなく、クエリを書かずに値を切り替える手段にもなります。`clamp()` の最小値を負、最大値を0にすると、余白が広いときだけ要素を外へはみ出させる値を作れます。`abs()` で絶対値を取れば、兄弟の並びの中央からの距離を、項目の数に関係なく求められます。`pow()` で累乗を求めれば、文字サイズや余白の段階を、基準と比率と段階の数から式で導けます。`round()` で丸めれば、式で求めた端数のある値を、決めた刻みの倍数にそろえられます。`calc()`、`min()`、`max()`、`clamp()` の基本と、推奨値の組み立て方は「[6-3 計算関数で根拠を式に残す](/values/math-functions/)」で説明しています。

長さを単位のない数値に変えるときは、三角関数の組み合わせではなく、単位のついた値で割ります。Chrome系のブラウザだけが対応する `calc-size()` と `@function` は、従来の書き方で足りる場面では使いません。

関数の意味と小さな例は、基礎編のこの位置で読めるように書いています。一方、応用例の「コンポーネントの中で、はみ出す量を余白から求める」は、2つの章の内容を前提にしています。内部プロパティと `@scope` の構成は第10章「[コンポーネントとカスタムプロパティ](/components/)」で、コンテナとコンテナ単位の使い方は第13章「[レスポンシブデザイン](/responsive/)」で説明します。初めて読むときはこの見出しを飛ばし、第10章と第13章を読んだあとで読み返してください。

## `clamp()` の範囲に負の値を含める

`clamp()` の最小値には、負の値も書けます。最小値を負、最大値を0にすると、ある幅を境に「はみ出すか、はみ出さないか」が切り替わる値を、クエリを使わずに作れます。{/* 要確認: 出典なし */}たとえば、見出しの上に付けたラベルを、本文の外の余白が広いときだけ本文の行頭より左へはみ出させ、余白が狭くなったらはみ出しをなくす、という指定です。

この指定を、画面の幅と結果の数値だけで書くと、次のようになります。`336px` が何の幅から求めた値なのかは、式からは読み取れません。

```css title="🙅‍♂ Not Recommended: 結果の数値だけで、はみ出しを切り替える" issue="convention"
/* 🙅‍♂ Not Recommended */
.section-label {
  position: relative;
  left: clamp(-24px, 336px - 50vw, 0px);
}
```

まず、計算関数の使い方だけを直します。中央の式を「本文の外の余白が、最小の余白をどれだけ超えたか」として組み立て、`336px` を、本文の幅（640px）と、本文の外に必ず残す余白（16px）に分けて書きます。最小値の `-24px` は、はみ出させる量の上限です。`vw` と `left` は元のまま残しているので、この段階のコードは、まだ本書の規約には合わせていません。

```css title="中央の式を、余白の差として組み立てる（規約にはまだ合わせていない）"
/* 途中の段階の式。vw と left は、次の見出しで置き換える */
.section-label {
  position: relative;

  /* 640px は本文の幅、16px は本文の外に必ず残す余白、24px ははみ出させる量の上限 */
  left: clamp(-24px, 16px - (100vw - 640px) / 2, 0px);
}
```

2つの式は同じ値を返しますが（`16px - (100vw - 640px) / 2` を展開すると `336px - 50vw`）、書き直した式は、中央の式が0になる幅を境に読めます。`(100vw - 640px) / 2` は本文の片側の余白なので、中央の式が0になるのは、画面の幅が「本文の幅＋最小の余白の2倍」（672px）のときです。672pxより狭いと中央の式は正の値になり、最大値の0で止まるので、ラベルの位置は本文の行頭と同じです。

672pxより広いと中央の式は負の値になり、ラベルは余白が広がった分だけ左へ動きます。最小値の `-24px` に達する720px以上では、はみ出しは24pxで止まります。なお、最大値の `0px` には単位が要ります。単位のない `0` は数値として扱われ、長さと混ぜた `clamp()` 全体が無効になるからです。

次の見出しでは、この式を本書のコンポーネントの書き方に整えます。第10章と第13章の内容を前提にするので、初めて読むときは「`abs()` で並びの中央からの距離を求める」へ進んでください。

## コンポーネントの中で、はみ出す量を余白から求める

前の見出しの式を本書の設計に整えると、次のようになります。最小値を負、中央を余白の差、最大値を0にする式の組み立ては変えていません。

```css title="🙆‍♂ Recommended: 余白が広い分だけ、ラベルを本文の外へ出す" from="values/hanging-label"
@scope (.scoped.article-header) to (.scoped) {
  :scope {
    --_content-width: calc(640 / 16 * 1rem);
    --_gutter: 16px;
    --_overhang: 24px;

    container: --scoped / inline-size;

    & > ._article-inner {
      margin-inline: auto;
    }
  }

  ._article-inner {
    inline-size: min(100% - 2 * var(--_gutter), var(--_content-width));

    & > ._label {
      /* 本文の外の余白が最小の余白より広い分だけ、最大で --_overhang まで本文の外へ出す */
      margin-inline-start: clamp(
        -1 * var(--_overhang),
        var(--_gutter) - (100cqi - var(--_content-width)) / 2,
        0px
      );
    }
  }

  ._label {
    inline-size: fit-content;
  }
}
```

変えたのは4点です。1つ目に、数値には内部プロパティの名前を付け、本文の幅を `--_content-width`、最小の余白を `--_gutter`、はみ出させる量の上限を `--_overhang` にしました（「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」）。2つ目に、基準の幅を、スクロールバーの幅を含む `100vw` から、ルートのコンテナの幅の `100cqi` に変えました。ページ全体の幅で決めてよい要素なら、`100svi` を使います（「[6-2 ビューポート単位とコンテナ単位](/values/viewport-and-container-units/)」）。

3つ目に、ラベルをずらす手段を、書字方向に従わない `left` から `margin-inline-start` に変えました。4つ目に、本文の幅を決める `._article-inner` とラベルの `._label` を、`@scope` の中の子要素として分け、ラベルをずらす `margin-inline-start` は、本文の幅を決める要素のネストに書きました。境の672pxと720pxは、画面の幅ではなく、コンテナの幅で数えます。

次のデモの破線の枠が本文の幅です。デモの左右の余白を外しているので、コンテナの幅はデモの幅と同じです。480pxではラベルが枠の左端にそろい、696pxでは12px、1024pxでは24px、枠の外へ出ます。

<Demo title="clamp() の範囲に負の値を含め、余白が広いときだけラベルを本文の外へ出す" html={hangingHtml} css={hangingCss} widths={[480, 696, 1024]} bleed="inline" />

はみ出させる手段には、`inset-inline-start` ではなく `margin-inline-start` を選びます。`inset-inline-start` でずらすには `position: relative` が要り、ずらしても元の場所が空いたまま描画だけが動きます。負の `margin-inline-start` なら、ラベルはレイアウトの中で動き、位置を決めるための指定だと分かります。要素の間隔を作る `margin` とは役割が違うので、次兄弟結合子で付ける規則の対象にもなりません（「[11-2 余白を設計する](/layout-practice/spacing/)」）。

## `abs()` で並びの中央からの距離を求める

`abs()` は、引数の絶対値を返す関数です。兄弟の中の位置を数値で返す `sibling-index()` と、兄弟の数を返す `sibling-count()` と組み合わせると、並びの中央からの距離を式で表せます（「[5-4 子要素の位置で選ぶ](/pseudo/child-index/)」）。中央の位置は `(sibling-count() + 1) / 2` で、自分の位置との差の絶対値を `abs()` で取れば、中央の項目が0、両端に近いほど大きい値になります。この値に一定の長さを掛けて項目を下げると、中央を頂点にして、両端へ下がる弧の形に並びます。{/* 要確認: 出典なし。abs() で中央からの距離を求め、弧の形に並べる例 */}

```css title="🙆‍♂ Recommended: 対応した環境でだけ、中央から離れた項目ほど下げる" from="values/sibling-index-arc"
@scope (.scoped.badge-row) to (.scoped) {
  :scope {
    --_step: 12px;

    /* 折り返すと弧の形が崩れるので、折り返さない */
    display: block flex;
    gap: 8px;
    padding-block: 8px;

    @supports (z-index: sibling-index()) {
      /* 5枚のとき、両端の項目は中央から2枚分離れ、2段分下がる */
      padding-block-end: calc(8px + 2 * var(--_step));
    }
  }

  li {
    @supports (z-index: sibling-index()) {
      /* 中央から離れた項目ほど下げて、中央を頂点にした弧の形にするため */
      translate: 0 calc(abs(sibling-index() - (sibling-count() + 1) / 2) * var(--_step));
    }
  }
}
```

<Demo title="対応した環境では、中央の項目が高く、両端の項目が低い弧の形に並ぶ" html={arcHtml} css={arcCss} widths={[]} />

`sibling-index()` に対応したブラウザでは、5つの項目のうち中央の「JS」がいちばん高く、隣の「CSS」と「a11y」が12px、両端の「HTML」と「SVG」が24px下がります。対応していないブラウザでは、5つの項目が同じ高さで横に並びます。`sibling-index()` は、Chrome 138、Firefox 154、Safari 26.2で使えます。

項目を下げるには、`margin-block-start` ではなく `translate` を使います。弧の形は見た目だけの装飾なので、レイアウトを変えない変形が向いています。`margin-block-start` で下げると、下げた分だけ一覧の高さが変わり、要素の間隔を作る `margin` とも見分けが付きません。ただし、`translate` は後ろの内容を押し下げないので、いちばん下がる項目の分だけ、一覧の下に余白を取っておきます。

中央の位置を `3` のような数値で書かず、`sibling-count()` から求めているので、項目の数を変えても、弧は左右対称のままです。ただし、折り返すと弧の形が崩れるので、一覧は折り返さずに並べています。項目を増やすときは、置き場所の幅に収まる数までにします。`abs()` は2025年6月から主要なブラウザで使え、本書の対象のブラウザもすべて対応しています。`sibling-index()` に対応したブラウザはどれも `abs()` にも対応しているので、`@supports` は `sibling-index()` の判定だけで足ります。

## `pow()` で基準と比率から段階を求める

`pow()` は、1つ目の引数を2つ目の引数の回数だけ掛けた値（累乗）を返す関数です。文字サイズや余白の段階を「基準の値に、同じ比率を段階の数だけ掛ける」と決めているなら、各段階を `pow()` の式で書けます。{/* 要確認: 出典なし。基準と比率から段階を求める書き方 */}基準を16px、比率を1.25とすると、1段階上は20px、2段階上は25px、3段階上は31.25pxで、段階の数が `pow()` の2つ目の引数になります。

この段階を、計算した結果の数値だけで並べると、次のようになります。`1.5625rem` が「16pxに1.25を2回掛けた値」であることは、コードからは読み取れません。比率を1.2に変えるときは、すべての段階を計算し直して書き換えることになります。

```css title="🙅‍♂ Not Recommended: 比率から求めた段階を、結果の数値だけで並べる" issue="convention"
/* 🙅‍♂ Not Recommended */
.section-title {
  font-size: 1.5625rem;
}

.section-lead {
  font-size: 1.25rem;
}

.section-note {
  font-size: 0.8rem;
}
```

`pow()` で書くと、基準を `--_base`、比率を `--_ratio` に置き、各段階はその2つと段階の数から求める式になります。基準より小さい段階は、負の数で表します。`pow(1.25, -1)` は1を1.25で割った値（0.8）なので、`._note-text` の文字サイズは12.8pxです。

```css title="🙆‍♂ Recommended: 基準と比率から、各段階を pow() で求める" from="values/pow-type-scale"
@scope (.scoped.article-body) to (.scoped) {
  :scope {
    /* 基準の大きさと、1段階ごとに掛ける比率 */
    --_base: 1rem;
    --_ratio: 1.25;
  }

  ._title-text {
    font-size: calc(var(--_base) * pow(var(--_ratio), 2));
  }

  ._lead-text {
    font-size: calc(var(--_base) * pow(var(--_ratio), 1));
  }

  ._note-text {
    font-size: calc(var(--_base) * pow(var(--_ratio), -1));
  }
}
```

式には、基準と比率と段階の数が残るので、それぞれの値がどう決まったのかを読み取れます。比率を変えるときも、`--_ratio` の1か所を書き換えれば、すべての段階が式に従って変わります。なお、`pow()` の2つの引数は、どちらも単位のない数値でなければなりません。`pow(1rem, 2)` のように長さを渡すと宣言が無効になるので、単位は、`pow()` の結果に基準の長さを掛けて付けます。

次のデモは、同じ5つの段階を、1つ目の区画は比率1.2、2つ目の区画は比率1.25で求めたものです。2つの区画の違いは `--_ratio` の値だけで、各段階の式は同じです。基準の段階0はどちらも16pxで、段階3は約27.6pxと31.25px、段階−1は約13.3pxと12.8pxになり、比率が大きいほど段階の間の差が開きます。{/* 要検証: ブラウザ。デモの各段階の計算値 */}

<Demo title="同じ式で、比率だけを1.2と1.25に変えた文字サイズの段階" html={powHtml} css={powCss} widths={[320, 768]} />

本書のデモでは、文字サイズを役割のトークン（`--text--<役割>--font-size`）で指定しています（「[14-5 文字の役割と色](/typography/text-roles/)」）。比率で段階を決めるデザインなら、`pow()` はコンポーネントの中ではなく、プリミティブのトークンの定義に書きます。プリミティブの文字サイズは単位のないpx相当の数値なので（「[10-4 デザイントークン](/components/design-tokens/)」）、`pow()` の結果も数値のまま持てます。役割はプリミティブを参照し、コンポーネントは役割を参照するので、比率を変えてもコンポーネントのCSSは変わりません。

```css title="🙆‍♂ Recommended: プリミティブのトークンを、基準と比率から求める"
:root {
  --font-size--base: 16;
  --font-size--ratio: 1.25;
  --font-size--sm: calc(var(--font-size--base) * pow(var(--font-size--ratio), -1));
  --font-size--md: var(--font-size--base);
  --font-size--lg: calc(var(--font-size--base) * pow(var(--font-size--ratio), 1));
  --font-size--xl: calc(var(--font-size--base) * pow(var(--font-size--ratio), 2));
  --text--body--font-size: var(--font-size--md);
  --text--title--font-size: var(--font-size--lg);

  /* ... */
}
```

ただし、本書のデモの文字サイズのトークン（12、14、16、20、28など）は、デザインで決めた値を並べたもので、1つの比率から求めたものではありません。こうした値を `pow()` の式に置き換えると、14が12.8に変わるように、デザインとは違う値になります。式に残すのは、その値を実際に決めた根拠です。比率から決めていない段階は、数値のままトークンにします（「[6-3 計算関数で根拠を式に残す](/values/math-functions/)」）。

この見出しで求めた段階は、どれも画面の幅によらない固定の値です。画面の幅に比例して大きさを変える文字サイズは、「[14-4 文字サイズと改行](/typography/size-and-line-breaks/)」の `clamp()` のユーティリティで扱い、段階の値はその最大値として渡します。`pow()` は、`sqrt()`、`hypot()`、`log()`、`exp()` とともに2023年12月から主要なブラウザで使え、本書の対象のブラウザもすべて対応しています。

## `round()` で値を刻みにそろえる

`round()` は、値を、指定した刻みの倍数に丸める関数です。`round(丸め方, 値, 刻み)` の順に書き、`round(down, 100%, 1ic)` は、要素の幅を全角1文字分（`1ic`）の倍数に切り下げます。本書では、この形で段落の幅を丸め、ベタ組みの行末に半端なすき間を残しにくくしています（「[14-2 和文組版を整える](/typography/japanese-typesetting/#約物のぶら下げ)」）。

丸め方は4つあります。省略したときの `nearest` は、近いほうの倍数を選び、ちょうど中間なら大きいほうに丸めます。`up` は常に大きいほうへ、`down` は常に小さいほうへ丸めます。`to-zero` は0に近いほうへ丸めるので、正の値では `down` と同じですが、負の値では結果が分かれます。`round(down, -30px, 16px)` は `-32px`、`round(to-zero, -30px, 16px)` は `-16px` です。「`clamp()` の範囲に負の値を含める」のはみ出し量のように負の値を取る式で、絶対値を上限より大きくしたくないなら `to-zero` を選びます。

丸め方は、刻みを超えてよい向きで選びます。親の幅を丸めた結果が親を超えると横にはみ出すので、幅は `down` で丸めます。中身を収めるための最小の高さを丸めるなら、中身より低くならない `up` です。どちらに振れても困らない余白なら、`nearest` で足ります。

刻みには、そろえたい単位の長さを書きます。全角の文字にそろえるなら `1ic`、行の高さにそろえるなら `1lh`、4pxの格子にそろえるなら `4px` です。値と刻みは同じ種類でなければならず、長さを丸めるなら刻みも長さにします。刻みを省略できるのは、値が単位のない数値のときだけで（刻みは1になります）、`round(17.3px)` のように長さの刻みを省くと宣言が無効になります。`100%` と `1ic` のように、パーセントと長さを組み合わせることはできます。

```css title="🙆‍♂ Recommended: コンテナの幅から求めた余白を、4pxの刻みにそろえる"
@scope (.scoped.feature-card) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
  }

  ._body {
    /* ほかの部品の4pxの倍数の余白と並べたときに、端数でずれないようにするため */
    padding-inline: round(clamp(16px, 5cqi, 40px), 4px);
  }
}
```

`clamp()` とコンテナ単位で求めた値は、幅に応じて `19.7px` のような端数を取ります。`round()` で包むと、余白は16px、20px、24pxのように4pxずつ変わり、ほかの部品の4pxの倍数の余白と並べてもずれが目立ちません。{/* 要確認: 出典なし。流動的な値を round() で刻みにそろえる使い方 */}`round()` は2024年5月から主要なブラウザで使え、本書の対象のブラウザもすべて対応しています。

## 長さを単位のない数値に変える割り算

長さを単位のない数値に変えるときは、単位のついた値で割ります。`calc(100svi / 1px)` は、画面の幅をpxで数えた数値（幅375pxの画面なら375）を返します。単位のついた値どうしを割り、単位を打ち消して数値にする計算は、「typed arithmetic」と呼ばれる仕様です。

この割り算が使えなかった時期には、`tan(atan2(長さ, 1px))` という三角関数の組み合わせで同じ数値を得ていました。`atan2()` が2つの長さから角度を求め、`tan()` がその角度から比を求めるので、結果は2つの長さの比になります。ただし、角度を経由する回り道なので、式を読んでも割り算だとは分かりません。既存のコードやAIの出力でこの形を見つけたら、割り算に書き換えます。

```css title="🙅‍♂ Not Recommended: 三角関数で単位を外す" issue="convention"
/* 🙅‍♂ Not Recommended */
:root {
  --viewport--width: tan(atan2(100svi, 1px));
}
```

```css title="🙆‍♂ Recommended: 単位のついた値で割って単位を外す"
:root {
  --viewport--width: calc(100svi / 1px);
}
```

この割り算に対応しているのはChrome 140以降とSafari 18.2以降です。本書の対象のブラウザ（Safari 18系の最終版以降と、ほかのブラウザの最新版）のうち、Firefoxだけは安定版が対応しておらず、158で対応する予定です。対応していない環境では、この式を含む宣言が無効になります。そのため、宣言が無効になっても内容を読めて操作できる場面で使います（「[1-2 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」）。

一方、デザインカンプの値を使う計算に、この割り算は要りません。`calc(40px / 1280px * 100svi)` と書かなくても、はじめから単位のない数値で割れば同じ結果になり、どのブラウザでも計算できます。「[6-1 pxとremを使い分ける](/values/px-and-rem/)」で説明したように、サイズのトークンを単位のない数値で持っておくと、こうした計算もしやすくなります。

```css title="🙆‍♂ Recommended: デザインカンプの値は単位のない数値で割る"
@scope (.scoped.page-section) to (.scoped) {
  :scope {
    padding-inline: clamp(16px, 40 / 1280 * 100svi, 40px);
  }
}
```

比率で求めた値にも、`clamp()` で最小値と最大値を付けます。比率だけで決めると、狭い画面では余白が細くなりすぎ、広い画面では際限なく広がるからです（「[13-7 カンプの幅で全体を拡大・縮小しない](/responsive/design-comp-pattern/)」）。

単位のついた値で割って作った長さには、ズームについての注意があります。Chromeでは、`calc(24px / 1rem * 1rem)` のように長さどうしの割り算を含む式で定義した値が、ブラウザのズームで拡大縮小されません（2026年初めに確認）。式の値は24pxと同じ長さですが、表示を拡大しても大きさが変わらないので、文字サイズに使うとWCAGの達成基準1.4.4（テキストのサイズ変更）を満たせなくなるおそれがあります。この割り算から求めた値を文字サイズに使うときは、`max()` でremの下限を付けます。

## Chrome系のブラウザだけが対応する `calc-size()` と `@function`

`calc-size()` は、`auto` や `fit-content` のようなキーワードで決まる大きさを、計算で扱える値に変える関数です。`calc-size(auto, size + 16px)` の `size` が、`auto` で決まる大きさを表します。計算した値は数値の大きさと同じように補間されるので、`block-size: 0` から「内容の高さ＋余白」まで変わるトランジションも書けます。

ただし、高さを `auto` まで動かすだけなら、`interpolate-size: allow-keywords` で足ります。本書はこの指定を、ベーススタイルの `:root` に1行で書いています（「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」）。MDNも、計算を伴わないなら `calc-size()` ではなく `interpolate-size` を使うよう勧めています。`calc-size()` が要るのは、内容の大きさに値を足したり掛けたりしたうえで動かす場面だけです。使うとしても、直前に `block-size: auto` のような普通の値を書きます。未対応の環境では `calc-size()` を含む宣言が捨てられ、前の値が残るからです。

```css title="🙅‍♂ Not Recommended: 計算を伴わないのに calc-size() で auto まで動かす" issue="behavior"
/* 🙅‍♂ Not Recommended */
.faq-item {
  &[open]::details-content {
    block-size: calc-size(auto, size);
  }
}
```

```css title="🙆‍♂ Recommended: auto への補間は、ベーススタイルの interpolate-size で有効にする"
@layer base {
  :root {
    @media (prefers-reduced-motion: no-preference) {
      interpolate-size: allow-keywords;
    }
  }
}
```

`@function` は、引数を受け取って値を返す関数を、CSSで定義するアットルールです。「[6-3 計算関数で根拠を式に残す](/values/math-functions/#計算はcssに任せる)」の傾きと切片の計算も、基準の値を引数として受け取る関数にまとめれば、使う側は関数を呼ぶだけで済みます。ただし、未対応の環境では、関数を呼んだ宣言が無効になります。その環境のために従来の式も書くことになり、重複を減らすという目的が果たせません。

```css title="🙅‍♂ Not Recommended: @function で定義した関数を、従来の式なしで呼ぶ" issue="behavior"
/* 🙅‍♂ Not Recommended */
@function --fluid(--min-size <number>, --max-size <number>) returns <length> {
  result: clamp(
    var(--min-size) / 16 * 1rem,
    (var(--max-size) - var(--min-size)) / 905 * 100svi + (var(--min-size) - (var(--max-size) - var(--min-size)) / 905 * 375) / 16 * 1rem,
    var(--max-size) / 16 * 1rem
  );
}

.fluid-heading h2 {
  font-size: --fluid(24, 40);
}
```

SafariとFirefoxでは `--fluid()` を含む宣言が無効になり、見出しはブラウザのデフォルトスタイルの文字サイズ（`h2` なら `1.5em`）のままになります。kiso.cssは、見出しの文字サイズをリセットしていないからです。それを避けるには、6-3の「計算はCSSに任せる」で示した式を前の宣言として書く必要があり、同じ計算を2か所で持つことになります。

`calc-size()` はChrome 129以降、`@function` はChrome 139以降のChrome系のブラウザだけが対応しています。SafariとFirefoxでは使えないので、本書では、どちらも現状では採用しません。大きさのアニメーションは `interpolate-size` で、計算の重複はカスタムプロパティの式とユーティリティで扱います。
