単位は、「ユーザーがブラウザの文字サイズを大きくしたとき、この値も一緒に大きくなるべきか」で選びます。大きくなるべき値にはrem（またはem）を、そうでない値にはpxを使います。文字サイズはrem、`padding` や線の太さはpxが基本です。

remへの変換は `calc(24 / 16 * 1rem)` のようにピクセル値からの式で書き、`html { font-size: 62.5% }` のようにルートの文字サイズを変える方法は使いません。`line-height` には単位を付けません。

## すべてremで書く場合と、すべてpxで書く場合

単位の話題でよく見かけるのが、「アクセシビリティのために `font-size` はremで指定する」というルールです。方向は正しいのですが、このルールだけが独り歩きすると、極端な書き方が生まれます。すべてをpxで書く書き方と、余白や線までremで書く書き方です。

```css title="🙅‍♂ Not Recommended: ルートの文字サイズを変えて、すべてをremで書く" issue="behavior"
/* 🙅‍♂ Not Recommended */
html {
  font-size: 62.5%;
}

.card {
  padding: 1.6rem 2.4rem;
  border: 0.1rem solid;
  border-radius: 0.8rem;
  font-size: 1.6rem;
}
```

すべてをpxで書くと、ブラウザの文字サイズの設定を大きくしても、文字は大きくなりません。文字を大きくしたいユーザーの設定が反映されません。反対に、上の例のようにすべてをremで書くと、文字と一緒に余白や線まで大きくなります。余白が広がった分だけ文字を置ける幅が狭まり、1行に入る文字数が減って、かえって読みにくくなります。

上の例には、もう1つ問題があります。ルートの文字サイズを `62.5%` にして1remを10px相当にする方法は、remの計算を簡単にするためのものです。しかし、ルートの文字サイズが16px相当であることを前提にした外部のCSSを読み込むと、そちらで指定した大きさが想定と変わります。ルートの文字サイズを `10px` のようにpxで指定する例もありますが、これではユーザーの文字サイズの設定そのものが反映されなくなります。

私が気になるのは、remを使っていても、文字サイズの設定を変えて確かめた形跡のないコードです。確かめれば、ルートに `font-size: 10px` と書いたサイトで設定が反映されていないことはすぐに分かります。remは使うだけで正しくなる単位ではなく、設定を変えたときの振る舞いまで考えて使う単位です。

## ズームと文字サイズの設定は別の機能

ブラウザには、表示を大きくする機能が2つあります。ページ全体を拡大するズームと、文字の大きさだけを変える文字サイズの設定です。ズームはpxで指定した値も含めてすべてを拡大します。一方、文字サイズの設定が変えるのはルートの文字サイズで、その影響を受けるのはremやemで指定した値だけです。

Chromeでは、設定の「デザイン」にある「フォントサイズ」が文字サイズの設定にあたります。デフォルトは16pxで、ここを大きくするとルートの文字サイズが変わり、remで指定した値もそれに比例して大きくなります。pxで指定した値は変わりません。

以前の私は、「remで指定した値が変わるのはChromeの文字サイズの設定だけで、使う人の少ない機能に合わせる手間は割に合わない」という意見にも一理あると感じていました。考えが変わったのは、`<meta name="text-scale">` が登場したからです。このメタタグを有効にすると、OSの文字サイズの設定とブラウザの文字サイズの設定の両方に比例して、文字サイズが拡大・縮小されます。pxで指定した値がこれに追従しないことは、策定中の仕様にも書かれています。

<Baseline id="meta-text-scale" />

`<meta name="text-scale">` に対応しているのはChrome系のブラウザだけです。それでも、OSの設定で文字を大きくしているユーザーの設定も反映されるようになり、remを使う意味は大きくなりました。

2つの機能は、全体を大きくしたいならズーム、文字だけを大きくしたいなら文字サイズの設定というように、役割が分かれています。すべてをremで書くと、文字サイズの設定がズームと同じ振る舞いになり、この役割の違いがなくなります。だからこそ、どの値を文字と一緒に大きくし、どの値をそのままにするかを、値ごとに選ぶ必要があります。

次のデモでは、文字サイズの設定を3段階で切り替えられます。ブラウザの設定はデモの中から変えられないので、ルートの文字サイズを切り替えて再現しています。「特大」を選ぶと、すべてpxのカードは何も変わらず、すべてremのカードは余白と線まで太くなります。使い分けたカードでは文字だけが大きくなり、文字を置ける幅が広く残ります。

<Demo title="文字サイズの設定を変えたときの、px・rem・使い分けの違い" html={scalingHtml} css={scalingCss} variant="neutral" />

すべてremのカードは、ズームで拡大したときとほとんど同じ見え方です。文字サイズの設定を使うユーザーが求めているのは、全体の拡大ではなく、文字を読みやすくすることのはずです。使い分けたカードのほうが、その求めに合っています。

## 文字と一緒に大きくなるべき値

判断の基準は、「ユーザーがブラウザの文字サイズを大きくしたとき、この値も一緒に大きくなるべきか」です。はいと答えられる値はremで、いいえと答えられる値はpxで指定します。

remで指定するのは、まず `font-size` です。段落の間の縦の余白も、文字の大きさとの釣り合いで読みやすさが決まるので、remにします。テキストを含む要素の幅（`max-inline-size`）やボタンの最小の高さも、文字だけが大きくなると窮屈になるため、remで指定します。一方、カードどうしやボタンどうしのような部品の間の余白は、文字と一緒に広げる必要がないのでpxにします。メディアクエリのブレイクポイントをremにする理由も同じで、「[13-2 ブレイクポイントの決め方](/responsive/breakpoints/)」で説明しています。

pxで指定するのは、`padding`、とくに水平方向の `padding` です。文字が大きくなった分だけ1行に入る文字数は減っているので、余白まで広げると、さらに文字数が減ってしまいます。`border-width`、`box-shadow`、`outline-width`、`outline-offset` のような装飾的な値も、文字の大きさとは関係がないのでpxにします。

emを使うのは、その要素自身の文字サイズに比例させたい値です。見出しの横に置くアイコンの大きさを `1em` にすれば、見出しの文字サイズに合わせてアイコンも大きくなります。アイコンとラベルの間の `gap` も、emにすると文字との比率を保てます。

```css title="🙆‍♂ Recommended: 値ごとに、文字と一緒に大きくなるべきかで単位を選ぶ"
@scope (.scoped.notice-card) to (.scoped) {
  :scope {
    max-inline-size: calc(640 / 16 * 1rem);
    padding: 16px 24px;
    border: 1px solid;
    border-radius: 8px;

    & > * + p {
      margin-block-start: calc(12 / 16 * 1rem);
    }
  }

  h2 {
    display: block flex;
    gap: 0.5em;
    align-items: start;
    font-size: calc(20 / 16 * 1rem);

    & > ._icon {
      flex-shrink: 0;
    }
  }

  ._icon {
    inline-size: 1em;
    aspect-ratio: 1;
    margin-block: calc((1lh - 1em) / 2);
  }
}
```

このカードでは、文字サイズと段落の間の余白、カードの最大幅をremで、`padding` と線と角丸をpxで指定しています。アイコンの大きさとラベルとの間隔は、見出しの文字サイズに比例させたいのでemです。見出しが折り返してもアイコンが縮まず1行目にそろうように、`flex-shrink: 0` と `1lh` の式も書いています（後の「行の高さを基準にするlhとrlh」）。`gap` や `margin` のように場面によって答えが変わる値は、先ほどの問いに照らして1つずつ判断します。

emのほかにも、その要素のフォントの寸法を基準にする単位があります。`cap` は大文字の高さ、`ex` は小文字の「x」の高さ（x-height）、`ic` は全角の「水」の送り幅（横書きでは1字分の幅）です。どれも、要素のフォントスタックで最初に使えるフォントの寸法から決まり、フォントがその寸法を持たないときは、`cap` はアセント、`ex` は `0.5em`、`ic` は `1em` として扱われます。文字サイズに比例するので、emと同じく文字サイズの設定にも追従します。

これらは、「文字の何に合わせるか」がemよりも具体的に決まっている値に使います。本書では、本文の行の長さを `40ic` のように全角の字数で決め（「[8-3 グローバルに書いてはいけないもの](/reset/global-pitfalls/#ほかの要素を壊すプロパティ)」）、段落の幅を `1ic` の倍数に丸めています（「[14-2 和文組版を整える](/typography/japanese-typesetting/#約物のぶら下げ)」）。見出しの各行に敷く背景の行の間隔は、大文字の高さの `1cap` から求め（「[16-7 文字とリストの装飾](/decoration/text-ornaments/#見出しの行ごとに背景を敷く)」）、メニューの区切りの点の大きさは、区切りの文字「・」と釣り合う `1ex` で決めています（「[16-10 区切り線を引く](/decoration/separators/#メニューに点の区切りを入れる)」）。値はフォントの寸法で変わるので、フォントを変えたら表示を確かめます。行の高さを基準にする `lh` は、フォントの寸法ではなく `line-height` から決まる単位で、後の「行の高さを基準にするlhとrlh」で説明します。

## pxからremへの変換は式で書く

デザインカンプの値は、たいていピクセルで書かれています。remに変換するときは、計算した結果（`1.5rem`）ではなく、`calc(24 / 16 * 1rem)` のように変換の式で書きます。16は、ブラウザの文字サイズのデフォルト値です。式にしておけば、カンプの「24px」をコードからそのまま読み取れ、電卓で割り算をする手間も、計算を間違える心配もなくなります。

この式があれば、ルートの文字サイズを `62.5%` にして計算を簡単にする必要もありません。ルートの文字サイズはブラウザの設定のままにしておき、変換は式に任せます。

```css title="🙆‍♂ Recommended: 変換の式で、カンプのピクセル値を残す"
@scope (.scoped.article-header) to (.scoped) {
  ._lead {
    max-inline-size: calc(560 / 16 * 1rem);
    font-size: calc(18 / 16 * 1rem);
  }
}
```

`clamp()`、`min()`、`max()` の中では、`calc()` を省いて `24 / 16 * 1rem` と書けます。これらの関数の引数では、もともと四則演算が使えるからです。メディアクエリの条件にも同じ式を使いますが、メディアクエリの中のremは、CSSでルートに指定した値ではなく、ブラウザの設定の文字サイズを基準に計算されます（[13-2](/responsive/breakpoints/)）。

サイズのトークンを作るときも、同じ考え方を使います。余白のトークンを `--spacing--md: 24;` のように単位のない数値で持ち、使う場所で単位に変換します。同じ24pxの余白でも、段落の間ならrem、カードの `padding` ならpxと、使う場所によって選ぶ単位が変わるからです。トークンの命名や置き場所は「[10-4 デザイントークン](/components/design-tokens/)」で扱います。

```css title="🙆‍♂ Recommended: 単位のないトークンを、使う場所で変換する"
:root {
  --spacing--sm: 16;
  --spacing--md: 24;
}

@scope (.scoped.notice-card) to (.scoped) {
  :scope {
    padding-inline: calc(var(--spacing--md) * 1px);

    & > * + p {
      margin-block-start: calc(var(--spacing--sm) / 16 * 1rem);
    }
  }
}
```

なお、カンプの比率を保つために、画面の幅に比例する係数をすべての値に掛ける書き方（フルリキッド）は使いません。文字サイズを画面の幅から決めると、狭い画面で文字が読めないほど小さくなり、文字サイズの設定も反映されにくくなるからです。理由と代わりの方法は「[13-7 カンプの幅で全体を拡大・縮小しない](/responsive/design-comp-pattern/)」で説明しています。

## line-heightには単位を付けない

`line-height` は、`1.6` のように単位のない数値で指定します。単位のない数値は「文字サイズの何倍か」という比率のまま子要素に継承されます。そのため、子要素の文字サイズが変わっても、行の高さはそれに合わせて計算し直されます。

単位を付けると、事情が変わります。`24px` や `1.5em` のように長さで指定すると、計算した後の長さがそのまま子要素に継承されます。本文の16pxに合わせた24pxの行の高さが32pxの見出しにもそのまま使われ、見出しが2行になると行が重なります。`%` で指定した場合も、計算後の長さが継承される点は同じです。

```css title="🙅‍♂ Not Recommended: 単位のある line-height" issue="behavior"
/* 🙅‍♂ Not Recommended */
.article {
  line-height: 24px;
}

.article h2 {
  font-size: calc(32 / 16 * 1rem);
}
```

```css title="🙆‍♂ Recommended: 単位のない数値で、比率として継承させる"
@scope (.scoped.article-body) to (.scoped) {
  :scope {
    line-height: 1.75;
  }

  h2 {
    font-size: calc(32 / 16 * 1rem);
    line-height: 1.4;
  }
}
```

単位のない数値なら、文字サイズの設定を大きくしたときも、行の高さが文字と一緒に大きくなります。行の高さは「文字と一緒に大きくなるべき値」の代表で、単位のない比率がそれを自然に満たします。本書のStylelintの設定では、`declaration-property-unit-allowed-list` で `line-height` に単位が付いていないかを検証しています。

デザインカンプでは、行の高さが「行送り28px」のようにピクセルで書かれていることがあります。その場合は、文字サイズで割った比率にします。16pxの文字で行送りが28pxなら、`line-height` は1.75です。見出しや本文ごとの具体的な値と、`line-height: 1` を使わない理由は、「[14-3 行の高さとハーフレディング](/typography/line-height/)」で説明します。

## 行の高さを基準にするlhとrlh

`lh` は、その要素の `line-height` を長さにした単位で、`rlh` は、ルート要素（`html`）の `line-height` を長さにした単位です。`line-height` を単位のない数値で指定していれば、行の高さは文字と一緒に大きくなるので、`lh` と `rlh` で決めた値も文字サイズの設定に追従します。「何行分か」で決まる値には、remよりもこれらの単位が合います。

<Baseline id="lh" />

たとえば、行頭のアイコンを1行目の中央に置くときは、アイコンの上下の `margin` を、1行の高さとアイコンの大きさの差の半分にします。文字の大きさや `line-height` を変えても、式を直す必要はありません。アイコンの配置の全体は「[11-13 アイコンを配置する](/layout-practice/icon-alignment/)」で説明しています。

```css title="🙆‍♂ Recommended: 1行の高さを基準に、アイコンを1行目の中央に置く" from="values/lh-icon"
@scope (.scoped.feature-list) to (.scoped) {
  ._item {
    display: block flex;
    align-items: start;

    &::before {
      content: "";
      flex-shrink: 0;
      inline-size: 1em;
      aspect-ratio: 1;
      margin-block: calc((1lh - 1em) / 2);
    }
  }
}
```

次のデモでは、文字サイズと `line-height` の違う3つの項目に、同じ式でアイコンを置いています。幅を狭めて項目が折り返しても、アイコンはどれも1行目の中央にとどまります。

<Demo title="1lh を基準に、文字サイズや行の高さが違っても1行目の中央にアイコンを置く" html={lhIconHtml} css={lhIconCss} widths={[320, 480, 768]} />

`lh` の基準は、値を使う要素の行の高さです。見出しと段落のように `line-height` の違う要素に同じ `1lh` を指定すると、要素ごとに長さが変わります。要素をまたいで同じ長さにそろえたいときは、`rlh` を使います。`lh` で行の高さのアキを打ち消す方法は「[14-3 行の高さとハーフレディング](/typography/line-height/)」で説明しています。

## 設定を変えて確かめる

remを使ったら、ブラウザの文字サイズの設定を大きくして、表示を確かめます。remを使っていても、設定が反映されていなかったり、文字が大きくなったときに崩れたりしていれば意味がありません。どちらも、設定を変えて見なければ分からないことです。

確かめるときは、文字が大きくなっているか、`padding` や線が太くなりすぎていないか、固定の高さから文字があふれていないかを見ます。高さを `height` で固定していると、文字が大きくなったときに中身があふれるので、高さは `min-block-size` で指定します（[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/#rule-min-block-size-over-fixed-height)）。ブレイクポイントをremで指定していれば、文字を大きくしたときに1カラムのレイアウトへ早めに切り替わることも確かめられます。

```css title="🙅‍♂ Not Recommended: 高さを固定したボタン" issue="behavior"
/* 🙅‍♂ Not Recommended */
.button {
  block-size: 48px;
  font-size: 1rem;
}
```

```css title="🙆‍♂ Recommended: 最小の高さだけを決め、文字が大きくなったら伸ばす"
@scope (.scoped.button) to (.scoped) {
  :scope {
    min-block-size: calc(48 / 16 * 1rem);
    font-size: 1rem;
  }
}
```

前者は、文字サイズの設定を「特大」にしてラベルが2行に折り返すと、48pxの高さから文字がはみ出します。1行に収まっている間は、24pxの文字でも行の高さは36px程度なので、はみ出しません。後者は最小の高さもremなので、文字と一緒に高くなります。

ズームでの確認も併せて行います。ズームはpxを含めてすべてを拡大するので、拡大したときに横スクロールが起きないかや、ビューポート単位で決めた値が拡大されているかを見ます。ビューポート単位とズームの関係は、「[6-2 ビューポート単位とコンテナ単位](/values/viewport-and-container-units/)」で説明します。
