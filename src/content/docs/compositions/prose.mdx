`prose` は、直下の子のうち2つ目以降に `margin-block-start` を付けて、子要素の間隔を作るコンポジションです。子は通常フローのまま縦に並び、間隔は公開プロパティ `--prose--space` で受け取ります。デフォルト値は `0` です。

`stack` と違うのは、間隔を子ごとに変えられることです。`margin-block-start` の `var(--prose--space)` は子要素の側で値が決まるので、ある子に `style="--prose--space: …"` を渡すと、その子の前の間隔だけが変わります。見出しの前だけ広げる、見出しの直後だけ詰めるといった調整を、セレクタを書き足さずに行えます。

本文の流れの間隔を `gap` ではなく `margin` で作る理由は、「[11-2 余白を設計する](/layout-practice/spacing/)」で説明しています。この節では、`prose` の仕組みと使い方、`stack` やCMSの本文エリアとの使い分けを説明します。

## 一律の `gap` に、子ごとの余白を足すと起きること

ページの見出し、導入文、本文、一覧へ戻るリンクのように、種類の違う要素が縦に続く場所では、間ごとに余白の大きさを変えるのが普通です。見出しの前は広く、見出しと直後の段落の間は狭く、末尾のリンクの前はさらに広く、といった具合です。

縦に積むコンポジションとして `stack` があるので、まずこれを使い、広げたい要素にだけ `margin` を足したくなります。

```css title="🙅‍♂ Not Recommended: Flexbox の gap に、見出しの margin を足す" issue="behavior"
/* 🙅‍♂ Not Recommended */
._body {
  display: block flex;
  flex-direction: column;
  gap: calc(16 / 16 * 1rem);

  & > h3 {
    margin-block-start: calc(32 / 16 * 1rem);
  }
}
```

この書き方では、見出しの前の間隔は32px相当ではなく48px相当になります。フレックスアイテムの `margin` は相殺されず、`gap` に足されるからです。デザインカンプの「見出しの前は48px相当」を再現するには、`gap` の値を引いた32px相当を書くことになり、後から `gap` を変えると見出しの前の間隔も一緒に変わります。さらに、`& > h3` は先頭の見出しにも一致するので、見出しから始まる本文では、先頭に余計な余白が付きます。

問題は、`gap` が親の1つの値で、すべての間に同じ大きさで入ることです。間ごとに違う余白を作るには、親の値を打ち消すか、差分を子に足すしかありません。`prose` は、間隔そのものを子要素の側に持たせて、この打ち消しと差分の計算をなくします。

## `prose` の仕組み

`prose` の実装は、1つのルールだけです。

```css title="🙆‍♂ Recommended: 2つ目以降の子の前に、子の側で解決される間隔を付ける"
/**
 * 子要素を通常フローのまま縦に並べ、2つ目以降の子の前に間隔を空ける。
 * 間隔は子要素の側で解決されるので、子ごとに値を上書きできる。
 *
 * @prop {length} --prose--space [0] - その子要素の前の間隔。ルートに渡すと全体の値に、子に渡すとその子の前だけの値になる
 *
 * @example
 * <div class="prose" style="--prose--space: calc(var(--spacing--sm) / 16 * 1rem)">
 *   <p>...</p>
 *   <h2 style="--prose--space: calc(var(--spacing--xl) / 16 * 1rem)">...</h2>
 *   <p>...</p>
 * </div>
 */
.prose {
  & > * + * {
    margin-block-start: var(--prose--space, 0);
  }
}
```

`& > * + *` は、`prose` の直下の子のうち、直前に兄弟要素があるものに一致します。最初の子には `margin` が付かないので、`prose` の先頭に余計な余白はできません。末尾にも何も付けないので、`prose` を置く場所の余白と干渉しません。

公開プロパティは `--prose--space` の1つだけで、意味は「その子要素の前の間隔」です。デフォルト値は `0` で、コンポジションの間隔のデフォルト値を `0` にする理由は「[10-3 コンポジションとユーティリティ](/components/compositions-and-utilities/)」で説明しています。渡す場所は2つあります。`prose` のルートに渡せば、カスタムプロパティの継承によってすべての子に届き、全体の間隔になります。子に渡せば、その子の値がルートから継承した値より優先されるので、その子の前の間隔だけが変わります。

この振る舞いは、`var()` を書いた宣言がどの要素にあるかで決まります。`margin-block-start` は子要素に指定されているので、`var(--prose--space)` も子要素の上で解決されます。ルートに書いた値は、子に継承されて初めて使われます。

そのため、`prose` には内部プロパティを置きません。`switcher` や `grid` は、計算に使う値をルートで内部プロパティに受け直します。`prose` で同じように `--_c--space: var(--prose--space, 0)` と受け直すと、`var()` はルートの上で解決され、子には解決済みの値が継承されます。子に `--prose--space` を渡しても `--_c--space` は計算し直されないので、子ごとの上書きが反映されなくなります。コンポーネントの公開プロパティは内部プロパティで受け直しますが（「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」）、`prose` は子ごとの上書きを生かすために受け直しません。

## 子ごとに間隔を渡す

使う側は、まず `prose` のルートに全体の間隔を渡し、違う間隔にしたい子にだけ値を渡します。見出しの前を広げたいなら見出しに、見出しの直後を詰めたいなら見出しの次の要素に渡します。`--prose--space` は「その子の前の間隔」なので、渡す先は、変えたい間の後ろにある要素です。

```html
<div class="prose" style="--prose--space: calc(var(--spacing--sm) / 16 * 1rem)">
  <p>…</p>
  <h2 style="--prose--space: calc(var(--spacing--xl) / 16 * 1rem)">…</h2>
  <p style="--prose--space: calc(var(--spacing--xxs) / 16 * 1rem)">…</p>
  <p>…</p>
</div>
```

値は、余白のトークンをremに変換して渡します。段落の間隔は文字の大きさに合わせて広がるように、部品の間隔（pxで渡す）と違ってremにします。トークンを単位なしの数値で持つ理由は「[10-4 デザイントークン](/components/design-tokens/)」で説明しています。`style` 属性で渡せば、どの間がいくつなのかが、対象のタグと同じ場所で読み取れます。

次のデモでは、記事のコンポーネントのルートに `prose` を付け、全体の間隔として16px相当を渡しています。小見出しには40px相当、その直後の段落には8px相当を `style` 属性で渡しています。末尾のリンクの前も40px相当です。

<Demo title="prose の子ごとに --prose--space を渡し、見出しの前だけ広げる" html={proseHtml} css={proseCss} />

小見出しの前が広く、直後が狭いので、小見出しは後ろの段落とひとまとまりに見えます。余白の大小でまとまりを伝える考え方は、「[11-2 余白を設計する](/layout-practice/spacing/)」で説明しています。デモのCSSのうち、コンポーネント（`prose-demo`）が書いているのは見出しや囲みの見た目と、囲みの中の間隔だけです。

囲み（`aside`）にも `prose` を付けて、入れ子にしています。囲みの前の32px相当は `style` 属性で、囲みの中の8px相当はコンポーネントのCSSで内側の子に渡しています。こう分ける理由は、後の「補足と注意点」で説明します。

画面の幅で間隔を変えるときや、同じ値を複数の子に渡すときは、コンポーネントのCSSで子に渡します。次の例は、記事のページで、記事の見出し、CMSの本文エリア、一覧へ戻るリンクを `prose` で並べたものです。`prose` は、コンポーネントのルートではなく、内側の `._layout` に付けています。

```html
<article class="scoped news-single">
  <div class="_layout | prose">
    <header>…</header>
    <div class="_body | wysiwyg">…</div>
    <p class="_back"><a href="/news/">一覧へ戻る</a></p>
  </div>
</article>
```

```css title="🙆‍♂ Recommended: コンポーネントの CSS で、子ごとの間隔を渡す"
@scope (.scoped.news-single) to (.scoped) {
  ._layout {
    --prose--space: calc(var(--spacing--lg) / 16 * 1rem);
  }

  ._body {
    --prose--space: calc(var(--spacing--xl) / 16 * 1rem);

    @media (width >= calc(768 / 16 * 1rem)) {
      --prose--space: calc(var(--spacing--xxl) / 16 * 1rem);
    }
  }
}
```

並べ方と、「前に要素があるときだけ間隔を空ける」という規則は `prose` が持ちます。コンポーネントのCSSが持つのは、どの子の前をいくつ空けるかという値だけです。子のCSSに `margin` は現れないので、子を並べ替えたり、条件によって `._back` を出力しなかったりしても、残った要素の間にだけ正しい間隔が空きます。

間隔の単位には注意が要ります。`var()` が子の上で解決されるので、`em` や `lh` で渡すと、子ごとの文字の大きさや行の高さが基準になります。`prose` のルートで `1lh` を渡しても、行の高さが違う見出しと段落では間隔もずれます。行の高さでそろえたいなら、文書のルート要素（`html`）の行の高さを基準にする `rlh` を使います（基準は `prose` のルートではないので、`prose` のルートの `line-height` を変えても `1rlh` は変わりません）。

## `stack`、空のグリッドセル、CMS の本文エリアとの使い分け

縦に積む方法の使い分けは、11-1の「[縦に積む方法を間隔の決まり方で選ぶ](/layout-practice/choosing/#縦に積む方法を間隔の決まり方で選ぶ)」の表にまとめています。`prose` を選ぶのは、その表で間隔が前後の要素の種類や有無で変わり、HTMLを自分で書く場合です。判断の基準は、11-1のルール「[縦に積む要素の間隔が前後の要素で変わるなら、通常フローのまま組む](/layout-practice/choosing/#rule-normal-flow-for-conditional-spacing)」にあります。

`stack` との違いは、子が通常フローのままであることです。`stack` の子はフレックスアイテムになるので、`float` による回り込みは使えず、`margin` も相殺されません。本文の中に回り込みの画像を置くなら、`prose` を選びます。空のグリッドセルとの違いは、要素が欠けたときに表れます。空のセルの行は要素が欠けても余白だけが残りますが、`prose` では残った子の間にだけ間隔が空きます。

CMSで編集者が入力する本文エリアには、`prose` を使いません。本書では、本文エリアの要素ごとの余白を `.wysiwyg` に集めるからです。CSSから見出しや段落を選んで `--prose--space` を渡すこともできますが、そうすると、本文エリアの余白を決める場所が `.wysiwyg` と `prose` の2つに分かれます。本文エリアでは、「[19-5 CMSのWYSIWYG本文にスタイルを当てる](/operations/wysiwyg/)」のように、`.wysiwyg` の `@scope` の中で、見出しの前の余白を要素の種類のセレクタで決めます。

本文エリアの要素に `prose` を重ねて付けることもしません。`.wysiwyg` の余白のルールと `prose` のルールが、同じ子の `margin-block-start` を指定することになります。`components` レイヤーは `compositions` レイヤーより後なので、`prose` の値は警告もなく上書きされ、HTMLに書いた `prose` のクラスが何の働きもしなくなります。先の記事の例のように、`prose` は本文エリアとその前後の要素を並べる外側に使い、本文エリアの中の余白は `.wysiwyg` に任せます。

## 補足と注意点

`prose` の子の間隔は `margin` なので、相殺が起きます。子が自分で `margin-block-end` を持っていても、間隔と足し算にはならず、大きいほうだけが残ります。中身が空の子は、上下の `margin` が自分を通り抜けて次の子の `margin` と相殺するので、空の段落が紛れ込んでも、間隔が2つ分空くことはありません。{/* 要確認: 出典なし */}`gap` では、高さが0の子の前後にも `gap` が1つずつ空きます。相殺の仕組みは「[11-2 余白を設計する](/layout-practice/spacing/)」で説明しています。

`* + *` は、表示されない要素も兄弟として数えます。`hidden` 属性で隠した要素や `template` 要素が先頭にあると、目に見える最初の子の前に間隔が空きます。条件によって表示しない要素は、HTMLに出力しないか、先頭以外の位置に置きます。

入れ子の `prose` には注意が要ります。外側の `prose` の子として置いた内側の `prose` では、ルートの `--prose--space` が、外側との間隔と内側の間隔の両方に使われます。ルートに渡した値は、継承によって内側の子にも届くからです。デモの囲みのように、ルートの値は外側との間隔に使い、内側の間隔はコンポーネントのCSSで内側の子に `& > * { --prose--space: … }` と渡します。内側の子に値を渡さないと、内側の段落の間も外側との間隔と同じになります。

同じことは、入れ子にしていない子にも当てはまります。子に渡した `--prose--space` は、その子の子孫にも継承されます。子孫に別の `prose` がなければ影響はありませんが、コンポーネントの中に `prose` があるなら、そのコンポーネントの側で値を渡し直します。

`prose` は要素の順番を変えないので、読み上げの順番と見た目の順番がずれることはありません。ただし、余白の大小で伝わるのは見た目のまとまりだけです。{/* 要確認: 出典なし */}見出しは見出しの要素で書き、余白だけで構造を表さないようにします。`margin-block-start` は論理プロパティなので、縦書き（`vertical-rl`）の本文に使えば、間隔は各要素の右側に空きます。
