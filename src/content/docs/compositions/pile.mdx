`pile` は、すべての子要素を1つのグリッドのセルに重ねるコンポジションです。ヒーローの画像の上に見出しを重ねる、サムネイルの隅にラベルを置くといった配置に使います。`position: absolute` で重ねる方法と違い、重ねた要素はどれもレイアウトの流れに残るので、親の高さは中身のうち高いほうで決まり、文字が増えても枠からはみ出しません。

ルートには `isolation: isolate` を指定して、子の重なり順を `pile` の中に閉じ込めます。重なり順はHTMLの順番で決め、足りないときだけ相対的なz-indexのトークンを使います。子の位置は、`--pile--placement`、`--pile--alignment`、`--pile--justification` の3つの公開プロパティで、動かしたい子の `style` 属性から変えます。

## 絶対配置で重ねたときに起きること

画像の上に見出しと短い説明文を重ねたヒーローを考えます。よく見かけるのは、親に `position: relative` を指定し、文字の要素を絶対配置にして、画像の下端に寄せる書き方です。

```css title="🙅‍♂ Not Recommended: 文字を絶対配置にして画像に重ねる" issue="behavior"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.hero) to (.scoped) {
  :scope {
    position: relative;

    & > ._body {
      position: absolute;
      inset-block-end: 0;
      inset-inline-end: 0;
    }
  }
}
```

絶対配置にした要素は、通常のレイアウトの流れから外れます。ヒーローの高さは画像だけで決まり、文字の量は反映されません。幅の広い画面では画像に十分な高さがあるので問題は見えませんが、画面が狭くなると画像は低くなり、文字は折り返して高くなります。その結果、文字は画像の上端を越えてはみ出し、上にある要素と重なります。

この不具合は、デザインカンプどおりの文字量では起きず、CMSで長い見出しが入ったときや、ユーザーが文字を拡大したときに起きます。`min-block-size` を足す、画面幅ごとに文字を小さくするといった対処は、文字量の想定を値として埋め込むだけなので、別の文字量でまた崩れます。原因は、文字の高さが親の高さに反映されない構造そのものです。

## `pile` の仕組み

`pile` の実装は、次の数行です。ルートを1セルのグリッドにし、直下の子をすべて同じエリアに置きます。

```css title="🙆‍♂ Recommended: すべての子を同じエリアに置き、重なりをルートに閉じ込める"
/**
 * すべての子要素を同じグリッドのセルに重ねる。
 *
 * @prop {keyword} --pile--placement     [なし]   - 子のブロック方向とインライン方向の配置（一括。キーワードは1つ）。指定すると個別の指定より優先する
 * @prop {keyword} --pile--alignment     [normal] - 子のブロック方向の配置
 * @prop {keyword} --pile--justification [normal] - 子のインライン方向の配置
 */
.pile {
  display: block grid;
  grid-template-areas: "--pile";
  isolation: isolate;

  & > * {
    grid-area: --pile;
    place-self: var(--pile--placement, var(--pile--alignment, normal)) var(--pile--placement, var(--pile--justification, normal));
  }
}
```

`grid-template-areas: "--pile"` は、`--pile` という名前のエリアが1つだけあるグリッドを作ります。行と列の大きさを指定していないので、列は1本で親の幅いっぱいに広がり、行の高さは `auto` です。子はすべて `grid-area: --pile` で同じエリアに置かれるので、行の高さは、重ねた子のうちもっとも高いものに合わせて決まります。見出しが長くなって画像より高くなれば、ヒーロー全体が伸びます。

エリア名を `--` で始めているのは、本書の命名規則です。グリッドのエリア名や線名、`@keyframes` の名前、コンテナの名前のように、自分で付ける名前はすべて `--` で始めます。こうしておくと、`auto` や `span` のようなCSSのキーワードと見分けやすくなります。カスタムプロパティと同じく、「作者が付けた名前」であることも字面から分かります。エリア名を使わずに `grid-area: 1 / 1` と書いても同じ配置になります。ただ、エリアに名前を付けておけば、「全部を同じ場所に置く」という意図をCSSから読み取れます。

ルートの `isolation: isolate` は、新しいスタッキングコンテキストを作る指定です。スタッキングコンテキストは重なり順を比べる単位で、その中の要素のz-indexは、外の要素とは比べられません。`pile` の子にz-indexを指定しても、重なりは `pile` の中で閉じ、ほかのコンポーネントと干渉しません。`z-index: -1` を指定した子も、`pile` の背景より奥には回らず、背景の手前に描かれます。z-indexとスタッキングコンテキストの関係は「[11-6 重なりと全幅](/layout-practice/layering/)」で説明しています。

子の `place-self` は、配置を決める公開プロパティを受け取る口です。デフォルト値の `normal` では、グリッドのアイテムは基本的にセルいっぱいに引き伸ばされます。ただし、`img` のように縦横比を持つ要素は引き伸ばされず、セルの先頭に元の大きさで置かれます。画像をセルいっぱいに広げる指定は、`pile` ではなくコンポーネントの側で書きます。

## 公開プロパティで子の位置を変える

公開プロパティは3つです。`--pile--alignment` はブロック方向（横書きでは縦）の配置、`--pile--justification` はインライン方向（横書きでは横）の配置を決めます。どちらも `start`、`center`、`end`、`stretch` などのキーワードを受け取ります。`--pile--placement` は2つを一括で指定するもので、渡したキーワードを両方の方向に使います。名前は、`cluster` の `--cluster--alignment` と `--cluster--justification` にそろえています。

`place-self` の値は、`var()` のフォールバックを入れ子にして組み立てています。1つ目の値（ブロック方向）は、`--pile--placement` があればそれを、なければ `--pile--alignment` を、どちらもなければ `normal` を使います。2つ目の値（インライン方向）も同じ順で、`--pile--justification` を見ます。`--pile--placement` を指定すると、`--pile--alignment` と `--pile--justification` は無視されます。

`--pile--placement` に渡せるキーワードは1つだけです。`end start` のように2つ渡すと、`place-self` の値は `end start end start` になり、計算値の時点で無効になります。その場合 `place-self` は初期値に戻り、何も指定しなかったときと同じ配置になります。エラーにはならないので、方向ごとに違う値を使うときは、`--pile--alignment` と `--pile--justification` を個別に指定します。

値は、動かしたい子の `style` 属性で渡します。次の例では、文字のまとまりだけを右下に寄せ、画像はセルいっぱいのままにしています。横書きの場合、`end` はブロック方向では下、インライン方向では右です。

```html
<section class="scoped hero | pile">
  <img src="…" alt="" width="1280" height="720">
  <div class="_body" style="--pile--placement: end">…</div>
</section>
```

`.pile` の側で `style="--pile--placement: end"` と渡すと、カスタムプロパティは継承されるので、すべての子に同じ配置がかかります。大きさを指定した画像は変わりませんが、大きさを持たない背景用の要素はセルいっぱいに広がらなくなり、中身の大きさ（空なら0）に縮みます。下端に帯を置くような、一方向だけ伸ばしたい配置には `--pile--alignment: end` を使います。インライン方向は `normal` のままなので、帯は横幅いっぱいに広がり、下端に寄ります。

次のデモは、画像、暗い層、文字のまとまりを `pile` で重ねたヒーローです。幅を320pxにすると、文字が折り返して画像より高くなり、ヒーロー全体が文字に合わせて伸びます。画像は伸びたセルに合わせて広がり、`object-fit: cover` で縦横比を保ったまま切り取られます。

<Demo title="pile で画像と文字を重ね、文字を右下に寄せたヒーロー" html={pileHtml} css={pileCss} widths={[320, 768, 1024]} />

`pile` が受け持つのは、子を同じセルに重ねることと、`style` 属性で受け取った配置だけです。画像をセルいっぱいに広げる `inline-size: stretch` と `block-size: 100%`、文字の色、余白、行の長さの上限は、コンポーネント（`hero`）のCSSが受け持ちます。`block-size: 100%` は、行の高さを求める段階では `auto` として扱われるので、文字が低いあいだは画像の縦横比で、文字が高くなれば文字の高さで、行の高さが決まります。

文字を読みやすくする暗い層は、ルートの `::before` で作っています。擬似要素もグリッドのアイテムになりますが、`.pile > *` では選ばれないので、`grid-area: --pile` をコンポーネントの側で指定しないと、別の行に置かれてしまいます。`::before` は画像より前のアイテムなので、そのままでは画像の下に描かれます。そこで、画像に `z-index: var(--z--backwards)`（値は-1）を指定し、暗い層より奥に回しています。この-1が `hero` の背景より奥に回らないのは、`pile` のルートがスタッキングコンテキストを作っているからです。

ルートの `background-color` は、画像を読み込めなかったときの備えです。背景色を文字色から決めているので（「[15-3 背景から文字色を決める](/color-media/contrast-text/#rule-contrast-color-for-image-fallback)」のルール）、白い文字には黒い背景が付き、画像がなくても文字を読めます。{/* 要確認: 出典なし */}

## 重なり順と読み上げ順

同じセルに置いた子は、HTMLの順番で描かれ、後に書いた要素ほど手前に来ます。画像を先に、文字を後に書けば、z-indexを使わずに文字が手前に描かれます。重なり順はまずHTMLの順番で解決し、それで足りないときだけ相対的なz-index（`--z--forwards` と `--z--backwards`）を使います。値をトークンで指定する理由は「[10-2 コンポーネントの境界を守る](/components/boundaries/#rule-z-index-tokens-only)」にあります。

ただし、HTMLの順番は、スクリーンリーダーが読み上げる順番でもあります。重なり順のためにHTMLを並べ替えると、読み上げの順番も変わります。装飾の画像は `alt=""` にすれば読み上げられないので、どこに書いても問題ありません。内容を伝える画像や、見出しより前に読ませたくない要素がある場合は、HTMLを文書の順番で書き、重なり順をz-indexで調整します。

重ねた要素のうち、手前にある要素はクリックも受け取ります。リンクを含む文字のまとまりの上に、後から書いた装飾の層が重なると、その層がクリックを受け取ってしまい、リンクを押せません。装飾の層は文字より前に書くか、`pointer-events: none` を指定します。

画像の上の文字は、画像のどの部分に重なっても、コントラスト比を満たさなければなりません。CMSで画像を差し替えると明るい部分の位置も変わり、文字が画面幅で折り返せば、文字の下の部分も変わります。そのため、文字と画像の間には暗い層を置きます。黒い層の不透明度が55%以上なら、真っ白な画像の上でも、白い文字のコントラスト比は4.5:1を超えます。半透明の色の合成はsRGBの値のまま行われるので、白（255）は約115になり、その相対輝度は約0.17だからです。{/* 要確認: 出典なし */}満たすべき基準は、「[15-5 強制カラーモードとコントラスト](/color-media/forced-colors/#rule-text-contrast-aa)」のルールのとおり、WCAG 2.1のAAです。

層は、全体を一様に暗くするだけでなく、文字のある側だけを暗くし、反対側へ向かって透明にするグラデーションにもできます。文字から離れた部分の画像は元の明るさのまま見えるので、写真の印象を残したいヒーローに向きます。グラデーションの向きと停止位置の書き方は「[16-6 グラデーションを描く](/decoration/gradients/)」で説明しています。{/* 要確認: 出典なし。文字のある側だけを暗くするグラデーションの層を選択肢として示すこと */}

```css title="🙆‍♂ Recommended: 文字が重なる下の側だけを暗くし、上へ向かって透明にする"
@scope (.scoped.hero) to (.scoped) {
  :scope {
    --_scrim: oklch(0% 0 none);

    &::before {
      content: "";
      grid-area: --pile;
      background-image: linear-gradient(to top, color-mix(in oklab, var(--_scrim) 75%, transparent), color-mix(in oklab, var(--_scrim) 55%, transparent) 60%, transparent);
    }
  }
}
```

この書き方では、層の暗さが位置によって変わるので、文字が重なりうる範囲のすべてで、不透明度55%以上を保つ必要があります。上の例では、下から60%の位置までを55%以上にしています。文字のまとまりが折り返して高くなり、その上端が60%より上に出ると、上の行は透明に近い部分にかかり、明るい画像の上でコントラスト比が足りなくなります。停止位置は、想定する最も狭い幅と最も長い文字量で文字の上端が来る位置から決め、実際の表示でコントラストを確かめます。背景から文字色を決めた場合も表示で確かめる必要があることは、「[15-3 背景から文字色を決める](/color-media/contrast-text/)」で説明しています。

層の色は、デザインのトークンか、上の例の `--_scrim` のような内部用のカスタムプロパティで1か所に決め、暗さの段階は `color-mix()` で作ります。こうすると、層の色を変えるときに直す場所が1つで済みます。前に置いたデモの層も55%から75%へのグラデーションですが、どの位置でも55%以上なので、一様に暗くする層と同じ扱いです。{/* 要検証: ブラウザ。幅320pxで文字のまとまりがグラデーションの透明な側にかかったときのコントラスト比 */}

## `pile` を使わない場面と注意点

`pile` は、子のどれもが親の大きさに影響してよい場合に使います。反対に、枠の外へはみ出させたい要素には使えません。カードの角から少しはみ出すバッジや、ボタンの下に開くドロップダウンは、親の大きさに影響させず、枠の外に出す必要があるので、絶対配置やポップオーバーで書きます。{/* 要確認: 出典なし */}

ドロップダウンを `pile` の子の中に置く場合は、`isolation: isolate` にも注意します。`pile` の中のz-indexは `pile` の中でしか比べられないので、ドロップダウンにどれだけ大きな値を指定しても、`pile` より後にあり、自身もスタッキングコンテキストを作る要素の手前には出られません。別の `pile` や、ルートに `isolation: isolate` を指定したコンポーネントがその例です。`popover` 属性や `<dialog>` のようにトップレイヤーに表示する要素なら、この制約を受けません。

コンポーネントに重ねる部分とそうでない部分がある場合は、`pile` ではなく、コンポーネントの `grid-template-areas` で組みます。たとえば、画像と本文を横に並べ、画像の上にだけラベルを重ねるカードでは、ラベルを画像と同じエリアに置きます。エリアの組み方は「[7-8 Gridの基礎](/layout/grid-basics/)」で説明しています。背景が単色やグラデーションだけで、`img` 要素にする必要がない場合は、`pile` を使わず、コンポーネントの `background-image` で足ります。

`pile` の子には、コンポーネントのCSSで `grid-area` や `grid-row` を指定しません。`components` レイヤーは `compositions` レイヤーより優先されるので、子のエリアが `--pile` から外れ、別のセルに移って重ならなくなります。例外は、先に説明した擬似要素で、こちらは `.pile > *` で選ばれないので、`grid-area: --pile` を自分で指定します。

公開プロパティは継承されるので、入れ子にも注意します。`--pile--placement: end` を渡した子の中に別の `pile` があると、内側の `pile` の子も、その値を継承して右下に寄ります。内側の `pile` に `style="--pile--placement: initial"` と書けば、値は無効に戻り、フォールバックの `normal` が使われます。
