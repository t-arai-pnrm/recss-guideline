`sidebar` は、伸び縮みするメインと、幅の決まったサイドを横に並べるコンポジションです。メインが最小幅を確保できなくなると、2つの子は縦に積まれます。クエリを使わず、`flex-wrap: wrap`、`flex-grow` の差、`flex-basis` の3つだけで折り返します。

使う側が決めるのは、メインの最小幅とサイドの幅と間隔の3つで、どれも `style` 属性で渡します。2つの子には `.main-column` と `.side-column` を付けます。サイドを左右どちらに置くかは、CSSではなくHTMLの順番で決めます。

## メディアクエリで2カラムを切り替えると起きること

記事の本文と関連記事の一覧のように、主となる内容の横に補助の内容を並べる配置は、ページの中にも、コンポーネントの中にも出てきます。よくある書き方は、ビューポートの幅で1カラムと2カラムを切り替える方法です。

```css title="🙅‍♂ Not Recommended: ビューポートの幅で2カラムに切り替える" issue="behavior"
/* 🙅‍♂ Not Recommended */
._layout {
  display: block grid;
  gap: 32px;

  @media (width >= calc(768 / 16 * 1rem)) {
    grid-template-columns: 1fr calc(240 / 16 * 1rem);
  }
}
```

この書き方の問題は、2カラムにしてよいかどうかを決める値が、本当に必要な幅と結び付いていないことです。メインに必要なのが480px相当なら、2カラムに必要な幅は480＋240＋32で752px相当です。768px相当という閾値は、この合計とは無関係に、カンプの幅から選ばれています。サイドの幅や間隔を変えるたびに、ブレイクポイントも計算し直さなければなりません。

もう1つの問題は、判定の基準がビューポートであることです。同じ配置を幅の狭いメインエリアの中に置くと、ビューポートが768px相当以上なら2カラムに切り替わり、メインが極端に細くなります。コンテナサイズクエリにすれば置き場所の幅で判定できますが、閾値を手で計算する手間は残ります。並べてよい条件は子の幅の指定にすでに含まれているので、そこから折り返しを導けば、閾値を別に書く必要はありません。

## flex-grow の差で折り返す仕組み

`sidebar` は、Flexboxの折り返しを使って、この閾値をブラウザに計算させます。コンポジションの全体は次のとおりです。

```css title="🙆‍♂ Recommended: メインを圧倒的に大きな比率で伸ばし、入りきらなければ折り返す"
/**
 * メインとサイドの2カラムに並べ、メインが最小幅を確保できなければ縦に積む。
 *
 * @prop {length} --sidebar--main-min-width [calc(480 / 16 * 1rem)] - メインの最小幅（これを確保できないと縦に積む）
 * @prop {length} --sidebar--side-width     [calc(320 / 16 * 1rem)] - 横に並べたときのサイドの幅
 * @prop {length} --sidebar--gap            [なし]                  - 行と列の間隔（一括）。指定すると個別の指定より優先する
 * @prop {length} --sidebar--row-gap        [0px]                   - 縦に積んだときの間隔
 * @prop {length} --sidebar--column-gap     [0px]                   - 横に並べたときの間隔
 *
 * @example
 * <div class="sidebar" style="--sidebar--side-width: calc(240 / 16 * 1rem)">
 *   <article class="main-column">...</article>
 *   <aside class="side-column">...</aside>
 * </div>
 */
.sidebar {
  --_c--row-gap: var(--sidebar--gap, var(--sidebar--row-gap, 0px));
  --_c--column-gap: var(--sidebar--gap, var(--sidebar--column-gap, 0px));
  --_c--main-min-width: var(--sidebar--main-min-width, calc(480 / 16 * 1rem));
  --_c--side-width: var(--sidebar--side-width, calc(320 / 16 * 1rem));

  display: block flex;
  flex-wrap: wrap;
  gap: var(--_c--row-gap) var(--_c--column-gap);

  & > .main-column {
    flex-grow: 9999;
    flex-basis: var(--_c--main-min-width);
  }

  & > .side-column {
    flex-grow: 1;
    flex-basis: var(--_c--side-width);
  }
}
```

折り返すかどうかは、`flex-basis` で決まります。ブラウザは、子の `flex-basis` と列の間隔を足した合計が親の幅に収まる間は1行に並べ、収まらなくなると次の行へ送ります。メインの `flex-basis` は最小幅、サイドの `flex-basis` はサイドの幅なので、「メインの最小幅＋サイドの幅＋列の間隔」がそのまま折り返す幅になります。閾値をどこにも書かずに、子の幅の指定から折り返しが決まるわけです。

横に並んだあとの幅は、`flex-grow` で決まります。余った幅は `flex-grow` の比で分けられるので、9999対1なら、メインが余りの9999/10000を、サイドが1/10000を受け取ります。余りが232pxなら、サイドが受け取るのは0.0232pxです。サイドはほぼ指定の幅のまま、メインが残りをすべて使います。

サイドの `flex-grow` を0ではなく1にしているのは、縦に積んだときのためです。折り返すと、メインとサイドはそれぞれ1つの行を占めます。行に1つしかない子は、`flex-grow` が0より大きければ行の幅いっぱいに伸びます。サイドの `flex-grow` が0だと、縦に積んだときもサイドだけが指定の幅のまま残り、行の右側が空きます。

この仕組みから、`--sidebar--main-min-width` の意味も正確に言えます。横に並ぶのは、親の幅が「メインの最小幅＋サイドの幅＋列の間隔」以上のときだけなので、横に並んでいる間のメインは、必ず最小幅以上になります。縦に積んだあとは、メインは親の幅に合わせて縮むので、最小幅より狭くなることもあります。この値は「サイドと並ぶための条件」であり、どんな幅でも守られる下限ではありません。

### 数値で確かめる

次のデモには、2つの `sidebar` を縦に積んでいます。1つ目は、本文を先に、関連記事を後に書いた例で、幅を768pxにすると縦に積まれ、1024pxにすると横に並びます。2つ目は、章の目次を先に、本文を後に書いた例で、メインの最小幅を400px相当、サイドの幅を200px相当にしています。折り返す幅は624px相当なので、768pxでも横に並び、480pxで縦に積まれます。

上のデモの1つ目は、メインの最小幅を480px相当（デフォルト）、サイドの幅を240px相当、間隔を24px相当にしています。折り返す幅は480＋240＋24で744px相当です。次の表は、この配置を置いた要素の幅ごとに、Chromeでメインとサイドの幅を測った結果です。

| 要素の幅 | 並び方 | メインの幅 | サイドの幅 |
|---|---|---|---|
| 432px | 縦に積む | 432px | 432px |
| 720px | 縦に積む | 720px | 720px |
| 976px | 横に並べる | 711.98px | 240.02px |
| 1232px | 横に並べる | 967.95px | 240.05px |

976pxの行では、余りが976−744で232pxです。サイドは240＋0.0232で240.02px、メインは480＋231.98で711.98pxになり、表の値と一致します。720pxは744pxに届かないので、縦に積まれ、どちらの子も720pxに伸びています。デモの幅には、`body` の左右の `padding`（24pxずつ）が含まれるので、表の要素の幅は、デモの幅の480px、768px、1024px、1280pxから48pxを引いた値です。

### 公開プロパティ

公開プロパティは5つです。間隔のデフォルト値は、ほかのコンポジションと同じく `0` にしています（「[10-3 コンポジションとユーティリティ](/components/compositions-and-utilities/)」。間隔は置く文脈で決まる値なので、使う側で指定します）。

| 公開プロパティ | デフォルト値 | 意味 |
|---|---|---|
| `--sidebar--main-min-width` | `calc(480 / 16 * 1rem)` | メインの最小幅。サイドと並ぶための条件 |
| `--sidebar--side-width` | `calc(320 / 16 * 1rem)` | 横に並べたときのサイドの幅 |
| `--sidebar--gap` | なし | 行と列の間隔を一括で指定する。指定すると個別の指定より優先する |
| `--sidebar--row-gap` | `0px` | 縦に積んだときの、メインとサイドの間隔 |
| `--sidebar--column-gap` | `0px` | 横に並べたときの、メインとサイドの間隔 |

`--sidebar--gap` を指定すると、個別の指定より優先されます。フォールバックを `var(--sidebar--gap, var(--sidebar--row-gap, 0px))` のように連ねているからです。横に並べたときと縦に積んだときで間隔を変えたいなら、`--sidebar--row-gap` と `--sidebar--column-gap` を別々に渡します。デフォルト値は、単位なしの `0` ではなく `0px` と書いています。単位なしの `0` は `calc()` の中で長さと足し算できないので、間隔を計算に使う `grid` や `switcher` と書き方をそろえています。

値は、HTMLの `style` 属性で、`calc(240 / 16 * 1rem)` のようにremで渡します。余白のトークンは `calc(var(--spacing--lg) / 16 * 1rem)` で変換します。remにしておくと、ユーザーが文字サイズを大きくしたときに折り返す幅も広がるので、文字が大きいほど早く縦に積まれます。

コンポーネントの中で使うときは、`sidebar` を付けた要素の直下に、`.main-column` と `.side-column` の2つの子を置きます。次の例では、記事のページのコンポーネントが、本文と関連記事の一覧を並べています。

```html
<div class="scoped article-page">
  <div
    class="_layout | sidebar"
    style="--sidebar--side-width: calc(240 / 16 * 1rem); --sidebar--gap: calc(var(--spacing--md) / 16 * 1rem)"
  >
    <article class="main-column">…</article>
    <aside class="side-column" aria-labelledby="related-heading">…</aside>
  </div>
</div>
```

並び方と幅は `sidebar` と2つの列のクラスが、見た目はコンポーネントが受け持ちます。コンポーネントのCSSでは `article` と `aside` をタイプセレクタで選び、子要素のクラスは付けません。役割を区別する必要があれば、`_` で始まる子要素のクラスを列のクラスと並べて付けます。コンポーネントのCSSには、`aside` の背景や `padding` は書きますが、`inline-size` や `flex` は書きません。幅を書くと `sidebar` の計算と食い違い、折り返す幅が読めなくなるからです。

### メインの flex-basis を sign() で切り替える書き方について

私が使っているテンプレートの `sidebar` には、メインの `flex-basis` を `sign()` で切り替える2行があります。`sign()` は、引数が正なら1、負なら-1、0なら0を返す関数です。

```css
--_c--main-growth: sign(100% - (var(--_c--side-width) + var(--_c--column-gap)));
--_c--main-basis: calc(var(--_c--main-min-width) * var(--_c--main-growth));
```

登録していないカスタムプロパティは、宣言した要素では計算されず、`var()` で参照した先に式のまま差し込まれます。参照先はメインの `flex-basis` で、`flex-basis` の `%` はフレックスコンテナの内側の幅に対して解決されます。そのため、この `100%` は `.sidebar` の `padding` を除いた幅です。Chromeでも、メインの `flex-basis` の計算値は `calc(480px * sign(100% - 352px))` と、`%` を含んだまま残っていました。

テンプレートのデフォルト値（メインの最小幅480px、サイドの幅320px、間隔32px）で数値を入れます。`.sidebar` の幅が800pxなら `sign(800px - 352px)` は1で、メインの `flex-basis` は480pxです。300pxなら-1で-480pxになりますが、`flex-basis` は負の値を取れないので0に丸められます。

{/* 要確認: 出典なし */}つまり、この2行が結果を変えるのは、`.sidebar` の幅が352px以下のときだけです。その幅は折り返す幅の832pxを下回っているので、メインはすでに1つの行を占めており、`flex-basis` が480pxなら縮んで、0なら伸びて、どちらも親の幅に収まります。Chromeで200px、300px、352pxの幅を測っても、メインの幅は `sign()` の有無で変わりませんでした。本書では、この2行を省いています。

## 補足と注意点

### 子のクラス名と本書の命名規則

`.main-column` と `.side-column` は、コンポジションと同じく接頭辞なしで書きます。コンポーネントの子要素の印である `_` は付けません（「[9-1 命名規則](/notation/naming/)」。`_` で始まる名前は、そのコンポーネントの `@scope` の中だけで意味を持つ名前です）。この2つのクラスは `sidebar` の一部で、どのコンポーネントの中で使っても同じ意味を持ち、CSSも `compositions` レイヤーの `.sidebar` の中に書くからです。`._main` と書くと、その要素が属するコンポーネントの子要素に見えてしまいます。

このクラスの指定は、`.sidebar > .main-column` のように、`.sidebar` の直接の子として選ぶときだけ適用されます。`.sidebar` の外や孫の要素に付けても、何も起きません。`-column` で終わる名前にしているのは、単独で配置を持つ `.stack` や `.cluster` と区別し、コンポジションの列であることを名前から読み取れるようにするためです。

位置で選ぶ `& > :first-child` を使わないのは、サイドを先に書く場合もあるからです。クラスで役割を指定しておけば、HTMLの順番を入れ替えても、どちらがメインかは変わりません。子は2つだけにします。3つ目の子は `flex-grow` と `flex-basis` を持たないので、折り返す幅の計算が成り立たなくなります。

### サイドを左右どちらに置くか

サイドを左に置くか右に置くかは、HTMLの順番で決めます。左から右へ書く言語では、先に書いた子が左に、後に書いた子が右に並びます。縦に積んだときは、先に書いた子が上に来ます。スクリーンリーダーの読み上げとキーボードの移動も、HTMLの順番どおりです。

関連記事や広告のように、本文を読んだ後に見る補助の内容は、本文の後に書きます。横に並ぶと右に、縦に積むと本文の下に来ます。章の目次や絞り込みの条件のように、本文より先に知っておくと便利な内容は、先に書きます。横に並ぶと左に、縦に積むと本文の上に来ます。どちらの場合も、見た目の順番と読み上げの順番が一致します。

{/* 要確認: 出典なし */}「横に並ぶときはサイドを左に、縦に積むときは本文を上に」というデザインでは、`flex-direction: row-reverse` で見た目だけを入れ替えたくなります。しかし、横に並んでいる間は、キーボードで移動する順番が右の本文から左のサイドへ進み、見た目の順番と食い違います。サイドにリンクがあるなら、デザインの側で、どちらの幅でも同じ順番になるように調整します。そのため、`sidebar` には左右を指定する公開プロパティを設けていません。

### 中身の最小幅で折り返す幅がずれる

折り返す幅が「メインの最小幅＋サイドの幅＋列の間隔」になるのは、子の中身がそれより狭く縮められる場合だけです。フレックスアイテムは、`min-inline-size` の初期値 `auto` によって、中身の最小幅（`min-content`）より狭くなりません。折り返しの判定でも、`flex-basis` がこの最小幅より小さければ、最小幅のほうが使われます。

たとえば、サイドに幅300pxの画像があると、`--sidebar--side-width` を240px相当にしても、判定には300pxが使われ、折り返す幅は計算より60px広がります。メインに幅の広い表があるときも同じなので、公開プロパティの値は、それぞれの中身の最小幅より大きくしておきます。縦に積んだあとで中身が親からはみ出すときの対処は、「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/)」で説明しています。

### grid-template で書くとき

`sidebar` が向いているのは、要素が2つで、横に並べるか縦に積むかの2通りしかない配置です。折り返す幅は中身の幅の指定から決まり、クエリは要りません。一方で、次のような配置は `sidebar` では組めないので、`grid-template` のエリアに名前を付けて書きます（「[7-8 Gridの基礎](/layout/grid-basics/)」。配置の構造が変わるレイアウトは、条件ごとにテンプレートだけを書き換えます）。

1つ目は、要素が3つ以上ある配置です。見出し、本文、サイドの3つがあり、広いときはサイドを見出しと本文の2行にまたがらせたい場合、Flexboxの折り返しでは表現できません。2つ目は、折り返す幅を中身ではなくデザインの都合で決めたい場合です。3つ目は、横に並べたときと縦に積んだときで、見た目の順番を変えたい場合です。

```css title="🙆‍♂ Recommended: サイドを見出しと本文の2行にまたがらせる"
@scope (.scoped.article-page) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
  }

  ._layout {
    display: block grid;
    reading-flow: grid-rows;
    grid-template:
      "--header"
      "--body"
      "--related";
    gap: 32px;

    @container --scoped (inline-size >= calc(800 / 16 * 1rem)) {
      grid-template:
        "--header --related"
        "--body --related" 1fr
        / 1fr calc(240 / 16 * 1rem);
    }

    & > ._header {
      grid-area: --header;
    }

    & > ._body {
      grid-area: --body;
    }

    & > ._related {
      grid-area: --related;
    }
  }
}
```

この書き方では、閾値の `800 / 16 * 1rem` を手で決めます。サイドの幅や間隔を変えたら、閾値も見直す必要があります。`sidebar` で済む配置をGridとコンテナサイズクエリで書くと、この手間が増えるだけなので、まず `sidebar` で足りるかを考えます。クエリを使う前にイントリンシックな方法を検討する順番は、「[13-1 検討する順番](/responsive/escalation/)」で説明しています。

似たコンポジションとの使い分けも、子の幅の決まり方で考えます。同じ幅の列を指定の数だけ並べ、閾値を下回ったらすべてを1列にするなら [`switcher`](/compositions/switcher/) を、同じ形のカードを最小幅に合わせて何列でも並べるなら [`grid`](/compositions/grid/) を使います。幅の違う2つの子を、片方の幅を固定して並べるのが `sidebar` です。

### サイドの中身を sticky で留める

横に並んでいる間、サイドの高さはメインと同じになります。`align-items` の初期値（`normal`）では、フレックスアイテムが行の高さいっぱいに伸びるからです。この性質を使うと、目次をスクロールに合わせて留める配置が作れます。

`position: sticky` は、`.side-column` そのものではなく、その中の要素に指定します。`.side-column` は行の高さまで伸びているので、中の要素はその範囲でずれる余地を持ちます。`.side-column` に直接指定するなら、`align-self: start` で伸びるのを止めます（「[7-10 positionの基礎](/layout/positioning/#rule-sticky-align-self-start)」。伸びた要素には、ずれる余地がありません）。縦に積んだあとは、サイドの行の高さは中身と同じになるので、`sticky` を指定しても留まりません。
