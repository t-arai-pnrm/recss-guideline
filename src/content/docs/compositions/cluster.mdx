タグの一覧、ボタンの並び、価格と注記のように、子を同じ側に寄せて横に並べ、入りきらなければ次の行へ折り返す配置は、コンポジション `cluster` で書きます。`cluster` が受け持つのは、Flexboxによる横並びと折り返し、子の間隔、主軸と交差軸の配置だけです。間隔は `--cluster--gap` で一括に、`--cluster--row-gap` と `--cluster--column-gap` で行と列を別々に受け取り、どれも指定がなければ `0` になります。

子を両端に分ける配置には、`cluster` ではなく `apart` を使います。対応しているブラウザでは `flex-wrap: balance` で各行の長さをそろえ、最後の行に子が1つだけ取り残されるのを防ぎます。

## 横並びをコンポーネントごとに組むと起きること

「横に並べて、入りきらなければ折り返す」配置は、記事のタグ、カードの下部のボタン、フッターのリンク集、商品の価格と注記など、サイトのいたるところに現れます。Flexboxなら `display: flex`、`flex-wrap: wrap`、`gap` の3行で書けるので、コンポーネントごとに毎回書いても手間はわずかです。

手間が少ないぶん、守りの指定が抜けても気付きにくくなります。`flex-wrap: wrap` を書き忘れると、子が増えたときや画面が狭いときに、子が縮みきったところでコンテナからはみ出します。間隔を子の `margin-inline-end` で作ると、折り返した行の末尾に余計な余白が残り、行の間隔は別に指定しなければなりません。どちらも、デザインカンプどおりの数で確認しているうちは表に出ません。

本書は、似た記述の重複を急いで共通化しない立場です（「[2-3 保守しやすさを最優先にする](/design-mindset/maintainability/)」。共通化は同じものが3回現れてから考えます）。横並びと折り返しは、コンポーネントの見た目と違って、どのコンポーネントでも同じ理由でしか変わりません。共通化しても、片方の都合で分岐を足すことにならないので、早い段階でコンポジションにしてかまいません。

コンポジションにしておくと、HTMLに `class="cluster"` とあるだけで、子が横に並んで折り返すことが読み取れます。コンポジション全般の考え方と、間隔のデフォルト値を `0` にする理由は「[10-3 コンポジションとユーティリティ](/components/compositions-and-utilities/)」で説明しています。

## cluster の書き方

`cluster` の実装は次のとおりです。ファイルの先頭には、公開プロパティの一覧をJSDocの形式で書きます。

```css title="🙆‍♂ Recommended: 子を横に並べて折り返し、間隔と配置を公開プロパティで受け取る"
/**
 * 子要素をインライン方向に並べ、入りきらなければ折り返す。
 * タグの一覧やボタンの並びのように、同じ側に寄せて並べる要素に使う。
 *
 * @prop {length}  --cluster--gap           [なし]   - 行と列の間隔（一括）。指定すると個別の指定より優先する
 * @prop {length}  --cluster--row-gap       [0]      - 行の間隔
 * @prop {length}  --cluster--column-gap    [0]      - 列の間隔
 * @prop {keyword} --cluster--justification [normal] - 主軸の配置（justify-content）
 * @prop {keyword} --cluster--alignment     [normal] - 交差軸の配置（align-items）
 *
 * @example
 * <ul class="cluster" style="--cluster--gap: calc(var(--spacing--xxs) * 1px)">
 *   <li>…</li>
 * </ul>
 */
.cluster {
  display: block flex;
  flex-wrap: wrap;
  gap: var(--cluster--gap, var(--cluster--row-gap, 0)) var(--cluster--gap, var(--cluster--column-gap, 0));
  justify-content: var(--cluster--justification, normal);
  align-items: var(--cluster--alignment, normal);

  /* 最後の行に子が1つだけ取り残されないよう、各行の長さをそろえる */
  @supports (flex-wrap: balance) {
    flex-wrap: balance;
  }
}
```

公開プロパティは5つです。どれも `cluster` を付けた要素の `style` 属性で渡します。

| 公開プロパティ | 意味 | デフォルト値 |
|---|---|---|
| `--cluster--gap` | 行と列の間隔（一括）。指定すると個別の指定より優先する | なし |
| `--cluster--row-gap` | 行の間隔 | `0` |
| `--cluster--column-gap` | 列の間隔 | `0` |
| `--cluster--justification` | 主軸（横）の配置。`justify-content` の値 | `normal` |
| `--cluster--alignment` | 交差軸（縦）の配置。`align-items` の値 | `normal` |

### 間隔のフォールバックの連鎖

`gap` の値は、`var()` のフォールバックを2段に重ねた式です。行の間隔は `var(--cluster--gap, var(--cluster--row-gap, 0))` です。`--cluster--gap` があればそれを使い、なければ `--cluster--row-gap` を使い、どちらもなければ `0` になります。列の間隔も同じ形で、2段目が `--cluster--column-gap` に変わるだけです。

この連鎖では、一括の指定が個別の指定より優先されます。`--cluster--gap` と `--cluster--column-gap` の両方を渡すと、`--cluster--column-gap` は使われません。CSSのショートハンドとロングハンドの関係（後に書いたほうが勝つ）とは違うので、個別に指定したいときは `--cluster--gap` を渡さないようにします。

```html
<!-- 行と列を同じ間隔にする -->
<ul class="cluster" style="--cluster--gap: calc(var(--spacing--xxs) * 1px)">…</ul>

<!-- 列だけに間隔を付け、行の間隔は0のままにする -->
<div class="cluster" style="--cluster--column-gap: calc(var(--spacing--sm) * 1px)">…</div>
```

デフォルト値が `0` なので、間隔を渡し忘れた `cluster` は子が隙間なく並び、渡し忘れにすぐ気付けます。余白のトークンをデフォルト値にすると、渡し忘れた箇所にもそれらしい余白が付き、デザインとの食い違いに気付きにくくなります（[ルール：コンポジションの間隔のデフォルト値は0にする](/components/compositions-and-utilities/#rule-composition-default-gap-zero)）。値には、単位なしの数値で持つ余白のトークンをpxに変換して渡します。

### 主軸と交差軸の配置

`--cluster--justification` は、行の中で子をどちらに寄せるかを決めます。デフォルトの `normal` は、Flexboxでは行の先頭に寄せる `start` と同じ結果になります。ボタンを行末に寄せるなら `end`、中央に寄せるなら `center` を渡します。`left` ではなく `start` と `end` を使えば、書字方向が変わっても意図どおりに寄ります。`flex-start` も書字方向には従いますが、主軸を逆向きにした（`row-reverse`）ときは反対の端に寄るので、`start` と `end` を使います。

`--cluster--alignment` は、同じ行の中で高さの違う子を縦にどう並べるかを決めます。デフォルトの `normal` は、フレックスアイテムでは `stretch` として扱われ、同じ行の子の高さがそろいます。ボタンの並びなら、ラベルが2行に折り返したボタンがあっても、ほかのボタンの枠も同じ高さになるので、このままで困りません。アイコンと文字を並べるときは `center`、文字の大きさが違う価格と注記を並べるときは `baseline` を渡すと、文字の並びが自然になります。

実装では、2つとも `var()` のフォールバックに `normal` を書いています。フォールバックがなくても、未定義のカスタムプロパティを参照した宣言は「計算値の時点で無効」になり、初期値の `normal` が使われるので、結果は変わりません。それでもフォールバックを書くのは、デフォルト値がJSDocの一覧と同じであることを、実装の1行だけで確かめられるようにするためです。

コンポーネントの中で `cluster` を使う例です。記事のカードの下部に、タグの一覧と、行末に寄せたボタンの並びを置きます。

```html title="🙆‍♂ Recommended: 配置は cluster に、見た目はコンポーネントに任せる"
<article class="scoped article-card | stack" style="--stack--gap: calc(var(--spacing--sm) * 1px)">
  <h2>…</h2>
  <ul class="cluster" style="--cluster--gap: calc(var(--spacing--xxs) * 1px)">
    <li>CSS</li>
    <li>Flexbox</li>
  </ul>
  <div
    class="cluster"
    style="--cluster--gap: calc(var(--spacing--sm) * 1px); --cluster--justification: end"
  >
    <button type="button">プレビュー</button>
    <button type="button">公開する</button>
  </div>
</article>
```

```css title="🙆‍♂ Recommended: コンポーネントはタグの見た目だけを書く" from="compositions/cluster"
@scope (.scoped.article-card) to (.scoped) {
  li {
    padding-block: 4px;
    padding-inline: 12px;
    border: 1px solid var(--border--base);
    border-radius: var(--rounded--full);
    font-size: calc(var(--text--body-compact--font-size) / 16 * 1rem);
    line-height: var(--text--body-compact--leading);
  }
}
```

コンポーネントのCSSが書いているのは、タグの余白、枠線、角丸、文字の大きさだけです。`ul` に `display` や `gap` を書かず、`li` に `margin` も書きません。並び方と間隔は `cluster` とHTMLの `style` 属性が決め、コンポーネントはその中の子の見た目を決める、という分担になります。

次のデモでは、タグの一覧は一括の間隔で並べ、価格と注記は列の間隔だけを渡して `baseline` でそろえ、ボタンの並びは `end` で行末に寄せています。幅を320pxにすると、タグとボタンが折り返します。`flex-wrap: balance` に対応したブラウザでは、タグの各行の長さがそろいます。

<Demo title="cluster でタグ、価格と注記、ボタンを並べる" html={clusterHtml} css={clusterCss} widths={[320, 480, 768]} />

ボタンの並びは、折り返したあとも各行が行末に寄ります。`--cluster--justification: end` は見た目の位置だけを変え、HTMLの順序（「下書きに戻す」「プレビュー」「公開する」）は変えません。キーボードでのフォーカスの移動も、スクリーンリーダーの読み上げも、HTMLの順序のままです。

### `flex-wrap: balance` で行の長さをそろえる

`flex-wrap: balance` は、折り返したときに各行の長さができるだけ同じになるように、子を行へ振り分ける値です。`text-wrap: balance` のフレックスアイテム版にあたります。通常の `wrap` は、1行目に入るだけ詰めてから残りを次の行へ送るので、たとえば7つのタグのうち6つが1行目に入ると、2行目にはタグが1つだけ残ります。`balance` なら、4つと3つのように振り分けられます。{/* 要確認: 出典なし。振り分けの数は例示 */}

<Baseline id="flexbox-flex-wrap-balance" name="flex-wrap: balance" />

`flex-wrap: balance` に対応しているのはChromeとEdgeの150以降だけで、SafariとFirefoxは対応していません。未対応の環境では `@supports` の中が読まれず、外側の `flex-wrap: wrap` のまま普通に折り返します。崩れではなく行の長さがそろわないだけなので、プログレッシブ・エンハンスメントとして使えます。

同じプロパティを `flex-wrap: wrap; flex-wrap: balance;` と2回書いても、未対応の環境では後の宣言が無視されるので、動作は同じです。しかし、この書き方では、後から読んだ人が単なる重複と見なして片方を消すおそれがあります。`@supports (flex-wrap: balance)` の中に書けば、新しい値に頼った指定であることが条件から読み取れ、すべての対象ブラウザが対応したときに分岐ごと消せます。

## 補足と注意点

### `apart` との使い分け

`cluster` と `apart` は、どちらもFlexboxで子を横に並べ、入りきらなければ折り返します。違いは寄せ方で、`cluster` は子をまとめて同じ側に寄せ、`apart`（「[12-4 apart](/compositions/apart/)」。子を両端に分ける）は `justify-content: space-between` で子を両端に分けます。ヘッダーのロゴとナビゲーション、フッターの著作権表記とリンク集のように、2つのまとまりを左右に分けるなら `apart` です。

`cluster` に `--cluster--justification: space-between` を渡しても、見た目の上では両端に分けられます。しかし、子が3つ以上ある `cluster` で `space-between` を使うと、行ごとに子の数が違うので間隔がばらつき、最後の行に子が2つ残れば左右の端に離れて置かれます。

子が2つしかない場合も、`apart` を使います。`apart` は寄せ方を `space-between` に固定しているので、クラス名を見ただけで「両端に分ける」と分かります。`cluster` は寄せ方を `start`、`center`、`end` から選ぶもの、`apart` は両端に分けるものと決めておけば、レビューで `style` 属性まで読まずに済みます。

### `ul` に付けるときのリストの意味

タグの一覧やリンク集のように、同じ種類の項目が並ぶものは、`div` ではなく `ul` に `cluster` を付けます。スクリーンリーダーは `ul` を「リスト、7項目」のように読み上げるので、利用者は項目の数を把握でき、不要ならリスト全体を読み飛ばせます。一方、ボタンの並びや価格と注記の組み合わせは項目の列挙ではないので、`div` や `p` に付けます。

`ul` を `cluster` にするときは、リストのマーカーを消す必要があります。このとき `list-style: none` を使うと、SafariのVoiceOverがリストとして読み上げなくなります。マーカーは `list-style-type: ""` で消します（[ルール：リストのマーカーは list-style-type: "" で消す](/reset/global-pitfalls/#rule-list-style-type-empty-string)）。kiso.cssは `ul` と `ol` にこの指定を済ませているので、`cluster` やコンポーネントで書き足す必要はありません。

### 入れ子にしたときの公開プロパティの継承

カスタムプロパティは継承します。外側の `cluster` で `--cluster--gap` を渡すと、その中の入れ子の `cluster` も同じ値を受け取ります。内側で何も指定しなければ、デフォルト値の `0` ではなく外側の間隔で並びます。{/* 要確認: 出典なし */}

さらに、内側で `--cluster--column-gap` だけを渡しても、外側から継承した `--cluster--gap` が優先されるので、列の間隔は変わりません。内側で個別に指定したいときは、`--cluster--gap: initial` を一緒に渡します。カスタムプロパティの `initial` は「値がない」状態を表すので、`var()` はフォールバックに進みます。

```html
<div class="cluster" style="--cluster--gap: calc(var(--spacing--lg) * 1px)">
  <ul
    class="cluster"
    style="--cluster--gap: initial; --cluster--column-gap: calc(var(--spacing--xxs) * 1px)"
  >
    …
  </ul>
</div>
```

入れ子の `cluster` が必要になるのは、まとまり同士を広い間隔で並べ、まとまりの中を狭い間隔で並べる場合です。この場合も、内側に一括の `--cluster--gap` を渡すなら、外側の値は上書きされるので問題になりません。`initial` が必要になるのは、内側で行と列を別々に指定するときだけです。

### はみ出しと折り返し

`cluster` は子を折り返し、1つの子がコンテナより広い場合は、その子をコンテナの幅まで縮めます。本書のベーススタイルは、すべての要素に `min-inline-size: 0` を指定しているので、フレックスアイテムも中身の最小の幅（`min-content`）より狭くなれるからです。kiso.cssは `:root` に `overflow-wrap: anywhere` を指定しているので、長いURLや英単語を含むタグも途中で折り返され、文字がはみ出すことはまずありません。

はみ出すのは、タグの文字を折り返さないよう、コンポーネントで `white-space: nowrap` を指定した場合です。タグは縮んでも、文字列は折り返さないので、狭いコンテナでは文字がタグの外へはみ出します。ベーススタイルがない環境では、`min-inline-size` の初期値 `auto` によってタグが文字列の長さより狭くならず、タグごとコンテナからはみ出します。長い文字列が入りうるタグには `nowrap` を指定せず、`overflow-wrap: anywhere` による折り返しを許します。長い語の折り返しは「[14-4 文字サイズと改行](/typography/size-and-line-breaks/)」で説明しています。
