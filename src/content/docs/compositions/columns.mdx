`columns` は、用語集やサイトマップのように上から下へ読むリストを、読む順番を保ったまま、幅に応じた数の段に分けるコンポジションです。中身はCSSの段組み（Multi-column Layout）で、段の最小幅と最大数を公開プロパティで受け取ります。HTMLは「`.columns` の要素、その直下のリスト、リストの項目」の3段で組みます。段組みはリストに、項目の間隔は項目の `padding-block` に付け、リストの負のマージンで先頭と末尾の余白を打ち消します。

段組みは、項目を1段目の上から下へ流し、段の下端に達したら2段目へ移します。横方向の順番で並べたいカードの一覧には向かないので、行で並べる `grid` や、高さの違いを詰める `masonry` と使い分けます。コンポジションの考え方そのものは「[10-3 コンポジションとユーティリティ](/components/compositions-and-utilities/)」で説明しています。

## 段組みで項目の間隔を空けるときの落とし穴

フッターのリンク集を、幅に応じて2段から4段に分ける場面を考えます。段組みの指定は `columns` の1行で済むので、リストに直接書き、項目の間隔は `margin` で空けるのが素直な書き方に見えます。

```css title="🙅‍♂ Not Recommended: リストに段組みを書き、項目の間隔を margin で空ける" issue="behavior"
/* 🙅‍♂ Not Recommended */
._links {
  columns: calc(200 / 16 * 1rem) 4;

  & > li {
    margin-block: 8px;
  }
}
```

この書き方には問題が3つあります。1つ目は、項目の間隔と段の上端がずれることです。隣り合う項目の上下の `margin` は相殺して大きいほうの8pxだけになるので、項目の間は16pxになりません。さらに、仕様では段の境目に接する `margin` は切り捨てられるので、1段目の先頭の項目には上の8pxが残り、2段目以降の先頭の項目では消えます。その分、2段目以降の上端が1段目より上にずれます。{/* 要検証: ブラウザ。2段目以降の先頭の項目の margin が切り捨てられ、上端が1段目よりずれるか */}

2つ目は、項目が段の境目で分かれることです。`break-inside: avoid` がないと、2行にわたる項目の1行目が1段目の下端に、2行目が2段目の上端に表示されることがあります。3つ目は、段の間隔が書かれていないことです。`column-gap` の初期値は `normal` で、段組みでは `1em` として扱われます。間隔をコードに書かないと、文字の大きさを変えたときに段の間隔まで変わることに気付きにくくなります。

同じ注意点を、リンク集、用語集、サイトマップのたびに思い出して書くのは負担です。段組みの指定と、間隔と分割の扱いを1か所にまとめたのが `columns` コンポジションです。

## `columns` コンポジションの書き方

`columns` は、段の最小幅、段の最大数、項目の間隔、段の間隔の4つを公開プロパティで受け取ります。段の最小幅と最大数のデフォルト値は私が使っているテンプレートに従い、間隔は10-3のルールどおり `0` にしています。

```css title="🙆‍♂ Recommended: 直下のリストに段組みを、リストの項目に間隔を付ける" from="compositions/columns"
/**
 * 直下のリストを、上から下へ読む順番のまま段に分ける。
 * 構造は「.columns > リスト > 項目」で、段組みはリストに、項目の間隔は項目に付ける。
 *
 * @prop {length}  --columns--column-width     [calc(240 / 16 * 1rem)] - 段の最小幅（これより狭くなると段が減る）
 * @prop {integer} --columns--column-max-count [5]                     - 段の最大数
 * @prop {length}  --columns--row-gap          [0px]                   - 項目の間隔
 * @prop {length}  --columns--column-gap       [0px]                   - 段の間隔
 */
.columns {
  --_c--column-width: var(--columns--column-width, calc(240 / 16 * 1rem));
  --_c--column-max-count: var(--columns--column-max-count, 5);
  --_c--row-gap: var(--columns--row-gap, 0px);
  --_c--column-gap: var(--columns--column-gap, 0px);

  /* リストの負のマージンを、外の要素のマージンと相殺させないため */
  display: block flow-root;

  & > * {
    column-gap: var(--_c--column-gap);
    columns: var(--_c--column-width) var(--_c--column-max-count);

    /* 先頭と末尾の項目に付く半分の余白を打ち消す */
    margin-block: calc(var(--_c--row-gap) / -2);
  }

  /* 段組みの中の項目はリストの直下の子なので、ユニバーサルセレクタが2つになる */
  /* stylelint-disable-next-line selector-max-universal */
  & > * > * {
    /* 半分ずつの margin は相殺して足されず、段の境目で2段目以降の先頭だけ切り捨てられるので、padding で空ける */
    padding-block: calc(var(--_c--row-gap) / 2);
    break-inside: avoid;
  }
}
```

使う側は、リストを `.columns` の要素で包み、値を `style` 属性で渡します。間隔には、余白のトークンを `calc(var(--spacing--sm) * 1px)` の形でpxに変換して渡します。

```html
<div
  class="columns"
  style="--columns--column-width: calc(200 / 16 * 1rem); --columns--column-max-count: 4; --columns--row-gap: calc(var(--spacing--sm) * 1px); --columns--column-gap: calc(var(--spacing--lg) * 1px)"
>
  <ul>
    <li><a href="/about/">会社概要</a></li>
    <li><a href="/news/">お知らせ</a></li>
    <!-- ... -->
  </ul>
</div>
```

`columns` プロパティは、`column-width` と `column-count` のショートハンドです。2つを両方指定すると、幅は段の最小幅、数は段の最大数として働きます。ブラウザは、まず「（要素の幅＋段の間隔）÷（段の最小幅＋段の間隔）」の小数点以下を切り捨てて入る段の数を求め、それが最大数を超えれば最大数に抑えます。段の実際の幅は、要素の幅から段の間隔の合計を引き、段の数で割った値に広がります。

デフォルトの240px相当の最小幅で、段の間隔を32pxにした場合を計算します。要素の幅が1000pxなら、（1000＋32）÷（240＋32）は約3.8なので3段になり、1段の幅は（1000−32×2）÷3で312pxです。要素の幅が最小幅より狭いときは1段になり、その段は要素の幅まで縮みます。段の数を幅から自動で決めるので、メディアクエリを書かずに済みます。

次のデモは、CSSの用語を五十音順に並べた用語集です。`dl` の中を `div` で用語ごとに包んでいるので、`.columns` の孫は `div` になり、用語と説明がまとめて `break-inside: avoid` の対象になります。段の最小幅は200px相当、最大数は4、段の間隔は32pxです。

<Demo title="五十音順の用語集を、上から下へ読む順番のまま段に分ける" html={columnsHtml} css={columnsCss} widths={[320, 480, 768, 1024, 1280]} />

デモの枠には左右24pxずつの余白があるので、要素の幅は枠の幅から48pxを引いた値です。段の数は「（要素の幅＋32）÷（200＋32）」を切り捨てた値なので、枠の幅から16pxを引いて232で割った値になります。320pxでは1段、480pxでは2段、768pxでは3段、1024pxでは4段です。1280pxでは5段分の幅がありますが、最大数の4段に抑えられます。

デモのCSSのうち、コンポーネント（`glossary`）が書いているのは、説明の文字の大きさだけです。用語の `dt` は、kiso.cssが太字にしています。段の数、段の間隔、項目の間隔、分割の禁止は、すべてコンポジションと `style` 属性で決まっています。フッターのサイトマップに使う場合も同じで、コンポーネントのCSSはリンクの色や下線のような見た目だけを受け持ちます。

`column-width` には `%` を指定できない点に注意します。Gridの `minmax(min(100%, …), 1fr)` と同じ感覚で `min(100%, …)` と書くと、値が不正になって宣言ごと無視されます。この点は「[11-11 grid-lanesで石積みのレイアウトを組む](/layout-practice/masonry/)」でも説明しています。

## 2段構成と負のマージンの仕組み

段組みを `.columns` 自身ではなく直下のリストに付けるのは、リストに負のマージンを持たせるためです。項目の間隔は、すべての項目に同じ `padding-block` を上下半分ずつ付けて作ります。隣り合う項目の間では、上の項目の下半分と下の項目の上半分が足されて、指定した間隔になります。

`margin` ではなく `padding` を使うのは、前の節で挙げたように、半分ずつの `margin` は隣り合う項目の間で相殺して足されず、段の境目では2段目以降の先頭の項目の分だけが切り捨てられるからです。`padding` は相殺せず、境目でも消えないので、2段目以降の先頭の項目にも、1段目の先頭と同じ半分の余白が付きます（[`columns-for-top-to-bottom-lists`](/layout-practice/masonry/#rule-columns-for-top-to-bottom-lists)）。どの段の上端にも同じ量の余白が付くので、段の上端はそろいます。

残るのは、リスト全体の先頭と末尾に付く半分の余白です。これをリストの `margin-block: calc(var(--_c--row-gap) / -2)` で打ち消します。項目の間隔を16pxにした場合、各項目の上下に8pxの `padding` が付き、リストは上下に−8pxのマージンを持ちます。その結果、先頭の項目の文字は `.columns` の上端にそろい、項目と項目の間は16pxになります。

この負のマージンを `.columns` 自身に付けると、マージンがコンポーネントの外へ出ます。親の `gap` から8pxが引かれたり、前の要素のマージンと相殺したりして、外側の余白が変わります。「[10-2 コンポーネントの境界を守る](/components/boundaries/)」で説明したとおり、ルートに外側の余白を持たせないのが本書の原則です（[`no-external-layout-on-root`](/components/boundaries/#rule-no-external-layout-on-root)）。そこで、負のマージンは内側のリストに持たせ、`.columns` を外から見て余白のない箱にしています。

`.columns` の `display: block flow-root` は、この負のマージンを `.columns` の中に閉じ込める指定です。通常のフローでは、枠線と `padding` のない親の先頭の子のマージンは、親を突き抜けて親のマージンと相殺します。前の段落の `margin-block-end` が24pxなら、−8pxと相殺して16pxになり、本文の余白が崩れます。`flow-root` で新しいブロック整形コンテキストを作ると、子のマージンは親のマージンと相殺しなくなります。`stack` のようなFlexboxの中なら、もともと相殺は起きません。記事の本文のような通常のフローにも置けるように、`.columns` 自身に指定しています。

## `grid`・`masonry` との使い分け

`columns` を選ぶ基準は、項目を読む順番です。用語集やサイトマップは、1段目を上から下へ読み、続けて2段目へ移るのが自然です。五十音順や階層順のように、順番が縦に続くリストでは、段組みならHTMLの順番と見た目の順番がそろい、読み上げとキーボードのフォーカスも見た目どおりに進みます。

横方向の順番で並べたい一覧には `columns` を使いません。新着順の記事のカードを段組みにすると、最新の記事が1段目の上から並び、2段目の先頭には中ほどの記事が来ます。カードを行ごとにそろえて並べるなら「[12-7 grid](/compositions/grid/)」を、高さの違うカードを横方向の順番のまま詰めるなら「[12-9 masonry](/compositions/masonry/)」を使います。

画面の高さを超える長いリストにも向きません。段組みでは1段目を読み終えたあと、2段目の先頭まで上へスクロールして戻る必要があるからです。項目が数百あるサイトマップなら、カテゴリごとの見出しとリストのまとまりに分け、まとまりを `grid` や `masonry` で並べ、各まとまりの中だけを `columns` にします。

## 補足と注意点

`.columns` の直下に置くのは、リスト1つだけにします。段組みの指定は `& > *` で直下の子すべてに付くので、見出しを `.columns` の中に入れると、見出し自身も段組みの要素になり、負のマージンも付きます。見出しが必要なら、`.columns` の外に置き、`stack` などで縦に積みます。

項目のセレクタ `& > * > *` は、本書のStylelintの設定 `selector-max-universal`（ユニバーサルセレクタは1つまで）に掛かります。この指定は、要素の種類に関係なく選びたい箇所で `*` を使い、セレクタの重さや意図しない要素の選択を防ぐためのものです。`columns` では、項目が `li` か `div` かを決めずに「リストの直下の子」を選ぶ必要があるので、理由のコメントと無効化のコメントを添えて、この行だけを例外にしています。ネストは `.columns` とその中の1段の2層なので、ネストの規則（[`nesting-depth-one`](/notation/nesting/#rule-nesting-depth-one)）には収まっています。`& > * { & > * { … } }` と入れ子にすると3層になるので、そう書かずに `& > * > *` と1段で書きます。

`break-inside: avoid` は、項目を段の境目で分けない指定です。ただし、1つの項目が段の高さより長いときは、分けないと収まらないので、ブラウザは項目を分割します。説明の長い用語集では、段の最小幅を広げて項目の高さを抑えるか、段の最大数を減らします。

段の数は要素の幅だけで決まり、段の高さはブラウザが段ごとの高さをそろえるように決めます（`column-fill` の初期値 `balance`）。そのため、項目の数が段の数で割り切れないと、最後の段が短くなります。項目が段の数より少なければ、右側の段は空のまま残ります。どちらも段組みの仕様どおりの動作で、項目の位置を行と列でそろえたいときは `grid` を選びます。{/* 要確認: 出典なし */}

`columns` の段組み、`break-inside`、`display: flow-root` は、本書の対象のブラウザすべてで使えます。新しい機能を使っていないので、`@supports` による分岐も要りません。
