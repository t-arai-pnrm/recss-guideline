`grid` は、列の最小幅と最大数を受け取り、置かれた場所の幅から列の数を自動で決めるコンポジションです。幅が広がるにつれて列は1列、2列、3列と1つずつ増え、最大数に達するとそれ以上は増えません。カードの一覧、記事の一覧、ロゴの一覧のように、同じ形のアイテムを格子状に並べる場面で使います。

列の数を決めるのは、メディアクエリではなく、列の幅を求める計算です。`repeat()` のキーワードは公開プロパティ `--grid--mode` で切り替えられ、デフォルトは `auto-fill` にします。アイテムが少ないときも列の幅が変わらないので、件数が変わる一覧で見た目がそろうからです。

## カードの一覧の列数を決める方法

カードの一覧の列数を、画面の幅ごとにメディアクエリで切り替える書き方はよく見かけます。スマートフォンでは1列、タブレットでは2列、デスクトップでは4列というように、デザインカンプの幅をそのまま条件にする方法です。

```css title="🙅‍♂ Not Recommended: 画面の幅ごとに列数を切り替える" issue="behavior"
/* 🙅‍♂ Not Recommended */
._card-list {
  display: block grid;
  grid-template-columns: repeat(2, 1fr);
  gap: 24px;

  @media (width >= calc(1024 / 16 * 1rem)) {
    grid-template-columns: repeat(4, 1fr);
  }
}
```

この書き方は、一覧が画面の全幅に置かれることを前提にしています。同じ一覧をサイドバーのある2カラムのページに置くと、画面が1024pxあっても一覧の幅は700px程度しかなく、4列のカードは1枚あたり150px前後まで縮みます。列数の条件が一覧の幅ではなく画面の幅を見ているので、置き場所が変わると破綻します。列の幅も `1fr` で、ベーススタイルによりアイテムの最小幅が0なので、カードがどこまで狭くなってよいかという下限を持っていません。

`repeat(auto-fill, minmax(min(100%, calc(320 / 16 * 1rem)), 1fr))` のように、列の最小幅だけを決めて列数をブラウザに任せる方法もあります。この方法なら一覧の幅を基準に列数が変わり、置き場所を選びません（「[13-1 検討する順番](/responsive/escalation/)」で、クエリを使わない段階の手段として扱っています）。ただし、列の数に上限がないので、2400pxの画面では列が7つに増えます。デザインで「多くても4列まで」と決まっている一覧には、この方法だけでは対応できません。

`grid` は、この2つの方法の間を埋めるコンポジションです。列の最小幅を下回らない範囲で列を増やし、最大数に達したら増やすのをやめます。列数の判定にメディアクエリを使わないので、置き場所が画面の全幅かサイドバーの横の狭い領域かにかかわらず、列数は一覧自身の幅から決まります。

## 列の最小幅と最大数を受け取る `grid`

`grid` のコードは次のとおりです。公開プロパティで受け取った値を `--_c--` で始まる内部プロパティに受け、列の幅を2段階で計算しています。

```css title="🙆‍♂ Recommended: 列の最小幅と最大数から、列の幅を計算する"
/**
 * 列の最小幅と最大数から、列の数を自動で決める。
 *
 * @prop {keyword} --grid--mode             [auto-fill]             - repeat() のキーワード（auto-fill | auto-fit）
 * @prop {length}  --grid--column-min-width [calc(320 / 16 * 1rem)] - 列の最小幅（これより狭くなると列が減る）
 * @prop {integer} --grid--column-max-count [5]                     - 列の最大数
 * @prop {length}  --grid--gap              [なし]                  - 行と列の間隔（一括）。指定すると個別の指定より優先する
 * @prop {length}  --grid--row-gap          [0px]                   - 行の間隔
 * @prop {length}  --grid--column-gap       [0px]                   - 列の間隔（単位を付けて渡す）
 *
 * @example
 * <ul class="grid" style="--grid--column-min-width: calc(240 / 16 * 1rem); --grid--column-max-count: 3">
 *   <li>…</li>
 * </ul>
 */
.grid {
  --_c--mode: var(--grid--mode, auto-fill);
  --_c--row-gap: var(--grid--gap, var(--grid--row-gap, 0px));
  --_c--column-gap: var(--grid--gap, var(--grid--column-gap, 0px));
  --_c--column-max-count: var(--grid--column-max-count, 5);
  --_c--column-min-width: var(--grid--column-min-width, calc(320 / 16 * 1rem));
  --_c--column-preferred-width: calc(
    (100% - var(--_c--column-gap) * (var(--_c--column-max-count) - 1)) / var(--_c--column-max-count)
  );

  /* 要素の幅より広い列ははみ出すので、min(100%, …) で要素の幅に収める */
  --_c--column-width: min(100%, max(var(--_c--column-min-width), var(--_c--column-preferred-width)));

  display: block grid;
  grid-template-columns: repeat(var(--_c--mode), minmax(var(--_c--column-width), 1fr));
  gap: var(--_c--row-gap) var(--_c--column-gap);
}
```

公開プロパティは6つです。`--grid--column-min-width` は列の最小幅で、デフォルトは320px相当です。列の幅がこれを下回りそうになると、列が1つ減ります。`--grid--column-max-count` は列の最大数で、デフォルトは5です。間隔は `--grid--gap` で一括に、`--grid--row-gap` と `--grid--column-gap` で個別に指定できます。個別の2つのデフォルトは `0px` です。一括の `--grid--gap` にデフォルト値はなく、指定すると個別の指定より優先します。間隔のデフォルトを0にする理由は、「[10-3 コンポジションとユーティリティ](/components/compositions-and-utilities/#rule-composition-default-gap-zero)」のとおり、間隔はコンポジションを置く文脈で決まる値だからです。

残る `--grid--mode` は、`repeat()` に渡すキーワードで、`auto-fill` か `auto-fit` を受け取ります。2つの違いが出るのは、アイテムの数が入る列の数より少ないときです。`auto-fill` は、アイテムのない列を空のまま残すので、アイテムは1列分の幅で行の先頭に寄ります。`auto-fit` は空の列を幅0に折りたたむので、残ったアイテムが `1fr` で行いっぱいに広がります。

本書では `auto-fill` をデフォルトにします。`grid` を使う一覧の多くは、お知らせや検索結果のように件数が変わるもので、件数が少ないときにカードが横長に伸びると、ほかのページの一覧と見た目がそろわなくなるからです。たとえば最大4列の一覧で、絞り込みの結果が2件だけになったとします。`auto-fit` では2枚のカードがそれぞれ行の半分の幅まで広がり、画像の比率や1行の文字数が、4件以上あるときとまったく違ってしまいます。`auto-fill` なら、カードの幅は2件のときも8件のときも同じです。

値は、使う側がHTMLの `style` 属性で渡します。`--grid--column-min-width: calc(240 / 16 * 1rem); --grid--column-max-count: 3` と書けば、240px相当を下回らない範囲で、多くても3列に並びます。関連リンクのバナーのように、件数が最大数に届かないときは行いっぱいに広げたい並びでは、`--grid--mode: auto-fit` を渡します。

## 列の幅を求める計算

計算の中心は、内部プロパティ `--_c--column-preferred-width` と `--_c--column-width` の2つです。`--_c--column-preferred-width` は、最大数の列でちょうど埋まるときの1列の幅で、要素の幅（`100%`）から列の間隔の合計を引き、最大数で割って求めます。列が5つなら間隔は4つなので、間隔に掛けるのは「最大数−1」です。

`--_c--column-width` は、`minmax()` の最小値として実際に使う幅です。列の最小幅と `--_c--column-preferred-width` の大きいほうを `max()` で選び、さらに `min(100%, …)` で要素の幅を超えないようにしています。`auto-fill` と `auto-fit` は、この最小値で入るだけの列を作るので、最小値が大きければ列は少なく、小さければ多くなります。

最大数を超えない仕組みは、`max()` にあります。要素が広くなると、`--_c--column-preferred-width` が列の最小幅を上回り、最小値として採用されます。この幅で並べると、最大数の列と間隔の合計がちょうど要素の幅に等しくなるので、それより多くの列は入りません。要素が狭いときは列の最小幅のほうが大きく、ブラウザはその幅で入るだけの列を作ります。最大数より少ない列から順に、入らなくなったアイテムが次の行へ回ります。

デフォルト値（最小幅320px相当、最大5列）に、列の間隔24pxを渡した場合を数値で確かめます。`--_c--column-preferred-width` は「（要素の幅−24px×4）÷5」です。列数は、入るだけ並べたときの「（要素の幅＋24px）÷（列の幅＋24px）」の整数部分になります。

| 要素の幅 | 最大数で割った幅 | 採用される最小値 | 列数 |
|---|---|---|---|
| 300px | 40.8px | 300px（`min(100%, …)` で抑える） | 1 |
| 960px | 172.8px | 320px | 2 |
| 1280px | 236.8px | 320px | 3 |
| 1800px | 340.8px | 340.8px | 5 |
| 2400px | 460.8px | 460.8px | 5 |

列が増える境目は、664px（2列）、1008px（3列）、1352px（4列）、1696px（5列）です。どれも「320px×列数＋24px×（列数−1）」で求められ、1696pxより広くなると最大数で割った幅が320pxを上回るので、2400pxでも5列のままです。最小値を320pxのまま固定していた場合、2400pxでは「2424÷344」の整数部分で7列になります。この表の値と境目は、Chromeで `grid-template-columns` の計算値を取得して確認しました。

`min(100%, …)` は、要素の幅が列の最小幅より狭いときのための指定です。表の300pxの行では、`max()` の結果は320pxですが、`min()` によって300pxに抑えられ、1列が要素の幅にちょうど収まります。この指定がないと、列が要素から20pxはみ出します。

## カードの一覧で使う

実際のコンポーネントでは、一覧のルートに `grid` を付け、列の最小幅、最大数、間隔を `style` 属性で渡します。次の例は、カードを最大3列で並べるお知らせの一覧です。

```html
<ul
  class="scoped news-list | grid"
  style="--grid--column-min-width: calc(280 / 16 * 1rem); --grid--column-max-count: 3; --grid--gap: calc(var(--spacing--md) / 16 * 1rem)"
>
  <li>
    <article class="scoped card">…</article>
  </li>
  <!-- ... -->
</ul>
```

コンポーネントのCSSが受け持つのは、セルの中身だけです。列の数と間隔は `grid` とHTMLの `style` 属性で決まるので、`news-list` のCSSには `grid-template-columns` と `gap` を書きません。

```css title="🙆‍♂ Recommended: 列の数と間隔はコンポジションに任せ、セルの中だけを書く" from="compositions/grid"
@layer components {
  @scope (.scoped.news-list) to (.scoped) {
    /* li を grid にして、中のカードをセルの高さいっぱいに伸ばす */
    li {
      display: block grid;
    }
  }
}
```

`li` を `display: block grid` にしているのは、同じ行のカードの高さをそろえるためです。`grid` の子である `li` は、行の高さいっぱいに伸びます。その `li` をグリッドにすると、中の `article` もデフォルトの `stretch` で `li` の高さまで伸び、隣のカードと下端がそろいます。カードの中の見出しや本文の位置まで行ごとにそろえたいときは、サブグリッドを使います（「[7-9 Gridでアイテムをそろえる](/layout/grid-alignment/#rule-subgrid-for-aligned-rows)」）。その場合は、カードを別のコンポーネントにせず、一覧の子要素として書きます。カードの行が一覧の行になり、カードだけを一覧の外に取り出せなくなるからです（「[10-1 何をコンポーネントにするか](/components/what-is-a-component/#行をそろえて並べる一覧と項目)」）。

次のデモは、最小幅200px相当、最大4列、間隔16px相当でカードを6枚並べています。デモの本体には左右に24pxの余白があるので、一覧の幅は表示の幅より48px狭くなります。幅を320px、480px、768px、1024pxと切り替えると、列は1列、2列、3列、4列と1つずつ増えます。1280pxでは、最小幅だけで並べれば5列入りますが、最大数の4列で止まります。

## `switcher` との使い分け

`grid` とよく似たコンポジションに、`switcher` があります。どちらも列の最小幅を受け取り、幅が足りなくなると列を減らします。違うのは減り方で、`grid` は最大数から1列ずつ減り、`switcher` は指定の列数から一気に1列になります（`switcher` の仕組みは「[12-5 switcher](/compositions/switcher/)」で説明しています）。

次のデモでは、3つのアイテムを、最小幅200px相当、最大3列の `grid` と、同じ値の `switcher` で並べています。768pxではどちらも3列です。480pxでは、`grid` は2列になって3つ目のアイテムが2行目に1つだけ残り、`switcher` は3つとも縦に積まれます。

<Demo title="grid は列が1つずつ減り、switcher は一気に1列になる" html={switcherHtml} css={switcherCss} widths={[320, 480, 768, 1024]} />

使い分けの基準は、アイテムの数が決まっているかどうかです。サービスの特徴を3つ並べる、料金プランを3つ並べるといった、数が決まっていて揃いで見せたいアイテムには `switcher` を使います。3つのうち1つだけが2行目に回ると、揃いの印象が崩れるからです。件数が変わり、どこで折り返しても意味が変わらない一覧には `grid` を使います。

アイテムの高さがばらばらで、行をそろえずに隙間を詰めたいときは、`grid` ではなく `masonry` を使います（「[12-9 masonry](/compositions/masonry/)」）。メインとサイドのように、幅の違う2つの領域を並べるときは `sidebar` です（「[12-6 sidebar](/compositions/sidebar/)」）。`grid` の列はすべて同じ幅になるので、幅の違う領域には向きません。

## 補足と注意点

列の間隔は、`0` であっても `0px` のように単位を付けて渡します。`--_c--column-preferred-width` の計算では、間隔を `100%` から引いています。単位のない `0` は長さではなく数値として扱われるので、`100% - 0 * 4` は型の合わない計算になり、`grid-template-columns` の宣言全体が無効になります。デフォルト値を `0px` と書いているのも同じ理由です。`--grid--mode` が `auto-fill` と `auto-fit` 以外の値のときや、`--grid--column-max-count` が0のときも、宣言が無効になります。どの場合も表示は崩れず1列になるだけなので、間違いを見落としやすくなります。

内部プロパティの `100%` が計算されるのは、宣言した時点ではなく、`grid-template-columns` の中で使われた時点です。カスタムプロパティの値は、使われる場所に置き換えられてから解釈されるからです。そのため `100%` はグリッドコンテナの内側の幅を指します。`grid` を入れ子にしたときも、それぞれが自分の幅を基準に列数を決めます。

`grid` はアイテムの順番を入れ替えません。アイテムはHTMLの順に左上から右へ並び、行の終わりで次の行へ回るので、スクリーンリーダーの読み上げ順と見た目の順が一致します。この一致を保つため、`order` や `grid-auto-flow: dense` による並べ替えはしません。並べ替えると、見た目の順と、キーボードのフォーカスの移る順がずれるからです。

列の幅は `minmax()` の最小値で守られていますが、カードの中に長いURLや英単語があると、カードの中身が列からはみ出すことがあります。グリッドのアイテムは、既定では中身の最小幅より狭くならないからです。単語の折り返しとアイテムの最小幅の扱いは、「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/)」で扱っています。

列の幅は計算で求めるので、小数になります。表の1800pxの行では、1列は340.8pxです。ブラウザは端数を丸めて配置するので、最大数の列でちょうど埋まる幅のとき、丸めの誤差によって列が1つ減ることも考えられます。Chromeでは、1696pxから2403pxまでの数か所を確かめ、どこも5列になりました。{/* 要確認: 出典なし */}SafariとFirefoxでの丸めの結果は確認していません。
