コンポジションは、縦に積む、横に並べて折り返す、幅に応じて列数を変えるといった配置のパターンを、コンポーネントから切り離して部品にしたクラスです。配置だけを受け持ち、間隔や列数は公開プロパティで受け取ります。考え方と書き方の規約は「[10-3 コンポジションとユーティリティ](/components/compositions-and-utilities/)」で説明しています。

この章では、私が使っている12のコンポジションに1ページずつを充て、使う場面と使わない場面、公開プロパティ、内部の計算、似たコンポジションとの使い分けを説明します。多くのコンポジションはFlexboxやGridの規則の上に成り立っています（`prose` は通常フロー、`columns` は段組みを使います）。通常フローとの違いや `align-items` と `align-content` の違いは「[7-1 レイアウトの基礎](/layout/fundamentals/)」で確かめてください。

この章は、前から順に通読するより、必要なときに引く参照用の章として書いています。まず次の「目的から選ぶ」の表で使うコンポジションを選び、そのページの冒頭と使い分けを読みます。内部の計算式は、実際に使うときや、値を変えたくなったときだけ読めば足ります。通して読む場合は、積む、並べる、格子を作るという基本の方法にあたる `stack`、`prose`、`cluster`、`sidebar`、`grid` を先に読むと、`switcher` や `masonry` のような計算の多いページが読みやすくなります。公開プロパティで値を受け取るという書き方の説明は、どのページにも短く繰り返しています。各ページを単体で引けるようにするためです。

## この章で判断できるようになること

この章を読むと、並べたい内容を見て、使うコンポジションを1つに絞れます。決め手になるのは、間隔が一律か、列数を1つずつ減らすか、列数と1列の二択で切り替えるか、子の役割が違うかといった条件です。似たコンポジションで迷ったときも、どの条件で一方を選ぶかを説明できます。間隔のように置く文脈で変わる値は、コンポジションの側に書かず、使う側から公開プロパティに渡すと決められます。

## 初めて読むとき

初めて読むときは、次の「目的から選ぶ」の表で12のコンポジションの役割をつかみます。そのうえで、基本の節の「[12-1 stack](/compositions/stack/)」「[12-2 prose](/compositions/prose/)」「[12-3 cluster](/compositions/cluster/)」「[12-4 apart](/compositions/apart/)」「[12-6 sidebar](/compositions/sidebar/)」「[12-7 grid](/compositions/grid/)」を読みます。参照の節は、この表から引いてください。

## 目的から選ぶ

並べ方の目的から、使うコンポジションを選びます。

| したいこと | コンポジション |
|---|---|
| 構成の決まった要素を、一律の間隔で縦に積む | [12-1 stack](/compositions/stack/) |
| 見出しや段落の続く本文の流れを通常フローのまま積み、子ごとに変えられる間隔を付ける | [12-2 prose](/compositions/prose/) |
| 中身の量で幅が決まる要素を横に並べ、入りきらなければ折り返す | [12-3 cluster](/compositions/cluster/) |
| 2つのまとまりを、インライン方向の両端に分ける | [12-4 apart](/compositions/apart/) |
| 決まった数の項目を、指定の列数か1列のどちらかで並べる | [12-5 switcher](/compositions/switcher/) |
| 幅の決まったサイドと、伸び縮みするメインを並べる | [12-6 sidebar](/compositions/sidebar/) |
| 件数の変わる一覧を、列の最小幅と最大数から列数を決めて並べる | [12-7 grid](/compositions/grid/) |
| 上から下へ読むリストを、段に分ける | [12-8 columns](/compositions/columns/) |
| 高さの違う項目を、隙間なく詰めて並べる | [12-9 masonry](/compositions/masonry/) |
| 画像と文字のように、子を同じ場所に重ねる | [12-10 pile](/compositions/pile/) |
| ページのコンテンツ幅とガターを決め、子ごとに全幅などの幅を選ばせる | [12-11 primary-layout](/compositions/primary-layout/) |
| 子を折り返さずに1列に並べ、入りきらない分を横にスクロールさせる | [12-12 reel](/compositions/reel/) |

横に並べる `cluster` と `reel` は、入りきらないときに次の行へ折り返すか、1列のまま横にスクロールさせるかで選びます。

迷いやすいのは、列に並べる3つのコンポジションです。`switcher` は列数か1列かの二択で、途中の列数を作りません。`grid` は、幅が狭くなるにつれて列数を1つずつ減らします。`sidebar` は、2つの子の役割が違い、サイドの幅を決めておきたいときに使います。

縦に積む `stack` と `prose` は、間隔の決まり方で選びます。間隔が一律なら `stack` を、前後の要素の種類や有無で間隔が変わるなら、通常フローのまま間隔を作る `prose` を使います（11-1のルール「[縦に積む要素の間隔が前後の要素で変わるなら、通常フローのまま組む](/layout-practice/choosing/#rule-normal-flow-for-conditional-spacing)」）。

コンポジションの公開プロパティに渡す間隔のデフォルト値は、どれも0です。間隔は置く文脈で決まる値なので、使う側で `style` 属性などから渡します。

## この章の判断のまとめ

並べ方で迷ったら、子の見た目ではなく、項目を読む向きと、幅が足りないときの変わり方を問います。項目を縦に読ませるなら `columns`、横方向の順番で並べるなら `grid` や `masonry` を選び、幅が足りないときに途中の列数を許すなら `grid`、許さないなら `switcher` です。間隔や列数など、置く文脈によって決まる値は、コンポジションの側に書かず、使う側から公開プロパティで渡します。コンポーネントのCSSでは、`gap` や `display` を上書きしません。

公開プロパティは継承するので、入れ子にしたコンポジションには値を渡し直します。列数と一緒にほかの要素も同じ閾値で切り替えるなら、コンポジションでは解決しきれないので、コンテナサイズクエリとフラグで書きます。

## 次の章へ

`switcher` や `grid` のように、クエリを書かずに置かれた場所の幅で並び方を変えるコンポジションもあります。ただ、それだけでは足りず、コンポーネントが置かれた幅やビューポートの幅を問い合わせて切り替える場面は残ります。第13章「[レスポンシブデザイン](/responsive/)」では、クエリを使う前に検討する順番と、コンテナサイズクエリとメディアクエリの使い分けを説明します。
