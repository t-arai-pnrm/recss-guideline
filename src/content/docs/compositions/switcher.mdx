`switcher` は、要素の幅が閾値以上なら指定の列数で並べ、閾値を下回ったら1列にするコンポジションです。閾値は「列の最小幅×列数＋列の間隔×（列数−1）」で求め、`sign()` で要素の幅と比べます。クエリを書かずに、置かれた場所の幅で並び方が切り替わります。

途中の列数を挟まず、n列と1列のどちらかだけを選ぶのが、`switcher` の特徴です。列数が4、3、2と段階的に減ってよい並びには `grid` を、幅の違う2つの要素を並べるなら `sidebar` を使います。この節では、公開プロパティと内部の計算を1つずつ説明し、数値の例で列数が切り替わることを確かめます。

## 列数が段階的に減ると困る並び

サービスの特徴を3つ並べるブロックを考えます。Gridの `auto-fit` と `minmax()` を使えば、クエリを書かずに列数をブラウザに任せられます（「[13-1 検討する順番](/responsive/escalation/)」で説明した、イントリンシックな方法です）。

```css title="🙅‍♂ Not Recommended: 3つの項目を auto-fit だけで並べる" issue="behavior"
/* 🙅‍♂ Not Recommended */
._items {
  display: block grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, calc(320 / 16 * 1rem)), 1fr));
  gap: 24px;
}
```

この書き方では、ブロックの幅が664pxから1007pxまでのあいだ、列は2つになります。3つ目の項目は2行目の左の列に1つだけ置かれ、右には空いたセルが残ります。対等な3つの項目を見せたいブロックで、1つだけが別の扱いを受けたように見えます。

この中途半端な状態を避けるために、メディアクエリで「768px以上なら3列」と書くこともよくあります。しかし、メディアクエリが判定するのはビューポートの幅です。同じブロックをサイドバーのような狭い場所に置くと、ビューポートが広くても3列のまま押し込まれ、各列が最小幅を割り込みます。

求めているのは、「置かれた場所の幅で、3列が入るなら3列、入らないなら1列」という判定です。この判定を、クエリを使わずに1つのクラスにまとめたものが `switcher` です。

## 閾値と sign() で列数を決める

`switcher` の実装は次のとおりです。公開プロパティを内部プロパティで受け、閾値と列の幅の目安を計算してから、`grid-template-columns` の1行で列数を決めます。

```css title="🙆‍♂ Recommended: 閾値を計算し、sign() で n 列と1列を切り替える"
/**
 * 幅が閾値以上なら指定の列数で並べ、閾値を下回ったら 1 列にする。
 *
 * @prop {integer} --switcher--column-count     [3]                     - 横に並べるときの列数
 * @prop {length}  --switcher--column-min-width [calc(320 / 16 * 1rem)] - 列の最小幅（閾値の計算に使う）
 * @prop {length}  --switcher--gap              [なし]                  - 行と列の間隔（一括）。指定すると個別の指定より優先する
 * @prop {length}  --switcher--row-gap          [0px]                   - 行の間隔
 * @prop {length}  --switcher--column-gap       [0px]                   - 列の間隔
 *
 * @example
 * <div class="switcher" style="--switcher--column-count: 2; --switcher--column-min-width: calc(384 / 16 * 1rem)">
 *   <div>Left</div>
 *   <div>Right</div>
 * </div>
 */
.switcher {
  --_c--row-gap: var(--switcher--gap, var(--switcher--row-gap, 0px));
  --_c--column-gap: var(--switcher--gap, var(--switcher--column-gap, 0px));
  --_c--column-count: var(--switcher--column-count, 3);
  --_c--column-min-width: var(--switcher--column-min-width, calc(320 / 16 * 1rem));

  /* 列の最小幅で指定の列数を並べるのに必要な幅 */
  --_c--threshold: calc(
    var(--_c--column-min-width) * var(--_c--column-count) + var(--_c--column-gap) * (var(--_c--column-count) - 1)
  );

  /* 指定の列数でちょうど埋まる 1 列の幅。auto-fit がこれより多くの列を作らないようにする */
  --_c--column-preferred-width: calc(
    (100% - var(--_c--column-gap) * (var(--_c--column-count) - 1)) / var(--_c--column-count)
  );

  display: block grid;

  /* 閾値より狭いと sign() が -1 になり、列の最小幅が 100%（1 列）になる */
  grid-template-columns: repeat(
    auto-fit,
    minmax(max(var(--_c--column-preferred-width), sign(100% - var(--_c--threshold)) * -100%), 1fr)
  );
  gap: var(--_c--row-gap) var(--_c--column-gap);
}
```

### 公開プロパティ

公開プロパティは次の5つです。列数と列の最小幅の2つで閾値が決まり、間隔の3つは見た目の隙間と閾値の両方に使われます。

| プロパティ | 意味 | デフォルト値 |
|---|---|---|
| `--switcher--column-count` | 横に並べるときの列数（単位のない整数） | `3` |
| `--switcher--column-min-width` | 列の最小幅。閾値の計算に使う | `calc(320 / 16 * 1rem)` |
| `--switcher--gap` | 行と列の間隔（一括）。指定すると個別の指定より優先する | なし |
| `--switcher--row-gap` | 行の間隔 | `0px` |
| `--switcher--column-gap` | 列の間隔 | `0px` |

値は、HTMLの `style` 属性で渡します。間隔には、単位のない数値で持っている余白のトークンを `calc(var(--spacing--md) / 16 * 1rem)` の形でremに変換して渡します。トークンを単位なしで持つ理由は「[10-4 デザイントークン](/components/design-tokens/)」で説明しています。

```html
<div
  class="switcher"
  style="--switcher--column-count: 3; --switcher--column-min-width: calc(200 / 16 * 1rem); --switcher--gap: calc(var(--spacing--md) / 16 * 1rem)"
>
  <section>…</section>
  <section>…</section>
  <section>…</section>
</div>
```

間隔のデフォルト値は、ほかのコンポジションと同じく0です（「[10-3 コンポジションとユーティリティ](/components/compositions-and-utilities/#rule-composition-default-gap-zero)」のルール）。ただし、`switcher` では単位のない `0` ではなく `0px` と書きます。列の間隔は閾値の `calc()` で長さと足し合わされるので、単位のない `0` が入ると「長さ＋数値」の式になって無効になるからです。無効になった `grid-template-columns` は初期値の `none` に戻り、どの幅でも1列になります。

コンポーネントの中で `switcher` を使うときは、`switcher` のクラスを付けた要素の直下に項目を置きます。`switcher` が決めるのは直下の子の並び方と間隔だけで、子の中身には関与しません。この役割分担は「[10-2 コンポーネントの境界を守る](/components/boundaries/)」で説明した「配置は置く側が持つ」という考え方にもとづいています。コンポーネント側では、項目に幅や `margin` を指定せず、次の例のように各項目の見た目だけを書きます。

```css title="🙆‍♂ Recommended: コンポーネントは項目の見た目だけを書く"
@scope (.scoped.feature-section) to (.scoped) {
  section,
  li {
    padding: calc(var(--spacing--sm) * 1px);
    border: 1px solid var(--border--base);
    border-radius: var(--rounded--md);
  }

  h2 {
    font-size: calc(18 / 16 * 1rem);
  }
}
```

### 閾値：`--_c--threshold`

`--_c--threshold` は、列の最小幅で指定の列数を並べたときに必要な幅です。列が3つなら隙間は2つなので、「列の最小幅×列数＋列の間隔×（列数−1）」になります。デフォルトの3列・320px相当に、列の間隔として24px相当を渡すと、320×3＋24×2で1008px相当です。

閾値に列の間隔を含めているので、間隔を変えると閾値も変わります。間隔を広げたのに切り替わる幅が変わらなければ、閾値ちょうどの幅で列が最小幅を割り込みます。閾値を式で書いておけば、値を変えても「列の最小幅が守られる」という条件が保たれます。クエリの閾値を式で書く考え方は「[13-2 ブレイクポイントの決め方](/responsive/breakpoints/#rule-threshold-as-formula)」で説明しています。

### 列の幅の目安：`--_c--column-preferred-width`

`--_c--column-preferred-width` は、要素の幅を指定の列数でちょうど埋めたときの1列の幅です。式は「（100%−列の間隔×隙間の数）÷列数」で、要素の幅から隙間の合計を引き、列数で割っています。隙間の数は列数−1です。閾値以上の幅では、この値が列の最小幅以上になります。

この値を `minmax()` の最小値に使うのは、`auto-fit` に指定の列数より多くの列を作らせないためです。`auto-fit` は、最小値を下回らない範囲で入るだけの列を作ります。最小値が「指定の列数でちょうど埋まる幅」なら、列数が1つ増えると幅が足りなくなります。列の最小幅（`--_c--column-min-width`）をそのまま最小値にすると、広い場所では4列、5列と増えてしまいます。

### 1列への切り替え：sign()

`sign()` は、引数が正なら1、0なら0、負なら-1を返す関数です。`sign(100% - var(--_c--threshold))` は、要素の幅が閾値より広ければ1、狭ければ-1になります。これに `-100%` を掛けると、閾値より広ければ `-100%`、閾値ちょうどなら `0%`、閾値未満では `100%` になります。

この値と列の幅の目安を `max()` で比べ、大きいほうを `minmax()` の最小値にします。閾値以上では `-100%` や `0%` は選ばれないので、最小値は列の幅の目安になり、指定の列数で並びます。閾値未満では `100%` が選ばれ、1列が要素の幅いっぱいを占めるので、すべての子が縦に積まれます。

### 数値で確かめる

列数3、列の最小幅320px、列の間隔24pxで、閾値の前後を確かめます。閾値は1008pxです。

要素の幅が1007pxなら `sign()` は-1になり、最小値は `100%` の1007pxになるので1列です。1008pxでは `sign(0)` が0になって最小値は列の幅の目安の（1008−48）÷3＝320pxになり、ちょうど320pxの列が3つ並びます。1400pxでは目安が（1400−48）÷3＝450.67pxになり、3列のまま各列が広がります。

列の幅の目安の式は、括弧の位置を誤りやすい箇所です。「100%÷列数−列の間隔×（列数−1）」と書くと、1列の幅から隙間の合計全体を引くことになり、目安が小さくなりすぎます。列数4、列の最小幅200px、列の間隔24pxで、要素の幅を1000pxとします。閾値は200×4＋24×3＝872pxなので、ここは4列になるはずの幅です。

正しい式では、目安は（1000−72）÷4＝232pxです。`auto-fit` が作る列の数は「（要素の幅＋間隔）÷（最小値＋間隔）」の整数部分なので、1024÷256＝4で4列になります。誤った式では、目安が1000÷4−72＝178pxになり、1024÷202≒5.07で5列になります。子が5つ以上あれば、4列を指定したのに5列で並びます。

この誤りは、列数が2や3では表に出にくいものです。列数3では、誤った式で4列になるのは要素の幅が間隔の15倍以下のときに限られ、間隔24pxなら360px以下です。この幅は通常の閾値を下回るので、`sign()` によって1列になります。列が増えるのは列数を4以上にしたときなので、列数3のまま使っているうちは誤りに気付きにくいのです。

この節の列数は、どれも実際のブラウザで要素の幅を変えて確かめた値です。式を変えたときも、閾値の前後と、閾値より十分に広い幅の3点で列数を確かめておくと、括弧の位置の誤りに気付けます。

次のデモには、`switcher` を2つ置いています。上は列数3、列の最小幅200px相当、間隔24px相当で、閾値は648px相当です。下は列数4、列の最小幅140px相当、間隔12px相当で、閾値は596px相当です。幅を672pxにすると下だけが4列になり、768px以上では両方が横に並びます。デモの本文には左右に24pxずつの余白があるので、要素の幅はデモの幅より48px狭く、672pxのときは624pxです。

## 補足と注意点

### 子の数が列数と違うとき

子の数が列数より少ないときは、`auto-fit` が空の列を幅0に折りたたみます。列数3に子が2つなら、2つの子が `1fr` で行いっぱいに広がり、それぞれ要素の幅の半分ほどになります。子が1つなら、閾値以上でも1つの子が行いっぱいを占めます。

子の数が列数より多いときは、指定の列数で行を折り返します。列数3に子が4つなら、2行目の左の列に4つ目の子が置かれ、右の2つは空いたセルになります。この場合は、どの行にも子のある列があるので、`auto-fit` は列を折りたたみません。

`switcher` はn列と1列のどちらかを選ぶためのものなので、子の数は列数に合わせるのが基本です。子の数がCMSの入力などで変わるなら、余りの行ができることを前提に、`grid` を使うほうが見た目を予測しやすくなります。

### grid、sidebar、cluster との使い分け

[`grid`](/compositions/grid/)は、列の最小幅と最大数から、入るだけの列を並べます。幅に応じて4列、3列、2列と段階的に列が減るので、カードの一覧のように件数が多く、途中の列数でも見た目が成り立つ並びに向いています。`switcher` を選ぶのは、3つの特徴や2つのプランのように、項目どうしが対等で、途中の列数にしたくない並びです。

[`sidebar`](/compositions/sidebar/)は、幅の決まったサイドと、残りを占めるメインの2つを並べます。`switcher` の列はすべて同じ幅なので、本文と補足のように役割と幅が違う2つの要素には `sidebar` を使います。

[`cluster`](/compositions/cluster/)は、子の幅を中身の大きさで決めて、入りきらなければ折り返します。タグやボタンのように幅が中身で決まる要素は `cluster` に、列の幅をそろえたい要素は `switcher` か `grid` に任せます。

### コンテナサイズクエリで書く場合との比較

同じ切り替えは、コンテナサイズクエリでも書けます。ただし、要素は自分自身をコンテナにして判定できないので、親にコンテナを指定し、子の `grid-template-columns` を条件で切り替える形になります。次の例は、「数値で確かめる」と同じ列数3、列の最小幅320px相当、列の間隔24pxで書いています。

```css title="列数の切り替えを、コンテナサイズクエリで書く"
@scope (.scoped.feature-section) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
  }

  ._items {
    display: block grid;
    gap: 24px;

    /* 列の最小幅 320px 相当 × 3 列 ＋ 列の間隔 24px × 2 */
    @container --scoped (inline-size >= calc(3 * 320 / 16 * 1rem + 2 * 24px)) {
      grid-template-columns: repeat(3, 1fr);
    }
  }
}
```

この書き方でも、閾値は式で書けます。ただし、公開プロパティから閾値を計算させることはできません。コンテナサイズクエリの条件の `var()` は、仕様の草案では認められていますが、対象のブラウザで実装がそろっていないので、本書では使わないからです（「[13-2 ブレイクポイントの決め方](/responsive/breakpoints/#rule-no-var-in-query)」のルール）。その代わり、列の最小幅と間隔の値を式の中に書き写せば、閾値の根拠はコードに残ります。2つの書き方の違いは、値を書く場所の数、同じ並びを使う回数、式を確かめる手間の3つに表れます。

1つ目は値の重複です。クエリで書くと、列の間隔を `gap` の宣言と閾値の式の2か所に書きます。列の最小幅は、式の中にだけ現れます。間隔を32pxに広げるとき、`gap` だけを直すと閾値は1008px相当のまま残ります。すると閾値ちょうどの幅で各列は（1008−64）÷3≒314.67pxとなり、最小幅を割り込みます。`switcher` は列数、列の最小幅、間隔を公開プロパティで一度受け取って閾値を計算するので、値を書くのは `style` 属性の1か所です。

2つ目は再利用する頻度です。クエリで書く場合は、同じ並びを使うコンポーネントごとに、コンテナの指定と閾値の式を書きます。値を変えるときは、その数だけ式を直すことになります。`switcher` なら、どのコンポーネントでもクラスを付けて値を渡すだけで、閾値の計算は1つの実装にまとまっています。

3つ目は式を保守する負担です。クエリの式は、書き写した箇所ごとに検算が要ります。列数を4に変えるなら、`repeat(3, 1fr)` の `3` と、式の `3 *` と `2 *` の3か所を直します。`switcher` の式は実装の中に一度だけあり、前の「数値で確かめる」で確かめた結果をどの使い方にも当てはめられます。ただし、`sign()` と `max()` を組み合わせた式は、クエリの条件の1行より読み解くのに時間がかかります。この読みにくさは実装の中に閉じていて、使う側はコメントに書いた公開プロパティだけを読めば済みます。

どちらで書くかは、`switcher` で解決しきれるかで決めます。「[13-1 検討する順番](/responsive/escalation/#rule-responsive-escalation-order)」のルールでは、上の段階で解決できるなら下の段階を使いません。列数だけを切り替えるなら、イントリンシックの段階にある `switcher` で解決できるので、`switcher` を使います。上で比べた値の重複、再利用の頻度、式の保守の3点は、どれも `switcher` を選ぶ理由を補強します。

一方、列数と一緒に、画像と本文の位置関係や文字の大きさも同じ閾値で切り替えるなら、`switcher` では解決しきれません。`switcher` の閾値は実装の式の中で計算され、クエリから参照できないので、`switcher` とクエリを組み合わせると、同じ閾値を2か所で持つことになるからです。この場合は、コンテナサイズクエリで書き、切り替えをフラグにまとめます。上の例の `._items` のように1つのルールにだけコンテナサイズクエリを書き、そのルールで `--_density` を宣言して、列数と一緒に `--spacious` へ切り替えます。ほかの子孫は、このフラグをスタイルクエリで読んで切り替えます（「[10-6 スタイルクエリで状態を伝える](/components/style-queries/#rule-density-via-style-query)」のルール）。クエリで組み替える例は「[13-3 コンテナサイズクエリ](/responsive/container-size-queries/)」で扱っています。

### はみ出しと置き場所

`switcher` の `minmax()` の最小値は、列の幅の目安か `100%` のどちらかで、どちらも要素の幅を超えません。そのため、`min(100%, …)` で包まなくても、列が要素からはみ出すことはありません。

ただし、列の幅は `minmax()` の最小値で決まり、中身の幅では広がりません。kiso.cssはルート要素に `overflow-wrap: anywhere` を指定しているので、長いURLは折り返されます。幅の決まった画像や表のように折り返せない中身は、列を押し広げずにセルの外へはみ出すので、コンポーネント側で `max-inline-size: 100%` などを指定して対処します。

`switcher` は、幅が親から決まる場所に置きます。`display: flex` の親の中で、幅を指定していないflexアイテムにすると、`100%` が中身の幅から決まるので、閾値の判定が意図どおりになりません。実際に試すと、中身の幅の1列になりました。flexアイテムにするなら、`flex-grow` などで幅を親から与えます。

### 読み上げ順

`switcher` は、子の順番を入れ替えません。横に並んだときは左から右、1列のときは上から下の順で、どちらもHTMLの順番と一致します。スクリーンリーダーの読み上げ順やキーボードでの移動順と、見た目の順番がずれないので、`order` や `grid-row` で並べ替えないようにします。

項目の並びに意味があるなら、`ul` や `ol` に `switcher` を付けると、リストであることと項目の数が支援技術に伝わります。デモの下の `switcher` は、`ul` に付けた例です。
