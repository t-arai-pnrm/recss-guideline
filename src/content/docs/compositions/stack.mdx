構成が決まっていて、すべての間を同じ大きさで空けてよい要素を縦に積むときは、コンポジション `stack` を使います。`stack` は `display: block flex` と `flex-direction: column` で子を縦に並べ、公開プロパティ `--stack--gap` で受け取った値を `gap` に渡して間隔を作ります。子の側には `margin` を書きません。

見出し、段落、図が続く記事の本文には、`stack` ではなく `prose` を使います。`stack` の中で一部の間隔だけを変えたいときは、子に `margin` を足さず、まとまりごとに `stack` を入れ子にするか、`grid-template` の空のセルか通常フローに切り替えます。コンポジション全体の考え方（配置だけを受け持つクラスにまとめ、間隔は公開プロパティで受け取り、デフォルト値は0にする）は「[10-3 コンポジションとユーティリティ](/components/compositions-and-utilities/)」で説明しています。

## 子要素のmarginで縦に積むと起きること

カードの中の番号、見出し、説明文、リンクのように、要素を縦に並べる場面はどのコンポーネントにもあります。この間隔を子要素の `margin-block-end` で作り、最後の要素だけ打ち消す書き方をよく見かけます。

```css title="🙅‍♂ Not Recommended: 子要素の margin で間隔を作り、最後の子だけ打ち消す" issue="behavior"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.card) to (.scoped) {
  :scope {
    & > * {
      margin-block-end: 16px;
    }

    & > :last-child {
      margin-block-end: 0;
    }
  }
}
```

この書き方では、間隔の情報が「すべての子に付ける余白」と「最後の子の打ち消し」の2か所に分かれます。要素を足したり順番を入れ替えたりするたびに、打ち消しが正しい要素に当たっているかを確かめ直すことになります。

もう1つの問題は、子の `margin` がほかのコンポーネントの手前で途切れることです。カードの中にボタンのコンポーネントを置くと、ボタンのルートはスコープの下限の `.scoped` なので、`& > *` の指定が当たらず、ボタンの下だけ間隔が空きません。これを補おうとボタンの側のルートに `margin` を持たせると、カードの余白と相殺したり足し合わされたりして、実際の間隔がどの指定で決まったのかを追えなくなります。「[10-2 コンポーネントの境界を守る](/components/boundaries/)」で説明したとおり、外側の余白は置く側が持つものです（ルートに `margin` を持たせず、置く側の `gap` などで間隔を作る）。

親をFlexboxにして `gap` を指定すれば、どちらの問題も起きません。`gap` は隣り合う子の間にだけ空くので、打ち消しが要らず、子のコンポーネントにも余白を持たせずに済みます。ただし、これを各コンポーネントで書くと、`display`、`flex-direction`、`gap` の3つの宣言があちこちに散らばり、HTMLを見ても子がどう並ぶのかが分かりません。この3つの宣言に名前を付けたのが `stack` です。

## stackの実装と公開プロパティ

`stack` の実装は、次の3つの宣言だけです。`compositions` レイヤーに置き、ファイルの先頭にJSDocの形式で公開プロパティを書きます。

```css title="🙆‍♂ Recommended: 子を縦に積み、間隔を公開プロパティで受け取る"
/**
 * 子要素を縦に積み、間隔をそろえる。
 *
 * @prop {length} --stack--gap [0] - 子要素の間隔
 *
 * @example
 * <div class="stack" style="--stack--gap: calc(var(--spacing--md) * 1px)">
 *   <h2>…</h2>
 *   <p>…</p>
 * </div>
 */
.stack {
  display: block flex;
  flex-direction: column;
  gap: var(--stack--gap, 0);
}
```

`display: block flex` は、外側には通常のブロックとして振る舞い、内側の子をフレックスアイテムとして並べる指定です（`display: flex` の2値構文）。`flex-direction: column` で並べる向きをブロック方向に変えるので、横書きでは子が上から下へ積まれます。`gap` は隣り合う子の間にだけ空くので、最初の子の上と最後の子の下には余白が付きません。

公開プロパティは、次の1つだけです。

| 公開プロパティ | 型 | デフォルト値 | 意味 |
|---|---|---|---|
| `--stack--gap` | 長さ | `0` | 隣り合う子の間隔 |

デフォルト値が `0` なので、値を渡さなければ子は隙間なく積まれます。渡し忘れた箇所がデザインと違って見えるので、指定の漏れにすぐ気付けます。間隔のデフォルト値を0にする理由は、10-3のルール「[コンポジションの間隔のデフォルト値は0にする](/components/compositions-and-utilities/#rule-composition-default-gap-zero)」にまとめています。

`switcher` や `grid` は計算の途中の値を `--_c--` で始まる内部プロパティに置きますが、`stack` は受け取った値をそのまま `gap` に渡すだけなので、内部プロパティを持ちません。

## 間隔の渡し方

間隔は、HTMLの `style` 属性で渡すのが基本です。余白のトークンは単位のない数値で持っているので、`calc(var(--spacing--md) * 1px)` のようにpxに変換して渡します。部品の間の間隔は、文字を大きくしても広げる必要がないのでpxにします。文字に合わせて広げたい段落の間だけを、「[12-2 prose](/compositions/prose/)」の中でremにします。

```html
<div class="_body | stack" style="--stack--gap: calc(var(--spacing--md) * 1px)">
  <h3>…</h3>
  <p>…</p>
  <a href="…">…</a>
</div>
```

`style` 属性で渡すと、HTMLを読むだけで「この要素の子は `--spacing--md` の間隔で縦に積まれる」と分かります。コンポーネントのCSSに間隔の指定が残らないので、間隔を変えるときもHTMLの1か所を書き換えるだけで済みます。トークンを単位のない数値で持つ理由は「[10-4 デザイントークン](/components/design-tokens/)」で説明しています。

画面や置き場所の幅によって間隔を変えたいときは、条件を `style` 属性に書けません。この場合は、コンポーネントのCSSで、`stack` を付けた要素に `--stack--gap` の値を渡します。コンポジションの実装には手を入れず、渡す値だけをクエリの中で切り替えます。

```css title="🙆‍♂ Recommended: 幅で変わる間隔は、コンポーネントのCSSで公開プロパティに渡す"
@scope (.scoped.service-section) to (.scoped) {
  ._heading {
    --stack--gap: calc(var(--spacing--xxs) * 1px);

    @media (width >= calc(768 / 16 * 1rem)) {
      --stack--gap: calc(var(--spacing--sm) * 1px);
    }
  }
}
```

このとき、`gap` を直接上書きしないようにします。`._heading { gap: … }` と書いても、`components` レイヤーは `compositions` レイヤーより後にあるので表示は変わります。しかし、コンポーネントのCSSが「`stack` は `gap` で間隔を作っている」という実装の詳細に依存することになり、コンポジションの書き方を変えたときに、この上書きが意図どおりに働かなくなります。公開プロパティを通せば、`stack` の中身を知らなくても値を渡せます。

次のデモは、サービスの一覧のセクションです。セクション全体、見出しのまとまり（`hgroup`）、各カード、カードの中の番号と見出しのまとまりの4か所に `stack` を使い、間隔はすべて `style` 属性で渡しています。カードの一覧は、「[12-5 switcher](/compositions/switcher/)」で並べています。幅を320pxと480pxにするとカードは1列に積まれ、768pxにすると3列に並びます。対等な3枚のカードが、2枚と1枚に分かれることはありません。

<Demo title="stack を入れ子にして間隔を2段にし、リンクをカードの下端に寄せる" html={stackHtml} css={stackCss} widths={[320, 480, 768]} />

カードの中では、間隔が2段になっています。番号と見出しは8pxの `stack` で1つのまとまりにし、そのまとまりと説明文、リンクの間は16pxの `stack` で空けています。近い要素ほど間隔を狭くすると、番号が見出しに属していることが見て分かります。この考え方は、11-2のルール「[グループの間の余白をグループの中の余白より大きくする](/layout-practice/spacing/#rule-spacing-proximity)」にまとめています。

リンクには、`align-self: start` と `margin-block-start: auto` を指定しています。`stack` の子は、何も指定しなければカードの幅いっぱいに広がるので、`align-self: start` で中身の幅に戻しています。カードはグリッドの行の高さまで引き伸ばされるので、説明文の短いカードには高さの余りができます。`margin-block-start: auto` は、その余りをリンクの上に取り、リンクをカードの下端に寄せます。余りがあっても `gap` の16pxは残るので、説明文とリンクがくっつくことはありません。

デモのCSSのうち、コンポーネント（`stack-demo`）が書いているのは、文字の大きさと色、カードの枠、リンクの寄せ方だけで、縦の間隔はすべて `stack` と `style` 属性で決まっています。リンクの `margin-block-start: auto` は位置を決める指定で、間隔の大きさを決める `margin` ではありません。

## stackを使う場面とproseとの使い分け

`stack` が向いているのは、部品としてHTMLの構成が決まっていて、間隔をすべて同じにしてよい場面です。並ぶ要素の種類がそろっている必要はありません。カードの中の要素、フォームの項目、お知らせの一覧、セクションの中の見出しと本文と一覧の並びが、これに当たります。CMSの入力によって子の数が変わっても、`gap` は存在する子の間にだけ空くので、間隔の指定を変える必要がありません。

縦に積む方法の使い分けは、11-1の「[縦に積む方法を間隔の決まり方で選ぶ](/layout-practice/choosing/#縦に積む方法を間隔の決まり方で選ぶ)」の表にまとめています。`stack` を選ぶのは、その表で間隔がすべての間で同じになる場合です。`stack` の子はフレックスアイテムなので、`float` は無視され、`margin` は相殺されずに `gap` へ足されます。また、`gap` は親に指定するので、見出しの前だけ間隔を広げるといった子ごとの指定はできません。見出しや段落が続く本文を自分でHTMLに書くなら、通常フローのまま子ごとに間隔を渡せる「[12-2 prose](/compositions/prose/)」を使います。

CMSで編集者が入力する本文エリアの中には、どちらも使いません。本文エリアには種類の違う要素が続くので、間隔が一律の `stack` は向きません。`prose` を使わないのは、本書では本文エリアの要素ごとの余白を `.wysiwyg` に集めるからです。

本文エリアの中の余白は、「[19-5 CMSのWYSIWYG本文にスタイルを当てる](/operations/wysiwyg/)」の `.wysiwyg` で、要素の種類ごとに決めます。本文エリアと、その前後にあるタイトルや関連リンクなどを並べる外側には、`prose` を使えます。

横に並べたいなら、`stack` に `flex-direction: row` を上書きせず、別のコンポジションを使います。折り返すなら「[cluster](/compositions/cluster/)」を、両端に分けるなら「[apart](/compositions/apart/)」を選びます。幅に応じて縦積みと横並びを切り替えたいときも、`stack` にクエリを足すのではなく、幅が閾値を下回ると1列に切り替わる「[switcher](/compositions/switcher/)」を使います。

## 間隔を子ごとに変えたいとき

`stack` の中で一部の間隔だけを変えたくなったら、まず、その違いが要素のまとまりの違いを表しているかを確かめます。デモのカードのように「番号と見出しは近く、そのまとまりと説明文は離す」という違いなら、近い要素を `stack` で包んで入れ子にします。HTMLの構造と見た目のまとまりが一致し、どの間隔もいずれかの `stack` の `gap` で決まります。

子に `margin` を足して調整する方法は採りません。フレックスアイテムの `margin` は相殺されないので、16pxの `stack` で見出しに `margin-block-end: 8px` を付けると、見出しの下は24pxになります。

```css title="🙅‍♂ Not Recommended: stack の子に margin を足して、一部の間隔を広げる" issue="convention"
/* 🙅‍♂ Not Recommended */
._card-title {
  margin-block-end: 8px;
}
```

この指定では、間隔が `gap` と子の `margin` の和で決まるので、値を読み取るのに2か所を見なければなりません。`--stack--gap` を変えると、見出しの下だけ増分が固定のまま残り、ほかの間隔との比率が崩れます。子が別のコンポーネントのルートなら、ルートに `margin` を書くこと自体が10-2のルール「[ルートに外部関連型のレイアウトを指定しない](/components/boundaries/#rule-no-external-layout-on-root)」に反します。

まとまりでは説明できず、間ごとに大きさの違う余白がデザインで決まっているときは、`stack` をやめて、`grid-template` の空のセルで余白を作ります。「見出しの下は24px、本文の下は16px」のような指定を、テンプレートの行の高さとして1か所に書けます。書き方は11-2のルール「[間ごとに違う余白は空のセルで作る](/layout-practice/spacing/#rule-empty-grid-cells-for-spacing)」と、その節の例を見てください。

子の有無が入力によって変わるときや、見出しの直後だけ詰めるように前後の要素の種類で間隔が変わるときは、`stack` をやめて通常フローに戻し、`prose` か、次兄弟結合子で選んだ子の `margin-block-start` で間隔を作ります。空のセルでは要素が欠けたときに前後の余白の行だけが残りますが、`* + *` の `margin` なら残った子の間にだけ間隔が空きます。

## 入れ子のstackと公開プロパティの継承

`stack` を入れ子にするときは、内側の `stack` にも `--stack--gap` を渡します。カスタムプロパティは子孫に継承されるので、内側の `stack` に値を渡さないと、デフォルト値の `0` ではなく、外側の `stack` に渡した値が使われます。

```html title="🙅‍♂ Not Recommended: 内側の stack に値を渡さない" issue="behavior"
<!-- 🙅‍♂ Not Recommended -->
<div class="stack" style="--stack--gap: calc(var(--spacing--lg) * 1px)">
  <div class="stack">
    <p>…</p>
    <h3>…</h3>
  </div>
  <p>…</p>
</div>
```

この例では、内側の `stack` も32pxの間隔で積まれます。番号と見出しを隙間なく並べたいつもりで値を省くと、意図しない間隔が付きます。隙間を空けないときも、`style="--stack--gap: 0"` と明示します。

継承は、コンポーネントのCSSで値を渡したときにも起きます。セクションのルートに `--stack--gap` を指定すると、その中のすべての `stack` に同じ値が届きます。値は、その値を使う `stack` の要素そのものに渡します。

`@property` で `inherits: false` を登録すれば継承は止まります。ただ、本書は `@property` を型の指定やアニメーションが必要なときに限って使うので（「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/#rule-at-property-only-when-needed)」）、`stack` では登録しません。

## 子がフレックスアイテムになることの影響

`stack` の直下の子は、すべてフレックスアイテムになります。交差軸（横書きでは横方向）の配置を決める `align-items` のデフォルト値 `normal` は、フレックスアイテムでは `stretch` と同じに振る舞うので、子は `stack` の幅いっぱいに広がります。そのため、ボタンやリンクのように中身の幅で見せたい要素まで横に伸びます。

中身の幅に戻したい子には、`align-self: start` を指定します。指定するのは、その子を置いている側のCSSです。子が別のコンポーネントのルートなら、そのルートは置く側のスコープの外にあるので、置く側のCSSからは選べません。置く側のコンポーネントが、子のコンポーネントを `._button-outer` のようなOuterの要素で包み、Outerに `align-self: start` を指定します。Outerの考え方は「[10-2 コンポーネントの境界を守る](/components/boundaries/)」で説明しています。

直下の子が `a` や `span` のようなインライン要素でも、フレックスアイテムになるとブロックレベルの箱として扱われます（ブロック化）。`stack` の中に直接書いたテキストは、無名のフレックスアイテムに包まれ、ほかの子と同じ間隔で積まれます。リンクを文中に置きたいなら、`p` などで包んでから `stack` の子にします。

`margin-block-start: auto` で末尾に寄せられるのは、`stack` の高さに余りがあるときだけです。デモのカードはグリッドの行の高さまで引き伸ばされているので余りがありますが、高さが中身で決まる `stack` では、`auto` の `margin` は0になり、リンクは説明文から `gap` の分だけ離れた位置に置かれます。横方向に同じ使い方をするときのルールは、11-1の「[一部の要素を行末側へ寄せるときは auto の margin を使う](/layout-practice/choosing/#rule-flex-auto-margin-for-end-items)」にあります。

子の並び順を見た目だけ逆にする `flex-direction: column-reverse` は使いません。読み上げとキーボードのフォーカスはHTMLの順に進むので、見た目の順番と食い違います。見た目の順番を変えたいときの考え方は、7-8のルール「[HTML は文書構造の順番で書く](/layout/grid-basics/#rule-source-order-for-reading)」にあります。
