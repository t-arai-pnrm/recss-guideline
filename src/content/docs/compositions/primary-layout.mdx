`primary-layout` は、ページやセクションの左右にガター（画面の端の余白）の列を置き、その内側にコンテンツの列を作るコンポジションです。列の境界の線には `--full-start` や `--narrow-end` のような名前を付け、フル、超ワイド、ワイド、コンテンツ、ナローの5段階の幅を用意しています。子はデフォルトでコンテンツ幅に置かれ、`full-column` や `wide-column` のクラスを付けた子だけが、その幅に広がったり縮んだりします。

画面が狭いときはフル以外の4段階の幅が同じになり、画面が広がるにつれて段階の差が開きます。この変化は列の幅の計算だけで起きるので、`primary-layout` にも子の側にもブレイクポイントを書きません。ガターなどの値は、1組の公開プロパティで受け取ります。

## 幅の違う要素が混在するページの組み方

記事のページを考えます。本文はコンテンツ幅に収め、引用は少し狭く、図版は少し広く、メインビジュアルは画面の端まで広げたいとします。こうした「幅の違う要素が縦に並ぶ」構成は、コーポレートサイトの下層ページやメディアの記事でよく見かけます。

これを要素ごとの最大幅と `margin-inline: auto` で組むと、次のようになりがちです。

```css title="🙅‍♂ Not Recommended: 幅ごとに最大幅と余白を書き、フル幅は vw で広げる" issue="behavior"
/* 🙅‍♂ Not Recommended */
._body {
  max-inline-size: calc(1140 / 16 * 1rem);
  margin-inline: auto;
  padding-inline: 20px;
}

._figure {
  max-inline-size: calc(1380 / 16 * 1rem);
  margin-inline: auto;
  padding-inline: 20px;
}

._hero {
  margin-inline: calc(50% - 50vw);
}
```

この書き方には3つの問題があります。1つ目は、ガターの `padding-inline` が要素ごとに書かれるので、画面幅でガターを変えるときにすべての箇所を直す必要があることです。2つ目は、`box-sizing: border-box` の環境では最大幅から `padding` の分だけ中身が狭くなり、「最大幅にガターを足す」という計算が要素ごとに入り込むことです。3つ目は、`vw` がスクロールバーの幅を含むので、フル幅の要素が横スクロールの原因になることです。

左右に余白の列を持つグリッドでこれらを解決する方法は「[11-2 余白を設計する](/layout-practice/spacing/)」で、`grid-column: --full` で画面の端まで広げる方法は「[11-6 重なりと全幅](/layout-practice/layering/)」で説明しています。`primary-layout` は、11-2の形を5段階の幅に広げて部品にしたものです。

## 線名で5段階の幅を表すグリッド

`primary-layout` は、列が9本のグリッドです。両端の2本がガターの列、中央の1本がナロー幅の列で、その間の6本が段階の差を作る列です。各列の境界の線に名前を付け、子は線の名前で置き場所を選びます。

```css title="🙆‍♂ Recommended: 線に名前を付けた9本の列で、5段階の幅を作る"
/**
 * 左右のガターと5段階の幅の列を持つグリッド。子はデフォルトでコンテンツ幅に置き、クラスで幅を選ぶ。
 *
 * @prop {length} --primary-layout--content-max-width [calc(1680 / 16 * 1rem)] - コンテンツ幅の最大値
 * @prop {length} --primary-layout--gutter            [20px]                   - 左右のガターの最小幅
 * @prop {length} --primary-layout--narrow-reduction  [20px]                   - ナロー幅とコンテンツ幅の片側の差（上限）
 * @prop {length} --primary-layout--wide-increase     [60px]                   - コンテンツ幅とワイド幅の片側の差（上限）
 * @prop {length} --primary-layout--ex-wide-increase  [40px]                   - ワイド幅と超ワイド幅の片側の差（上限）
 * @prop {length} --primary-layout--row-gap           [0px]                    - 行の間隔
 */
.primary-layout {
  --_c--content-max-width: var(--primary-layout--content-max-width, calc(1680 / 16 * 1rem));
  --_c--gutter: var(--primary-layout--gutter, 20px);
  --_c--narrow-reduction: var(--primary-layout--narrow-reduction, 20px);
  --_c--wide-increase: var(--primary-layout--wide-increase, 60px);
  --_c--ex-wide-increase: var(--primary-layout--ex-wide-increase, 40px);
  --_c--row-gap: var(--primary-layout--row-gap, 0px);

  display: block grid;
  grid-template-columns:
    [--full-start]
    minmax(var(--_c--gutter), 1fr)
    [--ex-wide-start]
    minmax(0, var(--_c--ex-wide-increase))
    [--wide-start]
    minmax(0, var(--_c--wide-increase))
    [--content-start]
    minmax(0, var(--_c--narrow-reduction))
    [--narrow-start]
    min(100% - var(--_c--gutter) * 2, var(--_c--content-max-width) - var(--_c--narrow-reduction) * 2)
    [--narrow-end]
    minmax(0, var(--_c--narrow-reduction))
    [--content-end]
    minmax(0, var(--_c--wide-increase))
    [--wide-end]
    minmax(0, var(--_c--ex-wide-increase))
    [--ex-wide-end]
    minmax(var(--_c--gutter), 1fr)
    [--full-end];
  row-gap: var(--_c--row-gap);

  & > * {
    grid-column: --content;
  }

  & > .full-column {
    grid-column: --full;
  }

  /* ... */
}
```

5段階の幅と線の名前の対応は、次の表のとおりです。幅の段階は外側から入れ子になっていて、外側の段階ほど、内側の段階の両側に列を1本ずつ足した幅になります。

| 幅 | 始まりの線 | 終わりの線 | 両側に含む列 |
|---|---|---|---|
| フル（`--full`） | `--full-start` | `--full-end` | ガターまですべて |
| 超ワイド（`--ex-wide`） | `--ex-wide-start` | `--ex-wide-end` | 超ワイドの差、ワイドの差、ナローの差 |
| ワイド（`--wide`） | `--wide-start` | `--wide-end` | ワイドの差、ナローの差 |
| コンテンツ（`--content`） | `--content-start` | `--content-end` | ナローの差 |
| ナロー（`--narrow`） | `--narrow-start` | `--narrow-end` | なし（中央の列だけ） |

子の側では、`grid-column: --full` のように、`-start` と `-end` を外した名前だけを書きます。グリッドでは、`--full-start` と `--full-end` のように「名前-start」と「名前-end」の組になった線があると、その名前の暗黙の領域ができるからです。`grid-column: --full` は、`grid-column: --full-start / --full-end` と同じ意味になります。

線の名前を `--` で始めるのは、`@keyframes` やコンテナの名前と同じく、自分で付けて値として使う名前だからです。CSSのキーワードは `--` で始まらないので、将来キーワードが増えても衝突せず、読む側も自分で付けた名前だと分かります（「[9-1 命名規則](/notation/naming/)」）。

## 列の幅の計算

両端のガターの列は `minmax(var(--_c--gutter), 1fr)` です。最小値がガターの幅なので、画面がどれだけ狭くても、左右にガターの分の余白が残ります。最大値の `1fr` は、ほかの列が広がりきったあとに余った幅を、左右のガターで等分するという意味です。

中央の列は `min(100% - ガター * 2, 最大幅 - ナローの差 * 2)` です。`100%` はグリッドの幅なので、前半は「グリッドの幅から左右のガターを引いた幅」になります。後半はコンテンツ幅の最大値から、ナローの差を両側の分だけ引いた幅です。2つの小さいほうを使うので、狭い画面では中央の列がガターの内側いっぱいに広がり、広い画面では最大幅に達した時点で止まります。

段階の差を作る6本の列は、すべて `minmax(0, 上限)` です。グリッドは、固定の幅の列とガターの最小値を確保したあと、残った幅をこれらの列へ均等に配ります。上限に達した列はそれ以上広がらず、残りはまだ広がれる列に配られます。6本がすべて上限に達しても幅が余れば、その分は `1fr` のガターが受け取ります。

デフォルト値（最大幅1680px相当、ガター20px、ナローの差20px、ワイドの差60px、超ワイドの差40px）で検算します。グリッドの幅が1920pxのとき、中央の列は `min(1920 - 40, 1680 - 40)` で1640pxです。残りは1920 − 1640 − 40（ガター2本の最小値）で240pxです。6本の列で均等に分けると40pxずつですが、ナローの差の列は20pxが上限です。余った40pxを残りの4本で分けると50pxずつですが、超ワイドの差の列は40pxが上限です。最後の20pxを受け取ったワイドの差の列も、ちょうど60pxの上限に達します。

| グリッドの幅 | ナロー | コンテンツ | ワイド | 超ワイド | フル |
|---|---|---|---|---|---|
| 1280px | 1240px | 1240px | 1240px | 1240px | 1280px |
| 1760px | 1640px | 1666.7px | 1693.3px | 1720px | 1760px |
| 1920px | 1640px | 1680px | 1800px | 1880px | 1920px |
| 2400px | 1640px | 1680px | 1800px | 1880px | 2400px |

1920pxでは、コンテンツ幅が1640 + 20 × 2で、指定した最大幅の1680pxちょうどになります。この幅で6本の列がすべて上限に達するので、2400pxでもナローからフル以外の幅は変わりません。3つの差の合計は両側で240pxなので、2400pxでは残りの720pxのうち480pxが左右のガターに240pxずつ加わり、ガターは260pxになります。表の値は、デモのCSSで各列の幅を測った値とも一致しました。

1280pxの行では、中央の列がガターの内側いっぱいに広がり、6本の列に配る幅が残らないので、フル以外がすべて1240px（1280 − 20 × 2）です。1760pxの行のように中央の列が最大幅に達した直後は、6本の列が同じ幅ずつ広がるので、コンテンツ幅はまだ最大幅に届きません。段階の差がデザインどおりの値になるのは、画面が十分に広いときだけです。

中央の列の最大幅で、ナローの差を2倍して引いている点に注意してください。コンテンツ幅は中央の列の両側にナローの差の列を1本ずつ足した幅なので、片側の分しか引かないと、コンテンツ幅は最大幅よりナローの差の分だけ広くなります。上の条件では、グリッドの幅が2400pxのときにコンテンツ幅が1700pxになり、指定した1680pxを超えます。

## 公開プロパティ

公開プロパティは次のとおりです。どの値も1組だけで、画面の幅による切り替えは持ちません。

| 公開プロパティ | 意味 | デフォルト値 |
|---|---|---|
| `--primary-layout--content-max-width` | コンテンツ幅の最大値 | `calc(1680 / 16 * 1rem)` |
| `--primary-layout--gutter` | 左右のガターの最小幅 | 20px |
| `--primary-layout--narrow-reduction` | ナロー幅とコンテンツ幅の片側の差の上限 | 20px |
| `--primary-layout--wide-increase` | コンテンツ幅とワイド幅の片側の差の上限 | 60px |
| `--primary-layout--ex-wide-increase` | ワイド幅と超ワイド幅の片側の差の上限 | 40px |
| `--primary-layout--row-gap` | 行の間隔 | `0px` |

行の間隔は、ほかのコンポジションと同じく、置く文脈で決まる値なのでデフォルト値を0にしています。

`primary-layout` の中に、メディアクエリやスタイルクエリで値を切り替える分岐は書きません。画面が広がるにつれて段階の差が開くのは列の幅の計算の結果なので、多くのページはデフォルト値のままで足ります。分岐を部品の中に持つと、部品を使うたびにブレイクポイントの値と切り替えの仕組みを持ち込むことになり、置く場所を選ぶ部品になるからです。

値を変えるときは、ほかのコンポジションと同じく `style` 属性で渡します。次の例では、コンテンツ幅の最大値を960px相当にし、行の間隔をトークンで指定しています。

```html
<div
  class="primary-layout"
  style="--primary-layout--content-max-width: calc(960 / 16 * 1rem); --primary-layout--row-gap: calc(var(--spacing--md) * 1px)"
>
  <!-- ... -->
</div>
```

画面の幅に応じてガターを広げたいときは、利用する側が公開プロパティに渡す値を工夫します。たとえば、ガターに `max(calc(20 / 16 * 1rem), 5%)` のような値を渡せば、`%` がグリッドの幅を基準にするので、画面が広いほどガターも広がります。ブレイクポイントで値を切り替える必要がある案件でも、切り替えは `primary-layout` を使う側のコンポーネントのCSSに書き、`primary-layout` 自身には書きません。{/* 要確認: 出典なし */}

## 子のクラスで幅を選ぶ

子の幅は、子に付けるクラスで選びます。クラスは、5段階のうちコンテンツ以外の4つの幅ごとに3種類ずつ、合わせて12個あります。何も付けない子は、`& > *` によってコンテンツ幅に置かれます。

| クラス | 置かれる範囲 |
|---|---|
| `full-column` | フル幅の両側 |
| `full-column-start-only` | 開始側だけフル幅、終了側はコンテンツ幅 |
| `full-column-end-only` | 開始側はコンテンツ幅、終了側だけフル幅 |
| `ex-wide-column`（`-start-only`、`-end-only`） | 超ワイド幅（同上） |
| `wide-column`（`-start-only`、`-end-only`） | ワイド幅（同上） |
| `narrow-column`（`-start-only`、`-end-only`） | ナロー幅（同上） |

`-start-only` と `-end-only` は、片側だけを広げたり縮めたりするクラスです。たとえば `wide-column-start-only` は `grid-column: --wide-start / --content-end` で、開始側はワイド幅の線まで広がり、終了側はコンテンツ幅の線にそろいます。横書きでは開始側が左なので、画像を左にはみ出させ、右端は本文とそろえるといったレイアウトに使えます。線の名前はインライン方向の始まりと終わりを指すので、右から左へ書く言語では左右が入れ替わります。

これらのクラスには接頭辞を付けません。本書の命名では、`_` はコンポーネントの `@scope` の中だけで意味を持つ子要素の印、`-` はどこに付けても同じ意味を持つユーティリティの印です。`full-column` はどちらでもなく、`primary-layout` の直下の子のときだけ意味を持つ、コンポジションの一部です。セレクタを `& > .full-column` のように直下の子に限っているので、`primary-layout` の外でこのクラスを付けても何も起きません。そこで、コンポジションと同じく接頭辞のない名前にし、名前の末尾の `-column` で列の選択だと分かるようにしています。

コンポーネントのCSSで、子の置き場所を `grid-column: --wide` と線の名前で直接書いてもかまいません。線の名前もクラスと同じく、`primary-layout` が外に公開している名前だからです。{/* 要確認: 出典なし */}

幅が1280pxのときは、中央の列が `min(1280 - 40, 640 - 40)` で600pxになり、残った640pxで6本の列がすべて上限に達します。ナローは600px、コンテンツは640px、ワイドは760px、超ワイドは840pxです。

実際のコンポーネントでは、ページの記事部分のルートに `primary-layout` を付けます。コンポーネントのCSSが受け持つのは、見出しの文字サイズや画像の縦横比のような見た目だけです。幅と左右の余白は `primary-layout` とクラスで決まり、子の間隔は行の間隔で作ります。

```html
<article
  class="scoped article-page | primary-layout"
  style="--primary-layout--row-gap: calc(var(--spacing--md) * 1px)"
>
  <h1>記事のタイトル</h1>
  <figure class="_hero | full-column">...</figure>
  <div class="_body | prose">...</div>
  <blockquote class="narrow-column">...</blockquote>
  <figure class="_figure | wide-column-start-only">...</figure>
</article>
```

このHTMLは、クラスを見るだけで各要素の幅が分かります。`primary-layout` の行の間隔はタイトルや図版のようなブロックの間の余白で、本文の段落の間隔は `_body` に付けた `prose` が受け持ちます（「[12-2 prose](/compositions/prose/)」）。

## 補足と注意点

`primary-layout` は、ページやセクションのように、画面の幅を基準に左右の余白と最大幅を決めたい場所で使います。カードの中やサイドバーの中のように、置かれた場所の幅に合わせて列を組む配置には使いません。そうした配置には、列の数を幅から決める「[12-7 grid](/compositions/grid/)」や、メインとサイドの2カラムにする「[12-6 sidebar](/compositions/sidebar/)」が向いています。

`100%` はグリッド自身の幅を指すので、フル幅はビューポートの幅ではなく、`primary-layout` を付けた要素の幅です。サイドバーのあるページのメインエリアに置けば、フル幅はメインエリアの端までになります。画面の端まで広げたいなら、`primary-layout` を画面の幅いっぱいの要素に付けます。

`primary-layout` を入れ子にするときは、内側の `primary-layout` を外側の `full-column` に置きます。コンテンツ幅の列に置くと、内側でもう一度ガターが確保され、左右の余白が二重になるからです。セクションごとに背景色を変えたいときは、セクションのルートを `full-column` にし、そのセクション自身にも `primary-layout` を付けます。{/* 要確認: 出典なし */}

片側だけのクラスや幅の段階は、見た目の位置を変えるだけで、HTMLの順番は変えません。スクリーンリーダーの読み上げ順やキーボードの移動順はHTMLの順番に従うので、子は読む順番どおりに書きます。`grid-row` などで見た目の順番を入れ替えるのは避けます。
