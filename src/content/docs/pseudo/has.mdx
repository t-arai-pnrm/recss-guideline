`:has()` は、引数のセレクタに当てはまる子孫や後ろの兄弟を持つ要素を選ぶ擬似クラスです。子の有無や状態によって祖先のスタイルを変える処理を、JavaScriptでクラスを付けずに書けます。本書では、`:has()` の直前に必ず起点のセレクタを書き、起点のない `:has()` は禁止します。

起点は、コンポーネントのルートのような狭い要素にします。引数は、`>` や `+` の結合子で探す範囲を絞ります。祖先のスタイルが子孫によって決まるので、DOMが変わるたびに、ブラウザは起点の要素が条件を満たすかを調べ直すからです。この節では、`:has()` の仕組み、使いどころ、範囲の絞り方を順に説明します。

## 祖先や前の兄弟を選べなかった問題

CSSのセレクタは、長いあいだ、祖先から子孫へ、前の兄弟から後ろの兄弟へという一方向にしか要素を選べませんでした。`.card img` はカードの中の画像を選べますが、「画像を持つカード」は選べません。`h2 + p` は見出しの直後の段落を選べますが、「段落が直後に続く見出し」は選べません。

そのため、子の有無や状態によって親の見た目を変えたいときは、JavaScriptで親にクラスを付けていました。画像を持つカードに `has-image` を付ける、チェックされたラジオボタンを含むラベルに `is-checked` を付ける、といった処理です。

この方法では、クラスと実際の状態がずれかねません。キーボードでラジオボタンの選択を変えたときや、CMSの編集で画像を消したときに、クラスを付け外す処理を書き漏らすと、見た目と中身が食い違います。状態を表す情報が、HTMLの状態とクラスの2か所に分かれているからです。

```css title="🙅‍♂ Not Recommended: JavaScriptで付け外すクラスで、親の見た目を変える" issue="convention"
/* 🙅‍♂ Not Recommended */
.plan-option.is-checked {
  /* ラジオボタンの選択が変わるたびに、スクリプトで is-checked を付け外す */
  border-color: var(--border--strong);
}

.card.has-image {
  /* 画像を消したときに has-image を外し忘れると、空の列が残る */
  grid-template-columns: calc(160 / 16 * 1rem) 1fr;
}
```

`:has()` を使うと、状態をHTMLの状態だけで表せます。ラジオボタンがチェックされているかどうかは `:checked` が、画像があるかどうかは要素そのものが表しているので、それを親から直接参照します。クラスを付け外す処理がなくなるので、ずれる原因もなくなります。

## `:has()` の仕組み

`:has()` の引数は、起点の要素から見た相対的なセレクタです。結合子を書かなければ子孫を探し、`>` なら直接の子、`+` なら直後の兄弟、`~` なら後ろのすべての兄弟を探します。`.card:has(img)` は「`img` を子孫に持つ `.card`」、`.card:has(> img)` は「`img` を直接の子に持つ `.card`」、`h2:has(+ p)` は「直後に `p` が続く `h2`」を選びます。

<Figure src="pseudo/has-scope" alt=":has()の引数ごとに、起点の要素から見てどの要素が探索範囲に入るかを示した表。左は、起点の.cardを中心にしたHTMLの木で、上から、前の兄弟のh2、起点の.card、その子のimgとdiv、divの子のspan（.cardから見て孫）、直後の兄弟のp、その後ろの兄弟のpが並ぶ。右の4列は引数の書き方で、結合子を書かない場合は子孫、> は直接の子、+ は直後の兄弟、~ は後ろのすべての兄弟を探索する。子孫の列では、img、div、spanが探索範囲に入る。> の列では、直接の子のimgとdivだけが入る。+ の列では、直後の兄弟のpだけが入る。~ の列では、直後の兄弟のpと、その後ろの兄弟のpが入る。前の兄弟のh2は、どの列でも探索範囲に入らない。スタイルが当たるのは、探索される要素ではなく、起点の.cardである。" />

スタイルが当たるのは、起点の要素です。`.card:has(> img)` のスタイルは `.card` に当たり、`img` には当たりません。引数は条件を表すだけで、選ぶ対象を変えないので、「`:has()` の前に書いたものが選ばれる」と読みます。

次のデモでは、同じ3枚のカードに、左は `&:has(img)`、右は `&:has(> img)` で枠線と背景色を付けています。色が付くのはどちらもカードで、`img` ではありません。`figure` で包んだ画像は孫にあたるので、左のカードには当たり、右のカードには当たりません。

<Demo title="結合子の有無で、画像を探す範囲が変わる" html={hasCombinatorHtml} css={hasCombinatorCss} variant="neutral" widths={[]} />

詳細度は、`:is()` と同じく、引数でいちばん高いセレクタの詳細度になります。`.card:has(> img)` は、`.card` の0.1.0に `img` の0.0.1が加わり、0.1.1です。詳細度の数え方は「[4-1 カスケード・詳細度・継承](/cascade/cascade-basics/)」で、`:is()` との共通点は「[4-2 セレクタで詳細度を設計する](/cascade/selectors/)」で説明しています。

引数の解釈には、`:is()` や `:where()` と違う点があります。`:has()` の引数は、解釈できないセレクタが1つでもあると全体が無効になります。初期の仕様では無視される扱いでしたが、2022年末に変わりました。対応が分かれるセレクタを引数に入れるときは、`:has(:is(:heading, h2))` のように `:is()` で包むと、解釈できないものだけが無視されます。また、引数の中に `:has()` を入れ子にすることと、`::before` のような擬似要素を書くことは、仕様で認められていません。

## 子の有無と状態で祖先を変える

もっともよく使うのは、子の有無によってレイアウトを変える場面です。次の例のカードは、直接の子に画像があるときだけ2列になります。CMSで画像が登録されなかった記事でも、HTMLのクラスを変えずに1列の表示になります。

```css title="🙆‍♂ Recommended: 子の有無でレイアウトを切り替える"
@scope (.scoped.media-object) to (.scoped) {
  :scope {
    display: block grid;

    &:has(> img) {
      grid-template-columns: calc(160 / 16 * 1rem) 1fr;
    }
  }
}
```

`:has()` が調べるのは、DOMの構造です。表示されているかどうかは調べないので、`hidden` 属性や `display: none` で隠した子孫にも当てはまります。`&:has(> img)` を「表示されている画像があるとき」の意味で書くと、スクリプトで画像に `hidden` を付けて隠しても、カードは2列のままになり、空の列が残ります。Chromeで確かめたところ、`hidden` を付けた子孫を持つ要素にも `:has()` が当てはまりました。

隠すことがある子を条件にするときは、隠した状態を属性で表し、その属性を `:has()` の条件に含めます。`hidden` で隠すなら、`:not([hidden])` を足して、隠していない子だけを数えます。CSSの `display: none` で隠している場合は、隠す条件をクラスや属性で表しておけば、隠すルールと `:has()` の条件の両方から同じ属性を参照できます。状態を属性で表す書き方は、第17章「[17-3 状態を属性で表す](/interaction/state-attributes/)」で説明しています。

```css title="🙆‍♂ Recommended: 隠していない画像があるときだけ2列にする"
@scope (.scoped.media-object) to (.scoped) {
  :scope {
    display: block grid;

    &:has(> img:not([hidden])) {
      grid-template-columns: calc(160 / 16 * 1rem) 1fr;
    }
  }
}
```

フォーム部品の状態を親に伝える場面にも使えます。次のデモは、ラジオボタンを含むカードの一覧です。`&:has(> input:checked)` で、直下のラジオボタンがチェックされたカードだけ、枠線の色を変えています。背景の色は変えません。淡い青を重ねると、カードの中の灰色の価格の文字が、背景とのコントラスト比4.5:1に届かなくなるからです。ラジオボタンの選択はブラウザが管理するので、マウスで選んでも、矢印キーで選んでも、見た目が状態とずれません。

<Demo title="直下のラジオボタンがチェックされたカードだけ、選んだ見た目にする" html={planHtml} css={planCss} />

入力欄の検証の結果を、ラベルや説明文に伝えることもできます。入力欄を包む要素に `&:has(:user-invalid)` を書けば、入力して離れたあとで値が不正なときだけ、説明文の色を変えられます。`:user-invalid` が当てはまる条件と、フォーム部品の実装は第17章「[17-7 フォーム部品](/interaction/forms/)」で説明しています。

キーボードの操作にも応じられます。カードの中のリンクにキーボードでフォーカスしたとき、カード全体に枠線を付けたいなら、カードのルートに `&:has(:focus-visible)` を書きます。子のフォーカスで親の見た目を変える書き方は、第17章「[17-3 状態を属性で表す](/interaction/state-attributes/)」で説明しています。

## 後ろの兄弟によって前の要素を変える

`:has()` の引数に `+` や `~` を書くと、後ろに続く兄弟を条件にして、前の要素を選べます。従来のセレクタでは、後ろの要素の状態は前の要素から参照できませんでした。

次の例は、星の数で評価を入力する部品です。ラジオボタンを包む `label` を5つ並べ、選んだ星と、それより前の星を塗ります。選んだ星は `&:has(> input:checked)` で、前の星は「後ろの兄弟に、チェックされたラジオボタンを持つ `label` がある」という条件の `&:has(~ label > input:checked)` で選びます。

```css title="🙆‍♂ Recommended: 選んだ星と、それより前の星を塗る" from="pseudo/star-rating"
@scope (.scoped.star-rating) to (.scoped) {
  label {
    color: var(--foreground--muted);

    /* 選んだ星と、後ろの兄弟にチェックされたラジオボタンを持つ label（選んだ星より前の星） */
    &:has(> input:checked),
    &:has(~ label > input:checked) {
      color: var(--foreground--base);
    }
  }
}
```

次のデモでは、3つ目の星を選んだ状態から始まります。最初は1つ目から3つ目までの星が濃い色で、4つ目と5つ目は灰色です。ほかの星を選ぶと、その星と、それより前の星だけが濃い色に塗られます。

<Demo title="選んだ星と、それより前の星だけを塗る" html={starHtml} css={starCss} widths={[]} />

前の兄弟を選ぶセレクタは、読み手が意味を取り違えやすい書き方です。`&:has(~ label > input:checked)` の `~` は `label` から見た後ろの兄弟を、`>` はその兄弟の直接の子を指します。結合子が2つ続くときは、上の例のように条件を文章にしたコメントを添えると、あとから読む人が式を追わずに済みます（ルール `comments-why-only` の補足）。

## `:has()` と `:not()` を組み合わせる

「画像を持たないカード」を選びたいとき、`:has()` と `:not()` を入れ子にします。そのとき、入れ子の順序で意味が逆になります。次の3枚のカードで考えます。1枚目は画像と説明文を、2枚目は説明文だけを、3枚目は画像だけを持っています。

```html
<article class="card"><img src="…" alt="" width="…" height="…"><span>説明文</span></article>
<article class="card"><span>説明文</span></article>
<article class="card"><img src="…" alt="" width="…" height="…"></article>
```

`.card:has(:not(img))` は、「`img` 以外の子孫を1つでも持つカード」を選びます。1枚目と2枚目には、`img` 以外の要素（`span`）があるので、どちらも当てはまります。画像を持たないカードだけを選んだことにはなりません。一方、`.card:not(:has(img))` は、「`img` の子孫を持たないカード」を選ぶので、当てはまるのは2枚目だけです。

<Figure src="pseudo/has-not" alt="3枚のカードに、2つのセレクタが当たるかを示した表。カードは、1枚目が画像のimgと説明文のspan、2枚目が説明文のspanだけ、3枚目が画像のimgだけを持つ。上の行のセレクタは .card:has(:not(img)) で、img以外の子孫を持つカードに当たる。1枚目と2枚目に当たり、3枚目には当たらない。画像を持たないカードだけを選ぶ意図とは違う。下の行のセレクタは .card:not(:has(img)) で、imgの子孫を持たないカードに当たる。2枚目だけに当たり、1枚目と3枚目には当たらない。こちらが意図どおりで、画像を持たないカードは2枚目だけである。" />

```css title="🙅‍♂ Not Recommended: 「画像を持たない」のつもりで :has() の中に :not() を入れる" issue="behavior"
/* 🙅‍♂ Not Recommended */
.card:has(:not(img)) {
  /* 1枚目と2枚目に当てはまる */
  padding-inline: 24px;
}
```

```css title="🙆‍♂ Recommended: 「持たない」は :not() の中に :has() を入れる"
@scope (.scoped.card) to (.scoped) {
  :scope {
    &:not(:has(> img)) {
      padding-inline: 24px;
    }
  }
}
```

入れ子のセレクタは、省略された `*` を補い、部品に分けてから、内側から外へ読むと取り違えません。`.card:has(:not(img))` なら、まず `.card:has(*:not(img))` と補い、`*:not(img)`（`img` ではない任意の要素）、`:has(…)`（それを子孫に持つ）、`.card`（起点）の3つに分けます。内側の部品から順に意味をつなげると、`:has(:not(img))` は「`img` ではない要素を持つ」、`:not(:has(img))` は「`img` を持つ」の否定と読め、意味の違いが式の形に現れます。

2つのセレクタの詳細度は、どちらも0.1.1です。順序を入れ替えても、詳細度は変わらずに意味だけが変わるので、見た目の差から誤りに気づきにくくなります。なお、上の例の `:not(:has(> img))` は、`img` が直接の子でなければ、孫の位置にあっても当てはまります。画像が別の要素に包まれることがあるなら、`>` を付けず、子孫全体を探す形にします。

## 起点のない `:has()` を書かない

`:has()` の直前に何も書かないと、すべての要素が起点になります。`:has(.foo)` は `*:has(.foo)` と同じで、「`.foo` を子孫に持つ、ページのすべての要素」を選ぶ指定です。ブラウザは、DOMが変わるたびに、ページのすべての要素について条件を調べ直す可能性があります。

```css title="🙅‍♂ Not Recommended: 起点のない :has()" issue="behavior"
/* 🙅‍♂ Not Recommended */
:has(> .entry-link) {
  position: relative;
}

*:has(> img) {
  display: block grid;
}
```

この重さは、Chromeの開発者ツールのパフォーマンスパネルで、セレクタごとの照合の時間として測れます。起点に要素名を加えて `article:has(> .entry-link)` のように書けば、照合の対象は `article` だけになります。`.bar:has(*)` のように引数が何にでも当てはまる形も、範囲を限定していない書き方です。引数の絞り方は、最後の見出しで説明します。

ネストと `@scope` の中では、起点を書き忘れやすくなります。ネストしたルールの中で `&` を省いて `:has(> img)` と書くと、`& :has(> img)` と解釈され、親の子孫のすべての要素が起点になります。`@scope` の直下に書いた `:has()` も、スコープの中のすべての要素が起点です。本書の規約どおり、ネストしたセレクタを `&` で始めていれば、この誤りは起きません。

```css title="🙆‍♂ Recommended: & やスコープのルートを起点にする"
@scope (.scoped.entry-card) to (.scoped) {
  :scope {
    &:has(> a) {
      position: relative;
    }
  }
}
```

本書のStylelintの設定には、起点のない `:has()` を検出する独自ルール `book/no-unanchored-has` を入れています。起点として認めるのは、`*` 以外のタイプセレクタ、クラス、ID、属性、`&`、`:scope`、`:root`、`:host` です。`&:not(:has(> img))` のように擬似クラスの引数の中に書いた `:has()` は、外側の `:not()` の直前に起点があれば通ります。

## 起点と引数の範囲を絞る

起点があっても、それが広すぎれば同じ問題が起きます。次の例は、どちらもページ全体を起点にしています。ページのどこかで要素が追加されたり、属性が変わったりするたびに、`body` や `:root` の子孫全体から `img` や `[aria-invalid="true"]` を探し直す可能性があります。

```css title="🙅‍♂ Not Recommended: ページ全体を起点に、子孫を広く探す" issue="behavior"
/* 🙅‍♂ Not Recommended */
body {
  &:has(img) {
    /* ... */
  }
}

:root {
  &:has([aria-invalid="true"]) {
    /* ... */
  }
}
```

起点はコンポーネントのルートのような狭い要素にし、引数は `>` や `+` の結合子で範囲を絞ります。デモの選択肢のカードは、`&:has(> input:checked)` でカードの直下の子だけを調べていました。調べる範囲はカード1枚の中に収まるので、ページの大きさには左右されません。

例外は、モーダルを開いている間に背面のスクロールを止める `:root:has(:modal)` のように、ページ全体の状態を表すスタイルです。ほかの要素を起点にできないので、`:root` を起点にします。こうしたルールは数を少なく保ちます。{/* 要確認: 出典なし */}`:root:has(:modal)` の書き方は第8章「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」で説明しています。

重さが気になったときは、推測せずに測ります。Chromeの開発者ツールでは、パフォーマンスパネルの記録の設定（Capture settings）で「Enable CSS selector stats」を有効にすると、スタイルの再計算の内訳がセレクタごとに表示されます。かかった時間（Elapsed）の長いセレクタのうち、照合を試みた数（Match Attempts）に比べて一致した数（Match Count）の少ないものを見直します。
