擬似クラスと擬似要素は、どちらもHTMLのクラスや属性に書かれていない条件で選ぶセレクタですが、選ぶ対象が違います。擬似クラスは `:first-child` や `:checked` のように1つのコロンで書き、要素の状態や位置を条件に、要素そのものを選びます。擬似要素は `::first-line` や `::before` のように2つのコロンで書き、要素の一部や、CSSで生成した箱を選びます。本書では、擬似要素を `:before` のような1コロンの旧記法で書くことを禁止します。

ブラウザの対応が分かれる擬似クラスは、カンマで区切ったセレクタリストに並べず、`:is()` か `:where()` の引数に書きます。セレクタリストは、解釈できないセレクタが1つあるだけで、ルール全体が無効になるからです。この節では、擬似クラスと擬似要素の違い、擬似要素を書ける位置、詳細度、セレクタリストの解釈の違いを順に説明し、最後に見出しをまとめて選ぶ `:heading` の書き方を示します。

## 1コロンの擬似要素と擬似クラスが混ざる問題

古いCSSでは、`a:hover` と `a:before` が同じ書き方で並んでいることがあります。どちらも1コロンですが、`:hover` は擬似クラスで、`:before` は擬似要素です。CSS2では両方を1コロンで書いており、擬似要素を2コロンで書いて区別する記法は、CSS3のセレクタの仕様で導入されました。

ブラウザは、互換性のために `::before`、`::after`、`::first-line`、`::first-letter` の4つだけ、いまも1コロンの記法を受け付けます。そのため、1コロンで書いても表示は変わらず、古い記法が残り続けます。

1コロンの記法が残っていると、読み手はセレクタの形から対象を判断できません。`p:first-line` と `p:first-child` は名前が似ていますが、前者は段落の1行目を、後者は親の最初の子である段落を選びます。どちらが要素の一部を選ぶのかは、名前を覚えているかどうかでしか判断できなくなります。

1コロンの習慣は、あとから加わった擬似要素で誤りを生みます。旧記法が認められているのは上の4つだけなので、`li:marker` や `input:placeholder` は無効なセレクタになり、ルール全体が無視されます。すべての擬似要素を2コロンで書くと決めておけば、こうした誤りは起きません。本書のStylelintの設定では、`selector-pseudo-element-colon-notation` で1コロンの擬似要素を検出しています。

```css title="🙅‍♂ Not Recommended: 擬似要素を1コロンで書く" issue="behavior"
/* 🙅‍♂ Not Recommended */
a:hover,
a:before {
  /* :hover は擬似クラス、:before は擬似要素だが、形から見分けられない */
  color: var(--foreground--accent);
}

li:marker {
  /* 旧記法が認められていないので、ルール全体が無視される */
  color: var(--foreground--muted);
}
```

## 擬似クラスは要素を、擬似要素は要素の一部を選ぶ

擬似クラスが選ぶのは、DOMにある要素そのものです。条件には、兄弟の中の位置（`:first-child`）、フォーム部品の状態（`:checked`）、ユーザーの操作（`:hover`）、子孫の有無（`:has()`）などがあります。条件はHTMLのクラスとして書かれていませんが、当てはまったときにスタイルが当たるのは、クラスで選んだときと同じ要素の箱です。

擬似要素が選ぶのは、要素の一部か、CSSで生成した箱です。`::first-line` は段落の1行目を、`::placeholder` は入力欄のプレースホルダーを、`::marker` はリストの項目のマーカーを選びます。`::before` と `::after` は、要素の内容の前と後ろに、`content` プロパティで箱を生成します。どれもHTMLに要素として存在しないので、擬似要素の子を選ぶことはできません。

次のデモで、2つの違いを比べます。左は `p:first-of-type` で、親の中で最初の段落を選んでいます。右は `p::first-line` で、すべての段落の1行目を選んでいます。左は条件に当てはまる段落の箱全体に背景色が付き、右は2つの段落のどちらも、1行目だけに背景色が付きます。

<Demo title="擬似クラスは段落の箱全体に、擬似要素は段落の1行目だけに当たる" html={targetHtml} css={targetCss} />

デモの幅を変えると、右で背景色の付く範囲が変わります。`::first-line` の範囲は、HTMLではなく、描画したときの行の折り返しで決まるからです。左の背景色は、幅を変えても段落の箱全体に付いたままです。

この章のほかの節では、擬似クラスと擬似要素を、選ぶ条件の種類ごとに説明します。`::before` と `::after` の使いどころは「[5-8 生成コンテンツと装飾の擬似要素](/pseudo/generated-content/)」で説明します。`:hover` と `:focus-visible` による状態の表し方は、第17章「[17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)」で扱います。

## 擬似要素を書ける位置

擬似要素は、原則としてセレクタの最後に1つだけ書きます。擬似要素は要素の一部を指すので、その後ろに子孫を選ぶ結合子を続けることも、別の条件を付けることもできません。`p::first-line > *` や `p::before.note` は無効なセレクタです。例外は、仕様が擬似要素の連結を定めている組み合わせです。`display: list-item` にした `::before` のマーカーを選ぶ `li::before::marker` や、Shadow DOMの部品の擬似要素を選ぶ `::part(label)::before` があります。

元の要素の状態によって擬似要素のスタイルを変えるときは、擬似クラスを擬似要素の前に書きます。`a:hover::after` は「ホバーしているリンクの `::after`」を選びます。順序を逆にした `a::after:hover` は、`::after` そのものがホバーされているという意味になりますが、Chromeでは無効なセレクタとして扱われ、ルール全体が無視されます。

本書では、ホバーとフォーカスで擬似要素の見た目を変えるとき、状態と擬似要素を1つのセレクタにつなげず、元の要素の状態のセレクタでフラグのカスタムプロパティ `--_hocus` を立てます。擬似要素の側は、`@container style(--_hocus: --true)` でフラグを問い合わせて見た目を切り替えます。擬似要素の名前なしの `style()` は、元の要素を問い合わせるからです。次の例では、ホバーのフラグを、`href` のあるリンクに限って `@media (any-hover)` の中で立てています（第17章のルール `hover-operable-in-any-hover`）。

```css title="🙆‍♂ Recommended: 元の要素の状態でフラグを立て、擬似要素はスタイルクエリで受ける"
@scope (.scoped.external-link) to (.scoped) {
  :scope {
    --_hocus: --false;

    &:any-link:hover {
      @media (any-hover) {
        --_hocus: --true;
      }
    }

    &:focus-visible {
      --_hocus: --true;
    }

    &::after {
      content: "↗" / "";
      display: inline flow-root;

      @container style(--_hocus: --true) {
        translate: 2px -2px;
      }
    }
  }
}
```

矢印の代替テキストを空にしているのは、外部へのリンクであることを、リンクの文字か、`aria-describedby` で結んだ説明が伝えている前提だからです。矢印だけが手がかりなら、代替テキストに「外部サイト」のような名前を書きます。

リンクにデフォルト値の `--_hocus: --false` を明示しているのは、外側の要素で立てたフラグを継承しないためです。矢印は、ホバーとフォーカスで右上へ少し動かしています。`translate` は非置換のインライン要素では働かないので、`::after` を `display: inline flow-root` にしています。変化を `opacity` で表さないのは、透けて読みにくくなるうえに、意図がコードから読み取れないからです（第17章のルール `no-opacity-for-hover`）。状態のセレクタは元の要素に書くので、擬似クラスを擬似要素の後ろに書き間違えることもありません。フラグとスタイルクエリで状態を伝える書き方は、「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」で説明しています。

```css title="🙅‍♂ Not Recommended: 擬似要素の後ろに擬似クラスを書く" issue="behavior"
/* 🙅‍♂ Not Recommended */
.external-link::after:hover {
  translate: 2px -2px;
}
```

擬似要素の後ろに擬似クラスを続けられるかどうかは、擬似要素ごとに決まっています。たとえば、ページ内検索で一致した文字列を選ぶ `::search-text` には、いま選択中の一致を表す `:current` を続けられます。`::before`、`::after`、`::first-line`、`::marker` の後ろに `:hover` を書くと、Chromeではどれも無効になりました。擬似要素の後ろに擬似クラスを書くのは、その擬似要素の説明で認められているときに限ります。

## 擬似クラスと擬似要素の詳細度

擬似クラスの詳細度は、クラスや属性セレクタと同じ0.1.0です。擬似要素の詳細度は、タイプセレクタと同じ0.0.1です。`li::marker` は0.0.2、`._note::marker` は0.1.1になります。1コロンで書いた `:before` も擬似要素として数えるので、0.0.1です。

```css title="🙆‍♂ Recommended: 擬似要素はタイプセレクタ、擬似クラスはクラスと同じ重さで数える"
@scope (.scoped.notice-list) to (.scoped) {
  li {
    /* li::marker の詳細度は 0.0.2 */
    &::marker {
      color: var(--foreground--muted);
    }

    /* li:first-child の詳細度は 0.1.1 */
    &:first-child {
      font-weight: var(--font-weight--bold);
    }
  }

  ._note {
    /* ._note::marker の詳細度は 0.1.1 で、li::marker に勝つ */
    &::marker {
      color: var(--foreground--base);
    }
  }
}
```

擬似クラスの0.1.0は、`@scope` の中のタイプセレクタと組み合わせたときに影響します。`a:hover` の詳細度は0.1.1で、子クラス `._sub-link` の0.1.0より高くなります。共通の `a:hover` に書いた文字色が、子クラスで指定した文字色を上書きしてしまうので、役割ごとに違う状態のスタイルは `._sub-link:hover` のように子クラスの側に書きます。この書き分けは、第10章「[10-2 コンポーネントの境界を守る](/components/boundaries/)」で説明しています。

引数にセレクタを取る `:is()`、`:not()`、`:has()`、`:nth-child(… of S)`、`:where()` は、この0.1.0の決まりに従いません。引数で詳細度が決まり、`:where()` は常に0です。5つの決まり方は、第4章「[4-2 セレクタで詳細度を設計する](/cascade/selectors/)」の「イレギュラーな擬似クラスの詳細度」に表でまとめています。`:is()`、`:where()`、`:not()` の使い分けは「[5-2 :is()・:where()・:not()](/pseudo/is-where-not/)」で、詳細度の数え方そのものは「[4-1 カスケード・詳細度・継承](/cascade/cascade-basics/)」で説明しています。

## 未対応のセレクタ1つでルール全体が無効になる

カンマで区切ったセレクタリストは、解釈できないセレクタが1つでも含まれると、ルール全体が無効になります。無効になるのはそのセレクタだけではなく、同じリストに並べたほかのセレクタも、宣言ブロックの指定もすべてです。仕様が、セレクタリストを1つのまとまりとして解釈し、一部でも解釈できなければ全体を無効にすると定めているためです。

解釈できないセレクタには、書き間違いのほかに、ブラウザがまだ対応していない擬似クラスが含まれます。たとえば、見出しをまとめて選ぶ `:heading` に対応しているのは、Safari 27だけです。次の例は、Safari 27では見出しと `caption` の両方に当たりますが、対応していないChromeやFirefoxではルールごと無視され、`caption` にもスタイルが当たりません。Chromeでは、このルールがスタイルシートから取り除かれることを確かめました。

```css title="🙅‍♂ Not Recommended: 対応の分かれる擬似クラスを、セレクタリストに並べる" issue="behavior"
/* 🙅‍♂ Not Recommended */
:heading,
caption {
  font-kerning: normal;
}
```

この誤りは、開発に使うブラウザだけでは見つかりません。対応しているブラウザで確認すると期待どおりに表示されるので、対応していないブラウザで、関係のない `caption` まで崩れていることに気づきにくくなります。

`:is()` と `:where()` の引数は、「寛容なセレクタリスト」として解釈されます。解釈できないセレクタは、その1つだけが無視され、残りは有効なままです。Chromeで `:is(:heading, h2)` と書くと、`:heading` が除かれた `:is(h2)` として扱われました。対応の分かれる擬似クラスをほかのセレクタと並べるときは、このどちらかで包みます。詳細度を加えたくないなら `:where()` を、引数の詳細度を残したいなら `:is()` を選びます。

`:not()` と `:has()` の引数は、寛容なセレクタリストではありません。Chromeでは、`p:not(:heading, .note)` と `p:has(:heading, span)` のどちらも、ルール全体が無効になりました。これらの引数に対応の分かれる擬似クラスを書くときは、`:not(:is(:heading, h2))` のように、引数の中でさらに `:is()` で包みます。`:has()` の引数の扱いは、仕様の変更の経緯とあわせて「[5-3 :has() で祖先と前の兄弟を選ぶ](/pseudo/has/)」で説明しています。

擬似要素には、この方法が使えません。`:is()` と `:where()` の引数に擬似要素は書けないので、`:where(::before)` は何も選びません。対応の分かれる擬似要素は、ほかのセレクタとカンマで並べず、別のルールに分けて書きます。

## `:heading` で見出しをまとめて選ぶ

`:heading` は、`h1` から `h6` までの見出しをまとめて選ぶ擬似クラスです。見出しのスタイルを `h1, h2, h3, h4, h5, h6` と並べて書く代わりに使えます。

<Baseline id="heading-selectors" compatKey="css.selectors.heading" name=":heading" />

web-featuresのデータでは、`:heading` に対応しているのはSafari 27だけです。そのため、`:heading` を単独では使いません。従来のタイプセレクタと並べて、`:is()` の中に書きます。

```css title="🙆‍♂ Recommended: 従来のセレクタと並べて :is() の中に書く"
@layer base {
  :is(:heading, h1, h2, h3, h4, h5, h6, caption) {
    font-kerning: normal;
  }
}
```

このルールは、`:heading` に対応していないブラウザでも、`h1` から `h6` と `caption` に当たります。`:is()` の詳細度は引数のうち最も高いものになるので、この例ではタイプセレクタ1つ分（0.0.1）です。ベーススタイルは `base` レイヤーに置くので、コンポーネントのレイヤーに書いた指定は詳細度と関係なくこれに勝ち、`:where()` で詳細度を0にする必要はありません。`:where()` を選ぶのは、CMSのテーマと共存する場合のように `@layer` を使えず、どこからでも上書きされる前提のスタイルを書くときです。

対象のブラウザがすべて `:heading` に対応したら、`h1` から `h6` を消して `:is(:heading, caption)` と書けるようになります。それまでは、`h1` から `h6` を並べた形がフォールバックを兼ねます。見出しのレベルを引数で指定する関数形の `:heading()` は、web-featuresのデータで対応しているブラウザがまだないので使いません。
