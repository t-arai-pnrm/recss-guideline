数量クエリ（quantity queries）は、子要素の数に応じてスタイルを切り替える手法の総称です。専用の構文があるわけではなく、子要素の位置で選ぶ擬似クラスを組み合わせて「3つ以上ある」「最後の1つが奇数番目にある」といった条件を表します。書き方は、スタイルを変える対象で選びます。親や兄弟の見た目を変えるときは、`&:has(> :nth-child(3))` のように親を起点にした `:has()` で書きます。数えた子要素そのものの見た目を変えるときは、`& > :nth-child(2n + 1):nth-last-child(1)` のように子の側で `:nth-child()` と `:nth-last-child()` を組み合わせます。

数量クエリを使う場面は限ります。列数のようなレイアウトの切り替えは、まず `auto-fit` やコンテナサイズクエリで行います。数量クエリを使うのは、「1件だけなら中央に置く」「最終行の端数を中央に寄せる」「引用がなければ特集を全幅に広げる」のように、子要素の数や有無そのものが条件になるときだけです。数量クエリを使った配置の実例（最終行の端数の中央寄せと、区画の有無による配置の組み替え）は、Gridの基礎を学んだあとに、第11章「[11-5 件数で配置を組み替える](/layout-practice/quantity-layouts/)」で扱います。

## 件数によって見た目を変えたい場面

お知らせや関連記事の一覧は、CMSの登録状況によって件数が変わります。3件や6件のときに整って見えるカードの一覧も、1件だけになると、カードが行いっぱいに引き伸ばされたり、左端に1枚だけ残ったりします。件数が少ないときや、最終行が埋まらないときだけ並べ方を変えたい、という要望は珍しくないでしょう。

CSSのセレクタには、子要素の数を直接表す仕組みがありません。そのため、テンプレートの側で件数を数え、`is-single` や `has-3-items` のようなクラスを親に付けて出し分けることがよくありました。JavaScriptで描画する一覧なら、項目を追加したり削除したりするたびに、クラスを付け直す処理も必要です。

```css title="🙅‍♂ Not Recommended: テンプレートで数えた件数をクラスにして出し分ける" issue="convention"
/* 🙅‍♂ Not Recommended */
.pickup-list {
  &.is-single {
    grid-template-columns: minmax(0, calc(400 / 16 * 1rem));
    justify-content: center;
  }
}
```

この方法では、クラスと実際の件数は、ずれることがあります。項目を絞り込む機能を後から足したときに、クラスを更新する処理を書き漏らすと、見た目が件数と合わなくなります。件数という情報が、DOMの構造とクラスの2か所に分かれているからです。数量クエリを使えば、DOMの構造だけを条件にして、件数による切り替えをCSSの中で完結できます。

## 子の側で数える従来の書き方

数量クエリは、`:has()` が使えるようになる前から知られていました。代表的な記事は、A List Apartが2015年に掲載した「Quantity Queries for CSS」です（参考リンク）。子要素の位置で選ぶ擬似クラスだけで、条件を子の側から表します。

`:nth-child()` は前から、`:nth-last-child()` は後ろから数えるので、2つを組み合わせると、子の位置と全体の数を同時に条件にできます。`li:first-child:nth-last-child(3)` は、「先頭で、かつ後ろから3番目」、つまり兄弟がちょうど3つのときの最初の子です。`li:nth-child(odd):last-child` は、「奇数番目で最後」の子で、子の数が奇数のときの最後の子です。スタイルが当たるのは、数えた子そのものです。

この書き方には、親や兄弟を変えられないという限界があります。選ばれるのは数えた子なので、親の `grid-template-columns` や `justify-content` は切り替えられません。ほかの兄弟を変えるには、`li:nth-last-child(n + 3), li:nth-last-child(n + 3) ~ li` のように、`~` の結合子で後ろの兄弟を拾う組を作る必要があります。この組は、「後ろから数えて3番目以降があるなら、全体は3つ以上ある」という逆算をしなければ、意味が取れません。

```css title="🙅‍♂ Not Recommended: 兄弟の見た目を変えるのに、子の側で数える" issue="convention"
/* 🙅‍♂ Not Recommended */
li:nth-last-child(n + 3),
li:nth-last-child(n + 3) ~ li {
  /* 3つ以上あるときの、すべての li */
  inline-size: 30%;
}
```

## 親や兄弟を変えるなら `:has()` で数える

`:has()` を使うと、条件を親から直接書けます。`&:has(> :nth-child(3))` は「3番目の子を持つ親」、つまり子が3つ以上ある親です。スタイルが当たるのは親なので、親自身のレイアウトを変えられます。すべての子や見出しのような兄弟を変えたいときも、親でカスタムプロパティの値を切り替えれば、条件の判定は1か所で済みます。

```css title="親を起点にした数量クエリの4つの形（3つを例に）"
@scope (.scoped.item-list) to (.scoped) {
  :scope {
    /* ちょうど3つ */
    &:has(> :nth-child(3):last-child) {
      /* ... */
    }

    /* 3つ以上 */
    &:has(> :nth-child(3)) {
      /* ... */
    }

    /* 3つ以下（0個は含まない） */
    &:has(> :last-child:nth-child(-n + 3)) {
      /* ... */
    }

    /* 2〜4つ */
    &:has(> :nth-child(2)):not(:has(> :nth-child(5))) {
      /* ... */
    }
  }
}
```

「ちょうど3つ」は、3番目の子が最後の子でもある、という条件です。「3つ以上」は、3番目の子が存在する、という条件です。「3つ以下」は、最後の子が先頭から3番目以内にある、という条件で、子が0個のときは最後の子がないので当てはまりません。0個も含めたいときは、`&:not(:has(> :nth-child(4)))` と書きます。範囲の条件は、「N個以上」と「M＋1個以上ではない」を組み合わせます。`:not()` の中に `:has()` を入れる形は、「[5-3 :has() で祖先と前の兄弟を選ぶ](/pseudo/has/)」で説明した「持たない」の書き方と同じです。上の4つの式は、Chromeで、子が0〜6個の場合について当てはまり方を確認しました。

反対に、数えた子そのものを変えるときは、`:has()` を使わずに子の側で書きます。「子の数が奇数のときの最後の子」を `:has()` で書くと、`&:has(> :nth-child(odd):last-child) > :last-child` のように、親と子の2か所に同じ条件が現れます。`& > :nth-child(odd):last-child` なら、条件と対象が1つのセレクタにまとまります。数える対象を絞る `of S` 構文と `An+B` の読み方は、「[5-4 子要素の位置で選ぶ](/pseudo/child-index/)」で説明しています。

## 起点と `>` を省かない

`:has()` で数えるときも、起点のない `:has()` は書きません。`:has(> :nth-child(3))` とだけ書くと、ページのすべての要素が起点になり、DOMが変わるたびに、ブラウザの調べ直す範囲が広がります。ネストしたルールの中では、必ず `&` から書き始めます（ルール `no-unanchored-has`）。

```css title="🙅‍♂ Not Recommended: 起点と > を省いて数える" issue="behavior"
/* 🙅‍♂ Not Recommended */
:has(> :nth-child(3)) {
  grid-template-columns: repeat(3, 1fr);
}

.item-list {
  &:has(:nth-child(3)) {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

引数の `>` も省けません。`&:has(:nth-child(3))` は、直下の3番目の子ではなく、「子孫のどこかにある、自分の親から見て3番目の要素」を探します。一覧の項目の中に、子要素を3つ以上持つものが1つでもあれば、項目が1つしかなくても当てはまります。子の側で数えるときも同じで、`& > :nth-child(odd):last-child` の `>` を省くと、孫やそれより深い位置の要素まで選びます。

```css title="🙆‍♂ Recommended: & から書き始め、直下の子だけを数える" from="pseudo/has-direct-child"
@scope (.scoped.item-list) to (.scoped) {
  :scope {
    &:has(> :nth-child(3)) {
      padding: 12px;
      border: 1px solid var(--border--strong);
      border-radius: var(--rounded--lg);
    }
  }
}
```

次のデモは、項目が1つだけの一覧に、項目が3つ以上なら一覧を枠で囲む指定を当てたものです。項目の中にタグが3つあるので、`>` を省いた1つ目の一覧は、タグの3つ目に当てはまり、項目が1つなのに枠で囲まれます。`>` を付けた2つ目の一覧は、直下の項目だけを数えるので、枠は付きません。件数そのものを条件にしてよい指定と、列の数のように幅で決める指定の区別は、次の見出しで説明します。

## 列数は幅で、件数は数量クエリで

数量クエリを覚えると、列数の切り替えにも使いたくなります。たとえば、項目が2つなら2列、3つ以上なら3列にする、という指定です。

```css title="🙅‍♂ Not Recommended: 件数で列数を決める" issue="behavior"
/* 🙅‍♂ Not Recommended */
.pickup-list {
  display: block grid;

  &:has(> :nth-child(2)) {
    grid-template-columns: repeat(2, 1fr);
  }

  &:has(> :nth-child(3)) {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

この指定は、一覧が使える幅を考えていません。同じ一覧をサイドバーのような狭い場所に置くと、3件あれば3列のまま、1列あたりの幅が数十pxまで縮みます。列数を決める本当の条件は、項目の数ではなく、項目を何列並べられるだけの幅があるかです。{/* 要確認: 出典なし */}

列数は、`repeat()` の `auto-fit` と `minmax()` に任せます。`auto-fit` は列の最小幅を下回らない範囲で列を作り、項目のない列を幅0に畳むので、項目が2つなら2列に広がり、幅が足りなければ列は減ります。`auto-fit` と `auto-fill` の違いは第7章「[7-8 Gridの基礎](/layout/grid-basics/)」で、置かれた場所の幅で配置を組み替える方法は第13章「[13-3 コンテナサイズクエリ](/responsive/container-size-queries/)」で説明しています。

一方、`auto-fit` でも解決できないのが、項目が1つだけの場合と、最終行が埋まらない場合です。`auto-fit` は残った1つの項目を行いっぱいに広げ、最終行の端数は行の先頭に寄せます。どちらも幅ではなく件数そのものが条件なので、数量クエリの出番です。この見出しでは1件の場合を扱い、最終行の端数を中央に寄せる方法は「[11-5 件数で配置を組み替える](/layout-practice/quantity-layouts/)」で説明します。

次のデモは、同じピックアップの一覧に、項目を1件、2件、3件、5件入れて並べたものです。列の数は幅から決まり、最小幅は200px相当、多くても3列までにしています。項目が1件のときだけ、親を起点にした `:has()` で列の幅を400px相当に固定し、中央に置いています。変えるのは親の `grid-template-columns` なので、`:has()` で書きます。

```css title="🙆‍♂ Recommended: 列数は幅で決め、1件のときだけ数量クエリで中央に置く"
@scope (.scoped.pickup-list) to (.scoped) {
  :scope {
    display: block grid;
    grid-template-columns: repeat(auto-fit, minmax(min(100%, calc(200 / 16 * 1rem)), 1fr));
    gap: 16px;

    &:has(> :only-child) {
      grid-template-columns: minmax(0, calc(400 / 16 * 1rem));
      justify-content: center;
    }
  }
}
```

<Demo title="列数は幅で決まり、項目が1件のときだけ中央に置かれる一覧" html={pickupHtml} css={pickupCss} />

幅を1024pxにすると、2件の一覧は2列に、3件と5件の一覧は3列に並びます。2件の一覧が2列いっぱいに広がるのは、`auto-fit` が3列目を畳んでいるからで、数量クエリは関わっていません。1件の一覧は、どの幅でも400px相当を超えず、中央に置かれます。デモの `grid-template-columns` には、列の最大数を3に抑える計算を加えています。第12章「[12-7 grid：列の最小幅と最大数から列数を決める](/compositions/grid/)」と同じ考え方で、コード例では省いています。

## 補足と注意点

`:has()` で数える数量クエリの詳細度は、引数の分だけ上がります。`:scope` の中で `&:has(> :only-child)` と書くと、`:scope`（0.1.0）に `:only-child`（0.1.0）が加わり、0.2.0になります。子の側の `& > :nth-child(2n + 1):nth-last-child(1)` も、親のクラスに擬似クラス2つが加わって0.3.0です。どちらも元のスタイルより詳細度が高いので、書く順序によらず上書きできます。

数えるのは要素だけです。テキストノードやコメントは数えず、`::before` などの擬似要素も子に含みません。一方、`hidden` 属性や `display: none` で見えなくなった要素は、DOMにある限り数えられます。絞り込みによって項目を隠す一覧では、`&:has(> :nth-child(3 of :not([hidden])))` のように `of S` 構文で数える対象を絞ります。

<Baseline id="nth-child-of" name=":nth-child() の of S 構文" />

数量クエリの条件は、子要素の並びが変わるとその場で判定し直されます。JavaScriptで項目を追加したり削除したりしても、クラスを付け直す処理は要りません。

子の数を値として式に入れる `sibling-count()` という関数もあります。数量クエリが数を条件にして宣言を切り替えるのに対し、`sibling-count()` は数から連続的に変わる値を作ります。本書の対象のブラウザのすべてが対応してはいないので、件数で見た目を切り替える処理は数量クエリで書きます（「[5-4 子要素の位置で選ぶ](/pseudo/child-index/)」）。
