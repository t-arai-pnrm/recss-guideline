`::before` と `::after` は、要素の内容の前と後ろに、CSSで箱を足す擬似要素です。この箱に入る内容を生成コンテンツと呼びます。本書では、生成コンテンツに入れるのは装飾だけにします。必須の印、単位、注意書きのように、読み手が知る必要のある文字はHTMLに書きます。

装飾として文字や記号を入れるときは、`content: "→" / ""` のように、スラッシュの後ろの代替テキストを空にします。記号の名前が読み上げられないようにするためです。この節では、擬似要素が作られる条件、読み上げとの関係、`::marker`、`::selection`、`::highlight()`、`::first-letter`、`::first-line` の制約を順に説明します。擬似要素の書き方そのものは「[5-1 擬似クラスと擬似要素の基本](/pseudo/basics/)」で説明しています。

## 生成コンテンツの文字が届かない場面

生成コンテンツは、DOMに含まれません。画面には表示されても、HTMLに書いた文字と同じようには扱われません。私は見出しの副題を `content: attr(data-subtitle)` で表示する書き方について、機械翻訳されず、選択してコピーできず、ページ内検索の対象にもならないことを記事に書きました。

読み上げも当てになりません。MDNは、生成コンテンツはDOMに含まれないので、支援技術とブラウザの組み合わせによっては読み上げられないと説明しています。WCAGの達成方法の文書には、装飾でない内容を `::before` と `::after` で挿入することを、達成基準1.3.1の失敗例として挙げたもの（F87）がありました。現在は、ブラウザとスクリーンリーダーの対応が進んだことを理由として廃止扱いです。ただし、文字を選択できないといった使い勝手の問題は残るとされています。読み上げられる環境が増えても、翻訳、コピー、検索の対象にならないことと、ユーザーがスタイルを無効にすると内容が失われることは変わりません。

この性質は、次のような指定で問題になります。入力欄のラベルに「必須」を、価格に「円（税込）」を、CSSで足す書き方です。見た目は整いますが、読み上げで「必須」が伝わらなければ、ユーザーは入力が必須の項目を知らないまま送信します。翻訳した画面では、金額の数字だけが訳され、単位だけが日本語のまま残ります。

```css title="🙅‍♂ Not Recommended: 意味のある文字を生成コンテンツで入れる" issue="behavior"
/* 🙅‍♂ Not Recommended */
.label--required {
  &::after {
    content: "必須";
  }
}

.price {
  &::after {
    content: "円（税込）";
  }
}
```

意味のある文字は、HTMLに書きます。見た目を変えたいときは、その文字を `span` で包んでスタイルを当てます。CSSでできるのは、すでにHTMLにある文字の見た目を変えることまでです。

```html
<label for="email">メールアドレス<span class="_required">必須</span></label>
<p class="_price">1,000円（税込）</p>
```

```css title="🙆‍♂ Recommended: HTMLに書いた文字に見た目を当てる"
@scope (.scoped.form-field) to (.scoped) {
  ._required {
    padding-inline: 4px;
    border: 1px solid;
  }
}
```

印刷のときにだけ、外部リンクの後ろへ `attr(href)` でURLを添える指定は例外です。URLは `href` 属性としてHTMLにあり、画面では読み上げもリンクの操作もできます。紙の上で行き先が分からなくなる分だけを、生成コンテンツで補っています。この書き方は第16章の「印刷のスタイル」で説明します。{/* 16-11の執筆後にリンクする: /decoration/print/ */}

## `::before` と `::after` が作られる条件

`::before` と `::after` は、`content` に `none` 以外の値を指定したときだけ作られます。`content` の初期値は `normal` で、`::before` と `::after` では `none` として計算されるからです。MDNによれば、`content` の値が無効な場合も、擬似要素は作られません。図形だけを描くときも、`content: ""` で中身が空の箱を作る必要があります。

作られた箱は、`display` を指定しなければインラインです。空のインラインの箱には `inline-size` と `block-size` が働かないので、線や図形を描くときは箱の種類を変えます。親がフレックスコンテナかグリッドコンテナなら、擬似要素はそのアイテムになり、`display` を指定しなくても大きさの指定が働きます。絶対配置した擬似要素も、ブロックの箱になります。空の擬似要素に `display: inline flow-root` を指定してアイコンを描く例は、第16章「[16-3 アイコンとSVG](/decoration/icons-and-masks/)」にあります。

```css title="🙆‍♂ Recommended: 空の擬似要素で図形を描くときは、content と箱の種類を指定する" from="pseudo/generated-box"
@scope (.scoped.status-label) to (.scoped) {
  :scope {
    &::before {
      content: "";
      display: inline flow-root;
      inline-size: 1em;
      aspect-ratio: 1;
      background-color: var(--background--inverse);
    }
  }
}
```

次のデモの3つの項目には、どれも `::before` に `inline-size` と背景色を指定しています。四角が表示されるのは、`content: ""` で擬似要素を作り、`display: inline flow-root` で箱の種類を変えた3つ目だけです。コード例の `status-label` の四角は、状態の名前の文字に添えた装飾なので、強制カラーモードで背景色が消えても、伝わる内容は変わりません。意味を持つ図形を描くときは、後で説明する見出しの線のように枠線で描くか、第15章のルール `background-current-for-shapes` に従います。

<Demo title="content がなければ擬似要素は作られず、インラインの箱には大きさが効かない" html={generatedBoxHtml} css={generatedBoxCss} widths={[]} />

擬似要素は、要素の子として内容の前後に作られます。そのため、子を持てない要素には作られません。MDNは、`img` のように中身が外部の資源で決まる置換要素には、`::before` を適用できないと説明しています。`video` や `iframe` も置換要素です。`img` に `::after` でキャプションや枠を足そうとしても表示されないので、`figure` や `div` で包み、包んだ要素の擬似要素で描きます。

ChromeとFirefoxでは、読み込みに失敗して代替テキストを表示している `img` に限り、`::before` と `::after` が表示されます。しかし、Safariでは表示されず（WebKitのバグ155227。2016年に報告され、未解決）、CSS 2.1も置換要素と擬似要素の関係を十分には定めていません。そのため本書では、壊れた画像の表示を擬似要素で整える書き方に頼りません。

`input` も、テキストの入力欄などでは擬似要素が表示されません。例外は、`appearance: none` を指定したチェックボックスとラジオボタンです。第17章「[17-7 フォーム部品](/interaction/forms/)」では、`input` 自体に `appearance: none` を指定し、`::before` でチェックマークを描いています。

## 装飾の記号は代替テキストを空にする

生成コンテンツが読み上げられる環境では、装飾の記号も読み上げられます。リンクの後ろに `content: "→"` で矢印を足すと、リンクの名前の後ろに記号の名前も読まれることがあります。「料金プランを見る」の後ろに矢印の名前が続いても、ユーザーが得る情報は増えません。{/* 要検証: ブラウザ。読み上げの具体的な文言は環境で異なる */}

`content` には、スラッシュの後ろに代替テキストを書けます。`content: "→" / ""` のように代替テキストを空にすると、矢印は画面に表示され、読み上げからは外れます。CSS Generated Content Module Level 3でも、装飾の擬似要素の代替テキストを空にすると読み上げを避けられる、と説明しています。

```css title="🙆‍♂ Recommended: 装飾の記号は代替テキストを空にする" from="pseudo/decorated-section"
@scope (.scoped.more-link) to (.scoped) {
  :scope {
    &::after {
      content: "→" / "";
    }
  }
}
```

<Baseline id="alt-text-generated-content" name="content の代替テキスト" />

代替テキストの構文には、2024年7月にFirefox 128が対応し、主要なブラウザがそろいました。Safariは17.4から対応しているので、本書の対象のブラウザはすべて対応しています。対応していないブラウザでは、`content` の宣言全体が無効になり、擬似要素は作られません。装飾が消えるだけなので、内容と操作は損なわれません。

`content: ""` で作る文字のない箱には、代替テキストは要りません。読み上げる文字がもともとないからです。反対に、擬似要素そのものが操作の対象になる場合は、代替テキストを空にせず、名前を書きます。カルーセルの前後のボタンを `::scroll-button()` で作るときは、`content: "←" / "前の事例"` のように、ボタンの名前を代替テキストで渡します。この例は第17章「[17-8 CSSでカルーセルを作る](/interaction/carousel/)」で説明しています。

代替テキストを書いても、「意味のある文字を生成コンテンツで入れてよい」ことにはなりません。代替テキストは画面に表示されず、表示される側の文字は、翻訳、コピー、ページ内検索の対象にならないままです。読み手に伝えたい内容はHTMLに書き、代替テキストは装飾を読み上げから外すためと、擬似要素の部品に名前を付けるために使います。{/* 要確認: 出典なし */}

次のデモでは、見出しの前の線、リストの項目の前のチェックの記号、リンクの後ろの矢印を、すべて擬似要素で描いています。どれも、見出し、リスト、リンクの文字で意味が伝わっている部分への装飾です。

<Demo title="見出しの線、リストのチェック、リンクの矢印を擬似要素で描く" html={sectionHtml} css={sectionCss} />

見出しの線は、`content: ""` で作った文字のない箱です。見出しを `display: block flex` にしているので、擬似要素はフレックスアイテムになり、`block-size` が働きます。幅は指定せず、`border-inline-start` の太さに任せています。高さの `1lh` は1行の高さなので、見出しの文字の大きさを変えても、線の長さが行に合います。見出しは `align-items: start` にしているので、見出しが2行に折り返しても、線は1行目の横に来ます。線は背景色ではなく `border-inline-start` で描いています。強制カラーモードでは背景色が消えますが、枠線は残るからです（第15章「[15-5 強制カラーモードとコントラスト](/color-media/forced-colors/)」）。

チェックの記号と矢印は文字なので、代替テキストを空にしています。リストの項目は `display: block grid` にして、記号を1列目に、本文を2列目に置いています。本文が2行に折り返しても、2行目が記号の下に回り込みません。リストの印を消すのに `list-style: none` を使わない理由は、次の見出しで説明します。

## `::marker` と `::selection` の制約

`::marker` は、リストの項目の印（マーカー）を選ぶ擬似要素です。指定できるのは、`color`、`font-*`、`content` など、文字に関わる一部のプロパティだけです。さらに、Safariが反映するのは `color` と `font-size` の2つに限られます。web-featuresでも、`::marker` はSafariの対応が不十分なため、Baselineに入っていません。

<Baseline id="marker" />

そのため、`::marker` に指定するのは `color` と `font-size` だけにします。印の記号を変える、番号を太くする、印をアイコンにするといった装飾は、Safariだけ元の見た目のまま残ります。こうした装飾が必要なときは、`list-style-type: ""` でマーカーを空にし、`::before` で描きます。`list-style: none` で消すと、SafariのVoiceOverがリストとして読み上げなくなるからです（第8章「[8-3 グローバルに書いてはいけないもの](/reset/global-pitfalls/)」）。番号を円で囲む例は第16章「[16-7 文字とリストの装飾](/decoration/text-ornaments/)」にあります。

```css title="🙆‍♂ Recommended: ::marker には color と font-size だけを指定する" from="pseudo/marker-props"
@scope (.scoped.point-list) to (.scoped) {
  li {
    &::marker {
      color: var(--foreground--muted);
      font-size: 1.25em;
    }
  }
}
```

次のデモの1つ目のリストは、`::marker` で黒丸の色と大きさだけを変えています。2つ目のリストは、`list-style-type: ""` でマーカーを空にし、チェックの記号を `::before` で描いています。デモの土台のkiso.cssがマーカーを空にしているので、1つ目では `list-style-type: revert` でブラウザのデフォルトの黒丸に戻しています。

<Demo title="::marker で色と大きさを変えたリストと、::before で印を描いたリスト" html={markerHtml} css={markerCss} />

`::selection` は、ユーザーが選択した範囲を選ぶ擬似要素です。指定できるのは、`color`、`background-color`、`text-decoration` とその関連のプロパティ、`text-shadow` など、ごく一部です。`background-image` は無視されます。iOSのSafariは `::selection` に対応していないので、選択範囲はシステムの色のままになります。

<Baseline id="selection" />

選択範囲の色を変えるときは、`color` と `background-color` の両方を指定し、2つの色のコントラスト比を確かめます。片方だけを変えると、もう片方にはブラウザやユーザーの設定の色が残り、組み合わせによっては選択した文字が読めなくなります。{/* 要確認: 出典なし */}MDNも、選択範囲の見た目を好みだけで変えないこと、変えるなら文字と背景のコントラスト比を確保することを勧めています。基準は第15章「[15-5 強制カラーモードとコントラスト](/color-media/forced-colors/)」の、通常の文字で4.5:1以上です。

```css title="🙆‍♂ Recommended: 文字と背景の色を組にして指定する"
::selection {
  background-color: oklch(30% 0.1 260deg);
  color: oklch(100% 0 0deg);
}
```

## `::highlight()` で文字の範囲に色を付ける

`::highlight()` は、JavaScriptで登録した文字の範囲を選ぶ擬似要素です。範囲は、CSS Custom Highlight APIで作ります。`Range` で始点と終点を決めて `Highlight` にまとめ、名前を付けて `CSS.highlights` に登録すると、CSSの `::highlight(名前)` でその範囲に色を付けられます。範囲を要素で包まないのでDOMは変わらず、要素の境界をまたぐ範囲も1つのハイライトにできます。ページ内検索の一致箇所や、エディターの構文の色分けのように、操作に合わせて範囲を描き直す表示に使います。

```js title="テキストノードの5文字目から9文字目を登録する"
const range = new Range();
range.setStart(textNode, 4);
range.setEnd(textNode, 9);
CSS.highlights.set('search-result', new Highlight(range));
```

```css title="🙆‍♂ Recommended: 背景色に下線を組み合わせて範囲を示す" from="pseudo/highlight-search"
::highlight(search-result) {
  background-color: oklch(92% 0.12 95deg);
  color: oklch(20% 0 0deg);
  text-decoration-line: underline;
  text-decoration-thickness: 2px;
}
```

次のデモでは、入力欄の語に一致する範囲を本文から集め、`search-result` という名前で登録しています。語を書き換えると、一致した範囲の背景色と下線が付け直されます。範囲を要素で包まないので、開発者ツールで本文を見てもDOMは変わりません。一致した数は、色とは別に文章でも示しています。

<Demo title="入力した語に一致する範囲を、::highlight() で背景色と下線で示す" html={highlightHtml} css={highlightCss} js={highlightJs} widths={[]} />

<Baseline id="highlight" name="::highlight() と CSS Custom Highlight API" />

2026年3月にFirefox 149が `::highlight()` に対応し、主要なブラウザがそろいました。Safariは17.2から対応しているので、本書の対象のブラウザはすべて対応しています。指定できるプロパティは `::selection` とほぼ同じで、`color`、`background-color`、`text-decoration` とその関連のプロパティ、`text-shadow` などに限られます。CSS Pseudo-Elements Level 4は、ハイライトの擬似要素で使えるプロパティを、レイアウトを変えないものに限っています。`padding` や `font-weight` で範囲を目立たせることはできません。

ハイライトは、範囲を目立たせても、文書の内容は変えません。MDNによれば、`Highlight` の `type` で綴りや文法の誤りといった意味を支援技術に伝えられますが、対応は環境と種類によって異なります。CSSやJavaScriptが動かない環境では、範囲そのものが表示されません。そのため、内容の一部として読み手に伝える強調は、`<mark>` で書きます。`<mark>` は、周りの文脈との関連で目印を付けた範囲を表す要素で、検索結果のページで検索語に付ける目印のような、ページを開いた時点で決まっている強調に合っています。

ただし、`<mark>` も、多くのスクリーンリーダーは初期設定で読み上げを区別しない、とMDNは説明しています。強調に気付かないと内容を取り違える場面では、「3件が一致しました」のように、要点を文章でも伝えます。`::highlight()` と `<mark>` のどちらで示す範囲も、色だけで区別しません（第15章のルール `no-color-only-information`）。

強制カラーモードでは、`color` と `background-color` がユーザーの配色に置き換わり、`text-shadow` は `none` になります。背景色だけで示したハイライトは、周りの文字と見分けられなくなるおそれがあります。{/* 要検証: ブラウザ。強制カラーモードでの ::highlight() の表示はブラウザで確かめていない */}上の例で下線を組み合わせているのは、強制カラーモードで線の色を置き換えられても、線そのものは残るからです。強制カラーモードの全体の扱いは、第15章「[15-5 強制カラーモードとコントラスト](/color-media/forced-colors/)」で説明しています。

## `::first-letter` と `::first-line` を和文に使うとき

`::first-letter` はブロックコンテナの最初の1文字を、`::first-line` は最初の1行を選ぶ擬似要素です。どちらも、指定できるプロパティは文字と背景などの一部に限られます。`::first-letter` には余白と枠線も指定できますが、`::first-line` には指定できません。和文では、1文字は仮名か漢字の1字です。MDNによれば、最初の文字の前後にある括弧や引用符のような約物も、`::first-letter` に含まれます。段落が開き括弧で始まれば、括弧と次の1字が一緒に大きくなります。

<Baseline id="first-letter" />

`::first-letter` は、`::before` で生成した文字があれば、その最初の文字を選びます。生成コンテンツに装飾の記号を入れた要素では、本文の最初の文字ではなく、記号が大きくなります。2つを同じ要素に指定するときは、表示を確かめます。

```css title="🙆‍♂ Recommended: 最初の文字と1行目を、区切りに意味を持たせない装飾にとどめる" from="pseudo/first-letter-line"
@scope (.scoped.lead-text) to (.scoped) {
  p {
    &::first-letter {
      font-size: 1.75em;
    }
  }
}
```

次のデモの1つ目と2つ目の段落は、`::first-letter` で最初の文字を大きくしています。開き括弧で始まる1つ目では、括弧と「擬」の2文字が大きくなります。3つ目の段落は `::first-line` で1行目を太字にしていて、幅を変えると、太字になる範囲が変わります。

<Demo title="::first-letter は開き括弧と次の1字を選び、::first-line の範囲は幅で変わる" html={firstLetterHtml} css={firstLetterCss} widths={[320, 480, 768]} />

`::first-line` が選ぶ範囲は、要素の幅と文字の大きさで決まります。幅の狭い画面では、同じ段落でも1行に入る文字が減り、太字になる範囲も短くなります。1行目だけを要約として目立たせるような、範囲に意味を持たせる使い方はできません。使うとしても、どこで区切れても意味が変わらない装飾にとどめます。{/* 要確認: 出典なし */}最初の文字を数行分の高さに沈める `initial-letter` は、本書では扱いません。接頭辞なしの `initial-letter` に対応しているのはChrome系のブラウザだけで、Safariは接頭辞付きの `-webkit-initial-letter` だけに対応しています。

フォームの部品に付いた擬似要素のうち、入力欄の例文を選ぶ `::placeholder` と、ファイルの選択ボタンを選ぶ `::file-selector-button` は、「[5-6 フォームの状態を表す擬似クラス](/pseudo/form-states/)」で扱います。
