大きさを指定しないときの `auto` は、ブロックの幅なら横いっぱい、高さなら中身の高さを意味します。中身に合わせた幅には `fit-content` を使い、固定の長さは `inline-size` ではなく、`min-inline-size` や `max-inline-size` で下限と上限として書きます。`%` は包含ブロックを基準に計算され、高さの `%` は親の高さが決まっているときにしか働きません。自然には広がらない要素を幅いっぱいに広げるときは、`100%` ではなく `stretch` を使います。

この節で扱うのは、ボックスの大きさがどの規則で決まるかです。ボックスの4つの領域と `box-sizing` は「[7-3 ボックスモデルの基礎](/layout/box-model/)」で、レイアウトの方式ごとに子の大きさが決まる規則は「[7-1 レイアウトの基礎](/layout/fundamentals/)」で説明しています。

## `auto` と中身に合わせた大きさ

`inline-size` と `block-size` の初期値は `auto` です。通常フローのブロックでは、`inline-size: auto` は包含ブロックの幅から左右の `margin` を引いた残りいっぱいの幅、`block-size: auto` は中身を収める高さを表します。一方、`float` の要素、`inline flow-root` の要素、左右の片側しか位置を指定していない絶対配置の要素、横に並ぶフレックスアイテムの `inline-size: auto` は、中身に合わせた幅を表します。絶対配置の要素でも `inset-inline` で左右の両方を指定すると、`auto` の幅は包含ブロックいっぱいに広がります。縦に並ぶフレックスアイテムも、`align-items` の初期値 `normal`（フレックスアイテムでは `stretch` として扱われる）によってコンテナの幅まで広がります。`auto` の意味は、要素がどのレイアウトの方式の中にあるかと、位置や揃え方の指定で変わります（「[7-1 レイアウトの基礎](/layout/fundamentals/)」）。

中身に合わせた幅は、キーワードで明示できます。`min-content` は、折り返せる位置ですべて折り返したときの幅で、英語なら最も長い単語の幅です。日本語は文字の間で折り返せるので、ほぼ1文字の幅になります。kiso.cssのように `overflow-wrap: anywhere` を指定していると、英単語の途中でも折り返せるので、英語でもほぼ1文字の幅になります。`max-content` は、一度も折り返さないときの幅です。

`fit-content` は、使える幅の中で `max-content` まで広がり、使える幅が狭ければその幅に縮み、`min-content` より狭くはならない値です。ラベルやバッジのように、中身の幅だけを占め、親が狭いときは折り返してほしい要素に使います。

```css title="🙆‍♂ Recommended: ブロックのまま、幅だけを中身に合わせる" from="layout/box-model-intrinsic"
.badge {
  inline-size: fit-content;
}
```

次のデモでは、同じ文の要素を、中身より狭い120pxの枠に入れています。`min-content` は1文字ずつ折り返し、`max-content` は折り返さずに枠からはみ出し、`fit-content` は枠の幅まで広がってそこで折り返します。

<Demo title="min-content、max-content、fit-content の幅の違い" html={intrinsicHtml} css={intrinsicCss} variant="neutral" widths={[]} />

幅を中身に合わせる目的で `display: inline-block` や `float` に変えると、要素が前後の文字と同じ行に並ぶなど、外側の振る舞いまで変わります。`fit-content` なら、ブロックのまま幅だけが変わります。{/* 要確認: 出典なし */}すべての主要なブラウザが対応しています。

## 最小値と最大値による制約

`min-inline-size` と `max-inline-size` は、計算した幅に下限と上限を付けるプロパティです。下限と上限が矛盾したときは、下限が優先されます。`min-inline-size` の初期値 `auto` は、通常のブロックでは0ですが、フレックスアイテムとグリッドアイテムでは中身の最小幅になり、長いURLを含むアイテムが縮まない原因になります。本書では、ベーススタイルで全要素に `min-inline-size: 0` を指定しています（「[8-2 ベーススタイルに書くもの](/reset/base-styles/#rule-global-min-inline-size-zero)」）。

固定の幅は、`inline-size` ではなく `max-inline-size` で上限として書きます。上限なら、親がそれより狭い場所では親の幅まで縮みます（「[13-1 検討する順番](/responsive/escalation/#rule-max-inline-size-over-fixed-width)」）。逆に、固定の長さの下限は親より大きくなってはみ出すことがあるので、`min(100%, …)` で親の幅を上限にします。

```css title="🙆‍♂ Recommended: 固定の下限は、親の幅を超えないようにする"
.button {
  display: inline flex;
  min-inline-size: min(100%, calc(240 / 16 * 1rem));
}
```

`min(100%, calc(240 / 16 * 1rem))` は、親の幅と240px相当のうち小さいほうを下限にします。広い場所では240px相当を保ち、狭い場所では親の幅まで縮みます。`minmax()` の最小値も同じ形で書きます（「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/#rule-minmax-min-capped-at-100-percent)」）。

次のデモでは、幅240pxの親の中に、`inline-size: fit-content` の要素を3つ置いています。1つ目は下限の320pxで親からはみ出し、`min(100%, …)` で書いた2つ目は親の240pxで止まります。3つ目は下限200pxと上限120pxが矛盾し、下限の200pxになります。

## `%` の基準

`inline-size` の `%` は、包含ブロックの幅に対する割合です。包含ブロックは、通常フローの要素ならいちばん近いブロックの祖先の内容の領域で、絶対配置の要素なら `position` が `static` 以外のいちばん近い祖先の `padding` の領域です（「[7-10 positionの基礎](/layout/positioning/)」）。

`block-size` の `%` は、包含ブロックの高さが決まっているときだけ計算されます。親の高さが中身から決まる場合、子の高さと親の高さが互いに依存して循環するので、`%` は `auto` として扱われます。子の高さを親にそろえるときは、`height: 100%` ではなく、親をGridにして伸ばします（「[幅いっぱいに広げる `stretch`](#幅いっぱいに広げる-stretch)」）。

`padding` と `margin` の `%` は、上下と左右のどちらでも、包含ブロックのインライン方向の大きさ（横書きなら幅）に対する割合です。上下の余白の基準を高さにすると、`block-size` と同じ循環が起きるからです。次のデモでは、幅の違う2つの親の中で、子に同じ `padding-block: 10%` を指定しています。上下の `padding` は、親の幅が160pxなら16px、320pxなら32pxになります。

<Demo title="上下の padding の % も、親の幅に対する割合になる" html={percentHtml} css={percentCss} variant="neutral" widths={[]} />

かつてはこの性質を使い、`padding-top: 56.25%` で16:9の箱を作っていましたが、今は `aspect-ratio` で書きます（「[16-1 画像の配置と比率](/decoration/images/#rule-aspect-ratio-for-ratios)」）。

```css title="🙅‍♂ Not Recommended: 上の padding の % で縦横の比率を作る" issue="convention"
/* 🙅‍♂ Not Recommended */
._video {
  block-size: 0;
  padding-top: 56.25%;
}
```

```css title="🙆‍♂ Recommended: 縦横の比率は aspect-ratio で書く"
._video {
  aspect-ratio: 16 / 9;
}
```

## 幅いっぱいに広げる `stretch`

`<img>` やフォーム部品、行方向のフレックスアイテムのように、自然には幅いっぱいに広がらない要素を広げるときは、`100%` ではなく `stretch` を使います。`stretch` は、ブロックレベルの要素の `auto` と同じように、`margin` を含めた箱を利用できる幅にちょうど収めます。`100%` と違い、`margin` や `box-sizing: content-box` と組み合わせても親からはみ出しません。

```css title="🙆‍♂ Recommended: 幅いっぱいに広げるなら stretch を使う"
._input {
  inline-size: -webkit-fill-available;
  inline-size: stretch;
}
```

`stretch` は比較的新しい値で、Chrome 138とSafari 27から使えます。それより前のバージョンでも、同じ働きの値を `-webkit-fill-available` という名前で使えます。Firefoxは `stretch` に対応していませんが、`-webkit-fill-available` には対応しています。公開されている資料では、Firefoxの対応は `width` と `height` に限られていますが、Firefoxで確かめたところ、`inline-size` にも適用されました。

<Baseline id="stretch" />

そのため、先に `-webkit-fill-available` を、後に `stretch` を書きます。`stretch` に対応したブラウザは後の宣言を使い、対応していないブラウザは理解できない後の宣言を捨てて、前の宣言を使います。Firefoxが以前に実装していた `-moz-available` は、いまのFirefoxが `-webkit-fill-available` を理解するので書きません。

`stretch` と `100%` の結果が違うのは、子が `margin` を持つときと、`content-box` の要素を広げるときです。ただし、子の周りの余白は、子の `margin` ではなく、親の `padding` や `gap` で取ることを優先します。親が余白を持てば、子は `margin` を持たずに済みます。それでも、幅を広げる指定が要る要素は `stretch` で書いておきます。あとから子に `margin` が加わっても、はみ出さないからです。配置を親に任せる理由は、「[10-2 コンポーネントの境界を守る](/components/boundaries/)」で説明します。

子要素を親の高さにそろえたいだけなら、親に `display: block grid` を指定すれば、子要素が高さいっぱいに広がります。グリッドアイテムの `align-self` の初期値 `normal` が、`stretch` として扱われるからです。この `stretch` は揃え方の値で、上で説明した大きさのキーワードの `stretch` とは別のものです。

```css title="🙆‍♂ Recommended: 子要素を親の高さにそろえるなら、親をgridにする"
._card {
  display: block grid;
  min-block-size: calc(240 / 16 * 1rem);
}
```

この方法なら、親が `min-block-size` で最小値だけを決めている場合にも成り立ち、高さの固定を避けられます。何にでも `width: 100%` や `height: 100%` を付ける書き方を避ける理由は、「[2-3 保守しやすさを最優先にする](/design-mindset/maintainability/#何にでも-width-100-を指定しない)」で説明しています。
