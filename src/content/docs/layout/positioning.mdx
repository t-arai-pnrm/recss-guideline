`position` の `static` 以外の値は、働き方で2つに分かれます。`relative` と `sticky` は、親が決めた方式（通常フロー、Flexbox、Grid）に参加したまま、配置された後の位置を `inset` の分だけ補正します。`absolute` と `fixed` は、要素を親の流れから外し、絶対配置という別のレイアウトの方式で置き直します。位置の基準になる「包含ブロック」は、値によって、また祖先の `transform` などの指定によって変わります。

本書では、絶対配置の要素の包含ブロックを、同じコンポーネントの中に `position: relative` ではっきり作ります。`position: sticky` を指定するときは、`inset` を指定し、GridとFlexboxの子なら `align-self: start` も指定します。

## positionをレイアウトの方式として考える

CSSには、通常フロー、Flexbox、Gridのように、要素の大きさと位置を決める方式が複数あります。同じプロパティでも、どの方式で配置されるかによって働き方が変わります。`width` は、通常フローでは決まった幅になり、Flexboxの子では縮むことのある仮の幅として扱われます。`z-index` は、通常フローの要素に指定しても何も起きませんが、FlexboxとGridの子なら `position` を指定しなくても働きます。

`position` も、この方式に関わるプロパティです。`top` や `left` を書くための前提の指定と覚えていると、`absolute` を指定した要素がFlexboxの子として並ばなくなる理由や、`relative` を指定しただけで重なり順が変わる理由を説明できません。前者は、要素が絶対配置に移って親の流れから外れたことで起きる変化です。後者は、`static` 以外の要素（位置指定された要素）が、`static` の要素より後に描かれることで起きる変化です。

```css title="🙅‍♂ Not Recommended: Flexbox の子の1つに position: absolute を指定する" issue="behavior"
/* 🙅‍♂ Not Recommended */
.tag-list {
  display: block flex;
  gap: 8px;

  & > ._new {
    position: absolute;
  }
}
```

この例の `._new` は、フレックスアイテムとして並ばず、`gap` の計算からも外れます。`inset` を指定していないので、一覧の先頭の位置に置かれ、最初のタグに重なって描かれます。

この節では、まず5つの値がそれぞれ何を変えるかを説明し、次に位置の基準になる包含ブロックを扱います。最後に、つまずきやすい `sticky` が留まらない原因を説明します。重なり順（z-index）と、要素を画面幅いっぱいに広げる方法は、「[11-6 重なりと全幅](/layout-practice/layering/)」で扱います。留まったヘッダーの見た目の切り替えと固定ヘッダーの条件は「[11-7 固定ヘッダー](/layout-practice/sticky-header/)」で、ツールチップのように別の要素を基準に置くアンカーポジショニングは「[7-11 アンカーポジショニングの基礎](/layout/anchor-basics/)」で扱います。

## positionの5つの値

### static

`static` は初期値で、要素を通常フロー、Flexbox、Gridのうち、親が決めた方式のまま配置します。`inset` を指定しても無視されます。通常フローの仕組みは「[7-2 通常フローの基礎](/layout/normal-flow/)」で説明しています。

### relative

`relative` の要素は、親が決めた方式で置かれた元の場所を占めたまま、`inset` の分だけ描かれる位置がずれます。周囲の要素は元の位置を基準に並ぶので、ずらした分だけ隣と重なったり、元の場所に隙間が残ったりします。

本書では、`relative` を位置の調整には使いません。用途は、子孫の絶対配置の要素のために包含ブロックを作ることです。見た目を少し動かしたいだけなら、`translate` で足ります。{/* 要確認: 出典なし */}

### absolute

`absolute` の要素は、通常フローから外れ、場所を占めなくなります。親の高さには反映されず、後ろの要素は、その要素がないものとして並びます。FlexboxやGridの子に指定した場合も、フレックスアイテムやグリッドアイテムとしては並ばず、`gap` の計算からも外れます。

位置は、包含ブロックの辺からの距離を `inset` で指定して決めます。`inset` が `auto` のままの辺は、その要素が `static` だった場合の位置（静的位置）に置かれます。幅を指定しなければ、内容に合わせて縮みます。

### fixed

`fixed` の要素も、`absolute` と同じく通常フローから外れます。違うのは包含ブロックで、通常はビューポートが基準になります。そのため、ページをスクロールしても画面の同じ位置に留まります。ただし、祖先の指定によって基準は変わります。この点は、あとの「position以外で包含ブロックを作る指定」で説明します。

### sticky

`sticky` の要素は、親のレイアウトの方式で置かれた位置のまま、スクロールに合わせて、祖先のスクロールコンテナと包含ブロックの範囲の中でずれます。場所を占め続けるので、周囲のレイアウトは `static` と変わりません。範囲の外へは出られないので、ずれる余地がなければ、何も指定していないのと同じに見えます。留まらない原因は、あとの節で扱います。

<Baseline id="sticky-positioning" />

`fixed` と `sticky` の要素は、z-indexを指定しなくてもスタッキングコンテキストを作ります。`relative` と `absolute` は、z-indexに `auto` 以外を指定したときだけ作ります。

次のデモでは、5つの値のBに、同じ `inset` を指定しています。枠の中をスクロールすると、`fixed` のBは枠の同じ位置に留まり、`sticky` のBは破線の枠の範囲で上端に留まります。スクロールする前の位置では、`static` のBは `inset` が無視されてAとCの間に並び、`relative` のBは元の場所を空けたまま下へ16px、行末側へ48pxずれます。`absolute` のBは流れから外れ、破線の枠の角から同じ距離に置かれます。

## 包含ブロックはどの祖先で決まるか

要素の位置と大きさは、「包含ブロック」を基準に計算されます。`inset` のパーセントの値も、`inline-size` や `padding` のパーセントの値も、包含ブロックの大きさに対する割合です。どの領域が包含ブロックになるかは、`position` の値で次のように決まります。

| `position` | 包含ブロック |
| --- | --- |
| `static`、`relative`、`sticky` | いちばん近いブロックコンテナの祖先の、内容の領域。フレックスアイテムはフレックスコンテナの内容の領域、グリッドアイテムは置かれたグリッドエリア |
| `absolute` | `position` が `static` 以外のいちばん近い祖先の、`padding` の領域。なければ初期包含ブロック |
| `fixed` | ビューポート |

<Figure src="layout/containing-block" alt="子要素のpositionの値ごとに、包含ブロックになる祖先の領域を示した入れ子の図。外側から順に、ビューポート、position: relativeのカード、position: staticのdiv、その中の子要素が入れ子になっている。3つの領域に番号を付けて強調している。1番は、divの中の内容の領域で、static、relative、stickyの子の包含ブロック。2番は、カードのborderの内側にあるpaddingの領域で、position が static 以外のいちばん近い祖先として、absoluteの子の包含ブロック。3番は、いちばん外側のビューポートで、fixedの子の包含ブロック。" />

`absolute` で当てはまる祖先がないときの「初期包含ブロック」は、ビューポートの大きさの矩形をページの先頭に置いたものです。基準を作り忘れると、要素はページの左上を基準に置かれ、置いた場所によって位置がずれます。

```css title="🙅‍♂ Not Recommended: 包含ブロックを作らずに、カードの角にバッジを置く" issue="behavior"
/* 🙅‍♂ Not Recommended */
.product-card {
  & > ._badge {
    position: absolute;
    inset-block-start: 8px;
    inset-inline-end: 8px;
  }
}
```

この例のバッジが置かれるのは、カードの角ではありません。`position` を指定したカードの外の祖先か、初期包含ブロックの角です。カードを置く場所が変わると、バッジの位置も変わります。包含ブロックは、基準にしたい祖先へ `position: relative` を指定して、はっきり作ります。`position: absolute` と `inset` は、包含ブロックを作る祖先との組み合わせで意味が決まるので、その祖先のルールの中に `& > ._badge` とネストして書きます（「[9-6 ネストの判断基準](/notation/nesting-criteria/)」）。

```css title="🙆‍♂ Recommended: コンポーネントのルートで、バッジの包含ブロックを作る" from="layout/position-containing-block"
.product-card {
  position: relative;

  & > ._badge {
    position: absolute;
    inset-block-start: 8px;
    inset-inline-end: 8px;
  }
}
```

次のデモでは、1つ目のカードだけ包含ブロックを作っていません。そのバッジは、デモの枠の右上に置かれます。`position: relative` を指定した2つ目のカードでは、バッジがカードの右上の角に収まります。

<Demo title="包含ブロックを作らないと、バッジがカードの外の角に置かれる" html={containingBlockHtml} css={containingBlockCss} variant="neutral" />

基準にする祖先は、同じコンポーネントの中に置きます。コンポーネントの外の祖先を基準にすると、置く場所によって位置が変わってしまうからです。コンポーネントのルートそのものに `position: absolute` と `inset` を指定しない理由は、「[10-2 コンポーネントの境界を守る](/components/boundaries/)」で説明しています。

## position以外で包含ブロックを作る指定

`position` の値だけでは、包含ブロックは決まりません。祖先に `transform`、`filter`、`perspective` が `none` 以外で指定されていると、その祖先が、子孫の `absolute` と `fixed` の両方の要素の包含ブロックになります。`contain: layout` と `contain: paint`（`strict` と `content` を含む）も同じです。

見落としやすいのは、個別の変形プロパティ（`translate`、`rotate`、`scale`）、すりガラスの効果に使う `backdrop-filter`、`content-visibility: auto` です。`will-change: transform` のように、これらのプロパティを `will-change` に書いただけでも包含ブロックになります。

影響が大きいのは `fixed` です。フェードインの演出のために `translate` を指定した要素の中に固定ヘッダーを置くと、ヘッダーはビューポートではなく、その要素に対して固定されてしまいます。スクロールすると、ヘッダーは要素と一緒に画面の外へ流れます。モーダルは `<dialog>` の `showModal()` でトップレイヤーに表示し、この問題を避けます。トップレイヤーの要素は、祖先の指定にかかわらずビューポートを基準にします。ダイアログの実装は「[17-6 開閉するUI](/interaction/disclosure/)」で扱います。

次のデモでは、2つ目の枠に `translate: 0` を指定しています。見た目は変わりませんが、枠の中をスクロールすると、2つ目の「固定」だけが枠と一緒に流れます。

<Demo title="祖先に translate を指定すると、fixed の要素がその祖先を基準に置かれる" html={fixedTransformHtml} css={fixedTransformCss} frame={fixedTransformFrame} variant="neutral" height="320px" />

コンテナサイズクエリのための `container-type`（`inline-size` と `size`）は、現在の仕様ではレイアウトの封じ込めを含まないので、包含ブロックを作りません。ただし、以前の仕様に沿って実装したブラウザでは、包含ブロックになることがあります。仕様が変わった経緯とブラウザの対応は、「[13-4 コンテナの副作用とコンテナ単位](/responsive/container-units-and-side-effects/)」で説明しています。固定ヘッダーやモーダルを含む `html` と `body` には、`container-type` を指定しません。

## 絶対配置の要素を中央に置く

絶対配置の要素を中央に置くときは、`translate: -50% -50%` ではなく、`inset: 0` と `margin: auto` を使います。`inset: 0` で包含ブロックいっぱいの範囲を作り、大きさを決めたうえで、残りを `margin: auto` で均等に分けます。

```css title="🙆‍♂ Recommended: inset: 0 と margin: auto で中央に置く" from="layout/position-center"
._media {
  position: relative;

  & > ._label {
    position: absolute;
    inset: 0;
    margin: auto;
  }
}

._label {
  inline-size: fit-content;
  block-size: fit-content;
}
```

<Demo title="inset: 0 と margin: auto で、ラベルを包含ブロックの中央に置く" html={centerHtml} css={centerCss} scheme="light" />

このデモでは、16:9の暗い色の枠を包含ブロックにして、「再生する」のラベルを枠の上下左右の中央に置いています。ラベルの大きさは中身で決まるので、文言を変えても中央からずれません。

`translate` を使う方法は、位置を決める指定が `inset` と変形の2か所に分かれ、何のための変形なのかが読み取りにくくなります。絶対配置の要素に `place-self: center` を指定する方法もありますが、Safariは26から対応したので、まだ使えません（「[1-2 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」）。

そもそも絶対配置にする必要がないことも多くあります。Gridの中なら `place-items: center` で足ります。高さのある通常のブロックの中で縦方向の中央に置くだけなら、そのブロックに `align-content: center` を指定します。`align-content` がブロックコンテナでも働くようになったのは、2024年4月からです。

## stickyが留まらない原因

`position: sticky` を指定したのに、要素が画面の端に留まらないことがあります。原因の多くは、GridやFlexboxの子として伸びている、`inset` を指定していない、祖先がスクロールコンテナになっている、要素が画面より高いの4つのどれかです。どれも、`sticky` の要素がずれる余地をなくします。

`sticky` の要素は、包含ブロック、つまり親の範囲の外へは出られません。ヘッダーを `div` で包み、その `div` の高さがヘッダーと同じなら、ヘッダーは留まりません。留めたい範囲（ページ全体なら `body` の直下）に要素を置いているかも、あわせて確かめます。

### GridやFlexboxの子は伸びる

サイドバーの目次を右の列に置き、スクロールに合わせて留めたい場面を考えます。親をGridにして、目次に `position: sticky` を指定しただけでは、目次は動きません。

```css title="🙅‍♂ Not Recommended: Grid の子に sticky だけを指定する" issue="behavior"
/* 🙅‍♂ Not Recommended */
.article-layout {
  display: block grid;
  grid-template-columns: 1fr calc(240 / 16 * 1rem);
  gap: 32px;
}

._nav {
  position: sticky;
  inset-block-start: 16px;
}
```

GridとFlexboxの子は、`align-self` の初期値（`normal`）が `stretch` として働き、セルの高さいっぱいに伸びます。本文が長ければセルも高いので、目次もそれと同じ高さになります。目次の高さが包含ブロックの高さと等しいと、ずらす余地がなく、目次は留まりません。`align-self: start` を指定すれば、目次は中身の高さで止まり、セルの中に余地ができます。

```css title="🙆‍♂ Recommended: sticky の子には align-self: start を指定する"
.article-layout {
  display: block grid;
  grid-template-columns: 1fr calc(240 / 16 * 1rem);
  gap: 32px;

  & > ._nav {
    align-self: start;
  }
}

._nav {
  position: sticky;
  inset-block-start: 16px;
}
```

次の2つのデモは、枠の中をスクロールできます。1つ目では目次が本文と一緒に流れ、2つ目では枠の上端に留まります。

<Demo title="Grid の子に sticky だけを指定すると、目次がセルの高さまで伸びて留まらない" html={stickyHtml} css={stickyBadCss} variant="not-recommended" height="360px" />

<Demo title="align-self: start を加えると、目次が枠の上端に留まる" html={stickyHtml} css={stickyCss} height="360px" />

親の `align-items: start` でも同じ結果になります。ただし、親に指定すると、同じ親のほかの子も中身の高さになります。`sticky` の要素だけが伸びなければよいので、私は子だけを指定する `align-self: start` を使います。`align-self` は、配置が親のレイアウトと対になっている指定なので、親のルールの中に `& > nav` とネストして書きます。

### insetを指定する

`sticky` は、どの位置で留めるかを `inset` で決めます。`inset-block-start` のように、留めたい軸のプロパティが1つは `auto` 以外でなければ、その軸では `relative` と同じ動きになります。先ほどの例の `inset-block-start: 16px` は、スクロールコンテナの上端から16px離れた位置で留める指定です。

下端や、横にスクロールする領域の端に留めるときも同じです。見出しを上端に、フッターの操作欄を下端に留めるなら、それぞれ `inset-block-start` と `inset-block-end` を指定します。本書では、ほかの場面と同じく、物理プロパティの `top` ではなく論理プロパティで書きます。

```css title="🙆‍♂ Recommended: 見出しを上端に、操作欄を下端に留める"
._heading {
  position: sticky;
  inset-block-start: 0;
}

._actions {
  position: sticky;
  inset-block-end: 0;
}
```

次のデモでは、1つ目の見出しにだけ `inset` を指定していません。枠の中をスクロールすると、1つ目の見出しは本文と一緒に流れ、2つ目の見出しは枠の範囲で上端に留まります。

### 祖先のスクロールコンテナ

`sticky` の要素は、いちばん近い祖先のスクロールコンテナを基準に留まります。スクロールコンテナを作るのは、`overflow` が `auto`、`scroll`、`hidden` の要素です。`visible` と `clip` は、それだけではスクロールコンテナを作りません。

スクロールコンテナは、実際にはスクロールしなくても基準になります。たとえば、祖先の `overflow: hidden` は、ユーザーがスクロールできないスクロールコンテナを作ります。`sticky` の要素はその領域を基準にしてしまい、ページのスクロールには反応しなくなります。

原因がはっきりしないときは、DevToolsで `sticky` の要素から祖先へ順にたどります。Computedタブで `overflow-x` と `overflow-y` の算出値を見て、`auto`、`scroll`、`hidden` のどれかになっている要素を探します。書いた値ではなく算出値を見るのは、片方の軸だけを指定すると、もう一方の軸の値も変わることがあるからです。たとえば `overflow-x: hidden` だけを書くと、`overflow-y` の `visible` は `auto` として算出され、その要素は縦方向にもスクロールするスクロールコンテナになります。

見つけたら、その指定が必要かを確かめます。はみ出しを切り取るだけなら、スクロールコンテナを作らない `clip` に変えます。`overflow-x: hidden` なら `overflow-x: clip` のように、切り取る軸はそのままにします。もう一方の軸は `visible` のまま残るので、縦にはみ出す影やフォーカスリングは切り取られません（「[11-4 はみ出しとスクロール](/layout-practice/overflow/)」）。親子のマージンの相殺を止めるために `overflow: auto` を使う書き方も、同じ理由で避けます。相殺を止めるなら `display: flow-root` を使います（「[11-2 余白を設計する](/layout-practice/spacing/)」）。

```css title="🙅‍♂ Not Recommended: はみ出しを切り取るために overflow-x: hidden を指定する" issue="behavior"
/* 🙅‍♂ Not Recommended */
.page-section {
  overflow-x: hidden;
}
```

```css title="🙆‍♂ Recommended: はみ出しを切り取るだけなら overflow-x: clip にする" from="layout/sticky-scroll-container"
.page-section {
  overflow-x: clip;
}
```

次のデモでは、1つ目の枠に `overflow-x: hidden` と同じ指定をしています。その枠がスクロールコンテナになるので、中の見出しはページのスクロールに反応せず、本文と一緒に流れます。

<Demo title="祖先がスクロールコンテナになると、sticky の見出しがページのスクロールで留まらない" html={stickyClipHtml} css={stickyClipCss} frame={stickyClipFrame} variant="neutral" height="240px" />

スクロールコンテナが意図したものである場合は、別の話です。たとえば、高さを決めて `overflow: auto` にした領域の中で見出しを留めるなら、見出しはその領域の中で留まります。領域に高さがなければスクロールせず、何も起きません。この場合に必要なのは、その領域に高さの上限を決めて、スクロールが起きるようにすることです。ページ全体のスクロールで留める通常の `sticky` では、親に高さを指定する必要はありません。

### 画面より高い要素

`sticky` の要素が画面より高いと、要素の下端が見えないまま上端で留まり、末尾に届かなくなります。目次が長い記事のサイドバーは、典型的な例です。要素の高さに上限を決め、上限を超える分は要素の中でスクロールさせます。

```css title="🙆‍♂ Recommended: 画面より高くなりうる sticky の要素には、高さの上限を決める"
.article-layout {
  display: block grid;

  & > ._nav {
    align-self: start;
  }
}

._nav {
  position: sticky;
  inset-block-start: 16px;
  overflow-y: auto;
  max-block-size: calc(100svb - 16px * 2);
}
```

上限は、スクロールで値が変わらない `svb`（小さいほうのビューポートの高さ）から、上下の余白を引いた値にしています。本書は `dvb` を要素の大きさに使いません。スクロールのたびに値が変わり、レイアウトシフトの原因になるからです（「[6-2 ビューポート単位とコンテナ単位](/values/viewport-and-container-units/)」）。`overflow-y: auto` を指定した要素自身はスクロールコンテナになりますが、要素の中の話なので、留まる動きには影響しません。

留まるようになった要素の応用は、「[11-7 固定ヘッダー](/layout-practice/sticky-header/)」で説明しています。上端に留まっている間だけ見た目を変える方法と、ビューポートの高さが十分なときだけヘッダーを固定する方法を扱います。
