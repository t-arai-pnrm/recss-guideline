Gridでアイテムをそろえる方法は、そろえる範囲で選びます。1つのセルの中やコンテナの中での位置は、配置のプロパティの `*-items` と `*-content` で、そろえる対象を区別して指定します。並べたカードの中の見出しやボタン、一覧の項目の中の列のように、別々のアイテムの中身をそろえるときは、サブグリッドで親のトラックを共有させます。列の幅は、列ごとに可変か不変かを決めてから、`max-content`、`fit-content()`、`1fr` で書きます。

トラック、線、エリアといった用語と、`fr` や `minmax()` によるトラックの大きさの決め方は「[7-8 Gridの基礎](/layout/grid-basics/)」で説明しています。このページでは、それらを前提に、アイテムの位置と列の幅をそろえる方法を説明します。

## Gridでそろえた位置がずれる理由

Gridでそろえたつもりの位置がずれる原因は、大きく2つあります。1つは、配置のプロパティが何をそろえるのかの読み違えです。もう1つは、そろえたい要素が、そもそも同じグリッドのトラックに並んでいないことです。

前者の典型は、`align-items: center` は効くのに `align-content: center` は効かない、あるいはその逆、という場面です。2つはそろえる対象が違うので、同じ値でも結果が変わります。

後者の典型は、横に並べたカードです。見出しの行数や本文の長さがカードごとに違うと、ボタンの位置がばらばらになります。カードを `flex-direction: column` にして本文に `flex-grow: 1` を指定すればボタンの位置はそろいますが、見出しの高さはそろいません。そろえられるのは、伸ばした1か所だけです。見出しに `min-height` を指定したり、JavaScriptで高さを測ったりする方法もありますが、固定の高さは見出しが想定より長くなるとそろわなくなり、JavaScriptは読み込みや再計算の手間がかかります。

```css title="🙅‍♂ Not Recommended: カードの中だけで縦に並べ、本文を伸ばしてボタンを下端に寄せる" issue="behavior"
/* 🙅‍♂ Not Recommended */
article {
  display: block flex;
  flex-direction: column;

  & > p {
    flex-grow: 1;
  }
}
```

次のデモは、この指定でカードを3つ並べたものです。幅を768pxにして3列にすると、ボタンは下端にそろいますが、見出しの行数が多いカードだけ本文の開始位置が下がります。同じカードをサブグリッドでそろえたデモは、後の「サブグリッドでカードの行をそろえる」にあります。

<Demo title="Flexboxで本文を伸ばしても、見出しの高さはカードごとにそろわない" html={subgridHtml} css={subgridBadCss} variant="not-recommended" widths={[320, 768]} />

列の幅でも、似たずれが起きます。画像とテキストを横に並べるカードで、画像の列を `1fr` や固定の長さにすると、画像の幅と列の幅が食い違います。幅300pxの画像を幅480pxの列に置くと、画像が引き伸ばされるか、横に余白が空きます。

## `*-items` と `*-content` の違い

配置のプロパティは、方向と対象の組み合わせでできています。`justify-*` はインライン方向（横書きでは横）、`align-*` はブロック方向（横書きでは縦）を扱います。`*-items` は、各アイテムを自分のグリッドエリアの中でそろえ、`*-self` はそれを1つのアイテムだけ上書きします。`*-content` は、トラックのまとまり全体を、グリッドコンテナの中でそろえます。

`*-items` の初期値 `normal` は、Gridではアイテムをエリアいっぱいに伸ばす `stretch` として働きます。ただし、画像のように縦横比を持つアイテムは、伸ばされず `start` として扱われます。

`*-content` が働くのは、トラックの合計がグリッドコンテナより小さく、余りがあるときだけです。`fr` のトラックは余りをすべて受け取るので、`fr` の列だけのグリッドに `justify-content: center` を指定しても、何も変わりません。トラックの大きさを固定の長さや `max-content` で決めたときに、`place-content: center` でまとまりを中央に寄せたり、`space-between` で両端に散らしたりできます。`*-content` の初期値 `normal` は、`auto` の大きさのトラックを余りの分だけ伸ばします。行を指定していないグリッドに高さを与えると各行が中身の高さより広がるのはこのためで、行を中身の高さのまま上に詰めたいなら、`align-content: start` を指定します。

`place-items` と `place-content` は、`align-*` と `justify-*` をまとめて書くショートハンドです。値を2つ書くときは、ブロック方向の `align-*` が先、インライン方向の `justify-*` が後になります。値が1つなら、両方の方向に同じ値が入ります。なお、Flexboxには `justify-items` と `justify-self` がなく、指定しても無視されます（「[7-7 Flexboxの基礎](/layout/flexbox-basics/)」）。

次のデモは、固定の大きさの2列2行のトラックを、高さ200pxのコンテナに置いたものです。`place-items: center` ではトラックは左上に残り、アイテムがセルの中で縮みます。`place-content: center` ではアイテムはセルいっぱいのまま、トラックのまとまりが中央へ移ります。

<Demo title="place-items と place-content の違い" html={alignmentHtml} css={alignmentCss} />

2つは対象が違うので、組み合わせても打ち消し合いません。アイコンの一覧をコンテナの中央に置き、アイコンもセルの中央に置くなら、両方を指定します。

```css title="🙆‍♂ Recommended: トラックのまとまりとアイテムを、それぞれ中央に置く"
._icon-list {
  display: block grid;
  grid-template-columns: repeat(4, calc(64 / 16 * 1rem));
  place-content: center;
  place-items: center;
}
```

## サブグリッドでカードの行をそろえる

グリッドの孫の要素は、親のグリッドに参加しません。子に `grid-template-rows: subgrid` を指定すると、子は自分の行を持たず、親の行をそのまま使います。子の中の要素は親の行に並ぶので、別々のカードの見出しや本文が、同じ高さの行に入ります。

<Baseline id="subgrid" />

```css title="🙆‍♂ Recommended: カードの行を、並べる側のグリッドの行に参加させる" from="layout/subgrid-cards"
.article-cards {
  display: block grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, calc(200 / 16 * 1rem)), 1fr));
  gap: 24px 16px;

  & > ._card {
    grid-row: span 3;
  }
}

._card {
  display: block grid;
  grid-template-rows: subgrid;
  row-gap: 8px;
}
```

行の高さは、その行でいちばん高い見出しに合わせて決まります。本文とボタンの行も同じなので、見出しや本文の長さがカードごとに違っても、ボタンの位置は横一列にそろいます。カードの行は一覧の行なので、この例では、一覧とカードを `article-cards` という1つのコンポーネントにしています（「[10-1 何をコンポーネントにするか](/components/what-is-a-component/#行をそろえて並べる一覧と項目)」）。

`grid-row: span 3` は、カードが親の行を3行分使うという指定で、中の要素の数と一致させます。指定を忘れると、カードは親の1行分にしかまたがらず、見出しと本文とボタンが同じ1行に押し込まれてしまいます。サブグリッドの行の間隔は、何も指定しなければ親の `gap` を引き継ぐので、カードの中の間隔は `row-gap` で指定し直しています。

サブグリッドにした方向には、暗黙のトラックが作られません。カードに4つ目の要素を足しても、`span 3` のままでは新しい行は増えず、はみ出した要素は最後の行に重なります。要素を足したら、`span` の数も直します。カードごとに要素の数が違い、`span` の数を1つに決められないときは、その方向をサブグリッドにしたままでは解決できません。サブグリッドの行の数は、親から受け継いだ数で決まり、中身から逆算する仕組みがないからです。そろえる行をすべてのカードに共通の部分に限るか、その方向のサブグリッドをやめます。

要素の数がカードごとに違う場合の回避策として、`grid-row: span 99` のように大きめの行数を予約する方法も知られています。中身のない行は高さ0になるので、先頭からの行はそろいます。ただし、親の `row-gap` は空の行の間にも入るので、親の行の間隔を0にしてカードの間隔を別の方法で作る必要があります。また、要素の数が違えば最後の要素は別の行に入るので、末尾のボタンの位置はそろいません。

サブグリッドの中の線の番号は、1から数え直されます。カードの中で `grid-row: 1` と書けば、カードが親のどの行に置かれていても、カードの最初の行を指します。一方、線の名前とエリアの名前は親から引き継がれ、サブグリッドの中のアイテムからもそのまま指定できます。サブグリッドの側で `grid-template-columns: subgrid [--label] [--value]` のように名前の並びを書くと、受け継いだ線に自分用の名前を足すこともできます。

サブグリッドにした要素の `padding` と `border` は、トラックを狭めるのではなく、端のトラックに置かれたアイテムの余白として扱われます。親の行の大きさを決めるときもこの余白が含まれるので、カードの最初と最後の行は、`padding` の分だけ高くなります。次のデモのカードには `padding: 16px` を指定していますが、すべてのカードが同じ余白を持つので、見出しや本文の位置はずれません。幅を768pxにすると3列になり、見出し、本文、ボタンの位置が横一列にそろいます。

## サブグリッドで一覧の列をそろえる

サブグリッドは、列をそろえるときにも使えます。日付、カテゴリ、タイトルを1行ずつ並べるニュースの一覧を考えます。列の幅を決める前に、それぞれの列が可変か不変かを考えます。日付は途中で改行されると読みにくいので、改行しない不変の列です。カテゴリは長すぎると窮屈になるので、上限を決めた可変の列にします。タイトルは、残りの幅をすべて使う可変の列です。

```css title="🙆‍♂ Recommended: 列ごとに可変か不変かを決め、項目の列をサブグリッドでそろえる" from="layout/news-list"
ul {
  display: block grid;
  grid-template-columns: max-content fit-content(calc(160 / 16 * 1rem)) 1fr;
  column-gap: 24px;

  & > li {
    grid-column: 1 / -1;
  }
}

li {
  display: block grid;
  grid-template-columns: subgrid;
  align-items: baseline;
  padding-block: 1rlh;
}
```

1列目の `max-content` は、日付の幅そのものです。日付の列は、中身より狭くならず、改行もされません。2列目の `fit-content()` は、中身の幅に合わせつつ、括弧の中の値を上限にする指定です。カテゴリが短ければ短いなりの幅になり、長ければ160px相当で折り返します。3列目の `1fr` は、残りの幅をすべて受け取ります。

項目の `li` は、親の `ul` のルールに書いた `grid-column: 1 / -1` で親の3列すべてにまたがり、`grid-template-columns: subgrid` で親の列をそのまま使います。どの項目のカテゴリが長くても、列の幅は一覧全体で1つに決まるので、日付、カテゴリ、タイトルの開始位置がすべての行でそろいます。`align-items: baseline` は、文字の大きさが違うカテゴリとタイトルを、文字のベースラインでそろえる指定です。項目の上下の余白には、ルート要素の行の高さを単位にした `1rlh` を使っています。

{/* 要確認: 出典なし */}ただし、一覧を狭い場所に置くと、日付とカテゴリの列に幅を取られて、タイトルの列が極端に細くなります。次のデモでは、一覧のルートをコンテナにして、タイトルが160px相当を確保できない幅ではタイトルを次の行へ移しています。幅を320pxか480pxにすると、タイトルが日付とカテゴリの下の行に移り、768px以上では日付、カテゴリ、タイトルが1行に並んで、各列の開始位置がすべての行でそろいます。

## 画像の幅に合わせて列を決める

画像の幅がカードごとに違うなら、画像の列は「画像の幅まで広がり、上限で止まる」可変の列です。この列には `fit-content()` が合います。

```css title="🙆‍♂ Recommended: 画像の列を画像の幅に合わせ、上限で止める" from="layout/image-card-fit-content"
.image-card {
  container: --scoped / inline-size;
}

._layout {
  --_density: --compact;

  display: block grid;
  reading-flow: grid-rows;
  grid-template:
    "--figure --figure  --figure"
    ".        .         .       " 1rlh
    ".        --heading .       "
    ".        .         .       " 1rlh
    ".        --body    .       "
    ".        .         .       " 1rlh
    / 24px 1fr 24px;

  @container --scoped (inline-size >= calc(240 / 16 * 1rem + 32px + 240 / 16 * 1rem + 32px)) {
    --_density: --spacious;

    grid-template:
      "--figure . .         ." 1.5rlh
      "--figure . --heading ."
      "--figure . .         ." 1.5rlh
      "--figure . --body    ." 1fr
      "--figure . .         ." 1.5rlh
      / fit-content(calc(480 / 16 * 1rem)) 32px minmax(min(100%, calc(240 / 16 * 1rem)), 1fr) 32px;
  }

  & > ._figure {
    grid-area: --figure;
  }

  & > ._heading {
    grid-area: --heading;
  }

  & > ._body {
    grid-area: --body;
  }
}

img {
  inline-size: -webkit-fill-available;
  inline-size: stretch;

  @container style(--_density: --spacious) {
    inline-size: initial;
  }
}

figcaption {
  contain: inline-size;
}
```

広い場所では、画像の列の `fit-content(calc(480 / 16 * 1rem))` が、`width` 属性で決まる画像の幅をそのまま列の幅にします。幅300pxと400pxの画像の列はその幅になり、幅500pxの画像の列は480px相当で止まります。画像は、ベーススタイルの `max-inline-size: 100%` で列の幅まで縮みます。テキストの列は、`1fr` ではなく `minmax(min(100%, calc(240 / 16 * 1rem)), 1fr)` にしています。Gridは、`fr` の列に幅を配る前に、`fit-content()` の列を上限まで広げます。テキストの列に下限がないと、大きな画像のカードでテキストの列が極端に細くなるからです。下限を `min(100%, …)` で包むのは、どの場所に置かれても、下限が親の幅を超えないようにするためです（[`minmax-min-capped-at-100-percent`](/layout-practice/defensive/#rule-minmax-min-capped-at-100-percent)）。テキストの上下の余白は、空の行（`1rlh` と `1.5rlh`）で作っています。

`figcaption` の `contain: inline-size` は、キャプションの長さで画像の列が広がるのを防ぐ指定です。`fit-content()` が合わせる `max-content` は、画像だけでなくキャプションの1行の長さも含みます。指定がないと、長いキャプションを付けた画像の列は、画像の幅に関係なく上限まで広がります。`contain: inline-size` を指定した要素は、中身を幅の計算に含めないので、列の幅は画像だけで決まり、キャプションはその幅の中で折り返します。

<Baseline id="contain-inline-size" />

狭い場所では、画像を上に置いて縦に積み、画像を `stretch` で列の幅まで広げます。広い場所では、フラグ `--_density` が `--spacious` に切り替わり、画像の幅を `initial`（初期値の `auto`。`width` 属性の幅）に戻します。エリアの名前は、置く子要素のクラス `._figure` にそろえて `--figure` にしています。HTMLには見出しを先に書き、見た目では画像を先に表示するので、`reading-flow: grid-rows` を指定しています。HTMLを文書構造の順番で書き、見た目の順番をエリアで変える書き方は「[7-8 Gridの基礎](/layout/grid-basics/#rule-source-order-for-reading)」で説明しています。

次のデモでは、幅300px、400px、500pxの画像のカードを並べています。幅を1024pxにすると、画像の列がそれぞれの画像の幅と480px相当の上限で決まり、長いキャプションを付けた2枚目も画像の幅のままです。

## 補足と注意点

サブグリッドにできるのは、グリッドの直接の子だけです。カードを `<li>` で包んでいるなど、グリッドとカードの間に別の要素があるときは、その要素に `display: contents` を指定して箱をなくします。箱をなくした要素はブラウザによって暗黙のロールを失うので、`<li>` や `<section>` なら `role` 属性でロールを明示します。使ってよい場面と注意点は「[7-12 display: contentsで箱をなくす](/layout/display-contents/)」で説明しています。

サブグリッドを使うカードは、親がグリッドであることを前提にしています。そのため、カードを並べる側のグリッドまで含めて、1つのコンポーネントとして扱います。この考え方は「[10-2 コンポーネントの境界を守る](/components/boundaries/)」で説明しています。

中身の幅で大きさが決まるトラックに置くアイテムは、コンテナにしません。コンテナには `contain: inline-size` と同じ封じ込めが付くので、画像カードの `figure` をコンテナにすると、画像の幅が列に伝わらず、列の幅が0まで縮みます。上の例でコンテナにしているのはカードのルートで、ルートの幅はカードを置いた場所から決まります。封じ込めの副作用は「[13-4 コンテナの副作用とコンテナ単位](/responsive/container-units-and-side-effects/)」で説明しています。
