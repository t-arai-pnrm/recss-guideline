Gridは、親の要素で線とトラック（行と列）を決め、子をその線に合わせて置くレイアウトの方式です。トラックの大きさは、`fr`、`max-content`、`fit-content()`、`minmax()` で書きます。行の数がアイテムの数で変わるなら、行は `grid-template-rows` ではなく `grid-auto-rows` で決めます。意味のある位置に置くアイテムは、線の番号ではなく、`--` で始まる線の名前かエリアの名前で指定します。

Gridの指定で読み違えが起きやすいのは、明示的なグリッドと暗黙のグリッドの区別と、トラックの最小幅を中身で決めるのか0にするのかの区別です。このページでは、この2つを中心に、グリッドの用語、トラックの大きさ、線とエリアによる配置を説明します。配置のプロパティでアイテムをそろえる方法と、サブグリッドで行や列をそろえる方法は「[7-9 Gridでアイテムをそろえる](/layout/grid-alignment/)」で、レイアウトの手法の中からGridを選ぶ基準は「[11-1 レイアウト手法の選び方](/layout-practice/choosing/)」で扱います。

## Gridの指定はどこで読み違えられるのか

Gridは2017年から主要なブラウザで使えますが、Gridを使ったコードには、書いた人の意図と違う振る舞いがよく紛れ込みます。原因の多くは、構文の誤りではなく、グリッドの仕組みの読み違えです。

典型的なのは、`grid-row: 1 / -1` でサイドバーを全行にまたがらせたつもりが、途中の行で止まってしまう例です。`-1` は、アイテムが増えて足された行を数に入れないからです。

行の大きさでも同じ種類の読み違えが起こります。`grid-template-rows: repeat(2, 160px)` と書いたカードの一覧で、3行目のカードだけが160pxではなく中身の高さで並ぶ、という現象です。3行目は、`grid-template-rows` の指定が届かない、ブラウザが足した行だからです。

長いURLを含む `1fr` の列だけがほかの列より広がる、という現象もあります。どれも仕様どおりの振る舞いなので、値を足して見た目を合わせる前に、どの規則が働いているかを確かめます。

次の例には、最初の2つの読み違えが含まれています。カードの数が増えると、3行目から高さがそろわなくなり、サイドバーも2行目で止まります。

```css title="🙅‍♂ Not Recommended: 行の数が変わるグリッドで、行を明示的に決め、負の線番号でまたがらせる" issue="behavior"
/* 🙅‍♂ Not Recommended */
._layout {
  display: block grid;
  grid-template-columns: calc(240 / 16 * 1rem) 1fr 1fr;

  /* 3行目からは暗黙の行になり、160px にならない */
  grid-template-rows: repeat(2, 160px);

  & > ._sidebar {
    /* -1 は明示的な2行の終わりの線なので、3行目以降にはまたがらない */
    grid-row: 1 / -1;
  }
}
```

## グリッドを構成するものの名前

`display: block grid` を指定した要素をグリッドコンテナ、その直接の子をグリッドアイテムと呼びます。孫の要素はアイテムではないので、親のグリッドには参加しません。孫を親のトラックに合わせたいときは、子をサブグリッドにします（「[7-9 Gridでアイテムをそろえる](/layout/grid-alignment/)」）。要素に包まれていない文字も、匿名のアイテムとして1つのセルを占めます。

グリッドを区切る線をグリッド線と呼びます。隣り合う2本の線の間の帯がトラックで、横方向に並ぶものが列、縦方向に並ぶものが行です。3列のグリッドには、列の線が4本あります。線の番号は、インライン方向とブロック方向の始まりの側から1、2、3と数え、終わりの側からは-1、-2と数えます。始まりの側は書字方向で決まり、`direction: rtl` の文書では右端が1本目の線になります。

1つの行と1つの列が交わる区画をセルと呼び、これがグリッドの最小の単位です。4本の線で囲まれた、1つ以上のセルからなる長方形の範囲をグリッドエリアと呼びます。アイテムは、線を指定してエリアに置かれます。トラックとトラックの間の隙間は、`gap` で作る溝（ガター）です。

次の指定は、下の図と同じ3列2行のグリッドを作ります。コメントに、それぞれの指定が作るものの名前を書いています。

```css
._grid {
  /* グリッドコンテナ。直接の子がグリッドアイテムになる */
  display: block grid;

  /* 列のトラックが3本、列の線は1〜4（-4〜-1）の4本 */
  grid-template-columns: repeat(3, 1fr);

  /* 行のトラックが2本、行の線は1〜3（-3〜-1）の3本 */
  grid-template-rows: repeat(2, calc(80 / 16 * 1rem));

  /* トラックの間の溝 */
  gap: 16px;

  & > ._wide {
    /* 列の線3〜4、行の線1〜3で囲まれた、2セル分のグリッドエリアに置く */
    grid-area: 1 / 3 / 3 / 4;
  }
}
```

## トラックの大きさを決める `fr`、`fit-content()`、`minmax()`、`repeat()`

列の大きさは `grid-template-columns`、行の大きさは `grid-template-rows` に、トラックごとの値を空白で区切って並べます。値には、長さ、中身の大きさを表す `min-content`、`max-content`、`auto`、そして `fr` が使えます。

`fr` は、固定の大きさのトラックと `gap` を引いた残りの空間を、比率で分ける単位です。`calc(200 / 16 * 1rem) 2fr 1fr` なら、200px相当の列と溝を除いた残りを、2対1で分けます。溝を除いてから分けるので、`%` で分けたときのように、列の合計が溝の分だけ親の幅を超えることはありません。

同じ理由で、グリッドアイテムの大きさに、親の大きさを前提にした `%` を書かないようにします。グリッドアイテムの `%` は、親ではなく、アイテムが置かれたグリッドエリアを基準に解決されます。`place-content: center` で中央に寄せたグリッドのアイテムに `inline-size: 50%` と書いても、トラックがアイテムの中身の大きさで決まっていれば、その50%にしかなりません。大きさは、トラックの側で `fr` と `minmax()` を使って決めます。

```css title="🙆‍♂ Recommended: 固定の列を除いた残りを、fr の比率で分ける"
._layout {
  display: block grid;
  grid-template-columns: calc(200 / 16 * 1rem) 2fr 1fr;
}
```

中身の大きさを表すキーワードは、折り返しの扱いで区別します。`max-content` は、中身を1か所も折り返さずに並べたときの幅です。`min-content` は、折り返せる位置ですべて折り返したときの幅で、いちばん長い単語や画像の幅になります。文章を含む列を `min-content` にすると、単語や文字ごとに折り返されるので、`min-content` は画像やボタンのように折り返さない中身の列に限ります。

`fit-content(上限)` は、トラックを中身の `max-content` に合わせ、上限で頭打ちにする関数です。中身が短ければ短いなりの幅になり、長ければ上限の幅で折り返します。下限は `auto` なので、`min-content` が上限より大きい中身では、トラックは上限を超えて `min-content` まで広がります。`auto` の下限とアイテムの `min-inline-size` の関係は、次の「アイテムの最小幅と `gap`」で説明します。

次のデモは、2列目を `1fr` にそろえ、1列目の値だけを変えて同じ文章を置いたものです。幅を320pxにすると、`1fr` と `fit-content(120px)` の列は文章を折り返し、`max-content` の列は折り返さずに幅を取ります。`min-content` の列は、和文が1文字ごとに折り返せるので、1文字分の幅まで狭まります。

<Demo title="fr、max-content、min-content、fit-content() のトラックの幅" html={trackSizingHtml} css={trackSizingCss} widths={[320, 768]} />

`max-content`、`fit-content()`、`fr` は、列ごとに「中身に応じて幅が変わってよいか」を決めてから選びます。改行させたくない不変の列は `max-content`、上限まで中身に合わせる可変の列は `fit-content()`、残りの幅をすべて受け取る可変の列は `fr` です。この選び方を、ニュースの一覧と画像を並べるカードに当てはめた例は「[7-9 Gridでアイテムをそろえる](/layout/grid-alignment/)」で示します。

`minmax(最小, 最大)` は、トラックの大きさに下限と上限を付ける関数です。最大が最小より小さいときは、最大が無視され、最小の値になります。`fr` は最大の側にだけ書けて、`minmax(1fr, 200px)` のように最小の側に書くと、宣言全体が無効になります。単独で書いた `1fr` は、`minmax(auto, 1fr)` として扱われます。この `auto` の下限が「`1fr` が等分にならない」原因で、仕組みは次の「アイテムの最小幅と `gap`」で説明します。

`repeat(回数, トラック)` は、同じトラックの並びを繰り返す関数です。`repeat(3, 1fr)` は等分の3列になり、`repeat(2, 2fr 1fr)` のように複数のトラックの組も繰り返せます。回数の代わりに `auto-fill` か `auto-fit` を書くと、最小の幅を下回らない範囲で入るだけの列を作ります。2つの違いはアイテムが列の数より少ないときに現れ、`auto-fill` は空の列を残し、`auto-fit` は空の列を幅0に折りたたみます。使い分けは「[13-1 検討する順番](/responsive/escalation/)」と「[12-7 grid](/compositions/grid/)」で説明しています。

## アイテムの最小幅と `gap`

グリッドアイテムの `min-inline-size` の初期値 `auto` は、0ではありません。下限が `auto` のトラックにまたがるアイテムでは、中身の最小幅（`min-content` に近い値）が下限になります。単独の `1fr` は `minmax(auto, 1fr)` なので、長いURLや幅の大きい入力欄を含むアイテムは、その下限まで列を押し広げます。例外は、`overflow: auto` などでスクロールコンテナになったアイテムで、この場合の下限は0です。

防ぎ方は2つあります。1つは、トラックの側で `minmax(0, 1fr)` と書き、列の下限を0にする方法です。もう1つは、ベーススタイルの全称セレクタで `min-inline-size: 0` を指定し、アイテムの下限を0にする方法です（「[8-2 ベーススタイルに書くもの](/reset/base-styles/#rule-global-min-inline-size-zero)」）。本書は後者を使い、列は `1fr` のまま書きます。アイテムの下限が0なら、下限が `auto` のトラックの下限も0になるからです（「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/#rule-fr-without-minmax-zero)」）。

次のデモは、`1fr 1fr` のグリッドに長いURLを置いたものです。上のグリッドだけ、アイテムの `min-inline-size` を初期値の `auto` に戻しています。幅を320pxにすると、上のグリッドではURLの列が押し広げられて等分にならず、下のグリッドではURLが列の中で折り返します。デモの環境は `overflow-wrap: anywhere` を継承しており、そのままではURLの最小幅が小さくなって列が広がりません。そこで、最小幅の計算では折り返さない `break-word` を `overflow-wrap` に指定して、違いを見せています。

<Demo title="アイテムの min-inline-size が auto のときと0のときの 1fr の列" html={minSizeHtml} css={minSizeCss} widths={[320, 768]} />

アイテムの間隔は、アイテムの `margin` ではなく、コンテナの `gap` で作ります（「[11-2 余白を設計する](/layout-practice/spacing/#rule-gap-over-child-margin)」）。`gap` は行の間隔と列の間隔を順に書くショートハンドで（次の例では行の間が24px、列の間が16px）、片方だけなら `row-gap` か `column-gap` で指定します。溝はトラックとトラックの間にだけ作られ、グリッドの外周にはできません。

```css title="🙆‍♂ Recommended: アイテムの間隔を、コンテナの gap で作る"
._list {
  display: block grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 24px 16px;
}
```

溝はトラックではないので、線の番号にも数えられません。一方、溝は空のトラックの間にも作られます。`auto-fit` で折りたたまれた列の溝は一緒に消えますが、暗黙の行がたくさん作られたグリッドでは、高さ0の空の行の間にも溝が残ります。アイテムの数より行が多くなる指定をしたときは、溝の積み重なりで余白が広がっていないかを確かめます。

## 明示的なグリッドと暗黙のグリッド

`grid-template-*` のプロパティで決めたトラックを、明示的なグリッドと呼びます。アイテムが明示的なセルより多いときや、外の線を指定されたときにブラウザの足すトラックを、暗黙のグリッドと呼びます。暗黙のトラックの大きさは、`grid-auto-rows` と `grid-auto-columns` で決まり、どちらも初期値は `auto`（中身の大きさ）です。

カードの一覧のように、行の数がアイテムの数で決まるグリッドでは、行を明示的に決める意味がありません。`grid-template-rows: repeat(2, 160px)` と書くと、3行目からは暗黙の行になり、160pxではなく中身の高さで並びます。行の大きさを `grid-auto-rows` で決めれば、何行になっても同じ高さで並びます。

```css title="🙅‍♂ Not Recommended: アイテムの数で行数が変わるのに、行を明示的に決める" issue="behavior"
/* 🙅‍♂ Not Recommended */
._gallery {
  display: block grid;
  grid-template-columns: repeat(3, 1fr);
  grid-template-rows: repeat(2, 160px);
}
```

```css title="🙆‍♂ Recommended: 暗黙の行の大きさを grid-auto-rows で決める"
._gallery {
  display: block grid;
  grid-template-columns: repeat(3, 1fr);
  grid-auto-rows: calc(160 / 16 * 1rem);
}
```

次のデモは、3列のグリッドにアイテムを7つ置いたものです。左のグリッドは、`grid-template-rows: repeat(2, 64px)` で2行だけを明示的に決めています。3行目は暗黙の行になり、高さは64pxではなく中身の高さです。`1 / -1` のアイテムは `grid-row: 1 / -1` ですが、明示的な2行にしかまたがりません（負の番号の数え方は、次の「線の番号と線の名前でアイテムを置く」で説明します）。

右のグリッドは、`grid-auto-rows: 64px` で暗黙の行の大きさを決めています。どの行も64pxにそろいますが、明示的な行がないので、`1 / -1` のアイテムは1行分にとどまります。

<Demo title="明示的な行と暗黙の行、負の線番号の範囲" html={implicitHtml} css={implicitCss} />

アイテムを自動で置く向きは、`grid-auto-flow` で決まります。初期値の `row` では、アイテムを行の端まで順に詰め、足りなくなると暗黙の行を足します。`column` にすると、列の方向に詰め、足りなくなると暗黙の列を足します。`grid-auto-flow: column` と `grid-auto-columns: 1fr` を組み合わせると、アイテムがいくつあっても1行に等分で並ぶ、ステップ表示のような並びが書けます。

`grid-auto-flow` に `dense` を加えると、複数のトラックにまたがるアイテムのせいで空いたセルへ、後ろのアイテムを先に詰めます。隙間は消えますが、見た目の順番だけが変わり、DOMの順番は変わりません。キーボードの移動と読み上げはDOMの順番のままなので、`dense` はタグやサムネイルの一覧のように、順序に意味のない並びに限ります。フォーカスできる要素や、手順、ランキングを並べたグリッドには指定しません。高さの違う項目を短い列へ詰める `display: block grid-lanes` でも、同じ種類の食い違いが起こります。その対処は「[11-11 grid-lanesで石積みのレイアウトを組む](/layout-practice/masonry/)」で説明しています。

## 線の番号と線の名前でアイテムを置く

アイテムを置く位置は、`grid-column` と `grid-row` に、始まりの線と終わりの線を `/` で区切って指定します。`grid-column: 2 / 4` は、2本目から4本目の線までの2列にまたがります。終わりの線の代わりに `span 2` と書くと、始まりの線から2トラック分にまたがります。明示的なグリッドより外の線を指定すると、そこまで暗黙のトラックが足されます。

終わりの側から数える負の番号は、明示的なグリッドの端から数えます。暗黙のトラックは数に入りません。`grid-column: 1 / -1` は、列を明示的に決めたグリッドでは端から端まで確実にまたがります。一方、行を決めていないグリッドで `grid-row: 1 / -1` と書くと、`-1` は1本目の線と同じになり、アイテムは1行分にしかまたがりません。

線には名前を付けられます。`grid-template-columns` のトラックの間に `[--content-start]` のように角括弧で名前を書き、アイテムの側でその名前を指定します。本書では、自分で付ける線とエリアの名前を `--` で始めます（「[9-1 命名規則](/notation/naming/)」）。`--content-start` と `--content-end` のように、`-start` と `-end` で終わる名前の組を付けると、その間は `--content` という名前のエリアとして扱われます。アイテムは `grid-column: --content` だけで置けます。

```css title="🙆‍♂ Recommended: 線に名前を付け、アイテムは名前で置く"
._page {
  display: block grid;
  grid-template-columns:
    [--full-start] minmax(16px, 1fr)
    [--content-start] minmax(0, calc(960 / 16 * 1rem))
    [--content-end] minmax(16px, 1fr)
    [--full-end];

  & > * {
    grid-column: --content;
  }

  & > ._hero {
    grid-column: --full;
  }
}
```

この例では、本文の列の左右に余白の列（ガター）を置き、通常のアイテムは本文の列に、`._hero` だけは画面の端から端まで置いています。同じ配置を `grid-column: 2 / 3` と `1 / 4` で書くと、列を1本足しただけで、すべてのアイテムの番号を直すことになります。名前なら、列を足しても名前の位置は変わらず、コードを読めば何の位置に置くのかが分かります。ガターの列を使う設計は「[11-2 余白を設計する](/layout-practice/spacing/#rule-gutter-columns-for-content-width)」で説明しています。

次のデモは、同じ指定で本文の列の上限を480px相当にしたものです。幅を768pxにすると、本文の列の左右に余白の列が広がり、`._hero` だけが余白の列までまたがります。

<Demo title="線の名前で、本文の列と端から端までの列に置き分ける" html={namedLinesHtml} css={namedLinesCss} widths={[320, 768]} />

名前を書き間違えたときの振る舞いは、見落としやすいので知っておきます。指定した名前の線がグリッドにないと、ブラウザは暗黙のトラックの線がすべてその名前を持つものとみなし、エラーを出さずに、アイテムを明示的なグリッドの外に置きます。配置がずれたときは、まず名前の綴りを確かめます。`grid-template-areas` で付けたエリアの名前も、同じように `-start` と `-end` の線の名前を作ります。

## `grid-template` のエリアに名前を付ける

幅によって配置の構造が変わるレイアウトは、`grid-template` のエリアに名前を付けて書きます。エリアの名前は、そのエリアに置く子要素のクラス名とそろえ、`--` で始めます。`._image` を置くエリアは `--image` です。`--` で始める理由は、前の「線の番号と線の名前でアイテムを置く」で述べたとおりです。

```css title="🙆‍♂ Recommended: エリアに名前を付け、条件ごとにテンプレートだけを書き換える" from="layout/grid-basics-areas"
.feature-card {
  container: --scoped / inline-size;
}

._layout {
  display: block grid;
  reading-flow: grid-rows;
  grid-template:
    "--image"
    "--heading"
    "--body";

  @container --scoped (inline-size >= calc(560 / 16 * 1rem)) {
    grid-template:
      "--image --heading"
      "--image --body" 1fr
      / 1fr 1fr;
  }

  & > ._heading {
    grid-area: --heading;
  }

  & > ._body {
    grid-area: --body;
  }

  & > ._image {
    grid-area: --image;
  }
}
```

```html
<article class="scoped feature-card">
  <div class="_layout">
    <h2 class="_heading">…</h2>
    <div class="_body">…</div>
    <img class="_image" src="…" alt="" width="640" height="480">
  </div>
</article>
```

狭い場所では、画像、見出し、本文の順で縦に積みます。広い場所では、画像を左側、見出しと本文を右側へ置いています。クエリの中で書き換えているのは `grid-template` だけで、子要素の配置の指定は1か所ずつしかありません。テンプレートの文字列が、そのまま配置の図として読めるのも利点です。

テンプレートの書き方には、宣言全体を無効にする規則が2つあります。1つは、各行の文字列に同じ数のセルを書くことです。もう1つは、同じ名前を書いたセルが1つの長方形を作ることです。L字の形に並べたり、離れた2か所に同じ名前を書いたりすると、そのエリアだけでなく宣言全体が無効になります。エリアに置かない空きのセルは、名前の代わりに `.` を書きます。

```css title="🙅‍♂ Not Recommended: 同じ名前のセルをL字に並べる" issue="behavior"
/* 🙅‍♂ Not Recommended */
._layout {
  grid-template:
    "--image --heading"
    "--image --image";
}
```

無効になった宣言は、構文の誤りと同じように読み込みの時点で捨てられ、前に書いた宣言が残ります。上の例のテンプレートを `@container` の中に書くと、どの幅でも1列のテンプレートのままになり、エラーも出ません。配置がクエリで切り替わらないときは、名前の綴りとあわせて、各行のセルの数と長方形の形を確かめます。L字のような形が要るなら、エリアを2つに分けて別々の要素を置くか、1つの要素を長方形のエリアに置き、その中で並べます。

次のデモは、この例に余白と文字の大きさを足して動かしたものです。幅を320pxと768pxで比べると、子要素の指定は変わらないまま、テンプレートの書き換えだけで配置が変わります。

<Demo title="エリアの名前を使い、幅に応じてテンプレートだけを書き換える" html={areasHtml} css={areasCss} widths={[320, 768]} />

子要素の `grid-area` は、親のルールの中に `& > ._heading` のようにネストして書いています。`grid-area` は、親のテンプレートとセットで初めて意味を持つ指定だからです。こうしておくと、どのグリッドに対する配置なのかが読み取れ、テンプレートを書き換えるときも一緒に直せます。ネストしてよい場面は「[9-5 ネストの書き方](/notation/nesting/)」で説明しています。

この例では、HTMLには見出しを先に書き、見た目では画像を先に表示しています。HTMLは見た目の順番ではなく、見出しから始まる文書構造の順番で書き、見た目の順番はGridの配置で変えます。スクリーンリーダーの読み上げや、CSSが適用されない環境でも、内容が意味の通る順番で伝わるからです。

ただし、リンクやボタンのようにフォーカスできる要素を並べ替えると、キーボードで移動する順番が見た目と食い違います。見た目の順番に合わせて移動させる `reading-flow` というプロパティもありますが、対応しているのはChromeとEdgeの137以降だけです。フォーカスできる要素は、HTMLの順番と見た目の順番をそろえておきます。上の例のように `grid-template` で並べ替えるときは、同じルールに `reading-flow` も指定します。理由と値の選び方は「[11-12 表示順と読み上げ順を合わせる](/layout-practice/reading-flow/)」で説明しています。
