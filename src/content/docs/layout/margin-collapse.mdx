通常フローでは、ブロック方向で隣り合う2つ以上の `margin` は、足し算されず、1つにまとまります。これをマージンの相殺（margin collapsing）と呼びます。まとまった余白の大きさは、正の値どうしなら大きいほうの値です。上の要素の `margin-block-end: 24px` と下の要素の `margin-block-start: 40px` が隣り合えば、間は64pxではなく40pxになります。

相殺は、兄弟の間だけでなく、親と最初の子、親と最後の子、中身のない要素の上下の間でも起きます。一方で、FlexboxやGridのアイテム、`display: flow-root` の要素とその子の間、`float` や絶対配置の要素では起きません。余白が思った大きさにならないときは、値を調整する前に、その `margin` がどの要素の `margin` と隣り合っているかを確かめます。

相殺は、余白を打ち消す仕組みではなく、隣り合う要素の余白のうち大きいほうが採られる仕組みです。`margin` を「前後の要素から最低これだけ離したい」という距離と捉えれば、段落や見出しが続く本文では、余白が重なって広がりすぎるのを防ぐ便利な仕組みです。一方、`margin` でカードやセクションを並べるレイアウトでは、思わぬずれを生みます。`margin` をこう捉える理由と、本書がレイアウトの間隔を親の `gap` で、文章の要素の間を `margin` で作る書き分けは、「[7-5 marginの役割](/layout/margin-role/)」で説明しています。

子の `margin` を残したまま親子の相殺を止めたいときは、親に `display: block flow-root` を指定します。`overflow: hidden` や見えない `padding` でも止まりますが、副作用があるか、止める意図がコードから読み取れません。この節では、相殺の規則と、止め方の選び方を説明します。

## 余白が足し算にならない場面

お知らせの一覧の見出しの下に24px、本文の段落の上に40pxの余白を付けたとします。デザインカンプでは2つの余白を合わせた64pxの間隔を想定していても、ブラウザでは40pxになります。2つの `margin` が相殺し、大きいほうだけが残ったからです。

```css title="🙅‍♂ Not Recommended: 上下の両方に margin を付けて、合計の間隔を期待する" issue="behavior"
/* 🙅‍♂ Not Recommended */
._heading {
  margin-block-end: 24px;
}

._lead {
  margin-block-start: 40px;
}
```

親と子の間でも、似たことが起きます。背景色を付けたセクションの見出しに `margin-block-start: 32px` を付けると、セクションの背景の内側ではなく、セクションの外側に32pxの余白ができます。見出しの `margin` が、セクション自身の `margin-block-start` と相殺して、親の外へ出るからです。セクションの背景は見出しの上端から始まり、余白の部分には背景が付きません。

どちらの場面でも、CSSの指定に誤りはありません。ずれの原因は値ではなく、通常フローで隣り合う `margin` をまとめる規則にあります。この規則を知らないまま、`padding-block-start: 1px` や `overflow: hidden` で直すと、なぜ直ったのかがコードから読み取れなくなります。

2つの場面では、`margin` に、合計で決まる間隔や背景の内側の余白という、前後の要素との最低限の距離とは別の意味を持たせています。間隔を親の `gap` で、背景の内側の余白を親の `padding` で作れば、そもそも相殺は起きません（「[7-5 marginの役割](/layout/margin-role/)」）。それでも、本文の `margin` や、親の外へ出た子の余白を読み解くには、相殺の規則を知っておく必要があります。

## 相殺が起きる場面

相殺するのは、ブロック方向の `margin` だけです。横書きでは上下の `margin` が相殺し、左右の `margin` は隣り合っても足し算になります。縦書きではブロック方向が横になるので、左右の `margin` が相殺します。物理的な上下ではなく、`writing-mode` が決めるブロック方向を基準にします（「[7-1 レイアウトの基礎](/layout/fundamentals/)」）。

1つ目の場面は、通常フローで隣り合う兄弟です。上の要素の `margin-block-end` と、すぐ下の要素の `margin-block-start` が相殺します。「隣り合う」は、2つの `margin` の間に、行（文字やインラインの要素が並んだ行ボックス）、`padding`、`border` のどれもないことを指します。HTMLのタグの間の改行や空白は、それだけでは行を作らないので、相殺を妨げません。

2つ目の場面は、親と最初の子、親と最後の子です。親に `border-block-start` と `padding-block-start` がなく、最初の子の前に文字もなければ、子の `margin-block-start` は親の `margin-block-start` と隣り合い、相殺します。親の `margin-block-start` が0でも相殺は起き、子の余白が親の外へ出ます。下の端でも同じことが起きますが、こちらは親の `block-size` が `auto` のときに限られます。

```css title="🙅‍♂ Not Recommended: 背景の内側の余白を、最初の子の margin で取ろうとする" issue="behavior"
/* 🙅‍♂ Not Recommended */
._section {
  background-color: var(--background--surface);
}

._heading {
  margin-block-start: 32px;
}
```

この例では、`._section` が `padding` と `border` を持たないので、見出しの32pxはセクションの外側にできます。

3つ目の場面は、中身のない要素です。`padding`、`border`、中身のいずれもなく、高さが0の要素では、自分の `margin-block-start` と `margin-block-end` が隣り合って1つにまとまり、さらに前後の兄弟の `margin` と相殺します。空の要素の `margin` は、前後の余白を通り抜けて1か所にまとまります。CMSの本文に入った空の `<p>` が余白を増やさないのは、この規則によるものです。

<Figure src="layout/margin-collapse-cases" alt="margin が相殺する3つの場面を、上から順に3つの図で示したもの。margin は、アクセント色の半透明の破線の帯で描いている。1つ目は兄弟どうしで、上の要素Aの下の24pxの帯と、下の要素Bの上の40pxの帯が重なって1つになり、間は64pxではなく40pxになる。2つ目は親と最初の子で、親にborderとpaddingがないため、最初の子の上の24pxの帯が親の外へ出て、親の背景の外に空きができる。3つ目は中身のない要素で、高さ0の空の要素の上下のmarginも、前後のmarginと1つにまとまり、AとBの間は最大の32pxになる。" />

次のデモは、段落、空の `<p>`、`<hr>` を並べた本文です。左は通常フローで、`* + :not(hr)` で区切り線を除く2つ目以降の要素に `margin-block-start: 16px` を付けています。右はGridで、`gap: 16px` で間隔を作っています。`<hr>` は、どちらも上下に24pxの `margin` を持ちます。

<Demo title="空の p と hr の余白は、通常フローでは相殺し、Grid では gap に足される" html={emptyHtml} css={emptyCss} variant="neutral" />

通常フローでは、空の `<p>` の `margin` が前後の16pxと相殺して通り抜けるので、1つ目と2つ目の段落の間は16pxです。`<hr>` は `border` を持つので通り抜けませんが、自分の24pxと前後の16pxが相殺し、線の上下はどちらも24pxになります。Gridでは、空の `<p>` の前後に `gap` が1つずつ空いて32pxになり、`<hr>` の上下は16pxと24pxを足した40pxになります。

## 相殺した余白の大きさ

正の値どうしが相殺すると、余白は大きいほうの値になります。24pxと40pxなら40pxです。2つの値が等しければその値のままで、16pxと16pxは16pxです。

負の値が混ざると、計算が変わります。正の値と負の値が相殺するときは、2つを足します。30pxと-20pxなら10px、25pxと-25pxなら0pxです。負の値どうしなら、絶対値の大きいほうが残り、-25pxと-75pxでは-75pxになって、下の要素は上の要素に75px重なります。

3つ以上の `margin` が相殺することもあります。CSS 2.2の仕様では、相殺に加わる正の値のうち最大のものから、負の値のうち絶対値が最大のものを引きます。上の要素の `margin-block-end: 40px` に、ラッパーの `margin-block-start: -16px` とその最初の子の `margin-block-start: 24px` が続くと、3つが1か所で相殺します。正の値の最大は40px、負の値の絶対値の最大は16pxなので、間は24pxです。

<Figure src="layout/margin-collapse-sizes" alt="相殺した margin の大きさを、数直線の上の棒で示した図。縦の破線が0で、右が正の値、左が負の値。灰色の棒が相殺に加わる margin、アクセント色の棒が相殺した結果。1行目の正と正は、24pxと40pxが相殺して、大きいほうの40px。2行目の正と負は、30pxと-20pxを足して10px。3行目の負と負は、-25pxと-75pxのうち、絶対値の大きいほうの-75px。4行目の3つ以上は、40pxと-16pxと24pxで、最大の正の値40pxから、負の値の絶対値の最大16pxを引いて24px。" />

次のデモでは、2つの兄弟の `margin` を3通りに組み合わせています。正と正では間が40px、正と負では10pxになり、負と負ではBがAに24px重なります。

<Demo title="正と負の組み合わせで、相殺した余白の大きさが変わる" html={sizesHtml} css={sizesCss} variant="neutral" />

親子と兄弟の相殺が重なると、1か所に4つ以上の `margin` が集まることもあります。加わる `margin` が増えるほど、どの指定で間隔が決まっているのかを追いにくくなります。本書が子の `margin` で間隔を作らない理由の1つは、この追いにくさです。

次の悪い例は、見出しの直後だけ間を詰めるために、段落に負の `margin` を足したものです。間は24pxと-16pxを足した8pxになりますが、その値は相殺の計算を知らないと読み取れません。

```css title="🙅‍♂ Not Recommended: 相殺の計算に頼って、負の margin で間を詰める" issue="behavior"
/* 🙅‍♂ Not Recommended */
._heading {
  margin-block-end: 24px;
}

._heading + ._lead {
  margin-block-start: -16px;
}
```

```css title="🙆‍♂ Recommended: 見出しの直後の間は、後ろの要素の margin-block-start だけで決める"
._body {
  & > * + * {
    margin-block-start: 24px;
  }

  & > :is(:heading, h1, h2, h3, h4, h5, h6) + * {
    margin-block-start: 8px;
  }
}
```

見出しに下の `margin` を付けなければ、相殺に加わる値は後ろの要素の1つだけになり、指定した8pxがそのまま間になります。

## 相殺が起きない場面

`margin` の間に何かが挟まると、相殺は起きません。親と子の間なら、親の `padding` や `border` が1pxでもあれば、子の `margin` は親の内側に留まります。兄弟の間に文字だけの行があったり、`<br>` が挟まったりした場合も同じです。インラインの要素や `inline flow-root` の要素も行を作るので、その前後の `margin` は相殺しません。

```css title="🙆‍♂ Recommended: 親の padding が挟まると、子の margin は親の内側に留まる"
._section {
  padding-block: 16px;
  background-color: var(--background--surface);
}
```

次のデモでは、同じ `margin-block-start: 24px` の子を2つの親に入れています。`padding` のない親では、24pxが親の外へ出て、点線の枠と背景の間に空きができます。`padding-block: 16px` の親では、24pxが `padding` の内側に留まり、背景の上端から子までが40pxになります。

<Demo title="親の padding が挟まると、子の margin は親の外へ出ない" html={blockedHtml} css={blockedCss} variant="neutral" />

高さの指定は、片側にだけ影響します。親に `block-size` を指定すると、最後の子の `margin-block-end` は親の外へ出なくなります。`min-block-size` は、CSS 2.2の注記では0でなければ外へ出るのを止めるとされていますが、Chromeで確かめたところ、止めたのは値が中身の高さを超えて親の高さを変えたときだけでした。中身より小さい `min-block-size: 1px` では、`margin-block-end` は親の外へ出ました。最後の子の `margin` を確実に親の中に留めたいときは、`min-block-size` に頼らず、`padding` か `border` を挟みます。{/* 要検証: ブラウザ。Firefox と Safari で、中身より小さい min-block-size の親から最後の子の margin-block-end が外へ出るか */}

一方で、最初の子の `margin-block-start` は、親の高さに関係なく親の外へ出ます。空の要素も、0より大きい `block-size` か `min-block-size` を指定すると上下の `margin` が隣り合わなくなり、通り抜けは起きません（値が0なら、指定していても通り抜けます）。

`gap` は、通常フローのブロックコンテナでは働きません。`gap` が働くのはFlexbox、Grid、段組みで、FlexboxとGridではそもそも相殺が起きません。フレックスアイテムとグリッドアイテムの `margin` は、隣のアイテムや親の `margin` と相殺せず、`gap` に足されます。`gap: 16px` の中で要素に `margin-block-start: 24px` を付けると、間は40pxになります。

新しいブロック整形コンテキストを作る要素は、子の `margin` を外へ出しません。`display: flow-root`、`overflow` が `visible` と `clip` 以外の要素、`float` した要素、`inline flow-root` の要素がこれにあたります。また、`float` した要素と絶対配置の要素は通常フローから外れるので、自分の `margin` がほかの要素の `margin` と相殺することもありません。ルート要素（`<html>`）の `margin` も相殺しません。

## 相殺を止めるときの `display: flow-root`

相殺を止める必要があるのは、子の `margin` を残したまま、その余白を親の内側に収めたいときです。本文の領域を包む要素に背景を付けた場合や、CMSで入力された本文の最初の見出しが `margin-block-start` を持つ場合がこれにあたります。並べる間隔や背景の内側の余白を新しく作るだけなら、親の `gap` や `padding` で足ります（「[7-5 marginの役割](/layout/margin-role/)」）。

その場合は、親に `display: block flow-root` を指定します（ルール「[`flow-root-for-margin-collapse`](/layout-practice/spacing/#rule-flow-root-for-margin-collapse)」）。`flow-root` は、スクロールコンテナや切り取りを作らずに、新しいブロック整形コンテキストを作れる値です。ただし、変わるのは相殺だけではありません。中の `float` した要素も、親の高さの計算に入ります。また、親の外にある `float` の横では、親のボックスは `float` と重ならないよう、幅を狭めるか `float` の下へ送られます（「[11-14 floatで文章を回り込ませる](/layout-practice/float/)」）。止まるのは親子の相殺で、`flow-root` の中の兄弟どうしは相殺したままです。

<Baseline id="display-flow-root" />

```css title="🙆‍♂ Recommended: 親子の相殺は flow-root で止める" from="layout/margin-collapse-modes"
._section {
  display: block flow-root;
}
```

```css title="🙅‍♂ Not Recommended: 見えない padding や overflow で相殺を止める" issue="behavior"
/* 🙅‍♂ Not Recommended */
._section {
  overflow: hidden;
  padding-block-start: 1px;
}
```

`overflow: hidden` でも相殺は止まりますが、要素がスクロールコンテナになり、中の `position: sticky` が働かなくなるほか、はみ出した影やフォーカスリングが切り取られます。`position: sticky` が働かなくなる理由は「[7-10 positionの基礎](/layout/positioning/)」で説明しています。1pxの `padding` は、相殺を止めるための指定であることがコードから読み取れず、レイアウトの高さも1px変わります。

次のデモでは、同じ2つの子要素を、3種類の親に入れています。1つ目の子は上に32px、下に24px、2つ目の子は上に40px、下に32pxの `margin` を持ちます。点線の枠は親を囲む要素で、親の外へ出た余白がその内側に見えます。

<Demo title="通常フロー、flow-root、Grid で、同じ margin の相殺の仕方が変わる" html={modesHtml} css={modesCss} variant="neutral" />

通常フローの親では、最初の子の上の32pxと最後の子の下の32pxが親の外へ出て、枠と背景の間に空きができます。子どうしの間は、24pxと40pxが相殺して40pxです。`display: block flow-root` の親では、32pxが背景の内側に収まりますが、子どうしの間は40pxのままです。Gridの親では、親子と兄弟のどちらも相殺せず、子どうしの間は24pxと40pxを足した64pxになります。

## 補足と注意点

余白を作るために、空の要素や `<p>&nbsp;</p>` を置くのは避けます。空の要素は、「相殺が起きる場面」のデモのとおり通常フローでは相殺で消え、`gap` で並べた領域では `gap` の2つ分の間隔になり、置き場所の親によって結果が変わります。`&nbsp;` だけの段落や `<br>` は1行を作るので、余白の大きさが行の高さで決まり、文字の大きさを変えると一緒に変わります。

{/* 要確認: 出典なし。空の要素で余白を作らない方針 */}

ブラウザの開発者ツールのボックスモデルの表示は、要素に指定された `margin` を示し、相殺した後の余白は示しません。親の外へ出た余白を探すときは、親と子を順に選び、それぞれの `margin` の領域が重なる位置を見比べます。

AIが生成するコードでは、親子の相殺を `overflow: hidden` で止める例をよく見かけます。切り取りの副作用はレビューで見落とされやすく、後から `position: sticky` を足したときなどに不具合として現れます。レビューでは、`overflow` の指定に「何を切り取るためか」が説明されているかを確かめ、相殺を止めるためだけなら `display: block flow-root` に置き換えます。
