要素は、内側から順に、内容、`padding`、`border`、`margin` の4つの領域を持つ箱（ボックス）として描かれます。`inline-size` がどの領域までの幅を指すかは `box-sizing` で決まり、本書ではkiso.cssに合わせて、すべての要素を `border-box` にしています。指定した幅は、`border` の外周までの幅です。

この節では、4つの領域と `box-sizing` に加えて、`margin` の負の値と `auto`、ボックスの大きさに含まれない `outline` と `box-shadow`、インライン要素での余白の扱いを説明します。大きさを指定しないときの `auto` や、中身に合わせた大きさ、下限と上限、`%` の基準、`stretch` は、「[7-4 大きさの決まり方](/layout/sizing/)」で説明します。

## 指定した幅と見た目の幅がずれる理由

`inline-size: 240px` と書いた要素が、画面上では304pxになることがあります。`box-sizing` が初期値の `content-box` で、左右に24pxの `padding` と8pxの `border` が付いている場合です。指定した値は内容の領域の幅で、`padding` と `border` はその外側に足されます。

この仕組みのまま列の幅を合わせると、`calc(50% - 34px)` のような引き算が要素ごとに入り込みます。`padding` を変えるたびに引き算も直す必要があり、直し忘れると列の合計が親の幅を超えて折り返します。

```css title="🙅‍♂ Not Recommended: padding と border の分を幅から引いて合わせる" issue="convention"
/* 🙅‍♂ Not Recommended */
.card {
  box-sizing: content-box;
  inline-size: calc(50% - 34px);
  padding: 16px;
  border: 1px solid;
}
```

AIが生成するコードでは、コンポーネントごとに `box-sizing: border-box` を書き足す例もよく見かけます。全称セレクタで指定済みなら、この宣言は何も変えません。どちらも、どの領域が幅として数えられるかを知っていれば書かずに済むコードです。

## 4つの領域と `box-sizing`

ボックスのいちばん内側は、文字や子要素が置かれる内容の領域です。その外側に、内容と枠の間を空ける `padding`、枠線を描く `border`、ほかのボックスとの間を空ける `margin` の領域が順に重なります。`background-clip` の初期値は `border-box` なので、背景色は `border` の下まで塗られ、破線の枠線の隙間からも見えます。

次のデモは、ボックスの4つの領域を色分けしたものです。内容の領域は緑、`padding` の領域は青、`margin` の領域は親の斜線で表しています。

<Demo title="ボックスの4つの領域と、背景が描かれる範囲" html={areasHtml} css={areasCss} scheme="light" />

`margin` の領域には、要素自身の背景は描かれず、クリックの対象にもなりません。ボタンの押せる範囲を広げるときに `margin` ではなく `padding` を使うのは、このためです。縦に並んだブロックの間では、上下の `margin` が足されずに大きいほうだけが残ることがあり、この現象は「[7-6 マージンの相殺](/layout/margin-collapse/)」で説明しています。

`box-sizing` は、`inline-size` と `block-size` がどの領域の大きさを指すかを決めます。初期値の `content-box` では内容の領域を指し、`border-box` では `border` の外周までを指します。kiso.cssは、全称セレクタと `::before`、`::after` を `border-box` にしています（「[8-1 壊さないリセット](/reset/kiso/)」）。そのため、`inline-size: 50%` の要素は、`padding` をいくつにしても親の半分に収まります。

```css title="🙆‍♂ Recommended: border-box を前提に、幅と余白を別々に決める"
.card {
  inline-size: 50%;
  padding: 16px;
  border: 1px solid;
}
```

次のデモでは、同じ240px相当の `inline-size` を指定した2つの要素を、`content-box` と `border-box` で比べています。どちらも左右に24pxの `padding` と8pxの `border` を持ちます。`content-box` の要素は上の帯より64px広い304pxになり、`border-box` の要素は帯と同じ幅に収まります。

<Demo title="同じ inline-size でも、box-sizing によって全体の幅が変わる" html={sizingHtml} css={sizingCss} />

`content-box` に戻すのは、内容の幅を固定したい要素だけです。その代表が、次に説明する、最大幅と左右の `padding` で中央に寄せる要素です。

## `border-box` を取り消して最大幅を内容の幅にする

最大幅を決めて中央に寄せ、左右に `padding` を付ける要素では、`border-box` が不便になります。`max-inline-size` に `padding` が含まれるので、内容の幅は最大幅から左右の `padding` を引いた分しかありません。内容を1140px相当に保とうとすると、最大幅に `padding` を足す `calc()` を書くことになり、`padding` の値を変えるたびに式も直す必要があります。

```css title="🙅‍♂ Not Recommended: 最大幅に左右の padding を足して、内容の幅を保つ" issue="convention"
/* 🙅‍♂ Not Recommended */
._content-inner {
  --_max-inline-size: calc(1140 / 16 * 1rem);
  --_padding-inline: 20px;

  max-inline-size: calc(var(--_max-inline-size) + var(--_padding-inline) * 2);
  margin-inline: auto;
  padding-inline: var(--_padding-inline);
}
```

この要素だけ `box-sizing: unset` にすれば、足し算は要りません。`content-box` では `max-inline-size` が内容の領域の幅を指すので、指定した最大幅がそのまま内容の幅になり、`padding` はその外側に付きます。画面が狭いときは、ブロックの `auto` の幅が `padding` を含めて親に収まるので、はみ出しもしません（ルール `unset-box-sizing-for-content-max-width`）。

```css title="🙆‍♂ Recommended: box-sizing を unset にして、最大幅を内容の幅にする"
._content-inner {
  box-sizing: unset;
  max-inline-size: calc(1140 / 16 * 1rem);
  margin-inline: auto;
  padding-inline: 20px;
}
```

次のデモでは、`max-inline-size` が240px相当で左右に20pxの `padding` を持つ2つの要素を比べています。緑が内容の領域です。`border-box` のままの要素では内容の幅が200pxに減り、`box-sizing: unset` の要素では内容の幅が240pxのまま、`padding` を含めた全体が280pxになります。

<Demo title="box-sizing を unset にすると、最大幅が内容の幅になる" html={unsetHtml} css={unsetCss} variant="neutral" scheme="light" />

`unset` は、継承するプロパティでは親の値を、継承しないプロパティでは初期値を使うキーワードで、継承しない `box-sizing` では初期値の `content-box` になります。本書で `content-box` と書かずに `unset` と書くのは、「ベーススタイルの `border-box` を取り消す」という意図を宣言で示すためです。`content-box` と書くと、その要素のためにボックスの数え方を選んだように読めます。同じ理由で、「[17-7 フォーム部品](/interaction/forms/)」でも、行数で高さを決めるテキストエリアに `box-sizing: unset` を書いています。

`content-box` へ戻した要素で `inline-size: 100%` を指定すると、`padding` の分だけ親からはみ出します。幅は `auto` のままにし、上限だけを `max-inline-size` で決めます（「[2-3 保守しやすさを最優先にする](/design-mindset/maintainability/#rule-no-redundant-width-100)」）。また、この方法は、画面幅いっぱいに広げる子要素を持たない要素に向いています。広げる子要素が混ざるページのレイアウトは、左右に余白の列を持つGridで組みます（「[11-2 余白を設計する](/layout-practice/spacing/)」）。

## `margin` の負の値と `auto`

`margin` には負の値を指定できます。`margin-block-start` を負にすると要素は前の要素に重なるように引き上げられ、幅が `auto` のブロックの `margin-inline` を負にすると、その分だけ横に広がります。負のマージンは、コンポジションの子に付いた余白を親の端で打ち消すといった、余白の調整に使います。要素を重ねる目的なら、Gridの同じエリアに置くほうが、重ねたどちらの大きさも親の高さに反映されます（「[11-6 重なりと全幅](/layout-practice/layering/#rule-grid-stack-before-absolute)」）。

次の例では、カードの画像の左右に、カードの `padding` と同じ大きさの負の `margin` を付けています。画像の幅は `auto` のままなので、左右の `padding` の分だけ広がり、カードの端まで届きます。

```css title="🙆‍♂ Recommended: 負の margin で、親の padding を越えて端まで広げる"
.card {
  --_padding: 24px;

  padding: var(--_padding);

  & > ._image {
    margin-inline: calc(var(--_padding) * -1);
  }
}
```

`margin` の `auto` は、余った空間を受け取る値です。通常フローのブロックでは、`inline-size`、左右の `margin`、`padding`、`border` の合計が包含ブロックの幅と等しくなるように決まります。左右を `auto` にすると、余りが等分されて中央に寄ります（「[7-3 ボックスモデルの基礎](/layout/box-model/#rule-margin-inline-auto-centering)」）。通常フローでは上下の `auto` は0として扱われ、上下の中央寄せには使えません。

フレックスアイテムとグリッドアイテムでは、上下の `auto` も余った空間を受け取ります。フレックスアイテムの1つに `margin-inline-start: auto` を付ければ、その要素から後ろが行の末尾に寄ります（「[11-1 レイアウト手法の選び方](/layout-practice/choosing/#rule-flex-auto-margin-for-end-items)」）。

```css title="🙆‍♂ Recommended: auto の margin で、ログインのリンクを行の末尾に寄せる" from="layout/box-model-margin-auto"
._header {
  display: block flex;

  & > ._login {
    margin-inline-start: auto;
  }
}
```

次のデモの上は、幅を中身に合わせたブロックの `margin-inline` を `auto` にしたもので、左右の余りが等分されて中央に寄ります。下は3つ並んだフレックスアイテムの最後の1つに `margin-inline-start: auto` を指定したもので、行の余りをすべてその `margin` が受け取ります。

## ボックスの大きさに含まれない `outline` と `box-shadow`

`outline` と `box-shadow` は、ボックスの外側に描かれますが、ボックスの大きさには含まれません。付けたり太さを変えたりしても、要素自身と周りの要素の位置は変わらず、はみ出した部分でスクロールバーが出ることもありません。その代わり、周りの要素に重なって描かれ、`overflow: clip` の祖先では切り取られます。

一方、`border` はボックスの大きさに含まれるので、ホバーや選択の状態で `border` を足すと、要素が広がって隣の要素や後ろの行が押し出されます。状態で枠を足すなら、同じ太さの透明な `border` を最初から置いて色だけ変えるか、`outline` や `box-shadow` で描きます（ルール [`hover-keeps-size`](/interaction/states-and-focus/#rule-hover-keeps-size)）。{/* 要確認: 出典なし */}

```css title="🙆‍♂ Recommended: 透明な border を置いておき、選択の状態では色だけを変える"
._tab {
  border-block-end: 2px solid transparent;

  &[aria-selected="true"] {
    border-block-end-color: currentColor;
  }
}
```

フォーカスリングを `outline` で描くのも、この性質によります。リングを付けても周りがずれず、強制カラーモードでも表示が残ります（「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」）。

次のデモでは、1行目のBにだけ `outline` と `box-shadow` を付けています。装飾は隣のAとCに重なって描かれますが、AとCの位置は装飾のない2行目と変わりません。

## インライン要素の `padding` と `margin`

`<span>` や `<a>` のようなインライン要素では、左右の `padding`、`border`、`margin` は前後の文字を押し広げますが、上下の値は行の高さに反映されません。上下の `margin` は無視され、上下の `padding` と `border` は描かれるものの、行の高さは `line-height` だけで決まるので、背景や枠線が前後の行に重なります。インライン要素には、`inline-size` と `block-size` も適用されません。

文中のリンクに上下の `padding` を付けると、背景と押せる範囲は上下に広がりますが、行の間隔は変わらず、前後の行の文字に重なります。そのため、上下の余白として見せたい場合には使えません。

上下の余白を行の高さに反映させたいときは、要素を `display: inline flow-root`（`inline-block`）にします。外側はインラインのまま、内側がブロックの規則になるので、上下の `padding`、`margin`、`inline-size` がボックスの大きさに反映されます。`<img>` のような置換要素も、インラインのまま上下の値が行の高さに反映されます。

```css title="🙆‍♂ Recommended: 上下の余白を行の高さに反映させるタグは inline flow-root にする"
._tag {
  display: inline flow-root;
  padding-block: 4px;
}
```

次のデモは、インライン要素に上下12pxの `padding` と `margin` を付けたものです。1つ目の段落では、背景が前後の行に重なるだけで行の間隔は変わらず、`inline flow-root` にした2つ目の段落では、その行だけ高さが増えています。

<Demo title="インライン要素と inline flow-root の要素で、上下の余白の扱いが違う" html={inlineHtml} css={inlineCss} />

## 補足と注意点

`border-box` でも、指定した幅より大きくなることがあります。`padding` と `border` の合計が指定した幅を超えると、内容の領域は0で止まり、ボックスは `padding` と `border` の合計まで広がります。小さな `inline-size` の要素に大きな `padding` を付けるときは、この下限に気を付けます。

この下限があるので、`padding` の違うフレックスアイテムは、`flex: 1` でも幅がそろいません（「[7-7 Flexboxの基礎](/layout/flexbox-basics/)」の「`flex: 1` でも列の幅がそろわない場合」）。
