CSSのレイアウトは、1つの仕組みではなく、通常フロー、Flexbox、Grid、位置指定（`position`）といった複数の方式の組み合わせでできています。同じ `margin` や `inline-size` でも、要素がどの方式の中に置かれているかで、働き方が変わります。指定が思いどおりに効かないときは、値を足す前に、その要素がどの方式の中にあり、大きさや位置の基準になる要素（包含ブロック）と、重なり順を決める範囲（スタッキングコンテキスト）がどれかを確かめます。

この節で新しく判断するのは、効かない指定の原因を方式の規則、包含ブロック、スタッキングコンテキストのどれかから特定し、規則どおりの直し方を選ぶことです。レイアウトを方式ごとのアルゴリズムとして捉え、プロパティをその入力として読む見方は、「[1-3 レイアウトをアルゴリズムへの入力として読む](/principles/layout-algorithms/)」で説明しています。各方式の詳しい規則は、続く7-2〜7-10で説明します。

## 「効かない」指定はどこから来るのか

インライン要素に付けた `margin-block`、ブロックの親に書いた `gap`、留まらない `position: sticky` のように効かない指定は、壊れているわけではなく、その方式の規則どおりに振る舞っています。規則を知らないまま値を足すと、不具合は見た目の上では消えても、原因は残ります。

たとえば、インライン要素の上下の余白を `position: relative` と `top` でずらして作ると、その要素だけが行から浮き、文字の大きさを変えたときに重なります。正しい直し方は、要素を `inline flow-root` にして、ブロックの規則で余白を持たせることです。直し方を選ぶには、どの方式の規則が働いているかを知る必要があります。

```css title="🙅‍♂ Not Recommended: インライン要素を位置指定でずらして余白に見せる" issue="behavior"
/* 🙅‍♂ Not Recommended */
._tag {
  position: relative;
  inset-block-start: 4px;
}
```

```css title="🙆‍♂ Recommended: inline flow-root にして、ブロックの規則で余白を持たせる"
._tag {
  display: inline flow-root;
  margin-block: 4px;
}
```

AIが生成するコードにも、同じ傾向があります。方式の違いを考えずに、`display: flex` と `align-items: center` を何にでも足し、効かなければ `position: absolute` で位置を合わせるコードはよく見かけます。レビューで「なぜこの指定が要るのか」を問うためにも、方式ごとの基本の振る舞いを押さえておきます。

## レイアウトの方式の一覧

本書で扱うレイアウトの方式と、それぞれの大きさの決め方は次のとおりです。

| 方式 | 指定 | 子の並べ方と大きさの決め方 | 説明する節 |
|---|---|---|---|
| 通常フロー | `display: block` など（デフォルト） | ブロックは積まれて親の幅いっぱいに広がり、インラインは行の中を流れる | 7-2 |
| Flexbox | `display: block flex` | アイテムの中身の大きさから出発し、余りや不足を配る | 7-7 |
| Grid | `display: block grid` | 親で行と列を決め、アイテムをセルに置く | 7-8 |
| 位置指定 | `position: absolute` など | 通常フローから外し、包含ブロックを基準に置く | 7-10 |

コードでは、通常フローは何も書かず、FlexboxとGridは親の `display` で、位置指定は要素自身の `position` で選びます。

```css title="🙆‍♂ Recommended: レイアウトの方式を、親の display と要素自身の position で選ぶ"
/* 通常フロー：display を変えない */

/* Flexbox と Grid：親の display の内側の値で選ぶ */
._actions {
  display: block flex;
}

._list {
  display: block grid;
  grid-template-columns: repeat(auto-fill, minmax(min(100%, 240px), 1fr));
}

/* 位置指定：position で選ぶ */
._card {
  position: relative;

  & > ._badge {
    position: absolute;
    inset-block-start: 8px;
    inset-inline-end: 8px;
  }
}
```

通常フローは、何も指定しない要素が従う方式です。ブロックレベルのボックスはブロック方向（横書きでは上から下）に積まれ、インラインレベルのボックスと文字は、行の中をインライン方向（横書きでは左から右）に流れます。FlexboxやGridへ切り替える前の仮の状態ではなく、行ボックス、匿名ボックス、マージンの相殺といった独自の規則を持つ方式です。詳しくは「[7-2 通常フローの基礎](/layout/normal-flow/)」で説明しています。

このほかに、段組み（`column-count`）や表（`display: table`）の方式もあります。どちらも、子の大きさと位置を自分の規則で決める点では、上の4つと変わりません。{/* 要確認: 出典なし */}

## 方式を決めるのは親の `display`

`display` の値は、外側と内側の2つの役割を持っています。外側は、その要素が親の通常フローの中でブロックとして積まれるか、インラインとして流れるかを決めます。内側は、その要素の子をどの方式で並べるかを決めます。本書が `display: block flex` のような2値構文で書くのは、この2つを分けて読めるようにするためです（「[9-8 モダンな記法にそろえる](/notation/modern-syntax/)」）。

つまり、要素がどの方式で並ぶかは、親の `display` の内側の値で決まります。親を `display: block grid` に変えると、子は通常フローではなくGridの規則で並び、子に書いた `margin` や `inline-size` の意味も変わります。要素自身の `display` を見ても、その要素がどう並ぶかは分かりません。

次のデモでは、`inline-size: 96px` と `padding-block: 16px` を指定した同じ `<span>` を、2つの親に入れています。通常フローの親では、`<span>` はインラインのまま行に流れ、幅は無視され、上下の `padding` は行の高さに加わりません。親を `display: block flex` にすると、同じ指定がアイテムの幅と高さとして働きます。

<Demo title="親の display を変えると、子の同じ指定の効き方が変わる" html={parentDisplayHtml} css={parentDisplayCss} variant="neutral" />

例外は、要素自身の指定で方式から外れる場合です。`position: absolute` と `fixed` の要素は、親がどの方式でも、その流れから外れます。`float` した要素も通常フローからは外れますが、フレックスアイテムとグリッドアイテムでは `float` が無視され、ほかの子と同じように並びます。不具合を調べるときは、親の `display` と、要素自身の `position` と `float` の両方を確かめます。

## 同じ `inline-size` が方式ごとに違う意味を持つ

方式が変わると、同じプロパティが別の入力として読まれます。ここでは幅の指定で比べます。本書のコードでは論理プロパティの `inline-size` で書きますが、横書きでは `width` と同じ向きの大きさです。

通常フローの、置換要素でないインラインボックス（`<span>` や `<a>`）には、幅の指定が適用されません。行の中を文字と一緒に流れる箱で、幅は中身の文字から決まるからです。画像のような置換要素や、`display: inline flow-root` の要素は、インラインでも幅を持てます。通常フローのブロックでは、幅の指定は守られる値です。親の幅が足りなくても縮まず、親からはみ出します。指定が親の幅と合わないとき、通常フローは幅ではなく行末側の `margin` を計算し直して帳尻を合わせるからです。

フレックスアイテムでは、同じ指定が伸び縮みの出発点になります。`flex-basis` が初期値の `auto` なら、Flexboxは幅の指定をアイテムの仮の大きさとして使い、並べて足りなければ `flex-shrink` の比で縮めます。デフォルトでは、中身の最小幅より小さくはなりません（「[7-7 Flexboxの基礎](/layout/flexbox-basics/)」）。

`%` の幅の基準になる包含ブロックも、方式で変わります。グリッドアイテムでは、アイテムを置いたグリッドエリアが包含ブロックになるので、`inline-size: 50%` は親ではなく、そのエリアの幅の半分です（「[7-8 Gridの基礎](/layout/grid-basics/)」）。`position: absolute` の要素は、`position` が `static` 以外のいちばん近い祖先の `padding` の領域を基準にします。幅を指定しなければ、左右の両方の位置を決めない限り、中身に合わせて縮みます（「[7-10 positionの基礎](/layout/positioning/)」）。

| 要素が置かれた方式 | `inline-size: 1000px` | `inline-size: 50%` の基準 |
|---|---|---|
| 通常フロー（置換要素でないインライン） | 適用されない | 適用されない |
| 通常フロー（ブロック） | 1000pxのまま。親より広ければはみ出す | 親の内容の領域 |
| Flexbox（横に並べるフレックスアイテム） | 伸び縮みの出発点。足りなければ縮む | フレックスコンテナの内容の領域 |
| Grid（グリッドアイテム） | 1000pxのまま | アイテムが置かれたグリッドエリア |
| 位置指定（`absolute`） | 1000pxのまま | `static` 以外のいちばん近い祖先の `padding` の領域 |

次のデモでは、幅200pxの親の中に、`inline-size: 280px` を指定した子を置いています。通常フローのインラインでは指定が無視され、子は文字の幅になります。通常フローのブロックとグリッドアイテムでは280pxのまま親からはみ出し、フレックスアイテムでは親の幅まで縮みます。

<Demo title="同じ inline-size: 280px が、置かれた方式によって無視される、はみ出す、縮む" html={inlineSizeHtml} css={inlineSizeCss} variant="neutral" />

直し方も、方式の規則に合わせて選びます。リンクに幅を持たせたいなら、値を変えずに `display: inline flow-root` を指定して、幅を持てる種類の箱へ変えます。フレックスアイテムが縮みすぎるときは、縮む量を決めているのは幅ではなく `flex-shrink` と最小幅なので、そちらで縮みすぎを防ぎます（「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/)」）。

```css title="🙆‍♂ Recommended: 方式の規則に合わせて、幅を決める指定を選ぶ"
/* 通常フローのインライン：幅を持てる種類の箱に変える */
._link {
  display: inline flow-root;
  inline-size: calc(160 / 16 * 1rem);
}

/* フレックスアイテム：幅を出発点のまま保ち、縮ませない */
._media {
  display: block flex;

  & > ._thumbnail {
    flex-shrink: 0;
  }
}

._thumbnail {
  inline-size: calc(96 / 16 * 1rem);
}
```

## 包含ブロック

`inline-size: 50%` のような `%` や、絶対配置の `inset` は、包含ブロックという矩形を基準にします。通常フローの要素なら、包含ブロックはたいていいちばん近いブロックの親の内容の領域です。`%` が何に対する割合になるか、`margin-inline: auto` で中央に寄る仕組みなど、大きさの決まり方は「[7-3 ボックスモデルの基礎](/layout/box-model/)」で説明しています。

位置指定の要素は、包含ブロックの決まり方が違います。`position: absolute` の要素は `position` が `static` 以外のいちばん近い祖先を、`fixed` の要素はビューポートを基準にします。ただし、祖先に `transform` などがあると、その祖先が包含ブロックになります。包含ブロックを作る条件は「[7-10 positionの基礎](/layout/positioning/)」で説明しています。

カードの角にバッジを置くときは、カードに `position: relative` を指定して、カードを包含ブロックにします。

```css title="🙆‍♂ Recommended: カードを包含ブロックにして、バッジを角に置く" from="layout/layout-containing-block"
._card {
  position: relative;

  & > ._badge {
    position: absolute;
    inset-block-end: 8px;
    inset-inline-end: 8px;
  }
}
```

次のデモでは、点線の枠が `position: relative` の祖先です。カードに `position` がないと、バッジは祖先の角を基準にして、カードの外に出ます。カードに `position: relative` を指定すると、バッジはカードの角に収まります。

## 重なりとスタッキングコンテキスト

要素の前後の重なりは、デフォルトではHTMLの順番で決まり、後に書いた要素が手前に描かれます。`z-index` で順番を変えられるのは、同じスタッキングコンテキストの中だけです。親が `z-index: 1` のスタッキングコンテキストを作っていれば、子に `z-index: 99` を指定しても、親の兄弟の `z-index: 2` の要素より手前には出ません。

次のデモは、この例をそのまま並べたものです。親に `z-index` がないと、子の `z-index: 99` が親の兄弟と比べられ、子が手前に出ます。親に `z-index: 1` を指定すると、子は親の中に閉じ込められ、親ごと兄弟の後ろに回ります。

<Demo title="親がスタッキングコンテキストを作ると、子の z-index は親の外と比べられない" html={stackingHtml} css={stackingCss} variant="neutral" />

`z-index` が働くかどうかも、方式で変わります。通常フローの要素は、`position` を指定しないと `z-index` が働きませんが、フレックスアイテムとグリッドアイテムは、`position` がなくても働きます。スタッキングコンテキストは、`opacity` が1未満の要素や、`transform` を持つ要素などでも作られます。意図して作るときは `isolation: isolate` を使います（「[11-6 重なりと全幅](/layout-practice/layering/)」）。

```css title="🙆‍♂ Recommended: z-index の数値を使わずにスタッキングコンテキストを作る"
._card {
  isolation: isolate;
}
```

## FlexboxとGridが通常フローを置き換える

`display` の内側を `flex` や `grid` にすると、その要素の子は、通常フローではなくFlexboxやGridの規則で並びます。子の外側の値は無視され、`<span>` のようなインラインの要素も、ブロックのように大きさを持つアイテムになります。マージンの相殺も、アイテムの間では起きません。

Flexboxは、アイテムの中身の大きさから出発して、余った空間や足りない空間をアイテムに配ります。Gridは、先に親で行と列を決め、アイテムをそのセルに置きます。前者は中身から外へ、後者は外から中身へと大きさを決める、と言い換えることもできます。それぞれの仕組みは「[7-7 Flexboxの基礎](/layout/flexbox-basics/)」と「[7-8 Gridの基礎](/layout/grid-basics/)」で、作るものに合わせて方式を選ぶ基準は「[11-1 レイアウト手法の選び方](/layout-practice/choosing/)」で説明しています。

配置のプロパティは、`*-items` と `*-content` で対象が違います。`align-items` は、各アイテムを、自分に割り当てられた領域（Gridならセル）の中でそろえます。`align-content` は、行や列のまとまり全体を、コンテナの中でそろえます。コンテナに余白があるときに、この違いが見た目に現れます。

`align-content` は、通常フローのブロックコンテナにも使えます。ブロックコンテナに指定すると、`display` を変えずに中身を上下の中央に置けます（「[7-2 通常フローの基礎](/layout/normal-flow/)」）。

次のデモでは、高さ200pxのコンテナに、高さ48pxの行を2つ持つGridと、段落1つのブロックを並べています。`align-items: end` では、各アイテムが自分のセルの下端にそろうだけで、行のまとまりはコンテナの上に残ります。`align-content: end` では、行のまとまりがコンテナの下端へ移ります。3つ目は、`display` をブロックのまま、`align-content: center` で段落を上下の中央に置いた例です。

<Demo title="align-items と align-content の違いと、ブロックコンテナの align-content" html={alignmentHtml} css={alignmentCss} />

方式どうしを組み合わせても、それぞれの規則は変わりません。GridやFlexboxのコンテナの中でも、`position: absolute` の子は流れから外れ、包含ブロックとスタッキングコンテキストの規則もそのまま働きます。一方、グリッドアイテム自身に `position: sticky` を指定すると、そのアイテムはデフォルトでセルの高さいっぱいに伸びるので、ずれる余地がなく、留まらないように見えます。同じアイテムに `align-self: start` を指定して伸びるのを止めると留まります（「[7-10 positionの基礎](/layout/positioning/)」）。組み合わせで起きる問題も、それぞれの方式の規則に分けて考えれば、原因を特定できます。

```css title="🙆‍♂ Recommended: グリッドアイテムを伸ばさずに、スクロールに追従させる"
._layout {
  display: block grid;
  grid-template-columns: 1fr calc(240 / 16 * 1rem);

  & > ._sidebar {
    align-self: start;
  }
}

._sidebar {
  position: sticky;
  inset-block-start: 16px;
}
```

## 効かない指定を調べる順番

ここまでの仕組みを、効かない指定を調べる順番にまとめます。まず親の `display` の内側の値を見て、要素が通常フロー、Flexbox、Gridのどれで並ぶかを確かめます。次に要素自身の `position` と `float` を見て、その流れから外れていないかを確かめます。最後に、そのプロパティがその方式で何を意味するか、包含ブロックとスタッキングコンテキストがどの要素かを確かめます（ルール [`identify-layout-mode-first`](/layout/fundamentals/#rule-identify-layout-mode-first)）。プロパティの意味は、7-2〜7-10の各節や、MDNのプロパティのページ（冒頭の説明と、公式定義の「適用対象」）で確かめられます。

ブラウザの開発者ツールも、この確認に使えます。Chromeの開発者ツールは、正しい宣言でもほかの指定の都合で働いていないものを薄い文字で表示し、横のアイコンにその理由を示します（Chrome 108から）。Firefoxの開発者ツールにも、同じように働いていない宣言を示す機能があり（Firefox 70から）、インライン要素に書いた `width` には、インライン要素では働かないという理由が表示されます。
