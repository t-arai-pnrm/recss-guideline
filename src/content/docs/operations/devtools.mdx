表示が崩れたら、CSSを書き足す前に、開発者ツールで原因を確かめます。詳細度を上げる、`!important` を付ける、`overflow: hidden` で隠すといった対処は、原因が分からないままでも見た目を直せてしまいます。しかし、原因の宣言は残ったままなので、同じ崩れが別の場所で起き、上書きも積み重なります。

この節は、よくある症状から、Chrome DevToolsで見る場所と、仕組みを説明している節へたどるための案内です。仕組みそのものは各節に任せ、ここでは何を確かめれば原因を絞り込めるかだけを書きます。UIの名前と挙動は、Chromeのものです。症状から節とルールを引く一覧は、付録K「[困りごとから引く](/appendix/troubles/)」にあります。

{/* 要検証: ブラウザ。FirefoxとSafariの開発者ツールでの同等の機能と名前 */}

## 宣言が効かない

宣言が効かないときは、要素パネルで対象の要素を選び、スタイルペインでその宣言がどう表示されているかを見ます。表示は大きく3つに分かれ、それぞれ原因の種類が違います。

1つ目は、取り消し線が引かれている宣言です。ほかのルールの宣言に負けている（上書きされている）ことを示します。勝っている宣言は、同じプロパティを持つ別のルールとして、スタイルペインの上のほうに表示されます。2つの宣言を見比べ、レイヤー、詳細度、スコープの近さ、出現順のどこで差が付いたかを確かめます。スタイルペインでは、ルールの上に `@layer` や `@scope` の条件も表示されるので、まずレイヤーが同じかどうかを見ます。レイヤーが違えば、詳細度をいくら上げても順位は変わりません。カスケードの順位の決まり方は「[4-1 カスケード・詳細度・継承](/cascade/cascade-basics/)」、レイヤーの順位は「[4-3 カスケードレイヤーで順位を決める](/cascade/layers/)」、スコープの近さは「[4-4 @scopeでスタイルを閉じ込める](/cascade/scope/)」で説明しています。

```css title="🙅‍♂ Not Recommended: 負けた理由を確かめずに順位を引き上げる" issue="convention"
/* 🙅‍♂ Not Recommended */
._title {
  color: var(--foreground--accent) !important;
}
```

`!important` で勝たせると、負けていた理由（たとえば、レイヤーの順番の誤り）が残ります。重要な宣言ではレイヤーの順位が逆になるので、次に上書きしたい人は、さらに別の手段を探すことになります。

2つ目は、取り消し線に警告のアイコンが付いた宣言です。プロパティ名の綴りの誤りや、そのプロパティが受け付けない値など、ブラウザが解釈できなかった宣言です。この宣言は構文の段階で捨てられているので、カスケードには参加していません。同じプロパティを前に書いていれば、そちらが使われます。プロパティ名が無効なら宣言全体に、値だけが無効なら値に印が付きます（Chrome DevToolsのドキュメントで確認）。

3つ目は、取り消し線がなく、勝っているように見えるのに、表示が変わらない宣言です。ここには2つの場合があります。1つは、宣言が働く条件を満たしていない場合で、Flexコンテナでない要素の `justify-content` などがこれに当たります。Chromeは、こうした宣言の横に情報のアイコンを表示し、何が足りないかを説明します。もう1つは、未定義のカスタムプロパティを参照している場合です。

```css title="🙅‍♂ Not Recommended: 未定義のカスタムプロパティを代替値なしで参照する" issue="behavior"
/* 🙅‍♂ Not Recommended */
._list {
  gap: var(--card-gap); /* 宣言したのは --card--gap */
}
```

`var()` が参照するカスタムプロパティが存在しないと、その宣言は計算値の時点で無効になります。構文の段階では正しいので、スタイルペインでは有効な宣言として表示され、ほかの宣言を負かしたうえで、プロパティは継承値か初期値になります。この例では、`gap` が初期値の `normal` になり、間隔がなくなります。スタイルペインで `var()` の中の名前にカーソルを合わせると、値が表示されるか、定義されていないことが分かります。値が見つからなければ、名前の綴りと、そのカスタムプロパティを宣言した要素が祖先にあるかを確かめます。

{/* 要検証: ブラウザ。未定義のカスタムプロパティを参照したときのスタイルペインの表示 */}

そもそも、書いたルールがスタイルペインに表示されないこともあります。スタイルペインには、選んだ要素に一致したルールだけが表示されるので、表示されなければ、セレクタが要素に一致していません。クラス名の綴り、`@scope` の範囲（下限の `to (.scoped)` で内側のコンポーネントが除かれていないか）、`:hover` などの状態を確かめます。状態は、スタイルペインの `:hov` ボタンから強制的に付けられます。ファイルが読み込まれていない、`@layer` の宣言の順番が意図と違う、といった原因も、ここで見当が付きます。

## 幅が縮まない・はみ出す

要素の幅が縮まない、親からはみ出すときは、算出ペインで実際の大きさと、大きさに関わるプロパティの値を確かめます。算出ペインの上部にあるボックスモデルの図で、内容、`padding`、`border`、`margin` のどこが幅を取っているかが分かります。各プロパティを展開すると、その値をどのルールが決めたかも表示されます。

Flexアイテムとグリッドアイテムが縮まないときは、`min-inline-size` を見ます。ここが `auto` のままだと、アイテムは内容の最小の幅（min-content）より小さくなりません。長いURLや単語、折り返さない表、`white-space: nowrap` の子要素が、この最小の幅を押し広げています。グリッドの `1fr` も、最小値が `auto` の `minmax(auto, 1fr)` として扱われるので、同じ理由で縮まりません。

原因の見当が付いたら、スタイルペインで値を一時的に書き換えて確かめます。アイテムに `min-inline-size: 0` を足す、`1fr` を `minmax(0, 1fr)` に変える、長い語に `overflow-wrap: anywhere` を足す、のどれで直るかを見れば、原因を1つに絞れます。直ったら、その変更をソースのCSSに書き戻します。開発者ツールでの変更は再読み込みで消えるので、書き戻すまでは直ったことになりません。

要素パネルでは、Flexコンテナとグリッドコンテナの横に `flex` と `grid` のバッジが付きます。バッジを押すと、レイアウトのオーバーレイが表示され、トラックや隙間、アイテムの大きさがページの上に描かれます。レイアウトペインからは、グリッドの線の番号やエリア名の表示も切り替えられます。どのトラックが広がっているかは、数値を読むより、オーバーレイで見るほうが早く分かります。

大きさが決まる仕組みは「[7-4 大きさの決まり方](/layout/sizing/)」、内容の長さに耐える書き方は「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/)」で説明しています。

## 横スクロールが出る

ページに横スクロールが出たら、はみ出している要素を先に特定します。`body` や `html` に `overflow-x: hidden` を付けると、スクロールバーは消えますが、はみ出した内容は切れたままになります。`html` と `body` の両方に付けると、`body` がスクロールコンテナになり、`body` の中の `position: sticky` も働かなくなります。片方だけなら、値はビューポートに移るので、`sticky` は留まります。{/* 要検証: ブラウザ。html だけ、body だけ、両方に overflow-x: hidden を付けたときの sticky の挙動（Chrome、Safari、Firefox） */}

はみ出している要素を探す手順と、そのためのコンソールのスクリプトは「[11-4 はみ出しとスクロール](/layout-practice/overflow/)」にあります。要素が見つかったら、前の見出しと同じく、算出ペインで幅を決めているプロパティを確かめます。デバイスモードで画面幅を狭めながら見ると、どの幅からはみ出しが始まるかも分かります。

## stickyが留まらない・z-indexが効かない

`position: sticky` が留まらないときは、祖先にスクロールコンテナがないかを確かめます。`sticky` の要素は、最も近いスクロールコンテナの中で留まる位置を決めます。祖先に `overflow: hidden` や `overflow: auto` の要素があると、その要素がスクロールコンテナになり、ページをスクロールしても `sticky` の要素は動いたままに見えます。はみ出しを切るだけなら、スクロールコンテナを作らない `overflow: clip` を使えます。

要素パネルでは、ユーザーがスクロールできる要素の横に `scroll` のバッジが付きます。ただし、バッジが付くのは、`overflow` が `scroll` の要素と、`auto` で中身があふれている要素だけです（Chrome DevToolsのドキュメントで確認）。`overflow: hidden` の要素や、中身があふれていない `auto` の要素もスクロールコンテナですが、バッジは付きません。祖先をたどるときは、バッジに加えて、算出ペインで `overflow` の値を確かめます。

祖先にスクロールコンテナがないのに留まらないときは、`inset-block-start` などの位置の指定があるか、親要素の高さが `sticky` の要素と同じでないかを見ます。`sticky` の要素は親要素の範囲の外へは出ないので、親要素に余白がなければ、留まる距離がありません。

`z-index` が効かないときは、重なりコンテキストを作っている祖先を探します。`z-index` の比較は、同じ重なりコンテキストの中でしか行われません。祖先に `opacity` が1未満、`transform`、`filter`、`isolation: isolate` などの要素があれば、その中でいくら `z-index` を上げても、外の要素の上には出ません。要素パネルには、重なりコンテキストを作った要素を示すバッジがありません（Chrome DevToolsのドキュメントで確認）。算出ペインで祖先を1つずつ選び、これらのプロパティの値を確かめます。

コンテナにする `container-type: inline-size` は、現在の仕様（CSS Conditional Rules Level 5）ではレイアウトの封じ込めを含まないので、それだけでは重なりコンテキストを作りません。レイアウトの封じ込めを含む旧実装（Chrome 128以前、Firefox 132以前、Safari 18.3以前）では、コンテナが `position: fixed` の包含ブロックや重なりコンテキストになります。どれも本書の対象のブラウザより古い版なので、本書の対象では起きません。対象より古いブラウザを支える案件で、そのブラウザでだけ重なりが崩れるなら、祖先のコンテナも確かめます。仕様が変わった経緯は「[13-4 コンテナの副作用とコンテナ単位](/responsive/container-units-and-side-effects/)」で説明しています。

`position` と `sticky` の基礎は「[7-10 positionの基礎](/layout/positioning/)」、重なりの設計は「[11-6 重なりと全幅](/layout-practice/layering/)」で説明しています。

## コンテナクエリが効かない

コンテナクエリが効かないときは、問い合わせ先のコンテナが見つかっているかを確かめます。要素パネルでは、`container-type` を持つ要素の横に `container` のバッジが付きます。対象の要素から祖先へたどり、`container: --scoped / inline-size` を宣言したルートにバッジがあるかを見ます。スタイルペインでは、ルールの上に `@container` の条件が表示され、カーソルを合わせると、問い合わせ先のコンテナがページの上で強調されます。

{/* 要検証: ブラウザ。@container の条件にカーソルを合わせると、問い合わせ先のコンテナがページの上で強調されるか（ドキュメントには、コンテナの名前が要素パネルへのリンクになるとだけある） */}

条件を満たさないコンテナクエリの中のルールは、スタイルペインに表示されません（Chrome DevToolsのドキュメントで確認）。書いたはずのルールが見えないときは、クエリの条件か、問い合わせ先のコンテナを疑います。

よくある原因は3つです。1つ目は、名前の不一致です。`@container --scoped (…)` の名前がルートの `container-name` と違うと、名前の合うコンテナが祖先にないので、クエリは一致しません。2つ目は、コンテナ自身をクエリで変えようとしていることです。コンテナサイズクエリが問い合わせるのは祖先のコンテナなので、コンテナの要素自身の宣言は、自分の大きさでは切り替わりません。

```css title="🙅‍♂ Not Recommended: コンテナ自身の余白を自分のクエリで切り替える" issue="behavior"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.card) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
    padding: 16px;

    @container --scoped (inline-size >= calc(640 / 16 * 1rem)) {
      padding: 24px;
    }
  }
}
```

この `padding: 24px` は、`.scoped.card` の外側にある `--scoped` のコンテナを問い合わせるか、外側になければ、どの幅でも適用されません。切り替えたい宣言は、コンテナの子要素に書きます。

3つ目は、フラグの値の食い違いです。本書では、コンテナサイズクエリでフラグ（`--_density` など）を切り替え、ほかの子孫はスタイルクエリでそのフラグを問い合わせます。スタイルクエリが一致しないときは、算出ペインで、問い合わせる要素の親のカスタムプロパティの値を確かめます。`--spacious` と `--Spacious` のような綴りの違いや、フラグを宣言した要素が問い合わせる要素の祖先にないことが、ここで見つかります。

コンテナサイズクエリの書き方は「[13-3 コンテナサイズクエリ](/responsive/container-size-queries/)」、コンテナにすることの副作用は「[13-4 コンテナの副作用とコンテナ単位](/responsive/container-units-and-side-effects/)」、フラグの仕組みは「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」で説明しています。

## 補足と注意点

開発者ツールで見えるのは、ブラウザが解釈した後のCSSです。ビルドで結合や変換をしていると、スタイルペインに表示されるファイル名と行番号は、ソースのファイルと一致しません。ソースマップを出力しておけば、元のファイルの位置が表示されます。直すのは、ソースのCSSの、原因の宣言です。

どの要素がどこまで幅を取っているかを一度に見たいときは、すべての要素に一時的に `outline` を付けると、箱の入れ子がページの上に描かれます。`border` ではなく `outline` を使うのは、`outline` が場所を取らないからです。`border` は要素の大きさに加わるので、付けた分だけ幅が増え、調べたい崩れそのものが変わってしまいます。`outline` は境界の外側に描かれるだけで、レイアウトを変えません。確認が終わったら、この宣言は消します。

```css title="一時的にすべての要素の箱を描く"
* {
  outline: 1px solid oklch(63% 0.25 27deg);
}
```

`outline` は、祖先の `overflow: hidden` や `overflow: clip` で切られます。はみ出した要素の線が途中で消えて見えたら、祖先で切られていることを疑います。要素1つの大きさと余白を確かめるなら、前に挙げた算出ペインのボックスモデルの図のほうが正確です。{/* 要確認: 出典なし。すべての要素に outline を付けて箱の構造を見る方法 */}

開発者ツールで原因を確かめる作業は、AIに直させるときにも省けません。AIに崩れを直させると、`!important` や `overflow: hidden` のような、症状を消す変更が返ってくることがあります。原因の宣言を確かめてから、その宣言を直すよう指示すれば、変更の範囲を絞れます。AIが出したCSSの確かめ方は「[20-8 生成したコードを確かめ、教訓を残す](/ai-coding/verify-output/)」で説明しています。

{/* 要確認: 出典なし */}

この節で挙げた見方は、Chrome DevToolsを前提にしています。FirefoxとSafariの開発者ツールにも、取り消し線による上書きの表示や、Flexboxとグリッドのオーバーレイがあります。ブラウザによって表示が違う崩れは、それぞれのブラウザの開発者ツールで確かめます。
