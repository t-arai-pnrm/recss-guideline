CMSのWYSIWYGエディタが出力する本文は、`wysiwyg` クラスを付けた要素で囲み、`@scope (.wysiwyg)` の中にタイプセレクタでスタイルを書きます。編集者が入力した `h2` や `p` に、クラスを付けてもらう必要はありません。

編集画面から挿入できる独自のブロックには、`cms-` で始まるクラスを付けます。本文エリアの `@scope` は `to ([class|="cms"])` で独自ブロックの手前で止めるので、本文の `h2` のスタイルが、ブロックの中の `h2` に漏れることはありません。ブロックの内側は、ブロック自身の `@scope` が受け持ちます。

この節は、ほかの章の規約に対する例外を2つ含みます。`@scope` をネストすることと、独自ブロックの `@scope` で `to()` を省略することです。どちらも、CMSの本文エリアに限って認めます。例外にする理由は、後半で説明します。

## 編集者はクラスを付けられない

コンポーネントのマークアップは、コードを書く人が決めます。中の要素はタイプセレクタで選び、同じ種類の要素を役割で区別したいときは `._main-link` のようなクラスを付けられます。CMSの本文は違います。見出しと段落を書くのは編集者で、エディタは `h2`、`p`、`blockquote` をクラスなしで出力します。本文の見た目は、要素の種類だけを手がかりに決めるしかありません。

素直に書くと、本文エリアのクラスに子孫セレクタを並べることになります。

```css title="🙅‍♂ Not Recommended: 子孫セレクタで本文の要素にスタイルを当てる" issue="behavior"
/* 🙅‍♂ Not Recommended */
.wysiwyg h2 {
  padding-block: 8px;
  padding-inline-start: 16px;
  border-inline-start: 4px solid;
}

.wysiwyg p {
  line-height: var(--text--body--leading);
}
```

このセレクタは、本文エリアの中にあるすべての `h2` と `p` に当たります。本文の中に独自ブロックがあれば、ブロックの内側の見出しと段落も対象です。独自ブロックは見た目を自分で決めたいので、本文の装飾を打ち消すルールを、ブロックの側へ足すことになります。打ち消すには、詳細度で上回るか、`revert` のような指定を使います。詳細度の競争は、独自ブロックが増えるたびに厳しくなります。

## @scope で本文エリアを囲む

`@scope` を使えば、本文エリアの中だけに適用されるルールを、詳細度を上げずに書けます。`@scope (.wysiwyg)` の中に書いたセレクタは、`.wysiwyg` の子孫にだけ一致します。スコープのルートの `.wysiwyg` は、詳細度に加わりません。

独自ブロックは、スコープの下限で切り離します。`@scope (:scope) to ([class|="cms"])` のように、`to()` にブロックの目印を指定すると、そのブロックの中にはスタイルが届きません。内側の `@scope` の `:scope` は、外側のスコープのルート、つまり `.wysiwyg` を指します。

```css title="🙆‍♂ Recommended: 本文エリアの @scope から、独自ブロックを切り離す" from="operations/wysiwyg"
@scope (.wysiwyg) {
  @scope (:scope) to ([class|="cms"]) {
    h2 {
      padding-block: 8px;
      padding-inline-start: 16px;
      border-inline-start: 4px solid;
    }

    p {
      line-height: var(--text--body--leading);
    }
  }
}
```

本文の `h2` には、横の `padding` と線を直接付けています。通常は、文字の要素には文字のスタイルだけを書き、左右の余白は包む要素で作ります（ルール [`text-elements-text-styles-only`](/layout/margin-role/#rule-text-elements-text-styles-only)）。編集者が要素を足せない本文エリアでは包む要素を用意できないので、この規約の対象から外します。

通常の規約では、`@scope` は `@scope (.scoped.<名前>) to (.scoped)` の形で書き、ネストはしません。本文エリアは、中に入る要素を自分で決められないので、この形を使えません。`.scoped` のクラスを付けられるのは、コードを書く人だけだからです。代わりに、`cms-` で始まるクラスを、独自ブロックの目印にします。

この節の例は、`@layer` で包まずに書いています。CMSでは、レイヤーに入っていないCMS自身のCSSと共存するので、レイヤーを使わず、9つの分類はディレクトリ構成と `@import` の順番で保つからです（「[4-3 カスケードレイヤーで順位を決める](/cascade/layers/)」）。

## 独自ブロックは下限で切り離す

独自ブロックのスタイルは、ブロックのクラスを起点とする `@scope` で書きます。このスコープは、本文エリアの中で使う前提なので、`to()` を省略します。ブロックの内側に、別のブロックを入れないからです。入れ子にするブロックを作るときは、通常の規約どおり `to (.scoped)` を付けた形で書きます。

```css title="🙆‍♂ Recommended: 独自ブロックのスタイルは、ブロック自身の @scope に書く" from="operations/wysiwyg"
@scope (.cms-custom-section) {
  :scope {
    background-color: var(--background--inverse);
    color: var(--foreground--inverse);
  }

  h2,
  h3,
  h4 {
    font-size: calc(var(--text--title--font-size) / 16 * 1rem);
  }
}
```

デモでは、本文エリアの `h2` に左の線と背景色が付き、独自ブロックの `h2` には付かないことを確かめられます。ブロックの中の `p` も、本文エリアの `p` の行の高さを受け取りません。

## ブロック間の余白は rlh で決める

本文のブロックの間隔は、2つ目以降の直下の子に付けます。`& > * + *` に `margin-block-start: 1rlh` を指定し、見出しと独自ブロックの前だけ `2rlh` に広げます。`rlh` は、ルート要素の行の高さを単位にした長さです。本文の `p` と見出しの `line-height` が違っても、余白はルート要素の行の高さの倍数で揃います。

```css title="🙆‍♂ Recommended: 余白は rlh で、見出しと独自ブロックの前だけ広げる" from="operations/wysiwyg"
@scope (.wysiwyg) {
  :scope {
    & > * + * {
      margin-block-start: 1rlh;
    }

    & > * + :where(h1, h2, h3, h4, h5, h6, [class|="cms"]) {
      margin-block-start: 2rlh;
    }
  }
}
```

`blockquote` のように、中にブロックを持つ要素は、中の余白を半分の `0.5rlh` に詰めます。引用の中の段落は、本文のブロックより近くに置くほうが、ひとまとまりに見えるからです。`blockquote` の中は、セレクタを1段ネストして `& > * + *` と書きます。セレクタは、`blockquote` と `& > * + *` の2層です。

## 例外にする理由と注意点

`@scope` のネストと `to()` の省略は、通常の規約では認めません。前者は、`@scope` を入れ子にすると、ルールの届く範囲が読みにくくなるためです。後者は、`to()` を省略すると、入れ子のコンポーネントへスタイルが漏れるためです。本文エリアでは、この2つを認めても危険が小さくなります。ネストするのは本文エリアと独自ブロックの2段だけで、独自ブロックの中にコンポーネントを置かない前提が成り立つからです。独自ブロックの中にコンポーネントを置くことになったら、この例外をやめて、通常の規約に戻します。

`[class|="cms"]` には、制約があります。この属性セレクタは、`class` 属性の値の全体が `cms` か、`cms-` で始まるときに一致します。`class="cms-custom-section"` は一致しますが、`class="foo cms-custom-section"` は、先頭が `foo` なので一致しません。独自ブロックのクラスは、`class` 属性の先頭に書くと決めてください。クラスを種類ごとに `|` で区切って並べる場合も（「[9-1 命名規則](/notation/naming/)」）、独自ブロックのクラスはルートのグループの先頭に置くので、この約束と両立します。CMSのエディタが、クラスを並べ替えたり先頭に別のクラスを足したりする場合は、`to ([class*="cms-"])` のように部分一致にする手もあります。ただし、`xcms-` のようなクラスにも一致するので、クラス名の付け方を別に決める必要があります。

`@scope` のBaselineは「新しく利用可能」の段階です。基本の動作には、本書の対象のブラウザ（Safari 18.6以降と、ほかのブラウザの最新版）がすべて対応しています。対応していないブラウザでは、`@scope` の中のルールがすべて無視されるので、対象により古いブラウザを含む案件では、その基準で確かめます。{/* 要検証: ブラウザ。Safari 18.6で、ネストした @scope (:scope) to ([class|="cms"]) が適用され、独自ブロックの中に本文のスタイルが届かないか */}
