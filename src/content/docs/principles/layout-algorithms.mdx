レイアウトに関わるCSSは、プロパティと値の組を並べたものとしてではなく、ブラウザが要素の大きさと位置を計算するアルゴリズムへの入力として読むと理解しやすくなります。通常フロー、Flexbox、Grid、位置指定といったレイアウトの方式は、それぞれが別のアルゴリズムで、プロパティはそのアルゴリズムへの入力として読まれます。同じ `width: 1000px` が、要素の置かれた方式によって、守られる値にも、縮む出発点にも、無視される値にもなるのはこのためです。

この節では、`width` が効かないという1つの現象から、CSSを見る見方を変えるところまでを説明します。方式ごとの規則と、効かない指定を調べる手順は「[7-1 レイアウトの基礎](/layout/fundamentals/)」で、作るものに合わせて方式を選ぶ基準は「[11-1 レイアウト手法の選び方](/layout-practice/choosing/)」で説明しています。

## `width` が効かないと感じる理由

CSSを書き始めて最初に覚える宣言は、たいてい `color: blue` のようなものです。書いた値がそのまま文字の色になるので、CSSを「プロパティに値を書けば、そのとおりに表示される言語」と捉えたくなります。プロパティごとに「この値ならこう表示される」という対応を覚えていけば、CSSを書けるようになると考えるわけです。

ところが、大きさと位置に関わるプロパティでは、この捉え方が通用しません。リンクに `width: 1000px` を書いても、幅は変わりません。横並びのカードで同じ指定をすると、カードは画面の幅に収まるまで縮みます。

プロパティと値の対応表しか持っていないと、こうした振る舞いは「CSSは予測できない」という印象になります。印象のまま値を足し引きすると、見た目は合っても原因は残ります。効かない `width` に `display: block` を足し、それでも合わなければ `position: absolute` や `!important` を重ねるような修正は、どの宣言がなぜ働いているのかを誰も説明できないコードを残します。

## 方式ごとに別のアルゴリズムがある

ブラウザは、ページを表示するたびに、すべての要素の大きさと位置を計算します。この計算の手順を、レイアウトのアルゴリズムと呼びます。アルゴリズムは並べ方ごとに別のものが用意されていて、主なものに通常フロー、Flexbox、Grid、位置指定（`position: absolute` と `fixed`）があります。この並べ方の区別を、本書ではレイアウトの方式と呼び、MDNではレイアウトモードと呼んでいます。要素がどの方式で計算されるかは、主に親の `display` と要素自身の `position` で決まります。

プロパティは、こうしたアルゴリズムへの入力です。アルゴリズムは入力を自分の規則で解釈し、使わない入力は無視します。`gap` を通常フローのブロックに書いても子の間が空かないのは、通常フローのアルゴリズムが `gap` を使わないからです。反対に、同じ入力を複数のアルゴリズムが使う場合は、アルゴリズムごとに別の意味として扱われます。

`color: blue` が期待どおりに働いたのは、`color` が方式に左右されないプロパティだからです。文字の色や `font-size` のように、文字と描画に関わるプロパティの多くは、どの方式の中でも同じように働きます。方式によって意味が変わりやすいのは、`width`、`margin`、`z-index` のように、大きさと位置と重なりを決めるプロパティです。

## 同じ `width` が別の入力として読まれる

冒頭の2つの場面も、それぞれのアルゴリズムが `width` をどう使うかで説明できます。リンクのような文字と一緒に行の中を流れる箱は、幅を中身の文字から決めるので、行を組むアルゴリズムは `width` を使いません。横に並べたフレックスアイテムでは、Flexboxのアルゴリズムが `width` を仮の大きさとして受け取り、並べて足りなければ縮めます。通常フローのブロックに同じ指定をすると、今度は親より広くても1000pxのまま保たれます。

つまり、`width` は「幅をこの値にする」という命令ではなく、方式ごとに意味の違う入力です。`%` の基準、位置指定での振る舞い、`z-index` が働く条件も、同じように方式で変わります。方式ごとの違いは、「[7-1 レイアウトの基礎](/layout/fundamentals/)」で表にまとめています。

## 問いを「どの方式の中にいるか」に変える

この見方に立つと、指定が効かないときの問いが変わります。「このプロパティは壊れているのか」ではなく、「この要素は今どの方式の中にいて、その方式でこのプロパティはどう働くのか」を問います。プロパティそのものが壊れていることはめったになく、ほとんどの場合は、方式の規則どおりに振る舞っています（ルール [`identify-layout-mode-first`](/layout/fundamentals/#rule-identify-layout-mode-first)）。

問いが変わると、直し方も変わります。リンクに幅を持たせたいなら、`width` の値を変えたり宣言を重ねたりせず、リンクを幅を持てる種類の箱に変えます。値を調整するより、その方式の規則に沿って入力を選び直すほうが、原因を取り除けることが多くあります。

## 補足と注意点

方式の規則を、書き始める前にすべて覚える必要はありません。前提として持っておくのは、方式が違えば同じプロパティの意味が変わる、ということです。この前提があれば、効かない指定に出会ったとき、調べる範囲を今の方式の規則へ絞れます。「[1-5 解決策を丸暗記しない](/principles/no-memorizing/)」で取り上げた画像の下の隙間も、画像が通常フローの行の中に置かれていることから生まれる現象です。

この見方は、「[1-1 CSSはブラウザへの「提案」である](/principles/browser-suggestion/)」の考え方とつながっています。最終的な大きさと位置を決めるのはブラウザのアルゴリズムで、実装者が書くのは、そのアルゴリズムへの入力です。どのアルゴリズムが入力をどう使うかを知っていれば、固定値で結果を決めつけなくても、意図した範囲に収まる入力を選べます。
