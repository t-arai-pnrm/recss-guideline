# ルールの定義

本書のルールは、このディレクトリの YAML ファイルだけで管理します。各ページの `<Guideline />`、付録A「ルール一覧」、AI 向けのスキルと MCP サーバーのデータ（`pnpm gen:ai`）は、すべてここから作ります。

- ファイルは章ごとに分けます（例: `13-responsive.yaml`）。ファイル名の順に読み込み、ファイルの中では書いた順に並びます。
- 各ファイルにはルールの配列を書きます。

```yaml
- id: query-range-syntax # 章の構成に依存しない英語のスラッグ。公開後は変えない
  level: 必須 # 必須 / 推奨 / 非推奨 / 禁止
  kind: judgment # spec（仕様にもとづく制約） / judgment（実装上の判断） / convention（本書の規約）
  rule: メディアクエリとコンテナサイズクエリの条件は範囲構文で書く。 # 1文で書く
  reason: 条件の意味が式として読め、境界の値を含むかどうかも明確になるため。
  note: 補足や例外があれば書く。 # 省略可
  lint: 'Stylelint: `media-feature-range-notation`' # 自動チェックの手段。省略可
  aiProne: true # AI が誤りやすいもの。省略すると false
  page: responsive/media-queries # 掲載するページの ID
  since: 0.1.0 # 追加したバージョン
```

- `kind` は、ルールの根拠の性質です。強度とは別に決めます。表示名は `src/lib/rule-kinds.mjs` にあります。
  - `spec`：CSS・HTML・ブラウザの振る舞いや WCAG を根拠にし、適用する条件に当たる場面で守らないと、表示、操作、情報の伝わり方に問題が出る。問題が起きる条件と適用する範囲は、ルールの補足に書く。根拠が仕様や挙動にあるという意味で、その書き方を仕様が義務づけているとは限らない。本書の方針だけを根拠にするルールは `spec` にしない。
  - `judgment`：状況とトレードオフで決まり、適用する条件がある。
  - `convention`：一貫性のために本書が選んだ約束。ほかの約束を選んでも同じように成り立つ。
- ルール本文・理由・補足では、バッククォートで囲んだ部分がコードとして表示されます。
- ルールを変えたり消したりしたらメジャー、追加したらマイナーのバージョンを上げ、付録F「更新履歴」に書きます。
