「$ARGUMENTS」の監査をする。このスキルでは、コードを1行も変更しない。

## 手順

1. 監査を表すスラッグを、英小文字とハイフンで決める（例：`audit-cards`）。`tasks/` と `tasks/archive/` に同じ名前があれば、別の名前を提案して確かめる。
2. 対象のディレクトリと、使う視点をチャットで確かめる。視点の既定は次の5つ。利用者が足したり外したりしたら、それに従う。
   - 一貫性：トークンにない色、文字サイズ、余白、角丸の値。同じ種類の部品（ボタン、カード、入力欄）どうしの見た目の差。`DESIGN.md` があれば、そこに書いた判断との食い違い（accent の使い場所、決めた変種にない見た目）
   - 小さい画面：320px での横スクロールとはみ出し、押せる範囲の大きさ、文字サイズ 200% での欠けと重なり
   - 状態：ホバー、押下、無効、`:focus-visible` の見た目の有無。項目が0件、画像がない、長い見出しのときの表示。読み込み中とエラーのときに、レイアウトが崩れないか。開閉と切り替えの動きと、動きを減らす設定での表示
   - 色：ライトとダークの両方のテーマでの文字のコントラスト、強制カラーモードでの表示、色だけで区別している情報
   - キーボード：すべてのリンクとボタンに届くか、フォーカスが見えるか、移動の順番が見た目の順番と合うか
3. 視点ごとに、サブエージェントを1つずつ起動する。ブラウザを使う視点（小さい画面、状態、色、キーボード）は同じブラウザを共有するので並行させず、1つの視点を終えてから次を起動する。並行させてよいのは、コードを読むだけの視点（一貫性）だけ。サブエージェントを使えないツールでは、視点ごとに順に行い、1つの視点を終えてから次へ進む。どちらでも、次のことを守らせる。
   - ファイルを編集しない。調べて、一覧を返すだけにする。
   - 書く前に recss-guideline スキルの手順を読み、指摘にはルールの ID を添える。ルールの補足に書いた例外に当たるものは、指摘しない。
   - 指摘ごとに、ファイルと行、症状、確かめ方（実行したコマンドか、ブラウザで再現した条件）を書く。確かめていないものは「未確認」と書く。
4. 返ってきた一覧を [templates/audit.md](templates/audit.md) の形にまとめる。同じ箇所への重複した指摘は1つにし、どの視点から出たかを残す。
5. `tasks/<slug>/audit.md` を書き出して止まる。チャットには、視点ごとの件数と、全ページに及ぶ変更（トークン、ベーススタイル、レイヤーの順番、コンポジション）が要る指摘を示す。
6. 直す項目は人が選ぶ。選んだ項目は `/task-new` で修正のタスクにし、`/task-start` で直すよう案内して終える。このスキルからは修正に進まない。
